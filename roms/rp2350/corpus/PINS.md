# RP2350 firmware corpus pins

Reproducibility record for the firmware binaries under `roms/rp2350/`.
See HLD `2026.04.15 - HLD - RP2350 Peripheral Coverage V5.md` §3
(firmware corpus / stop rule) and Appendix A.

Two classes of binaries live under this directory:

- **Agent-authored** — hand-assembled Thumb-2 generated by the
  `gen_hello_*.py` scripts checked in beside the binaries. These are
  self-contained (no SDK/toolchain dependency): running the generator
  should reproduce the `.bin` bit-for-bit. First-build SHA256 is pinned
  below so any drift between the script and the binary is immediately
  visible.
- **pico-examples-pico2 sourced** — full SDK builds taken from
  `github.com/raspberrypi/pico-examples` for RP2350. These depend on a
  pinned pico-sdk-pico2 + ARM GCC toolchain, and the build is not
  deterministic byte-for-byte. Entries are listed below but pin
  placeholders are left for Arthur to fill when the binaries are
  generated on his rig.

## Agent-authored binaries

| Binary                        | Generator                             | Size  | SHA256 (first build) |
|-------------------------------|---------------------------------------|-------|----------------------|
| `roms/rp2350/hello_timer.bin` | `roms/rp2350/gen_hello_timer.py`      | 256 B | `4ce00917417410a9e0f20de5db20bcbf86171cc97910a3938dfbce3b7f10c582` |
| `roms/rp2350/hello_uart.bin`  | `roms/rp2350/gen_hello_uart.py`       | 256 B | `2fb7f0a258c64f48120ffed8e4fdb362275efadda9f9251780f01c29a6599add` |
| `roms/rp2350/hello_pwm.bin`   | `roms/rp2350/gen_hello_pwm.py`        | 256 B | `b1d0b59984cb856a1f7b324485f1a2985d97b480cec4c97a595f47cd860e0b6a` |

Regenerate all three via:

```bash
python3 roms/rp2350/gen_hello_timer.py
python3 roms/rp2350/gen_hello_uart.py
python3 roms/rp2350/gen_hello_pwm.py
```

Verify with:

```bash
sha256sum roms/rp2350/hello_timer.bin \
          roms/rp2350/hello_uart.bin \
          roms/rp2350/hello_pwm.bin
```

If the hash differs from the table above, the generator and the binary
are out of sync — regenerate, commit, and update this file.

When these are generated:

1. Record the `pico-sdk-pico2` SDK tag (e.g. `2.2.0-rp2350`) and the
   exact `pico-examples` commit SHA.
2. Compute `sha256sum` of the produced `.bin`.
3. Update the row above.
4. Flag any `.elf`-to-`.bin` post-processing (stripping, size trim,
   relocation) separately so independent rebuilds can match.

Toolchain (once pinned) should also record:

- ARM GCC version (e.g. `arm-none-eabi-gcc 13.2.Rel1`).
- CMake flags (`Release` vs `Debug`, LTO on/off).
- Any SDK-side patches applied.
