# Mutation Testing V1 — Implementation Journal

Date: 2026-04-26
Driver: supervisor (Opus 4.7) + agent team
Plan: `wrk_docs/2026.04.26 - HLD - Mutation Testing V1.md` (V1.1.0)

## Approach

Supervisor pattern: I direct, agents implement. Agents do all file reads, tool
runs, debugging. I read summaries, decide next, commit, journal.

Per-stage loop: implementer → reviewer (code-reviewer skill) + devil's
advocate (parallel) → apply-feedback if needed → commit → journal.

TDD note: this feature is "create two config files + run a tool". There is
no functional code to test. The acceptance criterion *is* the tool running
successfully and producing a survivor list. Loose-TDD interpretation:
calibration step is the test for the config; the missed.txt is the test for
the sweep.

## Stages

1. **Config files.** `.cargo/mutants.toml` + `.gitignore` line. Verify
   cargo-mutants installed (install if not). Validate config parses.
2. **Calibration.** Run cargo-mutants on `mdrp2040/src/core/decode.rs`
   (110 LOC). Confirm config field names, measure real per-mutant time,
   project full-sweep wall-clock.
3. **Decision.** Proceed to full sweep, scope down, or pause for user
   input — based on Stage 2 numbers.
4. **Full sweep.** Run cargo-mutants on all 7 in-scope files.
5. **Triage.** Bucket survivors, write triage HLD.
6. **Final compliance check.** Verify HLD acceptance criteria are met.

### Stage 2-3 — Calibration → decision (collapsed into Stage 4)

**Surprise**: `cargo mutants --file crates/mdrp2040/src/core/decode.rs` did
NOT scope-restrict in cargo-mutants 27.0.0. The CLI flag was effectively
ignored and the full 4389-mutant 7-file enumeration started. Mutants in
`execute.rs` ran alongside the intended decode.rs ones. Either v27's
`--file` semantics changed or it's overridden by `examine_globs` in the
toml — investigate post-run, doesn't affect outcome.

**Decision**: let it run, don't restart. Calibration data was acquired
from the first ~10 min of the run, which is sufficient to validate every
Stage-3 question. Restarting wastes ~10 min of baseline build + amortised
compilation that already paid out.

**Calibration data captured (n=70 mutants, ~6 min into run)**:
- Per-mutant cost: **5.4 s/mutant** (vs HLD estimate 60-180 s).
- Cargo command per mutant: full `cargo test`, NOT `cargo check --tests`.
  DA finding #2 was wrong — log shows
  `cargo test --no-run --verbose --package=mdrp2040@0.19.0 --package=mdrp2350@2.4.1`
  followed by `cargo test --verbose ...`.
- Integration tests under `tests/`: confirmed running. `tests/smoke.rs`,
  `tests/firmware.rs`, `tests/dual_model.rs`, `tests/multicore.rs` all
  compile and execute per-mutant.
- Outcome distribution at snapshot: 94.3 % caught, 4.3 % missed, 1.4 %
  unviable, 0 timeout.
- Free disk on C:: **258 GB**. DA finding #1 was correct (scratch lives
  in `%TEMP%`, on C:) but worth noting it's a non-issue at single-worker
  jobs — not yet stressed.

**Full sweep projection**: 4389 mutants × 5.4 s = ~6.6 h single-threaded.
Confortably within overnight. No need for `--jobs N` parallelism or
sharding for V1.

**First survivors observed** (all in `execute.rs::add_with_carry`,
classic boundary mutations):
- `execute.rs:25:26` — replace `>` with `>=`
- `execute.rs:26:25` — replace `^` with `|`
- `execute.rs:26:40` — replace `^` with `|`

These will go to triage in Stage 5. Initial flavor: looks like the unit
tests don't densely cover `add_with_carry`'s flag-update edge cases.

### Stage 1 — Config files (complete)

**Implementer**: cargo-mutants 27.0.0 was already installed. Created
`.cargo/mutants.toml` and added `mutants.out/` block to `.gitignore`.
Validated config with `cargo mutants --list-files` — returns the 7
in-scope files. The HLD's primary suggestion (`test_package`) was
correct for v27; no field-name surprise.

**Reviewer**: clean. No required changes. Confirmed comment style
matches surrounding `.gitignore` entries; toml mirrors HLD spec.

**Devil's advocate**: three real findings, ranked:

1. **Scratch dir is in `%TEMP%` (NTFS, no reflink), not `target/`.**
   ~517 MB per parallel worker on the system SSD. The HLD's "Risks"
   section was wrong about this. Action: address in Stage 2 disk
   planning, not Stage 1.
2. **Per-mutant phase may only run `cargo check --tests`** (DA observed
   ~11s for that phase). If true, the HLD's 60-180s/mutant estimate is
   off by a large factor. Action: verify directly via Stage 2
   calibration timings — calibration will observe whether `cargo test`
   also fires per-mutant.
3. **Mutant count is 4389**, not the HLD's 1500-3000 estimate (~0.71
   mutants/LOC vs. estimated 0.3-0.5). Confirmed by running
   `cargo mutants --list`. Action: feeds Stage 3 wall-clock projection.

Plus one cheap supervisor-awareness item applied immediately: a comment
in the toml warning that `test_workspace = true` / `--workspace` would
silently undo the probe-rs build-graph protection. Applied via fresh
agent using the code-review-apply-feedback skill.
