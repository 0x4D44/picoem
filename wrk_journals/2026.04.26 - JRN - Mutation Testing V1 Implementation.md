Date: 2026-04-26

## Approach

Supervisor pattern: I direct, agents implement. Agents do all file reads, tool
runs, debugging. I read summaries, decide next, commit, journal.

Per-stage loop: implementer → reviewer (code-reviewer skill) + devil's
advocate (parallel) → apply-feedback if needed → commit → journal.

TDD note: this feature is "create two config files + run a tool". There is
no functional code to test. The acceptance criterion *is* the tool running
successfully and producing a survivor list. Loose-TDD interpretation:
calibration step is the test for the config; the missed.txt is the test for
the sweep.

## Stages

1. **Config files.** `.cargo/mutants.toml` + `.gitignore` line. Verify
   cargo-mutants installed (install if not). Validate config parses.
2. **Calibration.** Run cargo-mutants on `mdrp2040/src/core/decode.rs`
   (110 LOC). Confirm config field names, measure real per-mutant time,
   project full-sweep wall-clock.
3. **Decision.** Proceed to full sweep, scope down, or pause for user
   input — based on Stage 2 numbers.
4. **Full sweep.** Run cargo-mutants on all 7 in-scope files.
5. **Triage.** Bucket survivors, write triage HLD.
6. **Final compliance check.** Verify HLD acceptance criteria are met.
