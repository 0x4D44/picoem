## Progress log

### Item 1 — drop dead-in-debug read-path patch (DONE)

Confirmed reachability analysis:

- `Bus::read32` carries an upstream `debug_assert!` at
  `crates/mdrp2350/src/bus/mod.rs:2792-2798` that panics for any PPB
  address (top nibble `0xE`) not in `is_boot_ram`
  (`0xEFFF_F000..0xF000_0000`) or `is_coresight_trace`
  (`0xE004_1000..0xE004_2000`). `0xE000_ED2C` (SCB_HFSR) matches
  neither, so the assert fires under default `cargo test`
  (debug-assertions ON) before reaching the cfg-gated short-circuit
  at the original lines 2918–2928.
- The only existing caller of `seed_hfsr_for_test` —
  `tests_narrow::s65_scb_hfsr_byte_write_clears_only_target_lane` —
  uses `bus.write8(SCB_HFSR + 1, …)` and `bus.bus_fault(0)`. It
  never invokes `bus.read32(SCB_HFSR)`. So the short-circuit was
  unreachable in practice across ALL build profiles, not just
  debug.
- Action: deleted the cfg-gated arm. Kept `seed_hfsr_for_test`
  in place — it's still useful for the future Stage 2/3/4
  narrow-access work (per the test's own comment) and the
  pre-existing storage in `peripheral_regs` is unaffected. Updated
  the helper's docstring to remove the now-stale "observable via
  `Bus::read32`" claim.

Verification:

- `cargo build -p mdrp2350 --release` — clean.
- `cargo test -p mdrp2350 --lib` — 3175 passed / 0 failed (incl.
  `s65_scb_hfsr_byte_write_clears_only_target_lane`).

### Item 2 — SAFETY comments on `pin_to_host_core` (DONE)

Five `unsafe` blocks in
`crates/mdpicoem-common/src/threaded/worker.rs::pin_to_host_core`,
all now carry per-block `// SAFETY:` prose:

1. `GetCurrentThread` (Windows) — pseudo-handle, never fails, no
   close required.
2. `SetThreadAffinityMask` (Windows) — handle is the pseudo-handle;
   `host_core < usize::BITS` precondition bounds the shift so
   `mask = 1usize << host_core` is non-zero (the only invalid mask
   the API rejects).
3. `std::mem::zeroed::<cpu_set_t>()` (Linux) — `cpu_set_t` is a
   POD bitset with the all-zero pattern equivalent to `CPU_ZERO`.
4. `CPU_ZERO` / `CPU_SET` (Linux) — `&mut set` is a valid aligned
   exclusive pointer to a fully-initialized cpu_set_t; `host_core`
   is bounded by the precondition (≤ 63 on 64-bit, well below the
   1024-bit `CPU_SETSIZE` of glibc).
5. `pthread_setaffinity_np` (Linux) — `pthread_self()` always
   returns a valid handle; `cpusetsize` matches the cpu_set_t we
   built; `&set` is read-only by the kernel for the duration of
   the call.

Verification:

- `cargo build -p mdpicoem-common --release` — clean.
- `cargo test -p mdpicoem-common --lib panic_message` — 1 passed.
