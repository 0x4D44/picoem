## Process

1. V1 of HLD written at `wrk_docs/2026.04.14 - HLD - Threaded Dual-Core Emulation.md`
2. Each review round: 3-5 agents with distinct perspectives critique the current version
3. Supervisor (me) synthesizes findings, writes next version, saves as Vn
4. Repeat until a round surfaces no critical issues

## Team perspectives

- **Concurrency/correctness** — race conditions, memory ordering, UB, deadlocks
- **Performance** — will this actually hit 150 MHz dual-core? Sync costs, cache effects
- **Architecture** — API design, separation of concerns, testability
- **Devil's advocate** — unstated assumptions, edge cases, things we might have missed

## "Critical" means

- Correctness bug (race, deadlock, UB)
- Blocks the performance goal (won't actually give expected speedup)
- Design flaw that makes it unmaintainable
- Missing major architectural consideration

Not "wording is unclear" or "I would have done it differently".
