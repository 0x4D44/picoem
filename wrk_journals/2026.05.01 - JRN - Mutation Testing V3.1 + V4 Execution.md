## Stage 1 — Thread 1: VCVT.F16.F32 subnormal-rounding corpus (complete)

### What landed

Added `vcvt_f16_rounding_edge_cases_f32()` to `crates/mdpicoem-harness/src/bin/softfloat_diff.rs` returning ~81 deterministic f32 inputs structured as four sweeps:

1. **Subnormal output corner sweep** — for `e ∈ {-15, -18, -21}` (representative of the `[-24, -15]` reachable range), build f32 inputs that independently set `(round_bit, sticky, lsb)` ∈ {0, 1}³ at the f16-mantissa boundary. Sign-mirrored. 48 cases.
2. **Normal-branch round-half-to-even spread** — for `e ∈ {-10, 0, 10}`, sweep `(round_bit, sticky, lsb)` ∈ {0, 1}³ over the bit positions used by the normal branch's mantissa-shift logic. 21 cases.
3. **Normal-branch carry boundary** — for `e ∈ {0, 5, -10}`, three constructions targeting the `rounded == 0x3FF` boundary at `f32_to_f16_bits:1563`. 9 cases.
4. **Normal-branch sticky-zero corner** — for `e ∈ {0, -5, 5}`, three f32 inputs with `frac & 0xFFF == 0` exactly to catch line 1553's `(frac ^ 0xFFF) != 0` mutations. 3 cases.

### Wiring

- Edge-case run path (None branch, no `--fuzz`) — appended after the existing `half_edge_cases_f32()` loop.
- Fuzz run path (Some(count) branch) — prepended as deterministic sweep before the random loop. Runs once per FPSCR mode regardless of fuzz count.

### Hidden V2 oracle issue surfaced

Reading the existing structure, I noticed: the V2 mutation runner uses `softfloat_diff --fuzz 2000` for execute_fpu.rs mutants. That invocation hits the **fuzz path only** — the existing `half_edge_cases_f32()` (which includes `65504.0`!) is NOT exercised by V2's runs. So a mutation killed by edge-case mode could survive V2 oracle replay because deep-pass also uses `--fuzz 2000`.

My Thread 1 patch fixes this by making the targeted cases run in BOTH paths. Pre-existing edge cases (`half_edge_cases_f32`) are still fuzz-mode-skipped, but the V3 Bucket 1 candidates are now covered. Deferred: a follow-up could extend fuzz mode to also run `half_edge_cases_f32()` once per fuzz invocation. Tech-debt note in V2 Triage HLD §11 update.

## Stage 2 — Thread 2: softfloat_diff op-coverage extension (complete)

Goal: convert the ~47 V3-Stream-B Bucket-4-by-oracle-routing mutants
in `execute_fpu.rs` into actually-tested ops. softfloat_diff didn't
exercise VABS / VNEG / VMINNM / VMAXNM / VCMP / VSEL / VCVT-to-int /
VCVT-from-int at all; this thread adds all of them.

### Two-part design

Per the V3.1 plan §4.2 (smallest-first ordering): VABS → VNEG →
VMINNM → VMAXNM → VCMP → VCVT-int → VSEL.

**Part 1** (`c07c315`): VABS, VNEG, VMINNM, VMAXNM, VCMP.
**Part 2** (`c1a5cbc`): VCVT-to-int family (6 variants) + VSEL (4 cc).

### Implementation choices

| Op | Encoder family | Reference shape | Notes |
|---|---|---|---|
| VABS / VNEG | `vfp_unary` (existing) at (0b0000, 1) / (0b0001, 0) | `(f32::abs(a), 0)` / `(-a, 0)` | Pure sign-bit; no FPSCR side effects, no DN/FZ. |
| VMINNM / VMAXNM | new `enc_vminnm` / `enc_vmaxnm` (0xFE prefix) | mirrors `fpu_minnum/maxnum` + IOC-on-SNaN from dispatch | New encoder family for the 0xFE Armv8-M extension. |
| VCMP / VCMPE | `vfp_unary` at (0b0100, t) | new `ref_vcmp` returns FPSCR.NZCV nibble | Output shape doesn't fit `run_single`. New `run_vcmp_one` runner; new `run_one` dispatcher. |
| VCVT.F32.U32 / VCVT.F32.S32 | `vfp_unary` (0b1000, t) | `as f32` cast | Operand bits read as integer. |
| VCVT-to-int family (4 ops) | `vfp_unary` (0b1100/0b1101, t) | mirrors `f32_to_u32_rmode/rtz` etc. | Result is u32/i32 reinterpreted as f32 bits. **Bypass NaN-equivalence** in `run_single` via new `Op::integer_result_bits()` flag — saturation values like `u32::MAX = 0xFFFFFFFF` decode as f32 NaN, would mask saturation-bit divergences otherwise. |
| VSEL (4 cc) | new `enc_vsel` (0xFE prefix) | new `ref_vsel(cc, n, z, v, sn, sm)` | Repurposes the FMA-accumulator `c` slot to carry APSR.NZCV bits via `f32::from_bits`. `is_vsel()` flag in `run_single` sets `emu.regs.xpsr` accordingly. Same NaN-bypass as VCVT-int. |
