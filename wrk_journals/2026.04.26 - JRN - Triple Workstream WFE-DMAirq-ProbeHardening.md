`wrk_docs/2026.04.26 - HLD - Probe Driver Hardening V1.md`.

Standout findings from the survey:

- **23:18 live patch already in tree.** The HLD agent caught that
  `M fuzz-runs/run-probe.sh` (in `git status` since 23:18 on 2026-04-25)
  added a 30s rc=2 back-off live during the cascade-2 incident. The new

  it.
- **Filter-driven skips do not contribute to `skip` counter.** Survey
  proved both binaries today: rp2350 has no filter; rp2040's filter is
  pre-loop. Means the existing in-loop `skip` counter is exactly the
  signal we want — no protocol change, no marker substring needed.

percent-of-attempted with ≥20 attempted floor.
- 08:51 incident at 76% → trips. ✓

  as a sign-off question.
- **Decision: keep 25%.** The 5-consecutive-cap (driver side) is the
  cascade defence. The percent threshold is just a per-batch quality
  signal. Trip cost = 60 s back-off; cap cost = bounded. 11% as a
  benign data-batch is acceptable.

**Sign-off decision:** APPROVED.

Build cadence is decoupled from live drivers per CLAUDE.md (drivers run
from pid-suffixed copies). Driver scripts staged as `.next` siblings;
