## Stage 0: Survey — Done

- **Bus (bus/mod.rs, 2.2KB):** Coarse 4-bit decode (addr>>28). ROM/SRAM/XIP routed; APB/AHB/SIO/PPB stubbed (return 0). Reads are `&self`, writes `&mut self`. No latency tracking.
- **Memory (memory/mod.rs, 4.5KB):** Flat 520KB SRAM, 32KB ROM, dynamic XIP. Little-endian. Bounds-checked (returns 0 OOB). No banking.
- **SIO (sio/mod.rs, 385B):** Spinlock array only, no ops.
- **Core (mod.rs, 4.4KB):** step() → decode_execute() → bus.readN(). stall_cycles model per HLD §6.4.
- **Call chain:** execute → bus.read32(addr) → match addr>>28 → memory.sram_read32(offset)

## Devil's Advocate Review

**Reviewer findings (severity-ranked):**

1. **[Critical] API design:** Change Bus reads to `&mut self` + `last_latency` field. Only 2 call sites break (`execute_one`/`execute_one_wide` in mod.rs:89-112 which create throwaway `Bus::default()`). All 245 instruction tests call these methods and won't see Bus signature changes.

2. **[Critical] Integration ordering:** Must wire latency into `decode_execute` return BEFORE implementing arbitration/atomics, otherwise those stages can't be tested end-to-end. **Acted on: moved integration to Stage 3.**

3. **[Important] SRAM striping: DA was wrong.** Claimed contiguous 64KB blocks (`bank = (offset >> 16) & 7`). HLD and test suite confirm word-striped (`bank = (word_offset) % 8`). Verified via codebase evidence.

4. **[Important] Arbitration scope:** Full 6x17 crossbar is overkill. Simplified to 2-master. **Acted on.**

5. **[Important] Atomic alias costs:** Native atomics (AHB) = no extra cost. Interposed atomics (APB: UART/SPI/I2C/SSI) = +2 cycles. Must distinguish in implementation. **Acted on.**

6. **[Minor] Fetch cycles:** Instruction fetches via bus.read16() will gain latency. Fine for Phase 2 (code runs from SRAM/ROM = 1 cycle). Documented assumption.
