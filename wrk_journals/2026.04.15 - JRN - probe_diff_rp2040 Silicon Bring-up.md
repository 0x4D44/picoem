## Stage 0 — HLD + journal start (2026-04-15)

### Context

Arthur connected a Pico V1 to a freshly-flashed CMSIS-DAP debugprobe and asked whether it was working. `probe-rs list` showed exactly one probe (`2e8a:000c:E46410955F3C5C27`); `probe-rs info --chip RP2040` confirmed multidrop TARGETIDs `0x01002927` / `0x11002927` and CPUID `0x410cc601` → Cortex-M0+ r0p1. Silicon is live.

Key finding during HLD drafting: `probe_diff_rp2040.rs` is **not** the stub CLAUDE.md and tech_debt.md describe — it was fully implemented in commit `529886b` ("RP2040 Phase 0 Wave 3", 2026-04-15). Filter (`is_m0plus_silicon_safe`), probe attach, single-step, semantic compare — all wired. What it has never done is execute against real silicon.

So the HLD scope collapsed from "design" to "bring-up". Runner already exists; what's missing is:

1. Probe disambiguation (`--probe <selector>`) so two probes can coexist on one host.
2. A post-step PC sanity check, so any `is_m0plus_silicon_safe` filter gap surfaces as a distinct `UNDEF_ON_SILICON` diagnostic rather than a mystery register divergence.
3. Actually running the thing against silicon and triaging what breaks.
4. Overnight fuzz driver + doc updates.

Confirmed probe-rs 0.31 APIs before committing to the design:

- `DebugProbeSelector` with `FromStr` via `TryFrom<&str>` at `probe-rs-0.31/src/probe.rs:911/990/1031`.
- `Lister::open(&selector)` at `probe-rs-0.31/src/probe/list.rs:31`.
- `Probe::attach(target, permissions)` at `probe-rs-0.31/src/probe.rs:328`.
- **Confirmed auto_attach first-probe-only bug**: `probe-rs-0.31/src/session.rs:446–458` uses `Lister::new().list_all()` and opens `probes.first()` with no target-aware fallback. This is the root cause of the disambiguation problem.

### Decisions locked in

- **`--probe` is a CLI flag, not an env var and not auto-detect by TARGETID.** Explicit, scoped, no magic. Consistent with probe-rs's own CLI.
- **Post-step PC sanity check is diagnostic, not behavioural** — doesn't change pass/fail, just classifies the failure mode. Keeps silicon HardFault escapes from being mystifying.
- **Filter duplication with `qemu_diff_m0plus` acknowledged as debt, deferred.** Collapsing `is_m0plus_safe` + `is_m0plus_silicon_safe` into one filter with a mode enum is out of scope; the ~80 lines of duplication is tolerable.
- **Scope strictly `probe_diff_{rp2040,rp2350}`.** Other silicon binaries stay on `auto_attach` until their own bring-up waves land.

## Stage 1 — `--probe` flag + UNDEF diagnostic (2026-04-15)

### Deliverables shipped

- `--probe <VID:PID:SERIAL>` CLI flag on both `probe_diff_rp2040.rs` and `probe_diff_rp2350.rs`. When supplied, attach via `Lister::new().open(&selector)?.attach(target, Permissions::default())?`; when absent, keep the existing `Session::auto_attach` path verbatim.
- `UndefOnSilicon { pc: u32 }` diagnostic on `probe_diff_rp2040.rs` only — classifies post-step PC into bootrom (`< 0x0000_4000`) as a distinct failure class, leaving the `[FAIL]`/`[SKIP]` classes for their existing meanings.
- 11 new unit tests across both binaries (arg-parse + PC classification + BL target regression test).
- `mdpicoem-harness` crate bumped `0.23.0 → 0.24.0` (minor — new feature).

### The devil's-advocate catch

First pass by the implementer keyed the UNDEF check off `pc == EMU_M0PLUS_TEST_SLOT + insn_len` (the BKPT sentinel address). The `code-reviewer` agent said READY_TO_COMMIT. The devil's-advocate agent caught a **real latent bug**: the filter admits BL, B, Bcond, BX/BLX, and POP-with-PC, none of which land at the BKPT. On silicon every admitted branch would have false-triggered `[UNDEF]` and caused `run_targeted` to exit 1 on the first run. The register-level `compare_probe` would have passed on those cases — silicon and emu both branch to the same target — so the UNDEF class was over-eager.

Fix: reframe the check. The HLD's actual intent was to catch silicon HardFault → VTOR=0 → dispatch into bootrom. Classify UNDEF only when silicon PC falls inside bootrom (`< 0x0000_4000` on RP2040), leaving every other post-step PC (BKPT sentinel, branch target, garbage) to the existing register comparison. Five-line fix, plus test-suite revision (removed 3 stale tests, added 5 new ones including a dedicated BL-target regression test).

Lesson: two reviewers disagreed. Trust the spec-reader, not the diff-reader. The HLD needs updating to record the corrected classifier semantics — do as part of Stage 4 alongside CLAUDE.md.
