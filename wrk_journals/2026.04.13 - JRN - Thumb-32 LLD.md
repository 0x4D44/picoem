# 2026.04.13 — Journal — Thumb-32 LLD Design Session

## Goal
Draft a low-level design for the Thumb-32 instruction decoder/executor.
Key concerns: cycle accuracy, complete coverage, performance (33 host cycles budget).

## Approach
Agent team:
- **Encoding agent**: Map the complete Thumb-32 encoding tree from ARM ARM / RP2350 datasheet
- **Cycle timing agent**: Research Cortex-M33 instruction cycle counts from available sources
- **Devil's advocate**: Question assumptions, find gaps, challenge the design

## Key Findings

### Encoding agent
- Complete Thumb-32 encoding tree mapped: ~150 base opcodes across 10 instruction groups
- ThumbExpandImm algorithm documented (12-bit → 32-bit with carry-out)
- 5 addressing modes for load/store single
- Priority list: Tier 1 (MOVW/MOVT, LDR.W/STR.W, ADD.W/SUB.W, B.W, BL) covers >80% of compiler output
- ARMv8-M additions: Load-Acquire/Store-Release, TrustZone instructions

### Cycle timing agent
- **ARM does NOT publish M33 cycle counts** (confirmed by ST Community, ARM forums)
- Best-estimate table assembled from M4 TRM, Aioanei thesis (Radboud 2025), Curve25519 paper
- Key finding: M33 may have eliminated 1-cycle setup for LDM/STM (N cycles instead of 1+N)
- Load-use interlock confirmed: 1-cycle stall when LDR result used immediately
- I-bus/D-bus overlap: consecutive LDR pipeline to ~1 effective cycle each
- SDIV/UDIV: 2-11 cycles data-dependent (M33 is 1 cycle better worst-case than M4)
- Write buffer absorbs stores: STR costs 1 cycle to pipeline

### Devil's advocate — critical issues found
1. **BLOCKING**: No IT block state machine — must design before any Thumb-32 work
2. **IMPORTANT**: SP banking not implemented (MSP/PSP swap on CONTROL.SPSEL)
3. **IMPORTANT**: Bus faults silently swallowed — blocks bootrom
4. **IMPORTANT**: execute.rs won't scale as single file (~3200 lines)
5. **IMPORTANT**: stall_cycles model too simple for SDIV/UDIV (data-dependent)
6. **IMPORTANT**: ThumbExpandImm design needed (hot path, ~40% of Thumb-32)
7. **IMPORTANT**: T-bit not enforced on BX
8. **IMPORTANT**: Missing bootrom prerequisites (exceptions, PPB, SIO, coprocessors)

### Cross-cutting insight
The devil's advocate correctly identified that IT blocks are not "another instruction" but a
fundamental change to the decode loop. This must be in place before Thumb-32 implementation
or we'll build on an incorrect foundation.

## Decisions Made
- Write full LLD document covering all findings
- Address blocking items (IT blocks, SP banking, bus fault API, file split) as prerequisites
- Use M4 cycle counts as starting estimates, with explicit confidence levels
- Validate against real hardware via DWT CYCCNT (Layer 3 testing) once available
