# 2026.04.13 - Journal - Probe-rs Hardware Test Harness LLD

## Goal
Write LLD for real-hardware test harness using probe-rs over SWD to an
RP2354 (OneROM) target. Two modes: halt-step (semantic diff) and firmware
mailbox (cycle counting).

## Hardware Setup (verified working)
- Probe: Pico H (RP2040) with debugprobe_on_pico firmware
- Target: OneROM (RP2354, Cortex-M33)
- Connection: GP2→SWCLK, GP3→SWDIO, GND→GND (J2 header)
- probe-rs 0.31.0 sees both M33 cores + DWT

## Approach
Research agents → draft → devil's advocate → iterate.

## Progress

### 14:30 - Research complete, LLD V1 drafted

Key findings:
- probe-rs 0.31 has clean Rust API: halt, write_core_reg, step, read_core_reg
- DWT CYCCNT doesn't tick when halted, counts during single-step
- Same address space (0x20000000) eliminates translation complexity
- No firmware needed for Phase A — pure SWD halt-step
- SRAM accessible from power-on without bootrom initialization

### 14:45 - Devil's advocate review, V1.1 patched

Fixes applied:
1. Documented SRAM always-on accessibility (Section 5)
2. Include T bit (bit 24) in probe xPSR mask (Section 6.3)
3. Calibrate DWT with NOP + ADDS + MUL, not just NOP (Section 8)
4. Corrected speed estimates: ~20-25ms/test, not 10-15ms (Section 9.2)
