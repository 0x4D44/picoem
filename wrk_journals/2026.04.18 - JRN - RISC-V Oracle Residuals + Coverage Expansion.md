## Task 1: Residual edge-case FAILs

### Known failure categories (from pre-commit snapshot)

- `upper_lui_*`, `upper_auipc_*`, `rv32m_*`: **pre-test mtvec drift** — QEMU=0x00000000 vs emu=0x80000200. The proxy prelude reseeds mtvec before the snapshot, but edge cases that don't go through that path see drift. Prime suspect: CSR_RESET or ordering.
- `branch_beq_far_neg`, `branch_jal_far_neg`: x6 off-by-1 (QEMU=0x2 emu=0x1). Real semantic diff — likely branch-not-taken fall-through accounting.
- `upper_auipc_addi_pair`: x5 differs by 0x10. `upper_auipc_jalr_pair`: x1 expected link = 0 vs emu=0x80000158. Both suggest layout/offset interaction with the longer proxy prelude.
- `branch_jalr_*`, `branch_beq_neg_off`, `branch_beq_far`, `branch_jal_near_neg`, `branch_jal_far_pos`, `branch_jalr_off0`, `branch_jalr_rdx0`, `upper_lui_zero`: QEMU vCont;c / memory-read **connection timeouts**. Likely network flakes but should still be treated as bugs worth investigating — a properly-behaved oracle should not time out.

### Agent 1 outcome

**Result: 0/205 edge-case FAIL, fuzz regression 2000/2000 PASS.**

Root causes found (not just patched):

1. **QEMU stale HW breakpoints** — QEMU's rv32 virt GDB stub replies `"OK"` to `z1,addr,kind` but retains the breakpoint. Stale bp from prior test fired on next test's `vCont;c`, halting one instruction early. Explained `upper_auipc_*_pair` x5/x1 diffs and all `csrside_*` layout failures. Fix: `hw_bps` tracking + `clear_all_hw_breakpoints` in `gdb_client.rs`, flushed per-test.
2. **mstatus MPP WARL divergence** — Hazard3 forces MPP=0b11 (M-only); QEMU virt has M+S+U and keeps MPP=0b00. `csr_rd_hint` masked immediate rd but not derived regs (x7 in `csrside_mstatus_use_old`). Fix: seed mstatus=0x1800 on both sides in the prelude (3 instrs, +12B shift of `test_start`).
3. **Lingering SELFCHECK_STUB code** — `branch_jalr_*` and `upper_lui_zero` timed out because JALR targets landed on the self-check stub's `csrrw mtvec, x0` instruction, which zeroed mtvec. Subsequent trap then went to mtvec=0 → unmapped → infinite trap loop. This was the single root cause behind BOTH the `upper_lui_*` / `rv32m_*` pre-mtvec-drift cluster AND the JALR timeout cluster — hypothesis confirmed. Fix: zero out SELFCHECK_STUB/INIT_SLOT regions after one-shot use.
4. **Branch targets landing in prelude/unmapped memory** — `branch_beq_neg_off`, `branch_jal_near_neg` looped because `-8` offset landed in proxy prelude CSR-reads; `branch_*_far*` landed in uninitialized memory with platform-divergent mcause. Fix: NOP sled for forward, planted ebreak for backward; large-offset `branch_*_far*` + JALR-off cases dropped (see risks).
5. **`step_emu_until_pc` ebreak halt** — stopped at planted ebreak inside test body while QEMU trapped through mtvec. Fix: `step_emu_until_pc_pair(target, alt_target)`.
6. **`rvc_c_jr_x1`/`c_jalr_x1` unmapped target** — pre-seed x1 to TRAP_STUB+16.
