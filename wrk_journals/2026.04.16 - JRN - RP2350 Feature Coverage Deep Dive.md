# 2026.04.16 — JRN — RP2350 Feature Coverage Deep Dive

## Goal

Compare the mdrp2350 emulator implementation against the RP2350 datasheet. Produce a
comprehensive supported-features / gap list, with a devil's-advocate critique of the
analysis itself. Final artifact lives in `wrk_docs/` as an HLD-style markdown.

## Team plan

Five parallel agents, one-shot research (read-only, no code edits):

1. **CPU/ISA agent** — Cortex-M33 + ARMv8-M baseline/mainline, FPU (VFPv5-SP),
   coprocessors (DCP CP4/5, RCP CP7, GPIO CP0), security extensions (TrustZone),
   MPU/SAU, exceptions/NVIC/SysTick, DWT.
2. **Bus/memory/clocks agent** — AHB fabric, APB bridge, bus priorities, address
   map, SRAM banking (striped + scratch), XIP + QSPI, ROM, clock tree (XOSC, ROSC,
   PLL_SYS, PLL_USB, dividers, gate model), RESETS block, watchdog, tick generators.
3. **Peripherals agent** — PIO (3 blocks on RP2350), SIO (GPIO, FIFO, spinlocks,
   interp, divider, DoubleSpinlock, RISC-V semantics on M33), DMA (12 channels,
   DREQs, CRC sniffer, timers), Timer (4 alarms × 2 timers), PWM, UART, I2C, SPI,
   ADC (single on RP2350 vs 4 on RP2040), USB, HSTX, TRNG, OTP, PSRAM, PWRMAN,
   GLITCH_DETECTOR, BOOTRAM, TBMAN, coresight, SysInfo, syscfg.
4. **Security/boot/NS agent** — Secure vs Non-Secure world, SAU, IDAU, MPU (banked
   secure/non-secure), boot ROM flow, signed boot, OTP keys, glitch detector,
   PSA/Mbed TLS integration, debug authentication, RISC-V cores (dual Hazard3
   alternative), chip-select register, arch-specific resets.
5. **Devil's advocate** — looks at the other four agents' outputs; challenges
   assumptions (e.g., "is cycle accuracy actually delivered?", "is 'pio support'
   claimed but gated by what it actually runs?"), spots gaps in the methodology
   itself, checks whether tests actually exercise what's claimed.

Agents 1–4 run in parallel as **Explore** subagents (read-only, thorough). Devil's
advocate runs **after** them so it can critique concrete output rather than priors.

## Risks / watchouts
- Claims like "PIO supported" need to be cross-checked against what the harness
  actually exercises (silicon_periph_diff, silicon_cycle_oracle) — test coverage
  is the ground truth, not module existence.
- Bus contention on RP2350 is *intentionally not modelled* (per CLAUDE.md) — flag
  that as a deliberate gap, not a bug.
- Pacer is x86_64-gated — feature-flagged limitations count as gaps.
- Cycle accuracy is load-bearing for the project's value prop; if the silicon
  cycle oracle shows systematic deltas, that's the real headline.

## Open questions for devil's advocate round
- Does "supported" mean "register-plumbed", "functionally stubbed", or "differentially
  verified against silicon"? Those are three different things and should be
  separated in the final artifact.
- What's not covered *at all* that we haven't even been tracking? (E.g., the RISC-V
  Hazard3 cores are an official RP2350 dual-ISA feature — do we have any of that?)
- Are we claiming boot ROM support but only running trivial firmware?

## 22:35 — Research agents returned

Four-way audit complete. Consolidated headline findings (full text in my working
memory; will surface in the HLD):

**CPU/ISA (Agent 1).** Thumb-16 essentially complete + QEMU-verified. Thumb-32
covers the mainline subset the fuzzer generates (`gen_t32_multiply_divide` and
a couple of others are commented out — so MUL/DIV, mod-imm DP, load/store-single
classes have implementations that never see QEMU fuzz). VFPv5-SP + lazy FP save
+ FPCCR flags verified via QEMU and silicon ISR oracle. CP0/4/5/7 coprocessors
present; DCP + RCP are **unit-tested only** (no silicon or QEMU diff for CDP
ops). Exception model + tail-chain silicon-verified. **Real gaps: MPU / SAU /
IDAU are register-plumbed but never enforce — TT instructions return hardcoded
"always allow"; no SecureFault class; BLXNS + FNC_RETURN + NSC missing; TT/TTA
decoded-but-stubbed.** ETM / ITM / PMU absent. No RISC-V at all.

**Bus/memory/clocks (Agent 2).** Address map, SRAM striping, RESETS (29-bit
mask), clock tree + glitchless mux, PPB NVIC with 52 IRQ lines + SysTick + DWT
all silicon-verified. QMI register bank is present; XIP cache 16 KB window
handled. **Gaps: BUSCTRL.BUS_PRIORITY ignored, APB arbitration simplified
(read=3/write=4 cycle flat), per-peripheral clock-gate enable bits stored but
not consulted, PSRAM aperture not modelled (breaks PicoGUS), ACCESSCTRL not
decoded at all, EPPB not in map.** Contention is *deliberately* omitted on
RP2350 per the declined-modelling journal — flag as policy, not bug.

**Peripherals (Agent 3).** Count confirmations match datasheet: **3 PIO, 16
DMA, 2 TIMERs, 12 PWM slices, 48 GPIOs** — all per-RP2350. Differentially
verified: PIO0-2, TIMER0/1, TICKS (with one known-broken alias at 0x81C
dropping writes), UART0, SPI0, I2C0, ADC, PWM, DMA, SIO, CLOCKS, PLL_SYS/USB,
IO_BANK0, PADS_BANK0. **Unit-tested only:** spinlocks, doorbells, RISCV_SOFTIRQ
(ironic, see below), interpolators (plain storage, no clamp/blend). **Stubbed:**
UART1 / SPI1 / I2C1 register ranges fall through HashMap, DMA_IRQ_2/3 not on
NVIC, DMA CRC sniffer / byte-swap / HIGH_PRIORITY all stored-but-inert, PWM
DREQs declared but never emitted. **Missing entirely (15 items):** USB, HSTX,
SHA-256, TRNG, GLITCH_DETECTOR, OTP, POWMAN, PSM, CORESIGHT_TRACE, TBMAN,
TMDS, SYSCFG, WATCHDOG, ACCESSCTRL, and QMI streaming/PSRAM path.

**Security/boot/RISC-V (Agent 4).** BXNS / SG / IDAU region mapper / banked
S-NS register pairs / CPACR enforcement / DCP / RCP / DWT CYCCNT implemented +
verified. **SAU storage only, MPU TT-query only (no data-access gate), no
SecureFault, no BLXNS/FNC_RETURN, EXC_RETURN S/NS bit hardcoded, no NSACR,
CPPWR, CPACR_NS, no NSC attribute, no BASEPRI preemption check.** Boot ROM
not *executed* — `load_bootrom` stuffs a prebuilt binary at 0x0. **RISC-V
Hazard3: zero bytes of implementation.** No ARCHSEL, no CPU model, no CSRs.
This is half the RP2350 chip architecture.

## Common themes across the four reports
1. **"Plumbed" ≫ "enforced".** SAU, MPU, ACCESSCTRL, BASEPRI, per-peripheral
   clock gates — all stored, none checked. Firmware that *relies* on these for
   correctness will pass our emulator silently and fail on silicon (or vice
   versa, silently succeed on silicon and break here).
2. **Differential verification coverage is uneven.** CPU + ISR + cycle oracles
   exist and pass; peripheral oracle exists with ~15 scenarios. DCP/RCP and all
   coprocessor CDPs have no differential oracle at all.
3. **No RISC-V.** Declared out of scope but the audit shouldn't bury it — it's
   load-bearing for any claim of "RP2350 emulator coverage".
4. **Boot ROM stubbed.** We load a canned image; we don't run the ROM. So
   everything downstream of real-ROM behaviour (secure boot chain, image A/B,
   rollback, RISC-V archsel) is uncoverable without that.
