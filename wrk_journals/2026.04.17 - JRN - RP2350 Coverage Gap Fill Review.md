# 2026.04.17 — JRN — RP2350 Coverage Gap Fill HLD Review

## Goal

Review the V1 design (`2026.04.17 - HLD - RP2350 Coverage Gap Fill V1.md`) with a
multi-perspective agent team, iterate until no critical issues remain, save
each version to disk.

## Team composition

- **Silicon-fidelity reviewer** — datasheet-accuracy lens
- **Rust/codebase idiom reviewer** — consistency with existing mdrp2350 patterns
- **Testing reviewer** — implementability of the tests specified
- **Simplicity reviewer** — guards against overengineering per CLAUDE.md
- **Devil's advocate** — spots implicit assumptions, missed scope

Rounds 2 and 3 used combined reviewers (fewer heads as findings converged), but
the devil's advocate was always present and always had the final say on
readiness.

## Round 1 — V1 → V2

Five agents reviewed V1 in parallel. Headline findings:

- **Rust reviewer** caught that V1's `last_fetch_pc` field on Bus doesn't
  exist — inventing cross-module plumbing.
- **Testing reviewer** caught that V1's warn-test address `0x4010_0000` is
  TICKS base (modelled) — the test was never going to fire a warn. Corrected
  to `0x400F_8000` (SHA-256).
- **Testing reviewer** caught that WATCHDOG reset scenario is structurally
  impossible as an end-state silicon oracle (the reset event halts the
  oracle). Split into unit-tested reset + non-firing silicon scenario.
- **Testing reviewer** caught that interpolator POP-reads mutate ACCUM —
  end-state oracle can't sample them correctly.
- **Simplicity reviewer** pushed to cut `rand_chacha`, the six pre-calibrated
  silicon interp scenarios, the per-module SYSCFG/TBMAN/GLITCH_DETECTOR
  files, and the OTP fuse-load builder.
- **Devil's advocate** flagged the biggest miss: V1 did not address the
  audit's systemic "plumbed but not enforced" finding for modelled
  peripherals. Six inert-register convention sites added to V2.

Tie-breaks I made as supervisor:
- HashSet (not counter) for warned addrs — simpler semantics.
- `[Uart; 2]` over `uart0, uart1` — explicit construction list + flat match
  stay readable.
- Datasheet unit tests over silicon scenarios for interp — silicon
  calibration is a blocking process step, not a design choice.
- Targeted convention (six sites) over warn-framework — framework is scope
  creep.

Devil's advocate argued V1 "solves the wrong problem at the wrong scale" —
rejected as out-of-scope for the finite bucket; structural items
(security enforcement, cycle model, RISC-V, bootrom) have their own HLDs.

## Round 2 — V2 → V3

Three teams (silicon+Rust, testing+simplicity, devil's advocate). Two of
three said "ready to implement"; devil's advocate said "ready with
reservations" and prosecuted ten concrete improvements. None were
architectural blockers — all were tightenings.

Folded into V3:
- §4.A2 list expanded to cover audit §5 in full: clock-gate enables,
  BUSCTRL.BUS_PRIORITY, POWMAN AON MATCH.
- §4.A1 clarifications: per-`Bus` HashSet lifetime, single-threaded
  concurrency note (no Sync needed).
- §4.A1 / §4.A2 unit-test pattern: "write twice, expect one warn".
- §5.B.4 eight named test vectors (SHIFT, SHIFT+MASK, SIGNED, CROSS_INPUT,
  ADD_RAW, BLEND, CLAMP, CROSS_RESULT) with specific expected values.
- §7.D.3 watchdog minimum cycles to fire (≤130 at LOAD=100).
- §2 accurate HLD cross-references: cycle and RISC-V HLDs exist;
  bootrom and security-enforcement do not.
- §9 amendment gate for datasheet surprises.
- §10 step 3 split into 3a/3b for bisect discipline.
- §10 effort estimate (~2–3 weeks solo, 3–4 weeks serial).

Held against pushback (documented in §14):
- Full AON timer impl — held at storage + MATCH warn.
- Warn-noise → debug level — held at warn; landing window is transient.
- Interp silicon scenarios now — held; unit tests are first gate.

## Round 3 — V3 → V4 (final)

Two teams (combined silicon+testing+simplicity, devil's advocate).

**Devil's advocate said GO unconditionally.** Sign off, proceed to step 1.
All three round-2 held-against items deemed defensible. One observation:
test 6 implementation will be more than 10 lines (not a blocker).

**Combined reviewer said CONDITIONAL YES.** Three polish items:
1. AON `COUNT` write should also warn, for symmetry with MATCH (silent hang
   otherwise if firmware polls COUNT).
2. BLEND ACCUM1 scaling is ambiguous in V3 — pin as Q0.32 so test 6's
   expected value of 150 is deterministic.
3. §1 line 16 misclassifies interp CTRL registers as "inert" — they are
   modelled via Part B, not warn-gated. Wording fix.

All three applied in V4. No architectural changes. No red flags.

**Convergence declared.** V4 is the implementation-ready version.

## What the final design says, in one paragraph

Add a per-`Bus` HashSet that warns-once on unmodelled MMIO fallthrough. Fix
the TICKS `0x81C` alias bug. Implement interpolator CTRL semantics with
eight datasheet-derived unit tests. Reshape UART/SPI/I2C to `[_; 2]` arrays
so UART1/SPI1/I2C1 work. Add simple storage-centric models for SYSCFG,
TBMAN, GLITCH_DETECTOR, PSM, WATCHDOG (with reset plumbing), OTP (OR-only),
TRNG (counter), SHA-256 (`sha2` crate). POWMAN storage-only with warns on
ARCHSEL/MATCH/COUNT. CORESIGHT_TRACE storage-only. Add targeted warn-once
convention at ten sites inside modelled peripherals (DMA BSWAP / CRC / PRIO,
PWM DREQ, ARCHSEL, AON MATCH/COUNT, CLOCKS gates, BUSCTRL priority). Five
commits, ~2–3 weeks solo. Ten entries on a datasheet verification checklist
front-loaded before coding each row.

## Explicitly out of scope (their own HLDs or declared deferred)

- Security enforcement (SAU/MPU/ACCESSCTRL gating accesses) — no HLD.
- Bootrom execution — no HLD.
- Cycle-model reconciliation — `2026.04.14` and `2026.04.16` HLDs hold it.
- RISC-V Hazard3 — `2026.04.17 - HLD - RP2350 RISC-V Hazard3 Core Support.md`.
- USB, HSTX, TMDS — engineering-week-scale; own HLDs needed.

## Lessons learned

1. **Rotating reviewers keep the bar high.** The devil's advocate was the
   only reviewer present in all three rounds. That continuity drove the
   agenda: its round-1 "plumbed ≠ enforced" push forced §4.A2 into V2, and
   its round-2 audit-§5-completeness push forced the V3 expansion. The
   other lenses rotated in to catch different issues.
2. **Fail-verify load-bearing critique before citing.** Round 1's devil's
   advocate claimed BASEPRI was stored as 8 bits without the 3-bit
   priority-compare mask. Spot-verified — the code was correct. Dropping
   the charge from the upstream audit doc avoided publishing a fabricated
   finding.
3. **Convergence is a threshold, not a perfection bar.** Round 3 had two
   reviewers say GO with three polish items. Applying the polish and
   stopping was the right call; round 4 would have been ceremony.
4. **Simplicity reviewer is worth its weight in cut scope.** Round 1's
   simplicity pass killed the `last_fetch_pc` plumbing, the `rand_chacha`
   dependency, the OTP fuse-load builder, and six pre-calibrated silicon
   scenarios. Each of those would have been a week of work landing a
   wrong-for-the-problem design.
