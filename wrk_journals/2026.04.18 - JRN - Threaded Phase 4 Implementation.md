## Pre-Stage-A audit (HLD §7)

Grepped the test suite for DMA references:

- `crates/mdrp2350/src/dma.rs` — 24 inline unit tests. All use
  serial `Bus`, not `ThreadedEmulator`. Exercised via the serial
  tick path, not affected by threaded Stage A.
- `crates/mdpicoem-harness/src/silicon_scenarios.rs` — hardware
  oracle scenarios (probe_diff, periph_diff). Not threaded-mode
  tests.
- `threaded/emulator.rs` — 24 `ThreadedEmulator::from_emulator`
  call sites, all Phase-3 worker-mechanics tests. None exercise
  DMA.

Conclusion: **no tests need gating for Stage A**. The §7 audit
concern is forward-looking — post-Phase-4 tests that use
`ThreadedEmulator` must not assume DMA progress until Phase 5.

## Stage A

`tick_peripherals` at `crates/mdrp2350/src/threaded/emulator.rs:672`
replaces the Phase-3 no-op stub. Ports `Bus::tick_peripherals`
(`bus/mod.rs:915-967`) excluding DMA (§2.2 defers to Phase 5).

- Signature narrowed `u64 → u32` per §3.1. Coord body caller now
  passes `step_q` directly (no `as u64`).
- Steps 1–3 (TICKS / TIMER0 / TIMER1) under a single `timers`
  Mutex acquire; step 4 (UART0/SPI0/I2C0/ADC/PWM) under a single
  `apb` Mutex acquire. Gating via `resets_state` snapshot (§3.2):
  one lock, stack-local `u32`, `held(bit)` closure over it at
  each call site.
- Clock-tree snapshot via `clocks.lock().unwrap().clock_tree`
  (Copy, outlives Mutex release) per §3.4.
- IRQ dispatch tail: `ext_irqs & PERIPH_IRQ_MASK` →
  `trailing_zeros` / `assert_irq_shared` / `mask &= mask - 1`
  per §3.3.
- Version: `mdrp2350` `1.3.0 → 1.4.0` (semver minor —
  threaded-mode peripheral tick becomes functional).

### Review outcomes

- **code-reviewer** (parity + style): zero blockers. Noted that
  `paced_bench_rp2350.rs` changes in the working tree are pre-
  Phase-4 (not part of Stage A scope) — kept separate from this
  commit. Approved the `held(bit)` local closure as an inline
  binding, not a helper per §3.2.
- **devil's advocate** (adversarial): flagged one critical gap —
  zero existing threaded tests exercised the new path. "1014
  tests pass" was misleading because none fired TIMER0 through
  `tick_peripherals`. Addressed below. Other findings (RESETS
  snapshot latency under Stage C, clocks-write vs tick-snapshot
  race, poisoned-Mutex debuggability) are either already
  accepted per HLD §3.1/§5.2/§5.4 or paranoid; journal-only.

### Test added

`tick_peripherals_fires_timer0_alarm0_shared_irq`
(`threaded/emulator.rs:830`). Programs TIMER0 via serial MMIO
before handoff (TICKS.TIMER0 domain enable, `INTE=1`,
`ALARM0=5`), halts both cores, runs 2 quanta (≈10 µs at
`step_quantum=64`), asserts `shared.atomics.irq_pending_load(c)
& (1 << IRQ_TIMER0_IRQ_0) != 0` on both cores.

### Test result

`cargo test -p mdrp2350 --lib` — 1015 passed, 0 failed
(previously 1014). No regressions. `cargo build -p mdrp2350
--release` warning-free.

### Journal notes (non-blocking)

- RESETS snapshot drift: under Stage C, a CPU-worker mid-quantum
  RESETS write is observed by coord next quantum. Adds up to one
  further step_quantum of latency on top of the 2× Stage-C
  ceiling. Accepted per §3.1 / §5.2.
- Poisoned Mutex unwrap on `timers`/`apb`/`resets`: root cause
  appears in the panicking worker's stderr per panic hook, not
  the aggregator. Matches §5.4's accepted trade-off.
- `raise_irqs_u64` applies `PERIPH_IRQ_MASK`; serial
  `raise_timer_irqs` does not. TIMER alarms are bits 0–7 —
  always in range — so no observable divergence. Threaded uses
  `PERIPH_IRQ_MASK` per §3.3.
