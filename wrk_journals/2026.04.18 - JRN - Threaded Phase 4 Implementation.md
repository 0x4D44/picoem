# Threaded Dual-Core Phase 4 — Implementation Journal

Date: 2026-04-18
Spec: `wrk_docs/2026.04.18 - HLD - Threaded Dual-Core Phase 4 V7.md`
Branch: `worktree-threading-phase0`

Three-stage execution:

- Stage A — `tick_peripherals` migration (ex-DMA), IRQ dispatch,
  clock-tree snapshot. Fills the Phase-3 stub at
  `crates/mdrp2350/src/threaded/emulator.rs:672`.
- Stage B — per-core `tick_systick` in CPU worker phase-1;
  `update_gpio` first in coord phase-2; `ThreadedPio::pads` snapshot
  + `from_emulator` seed.
- Stage C — collapse two-barrier rendezvous to single barrier.

Each stage: implementation agent + code-reviewer + devil's advocate
→ apply feedback → commit → journal entry.

## Stage A

`tick_peripherals` at `crates/mdrp2350/src/threaded/emulator.rs:672`
replaces the Phase-3 no-op stub. Ports `Bus::tick_peripherals`
(`bus/mod.rs:915-967`) excluding DMA (§2.2 defers to Phase 5).

- Signature narrowed `u64 → u32` per §3.1. Coord body caller now
  passes `step_q` directly (no `as u64`).
- Steps 1–3 (TICKS / TIMER0 / TIMER1) under a single `timers`
  Mutex acquire; step 4 (UART0/SPI0/I2C0/ADC/PWM) under a single
  `apb` Mutex acquire. Gating via `resets_state` snapshot (§3.2):
  one lock, stack-local `u32`, `held(bit)` closure over it at
  each call site.
- Clock-tree snapshot via `clocks.lock().unwrap().clock_tree`
  (Copy, outlives Mutex release) per §3.4.
- IRQ dispatch tail: `ext_irqs & PERIPH_IRQ_MASK` →
  `trailing_zeros` / `assert_irq_shared` / `mask &= mask - 1`
  per §3.3.
- Version: `mdrp2350` `1.3.0 → 1.4.0` (semver minor —
  threaded-mode peripheral tick becomes functional).

### Review outcomes

- **code-reviewer** (parity + style): zero blockers. Noted that
  `paced_bench_rp2350.rs` changes in the working tree are pre-
  Phase-4 (not part of Stage A scope) — kept separate from this
  commit. Approved the `held(bit)` local closure as an inline
  binding, not a helper per §3.2.
- **devil's advocate** (adversarial): flagged one critical gap —
  zero existing threaded tests exercised the new path. "1014
  tests pass" was misleading because none fired TIMER0 through
  `tick_peripherals`. Addressed below. Other findings (RESETS
  snapshot latency under Stage C, clocks-write vs tick-snapshot
  race, poisoned-Mutex debuggability) are either already
  accepted per HLD §3.1/§5.2/§5.4 or paranoid; journal-only.

### Test added

`tick_peripherals_fires_timer0_alarm0_shared_irq`
(`threaded/emulator.rs:830`). Programs TIMER0 via serial MMIO
before handoff (TICKS.TIMER0 domain enable, `INTE=1`,
`ALARM0=5`), halts both cores, runs 2 quanta (≈10 µs at
`step_quantum=64`), asserts `shared.atomics.irq_pending_load(c)
& (1 << IRQ_TIMER0_IRQ_0) != 0` on both cores.

### Test result

`cargo test -p mdrp2350 --lib` — 1015 passed, 0 failed
(previously 1014). No regressions. `cargo build -p mdrp2350
--release` warning-free.

### Journal notes (non-blocking)

- RESETS snapshot drift: under Stage C, a CPU-worker mid-quantum
  RESETS write is observed by coord next quantum. Adds up to one
  further step_quantum of latency on top of the 2× Stage-C
  ceiling. Accepted per §3.1 / §5.2.
- Poisoned Mutex unwrap on `timers`/`apb`/`resets`: root cause
  appears in the panicking worker's stderr per panic hook, not
  the aggregator. Matches §5.4's accepted trade-off.
- `raise_irqs_u64` applies `PERIPH_IRQ_MASK`; serial
  `raise_timer_irqs` does not. TIMER alarms are bits 0–7 —
  always in range — so no observable divergence. Threaded uses
  `PERIPH_IRQ_MASK` per §3.3.

## Stage B

Three pieces per V7 §4:

- `tick_systick` at CPU worker phase-1 tail
  (`threaded/emulator.rs:513`): `core.ppb.systick_advance(core.cycles())`
  between the per-quantum while-loop and `barrier.wait()`. Halted
  cores produce zero delta, matching serial.
- `update_gpio` first in coord phase-2
  (`threaded/emulator.rs:671` call, `:689-701` body). Sequence:
  `update_gpio` → `master_cycle.fetch_add(Release)` → `mtime_advance`
  → `tick_peripherals` → barrier-B-wait. Merge ports serial
  `Emulator::update_gpio` (`lib.rs:406-415`):
  `merged = read_out(0) & read_oe(0)`, fold blocks 0..2 with
  `(merged & !pad_oe) | (pad_out & pad_oe)`, then external overlay
  last. Bank 0 only per §2.2.
- `ThreadedPio::pads` (`threaded/pio.rs:48`): `[AtomicU64; 3]`
  packed high32=pad_out, low32=pad_oe, Release/Acquire. PIO worker
  publishes all three blocks each phase-1 tail
  (`emulator.rs:574-577`). Handoff seed in `from_emulator`
  (`emulator.rs:255-260`) carries live `PioBlock.pad_out`/`pad_oe`
  into `pads` before any worker spawns.

### Review outcomes

- **code-reviewer**: zero blockers. Two nits (hardcoded `0..3` vs
  `PIO_BLOCKS` constant; handoff-seed comment could be stronger).
  Nit #1 declined — inline `0..3` matches existing style at the
  publish site. Nit #2 addressed (see below).
- **devil's advocate**: one actionable correctness concern. Stage
  B is the first cross-thread reader of `AtomicGpio::external_in`
  / `external_mask` (two independent `AtomicU32` today). A
  concurrent harness writer could cause a torn `(val, mask)` pair.
  HLD §4.3 packed `pads` for exactly this pattern. Also flagged:
  ordering-assertion test gap, handoff-seed dead-under-B-but-live-
  under-C, integration test absence.

### Feedback applied

- Packed `AtomicGpio::external_in` + `external_mask` into a single
  `external: AtomicU64` (`threaded/gpio.rs:33-108`). New API:
  `read_external() -> (u32, u32)` (Acquire), `write_external(val,
  mask)` (Release). Old four methods deleted. Four call sites
  updated.
- Stage C prerequisite comment above handoff seed loop
  (`emulator.rs:255-260`); regression-guard doc on
  `from_emulator_seeds_pio_pads` test.
- Integration test `run_quanta_integrates_sio_external_and_systick`
  (`emulator.rs:1721-1785`) exercises the phase-2 chain end-to-end:
  SIO GPIO write + external stimulus + SysTick decrement through
  `run_quanta(2)`. Dropped PIO from this test (PIO worker
  republishes each quantum, overwriting any pre-`run_quanta` seed)
  since `update_gpio_merges_sio_pio_and_external` covers PIO merge
  directly.

### Test results

`cargo test -p mdrp2350 --lib` — **1019 passed**, 0 failed, 2
ignored (+4 from Stage A's 1015 baseline: 3 new Stage B tests + 1
integration test). `cargo build -p mdrp2350 --release` warning-

### Journal notes (non-blocking, deferred)

- **Floating-pin semantics** (devil's advocate #6). When OE=0 on
  all drivers and external mask doesn't cover the pin, `gpio_in`
  reads 0. Real silicon shows the last driven value or pad-pull
  default. Serial has the same limitation — inherited faithfully.
  Add to `tech_debt.md` if firmware surfaces it.
- **PIO publish-all-blocks cost** (devil's advocate #3). PIO
  worker unconditionally publishes all three blocks each quantum,
  including disabled ones. Three atomic stores + coord's reads
  bounce cache lines. Under Stage C, measure for hot path; gate
  only if shown to matter.
- **`core.cycles()` coord-write invariant** (devil's advocate #7):
  coord must never write `core.cycles()` or `tick_systick`'s
  cross-thread correctness collapses. Respected today; flag for
  future reviewers.
- **Ordering assertion test** (devil's advocate #9.1): no test
  proves `update_gpio` precedes `tick_peripherals` in phase-2. A
  refactor swapping the order would break silently (all Stage B
  tests pass without the ordering). Would require test-only trace
  instrumentation — deferred.
- **Halted/running asymmetry in tick_systick** (devil's advocate
  #9.2): tests cover both-halted case; no running + halted mix.
  Serial has the same coverage — not a regression.

## Stage C

Collapsed the two-barrier rendezvous in every worker body to a
single `barrier.wait()` at the tail per V7 §5.1. Final shape:

```rust
for _ in 0..n {
    // phase work
    barrier.wait();
}
```

CPU/PIO phase-1 of quantum N and coord phase-2 of quantum N now
run in parallel. `2 × step_quantum` staleness ceiling accepted
per §5.2. Module doc + Stage-7 worker-body header updated.

### Review outcomes

- **code-reviewer**: zero blockers. Verified barrier parity (one
  `barrier.wait()` per worker after its phase work); memory
  ordering unchanged from Stage B (§5.3 assertion holds); poison
  propagation preserved (§5.4).
- **Supervisor-discovered regression**: TIMER0 smoke test from
  Stage A (`tick_peripherals_fires_timer0_alarm0_shared_irq`)
  became race-sensitive on Stage C. Root cause: TIMER alarms
  level-re-assert every poll while `intr & inte` is latched, so
  coord raises `IRQ_TIMER0_IRQ_0` every quantum; CPU workers
  swap-to-zero `irq_pending` at the top of each iteration via
  `take_irq_pending`. Under Stage B's strict phase ordering the
  coord's final-quantum raise was always observable on the atomic
  wire at end of `run_quanta`. Under Stage C overlap the CPU-take
  vs coord-raise ordering in the final iteration is race-
  dependent: if CPU's take runs after coord's raise, the atomic
  wire is 0 at end. **This is correct Stage C behavior, not a
  bug** — the IRQ still delivers (accumulates in `ppb` NVIC
  ISPR), just with variable delivery timing per §5.2.
- **Fix applied to the test, not production code**: assertion
  now observes `TIMER0.INTR` (latched on alarm match, cleared
  only by explicit W1C) via
  `shared.peripherals.timers.lock().unwrap().timer0.read32(INTR_OFFSET)`
  instead of the transient atomic wire. Semantic improvement:
  "the alarm fired at some point" vs "the wire is set right
  now".

### Test results

`cargo test -p mdrp2350 --lib` — **1019 passed**, 0 failed, 2
ignored. TIMER0 test run 5× in isolation — 5/5 pass (was
flaky before the observable swap).
`cargo build -p mdrp2350 --release` — warning-free.

### Journal notes

- **Lesson for future level-triggered IRQ tests under Stage C**:
  observe source state (peripheral INTR latches), not the
  cross-thread atomic wire, since the wire is consumed every
  quantum. Applies to TIMER, UART, SPI, I2C, ADC, PWM — anything
  going through `assert_irq_shared`.
- The race-window analysis confirms HLD §5.2's "2 × step_quantum
  IRQ delivery latency ceiling" is observable in practice. Tests
  that make latency-sensitive assertions need to account for it.
