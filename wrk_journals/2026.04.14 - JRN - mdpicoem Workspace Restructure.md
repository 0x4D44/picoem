# mdpicoem Workspace Restructure — Journal

Date started: 2026-04-14
Supervisor: Claude (Opus 4.6, 1M context)
Blueprint: `wrk_docs/2026.04.14 - HLD - mdpicoem Workspace Restructure.md` (v1.1.0)

## Mission

Restructure the RP2354 emulator workspace to support both RP2350 and
RP2040 as independent library crates. Full plan in the HLD. This journal
tracks supervisor decisions, agent dispatches, quality gates, and
findings.

## Roles

- **Supervisor (me):** plan, dispatch agents, verify results, commit
  between phases, maintain this journal. Does not write implementation
  code or run long debug loops myself.
- **Implementer:** general-purpose agent writing code for a phase.
- **Reviewer:** agent using `code-reviewer` skill on implementer's output.
- **Apply-feedback:** agent using `code-review-apply-feedback` skill to
  land reviewer findings.
- **Devil's advocate:** agent challenging the result — looks for
  shortcuts, unverified assumptions, missed edge cases, oversimplifications.

Not every phase needs the full roster. Trivial phases (Phase 0, 3) may
skip review cycles. Risky phases (Phase 4 M0+ CPU, Phase 5 RP2040 bus)
get the full treatment.

## Quality gates per phase

1. `cargo build --workspace` clean (no warnings).
2. `cargo test --workspace` green.
3. Phase-specific runtime check (e.g., `mdrp2350app` opens post-rename;
   `paced_bench` within 2% of baseline post-extract).
4. Reviewer findings triaged and either addressed or deliberately
   deferred with rationale in this journal.
5. Devil's advocate has no open objections, or objections captured and
   resolved.
6. Atomic commit with descriptive message.

## Protected-context discipline

- I don't read raw agent outputs into my context unless necessary.
- Agents report in bounded summaries (<500 words typically).
- Long build/test outputs stay inside the agent's context.
- Large file reads stay inside the agent's context; I skim or ask
  pointed questions.
- Journal is my persistent state — when I need to recall a decision, I
  check the journal, not scrollback.

### Phase 2 — extract mdpicoem-common
Status: completed

**Implementer**: 6 sub-steps (2.0 setup, 2.1 Peripheral, 2.2 clock+pacer,
2.3 Memory, 2.4 PLL math, 2.5 Fifo+Divider, 2.6 pio, 2.7 version+gate).
All green at each step. 840 tests pass, mdrp2350 → 0.3.0.

**Structural decisions**:
- `bank_for_address` → free function in `crates/mdrp2350/src/memory.rs`;
  `Memory` struct in common has no `bank_for_address` method. Chip code
  uses `crate::memory::bank_for_address(addr)`.
- Spinlock helpers (`spinlock_read`/`spinlock_write` in `sio/mod.rs`)
  **not** extracted. Reviewer flagged this against the HLD's top-level
  "What moves where" row; I re-read the HLD's Phase 2 sub-step 2.5
  which explicitly says "err on the side of NOT extracting" when the
  helpers decode register offsets rather than being pure bitmap ops.
  The current methods decode SIO register offsets before touching the
  bitmap — decision stands. RP2040 may need its own copy; that's fine.
- PIO test split: 60 `#[test]` in Phase 1 pio/mod.rs → 51 primitive
  tests in common + 9 chip-through-Bus tests in new
  `mdrp2350/src/pio_tests.rs`. Zero tests lost.
- `StopReason` enum stayed in chip crate (not referenced in code outside
  its declaration; HLD didn't explicitly require moving it).

**Reviewer (code-reviewer)**: PASS-with-notes. Flagged `StateMachine`
over-promotion. Verified 60/60 PIO test preservation. `#[inline(always)]`
counts identical pre/post (5 in pacer; none in memory — HLD's inline
preservation mandate was moot for Memory since they weren't annotated
in Phase 1 either).

**Devil's advocate**: ran paced_bench across both worktrees. Post-Phase-2
**40.9 MHz median** vs Phase 1 worktree **19.2 MHz** on the same host
(different from the supervisor's Phase 1 number of 32.8 MHz — host
was under different load). The 2× gap is real but the A/B is
contaminated by host load/thermal/cold-cache effects. Caveat: perf
numbers are host-sensitive. The >=32.24 gate passed on the implementer's
host at 42.2 MHz.

**Findings addressed (apply-feedback)**:
1. **`StateMachine` visibility**: reverted all fields + `StallKind` to
   `pub(crate)` in common. Only `PioBlock::sm` stays `pub` (its inner
   fields are `pub(crate)`, so invariants are enforced by module). Added
   `StateMachine::enabled()` accessor — the only field actually read
   cross-crate (6 sites in `pio_tests.rs`). Added module-level doc
   comment on `sm.rs` listing the invariants. `PioBlock::instr_mem` and
   `irq_flags` reverted to `pub(crate)` — no cross-crate users found.
2. **`.claude/` gitignored**: `/.claude/` added to root `.gitignore`.
   `git status` confirms no longer untracked.

**Surprise**: the blast radius of the over-promotion was just 6 call
sites reading `.enabled`, not the 21 fields the implementer originally
promoted. The full `pub` surface was defending against a need that
didn't exist.

**Post-phase state**: `cargo build --workspace` clean; `cargo test
--workspace` 840/7; paced_bench gate PASS at implementer's 42.2 MHz.

### Phase 4 — M0+ core

#### Phase 4.A: Registers + decoder + Thumb-16 executor
Status: completed

**Implementer**: ~2400 lines of new M0+ code. All 7 checkpoints cleared
in one agent call.
- `crates/mdrp2040/src/core/registers.rs` (235 lines) — ARMv6-M register
  set (no banked regs, no FAULTMASK, no BASEPRI; 2-bit CONTROL).
- `crates/mdrp2040/src/core/decode.rs` (111 lines) — group dispatch +
  `is_wide` (only accepts `0b11110` prefix; other wide forms fault).
- `crates/mdrp2040/src/core/execute.rs` (844 lines) — every M0+
  Thumb-16 executor. IT/CBZ/CBNZ rejected as UNDEFINED. No wide-path.
- `crates/mdrp2040/src/core/mod.rs` rewritten (167 lines).
- `crates/mdrp2040/src/tests.rs` (1151 lines) — 105 new unit tests.
- `crates/mdrp2040/src/bus/mod.rs` (+38 lines) — 6 no-timing
  read/write delegate methods to `Memory::peek*/poke*`. Scope creep
  noted; Phase 5 replaces with real fabric.

Not yet: Thumb-32 subset (BL/MRS/MSR/DSB/DMB/ISB), exception
entry/return, BKPT/SVC handler bodies, unaligned fault, Emulator::step
integration — all Phase 4.B.

**Reviewer (code-reviewer skill)**: PASS-with-notes. Critical finding:
**CPS bit-swap bug** in `thumb16_misc` at the CPS encoding — code
checked `opcode & (1 << 0)` for `affect_i`, but ARMv6-M A6.7.38 says
bit 1 = I, bit 0 = F. Canonical encodings `CPSIE i` = 0xB662, `CPSID i`
= 0xB672 were silently no-op on PRIMASK. Test `cpsie_clears_primask`
was using 0xB661 (CPSIE f) — passed for the wrong reason. Same bug
exists in mdrp2350 (code inherited from it); logged as tech debt, not
fixed in 4.A scope.

**Devil's advocate**: stress-tested cycle counts (no oracle — any
`return N` change would be invisible), test trivially-passing
patterns, encoding spot-checks (all 7 verified correct), Phase 4.B
landmines (silent T=0 branches, unaligned loads will flip when fault
model lands).

**Findings addressed (apply-feedback)**:
1. CPS bit-swap fixed in mdrp2040: `opcode & (1 << 1)` for `affect_i`.
   F bit ignored on M0+ (no FAULTMASK; UNPREDICTABLE). Tests updated
   to canonical encodings + new `cps_with_only_f_bit_is_noop_on_m0plus`.
2. Strengthened `rev_subop_0b10` and `it_encoding` UNDEFINED tests to
   assert no register clobber (not just fault flag).
3. Added `mul_preserves_c_and_v` test.
4. Added 3 cycle-count oracle tests (`cycles_taken_branch_is_3`,
   `cycles_simple_dp_is_1`, `cycles_ldm_is_1_plus_count`) so Phase 5
   recalibration surfaces as test failures, not silent drift.
5. Added `TODO(Phase 4.B)` comments at 4 sites where Thumb bit is
   silently stripped (BX, BLX, POP{PC}, MOV/ADD to PC).
6. `tech_debt.md` gained a "Core Correctness" section logging the
   mdrp2350 CPS bug.

**Post-phase state**: 955 tests pass (950 + 5 new in apply-feedback),
clean workspace build, zero warnings in mdrp2040.

#### Phase 4.B: Thumb-32 subset + exceptions + integration
Status: completed

**Implementer**: ~700 lines new across `execute_wide.rs` (207),
`exceptions.rs` (197), `bus/ppb.rs` (104), plus modifications to
`core/mod.rs`, `core/decode.rs`, `core/execute.rs`, `bus/mod.rs`,
`lib.rs`, `tests.rs`. 31 new unit tests; `Emulator::step` and
`Emulator::run` now functional.

**Coverage delivered**: BL/MRS/MSR/DSB/DMB/ISB; exception entry for
SVC/BKPT/HardFault/NMI; EXC_RETURN 0xF1/0xF9/0xFD; invalid EXC_RETURN
→ HardFault; unaligned fault on LDR/STR/LDRH/STRH/LDM (base)/PUSH/POP;
T=0 HardFault at BX/BLX/POP{PC}/MOV-to-PC; minimal PPB (vtor, shpr,
icsr, active bitmap).

**Reviewer**: PASS-with-notes. Flagged PRIMASK+SVC (spec-violation),
T=0 non-HardFault vector silent corruption, SYSm=4 misclassified as
APSR, exit_exception cycle drop.

**Devil's advocate**: Found a real **banked SP staleness bug** —
`enter_exception`/`exit_exception` read `self.regs.msp`/`psp` directly,
but `SUB SP,#imm` in a handler updates `r[13]` without syncing to the
banked field. Every Pico SDK handler allocating stack locals would
break. Also confirmed PRIMASK+SVC spec issue and T=0 corruption.

**Findings addressed (apply-feedback)**:
1. **Banked SP sync** — added `sync_sp_to_banked()` at top of enter
   and `sync_sp_from_banked()` after exit, so banked MSP/PSP and r[13]
   stay coherent across handler SP manipulation. New test
   `handler_sp_mutations_sync_to_banked_on_exit` exercises the flow
   end-to-end.
2. **PRIMASK + SVC** — `deliver_fault(Fault::Svc)` now checks PRIMASK
   and escalates to HardFault (exception #3) when set. Test
   `step_primask_does_not_mask_svc` renamed to
   `step_primask_escalates_svc_to_hardfault` with flipped expectation.
3. **T=0 vector escalation** — non-HardFault with T=0 vector now sets
   `pending_fault = HardFault` (with pre-bailout SP sync so the next
   enter sees the committed partial frame); HardFault-in-HardFault
   still locks up. Test
   `nonhardfault_with_t0_vector_escalates_to_hardfault` added.
4. **Alignment pad test** added (`exception_entry_pads_when_sp_is_4_aligned_not_8`).
5. **Emulator::run test** added (`run_advances_pc_over_nops`).
6. **SYSm match tightened** to exact values (0 | 3 | 5 | 8 | 9 | 16 | 20);
   reserved → HardFault. Two new tests for MSR and MRS reserved cases.
7. **`exception_priority`** in `bus/ppb.rs` annotated
   `#[allow(dead_code)]` (will be wired in Phase 5 NVIC work).

**Tech debt surfaced (not fixed in Phase 4)**:
- `mdrp2350` has the same banked-SP staleness in its
  `enter_exception`/`exit_exception`. Not touched per review scope.
  Should add to `tech_debt.md` under "Core Correctness" when CPS bug
  entry gets revisited.

**Post-Phase-4 state**: 992 workspace tests pass (955 → 992, +37).
mdrp2040 unit tests: 147 total. Clean workspace build, zero warnings.
`Emulator::step`/`run` functional on Thumb-16 + Thumb-32 subset + full
exception model. `load_image`/`load_bootrom`/`gpio_*` remain `todo!()`
for Phase 5.

### Phase 5 — RP2040 bus + peripherals

#### Phase 5.A: bus fabric + clocks + SIO + GPIO + integration
Status: completed

**Implementer**: ~2000 lines new. `bus/mod.rs` 127 → 987, plus new
`memory.rs`, `bus/{clocks,resets,sio,io_bank0,pads_bank0}.rs`, and
`tests/firmware.rs`. `lib.rs` completed: `load_image`, `load_bootrom`,
`gpio_read/write/read_all` all functional. Dual-core step:
per-instruction cadence (not quantum like mdrp2350 — noted as tech
debt). Core 1 halted at reset; wakes on FIFO event.

Coverage: RP2040 address decode, SRAM 4-stripe + 2-scratch banking
with +1-cycle contention, CLOCKS/RESETS/XOSC/ROSC/PLL_SYS/PLL_USB
register models, full SIO (GPIO, CPUID, FIFO, 32 spinlocks, divider,
interp storage), IO_BANK0 (30 GPIOs with FUNCSEL), PADS_BANK0, XIP_CTRL
+ SSI stubs.

**Reviewer**: flagged a real bug — CLK_SYS_DIV (0x40) and
CLK_SYS_SELECTED (0x44) were swapped. Also inconsistent unmapped
handling across write widths.

**Devil's advocate**: caught two critical bugs the reviewer missed —
SRAM alias XOR/SET/CLR semantics (wrong per RP2040 §2.1.2: these are
bank-striping aliases, not peripheral aliases) and `bus_fault` sticky
flag set but never observed by CPU (unmapped loads silently returned
0). Test `sram_xor_alias` was actively encoding the SRAM bug. DA also
surfaced landmines around WFE wiring and SDK multicore handshake not
being parsed.

**Findings addressed (apply-feedback)**:
1. **SRAM aliases** — removed XOR/SET/CLR helpers. Aliases now plain
   storage mirror. Old test deleted; 3 new tests (`sram_aliases_mirror_same_storage`,
   `unmapped_writes_fault_at_every_width`, `rom_writes_silently_ignored_at_every_width`).
2. **bus_fault → HardFault** — `CortexM0Plus::step` now observes
   `bus.bus_fault()`, clears it, stages `Fault::HardFault`. New test
   `unmapped_load_escalates_to_hardfault`.
3. **CLK_SYS_DIV/SELECTED swap** — offsets fixed. Test
   `clk_sys_div_offset_0x40_feeds_recompute` guards the correct wiring.
4. **Write-width consistency** — unmapped at any width → `bus_fault`;
   ROM/XIP writes at any width → silent.
5. **MULTICORE_LAUNCH_WAKE_MAGIC dead-code hack** — deleted. TODO
   comment documents the wake-simplification until Phase 6.

**Tech debt logged** (new section "Phase 5.A Simplifications" in
tech_debt.md): WFE/SEV wiring, divider 8-cycle latency, PLL LOCK
always-1, core 1 SDK handshake, per-instruction cadence vs quantum,
divider 2-read dirty-clear heuristic.

**Post-phase state**: 1052 workspace tests pass (1046 + 6 net).
mdrp2040: 212 tests. Clean workspace build, zero warnings. Real RP2040
firmware writing to SIO GPIO runs end-to-end via `Emulator::step`.

#### Phase 5.B: PIO wiring
Status: completed

**Implementer**: +41/-12 lines in `bus/mod.rs`, +54/-14 in `lib.rs`,
plus new `pio_tests.rs` (382 lines, 15 tests). Bus gains
`pio: [PioBlock; 2]` (vs mdrp2350's [3]). PIO0 at 0x5020_0000, PIO1 at

pad_oe overriding SIO), masked to 30 pins. PIO steps per `emu.step`
by the core-0 cycle cost (3 for branches, 1 for NOPs) — matches
hardware where PIO clock = sys clock.

All `todo!()` in `mdrp2040/src/` now resolved.

**Review + DA (combined)**: PASS-with-notes. Confirmed merge semantics
mirror mdrp2350, alias stripping correct, reset coverage complete.
Flagged: clippy::identity_op noise in tests; RESETS-not-gating-PIO

**Findings addressed (apply-feedback)**:

2. Logged "PIO not gated on RESETS bit" in tech_debt.md's Phase 5.A
   Simplifications section.
3. Added `emu_step_advances_pio_by_core0_cycle_cost` cadence test +
