# mdpicoem Workspace Restructure — Journal

Date started: 2026-04-14
Supervisor: Claude (Opus 4.6, 1M context)
Blueprint: `wrk_docs/2026.04.14 - HLD - mdpicoem Workspace Restructure.md` (v1.1.0)

## Mission

Restructure the RP2354 emulator workspace to support both RP2350 and
RP2040 as independent library crates. Full plan in the HLD. This journal
tracks supervisor decisions, agent dispatches, quality gates, and
findings.

## Roles

- **Supervisor (me):** plan, dispatch agents, verify results, commit
  between phases, maintain this journal. Does not write implementation
  code or run long debug loops myself.
- **Implementer:** general-purpose agent writing code for a phase.
- **Reviewer:** agent using `code-reviewer` skill on implementer's output.
- **Apply-feedback:** agent using `code-review-apply-feedback` skill to
  land reviewer findings.
- **Devil's advocate:** agent challenging the result — looks for
  shortcuts, unverified assumptions, missed edge cases, oversimplifications.

Not every phase needs the full roster. Trivial phases (Phase 0, 3) may
skip review cycles. Risky phases (Phase 4 M0+ CPU, Phase 5 RP2040 bus)
get the full treatment.

## Quality gates per phase

1. `cargo build --workspace` clean (no warnings).
2. `cargo test --workspace` green.
3. Phase-specific runtime check (e.g., `mdrp2350app` opens post-rename;
   `paced_bench` within 2% of baseline post-extract).
4. Reviewer findings triaged and either addressed or deliberately
   deferred with rationale in this journal.
5. Devil's advocate has no open objections, or objections captured and
   resolved.
6. Atomic commit with descriptive message.

## Protected-context discipline

- I don't read raw agent outputs into my context unless necessary.
- Agents report in bounded summaries (<500 words typically).
- Long build/test outputs stay inside the agent's context.
- Large file reads stay inside the agent's context; I skim or ask
  pointed questions.
- Journal is my persistent state — when I need to recall a decision, I
  check the journal, not scrollback.

## Phase log

### Phase 0 — capture paced_bench baseline
Status: completed

**Baseline: 32.9 MHz emulated** (median of 3 x 15s runs, variance 0.6%).
Host/emu ratio: 93.35 (already over the HLD §12 <33 target on master;
existing state, not a regression concern).

Command: `paced_bench --unpaced --seconds 15` (default `basic` workload:
2-insn tight loop `ADDS R0,R0,#1 ; B .-2` at `0x2000_0000`).

**HLD correction needed:** HLD says baseline runs against
`roms/benchmark.bin`. Wrong — paced_bench has a hardcoded workload, not
a firmware input. The benchmark.bin file belongs to mdrp2354-app. The
HLD's Phase 0 and "Validation gate" paragraphs will be corrected inline
during Phase 1's doc sweep.

**Phase 2 gate: post-extract paced_bench within 2% of 32.9 MHz**
(i.e. >= 32.24 MHz).

### Phase 1 — rename crates + doc sweep
Status: completed

**Implementer**: 64 files moved (35 pure renames + 29 renames-with-content),
4 deletes (stub crates), 9 in-place modifications. 840 tests pass, clean
release build, `mdrp2350app blinky` TUI launches successfully.

**Reviewer (code-reviewer skill)**: PASS. Zero stale `mdrp2354` code
references outside legitimate categories (physical-chip / firmware-encoded /
historical-doc). Cargo.lock clean, no backwards-compat shims, no feature
flags added. Flagged pre-commit action: stage `roms/rp2040/.gitkeep`.

**Devil's advocate**: caught one real regression + 2 minor inconsistencies.
Also ran `paced_bench` post-rename: **32.8 MHz median** (0.3% below the
32.9 MHz baseline — well within the 2% gate).

**Findings addressed (apply-feedback)**:
1. `rust-version` lift was non-functional — `[workspace.package]` had the
   field but no crate had `rust-version.workspace = true`, so the 1.88
   MSRV silently dropped. Added the inheritance opt-in to all 4 renamed
   crates. `cargo metadata` confirms all now report `rust_version: 1.88`.
2. `src/main.rs:6` banner: "RP2354 emulator initialised" → "RP2350
   emulator initialised" (crate-role context, not silicon).
3. `crates/mdrp2350/src/lib.rs:62` doc comment: same fix.

**Decisions logged**:
- TUI window title changed from `"mdrp2354 showcase"` → `"mdrp2350app showcase"`.
  Developer-facing TUI, not user branding; crate-name reading is appropriate.
  Both reviewers accepted; devil's advocate flagged it as a judgement call
  worth documenting — done here.
- The root `src/main.rs` is outside the workspace (virtual workspace, no
  root `[package]`). It's the "sanity-check stub" per CLAUDE.md. Banner
  fix still applied for consistency, but the file is effectively orphaned
  and won't be built by `cargo build --workspace`. Pre-existing state,
  not a Phase 1 concern. Candidate for later cleanup (could move into
  `mdrp2350app` or delete entirely).

**Perf**: 32.8 MHz (from 32.9 MHz baseline, 0.3% delta). Rename did not
regress inlining or codegen.

**Post-phase state**: `cargo build --workspace` clean, `cargo test
--workspace` 840 pass / 7 ignore (unchanged from pre-rename).
