### 2026-04-17 — Wave 1.5: fresh diagnosis and oracle correctness fix

- Delegated a 2nd root-cause pass. Fresh diagnosis identified the **true** culprits:
  - **H1 (primary):** the oracle reads `resolved_addr` from the MMIO `CH1.READ_ADDR` register, which CH0 keeps overwriting with newer pushes. So the reported `resolved_addr` is *decoupled* from the byte actually observed on D0..D7. Structural oracle bug.
  - **H2 (secondary):** `GAP_CYCLES = 12` is too short to drain the PIO → CH0 → CH1 pipeline, so case N's residue bleeds into case N+1.
  - **H3 (tertiary):** PIO1 SM0 occasionally emits a high/low swapped word on its first push after sync, giving addresses like `0xB000_2000` (= swapped `0x2000_B000`). Out of scope for this wave.
- Agent landed H1 + H2 fixes in `crates/mdpicoem-harness/src/onerom_glue_dma.rs` and `onerom_serving_oracle.rs`:
  - Glue DMA now exposes `last_pushed_read_addr()` — the address CH1 actually fetched from for its most recent push.
  - Oracle snapshots address + byte atomically when `ch1_pushes > pushes_before`.
  - Gap drain replaced with `is_idle()` invariant (capped at 64 cycles).
- Post-fix verdict: **0 PASS / 0 WB / 5 AOOR / 10 LOOE** (was 1 / 3 / 3 / 8). Numerically worse — but the oracle is now honest:
  - The 3 WrongByte cases (A4/A5/A6) were oracle misreports; they now correctly report the byte that was actually fetched (gap-level byte 0x00).
  - Every case now reports `resolved=0x2000_B000` (gap address). The H2 drain floods the pipeline with gap-level addresses; after drain, stim is applied but gap residue wins the "first new push" race.
- **Diagnosis: H2 is counter-productive.** The drain is gap-driven, so gap pushes dominate by construction. Next step: match pushes by `resolved_addr` — skip gap-level pushes, wait for a stim-matching push. That's the push whose byte we care about.

#### mdrp2350 bugs surfaced + fixed (1.8.2 → 1.8.3)

1. `Bus::write8` / `write16` had no region-`0xD` (SIO) arm — narrow writes silently dropped. Latent; PIO path doesn't go via `write8`.
2. Narrow writes to SIO `GPIO_OUT` / `GPIO_OE` family must **replicate across all 4 byte lanes** on real RP2350 (OneROM firmware comment in `rom_asm.h`: "we will write a byte, will be replicated across word"). Without this, STRB R1, [SIO_GPIO_OUT] only lit pins 0..7 instead of 16..23.

Fix in `crates/mdrp2350/src/bus/mod.rs`:
- New `0xD` arm in `write8` + `write16`. For GPIO_OUT/GPIO_OE family offsets (`0x010/0x018/0x020/0x028/0x030/0x038/0x040/0x048`), byte/halfword multiplied to fill the word then committed via `write32`. Other SIO regs: `sio.read32`+splice RMW into the natural lane.

Three TDD tests in `crates/mdrp2350/src/tests.rs` (`sio_gpio_out_byte_write_replicates_across_lanes`, `sio_gpio_oe_byte_write_replicates_across_lanes`, `sio_gpio_out_halfword_write_replicates`) fail on baseline, pass after fix.

#### CPU oracle (harness 0.28.3 → 0.29.0)

New files in `crates/mdpicoem-harness/`:
- `src/onerom_serving_oracle_cpu.rs` — oracle library (transition-aware stability detector, two-phase sync with shadow-readiness tripwire).
- `src/bin/onerom_serving_oracle_cpu_rp2350.rs` — 15-case driver.
- `src/bin/onerom_cpu_probe.rs` — diagnostic probe.
- `fixtures/onerom-fire-24-a-rp2350-test-sdrr-0-cpu.bin` — CPU-mode fixture.

HLD: `wrk_docs/2026.04.17 - HLD - OneROM CPU-Serve Oracle.md`.

Key design:
- **Two-phase sync**: phase 1 = PC in serve-loop range; phase 2 = shadow-readiness tripwire (known non-zero byte at a tail-biased sentinel offset). Phase 2 is required because the firmware walks through the serve-loop PCs during init *before* the SRAM shadow copy completes; without it, LDRB returns 0x00 for every case.
- **Observation**: `(bus.gpio_in >> 16) & 0xFF` with OE gating. Pure `observe_tick` state machine with transition-or-timeout stability.
- **Envelope** `9..=60` — non-zero cases stabilise at 9..=11 cycles (first STRB + MIN_STABLE_CYCLES=4); zero cases latch via 40-cycle timeout.
- Shim aliases `stimulus_level_pub` / `lift_shadow_from_flash_pub` in the PIO oracle so the CPU oracle reuses pin permutation + shadow lift without duplication. New `pub mod onerom_serving_oracle_cpu` in harness `lib.rs`.
