### Why the remaining 114 weren't fixed

These are entirely stylistic or design-feedback lints in test code or
intentional design choices. None reflect bugs:

- **`needless_range_loop` (×~36, mostly tests).** `for i in 0..N { arr[i] = ... }` patterns where the conventional iter+enumerate alternative is uglier in test-setup code.
- **`doc_list_item_without_indentation` / `doc_list_item_overindented` (×~28).** Markdown-formatting nits in doc comments. Most are in places where the prose is intentionally informal.
- **`too_many_arguments` (×9).** Test helpers and encoder helpers that take one parameter per hardware-register bit-field (DMA CTRL has 9 fields, Thumb-32 encoders have 8–9 fields). Bundling into a struct just adds a one-shot type that hurts call-site readability.
- **`type_complexity` (×6).** Tuple-returning helpers in test setup.
- **`enum_variant_names` (×4).** Naming conventions that match an external API (e.g. probe-rs error variants).
- **`large_size_diff_between_variants` (×2).** Box-wrapping a variant would force an indirection on the hot path; the size difference is intentional.
