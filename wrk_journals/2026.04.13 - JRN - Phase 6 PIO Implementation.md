## Review Findings Summary

Each stage had a code review + devil's advocate pair. Issues caught and
fixed:

### Stage A (5 fixes)
1. FIFO `is_full()` returned true at depth=0 (broke FSTAT for joined
   FIFOs)
2. SM_RESTART was flushing FIFOs (real hardware preserves them)
3. read8/read16 missing PIO dispatch (sub-word reads returned 0)
4. PIO step not wired into `Emulator::step()`
5. Dead `irq_force` field

### Stage B (3 critical fixes)
1. **Stall-then-unstall skipped instruction re-execution** — blocking
   PULL never read from FIFO after unstalling. Root cause: `advance_pc`
   called on unstall path. Fix: remove advance, fall through to
   re-execute. Both reviewers caught this; existing test masked the bug
   by not asserting the data transfer.
2. **Shift-by-32 wrapped to no-op in Rust** — `u32 >> 32` wraps to
   `u32 >> 0` in release mode. OUT/IN with bit_count=0 (meaning 32) left
   OSR/ISR unchanged. Fix: guard with `if bc >= 32 { reg = 0 }`.
3. **Non-blocking PULL from empty FIFO didn't copy X** — RP2040
   datasheet specifies this behavior. Fix added.

### Stage C (2 medium fixes)
1. **`out_pins | set_pins` OR-merge was wrong** — real hardware has one
   output latch per pin shared by OUT/SET/MOV. Fix: collapse into single
   `pin_values` field; last writer wins.
2. **Side-set PINDIRS mode wrote to wrong field** — fixed to write to
   `sideset_dirs` when SIDE_PINDIR is set.

### Stage D
No fixes needed — waveform tests passed first try, confirming the
Stage A/B/C fixes were complete.

### Final verification (2 fixes)
1. **Decoder panic on SIDESET_COUNT=6 or 7** — illegal PINCTRL values
   would underflow `5 - sideset_count`. Fix: clamp to min(5). Real
   silicon doesn't crash on bad writes, just produces unspecified
   waveforms.
2. **SM_RESTART didn't clear `pending_exec`/`stall_kind`** — stale
   pending OUT EXEC would fire after restart. Fix: clear on restart.

## Key Observations

1. **The devil's advocate caught critical bugs the code reviewer missed.**
   Examples: Stage A's SM_RESTART-flushing-FIFOs bug (semantic error
   invisible to code inspection), Stage C's pin merge OR-bug (requires
   understanding hardware latch semantics). Having both perspectives was
   essential.

2. **Tests can mask bugs.** The Stage B stall-unstall bug existed from
   the start, but the initial test didn't assert `osr == 42` after
   unstalling. The DA review specifically probed this and exposed it.

3. **PIO encoding traps.** Two instruction-encoding bugs were fixed
   without any test catching them initially: shift-by-32 wrapping and
   decoder SIDESET_COUNT clamping. Both are Rust-specific gotchas (Rust
   panics/wraps on out-of-range shifts; underflow panics in debug mode).

4. **The 4-stage plan was well-calibrated.** Each stage produced
   committable, testable code with a clear exit criterion. Review cycles
   per stage: ~20 min implementer + 2 parallel reviewers (~5 min each) +
   ~3 min fix application.
