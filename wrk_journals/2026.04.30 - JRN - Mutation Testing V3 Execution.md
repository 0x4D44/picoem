## Stage 1 — Stream A: classifier unit tests (complete)

### Decision: inline `#[cfg(test)] mod classifier_tests` block

The classifier helpers (`classify_is_pure`, `classify_thumb16_pure`,
`classify_thumb16_misc_pure`, `classify_thumb32_pure`, plus mdrp2350's
`classify_thumb32_branch_misc_pure`, `classify_thumb32_misc_control_pure`,
and `is_thumb16_flag_only`) are private (`fn`, no `pub`) inside the
respective `decode.rs` files. To test them externally I'd need to bump
their visibility. Instead I added an inline `#[cfg(test)] mod
classifier_tests { use super::*; ... }` block at the bottom of each
`decode.rs` — same pattern used in `crates/mdrp2350/src/core/mod.rs:1147`.
Zero visibility surface change; tests live next to what they exercise.

### Test design

Two layers per classifier:

1. **Per-match-arm structural assertions** with named encodings. Catches
   match-arm-delete, boolean-flip, and constant-flip mutations with
   human-readable diagnostics. Documents intent.
2. **FNV-1a 64-bit fingerprint** over the relevant input space —
   exhaustive 16-bit for Thumb-16 classifiers, structured cross-product
   for Thumb-32. Catches any mutation that changes even a single
   input → output mapping. Single-line assert against a checked-in
   constant computed once and pasted in.

FNV-1a was chosen over `std::collections::hash_map::DefaultHasher`
because the std hasher is **not stable across Rust versions**. FNV-1a
(`offset_basis = 0xcbf29ce484222325`, `prime = 0x100000001b3`) is
canonical, ~5 lines inline, and survives toolchain changes.

### §3.1 Confirmed Bucket 4: structural disjoint-bit `| → ^` / `| → &`

Sampled `vfp_sd:26`, `vfp_sn:33`, `vfp_sm:40`, `fpscr_set_nzcv:53`,
`f32_to_f16_bits:1476/1488/1509/1521/1544/1546/1566/1568/1570`. All
follow the pattern `(high_bits) | (low_bits)` where the two operands
have **disjoint bit fields**. Examples:

- `vfp_sd: (vd << 1) | d` — `vd << 1` has bit 0 = 0; `d ∈ {0, 1}`. So
  `|` ≡ `^` ≡ `+`. **Equivalent mutant for all inputs.**
- `fpscr_set_nzcv: !(FPSCR_N | FPSCR_Z | FPSCR_C | FPSCR_V)` — the
  four constants are single-bit flags at bits 31, 30, 29, 28. Disjoint.
  `|` ≡ `^`.
- `f32_to_f16_bits:1476: sign | 0x7C00` — sign is bit 15; `0x7C00`
  spans bits 14-10. Disjoint.

**Verdict: ~30 mutants in this category across `vfp_sd/sn/sm`,
`fpscr_set_nzcv`, `f32_to_f16_bits` final-assembly steps, and
`fpu_v8m_dp` register-encoding sites are structural Bucket 4.**

### §3.2 Confirmed Bucket 4: NaN-path equivalence in fp_sub / fp_div

V2.1 §9.4 flagged `fp_sub:218 (- → /)` and `fp_div:278 (/ → %)` as
"the interesting ones" — the operations differ in the general case.
Reading the source:

- **`fp_sub:218`**: `let nan = canonicalize_nan(a - b, a, b);` is
  inside the `inf - inf same-sign` branch. By IEEE 754, `inf - inf ==
  NaN` and `inf / inf == NaN`. `canonicalize_nan(NaN, a, b)` produces
  the same canonical NaN regardless of which NaN it received. **Mutation
  is equivalent.**
- **`fp_div:278`**: `let nan = canonicalize_nan(a / b, a, b);` inside
  the `0/0 || inf/inf` invalid branch. Same argument: `0.0 % 0.0 ==
  NaN`, `inf % inf == NaN`. Both produce NaN, both canonicalize to the
  same value. **Equivalent.**

**Verdict: both V2.1 headlines confirmed Bucket 4.**

### §3.3 Confirmed Bucket 4: shift by zero

`execute_fpu.rs:81: const FPSCR_IOC: u32 = 1 << 0;` — the `<<` mutates
to `>>`, but `1 << 0 == 1 >> 0 == 1`. **Equivalent.**

### §3.4 Mixed cluster: `f32_to_f16_bits` (26 survivors)

Detailed pattern × line-number breakdown:

| Pattern | Lines | Verdict |
|---|---|---|
| `\| → ^` | 1476, 1488, 1509, 1521, 1544, 1546, 1566, 1568, 1570 (×11 total — some lines have multiple `\|`) | **Bucket 4 disjoint-bit** |
| `& → ^` / `& → \|` | 1532, 1534, 1553, 1554 (×7 total) | mixed — see below |
| `- → +` / `- → /` | 1532 (×4 total) | **Bucket 4 by reachability** — see below |
| `< → <=` / `< → ==` | 1529 (×2) | **Bucket 4 by reachability** — see below |
| `!= → ==` | 1536 | **Bucket 1 candidate** — round-to-nearest-even subnormal |
| `> → >=` | 1563 | **Bucket 1 candidate** — round-to-max-mantissa corner |

**Lines 1529 / 1532 reachability**: these mutations are in the
subnormal-rounding branch (lines 1516-1547), reached only when
`e ∈ [-24, -15]`. In this branch, `shift = (-e - 1) ∈ [14, 23]`. The
test `if shift < 2` (line 1529) is **always false** at runtime — `shift`
never < 2. The mask computation `(1u64 << (shift - 1)) - 1` (line 1532)
likewise operates on shifts ≥ 13, where `- → +` and `- → /` produce
different masks but only matter if the corresponding `shift` value is
ever 0 or 1 — which it isn't. **Bucket 4 by reachability.**

**Line 1536 `if round_bit != 0 && (sticky || lsb != 0)`**: the `!= →
==` mutation flips the round-trigger condition. For random fuzz input,
`round_bit` should be ~50% set; the mutation should fire on ~50% of
inputs. The fact that it survives 2000 iterations of softfloat_diff
suggests **the corpus doesn't generate enough subnormal cases** to
exercise this branch's both-states. **Strong Bucket 1 candidate** —
file a tech_debt entry for "softfloat_diff VCVT.F16.F32 corpus needs
more subnormal coverage".

**Line 1563 `if rounded > 0x3FF`**: the `> → >=` mutation differs only
when `rounded == 0x3FF`. That requires the round-to-nearest-even
arithmetic at line 1555 to land exactly on `0x3FF`. Narrow corner.
Likely **Bucket 2 corpus gap** — softfloat_diff doesn't generate the
specific bit patterns that exit at `rounded == 0x3FF`.

- ~47 mutants Bucket 4 by oracle routing (function not exercised).
- ~30 mutants Bucket 4 by structural disjoint-bit `|/^/&` equivalence.
- ~10 mutants Bucket 4 by reachability (dead branches under runtime
  shift constraints).
- ~5 mutants Bucket 4 by NaN-path equivalence (fp_sub:218 family +
  fp_div:278).
- **~5 candidates Bucket 1 / Bucket 2** for hand-followup: the
  `f32_to_f16_bits:1536 != → ==` and `:1563 > → >=` mutations, plus
  similar at lines 1534, 1553-1554.
- ~16 mutants in canonicalize_nan / fpu_unary / dispatch entries that

Total Bucket 4 confirmed: **~92 / 113**. Remaining ~21 split between
Bucket 1 candidates (subnormal rounding corners) and Bucket 2 (corpus
gap).

The corpus-gap recommendation: extend softfloat_diff's VCVT.F16.F32
fuzz to deliberately stress subnormal rounding edge cases. Specifically:
- f32 inputs with exponent in [-24, -15] (subnormal-output range).
- f32 inputs that round-to-nearest-even land on `0x3FF` (max

- f32 mantissas where round_bit and sticky bits independently vary.

This is a tech_debt entry, not a V3 deliverable.

## Stage 4 — Stream C: `#[mutants::skip]` annotations decision (closed; no annotations applied)

The action plan §4 Stream C tentatively listed three skip targets.
After the §3 triage, none turn out to be the right call:

1. **vfp_sd / vfp_sn / vfp_sm / fpscr_set_nzcv / vfp_expand_imm_f32**.
   The `| → ^` mutations are structurally equivalent (disjoint
   bit-fields), but the same functions also have `>> with <<` and
   `& with |` mutations that ARE non-equivalent (would extract
   different bits) and ARE observable through `qemu_diff_m33 --classes
   fpu`. Per-function routing already routes to FPU class with
   `requires: "fpu_class"`, classifying as `oracle_unavailable` while
   the QEMU env is broken. Adding `#[mutants::skip]` would silence
   the signal that the env fix is owed.
2. **mdrp2040 classifier helpers**. After Stream A's exhaustive unit
   tests, every non-equivalent mutation is caught. Remaining MISSED
   mutants are structurally equivalent (e.g. `delete match arm 0b01001
   in classify_thumb16_pure` where the deleted arm body is `false` and
   the default arm body is also `false`) — real cargo-mutants
   methodology artefacts, not test gaps. Skipping silences true
   negatives.
3. **MSR/MRS unreachable register IDs in `execute_wide.rs`**. Per V2
   triage HLD §3.2, same argument as (1) — the per-function routing
   handles oracle visibility; whole-function skips would lose
   specificity.

**Stream C closes with no source changes.** The right closure is
landing the QEMU FPU class env fix (V2 Triage HLD Action 3, deferred
because it's an env problem not a code problem) plus the per-function
routing already in place.

### Note on criterion #2

The mdrp2350 classifier has a `_ => true` fallback in
`classify_thumb16_misc_pure` and `_ => false` fallbacks in the other
two top-level classifiers. Many V2-missed mutants on mdrp2350's
classifiers are **structurally equivalent** by virtue of the fallback
matching the deleted explicit arm's body. cargo-mutants generates
these as candidates but no test can distinguish them from the
original. This is why the mdrp2350 classifier kill rate looks low (3
of 51) — the 48 remaining are equivalent mutants per the cargo-mutants
methodology, not test gaps. The mdrp2040 classifier doesn't have this
issue at the top level (the `_ => false` fallback only matches the
already-impure prefixes 0b11101/0b11110/0b11111), so kill rate is
much higher there.

This is a known cargo-mutants limitation noted in the
`cargo-mutants` documentation. Closing those would require either:
- Restructuring the classifier to remove the default fallback (replace
  with explicit arms for every prefix/op-code).
- Marking the affected function with `#[mutants::skip]`.

The first introduces ~30 lines of redundant code with no semantic
benefit. The second silences true negatives. Neither is a clear win;
**accepted as residual structural noise**.
