### Stage 2 — quantum-invariance integration test (complete)

**Implementer.** Created `crates/rp2350-emu/tests/dma_quantum_invariance.rs` (507 lines). One `#[test]` function asserts end-state equality between quantum=1 (reference) and quantum ∈ {4, 16, 64, 256} for 5 workloads = 20 invariance assertions. All pass post-fix; full crate suite no regressions.

Key implementation choices documented:
- PIO FIFO occupancy captured via FLEVEL register read (offset 0x00C, side-effect free) since no public `tx_fifo_level()` accessor crosses the crate boundary. FLEVEL bit layout (TX `[i*8..i*8+4]`, RX `[i*8+4..i*8+8]`) verified against `picoem-common/src/pio/mod.rs:553-562`.
- `make_ctrl` reimplemented inline (in-crate `dma.rs::tests::make_ctrl` is private) with bit positions cited from `dma.rs:136-166`.
- `timer_paced` TRANS_COUNT=200 (768 cycles ÷ Y=10 ⇒ ~76 fires, well below 200 — partial completion as required).

**Reviewer.** Approve with no required changes. Flagged a substantive concern: of the 5 workloads, only 3 strongly catch the §3 fix's regression (`force_64_words`, `timer_paced`, `two_channels_armed` — all gate at multiple quanta); `chain_4_then_4` catches only at q=256; `pio_rx_paced` self-limits at 4 transfers (FIFO depth) and may match end-state by accident. Recommendation: strengthen `pio_rx_paced` with a running PIO program OR accept redundancy.

**Devils-advocate.** Refuted reviewer's claim that `pio_rx_paced` catches nothing — it does diverge at q=256 (only 3 ticks fire pre-fix, vs 4 fired post-fix), and it gates DREQ snapshot freshness (a class the §3 correctness argument explicitly preserves). Verdict: **ship as-is**. Strengthening would add ~50 lines of brittle PIO instruction-word encoding for marginal gain; that path is silicon-validated in §4.3.1 (Stage 3). Reviewer's matrix slightly overstated coverage at low quanta but conclusion stands: the test ensemble strongly gates the fix at quantum ≥ 64 across multiple workload classes.

**Test-power summary** (post devils-advocate analysis):

| Workload | Catches divergence at | Class |
|---|---|---|
| `force_64_words` | q=16, q=64, q=256 | throughput cliff |
| `timer_paced` | every q>1 | timer accumulator advance |
| `pio_rx_paced` | q=256 + DREQ freshness | DREQ snapshot semantics |
| `chain_4_then_4` | q=256 | chain mechanism at large quanta |
| `two_channels_armed` | q=64, q=256 | multi-channel arbitration |

Coverage gaps acknowledged out-of-scope per HLD §6: ring-buffer wrap, DMA-DMA register writes (deferred to §4.4 OneROM smoke), per-cycle reset re-check.

**Apply-feedback.** No required actions; reviewer's "suggested" items were stylistic and the devils-advocate confirmed ship-as-is. Skipped this round.

**Commit.** `58332f5` — "tests(rp2350): quantum-invariance integration test (stage 2)" — 2 files, +536/0.

### Stage 3 — silicon scenarios + calibration (partially blocked)

**Implementer.** Added two scenarios to `crates/picoem-harness/src/silicon_scenarios.rs`:

- **`dma_pio_rx_paced`** (57-halfword sled, 114 bytes). PIO0 SM0 runs `SET X,4 / IN X,32 / NOP` with `WRAP_TOP=2`, `SHIFTCTRL` set for AUTOPUSH. DMA CH0 paced on `DREQ_PIO0_RX0` drains 8 words to `0x2000_0B00..1C`. Observables: 8 destination words = `0x0000_0004`, `DMA.INTR` bit 0, CH0 BUSY clear.
- **`dma_pio_tx_paced`** (50-halfword sled, 100 bytes). PIO0 SM0 runs `OUT NULL,32` with AUTOPULL. DMA CH0 paced on `DREQ_PIO0_TX0` pushes 8 words from SRAM to PIO0 TXF0. Sled includes a 16-iteration drain spin so EMU matches silicon's natural post-BKPT drain. Observables: PIO0 SM0 TX FIFO empty, `DMA.INTR` bit 0, CH0 BUSY clear.

EMU-side end-to-end tests added (`test_dma_pio_rx_paced_sled_on_emu`, `test_dma_pio_tx_paced_sled_on_emu`) — both pass; full lib suite (657 tests) clean.

EMU-side baseline cycle counts (proxy for silicon calibration): rx_paced ≈ 67 sysclks, tx_paced ≈ 90 sysclks.

**Silicon calibration: BLOCKED.** Probe attachment failed with generic `probe-rs` error (`DebugProbeError`) — both new scenarios AND the existing `dma_mem_to_mem_32bit` hit the same error. Since `dma_mem_to_mem_32bit` previously worked, this is a probe-state issue (disconnect, stale process holding the probe, or wrong probe enumerated by `auto_attach`). Implementer correctly refused to fake calibration data.

Pre-calibration `min_sysclks=0`, `max_sysclks=2000` (conservative). Final calibration deferred until probe is usable.

**Reviewer.** Approved with one required change: HLD §4.3.2 listed `TXSTALL not set` as an observable but the implementer's `OUT NULL,32` + drain spin design would actually GUARANTEE TXSTALL gets set on silicon. Recommended either adding the FDEBUG observable or documenting the omission. Hand-decoded ~10 Thumb-32 instructions across both sleds — all encodings correct.

**Devils-advocate.** Refuted reviewer's "add FDEBUG observable" recommendation. Found that **EMU's PIO model doesn't implement FDEBUG.TXSTALL/RXSTALL bits at all** (zero writers in the workspace). Adding the observable would create a guaranteed silicon-vs-EMU false-positive on first contact, masking real pacing bugs. Right call: drop the observable, document the model gap as a separate concern. Also flagged: `min_sysclks=0` left half of calibration band un-set; the 4000-cycle EMU test budget hides infinite-loop bugs; an EMU-side `actual_sysclks` regression assertion would catch pacing drift without silicon.

**Apply-feedback.** Executed devils-advocate's plan:
1. Documented FDEBUG model gap in scenario header (no observable removed — none was present; reviewer's "add" was the wrong call).
2. Set `min_sysclks` to half EMU baseline: rx=33 (half of 67), tx=45 (half of 90). `max_sysclks=2000` retained pre-silicon-calibration.
3. Added EMU-side regression assertions: RX `(60..=80).contains(&cycles)`, TX `(80..=100).contains(&cycles)`.
4. Tightened sled budget 4000 → 500 (~5–7× headroom).

EMU baselines reproduced exactly (RX=67, TX=90). All 657 picoem-harness lib tests pass; both EMU end-to-end tests still pass.

**Silicon calibration: still deferred** until probe-attachment is resolved. Code is in place with tight EMU-side gates and conservative silicon `max_sysclks` that won't false-PASS on a real divergence. Once probe attaches, follow-up commit replaces `min/max_sysclks` with `0.5×/4×` of measured silicon `actual_sysclks` per HLD §4.3.

**Commit.** Pending — committing Stage 3 with calibration deferred. Final calibration to land in a follow-up commit when probe is usable.
