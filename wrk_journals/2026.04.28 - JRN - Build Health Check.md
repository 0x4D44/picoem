## Findings

### Build (cargo build --release)

**Initial run failed** with one hard error:

```
error[E0133]: call to unsafe function `__cpuid` is unsafe and requires unsafe block
   --> crates/mdpicoem-common/src/pacer.rs:158:18
```

**Investigation.** `require_constant_tsc` calls `std::arch::x86_64::__cpuid(0x80000007)`
without an `unsafe` block. The neighbouring `_rdtsc` and `__rdtscp` calls
are correctly wrapped. `git log` shows the bug present since the function
was introduced in `d158246` (Phase 2 extract of `mdpicoem-common`). The
2026-04-27 sessions reported a clean build because the host toolchain
was 1.94.0 nightly, where intrinsic-unsafety enforcement was apparently
relaxed. Stable 1.92.0 catches it correctly.

**Fix** (`crates/mdpicoem-common/src/pacer.rs:158`): wrap the call in
`unsafe { ... }` with a SAFETY comment noting that leaf 0x80000007 is
the AMD/Intel "Advanced Power Management" feature leaf, defined on every
x86_64 CPU.

After the pacer fix the build emitted **one warning**:

```
warning: unused imports: `Command` and `Stdio`
  --> crates/mdpicoem-harness/src/bin/test_helper_job_object.rs:24:20
```

**Investigation.** `Command` and `Stdio` are only used inside the
`#[cfg(windows)]` block; on Linux they are dead. The neighbouring
`gdb_client` import is already gated `#[cfg(windows)]`. Real defect.

**Fix** (`test_helper_job_object.rs:24`): gate the `std::process` import
on `#[cfg(windows)]` to match.

After both fixes: `cargo build --release` is clean, **0 warnings, 0
errors**.

The remaining 80 source warnings break down as:

- **`clippy::needless_range_loop` (~33).** Mostly `for i in 0..N { arr[i] = ... }` in test setup, encoder helpers, and the picogus_diff test corpus. The iter+enumerate alternative is uglier in those sites.
- **`clippy::doc_lazy_continuation` / overindented (×23).** Markdown-formatting nits in deliberately informal doc comments.
- **`clippy::too_many_arguments` (×9).** Test helpers and instruction encoders that take one parameter per hardware-register bit-field. Bundling into a struct hurts call-site readability.
- **`clippy::type_complexity` (×6).** Tuple-return helpers in test setup.
- **`clippy::enum_variant_names` (×4).** Naming conventions matching external APIs (HardFault, BusFault, etc.).
- **`clippy::large_enum_variant` (×2).** Boxing the variant would force indirection on the hot path; the size diff is intentional.
