2. **`spi0_loopback_single_byte` is NOT a `25449db` regression.** `25449db` only touched PWM/PIO0/UART0 scenarios; SPI0 scenario unchanged. Same class of bug as the four `25449db` fixed, just on the SPI0 scenario. **Follow-up (scenario-author lane):** add `PREFIX_SPI0_HARD_RESET` prefix.

3. **`sysinfo_readonly_fields` is NOVEL but trivial** — mismatch on **PACKAGE_SEL** at offset 0x04 (not PLATFORM at 0x08 as I initially assumed). `13598b7` silicon-validated CHIP_ID (0x00) and PLATFORM (0x08) but did NOT re-measure PACKAGE_SEL. Silicon reports 0x1 (probably indicating QFN80 variant), emu returns 0 (SDK RESET literal). **Follow-up:** V13 stage — silicon-validate PACKAGE_SEL and update `crates/mdrp2350/src/bus/peripherals.rs:92` literal.

4. **`isr_ext_irq_timer0_cold` and `isr_ext_irq_masked_pending` are documentation gaps.** Both show +2 cyccnt delta, same exception-entry over-count root cause as `isr_pendsv_cold`/`isr_tail_chain_pendsv_systick` (+3). Not explicitly catalogued in tech_debt.md §"ISR Oracle Residual Cycle Deltas" (which names only the two PendSV cases). No commit in `283920f`/`13598b7`/`25449db`/`73fffbe` touches `core/exceptions.rs`. **Follow-up:** widen tech_debt.md:543-574 bucket from "two PendSV cases" to "four ISR-entry cases with +2 or +3 delta".
