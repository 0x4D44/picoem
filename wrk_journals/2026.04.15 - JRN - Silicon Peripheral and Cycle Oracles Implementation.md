**Aim**: verify that writing `CTRL.SM_ENABLE=0` via probe-rs immediately after BKPT halt freezes PIO cleanly — i.e., a subsequent readback is deterministic regardless of probe-rs transfer latency.

**Approach** (purely probe-rs driven, no firmware needed):
1. Attach + reset_and_halt core 0.
2. Write PIO instruction memory with `jmp 0` (opcode 0x0000) at slot 0.
3. Configure SM0: CLKDIV=1, INSTR reset (force PC=0).
4. Write CTRL.SM_ENABLE=1 to start PIO.
5. Poll-read SM0_ADDR twice with a wall-clock delay; confirm it advances (PIO runs while core halted).
6. Write CTRL.SM_ENABLE=0. Read SM0_ADDR → A1. Wait 10 ms. Read SM0_ADDR → A2.
7. A1 must equal A2. If they don't, the mitigation is insufficient and the HLD's fallback ("self-terminating programs only") applies.
