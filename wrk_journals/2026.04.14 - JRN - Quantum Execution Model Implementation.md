## Agent coordination model

Each stage runs this pipeline:

1. **Implementation agent** — writes the code following the HLD. TDD where
   the change is additive (Stage 2); refactor-with-tests-passing for Stage 1.
2. **Code reviewer agent** — invokes the `code-reviewer` skill on the diff.
3. **Devil's advocate agent** — independent adversarial review: did we miss
   HLD items? Over-engineered? Tests actually covering the new behaviour?
   Any ghost references to deleted APIs?
4. **Apply-feedback agent** — invokes `code-review-apply-feedback` skill to
   act on reviewer + devil's advocate output.
5. **Test/build verifier agent** — `cargo build --release`,
   `cargo test -p mdrp2354`, `qemu_diff` sanity run.
6. **Commit** — supervisor commits the stage once verification is clean.

**Architectural choices:**

1. **Threading `core.cycles` to PPB reads.** HLD offered two options:
   (a) refactor `Bus::read32/write32` signatures to accept
   `core_cycles`, or (b) have the scheduler poke the latest cycle count
   into the PPB. Chose (b) — added `Ppb::update_latest_cycles(u64)` +
   `latest_cycles: u64` field. `Emulator::step()` refreshes before each
   instruction (+ a final refresh after the loop so inter-step test
   inspection sees a current base). One-instruction staleness is
   bounded — much better than the up-to-quantum staleness the HLD
   already accepts in "CYCCNT-vs-clock polling skew" risks. Touches
   exactly one call-site in `lib.rs::step`; zero bus.rs signature
   churn.

2. **SysTick pending mechanism.** HLD pseudocode says
   `core.ppb_pend_systick()` and told me to "check how SysTick is
   currently pended" — the existing `pending_fault` enum only handles
   synchronous faults (UsageFault/MemManage/NMI); there is no
   async-exception dispatch infrastructure. I added
   `Ppb::pend_systick()` which sets **ICSR.PENDSTSET** (bit 26), the
   architectural pending bit per ARMv8-M §B3.2.4. Tests verify this
   bit. A future commit that adds async-exception delivery to
   `CortexM33::step()` will consume ICSR.PENDSTSET — no abstraction
   pre-invented here.

3. **`Ppb::read32` signature change: `&self` → `&mut self`.** Required
   to implement COUNTFLAG read-clears cleanly. Both `Bus::read32`
   callsites (line 732 and 920) are already in `&mut self` methods.
   Test call sites updated to `let mut ppb`. No semantic regression.

**Deviations from HLD:**

- HLD put DWT state "Per-core, on `CortexM33`". Moved to `Ppb`
  because that's where the register read/write path routes via
  `bus.ppb[active_core]` — matches the existing FPCCR/FPCAR/FPDSCR
  pattern. No functional difference; co-location wins.
- Added a single-shot RVR=0 break-out in `systick_advance` per
  ARMv8-M §B11.1 — without it the loop would spin on `rem > cvr=0`
  forever when the caller left RVR=0. Defensive, not in HLD.

**Surprises:**

- First test run had 4 failures because I'd written tests that

  separately by `test_systick_cvr_write_clears_cvr_and_countflag`.
  TDD caught my own test-setup bug.
- `read32(&self) → (&mut self)` cascaded into five pre-existing PPB
  tests needing `let mut ppb`. Small fix.
