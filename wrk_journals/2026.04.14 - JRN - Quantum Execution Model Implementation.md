## Agent coordination model

Each stage runs this pipeline:

1. **Implementation agent** — writes the code following the HLD. TDD where
   the change is additive (Stage 2); refactor-with-tests-passing for Stage 1.
2. **Code reviewer agent** — invokes the `code-reviewer` skill on the diff.
3. **Devil's advocate agent** — independent adversarial review: did we miss
   HLD items? Over-engineered? Tests actually covering the new behaviour?
   Any ghost references to deleted APIs?
4. **Apply-feedback agent** — invokes `code-review-apply-feedback` skill to
   act on reviewer + devil's advocate output.
5. **Test/build verifier agent** — `cargo build --release`,
   `cargo test -p mdrp2354`, `qemu_diff` sanity run.
6. **Commit** — supervisor commits the stage once verification is clean.

**Deviations from HLD the agent made (all sensible):**

1. **HLD pseudocode bug.** Added `!is_wfe_waiting()` to the per-core
   `while` predicate. A WFE-waiting core's `step()` returns early without
   incrementing `core.cycles`, so the loop would spin forever. This is a
   real correctness fix to the HLD itself — the wake-check at quantum end
   only fires after the loop, so WFE cores must be skipped inside the loop.
   Will need to backport to HLD after Stage 2.
2. **Touched `mdrp2354-test-harness/src/lib.rs`.** My scope directive said
   "do not touch the harness". But `run_one_emu_multistep` /
   `run_one_emu_fpu` use `core.step()` (not `execute_one*`) and called
   `core.stall_cycles()`. Once that accessor was deleted, the harness
   wouldn't compile. Agent deleted three drain loops — no semantic effect
   in atomic mode. HLD's "unaffected" claim was incorrect. Backport.

   **Correction (2026-04-14, post-verify):** Devil's advocate's `git blame`
   was right — the drain-loop removal in `mdrp2354-test-harness/src/lib.rs`
   was actually from commit `8548f6c5` (pre-refactor), not this work.
   `git status` at verify time shows the harness unmodified; no harness
   files appear in the Stage 1 diff. The implementation agent either
   re-described a pre-existing change or confused branches. Harness is
   clean and untouched by Stage 1; HLD row "harness: None" was correct.
3. **`pio_test_emulator()` uses `step_quantum(1)`.** Three PIO integration
   tests observe pin state after every `emu.step()` assuming 1
   cycle/step. At default Q=64 they break (GPIO-latency risk from HLD made
   concrete). Agent set the helper's quantum to 1 — minimal, localised,
   preserves exact legacy semantics. HLD did not enumerate these tests.
4. **`tick_mtime_n` honours `mtime_ctrl`.** HLD's literal
   `mtime += n` would regress disabled-counter tests. Agent followed
   existing `tick_mtime` pattern. Correct.

**Surprises:**

- `Clock::advance(n)` already existed; only `tick()` needed deletion.
