## Design Decisions (agreed with Arthur)

1. **Pacer is separate from Emulator** — Emulator stays pure simulation, no wall-clock awareness
2. **Caller owns the run loop** — Pacer provides begin_quantum() / end_quantum()
3. **rdtsc only** — no QPC fallback (Arthur's decision)
4. **Quantum size** — 150 cycles default (1 us at 150 MHz)
5. **Falling behind** — skip spin-wait and log; no catch-up
6. **Monitoring** — Arc<PacerStats> with atomics, monitoring thread from start
7. **Core crate** — Pacer lives in mdrp2354 core crate, no feature flag
8. **Dual-core** — already lockstep single-threaded (correct for cycle-accurate emulation)

## Key Types

- `PacerStats` — AtomicU64 counters (emulated_cycles, emulation_ns, spin_ns, behind_count, running)
- `PacerSnapshot` — plain-value snapshot with derived metrics (utilization, emulated_mhz, headroom)
- `Pacer` — rdtscp calibration, begin/end quantum, spin-wait
