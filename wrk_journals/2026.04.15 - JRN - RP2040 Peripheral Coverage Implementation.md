## Phase 0 Wave 1 — landed 2026-04-15

### 0.A IRQ constants
- `crates/mdrp2040/src/irq.rs` new: 26 `pub const IRQ_X: u32` + `IRQ_COUNT = 26`, cites datasheet §2.3.2 Table 26 and HLD §5.2 `u32`-shift-UB rationale.
- `crates/mdrp2040/src/lib.rs`: `pub mod irq;` added alphabetically.
- Test strengthened per review: collects all 26 constants into a Vec, sorts, asserts equality with `(0..26)`. Catches swapped-pair / duplicate bugs that the earlier `< IRQ_COUNT` assertion missed.

### 0.B CLOCKS `_SELECTED` handshake
- `crates/mdrp2040/src/bus/clocks.rs`: extended with 7 previously-absent clocks (gpout0..3, peri, usb, adc, rtc) — 14 new CTRL/DIV backing fields, offset constants, `_SELECTED` synthesis.
- Glitchless clk_ref/clk_sys pre-existing behaviour preserved (`1 << SRC`).
- Non-glitchless clocks read `1` always, per datasheet §2.15.7 (*"only has one source so just reads 1"*).
- 10 new tests including alias-RMW proof test `alias_rmw_applies_to_new_clock_fields` covering BITSET/BITCLR on a CTRL and a DIV field; existing uniform `apply` closure at `clocks.rs:161` confirmed to route alias correctly for all fields.
- `write32` returns `false` from the new fields (no ClockTree recompute). Current `ClockTree` only carries sys/ref frequencies; Phase 2 UART will need to extend for `clk_peri_hz` — note for then.
- HLD §9.6 originally claimed "zero grep hits for `selected` in bus/clocks.rs" — slightly overstated. Pre-existing code had glitchless mirrors for clk_ref/clk_sys; real gap was the 7 missing non-glitchless clocks.

### 0.G Thumb-32 generator audit (research, no code)
- **Finding**: all 6 M0+ subset encoders (BL, MRS, MSR, DSB, DMB, ISB) already exist in `thumb32_gen.rs`. Only `is_m0plus_safe` at `qemu_diff_m0plus.rs:291-314` needs relaxing.
- Revised effort: **1–3 hours**, not 2 days as V7 §4.1 budgeted.
- **Gotcha flagged by devil's advocate for Wave 3 (0.D)**: existing generator emits MSR/MRS for BASEPRI (sysm=17), FAULTMASK (sysm=19), and banked *_NS aliases (M33-only). If 0.D naively relaxes the filter by encoder category, probe_diff_rp2040 will UNDEF/HardFault on these. **Wave 3 0.D must gate sysm ∈ {16 (PRIMASK), 20 (CONTROL)} when relaxing**.

### Devil's advocate raised (noted, not acted on)
- POR state of `_SELECTED` — emulator always reads 1; silicon may read 0 before first CTRL write. No pico-sdk firmware in our corpus appears to rely on `_SELECTED==0`-before-enable. Accept.
- BL far-range encoder not generated (only ±16/±8). Pre-existing limitation.
- Byte-granularity reads of `_SELECTED` not tested. Out of Phase 0 scope.
