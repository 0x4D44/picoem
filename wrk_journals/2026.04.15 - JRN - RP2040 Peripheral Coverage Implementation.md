### Red-path scenarios renamed for honesty
The V7 HLD §4.4.3 advertised "three deliberately-broken scenarios — one per oracle class". Analysis found only one genuinely diverges (TIMER unmodelled today → EMU returns 0, HW advances). The other two exercised round-trip paths that would PASS on both sides. Renamed:
- `RED_GPIO_WRONG_BIT` → `SMOKE_GPIO_BIT24_ROUND_TRIP` (baseline SIO dispatch smoke)
- `RED_XOSC_SWALLOWED_WRITE` → `SMOKE_XOSC_CTRL_WRITE_ROUND_TRIP` (baseline write-then-read)
- `RED_TIMER_RETURNS_ZERO` → `GAP_TIMER_UNMODELLED` (genuine divergence; will flip PASS once Phase 1 TIMER lands — this IS the Phase 0 red-path-validation witness)

Phase 0 exit criterion 3 interpretation updated: oracle's FAIL path is proven by `GAP_TIMER_UNMODELLED`; the two SMOKE scenarios validate the PASS path. Stretching "three deliberately-broken" to "one deliberate gap + two smoke baselines" is the honest description of what the scenarios actually do.

### Scope

### ADC (adc.rs ~600 LOC, 21 tests)
- Base `0x4004_C000`, RESETS bit 0, IRQ `ADC_IRQ_FIFO=22`.
- Full register surface: CS/RESULT/FCS/FIFO/DIV/INTR/INTE/INTF/INTS.
- clk_adc scaling via fixed-point accumulator: `adc_phase += ADC_HZ(48e6); while adc_phase >= sys_hz { sub-tick; adc_phase -= sys_hz }`. Regression test `clk_adc_scaling_matches_ratio` pins the 125:48 ratio.

- Sample source: deterministic `channel<<8 | counter` pattern.
- START_ONCE self-clears on completion; START_MANY re-arms each cycle.
- FIFO depth 4 with threshold-gated IRQ; UNDER/OVER latched on FCS.
- Byte/halfword narrow dispatch to FIFO for DMA-byte-buffer mode (FCS.SHIFT).

### PWM (pwm.rs ~420 LOC, 21 tests)
- Base `0x4005_0000`, RESETS bit 14, shared IRQ `PWM_IRQ_WRAP=4`.
- 8 slices × 5 regs (CSR/DIV/CTR/CC/TOP at stride 0x14); global EN/INTR/INTE/INTF/INTS.
- Phase 3 cadence: CTR += 1 per sys_clk on enabled slices (ignores DIV fractional; deferred to Phase 4).
- Wrap latches INTR[slice]; shared NVIC line fires via INTE | INTF.
- W1C on INTR.
- Multi-slice concurrent wrap tested.

### Integration

## Phase 4 — landed 2026-04-15

### Scope
DMA bus master per HLD V7 §5.6, §6 Phase 4, Appendix C. Replaces the Phase 1 stub. Corpus: `hello_dma`, `dma_uart`, `audio_i2s`.

### DMA (dma.rs, ~620 LOC, 20 tests)
- 12 channels with full register surface: READ_ADDR/WRITE_ADDR/TRANS_COUNT/CTRL plus trigger aliases (CTRL_TRIG, AL1/AL2/AL3_*_TRIG, MULTI_CHAN_TRIGGER).
- Transfer sizes 1/2/4 bytes, INCR_READ/INCR_WRITE.
- Ring mode: RING_SIZE/RING_SEL address masking `(addr & !mask) | ((addr+size) & mask)`.
- Chain trigger: on TRANS_COUNT→0, if CHAIN_TO != self, reload and re-arm target.
- CH_ABORT: W1 clears BUSY immediately.
- INTE0/INTE1/INTS0/INTS1 with W1C semantics, INTS computed live as `(INTR | INTF) & INTE`.
- IRQ routing: DMA_IRQ_0 (bit 11), DMA_IRQ_1 (bit 12) raised from `(intr & inte0)` / `(intr & inte1)`.
- Flat lowest-channel-first arbitration (HIGH_PRIORITY stored but ignored per V1 scope).
- RESETS bit 2.

### DREQ infrastructure
- `crates/mdrp2040/src/dreq.rs` — 40 sources + `DREQ_FORCE=63` per Appendix C.
- Per-peripheral DREQ accessors: `UartRegs::tx_dreq/rx_dreq`, `SpiRegs::tx_dreq/rx_dreq`, `I2cRegs::tx_dreq/rx_dreq`, `AdcRegs::dreq`, `PioBlock::tx_dreq(sm)/rx_dreq(sm)` (added in `mdpicoem-common`).
- `StateMachine::tx_fifo_full()`, `rx_fifo_empty()` helpers (fields are pub(crate)).
- `Bus::collect_dreqs() -> u64` assembles the full bitmap from all sources before each DMA tick.

### Bus master integration
- `Bus::tick_dma()` uses `std::mem::take` swap pattern per V7 §5.6 (Dma: Default + DmaChannel: Default).
- `Dma::tick(&mut self, bus: &mut Bus)` snapshots DREQs BEFORE issuing transfers.
- Ordering: `tick_peripherals` calls all peripherals first (they produce DREQ), then `tick_dma` last (consumes DREQ) — per V7 contract.
- `all_peripherals_idle` ANDs `dma.is_idle()` to keep fast-path gate correct.
- `Emulator::reset` calls `dma.reset()`.

### Deferrals (documented in code + tech_debt)
- BSWAP, SNIFF_EN, HIGH_PRIORITY: stored in CTRL but ignored.
- CRC sniff.
- Ring across non-aligned base.
- PWM wrap DREQs (24-31): collect_dreqs leaves zero. audio_i2s uses PIO DREQ so corpus unaffected.
- XIP DREQs (37-39): not modelled.
- Timer pacing (TIMER0..3): storage only.
- Per-channel DBG_CTDREQ: reads as 0.
- `trans_count_reload` field is redundant with `trans_count` today; future audit item (flagged in review as M1).
