### 0.G Thumb-32 generator audit (research, no code)
- **Finding**: all 6 M0+ subset encoders (BL, MRS, MSR, DSB, DMB, ISB) already exist in `thumb32_gen.rs`. Only `is_m0plus_safe` at `qemu_diff_m0plus.rs:291-314` needs relaxing.
- Revised effort: **1–3 hours**, not 2 days as V7 §4.1 budgeted.
- **Gotcha flagged by devil's advocate for Wave 3 (0.D)**: existing generator emits MSR/MRS for BASEPRI (sysm=17), FAULTMASK (sysm=19), and banked *_NS aliases (M33-only). If 0.D naively relaxes the filter by encoder category, probe_diff_rp2040 will UNDEF/HardFault on these. **Wave 3 0.D must gate sysm ∈ {16 (PRIMASK), 20 (CONTROL)} when relaxing**.

### Devil's advocate raised (noted, not acted on)

- BL far-range encoder not generated (only ±16/±8). Pre-existing limitation.
- Byte-granularity reads of `_SELECTED` not tested. Out of Phase 0 scope.

## Phase 0 Wave 3 — landed 2026-04-15

### 0.D probe_diff_rp2040
- `crates/mdpicoem-harness/src/bin/probe_diff_rp2040.rs` (replaces stub) — full port of probe_diff_rp2350 targeting `Session::auto_attach("rp2040")`.
- New `is_m0plus_silicon_safe` filter admits the small M0+ Thumb-32 subset: BL (T1), MSR/MRS (sysm ∈ {16=PRIMASK, 20=CONTROL}), DSB/DMB/ISB. Rejects FPU, CBZ/CBNZ, IT blocks, BASEPRI (sysm=17), FAULTMASK (sysm=19), banked _NS aliases (sysm ≥ 0x80), and any other Thumb-32 not on the admit list.
- 12 unit tests including filter regressions (`filter_rejects_basepri_faultmask`, `filter_rejects_banked_ns_aliases`, `filter_admits_bl`, etc.) and 2 emu-side dispatch smokes.
- `qemu_diff_m0plus` filter NOT modified; QEMU cortex-m0 model continues to UNDEF Thumb-32, so that runner stays strict.

### 0.E silicon_periph_diff_rp2040
- `crates/mdpicoem-harness/src/bin/silicon_periph_diff_rp2040.rs` (new, ~700 lines). Local `PeriphScenario` with new `min_sysclks` field.
- SysTick 24-bit window (`SYST_RVR = 0x00FF_FFFF`), soft-assertion timing — window reported but verdict failures only when outside `[min_sysclks, max_sysclks]`. EMU side uses HW-measured window as cycle budget (no DWT on M0+).
- Retry-once on `probe_rs::Error::Probe` / `Timeout` (strict error-kind match, verified this matches the transient set exposed by probe-rs 0.31 — HLD V7 §7 text says "Io/Session" but those variants don't exist in the crate; implementation uses the actually-available transient set).
- RP2040 SIO address layout (4-byte stride, different from RP2350's 8-byte) pinned by `sio_addresses_match_rp2040_layout` test.
- **MUST-FIX bug caught in review**: initial sled bne encoding was `0xD1FE` (infinite self-loop) — every scenario would have timed out. Fixed to `0xD1FD` (loop back 3 halfwords to `subs; bne` start). New `assemble_sled_converges_to_bkpt` test steps the assembled sled through `mdrp2040::Emulator` as a dry-run regression guard.

### 0.F silicon_isr_diff_rp2040
- `crates/mdpicoem-harness/src/bin/silicon_isr_diff_rp2040.rs` + `crates/mdpicoem-harness/src/isr_scenarios_rp2040.rs` (new module).
- `build_image_m0plus` copied from `isr_scenarios.rs::build_image` and simplified to 17-entry vector table (adds TIMER_IRQ_0 at vector[16]).
- 2 scenarios: `isr_m0_timer_cold` (TIMER ALARM0 → handler increments SRAM counter, W1C INTR, BX LR; observe counter==1), `isr_m0_tail_chain_pendsv_systick` (shared handler dispatches on IPSR via `mrs r2, IPSR`; both counters increment).
- Halt strategy: no in-handler BKPT; runner polls primary counter every 5ms with `max_millis` watchdog. Handler returns via BX LR keeping PC state clean.
- **MUST-FIX bug caught in review**: `HANDLER_TAIL[3]` bne encoding was `0xD102` (branches to wrong hw, SysTick counter path broken). Fixed to `0xD101`. Derivation comment rewrote (had cascading offset typos). New `handler_tail_bne_target_is_hw6` decode-and-verify test.

### Red-path scenarios renamed for honesty
The V7 HLD §4.4.3 advertised "three deliberately-broken scenarios — one per oracle class". Analysis found only one genuinely diverges (TIMER unmodelled today → EMU returns 0, HW advances). The other two exercised round-trip paths that would PASS on both sides. Renamed:
- `RED_GPIO_WRONG_BIT` → `SMOKE_GPIO_BIT24_ROUND_TRIP` (baseline SIO dispatch smoke)
- `RED_XOSC_SWALLOWED_WRITE` → `SMOKE_XOSC_CTRL_WRITE_ROUND_TRIP` (baseline write-then-read)
- `RED_TIMER_RETURNS_ZERO` → `GAP_TIMER_UNMODELLED` (genuine divergence; will flip PASS once Phase 1 TIMER lands — this IS the Phase 0 red-path-validation witness)

Phase 0 exit criterion 3 interpretation updated: oracle's FAIL path is proven by `GAP_TIMER_UNMODELLED`; the two SMOKE scenarios validate the PASS path. Stretching "three deliberately-broken" to "one deliberate gap + two smoke baselines" is the honest description of what the scenarios actually do.

### Devil's advocate caught additional concerns (noted for later)
- MSR/MRS filter is pass-by-default within Thumb-32: admits only known-good sysm set, but generator could emit other sysm values in future fuzz extensions — worth defensive tightening when fuzz surface grows.
- SysTick window is ROSC-clocked at emulator reset (~6.5 MHz), not post-bootrom 125 MHz sysclk — scenario min/max values generous enough to accommodate, but name is a mild misnomer.
- Dup code across 0.D/0.E/0.F (retry helpers, register constants) — defer consolidation into `silicon_oracle` until Phase 1 proves more duplication.
