### 2026-04-13 — Stage C feedback applied
- Devils-advocate review flagged a significant gap: SMMUL/SMMLA/SMMLS,
  SMUAD/SMUSD/SMLAD/SMLSD, SMULWB/SMLAWB, SMLAL<x><y>/SMLALD/SMLSLD,
  UMAAL, USAD8/USADA8 were all implemented in `execute_thumb32.rs` but
  had no fuzz coverage.
- Added 14 new encoders in `thumb32_gen.rs` and 5 new fuzz classes
  inside `generate_fuzz_t32_alu` (SMMUL family, dual halfword, word x
  halfword, long halfword, special DSP).
- Test class count went 11 → 16 for T32 ALU, assertion in
  `fuzz_generates_expected_count` updated accordingly (190 → 240
  tests per 10-per-class fuzz run).
- Expanded QADD/QSUB/QDADD/QDSUB edge bias from 4 to 8 values so the
  2*Rn doubling boundary (0x4000_0000 / 0xBFFF_FFFF) is exercised, not
  just the raw int boundary.
- **Tech debt logged** (not fixed per instructions): the existing long
  multiply fuzz (SMULL/UMULL/SMLAL/UMLAL) unnecessarily forces all four
  operand registers distinct. The new long-halfword fuzz block only
  enforces RdLo != RdHi, matching the devils-advocate recommendation.
  Harmonising the older block is a follow-up.
- Build: `cargo build -p mdrp2354-test-harness --release` clean, zero
  warnings. Tests: 114/114 pass. Smoke run
  `qemu_diff --fuzz 100` reports 3264/3300 passed — the 29 failures
  are all pre-existing PARADD / LDM writeback issues, none in the new
  classes.
