### 2026-04-13 — HLD Review

All 5 HLDs returned. Review notes:

**HLD 1 (SDIV/UDIV) — APPROVED.** Clean 2-line fix (rd_lo→rd_hi). Good catch on unit test
encoders in tests.rs also having fields swapped — both must be fixed together.

**HLD 2 (Parallel axes) — APPROVED with guidance.** Preferred approach: restructure the
dispatcher to match par_op2 (modifier) as outer match, pass par_op1 (operation) to
sub-functions. Update 16-bit sub-function match values from (0,1,2,3) to ARM op1 values
(1,2,3,5). 8-bit sub-functions already use correct values (0,4). This avoids an extra
remapping layer.

**HLD 3 (QSUB/QDADD/QDSUB) — APPROVED.** Straightforward operand swap in 3 match arms.
QADD unaffected (commutative). Register extraction is correct — fix is expression-level only.

**HLD 4 (Fuzz xPSR) — APPROVED with note.** Reordering alone may be insufficient if QEMU's
reset sequence has already faulted before GDB connects. Implementation should: write vector
table → issue system_reset via GDB if available → then sanity_check. If system_reset
isn't available, mask IPSR bits [8:0] out of the sanity check.

**HLD 5 (QADD saturation) — APPROVED.** Helper pattern (overflowing_add for Q flag +
saturate for result) is correct. All 6 overflow sites identified. Independent of Fix 3.

Dispatching 5 implementation agents in parallel.

### 2026-04-13 — Implementation & Merge

All 5 agents completed. Each ran /code-reviewer — all passed with no required changes.

**Merge order:** Fix 4 (independent) → Fix 1 (SDIV lines) → Fix 2 (parallel lines) →
Fix 3 (QSUB operands) → Fix 5 (saturation, manual merge over Fix 3).

Fix 5 patch conflicted with Fix 3 (same match arms). Resolved by manually applying
Fix 5's saturation closure on top of Fix 3's corrected operand order.

**Fix 4 iteration:** Initial reorder (vector table before sanity_check) was insufficient
because QEMU's reset sequence reads the vector table BEFORE GDB connects. Added mask
relaxation in sanity_check: changed `0x0600_FC1F` → `0x0600_FC00` to exclude IPSR
exception number bits [4:0]. This is appropriate because the sanity check validates
register indices, not CPU state.
