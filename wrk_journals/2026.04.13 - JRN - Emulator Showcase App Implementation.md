### 2026-04-13 — Phase 2 in flight

**Implementation** — agent delivered full LCD decoder, panel, integration test, and `gen_lcd_demo.py` builder. 7 tests green (3 decoder unit + 2 preset-alias + blinky smoke + new lcd_demo smoke). Clippy and fmt clean.

Generated `roms/lcd_demo.bin` (15,872 bytes). **Caveat:** `roms/` is .gitignored and `roms/*.bin` is excluded, so committing the firmware needs `git add -f`. Flagged for reviewers.

Implementer flags:
- Delay loop at the minimum 300-cycle contract floor (zero margin)
- Hand-rolled Thumb-32 B.W (T4) encoding in the Python builder — fragile spot
- LCD panel is fixed-width 22 cols (no guard for narrow terminals)

Ambiguity resolved: §7.3 "first byte decides". Decoder treats `0x01` / `0x02` as commands (rest of frame as args or ignored), any other first byte treats the whole frame as characters. `emit_cmd_write` sends raw text with no leading command byte.

Dispatched code review and devil's advocate in parallel.

**Reviews** — both reviewers agreed on two critical items and found several gaps:

*Critical:*
1. Wire protocol `0x03` WRITE opcode divergence — LLD reserves 0x03; implementer dropped it and treated "any other first byte" as chars. Fix by conforming code to LLD.
2. `roms/lcd_demo.bin` is `.gitignored` — so are `blinky.bin` and `bootrom-combined.bin`. Phase 1 committed but the binaries aren't in the repo. Integration tests pass locally but a fresh clone would fail. Fix by allow-listing in `roms/.gitignore` and replacing the top-level `roms/` rule with a comment.
3. Delay loop at floor — `DELAY_ITERS=150` produces exactly 300 cycles = 2×quantum. Zero margin. Bump to 200.

*Important:*
4. Integration test assertion too weak ("any non-space byte"). Replace with substring check on "Hello from" and "mdrp2354!".
5. CS-falling edge doesn't reset prior SCLK — latent bit-7 loss for firmwares that idle SCLK high.
6. Cursor transiently (20, 1) between writes — panel reads this. Eager wrap.
7. Unit test gaps: zero-byte frame, SET_CURSOR short/out-of-range, col-wrap-without-scroll, mid-byte abort.

*Positive confirmations from DA:*
- Thumb-32 B.W and STR.W encoders verified byte-for-byte against the Rust reference
- Python builder deterministic (ran twice, identical output)
- All 4 gates clean (DA ran them)
- No GPIO 25 contamination (verified by literal scan of the .bin)
- Firmware size fully accounted for (15,556 bytes of reset code = exact inline expansion)
- Decoder panic-safe on all edge-case frame shapes

**Fixes applied** — apply agent completed all 7 items in one pass. Notably caught that reviewer's literal fix-5 was subtly wrong (would have been overwritten by end-of-sample assignment and produced a phantom bit on CS-falling-with-SCLK-high); implemented a correct variant with a trace-justified regression test.

Tests went from 7 → 15 (8 new LCD unit tests covering all the edge cases). `lcd_demo.bin` grew from 15,872 → 16,896 bytes (+1 KB for the 0x03 opcode bytes and 200-iter delay expansion).

### 2026-04-13 — Phase 3

**Implementation** — agent hit its limit partway through but produced all files before dying. One test failure: `stall_does_not_latch_once_complete` — `report()` returned `None` for a complete-but-empty run. Fixed: added `!self.complete` to the early-return guard (1-line fix, strictly better than the LLD spec).

Second failure: integration test `benchmark_completes_all_six_sections_within_10s` showed 0 sections. Root cause: inter-section phase transitions were overwritten within ~4 CPU cycles (much faster than the 150-cycle quantum), so the poller never observed any "done" phases. Fix: added 300-cycle inter-section delays in the benchmark firmware.
