## Stage 2 — `CoreBus` trait + generic rewiring (2026-04-17)

### What landed

- New `crates/mdrp2350/src/core/bus_trait.rs` with `pub trait CoreBus`
  exposing the 13 canonical methods (LLD V7 §1) plus 11 **transient**
  accessors (`atomics`, `signal_sev`, `sio`/`sio_mut`, `gpio_in`,
  `decode_cache_get/set`, `extra_wait_states`,
  `reset_extra_wait_states`, `trace_enabled`, `emit_trace`). The
  transients exist because state that Stage 3+ migrates off `Bus`
  (DIV/INTERP, decode cache, SIO/GPIO, RCP-via-atomics) is still
  reached via the generic bus in Stage 2. Each transient is
  annotated `TRANSIENT` in the trait doc and is slated for removal
  as state moves onto `CortexM33` or `SharedState` in later stages.
- `impl CoreBus for Bus` at the bottom of `crates/mdrp2350/src/bus/mod.rs`
  — every method is a one-liner forward to an existing inherent
  method or field.
- Added inherent `Bus::take_extra_wait_states(&mut self) -> u32` —
  drain-and-return; backs the canonical trait method.
- `CortexM33::step`, `debug_step`, `decode_execute`,
  `populate_decode_cache`, `execute_thumb16`, `execute_thumb32`,
  `wfe`, `bus_read{8,16,32}`, `bus_write{8,16,32}`,
  `sync_nvic_to_irq_pending`, every `thumb16_*`, every `thumb32_*`,
  every `fpu_*`, every `cp0_*`, every `cp7_*`, `enter_exception`,
  `exit_exception`, `try_take_any_pending_exception`,
  `deliver_fault`, `flush_lazy_fp_context` all became
  `<B: CoreBus>` generic.
- `DecodedOp` changed from `pub(crate)` to `pub` so the trait method
  signatures `decode_cache_get/set` type-check without leaking
  privacy warnings.
- Arc-sharing debug trip-wire moved from `CortexM33::step` to
  `Emulator::step`. A generic `B: CoreBus` can't inspect a non-Bus
  implementor's atomics, so the invariant check lives at the
  concrete-Bus boundary where it compares both cores' Arc against
  the Bus's Arc. Stage 5's `WorkerBus` will establish its own
  setup invariants.
- New unit test `bus_core_bus_impl_covers_all_methods` in
  `bus/mod.rs` exercises every trait method through a
  `&mut dyn CoreBus` coercion (dyn-safety + coverage check).
  Confirms `take_extra_wait_states` returns the added amount and
  drains to zero on second read.

### Deviation from spec

LLD V7 §1 lists exactly 13 trait methods. Stage 2 ships with those
13 plus 11 transient accessors. The deviation is unavoidable while
state that the helpers reach is still on `Bus` — the alternative
(keep helpers concrete on `&mut Bus` while `step` is generic) fails
to compile because `step` calls into the helpers with its generic
bus. The transients are tagged with `TRANSIENT` doc comments; later
stages prune them as state migrates.

### Stage 3 concerns

- DIV/INTERP intercept on `CortexM33::bus_read32/write32` (Stage 3)
  will add a conditional branch to every data-side bus access. The
  monomorphised `step` cost has already landed, so the combined
  perf-sanity check (Phase 0c `paced_bench`) is the right gate.
- Once `PerCoreSio` lands on `CortexM33`, the `sio`/`sio_mut` trait
  methods can be deleted. `bus.gpio_in()` stays until GPIO moves
  onto `SharedState` in Stage 5.
- `decode_cache_get/set` + `extra_wait_states`/`reset_extra_wait_states`
  stay until the decode cache moves onto `CortexM33` (no stage
  assigned yet in the LLD roadmap — flag for the next HLD
  revision if it slips past Stage 5).

### 2026-04-17 — Stage 2 review round

**Review team findings:**

- Code-reviewer (must-fix): **trip-wire coverage hole** — moving the
  Arc-ptr-eq assert from `CortexM33::step` to `Emulator::step`
  opened a gap because 17+ test sites plus all `mdpicoem-harness`
  call `core.step(&mut bus)` directly, bypassing the outer wrapper.
- Devil's-advocate escalated the same concern + confirmed
  `mdpicoem-harness` specifically had never been exercised under
  the Stage 1 trip-wire.
- Both reviewers flagged the 11 transient trait accessors — some
  (`atomics`, `signal_sev`) deletable now by inlining `self.atomics.*`
  at call sites; others (`decode_cache_get/set`) representing real
  architectural debt with the `pub DecodedOp` leak as collateral.

**Applied:**

- Fix 1: trip-wire restored at `CortexM33::step` top using the trait
  accessor `bus.atomics()`; removed from `Emulator::step`.
- Fix 2: validated by running `cargo test -p mdpicoem-harness` in
  debug mode. **5 harness sites fired** (not the 17+ initially
  feared — the fires concentrate in 4 helper chokepoint fns).
- Fix 3: 9 sites migrated to shared-Arc construction. 5 harness
  helpers + 4 coprocessor tests (the latter surfaced by Fix 4's
  inline inference — their `rcp_setup` poked `bus.atomics` while
  the core read `self.atomics`; disjoint-Arc shadow).
- Fix 4: 10 `bus.atomics()` / `bus.signal_sev()` call sites inlined
  to `self.atomics.*`. `CoreBus::signal_sev` deleted. `atomics()`
  retained on trait (needed by the Fix 1 trip-wire).

**Deferred:**

- Fix 5 (decode cache migration to CortexM33) — the devil's-advocate
  estimated ~4 lines / 4 files; the apply-feedback agent surfaced
  the real scope: (a) Bus write paths embed invalidation at 6+
  call sites, (b) moving the cache requires a Bus→core dirty-range
  log + drain protocol, (c) 25+ existing tests probe
  `bus.decode_cache[slot]` directly, (d) `DecodedOp` must stay
  `pub` while the trait methods remain `pub` (since `CoreBus` is
  `pub` via `CortexM33::step`). This is a real micro-phase, not a
  Stage 2 cleanup. **Action: Stage 8 final-verification must
  confirm a plan exists for decode cache migration; add a
  follow-on micro-phase if the LLD roadmap hasn't scheduled it.**
