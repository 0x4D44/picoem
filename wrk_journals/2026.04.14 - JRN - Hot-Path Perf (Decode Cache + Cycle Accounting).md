# Journal: Hot-Path Perf — Decoded-Op Cache + Cycle-Accounting Short-Circuit

**Date:** 2026-04-14
**Supervisor:** Claude (Opus 4.6) — team lead
**Goal:** Improve `paced_bench_rp2350 --workload basic` throughput from current ~38 MHz baseline toward 150 MHz, by attacking the per-instruction fetch+decode+cycle-bookkeeping tax.

## Scope

Two optimizations, scoped tightly:

1. **PC-keyed decoded-op cache.** Skip `bus.read16(pc)` (full bus-path fetch) + re-dispatch through the Thumb-16/32 match trees on every instruction. Cache the work keyed by PC. Invalidate on writes to executable regions.
2. **Short-circuit cycle accounting.** Stop calling `bus.reset_extra_wait_states()` / `bus.extra_wait_states()` on every instruction. Fold base cycles into the cached op; only take the slow path when an access actually adds wait states.

Out of scope (deferred): basic-block cache, peripheral-regs HashMap replacement, hot-path dispatcher specialization, threading.

## Pipeline

1. **Baseline** — supervisor runs `paced_bench_rp2350 --unpaced --seconds 5 --workload basic` on `master` (no changes). Record MHz + host-cycles/emu-cycle.
2. **HLD phase (parallel)** — two agents write one HLD each:
   - Agent A: decoded-op cache (data structure, invalidation model, hit/miss paths).
   - Agent B: cycle-accounting short-circuit (how to fold `base_cycles` into the cached op; fast/slow path decision).
   Both agents briefed on the shared `DecodedOp` struct so fields converge. Supervisor reviews, sends feedback, iterates until signed off.
3. **Implementation phase (sequential, single worktree)** — Agent A lands the cache first (defines the shared struct and hit path). Agent B layers cycle-accounting short-circuit on top.
4. **Review phase** — each implementation invokes `/code-reviewer`, feedback applied via `/code-review-apply-feedback`.
5. **Verify** — `cargo test -p mdrp2350`, `cargo test -p mdpicoem-harness --tests` if relevant, then re-run `paced_bench_rp2350` to measure speedup.
6. **Close** — supervisor writes final perf delta and sign-off here.

Supervisor stays supervisory: no implementation code, just review + coordination.

## Quality gates

- `cargo test -p mdrp2350` — zero regressions
- `paced_bench_rp2350 --workload basic --unpaced --seconds 5` — MHz strictly higher than baseline
- `cargo build --release` — warnings-clean
- Cycle-accuracy preserved: the cached base_cycles must equal what the slow path would compute; slow path must still run when any extra wait state is possible.

### 2026-04-14 — Agent A HLD v1.0.0 received

`wrk_docs/2026.04.14 - HLD - Decoded-Op Cache.md` (562 lines, 13 sections).

**Initial supervisor read:**

Design choices I'd sign off:
- Direct-mapped 16384-entry table on `Bus`, indexed by `(pc >> 1) & 0x3FFF`, full-PC tag. Correct rejection of per-region tables (3 dispatches on hot path) and HashMap (hash cost > `read16` for this loop).
- Placement on `Bus`, not per-core — shared hits across cores are the right call; threading concerns are future work.
- `#[cold] #[inline(never)]` on the populate path — keeps the hit-path prologue tight.
- Preserving the `execute_one*` test entry points untouched.
- **`fetch_wait: u8` field.** This caught a real cycle-accuracy regression I'd missed: `Bus::read16` on SRAM bank 2/6 charges +1 wait state via `sram_bank_wait`, and a naive cache hit would silently drop it. The HLD's solution (capture on populate, re-add on hit via `bus.add_extra_wait_states`) preserves it exactly.
- Packed `flags: u8` with `is_pure` bit reserved for Agent B, always 0 in Agent A's populate path. Clean contract.

Minor feedback I'll bundle with Agent B's review before sending both:

2. **Q2 (16384 vs 8192):** stick with 16384. Reasoning matches ROM-halfword 1:1 mapping; 192 KB is not meaningful next to existing `Bus` state.
3. **Q3 (struct name):** `DecodedOp` is fine.
4. **Q4 (base_cycles in struct):** wait for Agent B's HLD. If B wants it, bump struct to 16 B.
5. **Q5 (qemu_diff gate):** strengthen to an explicit `cargo run --bin qemu_diff_m33 --release -- --fuzz 10000` gate — short enough to run routinely, long enough to catch classes of regressions the unit tests miss.

### 2026-04-14 — Agent B HLD v1.0.0 received

`wrk_docs/2026.04.14 - HLD - Cycle Accounting Short-Circuit.md` (462 lines).

**Key design elements I sign off:**
- **Dual-condition `is_pure` definition** — no `bus.readXX/writeXX` AND no `deliver_fault`/`enter_exception`. The fault clause is correct: synchronous stacking goes through `bus.write32` ×8, which would silently leak wait states past the fast-path boundary.
- **All FPU ops impure** — because `fpu_execute` unconditionally gates on `FPCCR.LSPACT` and may call `flush_lazy_fp_context` (18 bus writes). State-dependent purity would defeat the fast-path savings; blanket impure costs nothing on integer-heavy workloads.
- **All coprocessor dispatches impure** — removes CPACR-state dependency.
- **Delta-check assert (`ws_before` vs `ws_after`)** — not `==0`, because residue from a previous slow-path instruction legitimately persists. This is the right oracle. Keep it.
- **Thumb-16 / Thumb-32 classification tables** — enumerated per-op. Matches the source.

### 2026-04-14 — Supervisor consolidated sign-off

Both HLDs are approved as v1.0.0 with the following supervisor notes reconciling minor gaps between them. The implementation agent should treat this section as authoritative where it adjusts either HLD.

**Naming reconciliation:**
- HLD A field: `fetch_wait: u8`. HLD B request: `fetch_wait_states: u32`. **Keep Agent A's `fetch_wait: u8`** — max observed value is 2 (wide instruction, both halves in bank 2/6); u8 is ample. Agent B's field is satisfied.

**Fast-path `fetch_wait` accounting:**
- HLD B §3 pseudocode omits the fetch-wait charge on the pure path. **The fast path must add `entry.fetch_wait as u32` to the returned cycle count** — directly, not through `bus.extra_wait_states`. This preserves bank 2/6 SRAM fetch accuracy without touching the accumulator:

  ```rust
  if entry.is_pure {
      // fetch cost is already baked into entry.fetch_wait; don't touch accumulator
      self.regs.set_pc(pc + (if is_wide { 4 } else { 2 }));
      let cycles = if cond_passed {
          if is_wide { self.execute_thumb32(hw0, hw1, bus) } else { self.execute_thumb16(hw0, bus) }
      } else { 1 };
      // IT / flag-only handling as today
      #[cfg(debug_assertions)] assert_ws_unchanged;
      cycles + entry.fetch_wait as u32
  }
  ```

**No dispatch-method split:**
- HLD B §3 proposes `self.dispatch_pure(entry)` / `self.dispatch_impure(entry, bus)` — **don't do that**. Refactoring every `thumb16_*` / `thumb32_*` handler's signature is out of scope. Keep the existing handlers. The pure/impure branch lives in `decode_execute`'s control flow only. Handlers on the pure path still take `&mut Bus`; by classification, they simply don't call `bus.readXX/writeXX`. The debug-assert is the correctness check.

**No `entry.size` or `entry.op` fields:**
- Use the existing `is_wide` bit (HLD A `flags` bit 0) to compute PC increment (`2` or `4`). The debug-assert's error message should format `hw0/hw1` from the cache entry directly, not a non-existent `entry.op`.

**Classification populate path:**
- A new free function `fn classify_is_pure(hw0: u16, hw1: u16, is_wide: bool) -> bool` in `core/decode.rs`, sourced from HLD B's tables. Called from Agent A's `populate_decode_cache`. Single source of truth.

**Answers to Agent A's open questions:**
- Q1 (poke hook): defer for v1.0.0. Add a public `bus.invalidate_all()` helper as the escape hatch. Document in rustdoc that `Emulator::poke` bypasses the cache and callers must call `invalidate_all` between poke and `step` when poking executable memory.
- Q2 (cache size 16384 vs 8192): 16384.
- Q3 (struct name `DecodedOp`): fine as-is.
- Q4 (base_cycles field): not needed per Agent B's §9. Keep struct at 12 B.
- Q5 (qemu_diff gate): mandatory gate — `cargo run -p mdpicoem-harness --release --bin qemu_diff_m33 -- --fuzz 10000` must exit clean. Adds ~2–3 minutes; acceptable.

**Sequencing:**

- Post-implementation: `/code-reviewer` skill, then `/code-review-apply-feedback`, then verifier (tests + bench + qemu_diff fuzz gate).
