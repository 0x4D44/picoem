### B1 — `test_silicon` threading fix (completed, 2026-04-16 ~20:20 UTC)

**Root cause:** Windows WinUSB/nusb USB handles are thread-affine. probe-rs's `Session` is marked `Send` at the Rust type level, but moving it into a worker thread via `thread::spawn` crosses the OS-level thread affinity boundary, causing `session.core(0)` to fail at runtime. Standalone oracles don't hit this because they keep Session on main thread throughout.

**Fix:** removed the worker-thread + watchdog model. `run_oracle_against` wrapper and `WorkerResult` deleted. `run_one_oracle` now called directly with `&mut session` on the calling thread in both `single_pass` and `soak_loop`. ~90 lines removed, ~15 added.

**Tradeoff:** per-oracle 60s watchdog gone. probe-rs has its own USB-level timeouts; wedge recovery in soak runs may require a signal-handler approach later if it becomes an issue.

**Collateral work:** B1 also corrected two array-size typos in `silicon_scenarios.rs` (lines 1677 `[u16; 48]`→`[u16; 64]` and 1809 `[u16; 48]`→`[u16; 49]`) that were blocking compilation. These looked like in-flight C1 work — **will need to verify C1 doesn't stomp them**.

## Stage C.1 — sled + emulator chain re-arm fix (2026-04-17 ~00:30 UTC)

Dispatching focused agent.

### Outcome (2026-04-17 ~01:00 UTC)

Major finding: the silicon-runner's "CHAIN_TO=self causes re-arm" diagnosis was wrong. Real root cause: **RP2350 CTRL adds INCR_READ_REV at bit 5 and INCR_WRITE_REV at bit 7, shifting all higher fields up by 2 bits vs RP2040.** The emulator was using RP2040 positions internally; sleds were written with RP2040 layout. On silicon, `0x001F_8039` decoded as TREQ_SEL=15 (PIO0_RX3, never asserted) instead of 63 (FORCE) — DREQ never fired, BUSY never cleared.

Fix: corrected all 6 CTRL constants (INCR_WRITE 5→6, RING_SIZE 6→8, RING_SEL 10→12, CHAIN_TO 11→13, TREQ_SEL 15→17, IRQ_QUIET 21→23) + added 2 new INCR_*_REV constants + 3 sled CTRL value updates (`0x001F_8039`→`0x007E_0059`, `0x001F_8839`→`0x007E_2059`, `0x001D_8039`→`0x0076_0059`) + new `ctrl_field_positions_rp2350_not_rp2040` regression test. 1320 unit tests pass. Committed as `a7266bf`.

### Silicon re-verification (2026-04-17 ~01:30 UTC)

Symptom evolved but didn't resolve. CTRL_TRIG write now accepted, BUSY=1 latches — but BUSY never clears. Hypothesis: silicon DMA needs bootrom-phase init (PSM, ACCESSCTRL, BUSCTRL, or clock tree) that `reset_and_halt` short-circuits. PIO sleds work because PIO doesn't need the AHB bus-master path.

Arthur approved Option A: commit C as-is, hand off to Stage C.2.
