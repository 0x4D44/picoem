## Known limitations (documented, not blockers)

- **Assumption 1 unverified on silicon**: `smoke_per_core_cyccnt_rp2350`
  must be run before `silicon_dualcore_diff_rp2350` measurements can be
  trusted. Arthur's job; can't be exercised in CI.
- **tech_debt.md:295 not retired**: `CortexM33::step` does not poll
  `ICSR.PENDSVSET`/`PENDSTSET`, so all four ISR scenarios are EXPECTED
  to FAIL on the EMU side until that gap is closed. The ISR oracle is
  the bug-surfacing tool for it; documented in module docstring and
  binary banner.
- **Bank-conflict halt-step**: kept as the only modality that exposes
  the +1 SRAM bank-contention cycle (devil's-advocate caught that
  K-delta sequence-in-loop masks the signal per `tech_debt.md:545-554`).
- **`clock_div_change_pio_running`** observes only CLK_SYS_DIV register
  survival, not PIO progress ratio, because the emulator's PIO advances
  one sysclk per `step_quantum` independent of `clock_tree.sys_clk_hz`.
  HLD warned about this in §"Cycle-vs-frequency semantics"; gap noted
  inline pointing at `mdpicoem-common/src/pio/mod.rs:143`.
- **EMU ICSR write semantics** are bare assignment, not W1S/W1C — will
  need fixing before tech_debt #295 dispatch lands so the ISR oracle's
  diff is interpretable. Documented in `isr_scenarios.rs` module header.

## Devil's-advocate ROI

Six review cycles, six load-bearing finds:
- Stage 1: smoke binary's symmetric design couldn't distinguish per-core
  from aliased CYCCNT.
- Stage 2: K-delta bank-conflict recast silently deleted the +1
  contention signal already documented at `tech_debt.md:545-554`.
- Stage 3: shuffle-by-filter trick fired `reset_and_halt` between every
  case, defeating cross-oracle leakage detection (HLD's core soak design
  rationale).
- Stage 4: `clock_div_change_pio_running` SM_ADDR observable was a
  false-PASS — emulator PIO doesn't honour sys_clk frequency.
- Stage 5: bank "control" case had core 1 antagonist in bank 0,
  contaminating the same-vs-diff bank contrast.
- Stage 6: hand-assembled Thumb encoding error in `MAIN_LAZY_FP[9]`
  fired NMI instead of PendSV in two scenarios.

Standard code-reviewer caught real issues each pass too, but devil's-
advocate consistently surfaced the structural / load-bearing problems
the standard reviewer treated as nits or didn't see at all. The
two-reviewer pattern is paying for itself.
