## First QEMU Differential Run — 2026-04-13

**Targeted tests:** 719/746 passed (96.4%), 27 failures, 0 skips
**Fuzz tests:** Blocked by xPSR sanity check failure at startup

Full triage saved to `notes/qemu_diff_first_run.txt`.

### Findings (7 categories, ordered by severity)

1. **SDIV/UDIV wrong destination register** (15 failures, HIGH)
   `execute_thumb32.rs:1157-1170` — writes quotient to `rd_lo` (hw1[15:12] = 0xF = R15/PC)
   instead of `rd_hi` (hw1[11:8] = actual Rd). PC gets corrupted, R0 stays 0.

2. **Parallel add/sub op1/op2 axes inverted** (4 failures, HIGH)
   `execute_thumb32.rs:1491-1614`, `thumb32_gen.rs:776` — ARM spec uses hw0[6:4] for the
   base operation (add/sub/asx/sax) and hw1[6:4] for the modifier (signed/Q/halving/unsigned).
   Emulator and test generator have these reversed. Confirmed by Capstone disassembly:
   "SSUB16" encodes UNDEFINED, "UADD8" encodes SSUB8, "QADD16" encodes SASX, etc.
   Passing tests (SADD16, SADD8, USUB8) work only because their op values are
   coincidentally correct under either convention.

3. **QSUB/QDADD/QDSUB operand swap** (5 failures, HIGH)
   `execute_thumb32.rs:1316-1334` — ARM spec: QSUB Rd = sat(Rm - Rn).
   Emulator: Rd = sat(Rn - Rm). Same inversion for QDADD/QDSUB doubling operand.

4. **Fuzz xPSR sanity check blocks fuzz run** (infrastructure, HIGH)
   `qemu_diff.rs:97-100` — sanity_check() runs before setup_vector_table(), so QEMU
   may be in HardFault. Exception number bits in IPSR may also be sticky (GDB can't clear).

5. **QADD saturation wraps instead of clamping** (2 failures, MEDIUM)
   `execute_thumb32.rs:1297-1303` — known issue.

6. **MRS BASEPRI test can't set precondition** (1 failure, LOW)
   `thumb32_gen.rs:4234` — TestCase lacks system register preconditions.

7. **LDM Rn-in-list address delta** (1 failure, LOW)
   `lib.rs:3025` — loaded value contains address-space base; delta comparison can't normalise.
