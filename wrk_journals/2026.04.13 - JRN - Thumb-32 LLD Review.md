# 2026.04.13 — Journal — Thumb-32 LLD Review Session

## Goal
Iterative team review of the Thumb-32 LLD until no critical issues remain.

## Review Rounds

### Round 1 (V0 → V1)
Three reviewers: architecture/correctness, simplicity, devil's advocate.

**Critical bugs found in V0:**
1. Long multiply/divide misrouted to coprocessor (op2 & 0x40 vs op bit)
2. SP banking ignores handler mode
3. PLD/PLI (Rt=1111 loads) would corrupt PC

**Simplification recommendations adopted:**
- Prerequisites demoted from "blocking" to "implement when needed"
- Rigid 5-tier system replaced with demand-driven priority list
- 5-file split replaced with 1 file, split later
- Cycle timing table slimmed to essentials
- Coprocessor trait dropped for plain match
- Open questions section removed

### Round 2 (V1 → V2)
One combined reviewer checking all V0 critical fixes.

**Found the op1=11 decode tree was STILL wrong in V1:**
- V1 checked op (hw1[15]) to distinguish multiply from coprocessor, but
  hw1[15] is the Ra register MSB for multiply instructions, not a dispatch bit
- V1 routed ALL op2[6]=0 to load_store_single, missing dp_register/multiply/long_multiply
- Load/store size field was at wrong bit position (hw0[10:9] → hw0[6:5])

### Round 3 (V2 verification)
Assembler-verified encoding agent traced 15 instructions through the tree.
Confirmed correct dispatch for op1=10 and op1=11.

One false alarm for op1=01 (STMIA routing) — the agent computed op2=0x14
for hw0=0xE8A0, but the correct value is op2=0x0A. Supervisor independently
verified: (0xE8A0 >> 4) & 0x7F = 0x0E8A & 0x7F = 0x0A. V2's `op2 & 0x04`
test is correct.

### Key insight for op1=11 (the bug that survived two revisions)
The `op` bit (hw1[15]) is NOT used for top-level dispatch in the op1=11
group. For multiply instructions, hw1[15] is the MSB of the Ra field.
The coprocessor/non-coprocessor split is entirely on op2[6] (hw0[10]).
Within op2[6]=0, the sub-dispatch uses op2[5], op2[4], op2[3] progressively.

### Round 4 (Supervisor personal review, V2 → V2.1)
Read every line of V2 myself, traced bit fields against actual encodings.

**Bug found:** Load/store single sign field wrong: `(hw0 >> 9) & 1` should be
`(hw0 >> 8) & 1`. Verified: LDRSB hw0=0xF990 has hw0[9]=0 but hw0[8]=1.
hw0[9] is always 0 within load_store_single (consumed by top-level dispatch).

**Gaps found and addressed:**
- Branch_misc sub-dispatch (BL vs B.W T3 vs T4 vs misc) not documented → added
- B.W T3 uses J1/J2 directly (no XOR trick, unlike T4/BL) — important to note
- Undefined opcodes within dp_modified_imm not mentioned → noted
- CBZ/CBNZ missing from Thumb-16 implementation → documented as known gap
- IT flag suppression save/restore approach → added as recommended implementation

**Also verified correct:**
- ThumbExpandImm algorithm (traced 0x100 rotation and 0xFF00FF00 replication)
- IT state machine advance logic (traced ITTE EQ 3-instruction block)
- Shifted register shift_amount extraction (imm3:imm2)
- B.W T3 offset formula (21-bit, J1/J2 direct)

## Final Status
- V0: initial draft, 3 critical bugs
- V1: fixed 2 of 3 criticals, introduced new decode tree bugs
- V2: decode tree verified, but sign-bit field wrong
- **V2.1: all known issues resolved** — sign bit fixed, sub-dispatch documented,
  Thumb-16 gaps noted, IT implementation approach added
