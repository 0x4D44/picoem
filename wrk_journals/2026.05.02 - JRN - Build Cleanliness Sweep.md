## Findings

### 1. `cargo build --release` — one real warning

```
warning: unnecessary `unsafe` block
   --> crates\mdpicoem-common\src\pacer.rs:160:18
160 |     let result = unsafe { std::arch::x86_64::__cpuid(0x80000007) };
```

**Root cause:** `std::arch::x86_64::__cpuid` was made safe-to-call in stdlib at some point before 1.94; the cpuid instruction is unconditionally available on x86_64 and the call has no memory side effects. The wrapping `unsafe` block is now unnecessary, and the `// SAFETY: …` comment no longer documents anything load-bearing.

**Fix:** drop both. Bumped `mdpicoem-common` 0.1.1 → 0.1.2.

22 files had drifted from `rustfmt 1.94.0` defaults — pure formatting deltas (e.g. inline-able `assert_eq!`, redundant `.into_iter()`, hex group-grouping). Mechanical `cargo fmt --all` resolved everything; release build re-verified clean.

#### Pass A — `cargo clippy --fix --all-targets --all-features`

Mechanical auto-fix dropped the count to 111. Substantive deltas:
- `manual_contains` collapsed `iter().any(|&b| b == x)` → `<slice>.contains(&x)` in two LCD test files.
- `chain(mem.into_iter())` → `chain(mem)`.
- `assert_eq!(name.is_empty(), false, ...)` → `assert!(!name.is_empty(), ...)`.
- `a.clone()` on `Copy` type → `a`.
- Nested `if let Some(x) { if cond { ... } }` collapsed into let-chains in three harness loop bodies and one `Emulator::apply_pending_panic_inject` path.
- `(i as u32) * 4` → `i * 4` in mdrp2350 stage2 FP-stack test (i was already u32 by inference from `wrapping_add`).

Auto-fix overstepped on **four classifier-encoding tests in `core/decode.rs`** and the **`exec_mret_with_mpp_zero_rounds_to_m`** RISC-V test. It stripped the explicit `| (0b00 << 11)` / `| (0b0000 << 8)` zero-field OR terms that document the encoding fields. The literal value is unchanged but the documentation value is lost. Restored these with targeted `#[allow(clippy::identity_op, clippy::erasing_op)]` so the field documentation stays visible.

Crate version bumps from this pass: mdpicoem-devices 0.1.0→0.1.1, mdpicoem-harness 0.38.0→0.38.1, mdrp2040 0.1.1→0.1.2, mdrp2350 0.1.2→0.1.3, mdrp2350app 0.1.0→0.1.1.

#### Pass B — manual fixes (4 categories, 10 sites)

- **`field_reassign_with_default`** (3 sites in `mdrp2350/src/tests.rs`): collapsed `let mut ppb = Ppb::default(); ppb.x = ...` into `Ppb { x: ..., ..Ppb::default() }` struct-update syntax.
- **`assertions_on_constants`** (3 sites in `mdpicoem-harness/src/riscv_gen.rs`): converted `assert!(SCRATCH_BASE >= 0x8000_0000)` into `const _: () = assert!(...)` so the address-map constraint is checked at compile time, not per test invocation.
- **`doc_lazy_continuation`** (1 paragraph spanning 3 lines in `ieee754_ref.rs`): added a blank-line separator so the IOC clarification paragraph isn't read as part of the preceding bullet list.
- Added the missing `clippy::identity_op` to the existing `clippy::erasing_op` allow on `tests_p5.rs:1730` (both fire on `(1 << 7) | (0b00 << 11)`).

#### Pass C — categorical workspace `[lints.clippy]`

The remaining warnings (most of the 111 → 0 delta) fell into six categories that are systematically misaligned with cycle-accurate emulator code. None reveal real defects — they're style lints arguing against well-justified code. Configured them as `allow` in workspace-level `[lints.clippy]` with a comment per entry explaining why:

| Lint                       | Why allowed in this workspace                                      |
|----------------------------|--------------------------------------------------------------------|
| `unusual_byte_groupings`   | ARM/RISC-V ISA bit-field literals like `0b11110_0_111000_0000`     |
| `needless_range_loop`      | Register/IRQ/pad indices are themselves the semantic value         |
| `too_many_arguments`       | Coprocessor / GDB-stub / SWD callback signatures                   |
| `type_complexity`          | Dense callback / scaffolding signatures in tests                   |
| `large_enum_variant`       | Intentional stack-allocated `Cores` and paced-bench `Runtime`      |
| `enum_variant_names`       | ARM exception names (`HardFault`, `UsageFault`) and RISC-V opcodes |

Each crate gained a `[lints] workspace = true` stanza so the policy applies. Care was taken to keep the `[lints]` block *outside* the `[package]` table — first attempt put it between `documentation` and `readme`, which TOML parses as `[lints] workspace = true; readme = ...; …`, throwing `invalid type: string "README.md", expected a map`. Repaired by moving each `[lints]` block past all `[package]` keys.

## Notes for future-me

- The `epio-sys` clang dependency means `cargo clippy --workspace` will always fail on hosts without clang. Always use the un-flagged form (`cargo clippy --all-targets --all-features`) which respects `default-members`. `--workspace` is only correct on a clang-equipped CI host with the vendored submodules cloned.
- The two `decode.rs` classifier tests (`t16_misc_group_dispatches`, `t32_op1_01_load_store_dual_is_impure`, `t32_op1_11_load_store_single_is_impure`) and the RISC-V `exec_mret_with_mpp_zero_rounds_to_m` test now carry `#[allow(clippy::identity_op, clippy::erasing_op)]` annotations documenting that the OR-with-zero fields are deliberate encoding-field documentation. If a future `cargo clippy --fix` strips them again, restore via the pattern in this commit, not by deleting the documentation.
- The workspace lint allowlist is ISA-emulator-specific. If a future contributor extracts a generic crate from this workspace they should consider whether each `allow` still applies in that context.
