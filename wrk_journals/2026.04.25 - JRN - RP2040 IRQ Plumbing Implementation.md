# 2026.04.25 — JRN — RP2040 IRQ Plumbing Implementation

Implementation journal for the design at `wrk_docs/2026.04.25 -
HLD - RP2040 IRQ Plumbing V5.md` (V5 supersedes V1–V4).

## Supervision shape

- **Implementer** agents — write code per stage spec; TDD where
  possible (unit tests first, then implementation).
- **Code-reviewer** agent (using the `code-reviewer` skill) —
  reviews implementer's diff.
- **Devil's-advocate** agent — challenges reviewer's review,
  surfaces missed assumptions and silent-divergence cases.
- **Code-review-applier** agent (using `code-review-apply-changes`
  skill) — applies reviewer + devil's-advocate feedback.

Supervisor (this journal's author):

- Does not write code, run tests, or debug.
- Spawns agents, sets briefs, tie-breaks controversial decisions.
- Maintains this journal — one entry per stage gate, plus
  blocker / decision entries inline.
- Commits after each stage.

## Method

Each stage follows this pattern:

1. **Implementer** spawned with the stage spec + V5 reference. TDD
   when the unit-test surface is small enough.
2. After implementer reports done, spawn **code-reviewer** +
   **devil's-advocate** in parallel.
3. Aggregate findings; tie-break.
4. **Code-review-applier** applies any CRITICAL / MAJOR fixes.
5. Re-review if substantial changes.
6. Commit. Update journal. Mark task completed.

- Code-reviewer (agent a524748344c24bc24): no CRITICAL or MAJOR.

- Devil's-advocate (agent a8e1d627c6486cab2): **two CRITICALs**
  the spec itself missed:
  1. Threaded SysTick ticks per *instruction*, not per *cycle*.
     `core.step()` returns N cycles for one instruction; ticking
     SysTick once decoupled the SysTick rate from the master
     clock. `LDM r0,{r1-r7}` (8 cycles) → 1 SysTick tick.

     activity after preamble.

  either because the spec was followed faithfully.

**Diagnostic (agent afbec0d63bbc3618e).** Two distinct root causes:

1. **TIMER held in reset by default.** `Bus::new()` defaults
   `resets.state = RESET_MASK = 0x01FF_FFFF` (`bus/resets.rs:18`),
   which includes bit 21 = RESET_TIMER (`peripheral_dispatch.rs:39`).
   `Bus::peripheral_write32` short-circuits when held in reset
   (`bus/mod.rs:761-763`). MAIN_TIMER's writes to ALARM0 / INTE /
   NVIC_ISER0 silently dropped → no fire ever scheduled →
   `ctr_timer` stays 0 → cycle budget exhausts. V7 §5.3 explicitly
   says emulator should default to "post-bootrom state" with
   commonly-used peripherals released — this is a pre-existing
   gap, surfaced by the V1 oracle's first real EMU-side test.
2. **HANDLER_TAIL SysTick re-fires during handler before disable
   lands.** Period RVR+1=5 cycles, handler runtime to disable at
   hw[13] is ~22 cycles. SysTick fires 3-4 times during handler
   body, latching ICSR.PENDSTSET. Dispatcher correctly clears
   PENDSTSET on initial dispatch, but level-pending re-asserts
   from the periodic SysTick fires. After handler exits with
   PENDSTSET still latched, `exit_exception`'s tail-chain poll
   dispatches SysTick a SECOND time → ctr_systick = 2.
   V5 §11's analysis missed this — the disable-late race is
   real.

**Diagnostic 2 (agent ab4d2c40b1dd3ad62).** Same shape as Failure
2 but for TIMER. `peripherals/timer.rs:214` has a level-reassert
path that ORs `(intr & inte)` into NVIC every `tick_peripherals`
cycle. Between dispatch (which clears NVIC.pending bit 0) and the
handler's W1C of TIMER.INTR, several slow-path cycles re-pend NVIC.
After handler exits, NVIC.pending bit 0 is set → re-dispatch →
ctr_timer = 2. The level-reassert behaviour is silicon-faithful
(real ARMv6-M NVIC is level-sensitive); the canonical mitigation
is the pico-sdk firmware pattern of W1C-INTR-FIRST + NVIC_ICPR
clear in the handler.
