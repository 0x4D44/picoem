## Supervision shape

- **Implementer** agents — write code per stage spec; TDD where
  possible (unit tests first, then implementation).
- **Code-reviewer** agent (using the `code-reviewer` skill) —
  reviews implementer's diff.
- **Devil's-advocate** agent — challenges reviewer's review,
  surfaces missed assumptions and silent-divergence cases.
- **Code-review-applier** agent (using `code-review-apply-changes`
  skill) — applies reviewer + devil's-advocate feedback.

Supervisor (this journal's author):

- Does not write code, run tests, or debug.
- Spawns agents, sets briefs, tie-breaks controversial decisions.
- Maintains this journal — one entry per stage gate, plus
  blocker / decision entries inline.
- Commits after each stage.

## Method

Each stage follows this pattern:

1. **Implementer** spawned with the stage spec + V5 reference. TDD
   when the unit-test surface is small enough.
2. After implementer reports done, spawn **code-reviewer** +
   **devil's-advocate** in parallel.
3. Aggregate findings; tie-break.
4. **Code-review-applier** applies any CRITICAL / MAJOR fixes.
5. Re-review if substantial changes.
6. Commit. Update journal. Mark task completed.
