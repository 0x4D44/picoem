# 2026.04.17 — JRN — RP2350 Peripheral Coverage Audit

## Goal

Produce an honest, evidence-based coverage audit of the mdrp2350 emulator
against the RP2350 datasheet peripheral set. Deliverable: a gap map that we
can prioritise future work against.

**Trigger**: after the V5 Gap Fill closed (6 commits, `a1f4f80..6919c19`),
Arthur asked: "so we've implemented all the peripherals?" — and I
overreached by saying yes. This audit is the penance: verify properly.

## Method

Agent team:

1. **Emulator surveyor** — walks `crates/mdrp2350/` and enumerates every
   peripheral base address that is bus-decoded, with a fidelity grade
   (full / partial / stub / warn-only / not modelled). Output is a table
   keyed by base address.
2. **Datasheet extractor** — compiles the authoritative RP2350 peripheral
   list from the repo (HLDs, code comments, datasheet references). Output
   is a table keyed by base address with peripheral name + short function.
3. **Gap synthesizer** — cross-references (1) and (2). Produces the final
   audit matrix: for every datasheet peripheral, what's the emulator's
   state. Highlights blockers.
4. **Devil's advocate** — challenges the whole exercise. Are we even
   looking at the right thing? What non-peripheral gaps are we hiding?
   What assumptions are baked into the approach?

Each agent's output feeds the next. Final deliverable lives at
`wrk_docs/2026.04.17 - RP2350 Peripheral Coverage Audit.md`.

### Devil's advocate returned — strong critique

Didn't hold back. Five headline challenges to incorporate into the
final doc:

1. **Axis confusion: implementation fidelity ≠ oracle coverage.** Of
   the 12 PARTIAL-BEHAVIOUR peripherals, roughly 9 are written but
   have zero `silicon_periph_diff_rp2350` cases. The matrix grades
   "code exists with side effects" as PARTIAL-BEHAVIOUR regardless
   of silicon verification. Need an oracle-coverage column.
2. **Synthesizer overreach on DMA.** Reclassifying DMA as "effectively
   STUB" without reading journals is synthesizer overreach — the
   missing FSM may be staged, not missed. Downgrade to "question for
   Arthur: staged or missed?"
3. **Inter-peripheral wiring is invisible.** DREQs, clock-domain
   propagation, reset-release re-init, NVIC fan-in all get no row.
   Two very different bugs (working UART + dead DREQ vs. broken UART)
   would get the same grade.
4. **Non-peripheral gaps**: bootrom image, Cortex-M33 ISA coverage
   buckets, VFPv5 completeness, DCP/RCP coprocessors, GDB RSP,
   SIO cross-core stress, ISR oracle cross-check, Hazard3 footer —
   all absent from the matrix.
5. **"Everything Secure" is self-contradictory** if any target
   firmware ever calls `rom_bootloader()`. Forces a choice.

Best alternative framing suggested: **firmware-pass matrix**. Pick 5
target firmwares (blinky, TinyUSB CDC, PicoDVI, a FreeRTOS image,
pico-examples/pio/ws2812), grade each "runs / fails / crashes /
wrong output". Gap map falls out for free. This is the single most
useful recommendation — the current peripheral-enumeration frame is
"how many AST nodes does the parser recognise" without a test suite.

Final doc will keep synthesizer's matrix as primary evidence (§2–§4),
but add an explicit §5 "what this audit does not measure", §6
"non-peripheral coverage dimensions", and §7 "recommendations" that
fold in the devil's advocate's challenges without whitewashing them.
DMA grade downgraded to "question mark" with a note.

### Post-publication correction — DMA + PIO misgrade

Arthur pushed back on the DMA grade: "I thought DMA was implemented —
go check." He was right to challenge it. Direct code inspection:

- **DMA**: `dma.rs` is 1573 lines of full behavioural model with 32
  passing unit tests covering mem→mem, DREQ gating, timer pacing,
  chains, rings, IRQ routing. `tick_dma()` wired into the per-cycle
  loop via `Bus::tick_peripherals` (bus/mod.rs:1077), called from
  `Emulator::step` (lib.rs:299). V5 §5.6 ordering contract honoured.
  Module drives `hello_dma` firmware tests per docstring. One firmware
  integration test fails (`hello_dma_firmware_completes_transfer`) but
  that's firmware-level, not DMA-absent.
- **PIO**: PIO primitive lives in `mdpicoem-common/src/pio/` (3585
  lines: mod.rs 2157, sm.rs 1159, decode.rs 121, fifo.rs 148). Real
  ISA decoder + execute. `PioBlock::step_n(cycles, gpio_in)` called on
  all three blocks every cycle from `Emulator::tick_peripherals`
  (lib.rs:374–379), gated by RESET_PIO0/1/2. 24 passing PIO tests.

**Both regraded FULL.** Total FULL count rises from 3 to 7. No
OPEN QUESTIONs remain.

**Root-cause post-mortem**: the Emulator Surveyor agent annotated DMA
as "stateless (no FSM progress)" and PIO as "no instruction execution"
in its output. Both were flat-out wrong — the surveyor appears to have
grepped register files (dma.rs has a large `read32`/`write32` register
decode) and concluded "this is just storage" without looking at
`tick()` / `step()` / `execute_insn()`. The synthesizer amplified the
wrong annotation to "effectively STUB". The devil's advocate caught
the synthesizer overreach and forced a downgrade to OPEN QUESTION —
but the root cause (wrong surveyor summary) was never verified.
Arthur's pushback caught it.

**Lessons (now in audit doc §5.6)**:
1. `wc -l` + running the peripheral's tests is a 30-second sanity
   check that would have caught this. Never skip it.
2. Agent downgrades must cite a specific line (missing FSM, missing
   execute loop) — not a vibes summary.
3. Peripheral modules with 1000+ lines and rich unit-test coverage
   are overwhelmingly likely to be fully modelled; treat "it's a
   stub" claims about such modules as extraordinary and demand
   extraordinary evidence.
4. Belt and braces: when the target audit is a *coverage* claim,
   running `cargo test -p mdrp2350 <peripheral>` should be part of
   the evidence, not optional.

**Accountability**: I let the surveyor's wrong annotation propagate
through three agents and into a published doc. The devil's advocate
reduced the damage by downgrading to OPEN QUESTION, but "OPEN QUESTION"
still implied "we don't know" when we could have known in 30 seconds.
That's on me, not the devil's advocate.
