# Journal: Hot Path Optimization

**Date:** 2026-04-13
**Feature:** Reduce emulator dispatch overhead identified by flamegraph
**Status:** COMPLETE — mixed results

## Flamegraph Findings

Profiled unpaced at ~85 MHz (no PGO, debug=2, lto=false via samply). Key self-time:

| Category | Self % | Notes |
|---|---|---|
| `CortexM33::step()` | 31% | Half is core 1 halted check |
| `condition_passed()` | 21% | Pure leaf, called every cycle |
| Bus fetch path | 20% | contention + bank calc + wait for every read16 |
| `execute_thumb16()` | 9% | Actual instruction work |
| `decode_execute()` self | 5% | Decode dispatch |

Actual instruction execution is only 9% of time. 72% is dispatch overhead.

## Three Optimizations Tried

### Opt 1: Skip halted core step (KEPT)
Gate core 1 step + contention on `is_halted()` in `Emulator::step()`.

### Opt 2: Inline + early-out condition_passed (KEPT)
Add `#[inline(always)]` + `if cond >= 0xE { return true; }` early exit.

### Opt 3: Inline bus/memory methods (REVERTED)
Add `#[inline(always)]` to downstream_port, sram_bank_wait, bank_for_address,
and all 13 Memory read/write methods.

## Results

### Opt 3 caused regression
| Config | Unpaced MHz | Paced MHz | Behind/sec |
|---|---|---|---|
| Pre-opts (PGO + pin) | 211 | 143.1 | 554 |
| All 3 opts (fresh PGO) | **186** | **138.8** | **47,853** |
| Opts 1+2 only (fresh PGO) | 185 | 143.8 | 13,705 |

**Opt 3 caused 12% raw regression** from I-cache pressure. The inlined helpers
expanded the hot loop beyond L1 I-cache capacity on this 3 GHz laptop CPU.
Reverted.

### Opts 1+2 gave ~0% paced improvement
The overhead calibration compensated: reduced overhead → calibration measures
less → quantum target stays the same → throughput unchanged.

Raw (unpaced) improvement without PGO: ~3% (94.5 → 97.6 MHz).

### Key insight
**The flamegraph hotspots were real, but fixing them doesn't improve
throughput.** The overhead calibration already accounts for per-quantum
dispatch cost. Reducing dispatch cost just means the calibration subtracts
less. Net effect: zero.

The only way to improve paced throughput is:
1. Reduce EMULATION time per instruction (not dispatch overhead)
2. Reduce OS preemption (priority, affinity, REALTIME)
3. PGO (2x improvement — the biggest single lever)
4. Faster hardware (5 GHz host as HLD assumed)

## Final Numbers (Opts 1+2, fresh PGO, priority+affinity)

```
Pinned to core 2 at HIGH priority / TIME_CRITICAL
Avg MHz:        143.8
Avg util:       73.8%
Behind count:   137,045
Verdict:        CANNOT SUSTAIN REAL-TIME (95.8% of target, 1.43% behind)
```

Essentially identical to the pre-optimization 143.1 MHz. The opts are kept
because they're correct (skip unnecessary work, add proper inline annotation)
even if they don't measurably improve paced throughput.
