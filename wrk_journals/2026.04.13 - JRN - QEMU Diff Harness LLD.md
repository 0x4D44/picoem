# 2026.04.13 - Journal - QEMU Differential Test Harness LLD

## Goal
Write a detailed low-level design for the QEMU differential test harness
(HLD Section 10.3, Oracle Layer 2). This harness validates full Thumb-2
instruction semantics by running identical test programs in both QEMU
(Cortex-M33 reference) and our mdrp2354 emulator, diffing register state.

## Approach
Using an agent team:
- Research agents: gather details on GDB RSP, QEMU MPS2-AN505, test binary
  generation, and our emulator's current API surface
- Drafter: synthesise research into LLD
- Devil's advocate: challenge assumptions, find gaps, question the approach

### 13:05 - Research complete, key findings

**QEMU MPS2-AN505:**
- Vector table at 0x10000000 (secure alias of ssram-0 at 0x00000000)
- SP from word 0, PC from word 1 (standard Cortex-M reset)
- Launch: `qemu-system-arm -machine mps2-an505 -cpu cortex-m33 -nographic -S -s`
- GDB server on localhost:1234, halts at reset with `-S`
- xPSR exception number bits (IPSR, bits [8:0]) are **read-only via GDB** — constraint!
- No known M33 instruction gaps in QEMU TCG

**GDB RSP:**
- Minimal command set: `?`, `g`, `P`, `m`, `M`, `s` (6 packets)
- ARM register ordering: R0-R15 (indices 0-15), xPSR (index 25)
- FPU: D0-D15 + FPSCR accessible via `p` packets
- Packet framing: `$payload#XX` with modular checksum, ACK with `+`

**Test binary generation:**
- Skip the assembler! Encode instructions as raw bytes, poke into QEMU SRAM
  via GDB `M` packets, set PC via `P` packet. No ELF needed.
- BKPT #0 = 0xBE00, place after test instruction as safety net
- 32-bit Thumb-2 only needs halfword alignment

**Emulator API (already built):**
- `Emulator` struct exists with dual cores, bus, memory, clock
- `CortexM33::execute_one(opcode)` / `execute_one_wide(hw0, hw1)` for direct
  instruction execution (no bus, no stepping)
- `CortexM33.regs` is pub — direct access to all register state, xPSR, FPU regs
- `Bus::new()`, `read/write 8/16/32` all pub
- No assembler needed for our emulator side either — we already pass raw opcodes

**Key insight:** Both sides (QEMU and our emulator) can be driven by raw opcode
bytes without an assembler. The diff harness is entirely self-contained.

### 13:20 - Devil's advocate review complete

**Valid critiques (will address):**

1. **QEMU is not an infallible oracle.** MUL flags are UNPREDICTABLE per ARM
   spec; QEMU will produce specific values. We must mask UNPREDICTABLE bits,
   not blindly accept QEMU. Need a triage protocol for disagreements.

2. **IT blocks are a blocking gap, not an open question.** No ITSTATE in our
   emulator, no IT bits in xPSR. Can't test conditional execution at all.
   Must either implement IT first or explicitly defer IT-dependent tests.

3. **Address space mismatch is under-specified.** Section 8.3 lists three
   approaches without committing. Must pick one and document it clearly.
   Best approach: use same SRAM address in both, compare relative PC deltas.

4. **`/dev/null` doesn't exist on Windows.** We're on Windows. Need `NUL`
   or empty temp file. Embarrassing miss.

5. **Most Thumb-32 tests will fail.** Only BL is implemented. Running 2,100
   Thumb-32 tests produces noise. Need capability gating — only generate
   tests for implemented instruction classes.

6. **WFI/WFE via GDB single-step may hang.** QEMU's WFI halts waiting for
   an interrupt. Need to either skip these or set up a pending interrupt.

7. **UNPREDICTABLE results need masking.** Flag bits that are architecturally
   UNPREDICTABLE must be excluded from comparison. Per-instruction masks.

8. **Performance estimate is optimistic on Windows.** TCP Nagle + delayed
   ACK on Windows localhost can add 1ms+ per round trip. Use `G` packet
   (write all regs at once) as default, not optimisation.

9. **QEMU version sensitivity.** GDB register indices should be discovered
   via target XML, not hardcoded.

10. **Windows process management.** Need `Child::kill()` with timeout,
    handle orphan processes.

**Points I disagree with (with reasons):**

- **"ARM pseudocode oracle is the right first oracle" (5.2):** Building a
  second implementation from ARM pseudocode IS building a second emulator.
  That's more work than the QEMU harness and equally bug-prone (our bugs vs
  transcription bugs). QEMU, despite imperfections, is a mature, tested
  implementation. The triage protocol (add masking for UNPREDICTABLE, cross-
  reference ARM ARM for disagreements) handles the trust gap.

- **"QEMU trace mode instead of GDB" (3.1):** Trace mode dumps text to
  stderr. Parsing QEMU's log format is fragile and version-sensitive.
  GDB RSP is a documented protocol with stable packet formats. The 6-packet
  client is ~200 lines — less fragile than a regex parser for QEMU logs.
  However, QEMU plugin API (3.2) IS worth investigating for v2.

- **"Too immature for this harness" (5.1):** We have 62 Thumb-16 tests.
  The harness exists precisely because hand-encoding expected outputs doesn't
  scale. But the capability gating point is valid — we should test only what's
  implemented. The harness structure should support incremental growth as we
  implement more instruction classes.

**Action: revising LLD to address valid critiques.**

### 13:45 - Round 1 review complete (4 agents)

**Agents:** correctness, simplicity, devil's advocate, API alignment

**Critical issues found:**

1. **`G` packet FPA gap.** QEMU M-profile has legacy FPA register slots at
   indices 16-24. Our 17-element `G` packet buffer puts xPSR at byte offset
   17, but QEMU expects it at index 25. Fix: drop `G`/`g`, use per-register
   `P`/`p` packets. Simpler and avoids the gap entirely.

2. **`execute_one_wide_with_bus()` doesn't exist.** The emulator has no
   bus-aware 32-bit execution method. All Thumb-32 load/store tests would
   silently use a throwaway default bus. Fix: note as prerequisite for
   Thumb-32 memory tests. Phase A (Thumb-16) is unaffected.

3. **PC-relative memory setup unsolved.** LDR PC-relative reads from
   PC+4+offset. PC differs between QEMU (0x10000100) and our emulator
   (wherever execute_one sets it). Memory must be placed at different
   absolute addresses per side. Fix: use relative offsets in test model.

**Simplification decisions (from simplicity reviewer):**
- Cut: RegisterMap/XML, FPU handling, JSON output, caching, plugin API,
  InstrClass enum, EmuRunner struct
- Reduce: 7 files → 3 files, 3 test strategies → 1 (edge cases)
- Shrink: ~2500 tests → ~500 (30/instruction, not 500/instruction)

**Devil's advocate key challenges:**
- ROI of QEMU diffing vs extending emulator is modest NOW but grows with
  Thumb-32. Phase A is deliberately minimal infrastructure investment.
- Encoding correctness is a blind spot — add bootstrap validation.
- Overlapping registers in generators need dedup.

**Resolved:** Open Question 1 (PC-reading) is confirmed correct in code —
  execute.rs consistently uses read_pc() for R15-as-source.
