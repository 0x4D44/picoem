## Bugs Found & Fixed

### Bug 1: FPU SNaN priority in binary ops (FIXED)
- **File:** `crates/mdrp2354/src/core/execute_fpu.rs:138`
- **Root cause:** `canonicalize_nan()` always picks operand `a` first when NaN, ignoring ARM FPv5 rule that SNaN takes priority over QNaN regardless of operand position.
- **Impact:** 9 FPU_ARITH failures (VSUB, VADD, etc.)
- **Fix:** Added `is_snan()` helper; check SNaN first, then QNaN in both `canonicalize_nan` and ternary variant.
- **Verified:** 9/9 FPU_ARITH failures eliminated.

### Bug 2: LDM fuzz generator address-space mismatch (FIXED)
- **File:** `crates/mdrp2354-test-harness/src/lib.rs:4502`
- **Root cause:** When `rn` stays in the LDM register list (50% chance), base register = 0, and address 0 has different contents in QEMU (vector table via NS/S SSRAM alias) vs our emulator (zeroed ROM).
- **Impact:** 314 LDM failures (93% of total). Harness bug, not emulator bug.
- **Fix:** Always exclude `rn` from register list in LDM fuzz gen (matches STM behavior). Set `addr_regs` unconditionally.
- **Verified:** 314/314 LDM failures eliminated.

### Bug 3: FPU MAC NaN propagation — three sub-issues (FIXED, pending verification)
- **File:** `crates/mdrp2354/src/core/execute_fpu.rs:260-344`
- **Sub-issues:**
  - **(a) Fused MAC missing inf*0 check:** VFMA/VFMS/VFNMA/VFNMS didn't return default NaN when Sn*Sm = inf*0, even when accumulator is QNaN. ARM FPMulAdd spec: inf*0 invalid overrides QNaN accumulator.
  - **(b) Non-fused MAC flat canonicalization:** VMLA/VMLS/VNMLA/VNMLS used 3-operand flat priority instead of two sequential 2-operand canonicalizations (multiply then add/sub).
  - **(c) Non-fused operand order:** VNMLS/VNMLA have product as first operand in the addition step, affecting QNaN propagation order.
- **Impact:** 6 FPU_MAC failures (all VFMA/VMLA).
- **Fix:** New `canonicalize_nan_fma()` with inf*0 check for fused ops; two-step `canonicalize_nan()` for non-fused ops with correct operand order.
- **Status:** Code applied, awaiting rebuild after background batches complete.
