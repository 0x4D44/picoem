# Journal: Clock Tree Implementation

**Date:** 2026-04-14
**Role:** Supervisor
**Scope:** Implement full RP2350 clock tree emulation per the revised V2 LLD.

## Context

The V1 boot clock fix (`Config::default()` → 6.5 MHz, ROSC STATUS stub)
shipped on 2026-04-13. Arthur pushed back on my scoping decision — the
emulator's goal is faithful 100% RP2350 emulation, so deferring the PLL
model because "no current firmware exercises it" was the wrong call.
The scope-advocate reasoning applies to application design, not to
emulating a defined piece of silicon.

V2 reverts that decision: implement the full clock tree (PLLs, CLOCKS
mux, dynamic sys_clk_hz, Pacer updates) that V0 designed, with the
three critical bugs the reviewers caught fixed, plus a handful of
refinements from the DA and formal review.

## Plan

1. Write V2 LLD incorporating all V0-review findings
2. Lightweight self-review (not a full team review — just verification)
3. Implementation via agent team (impl → review → apply → commit)
4. Final audit vs V2 LLD

## Timeline

### 2026-04-14 — V2 design

V2 draft complete. Self-review found one hedge worth tightening: made
`Config::sys_clk_hz` explicitly a "vestigial seed" rather than leaving
the remove-vs-keep decision for implementation. Confirmed only
`paced_bench.rs` explicitly overrides it; 12 `Config::default()` sites
are all safe.

### 2026-04-14 — Phase B (PLL model + subword alias fix)

- 8 new tests, 478 total
- Committed `622e578`

### 2026-04-14 — Phase C (Pacer dynamic updates)

### 2026-04-14 — Phase D (ROSC/XOSC register extensions)
