### Stage 3 — GLITCH_DETECTOR (done)

- Implementer's WebFetch revealed a real HLD shorthand vs silicon
  divergence: there is no separate `CTRL` / `STATUS` — one
  16-bit `ARM` RW register at 0x00 with sentinel values
  (`ARM_VALUE_NO = 0x5bad`, anything else = force-arm). "ARM
  readback tracks CTRL" reduces to plain RW + `0x5bad` reset seed.
- Also surfaced: TRIG_STATUS is actually at offset **0x10**, not
  0x08 as the pre-Stage-3 code assumed. Cascade effect: stale W1C
  mask entry in `bus/w1c.rs` pointed at `0x4015_8008` which is
  SENSITIVITY (plain RW — the bogus W1C mask would corrupt narrow
  writes to SENSITIVITY). Also `tests_narrow.rs` had the same
  stale constant.
- Code-reviewer caught the offset cascade as SHOULD-fix.
  Apply-feedback replaced the stale `0x4015_8008 => 0xFFFF_FFFF`
  catalogue entry with `0x4015_8010 => 0x0000_000F` (pico-sdk
  TRIG_STATUS_BITS) and deleted the stale SENSITIVITY entry.
  Updated `bus/mod.rs` doc comment. Added post-write `ARM_MASK`
  to prevent upper-16-bit pollution.
- Devil's-advocate caught two real issues:
  - Warm-reset modelling gap: `GlitchDetector` had no `reset()`
    method, inconsistent with every other peripheral. Fix: added
    `reset()` (re-seeds `ARM_RESET`) and wired into
    `Emulator::reset()`. Unit test
    `glitch_detector_arm_resets_to_arm_value_no_on_warm_reset`.
  - Silicon scenario tautology: writing `ARM_VALUE_YES = 0x0000`
    and observing 0x0000 couldn't discriminate a working write
    from a silently-sunk one. Fix: write `0x0000_1234` instead
    (distinctive, not sentinel, not reset, fits ARM_BITS).

**Landed**:
- `GlitchDetector` HashMap seeded with `ARM_RESET = 0x5bad`.
  Plain RW with `ARM_MASK` applied. `reset()` method.
- Bus W1C catalogue corrected (0x4015_8010 instead of
  0x4015_8008).
- `pub` offsets + sentinels exported from `inert.rs`; harness
  imports.
- Unit tests: `glitch_detector_arm_readback_tracks_ctrl` +
  `glitch_detector_arm_resets_to_arm_value_no_on_warm_reset` +
  5 module-level tests.
- Silicon scenario `glitch_detector_arm_readback_tracks_ctrl`
  writes 0x1234 discriminator.
- Cargo 1.11.0 → 1.12.0.
- `cargo test -p mdrp2350` = 1254 passed; catalogue invariants
  green; workspace release build clean.

**Lesson**: HLD register-name shorthand can hide structural
divergence from silicon. Implementers MUST WebFetch the SDK
header first to sanity-check register layout before implementing
to an HLD spec. Stage 3 caught this; it is now a reproducible
rule.

### Stage 4 — POWMAN COUNT + MATCH (done)

The biggest stage. Implementer's WebFetch correctly mapped HLD
logical names to silicon registers and surfaced that the previous
"educated guess" POWMAN module had `AON_COUNT_LO=0x08` colliding
with silicon `VREG_STS=0x08` (firmware writing to our placeholder
would have hit silicon's VREG status).

**Silicon-correct register layout adopted from pico-sdk
(commit `a1438dff`)**:
- `READ_TIME_LOWER/UPPER` at 0x74/0x70 (RO COUNT view).
- `ALARM_TIME_15TO0..63TO48` at 0x84..0x78 (RW MATCH lanes).
- `TIMER` at 0x88 (RUN bit 1, ALARM_ENAB bit 4, ALARM W1C bit 6).
- `INTR/INTE/INTF/INTS` at 0xE0/E4/E8/EC (TIMER is bit 1).

**Code review caught two MUST-fix items**:
- Handler LDR encoding bug: `HANDLER_POWMAN_SENTINEL[1] = 0x4902`
  resolved (via PC-align rounding for non-word-aligned handler
  hw[1]) to load the sentinel, not the mailbox. Fix: opcode
  `0x4903` (`ldr r1, [pc, #12]`). Added regression test asserting
  loaded word values, not just target alignment.
- POWMAN password protocol: writes to ALARM_TIME / TIMER without
  `0x5AFE` in upper-16 are silently dropped on silicon. Fix: bake
  password into silicon scenario literals; add password-strip
  (Option A) to emulator write paths so emulator accepts the
  prefixed values consistently.

**Devil's-advocate caught two more blockers**:
- Pre-flight binary `smoke_powman_pacing_rp2350` was skipped
  per supervisor brief but HLD §8 explicitly mandates it. Fix:
  binary written (compile-only — Arthur runs it on silicon).
  Implements the HLD-specified `(CYCCNT, COUNT)` sample pairs +
  derived sys_clks/tick + register dump.
- ARCHSEL @ 0x20 collision risk: silicon offset 0x20 is NOT
  ARCHSEL on RP2350; the emulator-only tripwire would spurious-warn
  on real firmware. Fix: downgraded `warn!` to `trace!`; renamed
  the test to `powman_archsel_non_arm_write_fires_tripwire_once`
  to reflect tripwire-on-flag semantics, not warn-level emission.

**Other applied fixes**:
- Comment drift: scenario comments said runner pre-seeds mailbox
  to `0xDEAD_BEEF`; actually pre-seeds to 0. Comments corrected.
- Dead PRIMASK=1 in `powman_match_pends_nvic_line_45` removed
  (test path doesn't step a core).
- Unused `MARKER_ADDR` pre-seed in `powman_match_enters_emulator_handler`
  removed.
- `powman.reset()` wired into `Emulator::reset()` (Stage 3
  GLITCH_DETECTOR precedent); regression test added.
- `>=` alarm fidelity comment + RUN-transition accumulator
  comment.
- TIMER write-mask fix: low-16 mask before `TIMER_RW_MASK` (which
  covers bits 19:16) to avoid leaking upper-16 password bits.

**Landed**:
- POWMAN module rewritten with pico-sdk-accurate offsets, COUNT
  advance from `tick_peripherals`, alarm fires NVIC 45 (one-shot),
  password-strip, ARCHSEL tripwire (trace-level), reset() wired.
- New `RESET_POWMAN = 17` constant gates POWMAN MMIO; not in
  `RESETS_POST_BOOTROM`.
- Pre-flight binary `smoke_powman_pacing_rp2350` (Arthur runs).
- Unit tests: 4 HLD-named + 9 module-level + reset test +
  handler literals test = 16 total POWMAN tests.
- Silicon scenario `isr_powman_match_timer_line_45` with
  password-prefixed literals (max_sysclks=5500 budget).
- Cargo 1.12.0 → 1.13.0.

**Deferred (DA tech-debt items, captured below for Stage 5 / V12)**:
- BADPASSWD silent-accept (no warn on wrong-password writes).
- `>=` vs `==` alarm comparator (firmware setting MATCH < COUNT
  with ALARM_ENAB would fire-immediately on emulator vs
  never-fire on silicon).
- Peripheral reset via RESETS_RESET bit toggling (codebase-wide
  gap — POWMAN is consistent with other peripherals).
- SET_TIME_* buffer semantics (emulator commits each lane
  immediately; silicon may latch only on the final write).
- POWMAN scenario lacks CYCCNT-delta observable to diagnose
  LPOSC-vs-XOSC pre-flight surprise.

**Lesson**: pre-flight binaries are scaffolding for Arthur, not
optional. Future stage briefs MUST write the pre-flight binary
unless the HLD specifically waives it.
