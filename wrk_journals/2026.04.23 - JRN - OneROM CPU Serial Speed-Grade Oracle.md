## Goal

Implement `onerom_cpu_speed_grade_serial_rp2350` — a single new harness binary
(~200 lines, no library changes). Reports per-rung cycle verdicts against a
ladder of thresholds using `CpuServingOracle::run_case()`, no wall-clock
measurement.

## Plan of stages

1. **Context gathering** — Explore agent maps existing `onerom_cpu_speed_grade_rp2350`,
   `onerom_stress_cpu_rp2350`, `CpuServingOracle`, `generate_sweep_cases`,
   `compute_histogram`, `boot_sync` pattern, `force_rom_set_index_via_sel_pins`.
2. **Implementation** — general-purpose agent writes the binary (`onerom_cpu_speed_grade_serial_rp2350.rs`)
   and the `Cargo.toml` `[[bin]]` entry, guided by the HLD §4 design and the
   Stage 1 context report. TDD: drive from the expected output format and
   validation checks in §6.
3. **Code review** — code-reviewer agent evaluates the new binary (quality,
   style, correctness against HLD, no scope creep).
4. **Devil's advocate** — general-purpose agent challenges the implementation:
   Does it actually validate the three §6 correctness checks? Are there
   silent failure modes? Is the ladder handling correct?
5. **Apply feedback** — code-review-apply-feedback agent merges review
   comments (Stages 3 + 4) into the binary.
6. **Final verification** — general-purpose agent compares final
   implementation line-by-line against the HLD's design sections §4–9,
   confirms §6 validation checks actually pass, reports any gaps.
7. **Commit** — after Stage 6 signs off, atomic commit.

## Non-goals per HLD §3

- No CLI mode-switch on threaded binary
- No app flag plumbing
- No library refactors
- No multi-sweep / shuffle
- No `SweepReport` extension
