## Sequencing (per HLD §14 DAG)

1. **Stage A.0** — Fault enum extension (NMI, MemManage variants). Prerequisite.
2. **Stage A.2** — New FPU instructions (VSEL, VMAXNM/MINNM, VCVTB/T). Risk-free.
3. **Stage A.1** — FPSCR exception flags + IEEE-754 reference oracle + retro.
4. **Stage C** — CP0 GPIOC.
5. **Stage E** — CP7 RCP extensions.
6. **Stage D** — CP4/5 DCP.
7. **Stage B** — Lazy FP context save. (Most invasive, last.)

Stage F testing is woven per-stage. Stage G (probe-rs) is parallel/optional
per HLD §2 and §9; deferred unless hardware driver materializes.

### Decision: SoftFloat vs hand-rolled reference (HLD §17.1)

**Pick hand-rolled**. Rationale:
- `softfloat-sys` is 170 recent downloads; C-dep fragility on MSVC.
- We need ~6 FPSCR flags. Narrow, enumerable.
- A ~100-LOC `ieee754_ref.rs` is cleaner than managing a `-sys` crate.
- Rust `f32`/`f64` are bit-exact IEEE-754 for our ops (with `+fma`).

If we hit a case where hand-rolled is insufficient, revisit.

## Stage A.0 — Fault enum extension ✅

Goal: add `Fault::Nmi` and `Fault::MemManage`; extend `deliver_fault`.

**Implementation agent**: added variants, extended deliver_fault, added 3 TDD tests.
492 tests green (488 pre + 4 new including retro-count).

**Code reviewer**: spec-conformant, tests meaningful. Flagged MMFSR bit choice —
should be DACCVIOL (bit 1) not IACCVIOL (bit 0) since MemManage's Phase 7 use
case is data-side (lazy FP flush). Suggested a fourth test.

**Apply-feedback**: flipped to DACCVIOL, added `test_memmanage_sets_mmfsr_daccviol`,
added clarifying NMI comment.

**Devil's advocate**: caught that all 4 tests were passing by coincidence — VTOR
was zero, vector table unwritten, zero-filled ROM decodes as NOP. Strong possibility
of silent breakage if memory init changes. Also flagged `test_memmanage_sets_mmfsr_daccviol`
could pass via HardFault escalation path.

**Fix-up**: test fixture now relocates VTOR to writable SRAM (0x2000_0000), plants
real vector table entries pointing at BKPT handler at 0x2000_0100. Every test
asserts PC lands on the handler. `test_memmanage_sets_mmfsr_daccviol` also asserts
IPSR==4 to distinguish from escalation.

**Result**: 492 tests green. Clean build.

**Commit**: eb400b0.

## Stage A.1 — FPSCR exception flags + FTZ/DN + retro-validation ✅

Goal: full FPSCR flag tracking (IOC/DZC/OFC/UFC/IXC/IDC), FTZ/DN mode
support, IEEE-754 reference oracle, retro-validate the 23 existing
arithmetic FPU instructions.

**Implementation**: added 6 FPSCR flag helpers with &mut fpscr signature
style; wired into VADD/VSUB/VMUL/VNMUL/VDIV/VMLA/VMLS/VNMLA/VNMLS/VFMA/
VFMS/VFNMA/VFNMS/VSQRT and VMAXNM/VMINNM sNaN→IOC. Built hand-rolled
IEEE-754 reference oracle in test harness (~414 LOC) per HLD §17.1 —
avoids softfloat-sys C dep. Built softfloat_diff differential harness
with edge-case + fuzz modes. 11 new FPSCR unit tests; 17 new oracle
unit tests. Caught and fixed own-oracle bug (MIN_NORMAL precision).

**Retro-validation result: clean.** No discrepancies in existing 23
instructions — they were arithmetically correct, just missing flag
tracking.

**Code review**: oracle independence verified (pure f64 path, not calling
into emulator). Found VNMUL NaN sign deviation (didn't flip sign for
NaN — wrong per DDI0553 §A2.2.6 FPNeg). Suggested shared MIN_NORMAL
constant, FMA probe doc, +fma verification.

**Apply-feedback**: fixed VNMUL + VNMLA to unconditionally flip NaN sign
(DN=1 canonicalizes). Added +fma enforcement via new .cargo/config.toml.
Added comment linkage for MIN_NORMAL constant across crates. Added FMA
inexact-probe caveat doc.

**Devil's advocate (2 blocks)**:
- B1: FZ/DN coverage was ZERO in the fuzz harness — oracle had no FZ/DN
  parameters. Retro-validation was incomplete.
- B2: .cargo/config.toml only covered x86_64-msvc/linux-gnu — other
  targets silently used non-fused FMA matching the ref oracle (also
  non-fused on those targets) — masking bugs.

**Fix-up**: threaded FZ/DN through oracle; extended fuzz to sweep 4
FPSCR modes. Added `compile_error!` on `cfg(not(target_feature="fma"))`
for loud failure on any target without +fma. Added more .cargo entries.

**Final result**:
- 528 mdrp2354 tests, 149 harness tests — all green.
- **3.6M fuzz iterations** (100k + 50k × 6 ops × 4 FPSCR modes × 2
  seeds) — all green. FZ/DN semantics bit-and-flag correct.

**Commit**: b5958fd.

## Stage C — CP0 GPIOC ✅

Goal: full CP0 dispatch wired to SIO (out/OE) and Bus.gpio_in (in).
Family-helper pattern matching CP7.

**Implementation**: 14 new SIO methods (bit + bulk for out/OE), CP0
dispatch with CRn/CRm/opc1/op2 decode, pin-30 masking. 15 new tests.

**Code review**: no blockers. Suggested PIN_MASK defense-in-depth on
reads (take); const-ify raw literal (take); one-line comment addition.

**Apply-feedback**: all three applied.

**Devil's advocate (CRITICAL BLOCK)**: implementer chose opc1 mapping
that disagreed with HLD §C.1 table. `gpioc_lo_out_get()` in the HLD
is opc1=0/CRn=0/CRm=0 — but the implementation routed opc1=0 to
per-bit ops, not bulk. SDK firmware emitting lo_out_get would have
hit the per-bit pin-0 path and returned just bit 0 — silent wrong
answer.

**BLOCK fix**: rewrote dispatch to match HLD §C.1. opc1 now selects
BANK (0=LO OUT, 1=LO OE, 2=LO IN, 4=HI OUT, 5=HI OE, 6=HI IN); within
each, (CRn=0,CRm=0) = bulk; else per-bit with pin=(CRn<<4)|CRm.
Tradeoff: pins 0 and 16 unreachable per-bit (bulk-only). Matches SDK
practice.

Added regression test `test_cp0_hld_lo_out_get_reads_full_bank` that
locks HLD compliance: SDK's exact `gpioc_lo_out_get()` encoding now
reads the full 30-bit bank.

Also fixed CPACR test to assert write suppressed (not just fault
raised).

**Result**: 544 tests green, zero warnings.

**Commit**: pending.
