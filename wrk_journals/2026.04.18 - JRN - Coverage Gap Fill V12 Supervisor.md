### Stage 2 — POWMAN INTE gating (done, commit `283920f`)

- Implementer changed `advance` to gate the NVIC return on
  `(self.inte & INT_TIMER_BIT) != 0` while keeping INTR.TIMER
  and TIMER.ALARM unconditional latches; changed `write32`
  signature to `#[must_use] -> u64` so writes that transition
  `(INTR & INTE) | INTF` 0→1 on TIMER (late INTE set, direct
  INTF force) propagate the level-sensitive raise; added a
  private `ints_timer_asserted` helper.
- Bus call sites consume the new return via `raise_irqs_u64`.
  Single bus write site, single advance site — no broader
  refactor needed.
- Silicon scenario `MAIN_IRQ_POWMAN` grew 32→40 halfwords:
  three new instructions at hw[9..11] write
  `POWMAN_INTE = 0x5AFE_0002` before NVIC_ISER1 enable; new
  literal-pool entries at hw[36..39]; all 8 LDR encodings
  recomputed (`Align(PC+4, 4) + imm8*4`). New regression test
  `test_main_powman_inte_literals_are_inte_addr_and_value`
  decodes the assembled image to lock-in the encoding.
- Reviewer/DA: GREEN with one SHOULD-fix — INTE/INTF were not
  password-stripped, leaving stored `0x5AFE_*` upper bits that
  would diverge from silicon on a firmware read. Applied inline:
  `value & 0xFFFF` in both write paths (same shape as TIMER /
  SET_TIME / ALARM_TIME password handling).
- Cargo 1.14.0 → 1.15.0. Release: 1270 passed / 0 failed
  (13 powman tests + 379 harness tests).

(POWMAN COUNT advances independent of core run state).

**Lessons from V12**:
- *Iterative silicon discovery is the value of the oracle.*
  V12 Stage 1 fixed CHIP_ID and that exposed PLATFORM as the
  next residual — both got fixed in-stage. The V11 Stage 6
  diff stopped at the first divergence; subsequent oracle
  runs were needed to surface the next layer.
- *Bit-shift math discipline.* PART occupies bits [14:12];
  V12 Stage 1 mis-placed it at bits [18:16]. The silicon
  measurement is the only ground truth — header literals
  encode field constants, not register layouts. Always
  cross-check `(field_value << field_lsb)` produces the
  silicon-observed contribution.
- *Run-mode probe reads aren't free on RP2354.* Smoke
  binaries that use `core.run()` then immediately
  `read_word_32` may fault. Use halt-read-resume cadence
  instead. Add to runbook for V13+ smoke binaries.
