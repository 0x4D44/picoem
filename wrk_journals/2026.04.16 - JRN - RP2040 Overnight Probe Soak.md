**Goal.** 8-hour soak of `probe_diff_rp2040` against real RP2040 silicon to
validate M0+ ISA correctness across a large random sample. This is the first
extended hardware-differential campaign for the RP2040 emulator — prior
overnight runs used QEMU only.

## Coverage Notes

- The `is_m0plus_silicon_safe` filter admits the M0+ Thumb-32 subset (`BL`,
  `MRS`/`MSR` for `PRIMASK`/`CONTROL`, `DSB`/`DMB`/`ISB`) that
  `qemu_diff_m0plus` cannot exercise — silicon is the only oracle for those
  encodings.
- No cycle comparison: M0+ has no DWT CYCCNT, so `--cycles` is intentionally
  absent. This run validates register-level correctness only, not timing.
- ALU-to-memory ratio is ~63:37, which is representative of the M0+ ISA
  surface (fewer addressing modes than M33).

## Observations

- Throughput was stable throughout (~175 s/batch, no drift). The probe
  connection stayed healthy for the full 8 hours with no reattach needed.
- The 162-batch / 413K-test volume compares favourably with the overnight QEMU
  campaign (2026-04-14) which ran ~400K M0+ tests via QEMU at similar
  throughput. The two oracles now have comparable coverage depth.
- Combined with the QEMU differential, the M0+ ISA implementation has now
  passed ~800K+ randomised tests against two independent oracles (QEMU
  `cortex-m0` model + real RP2040 silicon) with zero failures.

## What This Doesn't Cover

- **Cycle timing**: no CYCCNT on M0+, so we cannot differential-test cycle
  counts against silicon. The hardcoded M0+ cycle model in
  `execute.rs`/`execute_wide.rs` is unit-test-only validated.
- **Dual-core contention**: `probe_diff_rp2040` runs single-core. The RP2040
  contention model (`Bus::contention_check_active`) is not exercised here.
- **Peripherals**: this harness tests ISA semantics only. Peripheral register
  behaviour (PIO, clocks, SIO beyond CPUID) is covered by unit tests and
  `silicon_periph_diff_rp2350` (RP2350 only — no RP2040 peripheral oracle
  yet).
