# mdrp2354 — Phase 7 HLD: Coprocessors and FPU

Version: 0.4.0 — DRAFT (addresses V3 review)
Date: 2026-04-14

## 1. Purpose and downstream drivers

Phase 7 completes the Cortex-M33 coprocessor surface. Phase 3 shipped the
**minimum** stubs required for the RP2350 bootrom to boot (accept RCP
salt, DCP scratch registers, GPIOC NOP). Phase 7 makes **code that
actually exercises these features** work.

### Concrete downstream drivers

Per the project HLD §1, deployment is OneROM → mddosem. Phase 7
targets:

1. **OneROM**: needs real CP7 RCP canary checks (bootrom runs them);
   the current silent-accept stub hides firmware bugs.
2. **A minimal float test firmware** exercising the FPU subset `-lm`
   emits. Follows the existing repo pattern: a Python generator
   `roms/gen_float_test.py` producing `roms/float_test.bin` (same
   pattern as `roms/gen_blinky.py` → `blinky.bin`).
3. **Pico SDK `pico_double`**: anything linking `-ldouble` lowers to
   CP4/5 DCP calls — the narrowest concrete DCP consumer.
4. **Pico SDK `hardware_gpio` coproc macros** (CP0): firmware compiled
   with the default SDK emits these.

Out of scope for Phase 7: hypothetical third-party applications. If
something we're not testing needs more, we extend in a follow-up.

### Explicit non-goals

- **QEMU is not the FPU oracle.** Documented FPv5 divergences (NaN
  payload, denormals). We use **SoftFloat** (Berkeley TestFloat via
  `softfloat-sys`) as the bit-exact primary oracle.
- **No random-delay simulation for RCP.** Deterministic emulation is
  more useful.
- **No double-precision FPU.** RP2350 M33 is FPv5-SP single-precision
  only; doubles go through DCP.
- **No TrustZone-correct EXC_RETURN S bit.** Carry forward Phase 3's
  S=1 stub (`exceptions.rs:76 FIXME(trustzone)`); Phase 7 only flips
  FType (bit 4). Proper NS EXC_RETURN is a TrustZone work item.
- **No NS lazy FP.** Follows from TrustZone stub.
- **No VCVTA/N/P/M, no VRINTA/N/P/M.** No current driver.
- **No feature flags, no migration shims, no backwards-compat shims.**
  Replace stubs in place.
- **Silicon errata not replicated.** Emulator follows IEEE-754 /
  datasheet specified behavior. Accepted divergences listed in README.
- **RP2354A (30-pin) only for CP0.** Matches current SIO `gpio_out: u32`.

### Things we will NOT design for

- Configurable FPU via env vars / Cargo features.
- A generalized "coprocessor framework." Four coprocessors, four
  family-helper dispatches in `coprocessor.rs`.
- New `core/dcp.rs` module. DCP state as plain fields on `CortexM33`;
  DCP dispatch inline in `coprocessor.rs`.
- Defensive "log on unknown encoding." Silent NOP, matching existing
  stub style.

## 4. Stage A — FPU correctness

### A.1 FPSCR exception flags

FPSCR bit positions per Armv8-M ARM DDI0553 §D1.2.88:

| Bit | Name | Status |
|-----|------|--------|
| 31-28 | NZCV | done |
| 26 | AHP — alternative half-precision | add (lands with VCVTB/T) |
| 25 | DN — default NaN | add |
| 24 | FZ — flush-to-zero | add |
| 23-22 | RMODE | done |
| 19 | FZ16 (v8.1-M; RAZ/WI on Armv8.0-M M33) | skip |
| 15-8 | Trap-enables (IDE/IXE/UFE/OFE/DZE/IOE) — **RAZ/WI on M33** | skip |
| 7 | IDC — input denormal cumulative | **add** |
| 4 | IXC — inexact cumulative | **add** |
| 3 | UFC — underflow cumulative | **add** |
| 2 | OFC — overflow cumulative | **add** |
| 1 | DZC — divide-by-zero cumulative | **add** |
| 0 | IOC — invalid operation cumulative | **add** |

Cumulative sticky: set on trigger, cleared only by VMSR. M33 has no
trapped handling (all FP exceptions untrapped).

**FTZ semantics** per DDI0553 §A2.7.3:
- FZ=1 with denormal input: treat as ±0, set **IDC**.
- FZ=1 with tininess-before-rounding: result = ±0, set **UFC + IXC**.

**Default NaN** (DN=1): any NaN result → quiet NaN `0x7FC00000`.

**Implementation signature** — update in place, no wrapper:

```rust
// execute_fpu.rs — matches existing fpscr_set_nzcv signature style
fn fp_add(fpscr: &mut u32, a: f32, b: f32) -> f32 { ... }
fn fp_div(fpscr: &mut u32, a: f32, b: f32) -> f32 { ... }
```

Internal helpers for FTZ-in, FTZ-out, DN-out, flag accumulation.

**IXC detection per op**:

- ADD/SUB/MUL: exact f32 op is representable in f64; check
  `(result as f64) == f64_exact`.
- **DIV**: residual `a − q·b` via `(-(q as f64)).mul_add(b as f64, a as f64)`.
  Nonzero residual → IXC. The `.mul_add` form uses one fused rounded
  op so the residual is computed without loss.
- **SQRT**: residual `r² − x` via `(r as f64).mul_add(r as f64, -(x as f64))`.
  Nonzero → IXC.
- FMA (VFMA/VFNMA etc.): host `f32::mul_add` with the `+fma` target
  feature gives the fused result; IXC set iff result != arithmetic-exact
  in extended precision (detected with `f64` reference).

### A.2 Armv8-M instructions to add

**In scope** (driven by actual downstream code):
- **VSEL** — GCC uses for branch-free FP conditional moves.
- **VMAXNM / VMINNM** — `fmaxf` / `fminf` in `-lm`.
- **VCVTB / VCVTT** (F16↔F32) — replaces "F16 stub" in current file;
  AHP flag lands here.

**Deferred to Phase 7.1**: VCVTA/N/P/M, VRINTA/N/P/M.

### A.3 Host-`f32` oracle caveats

The "IEEE-754 single-precision is deterministic across x86/ARM" claim
holds only under these constraints:

- `f32::mul_add` on Windows MSVC x86_64 without `+fma` falls back to
  separate rounded mul+add — **not** bit-identical to fused.
  **Requires** `+fma` target feature via `.cargo/config.toml` (see §10).
- **NaN payload propagation** differs across hosts (x86 SSE vs ARM VFP).
  Tests assert only the quiet-bit and DN-override, not payload bits.
  Documented non-goal.
- Subnormal arithmetic: host MXCSR/FPCR pinned to strict IEEE-754 at
  test startup; fail-loud if pin fails.

SoftFloat (Berkeley TestFloat) is the independent bit-exact reference
for exception-flag coverage and edge denormals; host `f32` is the
runtime of the emulator's computation.

### A.4 Retro-validate the existing 23 instructions

The 23 already-implemented ops were unit-tested but never
differential-tested. Stage A.1 must first sweep them against SoftFloat.
Any discrepancy is a fix or a documented divergence. Without this
baseline, any flag regression can't be attributed.

## 5. Stage B — Lazy FP context save

### B.1 Background

Thread with `CONTROL.FPCA=1` enters exception → architecture stacks 18
extra words of FP context. Lazy (`FPCCR.LSPEN=1`, default): reserve
space, defer write until first FP op in handler.

### B.2 New PPB state

Add to `crates/mdrp2354/src/bus/ppb.rs` (per-core, alongside `cpacr`):

```rust
/// FP Context Control Register. DDI0553 §D1.2.32.
/// Reset 0xC000_0000 (ASPEN=1, LSPEN=1; we take the NS-alias reset value
/// even though the TrustZone stub reports S=1).
pub fpccr: u32,

/// FP Context Address Register. Writes forced to 8-byte alignment
/// (bits [2:0] = 0 on write).
pub fpcar: u32,

/// FP Default Status Control — template for FPSCR at exception entry.
/// Only AHP (bit 26), DN (25), FZ (24), RMODE (23:22) are defined.
pub fpdscr: u32,
```

**FPCCR bit positions** (correct per DDI0553 §D1.2.32 — V2 had these
wrong):
- `[0] LSPACT`, `[1] USER`, `[2] S`, `[3] THREAD`, `[4] HFRDY`,
  `[5] MMRDY`, `[6] BFRDY`, `[7] SFRDY`, `[8] MONRDY`,
  `[9] SPLIMVIOL`, `[10] UFRDY`
- `[26] TS`, `[27] CLRONRETS`, `[28] CLRONRET`, `[29] LSPENS`,
  `[30] LSPEN`, `[31] ASPEN`.
- Bits 11-25 reserved.

Emulator only actively models: ASPEN, LSPEN, LSPACT, SPLIMVIOL, MMRDY,
BFRDY. Others are RW storage (so reads round-trip) but not acted upon.

MMIO: FPCCR at `0xE000_EF34`, FPCAR at `0xE000_EF38`, FPDSCR at
`0xE000_EF3C`.

**Invariants** (replicate as `///` comments on the fields):

1. `CONTROL.FPCA=1 ⇒ S0-S31 + FPSCR are live thread-mode state`.
2. `FPCCR.LSPACT=1 ⇒ FPCAR points at a reserved FP frame; S0-S15 and
   FPSCR are still the pre-exception values and have not yet been
   written to the frame`.
3. `EXC_RETURN[4]=0 ⇒ the exception-entry path reserved 18 words above
   the basic frame`.
4. Only `fpu_execute` writes `FPCA=1`. Only `enter_exception` /
   `exit_exception` write `FPCA=0` / restore it.

### B.3 CONTROL.FPCA — single owner

Three write sites (and no more):

- **`fpu_execute`**: sets FPCA=1 after CPACR access check passes
  **and** after any lazy flush, before register writeback.
- **`enter_exception`**: reads FPCA into EXC_RETURN[4] = !FPCA, then
  clears FPCA=0.
- **`exit_exception`**: restores FPCA from !EXC_RETURN[4].

MSR-to-CONTROL path already masks out bit 2 per architecture rules.

### B.4 Exception entry

Changes to `enter_exception` at `exceptions.rs:41`:

1. `let had_fp = (self.regs.control & 0x4) != 0;`
2. **EXC_RETURN** (carrying forward Phase 3 S=1 convention):
   - FType=0 (FP frame present): `0xFFFF_FFE1` (handler/MSP),
     `0xFFFF_FFE9` (thread/MSP), `0xFFFF_FFED` (thread/PSP).
   - FType=1 (no FP frame): `0xFFFF_FFF1 / F9 / FD` as today.
3. **Allocation**: basic frame 32 bytes; if `had_fp`, +72 bytes (18
   words = S0-S15 + FPSCR + 1 reserved); +4 bytes alignment padding if
   needed.
4. **Stack-limit check**: before any write, compare prospective
   `frame_sp` against `msplim` / `psplim`. Violation → set
   `FPCCR.SPLIMVIOL=1`, raise UsageFault, no frame written.
5. **FP frame write**:
   - `FPCCR.LSPEN=1` (default): set `LSPACT=1`, set `FPCAR=<FP region>`,
     do **not** write S0-S15.
   - `LSPEN=0` (eager): write S0-S15 + FPSCR (18 words). M33 TRM
     typical ~17 cycles plus bus latency.
6. Reset FPSCR from FPDSCR bits [26, 25, 24, 23:22] (AHP, DN, FZ, RMODE).
7. Clear `CONTROL.FPCA=0`.

### B.5 Lazy flush trigger (`core/execute_fpu.rs`)

At `fpu_execute` entry, after the CPACR dispatch check already
performed at `coprocessor.rs:10-15`:

```rust
fn fpu_execute(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let core = bus.active_core();
    let ppb = &mut bus.ppb[core];
    if ppb.fpccr & 1 != 0 {  // LSPACT
        // Writes 18 words to FPCAR. Checks MPU/bus faults per-word:
        // on fault, set FPCCR.MMRDY / BFRDY, leave LSPACT set, propagate.
        match self.flush_lazy_fp_context(ppb.fpcar, bus) {
            Ok(()) => bus.ppb[core].fpccr &= !1,   // clear LSPACT
            Err(fault) => {
                self.pending_fault = Some(fault);
                return 0;
            }
        }
    }
    self.regs.control |= 0x4;  // FPCA = 1
    // ... dispatch ...
}
```

Cost when LSPACT=0 (the common path): one `u32` read of the same PPB
struct already loaded for CPACR — same cache line, <1 host cycle.

Flush cost: ~17 emulated cycles (18 word-writes + overhead).

### B.6 Exception return

If EXC_RETURN[4]=0:
- `LSPACT=1`: handler never touched FP → clear LSPACT, deallocate 18
  words. S0-S15 retain pre-exception values.
- `LSPACT=0`: pop S0-S15 + FPSCR from the FP region.

Restore `CONTROL.FPCA=1`.

Integrity check (DDI0553 "Exception return → Integrity signature"):
EXC_RETURN[4]=0 with inconsistent state → UsageFault.

### B.7 FPU × sleep, FPU × Core 1

Sleep (WFI/WFE): FP state is retained; LSPACT not cleared. Comment on
the sleep-handling site; no code change.

Core 1: each `CortexM33` has its own register file; PPB is already
per-core. Integration test (§B.9 #9) brings Core 1 up with CPACR
CP10/11 enabled on Core 1's PPB, executes VADD on Core 1, confirms no
cross-core contamination.

### B.8 Fault handling during flush

`flush_lazy_fp_context` returns `Result`. On any word-write fault:
- Set the appropriate `FPCCR.*RDY` bit (MMRDY for MemManage, BFRDY for
  BusFault).
- Leave `LSPACT=1` so a subsequent retry or exception-return sees the
  unflushed state.
- Propagate the fault.

### B.9 Test matrix (`crates/mdrp2354/tests/lazy_fp.rs`)

1. No-FP handler — LSPACT=1 observed; S0-S15 untouched; zero FP-region
   bus writes.
2. FP handler — LSPACT cleared after first FP op; S0-S15 preserved
   across.
3. Nested interrupts — each entry captures+clears FPCA; each return
   restores from its own EXC_RETURN[4].
4. Eager mode (LSPEN=0) — FP frame written on entry.
5. Stack-limit during FP reserve — UsageFault, SPLIMVIOL=1.
6. MPU fault during lazy flush — MemManage, MMRDY=1, LSPACT still set.
7. EXC_RETURN[4]=0 mismatch (fabricated) — UsageFault.
8. Phase 3/4/5 exception regression replay under FPCA=0 and FPCA=1.
9. Core 1 FPU — enable CPACR on Core 1 PPB, execute VADD, interrupt,
   return, verify state.

### C.3 SIO fast-path methods

Add to `sio/mod.rs` alongside `gpio_out: u32` / `gpio_oe: u32` /
`gpio_in: u32`. Final method names match SDK conventions:

- `gpio_bit_out_get(pin) / gpio_bit_out_put(pin, v) /
  gpio_bit_set(pin) / gpio_bit_clr(pin) / gpio_bit_xor(pin)`
- `gpio_bit_oe_get(pin) / gpio_bit_oe_put(pin, v) /
  gpio_bit_oe_set(pin) / gpio_bit_oe_clr(pin) / gpio_bit_oe_xor(pin)`
- `gpio_bit_in_get(pin)`
- `gpio_lo_out_get() / gpio_lo_out_put(v) / gpio_lo_out_set(v) /
  gpio_lo_out_clr(v) / gpio_lo_out_xor(v)` and `_oe_` / `_in_` variants
- `gpio_hi_*` variants (always 0 / no-op on RP2354A; present for
  interface symmetry)

Each is a plain field read/write on `Sio` — no bus round-trip.

Cycle cost: 1.

### C.4 Test strategy

- Unit tests per encoded op — verify SIO state matches direct-MMIO
  path.
- **Discrimination integration test**: firmware blinks via CP0; test
  harness instruments the bus to count SIO MMIO accesses; assert 0
  MMIO accesses during the CP0 blink loop. Proves CP0 is actually
  dispatched, not silently fallen through.
- Mixed-path ordering: alternate CP0 and MMIO writes to the same pin;
  last-writer-wins.
- CPACR-disabled: UsageFault.

## 7. Stage D — DCP (CP4/5)

### D.1 Scope

Instructions emitted by Pico SDK `double_aeabi_dcp.S` **plus any ops
our float_test firmware demonstrably emits** (let the firmware drive
the list, not a datasheet sweep). Final list committed in the Stage D
PR.

Typical coverage (from a walk of `double_aeabi_dcp.S`): arithmetic
(`dadd/dsub/dmul/ddiv/dsqrt`), compare (`dcmp_*`), convert
(`i2d/u2d/d2i/d2u/d2f/f2d`), transfer family (`rfma/rfmb/wxma/wxmb`).
No pipeline (`wxup/rxup`) or accumulator ops.

### D.2 State — inline, no new module

On `CortexM33` (replace `dcp_data: [u32; 2]`):

```rust
pub(crate) dcp_halves: [u32; 16],  // 8 doubles × 2 halves per datasheet §3.6.7
pub(crate) dcp_status: u32,
```

Dispatch inline in `coprocessor.rs` as `dcp_cdp_family` +
`dcp_transfer_family`, paralleling CP7's split.

### D.3 Instructions + cycle counts

One match, returns both result and cycle count:

```rust
match op {
    DcpOp::Dadd => { set_halves(...); 4 }
    DcpOp::Ddiv => { set_halves(...); 18 }
    // ...
}
```

### D.4 Oracles

- **Arithmetic**: SoftFloat double-precision (round-to-nearest-even)
  is the independent reference. Host `f64` is the emulator's compute.
  Tests diff emulator vs SoftFloat.
- **Status register**: a hand-written spec table (one row per op,
  which bits set on which inputs) — written in the Stage D PR from
  datasheet §3.6. This table *is* the oracle; no external reference
  exists.
- **Probe-rs spot check** (parallel track G, not blocking): sample
  ops on silicon; confirm bit-identical result + status.

## 8. Stage E — RCP (CP7)

### 8.1 Current state (keep)

- `rcp_canary_get` — returns `salt ^ 0xDEADBEEF`.
- `rcp_canary_check` — **currently silent-accept; changes to check+NMI**.
- `rcp_salt_core0/1` — sets salt.

### 8.2 Additions and the NMI decision

NMI is **inferred** from two independent sources: (a) the SDK `rcp.h`
intrinsics comment on trap target, and (b) pico-bootrom-rp2350's NMI
handler presence matching the pattern. Primary plan: ship Stage E with
NMI based on this SDK+bootrom evidence; this is not a "guess," it is
inference from authoritative source we control.

Plan B (optional confirmation): if Stage G probe-rs is already green at
Stage E landing, flash a canary-check-fail sequence, observe which
vector fires, confirm. If Stage G slips, SDK+bootrom evidence is
sufficient — if silicon later proves HardFault we change the emulator
behavior. This is not a blocker.

Assuming NMI (exception #2): set `pending_fault = NMI`, log
`"RCP assertion failed: <op> <args>"`. NMI is not masked by PRIMASK
but **is** masked by FAULTMASK — note for future diagnosis.

Full table (encodings enumerated in Stage E PR from SDK `rcp.h`):

| Instruction | Semantics | On mismatch |
|-------------|-----------|-------------|
| `rcp_canary_check` | Compare Rt vs salt^0xDEADBEEF | NMI |
| `rcp_iequal` | Compare two Rt values | NMI |
| `rcp_bvalid` | Rt ∈ {0, 1} | NMI |
| `rcp_btrue` / `rcp_bfalse` | Rt == 1 / == 0 | NMI |
| `rcp_ifgte` / `rcp_iflte` | Unsigned compare | NMI |
| `rcp_count_init` | Start counter (Bus state) | side effect |
| `rcp_count_check` | Assert counter value | NMI |
| `rcp_panic` | Unconditional | NMI |
| `rcp_switch` | Redundancy compare + branch | NMI |

## 11. Testing strategy

Single primary oracle per stage (V2's multi-layer setup trimmed):

| Stage | Oracle | Harness |
|-------|--------|---------|
| A | SoftFloat | `softfloat_diff` |
| B | Armv8-M spec (hand-written) + Phase 3-5 regression replay | `tests/lazy_fp.rs` |
| C | SIO direct-MMIO self-consistency + zero-MMIO-accesses discrimination | unit + integration |
| D | SoftFloat (arithmetic) + hand-written status-register spec table | unit + proptest |
| E | Datasheet + SDK `rcp.h` + bootrom boot | unit + encoding fuzz |
| G | Round-trip instruction + DWT | `probe_smoke` |

Probe-rs (from Stage G) is optional confirmation on any stage when
silicon is available — a spot-check, not a gate.

### qemu_diff extension

V1's `qemu_diff --fuzz 100000` doesn't exercise Phase 7 code. Add
`--classes=base|fpu|cp0|cp4_5|cp7` selector. Gate:
`qemu_diff --fuzz 100000 --classes=base,fpu,cp0,cp7` + separately
`softfloat_diff --fuzz 100000`. CP4/5 via SoftFloat only (QEMU has no
DCP).

### Determinism
- PRNG seed corpus committed to `mdrp2354-test-harness/seed-corpus.txt`.
- Host MXCSR/FPCR pinned at harness startup.
- `+fma` enforced via `.cargo/config.toml`; harness aborts with clear
  message if not detected.

### Build-time prerequisites
- `softfloat-sys` wraps Berkeley TestFloat C sources: requires Visual
  Studio Build Tools (C++ workload) on MSVC, a C compiler on Unix. CI
  runner config updated to install these.

### Performance budget check (HLD §9.1: 33 host cycles/emulated cycle)

Phase 7 adds to the hot path:
1. Every FPU op: LSPACT read (same cache line as CPACR), FPCA OR —
   sub-cycle.
2. Every arithmetic FPU op with flag tracking: ~3-5 host cycles for
   comparison + OR — lost in the 33-462 host-cycle budget of 1-14
   emulated-cycle FPU ops.
3. Exception entry: +1 branch, +1 PPB read — negligible.

**Gate**: `paced_bench --unpaced --workload fpu-heavy` post-Stage A
stays under 33 host cycles per emulated cycle. Requires adding the
`--workload` flag + `fpu-heavy` workload to `paced_bench` (§10).

## 13. Risks

1. **SoftFloat build.** Needs MSVC Build Tools on Windows. Once-per-host
   setup; documented.
2. **Probe-rs availability.** Stage G is parallel — no stage blocks on
   it.
3. **Lazy FP edge cases.** Test matrix §B.9 covers. Unknown cases add
   to the matrix, not the architecture.
4. **DCP enumeration completeness.** Firmware-driven; silent NOP on
   unrecognized encodings matches existing stub behavior.
5. **NaN payloads.** Non-goal, documented.
6. **MSVC `mul_add` fallback.** `+fma` target feature enforced.
7. **RCP behavior change.** Stage E audit + bootrom boot test.
8. **Hot-path budget.** §12 benchmark gate.
9. **NMI inference.** Ship NMI per SDK+bootrom evidence; silicon
   confirms opportunistically via §8.2 Plan B. If silicon later proves
   HardFault, flip the emulator behavior.
