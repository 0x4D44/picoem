## 1. Purpose

Make `silicon_isr_diff_rp2040` PASS on the EMU side for both V1
scenarios:

- `isr_m0_timer_cold` — TIMER ALARM0 → NVIC IRQ #0 → handler.
- `isr_m0_tail_chain_pendsv_systick` — SysTick underflow + ICSR
  PENDSVSET → tail-chained PendSV + SysTick handlers.

Exit criterion is "two scenarios green on EMU; FAIL surface
shrinks to genuine HW divergences when the probe attaches."

## 2. Current state — what's already there

V7 §5.2/§5.5 plumbing has landed in `crates/mdrp2040/src/`:

- `Bus::irq_pending: u32` — peripheral-asserted level/pulse bitmap
  (26 IRQ lines, `crates/mdrp2040/src/irq.rs`).
- `Bus::tick_peripherals` (`bus/mod.rs:1692`) — per-cycle slow-path
  tick that folds TIMER alarms, UART/SPI/I2C/ADC/PWM level IRQs
  into `irq_pending`.
- `Emulator::drain_pending_irqs_to_cores` (`lib.rs:678`) — drains
  `irq_pending` into **both** cores' `Nvic::set_pending`.
- `CortexM0Plus::maybe_dispatch_external_irq` (`core/mod.rs:280`,
  called from `step` at `:229`) — pre-instruction poll for IRQs ≥
  16; honours PRIMASK; "no preemption" rule (returns 0 if any
  handler active — see §9.2 for the limitation).
- `Bus::nvic_mmio_read32`/`write32` (`bus/mod.rs:1387-1457`) —
  ISER/ICER/ISPR/ICPR/IPR per-core via `Bus::active_core()`.
- `Bus::ppb` is `[Ppb; 2]` (per-core); each holds VTOR, ICSR
  W1S/W1C bits, SHPR2/3 storage. ICSR `PENDSVSET`/`PENDSTSET`
  latch correctly on write (`bus/ppb.rs:153-164`).
- TIMER ALARM emission end-to-end works: `TimerRegs::poll_alarms`
  (`peripherals/timer.rs:182`) is invoked from `tick_peripherals`
  at `bus/mod.rs:1699`. INTE is checked at fire-time, not arming-
  time, so the oracle's ALARM0-then-INTE-then-ISER write order is
  safe.

What's missing is the **CPU-side dispatch** for internal exceptions
(PendSV / SysTick), the **SysTick model** itself, and the
**threaded-runtime parity** for NVIC MMIO writes.

## 3. Gap analysis

| # | Gap | Today | Effect on oracle |
|---|---|---|---|
| 1 | SysTick (`SYST_CSR/RVR/CVR/CALIB` at `0xE000_E010..0x1F`) | Not decoded; PPB falls through with `_ => 0` / `_ => {}` (`bus/ppb.rs:142,177`) | Tail-chain scenario's SysTick MMIO writes are no-ops → no underflow → `ICSR.PENDSTSET` never asserted by HW → SysTick handler never runs |
| 2 | ICSR `PENDSVSET` / `PENDSTSET` dispatch | Bits latch in `Ppb::icsr` but neither `core/mod.rs::step` nor `core/exceptions.rs::exit_exception` polls them; only `maybe_dispatch_external_irq` runs (IRQs ≥ 16 only) | Even when firmware writes PENDSVSET via ICSR (`MAIN_TAIL[2]`), PendSV never dispatches; tail-chain back-edge missing |
| 3 | Threaded `WorkerBus` NVIC MMIO interception | `WorkerBus::ppb_read32`/`write32` (`threaded/bus.rs:769-775`) routes ALL of region 0xE directly to per-core `Ppb::read32`/`write32` — no NVIC decode | When the threaded runtime is active (default), `str` to `NVIC_ISER0` falls into `Ppb::write32`'s catch-all and is silently dropped → IRQ #0 never enabled → cold TIMER scenario hangs in threaded mode (the default) |

Closing 1, 2, 3 satisfies the oracle. No other gaps surfaced during
the survey.

as a fourth gap. It isn't — see §2 above.)

## 4. M33 → M0+ delta

The proven shape lives in `crates/mdrp2350/src/`. Everything below
is the M0+-trimmed port.

- **No Secure / Non-Secure split.** Single ICSR / NVIC / SysTick
  alias on M0+. The oracle uses `VTOR_ADDR = 0xE000_ED08`
  (singular).
- **No FAULTMASK, no BASEPRI.** Priority masking is just PRIMASK.
- **4 priority levels**, top 2 bits significant. SHPR3 already
  models this; NVIC IPR already masks to `PRIORITY_MASK = 0xC0`
  (`core/nvic.rs:52`).
- **No DWT CYCCNT.** The oracle's CYCCNT mailbox is a no-op on
  M0+; `silicon_oracle::enable_cyccnt`/`reset_cyccnt` tolerate
  read errors. No CYCCNT delta to chase.
- **17-entry vector table** (oracle places TIMER_IRQ_0 at
  vector[16]). VTOR-driven walk reads `mem[vtor + 4*exc_num]`;
  nothing for us to do.
- **Configurable exceptions are SVCall (#11), PendSV (#14),
  SysTick (#15).** Same priority arbitration as M33: lowest
  numerical priority wins; tie-break by lowest exception number.
  Reset (#1), NMI (#2), HardFault (#3) have fixed priorities.
- **No ICI continuation on multi-register transfers.** ARMv6-M
  asynchronous-exception entry is at instruction boundaries only;
  the existing `maybe_dispatch_external_irq` already fires before
  fetch (`core/mod.rs:228`). The new `try_take_any_pending_excep
  tion` (§5.3) inherits the same call site — explicit one-line
  reaffirmation, no behaviour change.
- **`Bus::irq_pending` is a single `u32` shared bus-wide on M0+**;
  mdrp2350 carries a per-core `irq_pending: [u32; 2]` with a
  "dual-clear invariant" (`crates/mdrp2350/src/core/exceptions.rs:
  608-622`). M0+ keeps the single shared mask — `drain_pending_
  irqs_to_cores` already broadcasts to both cores' NVICs, and the
  V1 oracle scenarios don't drive cross-core asymmetric
  delivery. The complexity isn't motivated.

What we explicitly do **not** copy from M33: SAU, MPU, CPACR,
FPCCR/FPCAR, lazy-FP, NMI ICSR.NMIPENDSET dispatch, dual-clear
invariant.

## 5. Design

Three components, in order. None requires migration; none uses
env vars or feature flags.

### 5.1 Component A — verify NVIC MMIO completeness; port to `WorkerBus`

The serial `Bus::nvic_mmio_read32`/`nvic_mmio_write32` is correct
and covers all five register families per-core. Component A is
narrow:

1. **Audit existing implementation.** Confirm `nvic_mmio_*` is
   unit-tested at `crates/mdrp2040/src/bus/mod.rs:2221-2230`. Add
   missing tests if any of the following aren't covered:
   - `ISER` W1S / `ICER` W1C / `ISPR` W1S / `ICPR` W1C round-trip.
   - IPR top-2-bits significant (write `0xC5`, read back `0xC0`).
   - Bits 26..31 ignored (RAZ/WI on RP2040 — only IRQs 0..25
     exist).
   - Per-core dispatch: write from core 0's perspective doesn't
     mutate `nvics[1]`.

2. **Port NVIC MMIO interception into `WorkerBus`.** Today,
   `crates/mdrp2040/src/threaded/bus.rs:769-775`'s
   `ppb_read32`/`ppb_write32` routes the entire 0xE region to
   per-core `Ppb::{read,write}32`. Add a small dispatch shim
   matching the serial-bus pattern:

   ```rust
   fn ppb_read32(&self, addr: u32) -> u32 {
       if let Some(v) = self.nvic_mmio_read32(addr) {
           return v;
       }
       if let Some(v) = self.systick_mmio_read32(addr) {  // §5.2
           return v;
       }
       self.ppb[self.core_id].read32(addr)
   }
   ```

   Same shape for write. The `nvic_mmio_*` functions on
   `WorkerBus` mirror the serial ones — they index
   `self.nvics[self.core_id]` (the per-worker NVIC state) and
   apply identical W1S/W1C/IPR semantics. The existing serial
   implementation is the spec; copy it.

3. **No signature changes elsewhere.** No `Ppb::write32`
   parameter rework. No call-site churn.

**Tests** (additions to `bus/mod.rs::tests` and a new
`threaded/bus.rs::tests` block, the latter feature-gated to
match the existing `threading` cfg pattern):

- `nvic_w1s_then_w1c_clears_enable` (serial; may exist).
- `nvic_ipr_top_two_bits_significant` (serial; may exist).
- `nvic_iser_through_workerbus_enables_in_per_worker_nvic`
  (threaded — the new one).
- `nvic_ispr_through_workerbus_pends_dispatchable_irq`
  (threaded — confirms the round-trip Worker → CPU).

### 5.2 Component B — SysTick model

Five registers at `0xE000_E010..0xE000_E01F`:

| Offset | Name | Purpose |
|---|---|---|
| 0x10 | `SYST_CSR` | ENABLE (bit 0), TICKINT (1), CLKSOURCE (2), COUNTFLAG (16, RC) |
| 0x14 | `SYST_RVR` | 24-bit reload value (writes truncated to `[23:0]`; reads return 24 bits) |
| 0x18 | `SYST_CVR` | 24-bit current value (any write zeroes `cvr` *and* clears `csr.COUNTFLAG`; reads return current decremented value) |
| 0x1C | `SYST_CALIB` | RAZ stub — `0` (RP2040 datasheet: SysTick calibration not exposed) |

**Where it lives.** Sibling to `Bus::ppb`/`Bus::nvics`: a new field
`pub(crate) systicks: [SysTick; 2]` on `Bus`. New module
`crates/mdrp2040/src/bus/systick.rs`:

```rust
pub struct SysTick {
    pub csr: u32,    // ENABLE | TICKINT | CLKSOURCE | COUNTFLAG (RC)
    pub rvr: u32,    // 24-bit
    pub cvr: u32,    // 24-bit
}

impl SysTick {
    pub fn new() -> Self { Self { csr: 0, rvr: 0, cvr: 0 } }
    pub fn read32(&mut self, addr: u32) -> u32 { /* … */ }
    pub fn write32(&mut self, addr: u32, val: u32) { /* … */ }
    pub fn is_enabled(&self) -> bool { self.csr & 1 != 0 }
    /// Tick once. Returns `true` iff this tick caused an underflow
    /// AND `TICKINT` is set — caller must then set ICSR.PENDSTSET
    /// on the active core's PPB.
    pub fn tick(&mut self) -> bool { /* … */ }
}
```

**Tick semantics.** Inside `tick`: if `!is_enabled()`, return false.
Otherwise:
- If `cvr == 0`: reload `cvr = rvr & 0x00FF_FFFF`; set `csr.COUNTFLAG`
  (bit 16); return `csr.TICKINT != 0`.
- Else: decrement `cvr`; return false.

Note `cvr == 0` triggers the reload-and-fire on the *next* tick,
matching ARMv6-M ARM §B3.3.1: "the counter transitions from 1 to
0 generates a SysTick exception when next clocked." Easy off-by-
one; the unit tests pin it.

**MMIO write semantics:**
- `RVR`: store `val & 0x00FF_FFFF`.
- `CVR`: any write stores `0`; also clear `csr.COUNTFLAG`.
- `CSR`: store `val & 0x7` (only ENABLE/TICKINT/CLKSOURCE
  writable); `COUNTFLAG` is read-clear, so leave it untouched on
  write but clear it on the next `read32` of CSR.

**MMIO read semantics:**
- `CSR`: return `csr`; *then* clear `csr.COUNTFLAG`. (Read-clear.)
- `RVR`: return `rvr` (already 24-bit).
- `CVR`: return `cvr`.
- `CALIB`: return `0`.

**CLKSOURCE.** RP2040 silicon: `CLKSOURCE=0` selects the watchdog-
tick generator (1 µs nominal); `CLKSOURCE=1` selects the processor
clock. The oracle imports `SYST_CSR_ENABLE_TICKINT_CORE` from the
M33 module — that constant is `0b111` (ENABLE | TICKINT |
CLKSOURCE), i.e. processor clock. **V1 ticks SysTick once per
master cycle when `csr.ENABLE`, regardless of CLKSOURCE.** This is
correct for `CLKSOURCE=1` (processor clock = master cycle);
`CLKSOURCE=0` is approximated as the same — the oracle's RVR=4
underflows in 4 master cycles either way. Note the deviation in
§9.4 and revisit if a future scenario needs the 1-µs cadence.

**Where it ticks.** Once per master cycle inside the slow-path
inner loop of `Emulator::step` (`lib.rs:653-664`), after
`tick_peripherals` and before `drain_pending_irqs_to_cores`. The
caller asserts `bus.ppb[active].icsr |= 1 << 26` when `tick`
returns true. SysTick belongs to the active core only —
`active_core` selects which `systicks[i].tick()` runs each
iteration.

The fast-path gate at `lib.rs:641-651` is **not modified** in V1.
SysTick-enabled workloads stay on the slow path because their
`tick_peripherals` activity already forces it; SysTick alone with
all peripherals idle would *still* take the slow path because
there's no fast-path bypass for SysTick. If `paced_bench_rp2040`
later shows ≥3% regression with SysTick enabled, add a gate then,
with a measurement to point at.

**Threaded path.** `WorkerBus` (`threaded/bus.rs`) gets a parallel
`systicks: [SysTick; 2]` and `systick_mmio_*` methods. The threaded
worker tick loop already runs per-cycle (see `threaded/peripher
als.rs`); add the SysTick tick adjacent to `tick_peripherals`.

**Tests** (in `bus/systick.rs::tests`):

- `enable_then_underflow_sets_countflag_and_returns_tickint`.
- `disable_during_countdown_freezes_cvr`.
- `cvr_write_clears_to_zero_and_clears_countflag`.
- `rvr_write_truncated_to_24_bits` (write `0xFFFF_FFFF`, read back

### 5.3 Component C — `try_take_any_pending_exception`

Replace `maybe_dispatch_external_irq` (`core/mod.rs:280`) with a
single helper that arbitrates **all** pending exceptions
(PendSV, SysTick, external IRQ) under one priority comparison. The
helper is a near-line-for-line port of mdrp2350's
`try_take_any_pending_exception` (`crates/mdrp2350/src/core/
exceptions.rs:564`), trimmed for ARMv6-M:

```rust
fn try_take_any_pending_exception<B: CoreBus>(&mut self, bus: &mut B)
    -> Option<u32>
{
    if self.regs.primask & 1 != 0 { return None; }

    let icsr = bus.ppb_icsr();   // active-core PPB ICSR
    let pendsv = icsr & (1 << 28) != 0;
    let pendst = icsr & (1 << 26) != 0;

    let mut best: Option<(u8, u16)> = None;  // (prio, exc_num)
    if pendsv {
        best = Some((bus.exception_priority(14), 14));
    }
    if pendst {
        let p = bus.exception_priority(15);
        best = match best {
            None => Some((p, 15)),
            Some((bp, be)) if p < bp || (p == bp && 15 < be) => Some((p, 15)),
            other => other,
        };
    }
    if let Some(irq) = bus.highest_priority_pending_irq() {
        let p = bus.nvic_priority(irq);
        let exc = 16 + irq as u16;
        best = match best {
            None => Some((p, exc)),
            Some((bp, be)) if p < bp || (p == bp && exc < be) => Some((p, exc)),
            other => other,
        };
    }

    let (_, candidate) = best?;
    if !self.can_preempt_v1(candidate, bus) { return None; }

    match candidate {
        14 => bus.ppb_clear_icsr_pendsv(),
        15 => bus.ppb_clear_icsr_pendst(),
        e  => bus.nvic_clear_pending((e - 16) as u8),
    }
    Some(self.enter_exception(candidate, bus))
}
```

**`can_preempt_v1`.** V1 preserves the existing `maybe_dispatch_
external_irq`'s "no preemption when any handler active" rule
(`core/mod.rs:289`) — i.e., return `true` iff `bus.ppb_active() ==
0`. This is **stricter** than ARMv6-M ARM §B1.5.4 (which permits
preemption by higher-priority handlers), and is a known limitation
matching today's behaviour. The V1 oracle scenarios don't exercise
preemption (PendSV, SysTick, TIMER all enter from thread mode), so
the limitation doesn't surface here. Tracked in §9.2 as a follow-up.

**Call site.** Replace the `maybe_dispatch_external_irq` call at
`core/mod.rs:229` with `try_take_any_pending_exception`. Same
position (top of `step`, before fetch), same return-type contract
(cycles consumed on dispatch, 0 otherwise). Delete the old helper.

**Tail-chain at exception return.** `core/exceptions.rs::
exit_exception` (`crates/mdrp2040/src/core/exceptions.rs:173-260`)
gets a single new line *after* the EXC_RETURN unstack-validation
and frame pop is complete (so SP, LR, PSR are all restored to the
pre-entry thread-mode values), but *before* returning to the
caller. Pseudocode:

```rust
fn exit_exception(...) -> u32 {
    // ... existing unstack + active-flag clear + register restore ...

    // Tail-chain poll: if any exception is still pending and
    // dispatchable now that we've exited handler mode, take it
    // without unwinding back to thread mode. Mirror M33 behaviour.
    if let Some(c) = self.try_take_any_pending_exception(bus) {
        return cycles_so_far + c;
    }

    cycles_so_far
}
```

The poll runs *after* SP unstack (so the next exception entry
stacks fresh thread-mode state, not the old handler frame) and
*after* the active-flag clear (so `can_preempt_v1` correctly sees
no handler active). This matches the M33 sequence at `crates/
mdrp2350/src/core/exceptions.rs` exit path.

**Tests** (in `core/exceptions.rs::tests`):

### 6.3 Regression budget

`paced_bench_rp2040 --workload basic` shows no measurable
regression vs the pre-change baseline. Apply the same noise-floor
escape clause as V5 Component 3 (HLD §"Hot-path cost gate"): if
cv ≥ 0.5%, the gate is a no-op as long as the post-change p50 sits
within ±5% of pre-change p50.

### 6.4 Threaded-runtime coverage

V1 does **not** add a new dual-model parity test. Rationale: the
existing SIO FIFO IRQ parity case at `crates/mdrp2040/tests/
dual_model.rs:444` already exercises cross-core IRQ delivery
through the threaded barrier, which is the load-bearing mechanism
this change exposes. NVIC, SysTick, and ICSR dispatch are all
per-core CPU-side state — once Component A's threaded `WorkerBus`
NVIC interception lands, the existing parity test continues to
PASS, which is the V1 sufficient signal. (If a future PendSV-
specific threaded bug surfaces, add a parity case then with a
concrete reproducer.)

## 7. Out of scope (V7 phasing)

- UART / SPI / I2C / ADC / PWM IRQ wiring — already plumbed via
  `tick_peripherals`; no V1 oracle scenario covers them. V7
  Phases 2–3.
- DMA IRQ_0 / IRQ_1 routing through `Bus::irq_pending`. V7 Phase 4.
- PIO IRQ routing. V7 Phase 1 mentions it but no oracle scenario
  exercises it yet; surfaces when a PIO ISR scenario lands.
- DWT CYCCNT modelling. M0+ silicon doesn't implement DWT
  uniformly; oracle treats CYCCNT as unobserved on M0+.
- Lazy-scheduled SysTick (advance many cycles at once when
  SysTick is the only thing forcing slow path).
- Preemption of an active handler by a higher-priority pending
  exception. Tracked in §9.2.
- M33-style per-core `irq_pending: [u32; 2]` with the dual-clear
  invariant. Single shared `irq_pending: u32` is sufficient for
  V1 scenarios.

## 9. Risks and open questions

**9.1 SysTick CLKSOURCE simplification.** V1 ticks once per master
cycle for both `CLKSOURCE=0` and `CLKSOURCE=1`. The oracle uses
`CLKSOURCE=1` (processor clock) so this is exact for the V1
scenarios. A future scenario relying on the 1-µs external tick
(`CLKSOURCE=0`) will see a faster countdown on EMU than silicon —
revisit then.

**9.2 No-preemption rule in `can_preempt_v1`.** ARMv6-M ARM
§B1.5.4 permits preemption of a lower-priority handler by a
higher-priority configurable IRQ. V1 follows the existing
`maybe_dispatch_external_irq` behaviour ("never preempt any
active handler"), which is a strict superset of the V1 oracle's
needs. Add proper priority-aware `can_preempt` in a follow-up
HLD when the first scenario actually exercises preemption. File
in `tech_debt.md` if the implementer wants it tracked separately
from this HLD.

**9.3 Image-base alignment.** The oracle places the vector table
at `ISR_IMAGE_BASE` and writes that value to VTOR. ARMv6-M VTOR
requires `ISR_IMAGE_BASE & 0x7F == 0` (128-byte alignment for ≤32
exceptions; vector-table size 17 × 4 = 68 bytes rounds up).
`crates/mdpicoem-harness/src/lib.rs` defines `ISR_IMAGE_BASE` —
add a `const _: () = assert!(ISR_IMAGE_BASE & 0x7F == 0);` to
catch any future drift. (M0+ silicon ignores low VTOR bits silently;
EMU should match.)

**9.4 Scenario divergences not covered by V1.** When the silicon
session attaches and runs the oracle for real, the silicon side
may reveal observable differences (stacked LR encoding, IPSR low
bits, exact CYCCNT-mailbox value) that V1 doesn't cover. Treat
any new FAIL surfaced by silicon as a follow-up ticket, not a V1
regression — V1 is "EMU side passes the V1 scenarios", not "EMU
fully matches silicon for all observables." File in `tech_debt.md`
when surfaced.

**9.5 `step_quantum` boundary effects.** `Emulator::run` advances
in `step_quantum` blocks. The oracle uses `step_quantum=1` so
`tick_peripherals` and `drain_pending_irqs_to_cores` run per-cycle
— the proposed design is exact in this configuration. The
existing dual-model parity test (`dual_model.rs:444`) uses
`step_quantum=64`, where alarm fire + IRQ enable can land in the
same quantum but the alarm is one-shot — INTE check at fire-time
(verified §2) means the IRQ asserts only if INTE was set when the
alarm fired, regardless of when within the quantum the writes
landed. No race for the existing test; the new EMU integration
test pins `step_quantum=1` to match the oracle.

**9.6 Boot-time reset state.** Add a unit test
`bus_new_zeroes_irq_state` asserting
`Bus::new()` (and `Bus::reset()`) zeroes:
- `nvics[0..2].enabled`, `nvics[0..2].pending`,
- `systicks[0..2].csr/rvr/cvr`,
- `ppb[0..2].icsr` (already covered).

The bootrom hook from V5 Component 3 doesn't touch any of these
on RP2040 (no RP2040 mask-ROM call surface yet) — but the assertion
documents the invariant.
