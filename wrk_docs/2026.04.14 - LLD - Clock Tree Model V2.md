# LLD: Clock Tree Model V2

**Version:** 2.0.0
**Date:** 2026-04-14
**Scope:** Faithfully emulate the RP2350 clock tree — ROSC at boot,
dynamic PLL configuration, Pacer tracks sys_clk_hz as it changes.

**Revision history:**
- v0.1.0 (2026-04-13) — Full clock tree design. Reviewers found 3
  critical design bugs + several refinements needed.
- v1.0.0 (2026-04-13) — Scaled back to boot-clock-only fix (Config default
  → 6.5 MHz, ROSC stub). **Shipped as commit `e89f859`.** Wrong scope
  call: the emulator's goal is faithful RP2350 emulation, not "just
  enough for current tests."
- v2.0.0 (2026-04-14) — Revives V0's structure with all review findings
  addressed. **This version.** V1 remains shipped; V2 extends it.

## 1. Goal

The RP2350 has a defined clock tree. A faithful emulator models it.
After V2:

1. Emulator boots at ROSC (6.5 MHz) — already true since V1.
2. Firmware writing PLL_SYS CS/FBDIV/PRIM/PWR registers computes the
   correct PLL output frequency.
3. Firmware writing CLOCKS CLK_REF_CTRL / CLK_SYS_CTRL / CLK_SYS_DIV
   routes the correct source to the CPU clock.
4. The Pacer tracks `sys_clk_hz` dynamically — when the CPU clock
   changes, wall-clock pacing follows.
5. SDK-compiled firmware that configures PLL → 150 MHz sees the
   emulator speed up correctly.

## 2. Starting Point (What V1 Shipped)

- `Config::default().sys_clk_hz = 6_500_000` and matching `Clock::new()` default
- `ROSC_FREQ_HZ` constant in `lib.rs`
- ROSC STATUS stub at `0x400E8000` — returns STABLE | ENABLED
- Existing CLOCKS stubs in `bus/peripherals.rs`: CLK_REF_CTRL,
  CLK_REF_SELECTED, CLK_SYS_CTRL, CLK_SYS_SELECTED
- Existing XOSC stub: STATUS always STABLE | ENABLED
- Existing PLL_SYS / PLL_USB stubs: CS reads LOCK=1, all writes ignored

V2 extends this. Nothing in V1 needs reverting.

## 3. What V2 Is NOT Modelling

- **XOSC startup delay.** ~1ms on real hardware. Our stub returns
  STABLE immediately. Firmware poll succeeds on first read. Flagged as
  known fidelity gap; revisit if a test depends on boot timing.
- **PLL lock delay.** ~100μs on real hardware. Same rationale.
- **ROSC frequency tuning** (FREQA/FREQB/DIV). ROSC is fixed at
  6.5 MHz. If firmware tunes ROSC, writes are accepted but ignored.
- **Fractional CLK_SYS divider.** Only integer part used. Frac bits
  stored but ignored.
- **Non-CPU clock domains** (CLK_PERI, CLK_USB, CLK_ADC, CLK_RTC,
  CLK_HSTX, CLK_GPOUT0-3). Not needed for CPU execution. When the
  peripherals that depend on them are modeled (Phase 7/8), extend then.
- **Glitchless mux sequencing.** Not observable in software.
- **PLL power gating semantics.** PWR register is stored but ignored
  (writes accepted, reads return last write). Real PLL can't lock with
  PD=1, but we always report LOCK=1 regardless. See §9 risk 2.

## 4. Design

### 4.1. Clock Tree State

A new struct, **owned by Bus**, holding the derived clock frequencies:

```rust
/// Derived clock tree frequencies. Recomputed eagerly whenever any
/// clock-relevant register (CLOCKS, PLL_SYS, PLL_USB) changes.
#[derive(Debug, Clone, Copy)]
pub struct ClockTree {
    /// Effective system clock in Hz. Drives the Pacer.
    pub sys_clk_hz: u32,
    /// Effective reference clock in Hz.
    pub ref_clk_hz: u32,
}
```

Lives in a new file `bus/clocks.rs` (peripherals.rs is getting busy).
Exposed via `pub fn sys_clk_hz(&self) -> u32` on `Bus`.

### 4.2. Source Frequencies

```rust
// in bus/clocks.rs
pub const ROSC_FREQ_HZ: u32 = 6_500_000;
pub const XOSC_FREQ_HZ: u32 = 12_000_000;
```

`ROSC_FREQ_HZ` already exists in `lib.rs` (from V1) — move it to
`bus/clocks.rs` and re-export from `lib.rs` for backward compatibility
with the Phase 1 tests.

### 4.3. PLL Model

Each PLL (PLL_SYS at 0x40050000, PLL_USB at 0x40058000) has four
registers in a 16-byte window:

| Offset | Register | Writable bits | Read value |
|--------|---------|--------------|-----------|
| 0x000  | CS      | [5:0] REFDIV, [8] BYPASS | stored OR (1 << 31) LOCK |
| 0x004  | PWR     | [0] PD, [2] DSMPD, [3] POSTDIVPD, [5] VCOPD | stored |
| 0x008  | FBDIV_INT | [11:0] FBDIV | stored |
| 0x00C  | PRIM    | [18:16] POSTDIV1, [14:12] POSTDIV2 | stored |

Backing storage on Bus: `pll_sys_regs: [u32; 4]` and `pll_usb_regs: [u32; 4]`.

Reset values (match hardware):
- CS = 0x00000001  (REFDIV=1)
- PWR = 0x0000002D (PD=1, DSMPD=1, POSTDIVPD=1 — PLL off)
- FBDIV = 0
- PRIM = 0x00077000 (POSTDIV1=7, POSTDIV2=7)

### 4.4. PLL Output Frequency

```rust
fn pll_output_hz(regs: &[u32; 4]) -> u32 {
    let fbdiv = (regs[2] & 0xFFF) as u64;
    if fbdiv == 0 {
        return 0;   // PLL not configured — honest zero, not a .max(1) hack
    }
    let refdiv   = ((regs[0] & 0x3F).max(1)) as u64;
    let postdiv1 = (((regs[3] >> 16) & 0x7).max(1)) as u64;
    let postdiv2 = (((regs[3] >> 12) & 0x7).max(1)) as u64;

    let vco_hz    = (XOSC_FREQ_HZ as u64 / refdiv) * fbdiv;
    let out_hz_64 = vco_hz / (postdiv1 * postdiv2);
    out_hz_64.min(u32::MAX as u64) as u32
}
```

**Why u64 intermediate:** `(12M / 1) * 4095 = 49,140,000,000` overflows
u32 (fits in u64 easily). Formal reviewer bug C2 fixed here.

**Why `fbdiv == 0 → 0 Hz` not `.max(1)`:** V0 silently turned an
unconfigured PLL into a 244 kHz output. V2 returns 0 honestly. The
Pacer guards against 0 (see §4.7), so this is safe.

Standard Pico SDK configuration: XOSC=12M, REFDIV=1, FBDIV=125,
POSTDIV1=5, POSTDIV2=2 → VCO=1500M, output=150M. ✓

### 4.5. CLOCKS Mux

Three registers drive CLK_SYS resolution:

| Offset | Register | Fields |
|--------|---------|-------|
| 0x030  | CLK_REF_CTRL | [1:0] SRC, [7:5] AUXSRC |
| 0x038  | CLK_REF_SELECTED | 1 << src |
| 0x060  | CLK_SYS_CTRL | [0] SRC, [7:5] AUXSRC |
| 0x064  | CLK_SYS_DIV | [31:16] INT, [15:0] FRAC (FRAC ignored) |
| 0x068  | CLK_SYS_SELECTED | 1 << src |

New Bus field: `clk_sys_div: u32` (default `0x0001_0000` = integer div 1).

Reference clock resolution:

```rust
fn ref_clk_hz(&self) -> u32 {
    match self.clk_ref_ctrl & 0x3 {
        0 => ROSC_FREQ_HZ,
        1 => {  // aux: CLK_REF_CTRL[7:5]
            match (self.clk_ref_ctrl >> 5) & 0x7 {
                0 => pll_output_hz(&self.pll_usb_regs),
                1 => 0,  // clksrc_gpin0 — unmodeled
                2 => 0,  // clksrc_gpin1 — unmodeled
                _ => 0,
            }
        }
        2 => XOSC_FREQ_HZ,
        _ => ROSC_FREQ_HZ,  // reserved — safe fallback
    }
}
```

System clock resolution:

```rust
fn sys_clk_hz(&self) -> u32 {
    let src_hz = match self.clk_sys_ctrl & 0x1 {
        0 => self.ref_clk_hz(),                 // clk_ref path
        _ => match (self.clk_sys_ctrl >> 5) & 0x7 {  // aux path
            0 => pll_output_hz(&self.pll_sys_regs),
            1 => pll_output_hz(&self.pll_usb_regs),
            2 => ROSC_FREQ_HZ,
            3 => XOSC_FREQ_HZ,
            4 => 0,  // clksrc_gpin0 — unmodeled
            5 => 0,  // clksrc_gpin1 — unmodeled
            _ => 0,
        },
    };
    // CLK_SYS_DIV[31:16] is the integer divider; 0 is treated as 1
    // (per RP2350 datasheet — divider of 0 is reserved/prohibited).
    let int_div = ((self.clk_sys_div >> 16) & 0xFFFF).max(1);
    src_hz / int_div
}
```

**Note on CLK_SYS_DIV layout.** V0 had `(self.clk_sys_div >> 8) & 0xFF_FFFF`
which reads bits [31:8] as a 24-bit integer. V2 uses `[31:16]` per the
RP2350 datasheet (INT=16 bits, FRAC=16 bits). Verify against datasheet
before coding — if datasheet disagrees, use datasheet.

### 4.6. Recompute Trigger

After any write to:
- CLK_REF_CTRL (0x40010030)
- CLK_SYS_CTRL (0x40010060)
- CLK_SYS_DIV  (0x40010064)
- PLL_SYS CS/PWR/FBDIV/PRIM (0x40050000–0x4005000C)
- PLL_USB CS/PWR/FBDIV/PRIM (0x40058000–0x4005800C)

…call `self.clock_tree.sys_clk_hz = self.compute_sys_clk_hz();` and the
matching `ref_clk_hz`. O(1) recomputation; no allocation.

### 4.7. Pacer Integration

Add to `Pacer`:

```rust
pub struct Pacer {
    // ... existing fields ...
    overhead: u64,           // NEW — was a local in with_quantum
    sys_clk_hz: u64,         // already exists, becomes non-dead
    quantum_cycles: u64,     // already exists
    tsc_freq_hz: u64,        // already exists
}

impl Pacer {
    pub fn update_sys_clk_hz(&mut self, new_hz: u32) {
        if new_hz == 0 {
            return;  // Div-by-zero guard: keep previous quantum
        }
        let new = new_hz as u64;
        if new == self.sys_clk_hz {
            return;  // No-op fast path
        }
        self.sys_clk_hz = new;
        let nominal = (self.tsc_freq_hz as u128
                     * self.quantum_cycles as u128
                     / new as u128) as u64;
        self.quantum_tsc_ticks = nominal.saturating_sub(self.overhead);
    }
}
```

**Why `new_hz == 0 → keep previous quantum`:** If firmware misconfigures
CLK_SYS to an unconfigured PLL, sys_clk_hz becomes 0. The previous
quantum was valid; using it avoids a division-by-zero crash. The
emulator keeps running at the previous pace until the clock is
reconfigured. This is more robust than panicking or running unpaced.

**Sim-thread integration** in `crates/mdrp2354-app/src/sim.rs`:

```rust
loop {
    pacer.begin_quantum();
    emu.run(qc);
    pacer.end_quantum();

    pacer.update_sys_clk_hz(emu.bus.sys_clk_hz());  // NEW

    // ... existing observation + snapshot ...
}
```

Zero-cost when clock doesn't change (one comparison + early return).

### 4.8. `clocks_write` Alias Handling (Pre-existing Bug)

`bus/mod.rs` currently dispatches `self.clocks_write(offset, val)`
without passing the atomic alias bits. `resets_write` already takes an
`alias` parameter and applies SET/CLR/XOR correctly. Fix `clocks_write`
to match:

```rust
// bus/mod.rs
0x4001_0000 => self.clocks_write(offset, val, alias),

// bus/peripherals.rs
fn clocks_write(&mut self, offset: u32, val: u32, alias: u8) {
    let apply = |current: u32| match alias {
        0 => val,               // normal
        1 => current ^ val,     // XOR
        2 => current | val,     // SET
        3 => current & !val,    // CLR
        _ => val,
    };
    match offset {
        0x030 => self.clk_ref_ctrl = apply(self.clk_ref_ctrl),
        0x060 => self.clk_sys_ctrl = apply(self.clk_sys_ctrl),
        0x064 => self.clk_sys_div  = apply(self.clk_sys_div),
        _ => {}
    }
    self.recompute_clock_tree();
}
```

This also applies to new `pll_sys_write` / `pll_usb_write` / `rosc_write`
functions — all must take `alias` and apply it. The bootrom's nsboot
path uses SET alias on PLL_USB PWR; without this fix, PWR bits would be
overwritten instead of set.

### 4.9. `Config::sys_clk_hz` Resolution

V1 left `Config::sys_clk_hz` semantics ambiguous. V2 decides: **keep
`Config::sys_clk_hz` as a vestigial seed** for `clock_tree.sys_clk_hz`.

Semantics:
- `Bus::new(config)` initialises `clock_tree.sys_clk_hz = config.sys_clk_hz`
  and `clock_tree.ref_clk_hz = config.sys_clk_hz` (reasonable default).
- Reset register state is ROSC/unconfigured-PLL, so the *first*
  `recompute_clock_tree()` call — triggered by any write to a CLOCKS
  or PLL register — overwrites the seed with the derived value.
- Pacer initialises from `bus.sys_clk_hz()` (which reads the seed).
- If firmware never touches clock registers, the seed sticks — this
  preserves `paced_bench`'s existing behavior exactly.
- If firmware does touch clock registers, the seed is immediately
  replaced by register-derived state.

**Why seed not remove:** only one caller explicitly overrides
`Config::sys_clk_hz` today — `paced_bench.rs`, which tests real-time
pacing at user-specified clock rates (150/200/250 MHz). Removing the
field would require paced_bench to compute PLL register values that
produce the target frequency, which is awkward. The seed approach
keeps paced_bench trivial and doesn't compromise correctness —
register-writing firmware always gets register-derived frequencies.

**`Clock::sys_clk_hz` is dead** (only read for reset preservation at
`lib.rs:99`). V2 removes the Clock struct's `sys_clk_hz` field and the
reset-time preservation logic. The single source of truth for system
clock frequency is `Bus::clock_tree.sys_clk_hz`.

**Grep results confirm migration is tiny:**
- `Config { sys_clk_hz: ..., }`: 1 call site (`paced_bench.rs:73-74`)
- `Config::default()`: 12 call sites (all safe — none read sys_clk_hz)
- `clock.sys_clk_hz`: 1 reader (`lib.rs:99`, goes away when field removed)

### 4.10. Reset State

After `Bus::new()` / `Emulator::reset()`:

| Register | Value |
|---------|-------|
| CLK_REF_CTRL | 0 → SRC=ROSC |
| CLK_SYS_CTRL | 0 → SRC=clk_ref |
| CLK_SYS_DIV  | 0x0001_0000 → int div = 1 |
| PLL_SYS CS   | 0x01 → REFDIV=1 |
| PLL_SYS PWR  | 0x2D → PD|DSMPD|POSTDIVPD = powered down |
| PLL_SYS FBDIV | 0 → output = 0 Hz (by §4.4 rule) |
| PLL_SYS PRIM | 0x77000 → POSTDIV1=7, POSTDIV2=7 |
| PLL_USB (same) | same |
| ClockTree.sys_clk_hz | = ROSC_FREQ_HZ (CLK_SYS → clk_ref → ROSC) |

### 4.11. ROSC Extensions (Beyond V1 Stub)

V1 added STATUS (0x018). V2 adds:

| Offset | Register | Behavior |
|-------|---------|---------|
| 0x000 | CTRL    | Stored, reads return last write |
| 0x004 | FREQA   | Stored, ignored |
| 0x008 | FREQB   | Stored, ignored |
| 0x00C | RANDOM  | Returns 0 (stub — no pseudo-random generation) |
| 0x010 | DORMANT | Accepts writes, ignored |
| 0x014 | DIV     | Stored, ignored |
| 0x018 | STATUS  | STABLE | ENABLED (existing) |
| 0x01C | RANDOMBIT | Returns 0 |
| 0x020 | COUNT   | Returns 0 |

Backing storage: `rosc_regs: [u32; 9]`. Writes accepted, most ignored.
This lets firmware configure ROSC without the emulator crashing —
values stick but have no effect on the 6.5 MHz fixed output.

### 4.12. XOSC Extensions

V0/V1 only handled STATUS. V2 adds:

| Offset | Register | Behavior |
|-------|---------|---------|
| 0x000 | CTRL    | Stored, reads return last write |
| 0x004 | STATUS  | STABLE | ENABLED (existing) |
| 0x008 | DORMANT | Accepts writes |
| 0x00C | STARTUP | Stored, ignored |
| 0x01C | COUNT   | Returns 0 |

Backing storage: `xosc_regs: [u32; 5]`. Same pattern — store, ignore.

- `Config::default()` still returns ROSC_FREQ_HZ. Behavior unchanged.

  these. Each needs to either (a) switch to poking registers, or (b)

## 9. Risks

1. **`Config::sys_clk_hz` removal is invasive.** 12 test sites use
   `Config::default()` (safe, no read). Explicit overrides need
   migration. Mitigation: keep field as vestigial seed if migration
   is painful. Decide during Phase E.

2. **PLL PWR ignored but LOCK reported.** Real PLL can't lock with PD=1.
   Our stub reports LOCK=1 regardless. SDK-like firmware checks LOCK
   after clearing PD — we short-circuit that poll. Functionally
   equivalent but not timing-accurate. Accept as known gap.

3. **CLK_SYS_DIV bit layout.** V0 used [31:8], V2 uses [31:16]. Must
   verify against RP2350 datasheet before coding. If wrong, trivial to
   fix (one shift).

4. **Alias handling regression.** Existing `clocks_write` doesn't use
   aliases but tests haven't caught it because no test writes via
   SET/CLR/XOR. Add a test (test 7) to lock in correct behavior. If
   bootrom flash path doesn't use aliases on CLOCKS, this won't show
   up in integration tests — unit test is the safety net.

5. **ROSC base address.** V1 shipped `0x400E8000`. V2 must use the
   same address (verified correct from bootrom disassembly).

## 10. Out of Scope (Deferred)

- Startup delays (XOSC stabilize, PLL lock)
- ROSC frequency tuning (FREQA/FREQB/DIV actually affect output)
- CLK_PERI, CLK_USB, CLK_ADC, CLK_RTC, CLK_HSTX — add when their
  dependent peripherals are modeled in Phases 7/8
- CLK_GPOUT0-3 clock outputs
- Glitchless mux sequencing (mux switch takes multiple cycles)
- PLL power gating (PWR.PD actually gates LOCK)
- Fractional CLK_SYS_DIV (FRAC field)
- Clock sleep modes (DORMANT)
