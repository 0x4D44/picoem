# Coverage Improvement Plan V2 — 2026-04-28

Companion to `2026.04.28 - CC - Coverage Baseline V2.md`.
Target: branch coverage ≥ **98 %** on the in-scope slice (regex in baseline § 7).
Starting point: **5 169 / 5 803 branches = 89.07 %** (gap = **518** branches to cross 98 %; **634** total in-scope misses).

## Operating rules

- **Agent-per-file (or tightly-related-pair).** Each agent gets a single file or a same-subsystem pair, the missed-branch number, and the cargo command. No "explore the codebase" prompts.
- **Run agents in parallel within a stage.** One stage = one parallel batch of 4–6 file-level agents → one re-measure → one commit. Do not re-measure between files within a stage; the cov build is ~12 min and the per-file deltas are too small to justify the cost.
- **Commit per stage.** Stage commit message: `tests: stage <N> — <area> coverage (<before%> → <after%> branch)`. No stage commit dumps > 20 modified files unreviewed.
- **Tests must be real.** No `assert!(true)` padding; no `#[ignore]`-but-counted tests. If a branch is provably unreachable, request `#[cfg_attr(coverage_nightly, coverage(off))]` with a one-line source comment justifying it.
- **No production-code reshape disguised as testing.** If a branch needs a tested code path but is sealed under a private/`pub(crate)` boundary, prefer adding a `#[cfg(test)]` accessor or moving the test inline rather than weakening the production API.
- **Match the existing test style.** Most chips already have giant `tests.rs` and `pio_tests.rs` files; new tests go there. Cross-cutting integration tests go under `crates/<crate>/tests/`. Don't fragment.

## Standard coverage command (every stage)

```bash
cargo +nightly llvm-cov --workspace --exclude epio-sys \
    --branch --json --output-path /tmp/cov-full.json --release
python3 wrk_docs/scripts/cov_analyze.py   # rollup against scope regex
```

`scripts/cov_analyze.py` is the JSON-walking helper that prints workspace + in-scope + per-crate totals plus the top-30 missed-branch files. It is the single source of truth for "are we at goal?".

## Stage 5 — Residue / over-the-line

After stage 4 we should be at or just above 98 %. This stage is for whatever remains — typically:
- 1-2 obscure `core_riscv/` paths (PMP edges, illegal-CSR write).
- 1-2 `core/coprocessor.rs` branches that cover unimplemented opcode arms.
- The `mdrp2350app::devices` tail (LCD frame-mid-byte abort variants).
- Annotation review: any `unreachable!()` arms and `match _ => panic!()` arms left uncovered get a `#[cfg_attr(coverage_nightly, coverage(off))]` line with a one-line source justification.

If we land below 98.0 % after Stages 1-4, this stage iterates with one fresh coverage run + one parallel agent batch until we cross.

Commit: `tests: stage 5 — coverage residue (~98.0 % → ≥ 98.0 % branch, final)`.

## Stage 6 — Lock the gain

- Run full-workspace `cargo test --workspace --exclude epio-sys --release` once; assert green.
- Re-measure once more on a fresh `cargo +nightly llvm-cov` to confirm no regression.
- Update `tech_debt.md` with any `coverage(off)` annotations added (so we revisit if the underlying invariant changes).
- Final commit: `tests: stage 6 — coverage at ≥ 98 % branch, lock-in`.
