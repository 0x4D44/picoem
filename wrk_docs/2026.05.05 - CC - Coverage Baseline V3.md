## 1. Method

```bash
cargo +nightly llvm-cov --workspace --exclude epio-sys --branch \
    --json --output-path target/cov-full.json
COV_JSON=target/cov-full.json python3 scripts/cov_analyze.py
```

`scripts/cov_analyze.py` is the JSON-walking helper used since
2026.04.28; it was updated this session to handle the restructure
crate paths (it previously matched only `mdpicoem-*`). Forward-slash
normalisation lets it run on Windows as well as POSIX.

In-scope filter (defined in `scripts/cov_analyze.py`):

- **Excluded**: `crates/picoem-harness/src/bin/` (all binary entry
  points), `crates/*-tui/src/{main,ui,sim,firmware,panels}` (interactive
  TUI shells), `crates/picoem-harness/src/{silicon_scenarios,
  isr_scenarios{,_rp2040}, dualcore_cases, cycle_cases,
  bank_conflict_cases, silicon_oracle, gdb_client, ieee754_ref,
  onerom_*, picogus_pins, silicon_periph_rp2040,
  probe_diff_rp2040_lib, test_silicon_common}.rs` (oracle support
  libs that need a probe + silicon to drive), `crates/*/src/tests*.rs`
  (test-runner files — branches inside test bodies are mostly
  assertion paths), `crates/*/tests/`, `third_party/`, registry,
  rustup toolchains, target dir.
- **Included**: everything else under `crates/<name>/src/` —
  i.e. the library code that actually ships in `picoem-common`,
  `picoem-devices`, `picoem-harness` (lib only), `rp2040-emu`,
  `rp2350-emu`, plus the small `devices/` modules in the two TUI
  crates.

`epio-sys` is excluded from the workspace build entirely (vendored
submodule + clang requirement); it is not a coverage target.

These add up to roughly **1 750 untested branches** in driver-style
code that runs only against external infrastructure. This is the
structural ceiling for raising the workspace headline without writing
test-doubles for QEMU + probe-rs + silicon — an enormous undertaking
that buys little, because the real correctness check is the diff
oracle's *output*, which is already exercised by the oracle library
code (`crates/picoem-harness/src/lib.rs` at 93.50 %).

The TUI crates contribute another ~80 missed branches (interactive
panels, `ui.rs` event loop, `main.rs`); those are interactive-only and
not unit-testable.

## 7. Provably-unreachable arms (skip-with-annotation candidates)

| `rp2350-emu/src/core_riscv/execute.rs:450` | `Op::Amo { Lr | Sc => unreachable!() }` | outer match already routed Lr/Sc to dedicated handlers |
| `rp2350-emu/src/core_riscv/csr.rs:330` | `_ => debug_assert!(false, "unsupported CSR")` | `read_csr` filters unsupported CSRs before `write_csr` is called |
| `rp2350-emu/src/dma.rs::apply_alias` | `_ => value` | alias is a 2-bit field on the Bus; values > 3 are unreachable from `Bus::write32` |
| `rp2350-emu/src/bus/peripherals.rs::pll_write_into` | `_ => val` | alias derived as `(addr >> 12) & 3`, always 0..=3 |

source comment justifying each removes ~10 branches from the
denominator (about +0.16 pp on the in-scope slice). Worth doing for
clarity even if the percentage gain is small.

## 8. Recommended target

`high-80s` is the user-stated bar for "defensible". We are already at
**91.18 % in-scope** on branch, **97.48 % line / 97.69 % region /
97.62 % function**. The plan that ships alongside this baseline
(`2026.05.05 - CC - Coverage Improvement Plan V3.md`) targets:

- **Primary**: in-scope branch coverage **≥ 95 %** (gap = ~228
  branches)
- **Stretch**: in-scope branch coverage **≥ 96 %**
  (gap = ~289 branches; consistent with §9 of the prior final
  report's "realistic plan to 96.8 %")
- The workspace headline (currently 63.22 %) is structurally bound
  by the harness binaries' need for external infrastructure; not a
  primary metric.

The plan structures this into four agent-driven stages plus one
annotation pass. See the companion plan document.
