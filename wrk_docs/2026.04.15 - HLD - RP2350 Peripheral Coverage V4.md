# RP2350 Peripheral Coverage — HLD V4

Companion to `2026.04.15 - HLD - RP2040 Peripheral Coverage V7.md`. That HLD is the
architectural template; this one lists the deltas for RP2350 and the Cortex-M33 /
ARMv8-M Mainline target. Read V7 first.

## Review history

V1 → V2: Round 1 (5 reviewers: silicon, architecture, oracle, devil's
advocate, simplicity) found ~8 criticals. Fixed in V2: NS-alias stripping
deleted, Phase 0 split into 0a/0b, core-local IRQs acknowledged, UART1/SPI1/
I2C1 cut, Phase 2+3 merged, misleading illustrative IRQ table removed.

V2 → V3: Round 2 (3 reviewers) found 5 new criticals. Fixed in V3: Cargo
workspace unification broke V2's compile-time `mmio_trace` feature
(reverted to runtime flag), mid-quantum drain had no IRQ source

peripheral-chosen target core (not static `CORE_LOCAL_IRQS` table), ISPR
self-pend on 46..51 clarified, stop-state sync pinned to cycle-budgeted
quiescent observables.

V3 → V4: Round 3 (2 reviewers) returned "implementable, no blocking
issues". V4 folds in six one-line clarifications:

- `assert_irq_core(core, irq)`: `core` is the NVIC target (receiver), not
  the writer — worked example in §5.3.
- TICKS `CYCLES=0` stops the tick and freezes `TIMELR/TIMEHR` (§5.4).
- DMA quiescent defined as `BUSY=0` on observed channels;
  `max_sysclks ≥ expected completion + 10%` (§3).
- §8 pins NVIC storage word-counts per register class.
- §4.1.4 pins the external-IRQ poll insertion site between the
  async-exception early-return and `decode_execute`.
- §9 adds WFE/WFI-wake acknowledgement — tracked in `tech_debt.md:780`,
  may surface in Phase 2 UART RX.

## 1. Purpose

Expand `mdrp2350` MMIO coverage beyond the eight peripherals modelled today
(SYSINFO, RESETS, CLOCKS, ROSC, XOSC, PLL_SYS, PLL_USB, QMI — plus SIO, PIO,
PPB and the QSPI/XIP/boot-RAM plumbing) so firmware in the motivating corpus
(§3) runs to completion instead of falling into the `HashMap<u32, u32>`
fallthrough at `crates/mdrp2350/src/bus/mod.rs:98`.

Scope: **TICKS + TIMER0/TIMER1** (Phase 1), **UART0 + SPI0 + I2C0 + ADC + PWM**
(Phase 2, merged), **DMA** (Phase 3). **Deferred** unless corpus or trace
evidence promotes: OTP, SHA256, TRNG, GLITCH_DETECTOR, POWMAN AON timer,
HSTX, ACCESSCTRL, UART1/SPI1/I2C1, extra DMA IRQs `DMA_IRQ_2`/`DMA_IRQ_3`.
Rollback plan: §9.3.

### Non-goals

- Full datasheet coverage.
- USB, ETM/TPIU, CORESIGHT_TRACE, TBMAN, BUSCTRL, SYSCFG, PSM.
- Non-pico-sdk runtimes, RISC-V Hazard3 cores, Non-Secure state firmware, SAU.
- Cycle-accurate peripheral timing finer than one sys_clk.
- RP2040 mirror. Impls live in `crates/mdrp2350/`.
- Backwards compatibility or migration.

## 2. Current state

`crates/mdrp2350/src/bus/peripherals.rs` covers SYSINFO, RESETS, CLOCKS, ROSC,
XOSC, PLL_SYS, PLL_USB, QMI. `bus/mod.rs` wires SIO, PIO, PPB. Everything else
round-trips through `peripheral_regs: HashMap<u32, u32>` with zero side effects.
No SRAM bank contention on RP2350. PPB NVIC is a stub — `ppb.rs:470` returns 0
for external-IRQ priority, `:201`/`:332` are read/write blackholes.

"Runs to completion" = emulator and silicon, **given identical MMIO setup and
the same `max_sysclks` budget**, converge on a register snapshot of the
scenario's declared observables. Observables are chosen to be **quiescent at
stop** (no in-flight transients at the read cycle). This is the existing
`silicon_periph_diff_rp2350` convention (V7 §4.2) — V3 just says so
explicitly. The `100k sys_clk without fault` property is a weaker necessary
condition, kept as a smoke gate but not sufficient.

For DMA scenarios specifically, quiescent = `BUSY=0` on all observed
channels (transfer complete, or `CH_ABORT`ed). Scenario `max_sysclks` must
be ≥ expected completion time + 10% margin to guarantee quiescence at the
read cycle.

Existing `roms/rp2350/*.bin` (blinky, dualcore, lcd_demo, benchmark) don't
touch in-scope peripherals — keep green as a regression gate.

**PicoGUS is out of scope** (that HLD targets `mdrp2040`).

Infrastructure exists: `silicon_periph_diff_rp2350`, `probe_diff_rp2350`,

- **`mmio_trace_rp2350`** — port from `mmio_trace_rp2040`. Runtime-flag

  fast-fetcher is unaffected.
- **Retry wrapper** ported to `silicon_periph_diff_rp2350` from

**Scenario-shape audit.** V7 scenarios are flat `setup` + end-state
`observe` — insufficient for TIMER-alarm-fire (arms mid-sled), UART TX

### 4.1 Phase 0a exit criteria — M33 exception / NVIC rework

1. **Pre-flight.** Run `silicon_isr_diff_rp2350` at HEAD (post-commit
   `2ed1c7c`) **before** starting 0a. If the PendSV/SysTick scenarios are
   still red, fix those first (ICSR polling may be incomplete) — do not
   proceed to 0a until they pass.
2. `crates/mdrp2350/src/bus/ppb.rs` external-IRQ register banks land:
   ISER, ICER, ISPR, ICPR, IABR, IPR — per-core, covering 52 NVIC input
   lines. All 52 bits writable in ISPR (software self-pend works on 46..51
   per datasheet §3.2 note following Table 95); only 0..45 are driven by
   peripheral asserts.
3. `execution_priority()` folds `BASEPRI` into the comparator (currently
   ignored at `core/exceptions.rs:322-338`). Audit: confirm no other PPB
   read site shadows the priority comparator. This is one behavioural
   change, not 39 edits.
4. `CortexM33::step` polls external-IRQ pending in a new block placed
   **after** the `try_take_async_exception` early-return path at
   `core/mod.rs:108` and **before** `decode_execute` at `core/mod.rs:110`
   — i.e. a third async-check block between them. **Mandatory
   short-circuit** at the top of that block:
   `if self.bus.irq_pending[core] == 0 { /* proceed to decode */ }` —
   branch predicts not-taken on the common path so there's no cost when
   no IRQ is pending.
5. `silicon_isr_diff_rp2350` gains **three** external-IRQ scenarios
   covering: (a) cold TIMER0_IRQ_0 assert + handler entry, (b) masked-pending
   (NVIC_ISER=0, assert, unmask, observe delivery), (c) priority preemption
   (two IRQs, higher-priority preempts lower in-flight handler). Each uses
   the extended vector-table shape from `build_image` (§4.1.6).
6. `isr_scenarios.rs::build_image` takes a **mode-set** parameter listing
   which vector slots to populate — needed for tail-chain scenarios with
   two peripheral handlers + PendSV handler in one image.

## 5. Architecture

### 5.1 Peripheral pattern

**See V7 §5.1.** Inherent methods, no trait, `pub(crate)` sibling fields on
`Bus`, direct field dispatch. No changes for RP2350.

### 5.2 Security

RP2350 enforces Secure/Non-Secure via ACCESSCTRL bus filtering (datasheet
§2.1.2, Tables 13/14), **not** via an aliased address range. One address per
peripheral. The only split-address peripheral is SIO
(`SIO_BASE=0xd000_0000`, `SIO_NONSEC_BASE=0xd002_0000`, Table 15).

V3 runs entirely in Secure state for the §3 corpus; ACCESSCTRL and SAU
modelling deferred. `SIO_NONSEC_BASE` is handled by the existing SIO address
decode if pico-sdk touches it. The Phase 0b bootrom trace (§4.2.11)
confirms this assumption or breaks it — §5.2 cross-references §9.3 rollback
if the trace shows non-trivial NS access.

### 5.3 IRQ plumbing

**See V7 §5.2 for the drain-loop structure.** RP2350 deltas:

- `irq_pending: [u64; 2]` — **per-core masks.** Shared IRQs (TIMER0/1, UART,
  SPI, I2C, DMA, PWM, ADC, etc.) are set on both cores. Core-local IRQs
  (listed below) set on the target core only. The **peripheral chooses**
  the core at assert time — not the drain loop. In
  `bus.assert_irq_core(core, irq)`, `core` names the NVIC **receiver**,
  not the writer. Example: when core 1 writes the core-0-bound FIFO, SIO
  calls `bus.assert_irq_core(0, IRQ_SIO_FIFO)` — the assert lands on
  core 0's NVIC pending mask. SIO already carries the writer's `core_id`
  through every access (FIFO/spinlock/CPUID path), so the target-core
  computation is one `.map()`-style lookup in the peripheral, not new
  plumbing.
- `Nvic::set_pending(irq: u8)` — 52 < 256, `u8` sufficient.
- Drain runs once per `Emulator::step()` iteration at step end (V2's
  mid-quantum drain claim is dropped — `tick_peripherals` only runs at
  quantum end, so there's no IRQ source to drain between core sub-quanta).
  Per-quantum IRQ latency (~64 cycles / ~512 ns) is below any corpus
  firmware's observable threshold.
- `CortexM33::step` polls `bus.irq_pending[core] == 0` as a short-circuit
  before walking NVIC (§4.1.4).

**Core-local IRQ set** (datasheet §3.2 GPIO / SIO bullets):
SIO_IRQ_FIFO, SIO_IRQ_BELL, SIO_IRQ_FIFO_NS, SIO_IRQ_BELL_NS,
SIO_IRQ_MTIMECMP, IO_IRQ_BANK0, IO_IRQ_BANK0_NS, IO_IRQ_QSPI, IO_IRQ_QSPI_NS.
(Note both Secure and NS GPIO variants are core-local; V2 listed only NS.)

`crates/mdrp2350/src/irq.rs`:

```rust
pub const IRQ_COUNT: u32 = 52;           // NVIC input count (ISPR accepts 0..=51)
pub const PERIPH_IRQ_COUNT: u32 = 46;    // silicon-connected; 46..51 peripheral-side RAZ
pub const CORE_LOCAL_IRQS: &[u32] = &[ /* 9 IRQs listed above; exact numbers pinned in Phase 0a from pico-sdk intctrl.h */ ];
```

ISPR software-self-pend on 46..51 is accepted and latches; peripherals
never drive those lines. Unit test: write NVIC_ISPR0 bit 48, verify pending
latches and an unmasked handler entry fires.

### 5.4 TICKS block

RP2350 factors the 1 µs tick generator out of WATCHDOG (RP2040) into a
dedicated peripheral at `TICKS_BASE = 0x4010_8000`. Six domains — PROC0,
PROC1, TIMER0, TIMER1, WATCHDOG, RISCV — each with `CTRL`, `CYCLES`, `COUNT`.
Hardware-reset `CYCLES = 0` (Table 619); pico-sdk `runtime_init` programs
`CYCLES = 12` for a 1 µs tick from 12 MHz `clk_ref` (datasheet §8.5, p.570).

Scenarios must account for reset = 0; TIMER0/1 do not advance until
firmware (or the scenario prelude) programs CYCLES. **A write of `CYCLES=0`
mid-run stops the tick and freezes `TIMELR/TIMEHR`** (datasheet §8.5: no
edge ever fires when divider is 0). The emulator must match — a
`CYCLES=0` write invalidates lazy schedules and prevents further TIMER
advance until a non-zero write.

TIMER0 and TIMER1 advance on their respective TICKS-generator edges; they
mirror the RP2040 TIMER shape (64-bit TIMELR/TIMEHR, 4 alarms,
INTR/INTE/INTF/INTS, lazy scheduling per V7 §5.3/§5.5). TICKS itself is
plain-storage.

**Invalidation path on TICKS write.** TIMER0/1 cached match cycles
invalidate on any TICKS register write that can shift the tick rate:
`CYCLES` (rate change), `CTRL.ENABLE` (start/stop), `COUNT` (phase reset):

```rust
// In Bus::peripheral_write32 after ticks.write32:
if addr_touches_ticks_timer_domain {
    self.timer0.invalidate_lazy();
    self.timer1.invalidate_lazy();
}
```

Unit test: write `CYCLES=24`, arm 1 ms alarm, verify fires at twice the
default cycle count. Second test: ENABLE 0→1 mid-sled, verify lazy schedule
advances from that cycle.

### 5.5 Per-cycle tick — fast-path gate DEFERRED

V2's "no gate exists on mdrp2350 today" observation stands — V3 does not
introduce one. Rationale: V7's 49% RP2040 regression was a PIO-heavy
benchmark; the RP2350 regression is unmeasured. §4.2.12 pins the baseline.

**Sequencing risk** (Round-2 devil's advocate): measure-baseline-first then
add-ticks is likely to produce a regression that is then unwound via
gate-addition. V3 acknowledges this — if Phase 1 measurement shows the
threshold breached, a follow-up HLD introduces the gate. Not this HLD.

Tick path without gate: at the end of every `Emulator::step()` iteration,
`bus.tick_peripherals()` calls each stateful peripheral's `tick`,
`pio.step_n(consumed, ...)` advances PIO, `bus.tick_dma()` runs DMA channels,
`drain_irqs` walks per-core pending into NVIC. Simple.

### 5.6 DMA — 16 channels

RP2350 DMA: 16 channels (datasheet §12.6.1, p.1095), DREQ table extended
with PIO2 + HSTX. V1 scope mirrors V7 §5.6.1:

- 16 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- `RING_SIZE`/`RING_SEL`, `CHAIN_TO`, `CH_ABORT`.
- `INTE0`/`INTS0`, `INTE1`/`INTS1` only. Silicon has `DMA_IRQ_0..3`; V3
  ships two. Promote to four if Phase 3 trace shows `INTE2`/`INTE3`
  written.
- Flat arbitration. Promote to tiered only if trace shows `HIGH_PRIORITY`.
- **Not in V3**: CRC sniff, byte-swap, `DMA_IRQ_2`/`DMA_IRQ_3`.

Emulator simplification on write visibility: **See V7 §5.6.**

## 7. Testing

**Oracle hierarchy** — see V7 §7. Primary: `silicon_periph_diff_rp2350` with
new scenarios per phase.

**Runtime budget.** Single `Session::auto_attach` reused. ~1 s/scenario.
~80 new scenarios → ~80 s silicon runtime.

**Authoring budget.** Scenario authoring (setup sequence + observe list +
pin list + silicon reverify) runs 30–60 min per scenario. 80 scenarios =
~48 hours (§6 allocation). Shared prelude (PLL, CLOCKS, GPIO funcsel)
factored into a per-phase helper — if per-scenario duplicated, add ~20%.

**Transient-handshake blind spot** (V7 §9.1 reprise). DMA `BUSY`, UART
`FR.BUSY`, TIMER `ARMED`, `CH_AL1_CTRL.BUSY` toggle 0→1→0 within one
scenario window — end-state diff misses them. Mitigation: `min_sysclks`
lower bound per scenario; intermediate halt-probe sampling deferred unless
DMA chain bugs surface.

**Flake policy.** See V7 §7; retry wrapper ported in Phase 0b.

## 9. Risks & open questions

**9.1 NVIC scope.** Phase 0a lands ISER/ICER/ISPR/ICPR/IABR/IPR per-core,
BASEPRI folding, external-IRQ poll, three scenarios. If impl days exceed
12, review before starting 0b.

**9.2 Pre-flight `silicon_isr_diff_rp2350` validation.** Phase 0a's first
action (§4.1.1) is running the existing scenarios at HEAD to confirm commit
`2ed1c7c`'s ICSR poll left them green. If red, fix ICSR pre-0a.

**9.3 Security-block / non-goal rollback.** If Phase 0b trace or Phase 1+
firmware hits OTP/SHA256/TRNG/GLITCH_DETECTOR/POWMAN/ACCESSCTRL with
non-trivial expectations (read-and-compare against non-zero), add an inline
plain-storage stub with the correct reset value (~2 hours per peripheral).
Escalate to a per-peripheral mini-HLD only if the register has active
silicon behaviour the corpus depends on. Mid-phase stall acknowledged for
escalations.

**9.4 Lab-rig probe contention.** `test_silicon` on RP2350 and any
`mdrp2040` silicon oracle work share the Pico probe. Tracked in a
top-level scratchpad; long soaks announced.

**9.5 Probe failure.** No fallback oracle. Acknowledged (V7 §9.5).

**9.6 Coexistence with in-progress RP2040 V7.** `bus/mod.rs`, `core/decode.rs`,
`core/exceptions.rs` on `mdrp2040` have unstaged edits; `mmio_trace_rp2040.rs`
is untracked. V3 Phase 0b's `mmio_trace_rp2350.rs` port waits for RP2040's
final shape. Any `mdpicoem-common` field renames on shared types force
review of §5.1.

**9.7 CORESIGHT / DAP-attached artefacts.** `silicon_periph_diff_rp2350`
runs with probe attached; some observables may differ DAP-attached vs
disconnected. None of the §3 corpus touches datasheet-flagged
debug-dependent registers; if a Phase 1+ divergence reproduces only with
DAP attached, record in `wrk_journals/` and revisit.

**9.8 `paced_bench_rp2350` regression floor.** §4.2.12 pins a number in a
journal entry at Phase 0b exit. Subsequent phases compare: >5% regression
→ investigate; >20% → halt phase. If measurement shows the fast-path gate
is needed, a follow-up HLD introduces it.

**9.9 TICKS cross-invalidation.** If a future peripheral depends on the
tick rate (WATCHDOG when modelled), add to §5.4's invalidation set. Tracked
in `peripherals/ticks.rs` header comment.

**9.10 Scenario authoring dominates Phase 2/3** (§7). Budget in §6 is
split impl/authoring.

**9.11 ISPR self-pend on 46..51.** Software can pend those bits though no
peripheral drives them. Emulator must accept ISPR writes to 46..51 and
latch. Covered by the Phase 0a unit test in §5.3.

**9.12 WFE/WFI wake on IRQ pending.** `tech_debt.md:780` tracks an
existing issue on both chips — a core halted via WFE/WFI with IRQ pending
+ enabled may not wake. Phase 1's `hello_timer` uses `busy_wait_us` (no
halt) and escapes. Phase 2's UART RX path uses `__wfe()` and may surface
this. V4 does not solve it here; address as a side task if a Phase 2
scenario reproduces it, reference the tech-debt entry.
