# RP2350 — RISC-V Hazard3 Test Oracles (V3)

**Date:** 2026-04-17
**Crate:** `crates/mdpicoem-harness/`
**Supersedes:** V2.
**Companion:** `wrk_docs/2026.04.17 - HLD - RP2350 RISC-V Hazard3 Core Support V6.md` (Hazard3 core HLD).

**V2 → V3 changes:**
- **Dropped the `riscv-tests` conformance phase entirely.** Two oracles, not three: QEMU diff + silicon diff. riscv-tests was pre-registered as V2 Phase 2B; round-2 review found its core premise (pre-built ELFs ship in upstream) was false, and that QEMU-diff fuzz plus silicon is sufficient for V1. Revisit as a follow-up if Phase 2 under-samples.
- **Mode-sentinel `csrr h3.misa` removed.** Round-2 review: the encoding `0xBF102573` decodes cleanly as Thumb (`MOVS r5, #0x73` + `YIELD`), so a M33 core running the sentinel produces no fault signature. Mode detection now rests on `probe-rs Core::architecture()` alone, with loud-exit on mismatch.
- **Precheck reworked.** `probe-rs chip info rp2350` is not a verified-existing offline CLI; V3 replaces with direct inspection of the probe-rs target YAML for an RV core stanza.
- **Decision tree collapsed** from 9 outcomes (0, A, B, C, D, E, F, Plan D, plus A′ under C) to **4** (Full / Partial / Mailbox / Plan D). Capability matrix collapsed from 11 items to 6.
- **Cycle oracle CLOCKS init pinned.** Stub prologue programs XOSC → PLL_SYS → clk_sys to the same pinned frequency the ARM cycle oracle uses, not the default ROSC.
- **`fence.i` cross-core silicon row dropped** as ceremony (per-hart semantics mean cross-core is outside spec; the real check is within-hart once a decoded-op cache lands).
- **Plan D triggers named.** Three concrete re-evaluation triggers plus an owner.
- **Oracle disagreement triage rule added** (two-way now that there are two oracles).
- **RP2354_RV_mode_procedure.md relocated** from HLD deliverable to RUNBOOK.md.
- Net length: shorter than V1.

## 1. Goal

Deliver verification for the Hazard3 port on RP2354 equivalent in rigour to the Cortex-M33 side: an ISA-level differential against QEMU (the `qemu_diff_m33` analogue) and a silicon differential against real RP2354 Hazard3 cores (the `probe_diff_rp2350` analogue). Two independent oracles because each catches bugs the other cannot.

## 2. Why two

| Oracle | Catches | Misses | Hardware? |
|---|---|---|---|
| **QEMU diff** (`qemu_diff_riscv32`) | RV32IMAC instruction semantics (including inside-reservable-region A-ext), base Zicsr CSRs, flag/`mstatus` shuffles, trap entry shape | Hazard3 custom CSRs (`meiea`/`meipa`/`meifa`/`meipra`/`meinext`/`meicontext` at `0xBE0..0xBE5`, `h3.misa` at `0xBF1`); Xh3Irq priority arbitration; outside-reservable-region atomics per RP2350 §2.1.6.2; `h3.block`/`h3.unblock`; cycle counts; WARL fields Hazard3 rounds differently from QEMU's generic rv32 | No |
| **Silicon diff** (`probe_diff_riscv_rp2350` + `silicon_cycle_oracle_riscv_rp2350`) | Everything the QEMU oracle misses: Hazard3 CSR semantics against real RTL, Xh3Irq, outside-reservable-region atomics, cycle accuracy (`mcycle` via mailbox — not debug-halt-readable), WARL rounding, level-sensitive `mip` timing | Nothing architecturally. Requires a Pico probe + RP2354 board in RV-select state. Not CI-runnable. | **Yes** |

**Independence is genuine at the test-corpus and implementation levels.** QEMU is an independent implementation; silicon is the implementation being verified. The only meaningful shared surface is *our* emulator's Hazard3 decoder (under test by construction) and the `riscv_gen.rs` fuzz generator (property-tested against a hand-rolled reference encoder — see §3).

## 3. Non-goals

- **No umbrella binary.** Each oracle is a separate `cargo run -p mdpicoem-harness --bin <name>`.
- **No feature flags, no cargo features, no env vars** (per CLAUDE.md).
- **No cross-arch test framework.** `thumb32_gen.rs` is M33-only; `riscv_gen.rs` is Hazard3-only; they share nothing meaningful.
- **No riscv-tests / riscv-arch-test / riscof / Spike dependency.** V2 proposed this as Phase 2B; V3 dropped it. If Phase 2 fuzz coverage proves inadequate, revisit as a follow-up.
- **No SDK firmware support.** Core HLD Q4 already deferred.
- **No WARL-exhaustion oracle in V1.** Silicon catches the WARL cases that matter for RP2354.

**Shared-code contamination hazards** (acknowledged, mitigated):
- `riscv_gen.rs` is used by QEMU-diff and silicon-diff. Phase 2 LLD ships a property test against a hand-rolled reference encoder.
- The ELF loader (if any — currently the emulator takes raw-byte images via `load_image`) has no shared-code exposure in V3 now that Phase 2B is dropped.
- The Hazard3 decoder under test in both oracles is the whole point; bugs there must surface as divergence, not coverage.

## 4. Phasing

Three phases, one LLD each, written just-in-time. Phase 1 is an information-gathering spike; its outcome reshapes Phase 3. **Phase 2 is independent of Phase 1.**

### Phase 1 — Probe-rs Hazard3 attach spike (≤1–2 days)

**Question:** can `probe-rs 0.31` reach a Hazard3 core on RP2354 at all, and at what capability level?

**Pre-spike precheck.** Inspect the probe-rs RP2350 target YAML (distributed with probe-rs 0.31 or upstream at `probe-rs/targets/RaspberryPi.yaml`) for a RISC-V core stanza. If absent, Phase 1 halts at Outcome **Plan D** — Path A/B are blocked pending upstream probe-rs target-file work. This is an offline file inspection, not a CLI subcommand.

**ARM-vs-RV mode detection.** The spike relies on `probe-rs Core::architecture()` returning `Riscv` after attach. If it returns `Arm` (or anything else), the spike exits loudly with a pointer to the RP2354 RV-mode procedure. **No additional sentinel read** — V2's attempted `csrr h3.misa` discriminator does not fault on M33 (the encoding disassembles as valid Thumb) and so gives no signal; `architecture()` alone is the gate.

**Getting the RP2354 into RV mode.** `CHIP_INFO` OTP fuses + POWMAN `CHIP_RESET.ARCH_SEL` soft-override. Procedure lives in `RUNBOOK.md` (new section added in Phase 1 PR), not in this HLD or a new doc. Without that procedure documented, the spike is unrunnable on a stock Pico 2.

**Deliverable.** ~150 LoC throwaway binary `crates/mdpicoem-harness/src/bin/riscv_probe_spike.rs` that runs the capability matrix and prints PASS/FAIL. Deleted when Phase 3 LLD lands, per the `smoke_per_core_cyccnt_rp2350` precedent.

**Capability matrix** (6 probes):

| # | Capability | Gates |
|---|---|---|
| 1 | Attach → `RiscvCore` exposed for both harts | Everything |
| 2 | Read/write GPRs (`core.read_core_reg` / `write_core_reg`) | Pre- and post-state |
| 3 | Read/write CSRs via `read_core_reg` / `write_core_reg` | Whether CSR-diff needs instruction-splice proxy |
| 4 | `set_hw_breakpoint` + `run` + `wait_for_core_halted` | HW breakpoint vs SW-breakpoint path |
| 5 | `core.step()` single-step | Stepping vs mailbox |
| 6 | Halt-under-IRQ-pressure (halt with `mip[11]` asserted, no spurious traps on resume) | Soak mode vs quiescent-only |

The spike also empirically measures whether `mcycle` ticks during single-step (standard RISC-V debug §4.9.1 specifies `countstop_debug` halts it). This does not gate path selection because the cycle oracle always uses the mailbox shape regardless (see Phase 3) — it is recorded for cross-reference.

**Decision tree** (4 rows):

| Outcome | Capabilities | Path | Phase 3 cost |
|---|---|---|---|
| **Full** | All 6 pass | Path A — probe-rs direct for semantic oracle; mailbox for cycle oracle. | ~1 week semantic + ~3 days cycle |
| **Partial** | 1 + 2 pass; any of 3/4/5/6 fails | Path A for what works + instruction-splice proxy for CSR access (if 3 fails) + SW breakpoint (if 4 fails) + mailbox for any scenario that trips (5 or 6). Phase 3 LLD picks exactly which mix after the spike reports. | +3–7 days over Full |
| **Mailbox** | 1 + 2 pass; nothing else works reliably | Path C — firmware stub uploaded via SWD memory-write; host polls SRAM mailbox. Same shape as `silicon_cycle_oracle_rp2350`; protocol reuses, RV-native stub. | ~2 weeks + per-scenario firmware |
| **Plan D** | Even attach (1) fails, or precheck found no RV stanza in target YAML | Accept the silicon gap. Hazard3 customs / Xh3Irq / outside-region atomics / cycle accuracy stay **Unit-tested only**. `tech_debt.md` entry created with named triggers (see below). | 0 |

**Plan D triggers** (named in the `tech_debt.md` entry; 90-day recurring review assigned to Arthur):
1. probe-rs ships a minor release with RP2350 RISC-V target-file support landed (watch `probe-rs/probe-rs` issues / release notes).
2. A second Pico probe + RP2354 board is available for concurrent-arch soak rigs.
3. Upstream Raspberry Pi contributes the probe-rs target YAML stanza.

Plan D is an explicit outcome, not a hidden failure mode. If triggered, V1 *Verified* tier ceiling is bounded to Phase 2 (Spec-conformant), and that is accepted.

**Phase 1 LLD** (`YYYY.MM.DD - LLD - RISC-V Probe-rs Attach Spike.md`) pins the exact probe-rs API call sequence, precheck YAML path, RV-mode runbook pointer, PASS/FAIL matrix format. Written day-of.

### Phase 2 — QEMU differential oracle

Binary: `qemu_diff_riscv32`. GDB port: **3335**.

**QEMU invocation — pinned in the LLD after empirical check.** First LLD step runs `qemu-system-riscv32 -cpu help` and `-cpu rv32,help` on the installed binary (`C:\Program Files\qemu\qemu-system-riscv32.exe`) and pins the invocation against what QEMU actually accepts. V1 guessed at `-cpu rv32,a=true,m=true,c=true,...`; that syntax may not be valid on QEMU 8+. Known-good elements: `-machine none -bios none -m 8M -nographic -icount shift=0,align=off,sleep=off -gdb tcp::3335 -S -kernel <bin>`. `QemuProcess` gains a `QemuProfile::RISCV32_RP2350` variant.

**CSR-diff mechanism — deferred to LLD pending empirical check.** First LLD step checks whether QEMU's RISC-V GDB stub exposes CSRs via `qXfer:features:read` (upstream-documented since ~7.0). Outcomes:
1. Stub exposes the minimum CSR set → direct read, primary path.
2. Stub is GPR-only → instruction-splice proxy: prelude/epilogue that `csrr`s CSRs into a fixed SRAM scratchpad, debugger reads scratchpad. **Excluded from this mechanism**: `csrr`/`csrrw` semantic tests (would self-mask decoder bugs — diff those via trap/post-state side-effects instead) and read-side-effect CSRs (`meinext` clears `meifa` on read per Hazard3 csr.adoc — silicon-only).

**Minimum CSR diff set:** `{mstatus, mcause, mepc, mip, mie, mtvec, mscratch}`.

`mtval` excluded: Hazard3 hardwires `mtval=0`; QEMU populates it on faults; every trap test would diff spuriously.

**WARL rounding.** Hazard3 and QEMU round differently on at least `mstatus.MPP` and out-of-range `mcause` writes. QEMU oracle does **not** enumerate WARL coverage up-front — that's silicon territory. If fuzz hits a WARL-divergence, the LLD's disposition is "mask the QEMU side on a per-field basis to Hazard3 semantics, or skip the fuzz variant". Enumeration is reactive, not pre-specified.

**Fuzz classes** (mirrors `qemu_diff_m33` structure; exact sample weights in LLD):
- RV32I ALU (register + immediate).
- RV32I memory (aligned load/store).
- RV32I misaligned load/store (exercises `mcause` 4/6 paths).
- RV32I branch/jump.
- RV32I upper (lui/auipc) + PC-relative pairs.
- RV32M.
- RV32A **inside reservable region** (addresses pre-primed to `0x2000_0000..0x2008_2000`). Outside-region is silicon-only per core HLD §4.7.
- RV32C (with Zcmp quadrant-2 encoding sweep per core HLD §4.5 V6 — exhaustive over the Zcmp-reachable bit patterns, not random).
- Zicsr (against the minimum CSR set; excluding read-side-effect CSRs).
- Zifencei self-modifying probe (small; no-op tripwire for future decoded-op cache).
- CSR-side-effect chains (`csrrw mstatus` → branch) exercising pipeline/hazard interaction.

**Unknown-opcode escalation.** In fuzz mode, our emulator's `warn!` on unknown-opcode escalates to test failure. QEMU's `mcause=2` is the expected reference.

**Phase 2 LLD** pins: QEMU invocation post-empirical-check, CSR-diff mechanism post-empirical-check, fuzz generators, the `riscv_gen.rs`-vs-hand-rolled property test.

### Phase 3 — Silicon oracle (shape set by Phase 1)

Two binaries because `mcycle` has different constraints from register state:
- **`probe_diff_riscv_rp2350`** — semantic oracle. Path per Phase 1 outcome (Full / Partial / Mailbox).
- **`silicon_cycle_oracle_riscv_rp2350`** — cycle oracle. **Always mailbox-shaped** (even under Full), because `mcycle` is a CSR (not bus-mapped like DWT CYCCNT on ARM) and halts during debug per RISC-V debug §4.9.1.

**Cycle stub contract.** The K-delta protocol from `silicon_cycle_oracle_rp2350` transfers directly; the stub is RV-native:
- Prologue: **program XOSC → PLL_SYS → clk_sys to the same pinned frequency the ARM cycle oracle uses.** Default boot leaves clk_sys on ROSC (~6 MHz, ±several-percent jitter); cycle deltas against ROSC are below signal. The CLOCKS init sequence is not a "peripheral-init dependency" to avoid — it is a mandatory oracle prerequisite.
- `csrrwi x0, mcountinhibit, 0` — clear inhibit bits.
- Per iteration: JAL into measurement slot, `csrrs t0, mcycle, x0`, `csrrs t1, mcycleh, x0`, run the case, re-read, write delta + hi/lo sentinels to mailbox, JAL back.
- K-delta cancels per-invocation framing (JAL/JALR) across K=101 vs K=201 runs.

**SW breakpoint path (Partial outcome)** contract:
- `ebreak` (0x00100073) or `c.ebreak` (0x9002), aligned to the preceding instruction's granule.
- After writing the sentinel, issue `fence.i` — our emulator makes it a no-op but real silicon needs the prefetch flush.
- Enter each test slot via JAL/JALR so the prefetch queue sees the slot from its head.

**Silicon-only test categories:**

| Category | What it tests | Depends on |
|---|---|---|
| Hazard3 custom CSR window | `meiea`/`meipa`/`meifa`/`meipra`/`meinext`/`meicontext` against real RTL | core HLD P4 |
| Xh3Irq priority arbitration | Nested preempt, `meinext.update` auto-clear of `meifa`, IRQ-coincident-with-mret | core HLD P4 |
| Atomics outside reservable region | `amo*.w` → `mcause=7`; `lr.w`/`sc.w` → infinite loop (RP2350 §2.1.6.2) | core HLD P3 |
| `mip[3]`/`mip[7]` level-sensitive timing | SIO register write → `mip` observable; IRQ asserted during `csrrw mstatus`/`mie` race | core HLD P4 |
| Cycle accuracy | `mcycle` deltas per instruction / short sequence | Cycle oracle |
| `mcycle`/`mcycleh` wrap | 32→64 bit transition; `mcycleh` sampling discipline | Cycle oracle |
| Reservation granule | Empirical byte granularity of `sc.w` invalidation | core HLD P3 |
| WARL rounding | Reactive on Phase 2 fuzz findings; validate Hazard3's rounding against real silicon | — |

**Dropped from V2:** `fence.i` cross-core row. Per RV spec, `fence.i` is per-hart; cross-core instruction coherence is outside its contract, so our no-op emulation matches silicon's per-hart semantics trivially. The real future check is *within-hart* `fence.i` after self-modifying writes, which matters only once the decoded-op cache lands.

**Concurrent probe use (core HLD Q7 promoted to constraint).** RP2354's ARCHSEL latches at reset. A single probe + single board cannot run ARM + RV soak in parallel. `test_silicon` soak runs **serialised alternating passes** (ARM soak → reboot into RV mode → RV soak → reboot). True-parallel needs two boards + two probes; not a V1 requirement.

**Phase 3 LLD** (written *after* Phase 1 concludes) specifies: path selection from the spike matrix, mailbox stub encoding, `test_silicon` orchestrator wiring (per-case filter prefix `rv:`, watchdog tuning, probe-serial + ARCHSEL state tracking), Plan D `tech_debt.md` entry if triggered.

## 7. Open questions / risks

**Q1 — Phase 1 exact outcome.** Resolved at spike conclusion.

**Q2 — QEMU Hazard3 alignment.** Generic `rv32` differs from Hazard3 on custom CSRs (excluded from QEMU diff) and WARL rounding (reactive masking).

**Q3 — Oracle disagreement triage.** When QEMU diff says X and silicon says Y: RV32 base ISA ties break to the RISC-V spec (Sail-derived), Hazard3 customs tie break to silicon + Hazard3 csr.adoc, any gap beyond that files a `tech_debt.md` entry. Two-way disagreement is bounded.

**Q4 — Phase 3 LLD timing.** After Phase 1.

**Q5 — Cycle-accuracy divergence budget.** Gaps found by cycle oracle land in `tech_debt.md`, not as Phase 3 blockers.

**Q6 — Concurrent silicon use.** Serialised alternating passes due to ARCHSEL-latches-at-reset. Two-board parallel is a rig upgrade.

**Q7 — Shared-code contamination.** `riscv_gen.rs` property-tested against hand-rolled reference (§3). No ELF-loader exposure now that Phase 2B is dropped.

## 8. Deliberate exclusions

- No conformance suite (riscv-tests / riscv-arch-test / riscof / Spike) in V1. Dropped in V3 from V2; reconsider only if QEMU-diff fuzz demonstrably under-samples.
- No cycle-accuracy from QEMU (not a cycle-accurate Hazard3 reference).
- No WARL exhaustion oracle in V1.
- No umbrella / cross-arch harness.

If the design grows beyond this document, the growth is wrong.
