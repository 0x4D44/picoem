## §3 Per-item design

### §3.1 SYSINFO — fill read-only fields

**Current** (`bus/peripherals.rs:48`): `sysinfo_read` returns
`CHIP_ID = 0x0000_0002`, `PACKAGE_SEL = 0`, `PLATFORM = 1`.

**Target**: add the remaining documented read-only fields
(`GITREF_RP2350`, `CHIP_ID` revision field, additional PLATFORM
bits) to match real RP2354 silicon.

**Silicon observable**: one probe-rs read at reset. Scenario diffs
the u32 at each documented offset.

**Capture**: before scenario commits, run
`probe-rs read-words --chip RP235x 0x4000_0000 8` on Arthur's
RP2354; paste the values into the match arms.

**Revision note**: `GITREF_RP2350` is chip-revision-specific; the
silicon scenario passes against Arthur's chip revision by
construction. Another RP2354 revision may need a scenario update.
Acknowledged, not fixed — dev sandbox.

**Unit test**: `sysinfo_reads_hardcoded_readonly_fields`.

### §3.2 POWMAN COUNT + MATCH

**Current** (`peripherals/powman.rs`): 64-bit COUNT/MATCH as
`AON_COUNT_LO` (0x08) + `AON_COUNT_HI` (0x0C), `AON_MATCH_LO`
(0x10) + `AON_MATCH_HI` (0x14). Storage-only — COUNT does not
advance. Warn-once on first write to COUNT/MATCH
(`peripherals/powman.rs:150, 168`).

**Unverified constants flagged by the module docstring**:
`POWMAN_BASE = 0x4010_0000`, register offsets, `STATUS.READY` bit
position. Pre-flight step (§8) resolves before the scenario
commits. If pre-flight reveals a wrong base, that's a blocker —
re-scope and re-run estimates.

**Target**:
- COUNT advances at 1 tick per POWMAN clock (XOSC / 4; 3 MHz on
  a 12 MHz XOSC).
- MATCH fires `POWMAN_IRQ_TIMER` (NVIC line 45) when COUNT ==
  MATCH and MATCH_EN is set. One-shot.
- `POWMAN_IRQ_POW` (line 44) stays unwired.
- ARCHSEL warn-once on non-Arm write **preserved** — runtime arch
  selection is out of scope for both V8 and the RISC-V Hazard3
  track (see §11).

**Silicon scenarios — both land in Phase 1:**

**A. COUNT advancement** (via `silicon_periph_diff_rp2350`):

- Setup: write `AON_MATCH_LO = 0x64` (K = 100), `AON_MATCH_HI = 0`,
  `MATCH_EN = 0`, enable POWMAN.
- `max_sysclks = 5500`, `min_sysclks = 5000`. At ~50 sys_clks per
  POWMAN tick, the window admits one cycle-exact COUNT value on
  both emulator and silicon. Implementer verifies the window's
  tightness empirically during capture.
- Observe: `(POWMAN_BASE + 0x08, 0xFFFF_FFFF)` and
  `(POWMAN_BASE + 0x0C, 0xFFFF_FFFF)`. LO stays well below 2^32
  at K = 100, so the LO/HI-straddle-a-carry hazard doesn't apply
  in Phase 1.

**B. MATCH fires IRQ line 45** (via `silicon_isr_diff_rp2350`,
shape-identical to the existing `isr_ext_irq_timer0_cold`
scenario at `isr_scenarios.rs:1010`):

- Vector table: slot 45 + 16 = 61 points at a handler stub that
  writes `0xCAFE_BABE` to a memory marker and `bkpt #0`.
- Main: enable POWMAN, set `MATCH = 100`, `MATCH_EN = 1`, NVIC
  ISER bit 45 set.
- Observable: memory marker `0xCAFE_BABE` present, CYCCNT delta
  matches an ISR-entry profile within tolerance.

This scenario does NOT require NVIC priority levels — it's a
cold-MATCH analogous to cold-TIMER0. Puts Phase 1 on equal
silicon-validation footing for its one firmware-impacting item.

**Unit tests**:
- `powman_count_advances_at_expected_rate` — tick N cycles, assert
  COUNT ratio.
- `powman_match_pends_nvic_line_45` — drive via emulator's own
  bus path; read NVIC ISPR1 bit 13 (line 45 / 32 = 1, line 45 %
  32 = 13) to confirm routing works without probe-rs. Closes the
  "unit test doesn't prove NVIC bank math" gap.
- `powman_archsel_non_arm_write_warns_once` — regression anchor.
  Tripwire for concurrent RISC-V work: if ARCHSEL semantics
  change, this test breaks visibly.

**Implementation**: add `aon_count: u64`, `aon_match: u64`,
`match_en: bool` to `PowmanRegs`. Drive from `tick_peripherals`.
Drop the warn-once on COUNT/MATCH writes. IRQ via
`raise_irqs_u64(1u64 << 45)` — `raise_irqs_u64` takes a u64
bitmask at `bus/mod.rs:1969`.

### §3.3 GLITCH_DETECTOR — ARM readback

**Current** (`peripherals/inert.rs:128, 139`): HashMap storage;
`STATUS.ARM` forced 0 on read; `TRIG_STATUS` W1C. Base
`0x4015_8000` flagged unverified.

**Target**: `STATUS.ARM` reads back the value written to
`CTRL.ARM`. `TRIG_STATUS` stays at 0 forever. No IRQ.

**Silicon observable**: setup writes `CTRL.ARM = 1`; observe
`STATUS.ARM = 1`, `TRIG_STATUS = 0`.

**Unit test**: `glitch_detector_arm_readback_tracks_ctrl`.

### §3.4 TBMAN — PLATFORM selector

**Current** (`peripherals/inert.rs:45`): HashMap storage only.

**Target**: PLATFORM field reads the silicon-observed value
(assumption `0b01`; confirm via pre-flight).

**Silicon observable**: one-shot read of `TBMAN_BASE + 0x00` at
reset.

**Unit test**: `tbman_platform_reads_silicon_value`.

## §8 Landing plan

**Pre-flight** (per item, before scenario commits): run
`probe-rs read-words --chip RP235x <BASE> 16` on Arthur's RP2354.
Sanity-check the dump matches the expected register layout and
captures read-only field values. For POWMAN, also measures:
- Actual sys_clk-per-POWMAN-tick ratio (resolves §3.2's 50:1
  assumption empirically).

If pre-flight reveals a wrong base or a wildly different pacing
ratio, re-scope the item before landing.

**Per-item cadence** (V5 convention): implement → code-review →
apply-feedback → devil's-advocate → commit.

**Order**:
1. SYSINFO
2. TBMAN
3. GLITCH_DETECTOR
4. POWMAN COUNT + MATCH (both silicon scenarios in one commit
   with the behaviour)

Cargo minor bump per item. Audit matrix update rolls into the
final item's commit.
