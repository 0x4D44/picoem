# Coverage Improvement Plan — 2026-04-23

Companion to `2026.04.23 - CC - Coverage Baseline and Plan.md`.

Target: branch coverage ≥ **98%** on the in-scope code defined in §4/§9 of the baseline doc.

All figures below refer to the **in-scope** slice (harness bins, TUI, and hardware-oracle support libs excluded). Totals for the in-scope slice are re-measured at the start of each stage from a fresh coverage run.

Starting point: **3,783 / 5,348 branches = 70.74%**. To reach 98% we must cover **~1,460** more branches.

## Operating rules

- **Commit per stage.** After each stage pushes coverage visibly (≥ +0.5% branch), commit. No stage dumps >15 files unreviewed.
- **Agent scope.** Each agent gets a single file (or a pair of tightly related files), a target `missed branches` count, and the exact cargo command. No "go explore the codebase" prompts.
- **Re-measure after each stage.** Fresh coverage run; update the baseline JSON and regenerate the priority list.
- **Tests must be real.** No `assert!(true)` padding; no ignored-but-counted tests. If a branch is unreachable (internal invariant), request a `#[cfg_attr(coverage_nightly, coverage(off))]` annotation with justification in a comment.
- **No refactor-disguised-as-tests.** Tests live in `#[cfg(test)]` modules or `tests/`. Do not reshape production code just to make it testable unless there is a clear separate justification — note it in the commit message.

## Standard coverage command (all stages)

```bash
cargo +nightly llvm-cov --workspace \
    --exclude epio-sys --exclude epio \
    --branch \
    --ignore-filename-regex '(crates[\\/]mdpicoem-harness[\\/]src[\\/]bin[\\/]|crates[\\/]mdpicoem-harness[\\/]src[\\/](silicon_scenarios|isr_scenarios|isr_scenarios_rp2040|dualcore_cases|cycle_cases|bank_conflict_cases|silicon_oracle|gdb_client|ieee754_ref|onerom_stress|onerom_serving_oracle|onerom_serving_oracle_cpu|onerom_cpu_speed_grade|onerom_trace|onerom_glue_dma|onerom_snapshot_fmt|onerom_sync|picogus_pins)\.rs|crates[\\/]mdrp2(350|040)app[\\/]src[\\/](main|ui|sim|firmware|panels[\\/][^\\]+)\.rs)'
```

To get just a summary against the cached `.profdata`:

```bash
cargo +nightly llvm-cov report --branch --ignore-filename-regex '<same regex>'
```

## Stage 6 — Residue

**Target: crossing 98% branch coverage.**

After Stages 1–5 re-run coverage and iterate on whatever remains. Common shapes:
- Remaining error paths in `core/mod.rs`, `core/registers.rs`, `threaded/atomics.rs`.
- Common crate cleanup: `mdpicoem-common/src/{memory,fifo,clock}.rs`.
- Harness library: `mdpicoem-harness/src/lib.rs` (170 branches, 50 missed — identify which are actually library helpers vs bin-only glue).
- riscv core: `core_riscv/{mod,decode,irq}.rs`.

Residual policy: a branch that protects an unreachable internal invariant (for example, `unreachable!()` after a `match` over an enum that covers every variant explicitly) is annotated `#[cfg_attr(coverage_nightly, coverage(off))]` with a one-line justification. These annotations must be reviewed in commit; no blanket adds.

## Acceptance criteria

- Fresh coverage run under the Stage 0 command shows **branch coverage ≥ 98.00%** on the in-scope slice.
- `cargo +nightly test --workspace` is green.
- `cargo build --release` has zero warnings on touched files.
- No net regression in line / region / function coverage (all ≥ their Stage 0 values).
- Each stage is a separate commit on `main` (or PR, per Arthur's preference). Commit messages follow the template in each stage.
