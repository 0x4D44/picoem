# RP2040 Peripheral Coverage — HLD V3

Supersedes V2. Incorporates Round-2 team review of 2026-04-15. Net change from V2: cuts ≫ additions — the design is lighter, not heavier.

## 1. Purpose

Add emulation for RP2040 peripherals that the motivating firmware corpus (§3) touches, so `mdrp2040` runs those binaries to completion instead of falling into `HashMap<u32, u32>` fallthrough.

In scope: **TIMER + WATCHDOG_TICK** (Phase 1), **UART, SPI, I2C** (Phase 2), **ADC, PWM** (Phase 3), **DMA** (Phase 4).

### Non-goals

- Full datasheet coverage per peripheral. Implement the register set the corpus actually touches; the bus dispatcher's own trace (§4.3) surfaces the gap when firmware reads a register we didn't model.
- WATCHDOG reset logic, RTC. Deliberately cut. Add a phase when a concrete firmware demands it.
- USB, VREG, TBMAN, BUSCTRL, SYSCFG, PSM. Stay in HashMap until something breaks.
- Non-pico-sdk runtimes (MicroPython, Embassy, bare-metal). Scope may under-cover; revisit when motivated.
- Cycle-accurate peripheral timing finer than one sys_clk. SysTick window treated as a soft assertion (§4.2). If a firmware ever needs tighter timing, it's a separate oracle HLD.
- RP2350 mirror. Impls live in `crates/mdrp2040/`. Extraction to `mdpicoem-common` deferred until a second consumer exists (CLAUDE.md §Quality: don't predict the future).
- Backwards compatibility or migration paths.

## 4. Oracle strategy

Hardware: physical RP2040 on the lab rig, Pico debug probe back-to-back, same topology as RP2354.

### 4.1 `probe_diff_rp2040` — CPU-level oracle

Port `crates/mdpicoem-harness/src/bin/probe_diff_rp2350.rs`. Two clarifications:

- **Filter is probe-side only.** `qemu_diff_m0plus.rs:291` stays strict (QEMU is `cortex-m0`, Thumb-32 UNDEFs). `probe_diff_rp2040` admits the subset `BL`, `MRS`, `MSR`, `DSB`, `DMB`, `ISB`.
- **Generator audit.** Phase 0 verifies `crates/mdpicoem-harness/src/thumb32_gen.rs` emits the subset. **Budget cap: 2 days.** If missing-case work exceeds that, Phase 0 slips and the slip is journaled. Do not absorb it silently into the Phase 0 budget.

### 4.2 `silicon_periph_diff_rp2040` — end-state scenario oracle

Port `silicon_periph_diff_rp2350.rs`'s `PeriphScenario`. V3's RP2040 shape is identical to the RP2350 shape **plus one u32 field**:

```rust
pub struct PeriphScenario {
    pub name: &'static str,
    pub setup: &'static [(u32, u32)],
    pub max_sysclks: u32,
    pub min_sysclks: u32,             // NEW: catches "completed too fast" bugs
    pub observe: &'static [(u32, u32)],
    pub observe_pins: u32,
    pub custom_sled: Option<&'static [u8]>,
}
```

`min_sysclks` is a single field, catches the off-by-one ring-wrap bug class where end-state looks correct but the scenario finished in N-1 iterations instead of N.

No `WaitSysclks` variant, no `checkpoints` array. If Phase 4 DMA work proves `min_sysclks` insufficient for catching ring off-by-one, an intermediate-state mechanism is added **then**, against a concrete failing scenario — not speculatively. (Round-2 team pressure was that adding these up front is machinery in search of a bug.)

**Timing window is a soft assertion.** SysTick programmed once at scenario start (`SYST_CSR = CLKSOURCE|ENABLE`, `SYST_RVR = 0x00FFFFFF`, `SYST_CVR = 0`). Read `SYST_CVR_start` before setup, `SYST_CVR_end` after halt. `window = CVR_start − CVR_end`. No wrap (24-bit window, scenarios < 2^24 sys_clk). Report-only unless outside `[min_sysclks, max_sysclks]`. No framing cancellation; single-run. If we ever need cycle-accurate RP2040 timing, a separate `silicon_cycle_oracle_rp2040` HLD (not this one).

### 4.3 MMIO capture — via the bus, not probe-rs

V2 proposed a Python script using probe-rs memory watchpoints. That doesn't work: RP2040 M0+ has no data-match DWT, and SWD does not observe bus cycles. Rejected.

Replacement: a harness binary, `crates/mdpicoem-harness/src/bin/mmio_trace_rp2040.rs`, that loads a firmware binary into the existing emulator and wraps the bus with a logger. On every peripheral MMIO access — **whether the peripheral is modelled or falls into HashMap** — log `(addr, size, R/W, core, pc)` to stdout or a file.

Why this works:
- The emulator IS the tracer. No external tooling.
- Already-modelled peripherals (CLOCKS, RESETS, SIO, PIO, PPB) log their hits, so we see what firmware touches before it would have fallen into HashMap. This is the dataset we actually want.
- The logger is ~20 lines of code added to `Bus::read32`/`write32` behind a runtime flag set by the binary, not an env var, not a feature flag.

Phase 0 runs `mmio_trace_rp2040` against `hello_timer` on the emulator to produce the TIMER register subset. Output is plain text, not committed — it's a scratch artefact; no `wrk_docs/trace/` directory, no repo bloat.

### 4.4 Phase 0 exit criteria — red-path validated

Phase 0 completes when **all four** hold:

1. `probe_diff_rp2040` runs `--fuzz 10000` green, including the Thumb-32 subset.
2. `silicon_periph_diff_rp2040` runs a known-good SIO GPIO scenario green.
3. `silicon_periph_diff_rp2040` runs **three deliberately-broken** scenarios — one per major oracle class — and each prints FAIL with correct `first_divergence`:
   - GPIO: wrong `SIO_GPIO_OUT` bit flipped.
   - TIMER: `TIMERAWL` read-path returns 0.
   - MMIO store: `XOSC_CTRL` write swallowed.
   
   Not a single oracle sniff-test; the three classes prove the oracle's red path fires across observable types we use in Phase 1+.
4. `mmio_trace_rp2040` runs `hello_timer` on the emulator to completion of its bootrom-probe portion (before TIMER is needed) and emits a readable stdout trace with non-empty TIMER-base-address entries once firmware calls `busy_wait_us_32`.

### 4.5 Triage procedure (silicon ≠ emulator)

1. **Reproduce** on silicon with scenario/seed.
2. **Check probe-rs** by reading a register with a stable, RESETS-released canonical value — the obvious candidate is SIO `GPIO_OUT_XOR` (documented 0 at reset, not held in RESETS). If probe-rs reads non-zero here, probe-rs is suspect.
3. **Check silicon health** via `probe_verify_rp2040` — round-trip the same scenario against a register known correct in the emulator (SIO mirror). If silicon disagrees with itself across runs, board issue.
4. Only after (2) and (3) clear: assume emulator bug.

Record each divergence in `wrk_journals/` with verdict and scenario seed.

## 5. Architecture

### 5.1 Peripheral pattern — inherent methods, no trait

Delete `mdpicoem-common::Peripheral` (unused). Each peripheral is a struct in `crates/mdrp2040/src/peripherals/<name>.rs` with inherent methods:

```rust
pub struct TimerRegs { /* fields */ }

impl TimerRegs {
    pub fn read32(&mut self, offset: u32) -> u32 { ... }
    pub fn write32(&mut self, offset: u32, value: u32, alias: u32, irqs: &mut u32) { ... }
    pub fn tick(&mut self, irqs: &mut u32) { ... }       // only if stateful-per-cycle
    // Optional overrides:
    pub fn read8(&mut self, offset: u32) -> u8 { ... }
    pub fn write8(&mut self, offset: u32, value: u8, irqs: &mut u32) { ... }
}
```

No trait. Consistency by review. Dispatch is a match arm in `Bus::peripheral_read32`/`peripheral_write32`.

**Ownership.** Peripheral fields and `irq_pending` are `pub(crate)` sibling fields on `Bus`. No accessor methods that borrow `&mut self`. Dispatch is direct field access:

```rust
// In Bus::peripheral_write32:
TIMER_BASE => self.timer.write32(off, val, alias, &mut self.irq_pending),
```

Compiles because Rust's split-borrow sees two disjoint `&mut` into different fields of the same struct.

### 5.2 IRQ plumbing

One field on `Bus`: `pub(crate) irq_pending: u32`. 26 IRQs (RP2040 has exactly 26, datasheet §2.3.2 — see Appendix B). Peripherals assert via `*irqs |= 1 << IRQ_TIMER_IRQ_0;`.

**Level semantics.** Peripherals re-assert every cycle the IRQ condition holds (UART RX FIFO non-empty → asserts each tick until the firmware drains). NVIC handles pending latching. Matches silicon's level-to-NVIC inputs.

**Pulse-style sources.** TIMER alarm match and similar "pulse" IRQs are asserted exactly once at the match cycle by the lazy-scheduled-event mechanism (§5.5). Level vs pulse is a peripheral-internal distinction; the `irq_pending` bitmap only carries "assert now or don't".

**Drain granularity.** `irq_pending` drains per inner-cycle iteration of the tick loop, not per `Emulator::step`. TIMER alarm matching on cycle 3 of a 10-cycle step fires on cycle 3:

```rust
if self.bus.irq_pending != 0 {
    let raised = std::mem::replace(&mut self.bus.irq_pending, 0);
    for irq in 0..IRQ_COUNT {
        if raised & (1 << irq) != 0 {
            self.cores[0].nvic.set_pending(irq);
            self.cores[1].nvic.set_pending(irq);
        }
    }
}
```

Threaded-cores will later need `AtomicU32`; not built now.

### 5.3 RESETS and clock gating

**RESETS gating — Bus-level guard, not per-peripheral.** `Bus::peripheral_read32` and `peripheral_write32` check `self.resets.is_held(bit)` for the dispatch target **before** calling the peripheral's method:

```rust
fn peripheral_write32(&mut self, addr: u32, val: u32) {
    match base_of(addr) {
        TIMER_BASE if self.resets.is_held(RESET_BIT_TIMER) => return, // swallowed
        TIMER_BASE => self.timer.write32(off, val, alias, &mut self.irq_pending),
        ...
    }
}
```

Peripherals never see a reset-gated call; the table of (BASE, RESET_BIT) pairs lives at the top of `bus/peripheral_dispatch.rs`. `ResetsState::is_held(bit: u8)` is added to the existing RESETS peripheral.

**Tick path** similarly: `tick_peripherals` short-circuits any peripheral held in reset before calling its `tick`.

**Clock domains.** Emulator reset state models post-bootrom state — `clk_sys` running at 125 MHz (firmware can reprogram), `clk_peri = clk_sys`, `clk_adc = 48 MHz`, `clk_rtc = 46875 Hz`. Deliberate simplification: firmware loaded via `load_image` skips the bootrom, so we start from a known-good clocked state. Firmware that reprograms CLOCKS reconfigures the `ClockTree` cache as it does today.

| Peripheral | Clock | V3 treatment |
|---|---|---|
| TIMER | `clk_ref / WATCHDOG_TICK.CYCLES` (1 µs) | Lazy; recompute from `master_cycle`. Cached fire-cycles invalidated on WATCHDOG_TICK write. |
| ADC | `clk_adc` (48 MHz) | Fixed-point accumulator: `adc_phase += ADC_HZ; if adc_phase >= SYS_HZ { adc_phase -= SYS_HZ; adc.tick(); }`. Constants derived from `ClockTree`. |
| RTC | `clk_rtc` | Cut from V1 (non-goal). |
| UART/SPI/I2C | `clk_peri` | V1: treat as clk_sys (post-bootrom default). If Phase 2 firmware reprograms clk_peri, revisit then. |
| PWM, DMA | `clk_sys` | No scaling. |

`WATCHDOG_TICK.CYCLES = 0` hangs the TIMER in silicon. Our emulator: same — TIMER does not advance, divide-by-zero avoided via explicit check in the lazy compute path.

### 5.4 Atomic aliases and byte/halfword access

**Alias per-register.** `write32(offset, value, alias, irqs)`. Peripheral decides per-register:

- **Plain storage register**: apply `apply_alias_rmw(&mut stored, value, alias)`. Helper in `peripherals/mod.rs`.
- **Side-effect register** (TIMER INTR W1C, UART_DR FIFO push, DMA CH_TRIGGER): alias interpretation is register-specific. TIMER_INTR alias-BITSET maps to W1C on the set bits. UART_DR alias is unspecified-behaviour at silicon; emulator treats as plain write. Each peripheral's module documents the table.

**Byte/halfword on side-effect registers.** UART_DR, SPI_DR, I2C_IC_DATA_CMD are byte-accessible on silicon. `bus/mod.rs:594-596` word-RMW pops/pushes an extra FIFO entry. Fix: the dispatcher prefers the peripheral's `read8`/`write8`/`read16`/`write16` if present (trait-like check via the match arm), falls back to word-RMW for peripherals that don't need it.

### 5.5 Per-cycle tick

Generalise the PIO slow-path loop at `crates/mdrp2040/src/lib.rs:303`. After the dual-core step:

```rust
for _ in 0..consumed {
    self.bus.tick_peripherals();       // body: simple ifs
    self.bus.update_gpio();
    self.drain_pending_irqs_to_cores();
}
```

`tick_peripherals` body (V3 simpler than V2):

```rust
fn tick_peripherals(&mut self) {
    // Order matters; see §5.6.
    self.pio[0].tick(&mut self.irq_pending, ...);
    self.pio[1].tick(&mut self.irq_pending, ...);
    if !self.resets.is_held(RESET_BIT_PWM) { self.pwm.tick(&mut self.irq_pending); }
    if !self.resets.is_held(RESET_BIT_ADC) { self.adc.tick(&mut self.irq_pending); }
    // DMA last — §5.6.
    self.tick_dma();
}
```

No `active_tickers` bitmap, no `PERIPHERAL_TICK_FNS` table. At most ~4 ifs per cycle; the indirect-call table was premature optimisation. Peripherals with no per-cycle state (TIMER, RTC, WATCHDOG_TICK) have no `tick` method — they're lazy, computed from `master_cycle` on read, with alarm IRQs scheduled at write-time.

UART/SPI/I2C tick only when actively transmitting/receiving; the `if !idle()` check lives inside their `tick` method (one-line early-out). 0–3 peripherals typically have real per-tick work.

### 5.6 DMA — bus master

`Dma` lives on `Bus` as a named field. Tick via owned swap:

```rust
// On Bus:
pub fn tick_dma(&mut self) {
    let mut dma = std::mem::take(&mut self.dma); // Dma: Default
    dma.tick(self); // bus without dma — but with irq_pending, uart0, pio, ...
    self.dma = dma;
}

// On Dma:
pub fn tick(&mut self, bus: &mut Bus) {
    // Read DREQ state from bus.uart0.tx_dreq() etc.
    // For each enabled channel: if dreq high, issue one transfer via bus.read/write.
    // Mutate bus.irq_pending directly for DMA_IRQ_0/1.
}
```

No `DmaMaster` trait (V2 compile error also fixed: V2 had `dma.tick(self, &mut self.irq_pending)` which violated borrow-checking because `self` included `irq_pending`; V3 passes `bus` only, DMA reaches irq_pending through it).

**Zero-read window.** While `self.dma` is moved out, a read to `DMA_BASE` returns `Default::default()` zeros. This can only happen via a same-cycle fault handler servicing a DMA-issued transfer that itself raises a fault. In our single-threaded model this is unreachable; documented as known anomaly.

**Ordering within a cycle** (documented contract):
1. PIO blocks tick (produces TX/RX DREQ).
2. PWM, ADC tick.
3. Other peripherals' per-cycle tick (UART/SPI/I2C when active).
4. `tick_dma` — reads DREQ snapshot, issues one transfer per enabled channel.
5. `update_gpio`.
6. Drain `irq_pending` to both NVICs.

DMA transfers issued on cycle N are visible to peripheral registers on cycle N (same-cycle write-through). Peripherals consuming the data (e.g. PIO consuming a new TX FIFO entry) observe it on their next tick (cycle N+1). This matches silicon AHB semantics — AHB write-settle is synchronous-on-cycle; consumption-by-producer is on the next peripheral-clock edge.

### 5.6.1 DMA V1 scope

- 12 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- **`RING_SIZE` / `RING_SEL`** — address masking for ring buffers. `audio_i2s` requires it.
- **`CHAIN_TO`** — **full chained triggering**, not just IRQ framing. `audio_i2s` uses a control-channel / data-channel pair where the control channel reloads and triggers the data channel. Implementation: when `TRANS_COUNT` reaches 0 on a channel with `CHAIN_TO != self`, issue a completion event that enables the CHAIN_TO target channel.
- **`CH_ABORT`** — writing 1-bits asserts abort; channel completes current in-flight transfer (single-cycle in our model, so "current" is the one being issued this tick), then clears BUSY. Documented: `BUSY` may remain 1 for up to one cycle after CH_ABORT write.
- `INTE0`/`INTE1` enable masks, `INTS0`/`INTS1` W1C, IRQ0/IRQ1 lines.
- Two-tier priority via `HIGH_PRIORITY`: priority-1 channels arbitrate among themselves lowest-channel-wins, then priority-0 channels the same. Round-robin within-tier is not modelled; `audio_i2s` uses priority without multi-high-priority competition. Documented simplification.
- **Not in V1**: CRC, sniff, byte-swap, read/write error IRQs, ring across non-aligned base.

**DREQ table.** Appendix C pins the 40 sources. `dreq.rs` lands in Phase 4 only, not V1 scaffolding. Phases 1–3 don't reference DREQ.

## 7. Testing

**Oracle hierarchy (strongest to weakest):**

1. **`silicon_periph_diff_rp2040`** — load-bearing. Peripheral ships scenarios sufficient to turn its corpus entry green. No scenario-count quota.
2. **`probe_diff_rp2040`** — CPU-level fuzz each phase. Catches `Bus` surgery regressions.
3. **In-crate self-consistency checks** — `#[cfg(test)]` per peripheral. Drive via inherent methods. Not unit tests in the strong sense; bidirectional bugs (same error in setup and observation) pass. Catch typos, protocol errors.
4. **Integration smoke** — corpus binary runs to its documented completion state.

**Scenario runtime.** Single `Session::auto_attach` reused across scenarios (per `test_silicon` convention). ~1 s/scenario overhead. Total V1 catalogue ≤60 scenarios → ~1 minute silicon run.

**Flake policy.** Retry once on probe-rs `Io` or `Session` transient errors. Any other error path fails the scenario. "Transient" = strictly matched by probe-rs error kind; not a judgment call, not an env var. Persistent flake → triage per §4.5.

## 9. Risks & open questions

### 9.1 SysTick window is a soft assertion

`[min_sysclks, max_sysclks]` detects catastrophic miscount; a scenario that finishes within bounds but with wrong cycle-by-cycle timing goes undetected. This is a conscious V1 limitation. A future `silicon_cycle_oracle_rp2040` HLD addresses it if the corpus demands.

### 9.2 Bootrom re-hit

Phase 1 TIMER + Phase 2 UART unblock firmware past `busy_wait_us_32`. Those firmwares reach bootrom paths (`flash_get_unique_id`, `_reset_to_usb_boot`, `rom_func_lookup`) that collide with the SSI stub (`bus/mod.rs:560-563`). **This HLD does not fix SSI.** Failure mode: pico-sdk boot halts at SSI. Mitigation today: `load_image` bypasses bootrom, loading directly into SRAM. Firmware using only the `__no_inline_not_in_flash_func` fast path runs without touching flash peripherals. When motivated, a separate HLD expands SSI.

### 9.3 HashMap fallthrough wrongness

Firmware reads USB_CTRL, BUSCTRL, VREG expecting specific reset values; HashMap returns 0. Some firmware doesn't care; some does. `mmio_trace_rp2040` surfaces these as "firmware read unmodelled address X, got 0"; resolution is per-firmware: promote the peripheral, or stub the single register with its datasheet reset value in the match arm. Known unknowns logged in `wrk_journals/`.

### 9.4 Dual-core peripheral arbitration

Both cores writing UART_DR same cycle: emulator single-threaded, core 0 goes first. Silicon: AHB arbitrates (undocumented order for APB peripherals). No scenario exercises this on pico-sdk; revisit on first corpus divergence.

### 9.5 Concurrent workspace collision on `Bus`

`Bus` is modified in this HLD. Land `irq_pending` field + `tick_peripherals` generalisation + RESETS guard as a **single atomic commit** before any peripheral-specific code. Minimises merge surface for concurrent work.

### 9.6 ISR re-assertion cost

Level-semantic IRQs (UART RX FIFO non-empty) `|= 1 << IRQ_N` every cycle until firmware drains the source. 125 M ORs/sec per idle-pending peripheral. Cheap, measured as noise, documented here for future profilers hunting tick cost.

### 9.7 Probe rig failure

No fallback oracle. Rig down → phase halts. Self-consistency checks and `qemu_diff_m0plus` keep running but don't exercise peripherals. Diagnosed per §4.5; expected time-to-repair is short given Arthur's 30-minute rig-up cadence for the RP2354 setup. Acknowledged, not engineered around.

### 9.8 Corpus binary bloat

Phase 0 builds corpus `.elf` + `.bin` from pinned SDK commits. Build script committed under `roms/rp2040/corpus/build.sh`; binaries regenerated, not committed, to avoid repo bloat and stale-artefact problems. Build reproducibility verified by Phase 0; SHA256 of each binary recorded in Appendix A.
