# Phase 5: Dual Core + SIO — Low-Level Design

Version: 0.1.0
Date: 2026-04-13
Parent: HLD Section 15, Phase 5
Depends: Phase 4 complete (bootrom + flash boot working)

## 1. Purpose

Enable both Cortex-M33 cores to run simultaneously. Core 1 boots the real
bootrom (same reset vector as Core 0), enters the bootrom's FIFO-polling wait
loop, and can be launched by Core 0 via the standard Pico SDK
`multicore_launch_core1` protocol. Implement the remaining SIO block features:
inter-processor FIFO, hardware spinlocks, integer divider, doorbells, and
platform timer.

### Milestone

Integration test: load bootrom + dual-core Pico SDK binary → bootrom boots
both cores → Core 0 app launches Core 1 via FIFO handshake → both cores
execute independently → each core sets a GPIO pin → verify both pins in
SIO GPIO_OUT.

### What exists today

| Component | Status | Gap for Phase 5 |
|-----------|--------|-----------------|
| Core 1 | Created + immediately halted | Must boot from bootrom |
| CPUID (0x000) | Returns `active_core()` | ✓ Works as-is |
| GPIO (SIO) | Inline in Bus dispatch | Move to Sio struct |
| FIFO | Not implemented | Needs TX/RX queues + status register |
| Spinlocks | `[u32; 32]` in Sio, unused | Needs atomic test-and-set logic |
| SPINLOCK_ST | Not implemented | Needs bitmask register |
| Integer divider | Not implemented | Needs per-core state |
| Doorbells | Not implemented | Needs per-core pending bits |
| Platform timer | Not implemented | Needs MTIME counter + compare |
| Interpolators | Not implemented | Register stub only (Phase 7) |
| WFE/SEV | Both are NOPs | Needs event flags + stall/wake |
| NS alias (0xD4xx) | Not handled (offset mismatch) | Fix addr masking |

## 2. Design

### 2.1. SIO struct refactor

Move GPIO state from Bus into Sio. Make Sio handle all region-0xD register
dispatch via `read32(reg_offset, core_id)` and `write32(reg_offset, val, core_id)`.
Bus delegates all 0xD accesses to `self.sio`, following the PPB pattern
(`self.ppb[core].read32(addr)`).

Move Sio from `Emulator` to `Bus` (currently Emulator owns both `bus: Bus`
and `sio: Sio` separately — the Sio field is constructed but never used by
Bus). After this change, `Emulator.sio` is removed.

Address masking fix: change `addr & 0x0FFF_FFFF` to `addr & 0xFFF` so both
Secure (0xD0000000) and Non-Secure (0xD4000000) aliases resolve to the same
register offset. The HLD specifies both aliases map to the same backing state
in v1.

```rust
// Bus dispatch (region 0xD):
0xD => {
    let reg_offset = addr & 0xFFF;
    let core = self.active_core();
    self.sio.read32(reg_offset, core)
}
```

External access changes: `emu.bus.gpio_out` → `emu.bus.sio.gpio_out`.

### 2.2. Inter-processor FIFO

Two 8-entry circular buffers, one per direction. Core 0's FIFO_WR pushes
to Core 1's receive queue, and vice versa.

```rust
struct Fifo {
    buf: [u32; 8],
    head: u8,  // read index
    tail: u8,  // write index
    count: u8,
}
```

| Offset | Register | Read | Write |
|--------|----------|------|-------|
| 0x050 | FIFO_ST | Status bits (see below) | Write clears WOF/ROE flags |
| 0x054 | FIFO_WR | — | Push to OTHER core's RX queue |
| 0x058 | FIFO_RD | Pop from THIS core's RX queue | — |

FIFO_ST bits:
- Bit 0 (VLD): this core's RX queue has data
- Bit 1 (RDY): other core's RX queue has space (can write)
- Bit 2 (WOF): write overflow (sticky, clear on FIFO_ST write)
- Bit 3 (ROE): read underflow (sticky, clear on FIFO_ST write)

FIFO_RD when empty: returns 0, sets ROE flag.
FIFO_WR when full: data is lost, sets WOF flag.

### 2.3. Hardware spinlocks

32 shared locks at offsets 0x100–0x17C (one per word). Spinlocks are shared
across cores (not per-core), unlike the divider/interpolator.

```rust
spinlocks: [bool; 32],  // false = free, true = claimed
```

| Offset | Register | Read | Write |
|--------|----------|------|-------|
| 0x100+4*N | SPINLOCK*N* | Atomic claim: if free → claim + return 1; if claimed → return 0 | Release (any value) |
| 0x05C | SPINLOCK_ST | Bitmask of all 32 locks (bit N = SPINLOCK*N* claimed) | — |

No ownership tracking — the hardware doesn't enforce which core can release.

### 2.4. WFE/SEV semantics

The bootrom's Core 1 wait loop uses WFE. The SDK's `multicore_launch_core1`
calls SEV after writing the FIFO launch sequence. We need these to actually
stall/wake rather than NOP.

Per-core event state lives on Bus (shared, accessible from the step loop):

```rust
pub event_flag: [bool; 2],   // ARM event register, per core
```

Per-core WFE stall tracked on CortexM33:

```rust
pub wfe_waiting: bool,  // true = core is WFE-sleeping
```

**WFE instruction** (Thumb-16 and Thumb-32):
1. If `bus.event_flag[core]` is set → clear it, return 1 cycle (no sleep)
2. Else → set `self.wfe_waiting = true`, return 1 cycle

**SEV instruction**: set `bus.event_flag[0] = true` and `bus.event_flag[1] = true`.

**Core step**: if `wfe_waiting`, skip entirely (no decrement, no fetch).

**Emulator step loop** (after both cores step):
```rust
for i in 0..2 {
    if self.cores[i].wfe_waiting && self.bus.event_flag[i] {
        self.bus.event_flag[i] = false;
        self.cores[i].wfe_waiting = false;
    }
}
```

This gives 1-cycle wake latency, which is realistic.

### 2.5. Core 1 boot sequence

Change `Emulator::reset()` to start both cores at the reset vector:

```rust
for id in 0..2 {
    self.cores[id] = CortexM33::with_id(id as u8);
    self.cores[id].regs.msp = initial_sp;
    self.cores[id].regs.r[13] = initial_sp;
    self.cores[id].regs.set_pc(reset_vector & !1);
    self.cores[id].regs.xpsr = 1 << 24;
}
```

The bootrom checks CPUID (SIO 0x000) to differentiate cores. Core 1 sees
CPUID=1, branches to `core1_wait`, enters the WFE + FIFO poll loop. Core 0
proceeds with normal boot. No special emulator-side wake mechanism needed —
the bootrom handles Core 1's lifecycle.

**Pico SDK launch protocol** (for reference — this is SDK code, not emulator):
1. Core 0 sends `{0, 0, 1, vtor, sp, entry}` via FIFO_WR
2. Core 1 validates the sequence, echoes non-zero values back via FIFO_WR
3. Core 0 verifies echoes
4. Core 1 sets VTOR (PPB 0xE000ED08), SP, and branches to `entry`
5. Core 0 calls SEV after FIFO writes to wake Core 1's WFE

### 2.6. Integer divider

Per-core hardware divider (each core has independent state via SIO).
Computation is immediate — result available on the same cycle the divisor
is written. CSR.READY is always 1.

```rust
struct Divider {
    dividend: u32,  // last written (signed or unsigned)
    divisor: u32,
    quotient: u32,
    remainder: u32,
    signed: bool,   // last operation was signed
}
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x060 | DIV_UDIVIDEND | Write: set dividend, mark unsigned |
| 0x064 | DIV_UDIVISOR | Write: set divisor, compute unsigned result |
| 0x068 | DIV_SDIVIDEND | Write: set dividend, mark signed |
| 0x06C | DIV_SDIVISOR | Write: set divisor, compute signed result |
| 0x070 | DIV_QUOTIENT | Read: result. Write: set directly |
| 0x074 | DIV_REMAINDER | Read: result. Write: set directly |
| 0x078 | DIV_CSR | Bit 0 (READY): always 1. Bit 1 (DIRTY): 1 after any div reg write |

Writing the divisor (UDIVISOR or SDIVISOR) triggers the computation. Division
by zero: quotient = 0xFFFFFFFF (unsigned) or -1/+1 (signed), remainder =
dividend. This matches ARM division semantics.

**Not implementing:** 8-cycle division latency with auto-stall on early read.
The SDK inserts explicit delays; immediate results are functionally correct.
Cycle-accurate divider timing is Phase 8 polish.

### 2.7. Doorbells

8 doorbell bits per core. Writing to DOORBELL_OUT sets bits on the other core.
Reading DOORBELL_IN shows which bits are pending for this core.

```rust
doorbell: [u8; 2],  // doorbell[core] = pending bits for that core
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x180 | DOORBELL_OUT_SET | Write: `doorbell[1 - core] |= val` |
| 0x184 | DOORBELL_OUT_CLR | Write: `doorbell[1 - core] &= !val` |
| 0x188 | DOORBELL_IN_SET | Read: `doorbell[core]` |
| 0x18C | DOORBELL_IN_CLR | Write: `doorbell[core] &= !val` |

**IRQ delivery:** When doorbell bits transition 0→nonzero on a core, set
SIO_IRQ_BELL pending on that core's NVIC. Exact IRQ number TBD — verify from
RP2350 datasheet during implementation.

### 2.8. Platform timer (MTIME)

64-bit counter accessible via SIO. Increments once per system clock tick when
enabled. Per-core 64-bit compare registers for timer interrupts.

```rust
mtime: u64,
mtime_ctrl: u32,
mtimecmp: [u64; 2],  // per-core compare value
```

Increment logic in `Emulator::step()` (after stepping cores):
```rust
if self.bus.sio.mtime_ctrl & 1 != 0 {  // enabled
    self.bus.sio.mtime = self.bus.sio.mtime.wrapping_add(1);
}
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x1B0 | MTIME_CTRL | Bit 0: enable. Other bits TBD |
| 0x1B8 | MTIME (low) | Read/write low 32 bits of counter |
| 0x1BC | MTIMEH (high) | Read/write high 32 bits of counter |
| 0x1C0+8*core | MTIMECMP (low) | Per-core compare value, low 32 |
| 0x1C4+8*core | MTIMECMPH (high) | Per-core compare value, high 32 |

Note: exact register offsets will be verified against the RP2350 datasheet
during implementation. The layout above follows the RISC-V MTIME convention.

### 2.9. Interpolator stubs

Two interpolators per core (INTERP0 at 0x080, INTERP1 at 0x0C0), each with
~16 registers. Phase 5 provides a register backing store only — no
computation logic. Reads return the last written value. Full interpolator
arithmetic is Phase 7.

```rust
interp: [[u32; 16]; 2],  // [core][register_index]
```

Offsets 0x080–0x0BC (INTERP0) and 0x0C0–0x0FC (INTERP1): index as
`(offset - base) >> 2`.

## 4. Staging

### Stage A: SIO refactor + FIFO + spinlocks

Establish the SIO module as a proper self-contained struct, then add the
data-path registers. Two logical steps:

1. **Refactor** — Move Sio into Bus. Move GPIO from Bus to Sio. Delegate
   all 0xD dispatch to `self.sio.read32(offset, core)`. Fix NS alias
   masking (`addr & 0xFFF`). Update tests. Zero behavior change — all
   existing tests must pass.

2. **FIFO + spinlocks** — Add Fifo struct (two 8-entry circular buffers).
   Wire FIFO_ST/FIFO_WR/FIFO_RD. Add spinlock test-and-set read + write
   release + SPINLOCK_ST bitmask. Unit tests for: FIFO push/pop, FIFO
   full/empty/overflow, spinlock claim/release/contention.

### Stage B: Core 1 boot + WFE/SEV + divider

Enable Core 1 and the mechanisms needed for the bootrom's Core 1 path:

1. **WFE/SEV** — Add `event_flag: [bool; 2]` to Bus, `wfe_waiting: bool`
   to CortexM33. Change hint handlers in `execute.rs` (line 731) and
   `execute_thumb32.rs` (line 848) to dispatch WFE/SEV/WFI instead of NOP.
   Add post-step wake check in `Emulator::step()`. Unit tests.

2. **Core 1 boot** — Change `reset()` to start both cores at reset vector.
   Integration test: bootrom boots, Core 1 enters WFE/FIFO poll, Core 0
   reaches application. Verify Core 1 is WFE-sleeping (not faulted).

3. **Divider** — Add `Divider` struct, per-core state. Wire DIV_* register
   dispatch. Immediate computation. Unit tests for unsigned, signed,
   divide-by-zero.

### Stage C: Doorbells + timer + stubs + integration test

Leaf features and final validation:

1. **Doorbells** — Add doorbell pending bits and SET/CLR register dispatch.
   IRQ delivery placeholder (connect to NVIC when IRQ number confirmed).

2. **Platform timer** — Add MTIME counter + per-core MTIMECMP. Increment
   in emulator step loop. Timer interrupt pending when MTIME >= MTIMECMP.

3. **Interpolator stubs** — Register backing store at 0x080–0x0FC. No
   computation logic.

4. **Integration test** — Dual-core Pico SDK binary: Core 0 launches Core 1
   via FIFO, both cores set GPIO pins, verify both pins in GPIO_OUT.

## 6. Known Limitations

- **No divider latency.** Results are immediate (no 8-cycle delay, no auto-stall). Phase 8.
- **No interpolator computation.** Register store only. Phase 7.
- **No FIFO IRQ.** The SDK uses SEV for Core 1 wake, not FIFO interrupts. Add if needed.
- **No doorbell IRQ.** Registers work, interrupt delivery deferred until IRQ numbers confirmed.
- **MTIME tick rate fixed.** Increments once per system clock. The MTIME_CTRL prescaler is not modeled. Sufficient for `time_us_64()` if the SDK configures 1 MHz via TICKS peripheral.
- **No WFI semantics.** WFI treated as NOP. WFI needs pending-interrupt check to work properly; the bootrom uses WFE, not WFI, for Core 1 wait.
- **No TrustZone differentiation.** Secure and Non-Secure SIO aliases map to the same state (per HLD v1 design).

## 7. Risk Assessment

**Low risk:** SIO refactor. The GPIO-move touches ~20 lines in `bus/mod.rs`
and 4 lines in tests. The PPB pattern is proven. Existing tests validate
correctness immediately.

**Low risk:** FIFO + spinlocks. Pure data structures with well-defined
semantics. Easy to unit test in isolation.

**Medium risk:** Core 1 boot. The bootrom's Core 1 path may use SIO/PPB
features we haven't anticipated. Mitigation: trace Core 1's bootrom
execution (same iterative approach as Phase 3/4). The bootrom source is
open — we can inspect the Core 1 entry point.

**Medium risk:** WFE/SEV correctness. If the wake mechanism has a bug, Core 1
hangs forever. Mitigation: unit test WFE→SEV wake in isolation before
attempting bootrom integration. Fallback: if WFE/SEV proves problematic,
Core 1 can busy-poll (WFE as NOP) — slower but functional.

**Low risk:** Divider, doorbells, timer. Independent features with no
cross-dependencies. Can be tested in isolation.
