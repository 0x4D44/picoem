## Tranche 5 — Deferred risk (keep on the radar)

The one item that's *not* in any tranche above because it's a strategic call:

### D1. Threaded-Emulator field-access footgun mitigation
- **Background:** `tech_debt.md` lines 45-89 documents this. After `promote_to_threaded()`, `pub bus`, `pub cores`, `pub clock` become placeholders. Typed APIs `debug_assert!` against the placeholder flag; raw field access (`emu.bus.sio.gpio_out`, `emu.cores[0].regs.r[0] = …`) bypasses the guard and silently corrupts state. **Release builds have zero protection** because the asserts elide.
- **Current exposure:** No live caller exercises the escape (workspace grep is clean). Risk is that *any future contributor* on the threaded path who reaches through fields lands a silent corruption.
- **Mitigation:** Migrate `cores` / `bus` / `clock` to `pub(crate)` and add typed accessors. Estimated ~1287 call-site updates across ~40 files (per `tech_debt.md`'s own estimate).
- **Recommendation:** **Defer.** Re-evaluate when Threaded execution graduates from "validated against Serial" to "primary path for some workload". Until then, the risk is low (most contributors use the typed API by default) and the cost is high.
- **Tripwire:** If any new code in the next quarter is observed reaching through `emu.bus.` / `emu.cores[` / `emu.clock.` after `promote_to_threaded()`, escalate this to Tranche 1.

## What we explicitly didn't try to fix

- Performance regressions or unmodelled silicon timing (out of scope; oracle-tracked).
- Test coverage gaps (out of scope unless surfaced as a documented limitation).
- Build-system hygiene beyond `cargo tree --duplicates`.
- API ergonomics that aren't current pain points.

The audit and this plan are deliberately **narrow**: visible debt, low-cost fixes, with the high-cost strategic items called out as "defer" rather than buried.
