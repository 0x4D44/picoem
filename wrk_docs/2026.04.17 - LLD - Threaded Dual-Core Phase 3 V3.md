# Threaded Dual-Core Phase 3 — Low-Level Design

Version: 3.0.0
Date: 2026-04-17
Supersedes: V2 (same date)
Parent HLD: `2026.04.16 - HLD - Threaded Dual-Core Emulation V5.md`

## Changes from V2

Review round 2 (devil's advocate found 3 critical + 4 high + 4 medium):

- **`rcp_count` uses `AtomicU32::compare_exchange`** for `rcp_count_check` —
  previous V2 plain-load/store would lose updates under concurrent boot paths.
- **Decode cache invalidation is per-core, self-only.** `WorkerBus::write*`
  to executable regions invalidates *this core's* cache. Cross-core SMC
  requires firmware-side DSB+ISB+ICIMVAU per ARM spec (same as real hardware).
  Resolves "Bus can't reach cores" ambiguity.
- **STREX wires `monitors.snoop` at the CortexM33 call site**, not inside
  `SharedMemory::cas32`. `SharedMemory` stays decoupled from monitors.
- **SIO split made explicit**: `ThreadedSio` covers cross-core state (FIFOs,
  spinlocks, doorbells, MTIME, GPIO via AtomicGpio); new `PerCoreSio`
  struct on `CortexM33` holds divider + interpolator. Per-method migration
  table added (§6).
- **Missing `from_emulator` fields documented**: `peripheral_regs` (legacy
  HashMap, drop — Phase 2 typed registers replaced it), `flash_loaded`
  (move to `SharedMemory`), `last_access_cycles` (drop — debug only).
- **Mutex poisoning**: revert to `.unwrap()` (panic-on-poison). `into_inner()`
  would propagate corruption silently — worse than failing loud.
- **Worker panic recovery**: `catch_unwind` + `barrier.poison()` wrapper
  around each worker loop body (~20 LOC). Prevents test hangs when a
  worker panics. Still no per-ExitReason propagation (Phase 4).
- **Pinning warning** emitted when `available_parallelism() == 4`.
- **`sev_both` via `event_flag` store**: caller (CortexM33 executing SEV)
  calls `atomics.sev_both()`. WFE handler calls `atomics.event_flag_consume(id)`.
  No other consumers.
- **Tests re-add cross-thread race-critical paths**: RCP salt cross-core,
  DMB fence visibility. Total tests 13 (was 11 in V2, 21 in V1).
- Deleted "≤10 ns fence" perf claim (unsupported).

## Scope

Compose Phase 1/2 primitives into a 4-thread runtime:

1. `CoreBus` trait — MMIO surface `CortexM33` uses.
2. `CoreAtomics` — `Arc`'d cross-core per-core state.
3. `SharedState` — `Arc` bundle: memory, GPIO, threaded SIO, threaded PIO,
   monitors, core atomics, peripherals.
4. `WorkerBus` — per-CPU-thread bus view (impls `CoreBus`).
5. `PioBus` — PIO thread's view + owns `PioBlock`s.
6. `PerCoreSio` — per-core divider + interpolator, lives on `CortexM33`.
7. `Peripherals` — mutex-protected coordinator-owned state.
8. `ThreadedEmulator::from_emulator` — one-way decomposition.
9. `ThreadedEmulator::run_quanta(n)` — spawn 4 workers, run n quanta, join.
10. Windows thread pinning (logical cores 0/1/2/3).

**Explicitly deferred** (see §12): Pacer integration, `StopSignal`,
duration-based `run`, `ExitReason`, `reset()`, full panic recovery,
WFI deadlock detection, runtime quantum tuning, `paced_bench`.

### Platform gate

`#[cfg(all(target_arch = "x86_64", target_os = "windows"))]` on
`ThreadedEmulator`, `WorkerBus`, `PioBus`, `worker::*`, `pin_to_host_core`.

`CoreBus`, `CoreAtomics`, `PerCoreSio`, `SharedState` — no gate
(used by `CortexM33` on all targets).

## 1. `CoreBus` trait

Surface CortexM33 needs on the bus: MMIO + PC stash + bus-fault sticky
flag. Everything else (IRQ pending, SEV, halted, wfe_waiting, RCP salt)
is on `CoreAtomics` (§2) and reached via `self.atomics` directly.

```rust
pub trait CoreBus {
    fn read8(&mut self,  addr: u32, core: u8) -> u8;
    fn read16(&mut self, addr: u32, core: u8) -> u16;
    fn read32(&mut self, addr: u32, core: u8) -> u32;
    fn write8(&mut self,  addr: u32, val: u8,  core: u8);
    fn write16(&mut self, addr: u32, val: u16, core: u8);
    fn write32(&mut self, addr: u32, val: u32, core: u8);

    fn set_active_pc(&mut self, pc: u32, core: u8);

    fn bus_fault(&self) -> bool;
    fn bus_fault_addr(&self) -> u32;
    fn clear_bus_fault(&mut self);
}
```

10 methods. `CortexM33::step` and every helper in `core/*.rs` becomes
generic: `step<B: CoreBus>(&mut self, bus: &mut B)`. Monomorphised
at release (zero dispatch cost, ~300 KB .exe bloat — §13).

`impl CoreBus for Bus`: one-line delegates to existing `Bus` methods.

`impl CoreBus for WorkerBus`: §4.

### Why not put `bus_fault` on `CoreAtomics` too?

`CoreAtomics.bus_fault` exists (§2) for consistency with the "all
per-core shared state lives here" model. The trait's `bus_fault`
accessors delegate to `self.shared.atomics.bus_fault` for
`WorkerBus`; for `Bus` they're on a local field. One source of
truth per impl; trait shields the core from the difference.

## 2. `CoreAtomics`

```rust
pub struct CoreAtomics {
    pub halted:      [AtomicBool; 2],
    pub wfe_waiting: [AtomicBool; 2],
    pub event_flag:  [AtomicBool; 2],

    // Coordinator asserts; worker grabs-and-clears.
    pub irq_pending: [AtomicU64; 2],

    // RCP cross-core salt (peer writes target, target reads).
    pub rcp_salt:       [AtomicU32; 2],
    pub rcp_salt_valid: [AtomicBool; 2],
    // Shared redundancy counter. `count_check` is compare-then-increment,
    // which MUST use compare_exchange to be atomic under dual-core boot.
    pub rcp_count:      AtomicU32,

    pub bus_fault:      [AtomicBool; 2],
    pub bus_fault_addr: [AtomicU32; 2],
}
```

### Methods

```rust
impl CoreAtomics {
    // --- IRQ pending ---
    /// Coordinator + peripherals assert via fetch_or.
    pub fn assert_irq(&self, core: usize, irq: u32) {
        self.irq_pending[core].fetch_or(1u64 << irq, AcqRel);
    }
    pub fn assert_irq_shared(&self, irq: u32) {
        self.assert_irq(0, irq);
        self.assert_irq(1, irq);
    }
    pub fn clear_irq(&self, core: usize, irq: u32) {
        self.irq_pending[core].fetch_and(!(1u64 << irq), AcqRel);
    }
    /// Worker calls at top of quantum: atomic grab-and-clear.
    pub fn take_irq_pending(&self, core: usize) -> u64 {
        self.irq_pending[core].swap(0, AcqRel)
    }

    // --- WFE/SEV ---
    /// SEV instruction. Sets event_flag on BOTH cores (Armv8-M).
    pub fn sev_both(&self) {
        self.event_flag[0].store(true, Release);
        self.event_flag[1].store(true, Release);
    }
    /// WFE instruction / wake check. Atomic consume.
    /// Returns true iff there was a pending event (then don't sleep).
    pub fn event_flag_consume(&self, core: usize) -> bool {
        self.event_flag[core].swap(false, AcqRel)
    }

    // --- Halt / WFE waiting ---
    pub fn set_halted(&self, core: usize)   { self.halted[core].store(true,  Release); }
    pub fn clear_halted(&self, core: usize) { self.halted[core].store(false, Release); }
    pub fn is_halted(&self, core: usize) -> bool { self.halted[core].load(Acquire) }
    // ... parallel setters for wfe_waiting

    // --- RCP count (compare-then-increment atomicity) ---
    /// `rcp_count_set X` — unconditional store.
    pub fn rcp_count_set(&self, value: u32) {
        self.rcp_count.store(value, Release);
    }
    /// `rcp_count_check Y`: returns Ok(()) if current == expected, and
    /// the counter is atomically incremented. Err if mismatch.
    /// Uses compare_exchange to avoid lost-update races between cores.
    pub fn rcp_count_check(&self, expected: u32) -> Result<(), u32> {
        loop {
            let cur = self.rcp_count.load(Acquire);
            if cur != expected { return Err(cur); }
            match self.rcp_count.compare_exchange(
                cur, cur.wrapping_add(1), AcqRel, Acquire)
            {
                Ok(_) => return Ok(()),
                Err(_) => continue,  // peer incremented between load and CX
            }
        }
    }

    // --- Bus fault (per-core sticky) ---
    pub fn set_bus_fault(&self, core: usize, addr: u32) {
        self.bus_fault_addr[core].store(addr, Relaxed);
        self.bus_fault[core].store(true, Release);
    }
    pub fn clear_bus_fault(&self, core: usize) {
        self.bus_fault[core].store(false, Release);
    }
}
```

### `CortexM33` holds `atomics: Arc<CoreAtomics>`

- Construction: `CortexM33::with_id(core_id, atomics)` takes the Arc.
  Every unit test that builds a bare `CortexM33` now calls a small
  helper `CortexM33::for_test(core_id)` that allocates a `CoreAtomics`
  and passes it. ~15 test-site updates; all mechanical.
- `Bus::new()` constructs a `CoreAtomics`, holds it, and clones into
  each `CortexM33` at `Emulator` build. Same Arc appears in
  `ThreadedEmulator.shared.atomics`.

### Why not put atomics reach inside `CoreBus`?

V2 considered routing every `self.atomics.*` call via a trait method.
That re-inflates the trait to ~20 methods for ~zero benefit. Current
design: `CortexM33` carries the Arc directly, `CoreBus` stays at 10
methods. Doubled bookkeeping acknowledged.

## 4. `WorkerBus`

```rust
pub struct WorkerBus {
    core_id: u8,
    shared: SharedState,
    active_pc: u32,
    burst_mode: bool,
    extra_wait_states: u32,
}
```

PPB is on `CortexM33` (Phase 0b.1 Commit B); `WorkerBus` never sees
PPB addresses.

### Address dispatch

| Region (`addr >> 28`) | Routing |
|---|---|
| `0x0` ROM | `shared.memory.read*` |
| `0x1` XIP | `shared.memory.read*` |
| `0x2` SRAM | `shared.memory.read/write*`; invalidate own decode cache on write |
| `0x4` APB | sub-decode (below) |
| `0x5` AHB (DMA) | `peripherals.dma` mutex |
| `0xD` SIO | `shared.sio.*` / `shared.gpio.*` / `shared.atomics.*` (per §6 table) |
| `0xE` PPB | unreachable here (intercepted on CortexM33) |

### APB sub-decode

Direct port of `Bus::read32` decode match arms:

| Offset | Target |
|---|---|
| `0x4000_0000` CLOCKS, `0x4002_4000` XOSC, `0x4002_8000` PLL_SYS, `0x4002_C000` PLL_USB, `0x4006_0000` ROSC | `peripherals.clocks` |
| `0x4002_0000` RESETS | `peripherals.resets` |
| `0x4002_8000` IO_BANK0, `0x4003_8000` PADS_BANK0, `0x4005_0000` PWM (and similar)... | `peripherals.apb` |
| `0x4005_0000..` TIMER0/TIMER1, `0x4005_8000` TICKS, `0x4005_A000` WATCHDOG | `peripherals.timers` |
| `0x4007_0000` UART0, `0x4008_0000` SPI0, `0x4009_0000` I2C0, `0x400A_0000` ADC | `peripherals.apb` |
| `0x400D_0000` QMI | `peripherals.qmi` |
| `0x5020_0000..0x5040_FFFF` PIO0/1/2 | `shared.pio` (FIFOs + atomic control) + `PioCommand` queue |

Exhaustive decode: missing addresses raise bus fault (same as `Bus`).

### Exclusive-monitor snoop hooked inside `WorkerBus::write*`

```rust
impl CoreBus for WorkerBus {
    fn write32(&mut self, addr: u32, val: u32, core: u8) {
        // ...region dispatch; includes atomic SRAM write via shared.memory...
        self.shared.monitors.snoop(addr);
    }
    // write16/write8 follow same pattern; snoop after write.
}
```

### Decode cache invalidation (per-core, self-only)

When a write hits an executable region (ROM, XIP, SRAM), invalidate
the **owning core's** decode cache. Reach it via a mutable reference
passed through the step path — `CortexM33::step(&mut self, bus: &mut B)`
already has exclusive `&mut self` — so we use a callback:

```rust
impl WorkerBus {
    fn note_exec_write(&mut self, addr: u32) {
        self.pending_cache_invalidation = Some(addr);
    }
}
```

After each instruction, `CortexM33::step` checks
`bus.take_pending_cache_invalidation()` and invalidates the relevant
entry on `self.decode_cache`. Cross-core SMC (core 0 writes instruction
memory being executed by core 1) is **not automatically handled** —
matches ARM architectural requirement that firmware issue
`DSB; ISB; IC IVAU` for cross-core SMC. Documented trade-off.

The `CoreBus` trait is NOT extended for this — it's a detail of the
`WorkerBus` impl. `Bus` (single-threaded) keeps its current
`invalidate_all` flow.

### MMIO reads with side effects (enumerated)

Same behaviour as single-threaded (matches real hardware under
concurrent access). Documented so tests don't surprise:

| Address | Effect | Safe under threading? |
|---|---|---|
| `SIO.FIFO_RD` | Pops inter-core FIFO | Yes — lock-free SPSC |
| `SIO.SPINLOCK<N>` | Test-and-set (claim) | Yes — atomic `fetch_or` |
| `SIO.DIV_QUOTIENT/REMAINDER` | Clears DIRTY bit | Yes — per-core (on `PerCoreSio`) |
| `PIO.RXF<n>` | Pops RX FIFO | Yes — lock-free SPSC |
| `ROSC.RANDOM/RANDOMBIT` | Consumes entropy | Yes — mutex-serialised |
| `TIMER*.TIMELR` | Latches TIMEHR | Yes — mutex-serialised |

## 5. `PioBus`

```rust
pub struct PioBus {
    shared: SharedState,
    blocks: [PioBlock; 3],
}
```

PIO thread loop per quantum:
1. `shared.pio.drain_commands()` → apply each `PioCommand` into the
   local `PioBlock`s (instr_mem, clkdiv, etc.).
2. For each active SM (`shared.pio.read_sm_enabled(block)`), execute
   one PIO cycle × `step_quantum` times: I/O via `shared.gpio`,
   TX/RX via `shared.pio.tx_pop / rx_push`.
3. Update `shared.pio.irq_flags` / `dreq` atomics.

### CPU → PIO write visibility

One-quantum delay. CPU writes to PIO MMIO in quantum N become
visible to the PIO thread at the drain point in quantum N+1. Firmware
that issues `write INSTR_MEM[0] = X` followed immediately by
`write SM_ENABLE = 1` in the same instruction stream works because
both land in the same CPU quantum and both are drained by the PIO
thread together in quantum N+1. Sub-quantum ordering is undefined;
firmware needing tighter ordering must issue a DMB (which on real
hardware is required too).

### `PioCommand` — unchanged from Phase 2

```rust
pub enum PioCommand {
    WriteInstrMem { block: u8, addr: u8, value: u16 },
    SetClkDiv     { block: u8, sm: u8, int_div: u16, frac_div: u8 },
}
```

FIFO join (`JoinFifos`) deferred to Phase 5.

## 6. SIO ownership split: `ThreadedSio` vs `PerCoreSio`

Current `Sio` (single `crates/mdrp2350/src/sio/mod.rs`, ~790 LOC)
carries both shared state and per-core state. In threaded mode this
splits in two.

### `ThreadedSio` (cross-core, already implemented in Phase 2)

| Sio method | Threaded routing |
|---|---|
| `fifo_push / fifo_pop / fifo_st / fifo_st_clear` | `ThreadedSio::fifo_*` (lock-free SPSC) |
| `spinlock_claim / spinlock_release / spinlock_bits` | `ThreadedSio::spinlocks` (`AtomicU32`) |
| `doorbell_set / doorbell_clear / doorbell_read` | `ThreadedSio::doorbells` |
| `mtime_read / mtime_write / mtime_advance / mtimecmp_*` | `ThreadedSio::mtime*` |
| `gpio_out / gpio_oe / set / clr / xor / in_read` | `AtomicGpio` (NOT `ThreadedSio`) |

### `PerCoreSio` (per-core, new; lives on `CortexM33`)

```rust
pub struct PerCoreSio {
    pub divider: Divider,        // DIV_{U,S}{DIVIDEND,DIVISOR}, QUOTIENT, REMAINDER, CSR
    pub interp:  [Interp; 2],    // INTERP0_*, INTERP1_* lanes (peek, pop, accum, base, ctrl)
}
```

| Sio method | Threaded routing |
|---|---|
| `divider_set_dividend / divisor / read_quotient / read_remainder / read_csr` | `CortexM33.sio_local.divider.*` |
| `interp_*` (`peek`, `pop`, `accum_*`, `base_*`, `ctrl_*`) | `CortexM33.sio_local.interp.*` |

The existing `Divider` + `Interp` code in `mdpicoem-common` (or
`sio/divider.rs`, `sio/interp.rs`) is **unchanged** — only the storage
location moves. All ~790 LOC of logic bodies stay where they are.

### SIO MMIO dispatch (`WorkerBus::read32` / `write32`) at `0xD0...`

Decoded by offset:

| Offset range | Target |
|---|---|
| `0xD000_0000..0xD000_00FF` (GPIO IN/OUT/OE + CPUID + MTIME) | `AtomicGpio` / `ThreadedSio.mtime*` / constant CPUID |
| `0xD000_0050..0xD000_007F` (FIFO_ST, FIFO_WR, FIFO_RD) | `ThreadedSio.fifo_*` |
| `0xD000_0100..0xD000_017F` (SPINLOCK<0..31>) | `ThreadedSio.spinlocks` |
| `0xD000_0060..0xD000_00FF` (DIV_*) | `self.shared` can't reach the owning core's divider — routed through **CoreBus method or back-channel**... |

**Back-channel for DIV/INTERP.** The owning CortexM33 needs direct
access to its own `sio_local.divider / sio_local.interp` when the
instruction stream hits these MMIO addresses. Two options:

(a) **Extend `CoreBus`** with `sio_div_read / sio_div_write /
sio_interp_read / sio_interp_write` methods. `WorkerBus` impl routes
them to a callback into the owning core's `PerCoreSio`.

(b) **Intercept on `CortexM33`**: `CortexM33::bus_read32` wrapper
(which already intercepts PPB at `0xE...`) also intercepts
`0xD000_0060..0xD000_00FF` and `0xD000_0080..0xD000_00FF` and routes
to `self.sio_local` directly. Only same-core accesses are possible
(SIO DIV/INTERP are per-core registers), so this is correct by
construction.

**Choose (b).** No trait growth, matches the existing PPB-intercept
pattern. Single-threaded `Bus` does the same intercept, so single
code path across both modes.

### CP0 coprocessor (SIO via CP0)

`coprocessor.rs` currently calls `bus.sio.cp0_read(reg, cpuid)` for
CP0 MMIO-style access. Same split applies:
- GPIO/FIFO/spinlock CP0 ops → `shared.sio` / `shared.gpio` / `shared.atomics`
- DIV/INTERP CP0 ops → `self.sio_local.*`

Mechanical rewrite: `~30 call sites` in `coprocessor.rs` split between
the two targets based on CP0 register number.

## 7. `Peripherals` — coordinator-owned state

```rust
pub struct Peripherals {
    pub clocks: Mutex<ClocksState>,
    pub qmi:    Mutex<QmiState>,
    pub resets: Mutex<ResetsState>,
    pub apb:    Mutex<ApbState>,
    pub timers: Mutex<TimersState>,
    pub dma:    Mutex<DmaState>,
}
```

### Lock order (documented in `Peripherals` rustdoc only)

`clocks < qmi < resets < apb < timers < dma`

No `PeripheralGuard`, no thread-local stack. If a nested-lock site
ever appears, add a local `debug_assert!` at that specific site.

### Mutex poisoning policy

`.lock().unwrap()` — panic propagates. Proceeding on a poisoned
mutex (`into_inner()`) silently uses corrupted state; failing loud is
the right default. If Phase 4's real panic handling returns
`ExitReason::Panic`, we can revisit.

### `tick_peripherals` snapshot pattern

Coordinator takes `clocks` + `resets` briefly, snapshots
`ClockTree` + `resets_state` into locals, drops both. Then takes
`apb` / `timers` / `dma` sequentially and ticks each against the
snapshot. Alternative (hold `clocks + resets + apb + timers + dma`
simultaneously during `tick_all`) would work but holds 5 locks at
once — ugly, and blocks any CPU worker MMIO for the full tick
duration. The snapshot adds ~160-byte copy per quantum; negligible.

## 8. `ThreadedEmulator` + `from_emulator` + `run_quanta`

```rust
#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
pub struct ThreadedEmulator {
    shared: SharedState,
    core0: Option<CortexM33>,
    core1: Option<CortexM33>,
    pio_blocks: Option<[PioBlock; 3]>,
    step_quantum: u32,
    master_cycle: u64,
}
```

Cores and PIO blocks are `Option<...>` — taken during `run_quanta` and
restored on join. `Option` lets us `take()` cleanly without unsafe;
the overhead is a tag byte per field.

### `from_emulator` decomposition (exhaustive destructure)

```rust
pub fn from_emulator(emu: Emulator) -> Self {
    // Host-core check
    let n = std::thread::available_parallelism()
        .map(|n| n.get()).unwrap_or(1);
    assert!(n >= 4,
        "ThreadedEmulator requires >= 4 host cores (found {})", n);
    if n == 4 {
        tracing::warn!(
            "ThreadedEmulator running on exactly 4 host cores — OS and \
             other processes will compete with pinned workers. \
             >= 5 cores recommended.");
    }

    let Emulator { cores, bus, clock, step_quantum } = emu;
    let [mut core0, mut core1] = cores;

    // Exhaustive destructure — any Bus field not handled = compile error.
    let Bus {
        memory, boot_ram, xip_sram,
        sio, pio, event_flag,
        irq_pending, irq_pending_dirty,
        resets_state, ticks, timer0, timer1,
        uart0, spi0, i2c0, adc, pwm, io_bank0, pads_bank0,
        dma,
        clk_ref_ctrl, clk_sys_ctrl, clk_sys_div, clock_tree,
        pll_sys_regs, pll_usb_regs,
        pll_sys_lock_at_cycle, pll_usb_lock_at_cycle,
        rosc_regs, xosc_regs,
        qmi_regs, xip_cache_offset,
        gpio_in, gpio_external_in, gpio_external_mask,
        gpio_hi_noise_state,
        rcp_salt, rcp_salt_valid, rcp_count,
        flash_loaded,
        // Dropped (not used post-decomposition):
        peripheral_regs: _,       // legacy HashMap — Phase 2 typed regs replaced it
        last_access_cycles: _,    // debug/test-only scalar
        extra_wait_states: _,     // per-instruction local; regenerates
        burst_mode: _,            // per-instruction local
        bus_fault: _,             // moved to CoreAtomics
        bus_fault_addr: _,        // moved to CoreAtomics
        active_pc: _,             // per-core local on WorkerBus
        trace_enabled: _,         // Phase 3: no threaded tracing
        trace_sink: _,            // Phase 3: no threaded tracing
        master_cycle: _,          // kept on ThreadedEmulator directly
        decode_cache: _,          // moved to CortexM33
    } = bus;

    // Build SharedMemory (includes flash_loaded state)
    let shared_mem = Arc::new(
        SharedMemory::from_memory(memory, boot_ram, xip_sram, flash_loaded)
    );
    // Build AtomicGpio (seed from sio.gpio_out/oe + external stimulus)
    let shared_gpio = Arc::new(AtomicGpio::seed(
        sio.gpio_out, sio.gpio_oe, gpio_in,
        gpio_external_in, gpio_external_mask));
    // Build ThreadedSio (cross-core fields of sio)
    let shared_sio = Arc::new(ThreadedSio::seed(&sio));
    // Per-core SIO: divider + interp migrate to CortexM33.sio_local
    core0.sio_local = PerCoreSio::from_sio(&sio, 0);
    core1.sio_local = PerCoreSio::from_sio(&sio, 1);

    let shared_pio = Arc::new(ThreadedPio::new());

    // CoreAtomics — seed from Bus fields + core fields
    let atomics = Arc::new(CoreAtomics::seed(
        [core0.halted_take(), core1.halted_take()],
        [core0.wfe_waiting_take(), core1.wfe_waiting_take()],
        event_flag,
        irq_pending,
        rcp_salt, rcp_salt_valid, rcp_count,
    ));
    // Note: irq_pending_dirty is dropped — the swap(0) protocol doesn't
    // need a separate dirty flag.

    // Wire atomics into each CortexM33
    core0.set_atomics(atomics.clone());
    core1.set_atomics(atomics.clone());
    // Move decode cache from Bus onto each core
    core0.decode_cache = fresh_decode_cache();
    core1.decode_cache = fresh_decode_cache();
```

### `run_quanta(n)` — spawn, run, join

```rust
impl ThreadedEmulator {
    pub fn run_quanta(&mut self, n: u64) {
        let core0 = self.core0.take().expect("run_quanta reentry");
        let core1 = self.core1.take().expect("run_quanta reentry");
        let blocks = self.pio_blocks.take().expect("run_quanta reentry");

        let barrier = Arc::new(SpinBarrier::new(4));
        let shared = self.shared.clone();

        // catch_unwind wrappers in each spawn; panic → barrier.poison()
        let h0 = spawn_core_worker(0, core0, shared.clone(),
                                    barrier.clone(), n, self.step_quantum);
        let h1 = spawn_core_worker(1, core1, shared.clone(),
                                    barrier.clone(), n, self.step_quantum);
        let hp = spawn_pio_worker(blocks, shared.clone(),
                                   barrier.clone(), n, self.step_quantum);
        let hc = spawn_coordinator_worker(shared.clone(),
                                           barrier.clone(), n,
                                           self.step_quantum,
                                           self.master_cycle);

        // Join all four. Panic in any worker: join returns Err; we
        // record and continue joining so no thread is leaked.
        let r0 = h0.join(); let r1 = h1.join();
        let rp = hp.join(); let rc = hc.join();

        // Restore state from successfully-joined threads
        if let Ok(c) = r0 { self.core0 = Some(c); }
        if let Ok(c) = r1 { self.core1 = Some(c); }
        if let Ok(b) = rp { self.pio_blocks = Some(b); }
        if let Ok(m) = rc { self.master_cycle = m; }

        // If any worker panicked, propagate after all are joined.
        for r in [r0.is_err(), r1.is_err(), rp.is_err(), rc.is_err()] {
            if r { panic!("worker thread panicked (see earlier backtrace)"); }
        }
    }

    pub fn core(&self, id: usize) -> &CortexM33 {
        match id {
            0 => self.core0.as_ref().expect("run_quanta in progress"),
            1 => self.core1.as_ref().expect("run_quanta in progress"),
            _ => panic!("invalid core id"),
        }
    }

    pub fn cycles(&self) -> u64 { self.master_cycle }
}
```

### Worker panic recovery (Phase 3 scope)

Each `spawn_*` wraps the loop body in `std::panic::catch_unwind`:

```rust
fn spawn_core_worker(...) -> JoinHandle<CortexM33> {
    thread::spawn(move || {
        let result = std::panic::catch_unwind(AssertUnwindSafe(|| {
            core_worker_body(core, shared.clone(), barrier.clone(),
                             n_quanta, step_quantum)
        }));
        match result {
            Ok(core) => core,
            Err(payload) => {
                // Poison barrier so peer workers don't hang
                barrier.poison();
                // Re-panic to propagate through join()
                std::panic::resume_unwind(payload)
            }
        }
    })
}
```

This fixes V2's "worker panic deadlocks peer workers at barrier"
(devil's M4). Cost: ~20 LOC × 4 workers = 80 LOC; one-shot cost.

`ExitReason::Panic` and structured panic propagation is Phase 4.

## 9. Worker loop bodies

### Core worker (0 and 1)

```rust
fn core_worker_body(mut core: CortexM33, shared: SharedState,
                    barrier: Arc<SpinBarrier>, n: u64, step_q: u32)
    -> CortexM33
{
    pin_to_host_core(core.core_id as usize);
    let mut bus = WorkerBus::new(core.core_id, shared.clone());
    let mut target: u64 = 0;
    let core_idx = core.core_id as usize;
    for _ in 0..n {
        target = target.wrapping_add(step_q as u64);

        // Drain coordinator-asserted IRQs from previous quantum
        let pending = shared.atomics.take_irq_pending(core_idx);
        if pending != 0 { core.ppb.merge_irq_pending(pending); }

        while !shared.atomics.is_halted(core_idx)
           && !shared.atomics.is_wfe_waiting(core_idx)
           && core.cycles < target
        {
            core.ppb.update_latest_cycles(core.cycles);
            core.step(&mut bus);
            // Process any pending decode-cache invalidation from this step
            if let Some(addr) = bus.take_pending_cache_invalidation() {
                core.invalidate_decode_cache_entry(addr);
            }
        }
        core.ppb.update_latest_cycles(core.cycles);

        if barrier.wait() == BarrierResult::Poisoned { return core; }
        // Coordinator runs between barrier 1 and barrier 2
        if barrier.wait() == BarrierResult::Poisoned { return core; }
    }
    core
}
```

```rust
fn pin_to_host_core(logical_id: usize) {
    use winapi::um::processthreadsapi::{GetCurrentThread, SetThreadAffinityMask};
    let h = unsafe { GetCurrentThread() };

}
```

## 10. Memory barriers

`DMB`/`DSB`/`ISB` execute `std::sync::atomic::fence(Ordering::SeqCst)`.
On x86 this emits `mfence` on threaded builds; on single-threaded it's
still correct (no-op at architectural level). Cost is small but not
zero; dropped the specific ns figure.

`ISB` additionally issues a no-op at the decode-cache layer (no
decode cache exists yet to flush, but the hook is left for Phase 5).

### Cross-core visibility

DMB on core 0 orders core 0's own stores against its later loads as
observed by a core 1 DMB. A DMB on one core alone does NOT push stores
into core 1's observation window — firmware must issue matching DMBs.
Matches real hardware.

## 13. Risks

1. **Generic monomorphisation.** `CortexM33::step<B: CoreBus>` doubles
   code size for `core/execute*.rs` (~10 KLOC). Measured: release
   `.exe` +~300 KB, debug +~1.2 MB, `cargo build` +~4 s. Acceptable
   for dev; if it regresses, switch to `&mut dyn CoreBus` (+~3 ns
   per call, -300 KB code).
2. **Bus destructure goes stale.** Exhaustive pattern makes new fields
   a compile error at `from_emulator` — forced handling.
3. **Decode cache cross-core staleness.** Core 0 writing an instruction
   in SRAM does NOT invalidate core 1's cache. Firmware must issue
   `DSB; ISB; IC IVAU` per ARM spec. Documented.
4. **Thread pinning assumptions.** < 4 cores = panic. = 4 cores = warn.
   SMT siblings not detected; pinning to logical 0–3 may double up if
   SMT enabled. Measured in Phase 5.
5. **APB mutex contention.** Tight UART/SPI/I2C write loops take the
   `apb` mutex per access. If Phase 5 shows contention, split per-
   peripheral. No pre-emptive split.
6. **`tick_peripherals` snapshot copy.** `ClockTree` + `resets_state`
   copied into coordinator locals each quantum (~160 bytes). Flagged
   so the lock-window narrowing is visible in review.
7. **PIO one-quantum setup delay.** Documented.
8. **`catch_unwind` covers panics, not deadlocks.** If a worker gets
   stuck in an infinite loop (not a panic), barriers still wait. No
   watchdog in Phase 3.
9. **`Peripherals::from_bus_components` constructor complexity.** 20+
   arguments. Builder pattern or a single `from_bus` helper is fine;
   flagged so reviewers don't insist on a "clean" ctor.
