# Threaded Dual-Core Phase 0 — Low-Level Design

Version: 2.0.0
Date: 2026-04-16
Parent HLD: 2026.04.16 - HLD - Threaded Dual-Core Emulation V5.md
Changes from V1: Fixes all CRITICAL and MAJOR issues from review round 1.

## Scope

Phase 0 prerequisite refactors and validation. Three sub-phases:

- **0b** — PPB move, LDREX/STREX, cross-core atomization (main work)
- **0a** — workload instrumentation + synthetic dual-core program
- **0c** — primitives micro-prototype (barrier, atomics, queues)

Implementation order: 0b first (critical path, independently valuable),
0c in parallel (standalone binary), 0a after 0b lands.

## Phase 0b.1 — Move PPB to CortexM33

### Goal

Eliminate `Bus::active_core()`. Move the per-core `Ppb` from
`Bus.ppb: [Ppb; 2]` to `CortexM33.ppb: Ppb`. Thread `CoreId` through
every Bus method that currently relies on `active_core`.

After this phase, `Bus` has no concept of "which core is running" —
the caller always supplies `CoreId` explicitly.

### What moves, what stays

| Field | Action | Rationale |
|---|---|---|
| `ppb: [Ppb; 2]` | Move to `CortexM33.ppb: Ppb` | Per-core, only owning core accesses |
| `rcp_salt: [u32; 2]` | **Stays on Bus** | Core 0 seeds core 1's salt via `rcp_salt_core1` coprocessor op — cross-core write |
| `rcp_salt_valid: [bool; 2]` | **Stays on Bus** | Same cross-core access pattern as `rcp_salt` |
| `rcp_count: u32` | Stays on Bus | Shared across cores |
| `event_flag: [bool; 2]` | Stays on Bus | SEV writes both; FIFO push writes peer's; Phase 0b.3 atomizes |
| `irq_pending: [u64; 2]` | Stays on Bus | Set by peripherals (Bus owns peripherals) |
| `active_pc: [u32; 2]` | Stays on Bus | Indexed by `core_id` parameter (replaces `active_core`) |
| `active_core: usize` | **Deleted** | Replaced by explicit CoreId parameters |

### Migration strategy

The migration is split into two commits for reviewability:

**Commit A (mechanical):** Add `core_id: u8` to Bus method signatures,
update all ~900 call sites (compiler-driven, no semantic change).

**Commit B (semantic):** Move PPB to CortexM33, add bus_read32/write32
wrappers, IRQ sync decoupling, remove Bus PPB dispatch.

#### Commit A: Add CoreId to Bus methods

Add `core: u8` parameter to these Bus methods:

| Method | New signature |
|---|---|
| `read32` | `(&mut self, addr: u32, core: u8) -> u32` |
| `write32` | `(&mut self, addr: u32, val: u32, core: u8)` |
| `read16` | `(&mut self, addr: u32, core: u8) -> u16` |
| `write16` | `(&mut self, addr: u32, val: u16, core: u8)` |
| `read8` | `(&mut self, addr: u32, core: u8) -> u8` |
| `write8` | `(&mut self, addr: u32, val: u8, core: u8)` |
| `set_active_pc` | `(&mut self, pc: u32, core: u8)` |

**Step B.2: Add PPB intercept wrappers to CortexM33.**

```rust
impl CortexM33 {
    /// Bus access with PPB intercept. PPB addresses (0xE000_0000–0xEFFF_FFFF)
    /// route to self.ppb UNLESS the address falls in boot RAM
    /// (0xEFFF_F000–0xFFFF_FFFF).
    pub(crate) fn bus_read32(&mut self, addr: u32, bus: &mut Bus) -> u32 {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            let val = self.ppb.read32(addr);
            if bus.mmio_trace_enabled {
                bus.emit_trace_read(addr, val, self.core_id);
            }
            val
        } else {
            bus.read32(addr, self.core_id)
        }
    }

    pub(crate) fn bus_write32(&mut self, addr: u32, val: u32, bus: &mut Bus) {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            self.ppb.write32(addr, val);
            self.sync_nvic_to_irq_pending(addr, bus);
            if bus.mmio_trace_enabled {
                bus.emit_trace_write(addr, val, self.core_id);
            }
        } else {
            bus.write32(addr, val, self.core_id);
        }
    }

    /// Narrow-width PPB access: read16 extracts halfword from 32-bit register.
    pub(crate) fn bus_read16(&mut self, addr: u32, bus: &mut Bus) -> u16 {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            let word = self.ppb.read32(addr & !3);
            if addr & 2 != 0 { (word >> 16) as u16 } else { word as u16 }
        } else {
            bus.read16(addr, self.core_id)
        }
    }

    /// Narrow-width PPB write: read-modify-write the 32-bit register.
    pub(crate) fn bus_write16(&mut self, addr: u32, val: u16, bus: &mut Bus) {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            let old = self.ppb.read32(addr & !3);
            let new_val = if addr & 2 != 0 {
                (old & 0x0000_FFFF) | ((val as u32) << 16)
            } else {
                (old & 0xFFFF_0000) | val as u32
            };
            self.ppb.write32(addr & !3, new_val);
            self.sync_nvic_to_irq_pending(addr & !3, bus);
        } else {
            bus.write16(addr, val, self.core_id);
        }
    }

    // bus_read8 / bus_write8: PPB byte access returns 0 / drops (current behavior).
    pub(crate) fn bus_read8(&mut self, addr: u32, bus: &mut Bus) -> u8 {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            0 // PPB byte reads return 0 (current Bus behavior)
        } else {
            bus.read8(addr, self.core_id)
        }
    }

    pub(crate) fn bus_write8(&mut self, addr: u32, val: u8, bus: &mut Bus) {
        if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
            // PPB byte writes dropped (current Bus behavior)
        } else {
            bus.write8(addr, val, self.core_id);
        }
    }
}
```

Note: `core/decode.rs` instruction fetches (`bus.read16(pc, core_id)`)
go directly to Bus — they do NOT use the PPB intercept wrapper, since
opcode fetches are never PPB addresses.

**Step B.3: Remove PPB dispatch from Bus.**

Delete the PPB branches from `Bus::read32`, `Bus::write32`,
`Bus::read16`. Add `debug_assert!(addr >> 28 != 0xE || Self::is_boot_ram(addr))`
in debug mode.

**Step B.4: IRQ routing — decouple from PPB.**

`Bus::assert_irq_core` / `assert_irq_shared` / `clear_irq_core` /
`clear_irq_shared` currently write both `irq_pending` and `ppb[core]`.
After the move, they only set `irq_pending`:

```rust
pub fn assert_irq_core(&mut self, core: usize, irq: u32) {
    if core < 2 && irq < IRQ_COUNT {
        self.irq_pending[core] |= 1u64 << irq;
        // ppb sync happens in Emulator::step via merge_irq_pending
    }
}
```

IRQ sync in `Emulator::step()` — runs before EACH core's instruction
loop (two sync points per quantum):

```rust
pub fn step(&mut self) -> u64 {
    self.bus.master_cycle = self.clock.cycles;
    let target = self.clock.cycles + self.step_quantum as u64;

    for core_id in 0..2 {
        // Sync IRQs: merge hardware-pending into core's NVIC.
        // UNION merge (|=) preserves firmware self-pends via ISPR MMIO.
        self.cores[core_id].ppb.merge_irq_pending(
            self.bus.irq_pending[core_id]
        );

        while !self.cores[core_id].is_halted()
            && !self.cores[core_id].is_wfe_waiting()
            && self.cores[core_id].cycles < target
        {
            self.cores[core_id].ppb.update_latest_cycles(
                self.cores[core_id].cycles
            );
            self.cores[core_id].step(&mut self.bus);
        }
        self.cores[core_id].ppb.update_latest_cycles(
            self.cores[core_id].cycles
        );
    }
    // ... tick_peripherals, tick_systick, wake_checks ...
}
```

`Ppb::merge_irq_pending` uses UNION, not overwrite:
```rust
pub fn merge_irq_pending(&mut self, pending: u64) {
    self.nvic_ispr[0] |= pending as u32;
    self.nvic_ispr[1] |= (pending >> 32) as u32;
}
```

Reverse sync (firmware writes ISPR/ICPR via MMIO → update irq_pending):
```rust
fn sync_nvic_to_irq_pending(&self, addr: u32, bus: &mut Bus) {
    let low = addr & 0xFFFF;
    // ISPR or ICPR writes affect the pending state
    if matches!(low, 0xE200..=0xE207 | 0xE280..=0xE287) {
        bus.irq_pending[self.core_id as usize] =
            self.ppb.nvic_ispr[0] as u64
            | (self.ppb.nvic_ispr[1] as u64) << 32;
    }
}
```

**Step B.5: Update Emulator-level PPB access.**

```rust
// tick_systick: bus.ppb[core_id] → cores[core_id].ppb
```

**Step B.6: Update Emulator::mmio_read32 / mmio_write32.**

These public API methods are used by the harness to poke registers
externally. After the move they can't reach PPB through Bus.

```rust
pub fn mmio_read32(&mut self, addr: u32) -> u32 {
    if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
        // External PPB access defaults to core 0
        self.cores[0].ppb.read32(addr)
    } else {
        self.bus.read32(addr, 0)
    }
}

pub fn mmio_write32(&mut self, addr: u32, val: u32) {
    if addr >> 28 == 0xE && !Bus::is_boot_ram(addr) {
        self.cores[0].ppb.write32(addr, val);
        // Sync back to irq_pending if ISPR/ICPR
        let low = addr & 0xFFFF;
        if matches!(low, 0xE200..=0xE207 | 0xE280..=0xE287) {
            self.bus.irq_pending[0] =
                self.cores[0].ppb.nvic_ispr[0] as u64
                | (self.cores[0].ppb.nvic_ispr[1] as u64) << 32;
        }
    } else {
        self.bus.write32(addr, val, 0);
    }
}
```

**Step B.7: Delete `Bus.ppb` and `Bus.active_core`.**

Remove fields and all remaining references. Compiler catches misses.

**Step B.8: Update direct `bus.ppb[core]` access in core code.**

~141 occurrences. The pattern is `bus.ppb[core].field` → `self.ppb.field`
in CortexM33 methods. For tests: `emu.bus.ppb[0]` → `emu.core(0).ppb`
(via existing `Emulator::core()` accessor; make `CortexM33.ppb` public
to the crate).

### Notes

- **Decode cache**: unaffected. PPB addresses are not in the cacheable
  PC range. No interaction with active_core.
- **Borrow checker**: `self.ppb.field` and `self.regs.field` are
  disjoint struct fields — Rust allows simultaneous mutable borrow.
  `self.bus_write32(addr, val, bus)` borrows `self` for the call
  duration; `self.ppb.field = x` is fine before/after the call.
- **`execute_one` / `execute_one_wide`**: these test helpers create a
  throwaway `Bus::default()` internally. Unaffected by the migration
  (PPB access goes through `self.ppb`, not the throwaway bus).

## Phase 0b.2 — LDREX/STREX

### Goal

Replace the current stubs with a proper exclusive monitor. Per-core
`exclusive_address` on CortexM33. STREX succeeds if the address
monitor is valid; snoop invalidates on peer writes.

### Current state

- LDREX (`0xE850`): treated as normal LDR (`execute_thumb32.rs:711`)
- STREX (`0xE840`): treated as normal STR, Rd always 0 (`execute_thumb32.rs:729`)
- CLREX (`0xF3BF, 0x8020`): 1-cycle NOP (`execute_thumb32.rs:866`)

### New fields on CortexM33

```rust
pub(crate) exclusive_address: Option<u32>,
pub(crate) did_write_this_quantum: bool,
```

Initialized to `(None, false)` in `with_id()`.

Note: `exclusive_value` from V1 is removed. ARM exclusive monitors
are address-based, not value-based. A CAS/value-comparison pattern
is architecturally wrong (gives spurious failures when the same core
does STR between LDREX and STREX, and false successes on ABA patterns
under threading).

### Implementation

**LDREX** (replace `execute_thumb32.rs:711-717`):
```rust
// LDREX Rt, [Rn, #imm8<<2]
let rn = (hw0 & 0xF) as usize;
let rt = ((hw1 >> 12) & 0xF) as usize;
let imm8 = (hw1 & 0xFF) as u32;
let addr = self.regs.r[rn].wrapping_add(imm8 << 2);
self.regs.r[rt] = self.bus_read32(addr, bus);
self.exclusive_address = Some(addr);
return 2;
```

**STREX** (replace `execute_thumb32.rs:729-737`):
```rust
// STREX Rd, Rt, [Rn, #imm8<<2]
let rn = (hw0 & 0xF) as usize;
let rt = ((hw1 >> 12) & 0xF) as usize;
let rd = ((hw1 >> 8) & 0xF) as usize;
let imm8 = (hw1 & 0xFF) as u32;
let addr = self.regs.r[rn].wrapping_add(imm8 << 2);

if self.exclusive_address == Some(addr) {
    // Monitor valid — store succeeds
    self.bus_write32(addr, self.regs.r[rt], bus);
    self.regs.r[rd] = 0;
} else {
    // Monitor invalidated by peer write or CLREX — store fails
    self.regs.r[rd] = 1;
}
self.exclusive_address = None; // STREX always clears local monitor
return if addr >> 28 == 0xD { 1 } else { 2 };
```

No extra read. No value comparison. Address-only monitor matching
ARMv8-M architecture.

**CLREX**:
```rust
0x2 => {
    self.exclusive_address = None;
    1
}
```

**Exclusive monitor snoop** — any peer write invalidates.

After each core's quantum in `Emulator::step()`:
```rust
let peer = 1 - core_id;
if self.cores[peer].exclusive_address.is_some()
    && self.cores[core_id].did_write_this_quantum
{
    self.cores[peer].exclusive_address = None;
}
self.cores[core_id].did_write_this_quantum = false;
```

`did_write_this_quantum` is set to `true` in `CortexM33::bus_write32`,
`bus_write16`, `bus_write8` (any memory-mapped write). Cleared at the
start of each quantum.

This is strictly more conservative than ARM's address-range tagging
(more STREX failures, never fewer). Correct for both single-threaded
and future threaded mode.

Same-core writes do NOT invalidate the local monitor — only peer
writes do. This matches ARM architecture (the local monitor is only
cleared by STREX, CLREX, or a peer snoop).

**LDREXB/LDREXH/STREXB/STREXH**: same pattern, narrower access width.
Monitor tracks word-aligned address regardless of width. Implement
after LDREX/STREX works.

### Parallelization note

Phase 0b.2 does not depend on Phase 0b.1's PPB move. It only touches
`execute_thumb32.rs` (instruction handlers), `core/mod.rs` (new fields),
and `lib.rs` (snoop in step). It can be developed on a branch in
parallel with 0b.1, with a small rebase when 0b.1 merges (the
`bus.read32(addr)` calls become `self.bus_read32(addr, bus)` after 0b.1).

### Verification

1. Unit tests: LDREX→STREX success, LDREX→peer-write→STREX fail,
   LDREX→CLREX→STREX fail, LDREX→self-write→STREX success (same-core
   writes don't invalidate)
2. `qemu_diff --fuzz 10000` — LDREX/STREX now correct vs QEMU

## Phase 0b.3 — Atomize cross-core fields + WFI

### Goal

Convert cross-core mutable fields to `AtomicBool` / `AtomicU32`.
Implement proper WFI (currently a NOP).

### Fields to atomize

| Field | Current | Location | New type | Rationale |
|---|---|---|---|---|
| `halted` | `bool` | CortexM33 | `AtomicBool` | Coordinator clears on wake |
| `wfe_waiting` | `bool` | CortexM33 | `AtomicBool` | Coordinator clears on wake |
| `event_flag` | `[bool; 2]` | Bus | `[AtomicBool; 2]` | SEV writes both; WFE reads own |
| `nvic_ispr` | `[u32; 2]` | CortexM33.ppb | `[AtomicU32; 2]` | Coordinator writes IRQs |
| `nvic_iabr` | `[u32; 2]` | CortexM33.ppb | `[AtomicU32; 2]` | Coordinator writes |
| `nvic_iser` | `[u32; 2]` | CortexM33.ppb | `[AtomicU32; 2]` | Read by coordinator in `any_pending_enabled` |

Notes:
- Array sizes are `[_; NVIC_BIT_WORDS]` which is 2 (not 8 as V1 said).
- `nvic_icpr` does not exist as a separate field — ICPR writes clear
  bits in `nvic_ispr`. Removed from table.
- `Ppb` loses `Clone`/`Copy` derivation when it contains atomics.
  Audit for any code that copies Ppb values.
- `pending_fifo_event` path: `Bus::write32` for SIO FIFO takes
  `sio.pending_fifo_event` and writes `event_flag[receiver]`. Update
  this path to use `.store(true, Release)` on the `AtomicBool`.

### WFI implementation

ARM spec (B1.5.17): "If WFI is executed and an enabled interrupt is
already pending, the processor does not enter sleep." WFI must check
for pending interrupts before halting.

```rust
// core/execute.rs, Thumb-16 WFI (0xBF30):
0x3 => {
    let pending = bus.irq_pending[self.core_id as usize];
    if self.ppb.any_pending_enabled(pending) {
        1 // pending interrupt — WFI is a NOP
    } else {
        self.halted.store(true, Release);
        1
    }
}

// core/execute_thumb32.rs, Thumb-32 WFI.W (0xF3AF 0x8003):
0x03 => {
    let pending = bus.irq_pending[self.core_id as usize];
    if self.ppb.any_pending_enabled(pending) {
        1
    } else {
        self.halted.store(true, Release);
        1
    }
}
```

`Ppb::any_pending_enabled`:
```rust
pub fn any_pending_enabled(&self, pending: u64) -> bool {
    let iser = self.nvic_iser[0].load(Acquire) as u64
             | (self.nvic_iser[1].load(Acquire) as u64) << 32;
    (pending & iser) != 0
}
```

### QEMU diff compatibility

The QEMU diff harness single-steps both emulators. In QEMU, the GDB
single-step skips over WFI (the core resumes at the next instruction).
In our emulator, WFI now halts, so the next `step()` returns without
executing. The harness would see PC not advancing.

**Mitigation:** In the QEMU diff harness, after each single-step, if
the emulator core is halted, auto-wake it before comparing state. This
matches QEMU's debugger semantics where single-step through WFI
advances past it. Add a `debug_step()` method on CortexM33 that
executes one instruction and auto-clears halted state afterward.

### Wake path

```rust
fn wake_checks(&mut self) {
    for i in 0..2 {
        // WFE wake
        if self.cores[i].wfe_waiting.load(Acquire)
            && self.bus.event_flag[i].load(Acquire)
        {
            self.bus.event_flag[i].store(false, Release);
            self.cores[i].wfe_waiting.store(false, Release);
        }
        // WFI wake: halted core with pending enabled IRQ
        if self.cores[i].halted.load(Acquire) {
            let pending = self.bus.irq_pending[i];
            if pending != 0
                && self.cores[i].ppb.any_pending_enabled(pending)
            {
                self.cores[i].halted.store(false, Release);
            }
        }
    }
}
```

### SEV update

```rust
pub fn signal_sev(&mut self) {
    self.event_flag[0].store(true, Release);
    self.event_flag[1].store(true, Release);
}
```

## Phase 0a — Workload study

### Goal

Measure dual-core workload characteristics to validate threading
assumptions.

### Instrumentation counters

Add `WorkloadCounters` to `Emulator`:

```rust
pub struct CoreCounters {
    pub decode_execute_cycles: u64,
    pub wfi_cycles: u64,
    pub wfe_cycles: u64,
    pub sram_reads: u64,
    pub sram_writes: u64,
    pub sio_accesses: u64,
    pub peripheral_accesses: u64,
    pub ppb_accesses: u64,
}
```

Increment in `CortexM33::bus_read32/write32` based on address range.
Track WFI/WFE cycles as `(quantum_target - core.cycles)` when
halted/waiting.

### Synthetic dual-core workload

Thumb program loaded via `load_image`:
- Core 0: GPIO toggle (CP0) + shared SRAM write + SIO FIFO push
- Core 1: decode loop + shared SRAM read + SIO FIFO receive

Core 1 launch: core 0 wakes via SEV (or direct `wake()` call).

### Reporting

`paced_bench --instrumented`: per-core breakdown of cycle usage,
SRAM access counts, cross-core write fraction.

### Decision gate

Proceed to Phase 1 only if ALL:
- Core 1 active ≥ 20%
- Cross-core SRAM writes < 10% of total
- Peripheral access ratio measured
