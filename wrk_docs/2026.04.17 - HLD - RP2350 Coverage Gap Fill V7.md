# 2026.04.17 — HLD — RP2350 Coverage Gap Fill V7

Supersedes V6 (same date). Changes: POWMAN MATCH silicon scenario
deferred to a later phase; ROSC COUNT demoted to Bucket D; multiple
scope-and-detail fixes surfaced by review. See §14 change log.

## §1 Goal

Close the Bucket A tranche of the 2026.04.17 coverage audit — the
peripherals that are (a) cheap to model, (b) directly verifiable
against real RP2354 silicon via `silicon_periph_diff_rp2350`, and
(c) currently STUB or PARTIAL-STORAGE.

**Framing note.** The precursor audit (§7.1) argued for a
firmware-pass matrix instead of peripheral enumeration. V7 retains
the peripheral-enumeration frame for this tranche because (a)
Arthur's explicit ask was "knock off easy items, reduce the
implementation surface"; (b) the firmware-pass axis is already
advancing in parallel via the `hello_*` firmware integration tests;
(c) Bucket A items are cheap + oracle-testable while a firmware-pass
campaign is a larger commitment. A later phase can pivot.

Target effort for Phase 1: **~1.5 weeks** in V5 cadence.

## §3 Per-item design

### §3.1 SYSINFO — fill read-only fields

**Current** (`bus/peripherals.rs:48`): `sysinfo_read` returns
`CHIP_ID = 0x0000_0002`, `PACKAGE_SEL = 0`, `PLATFORM = 1`. No
storage.

**Target**: populate remaining documented read-only fields
(`GITREF_RP2350`, additional PLATFORM bits if any, `CHIP_ID`
revision field) to match real RP2354 silicon. All read-only. No
storage.

**Silicon observable**: one probe-rs read of each register at
reset; diff the u32 value.

**Capture procedure**: before the scenario commits, run
`probe-rs read-words --chip RP235x 0x4000_0000 8` on Arthur's
RP2354; paste the four register values into `sysinfo_read`'s match
arms. One-shot; not automated.

**Datasheet**: RP2350 §5.1 SYSINFO.

### §3.2 XOSC startup latency

**Current** (`bus/peripherals.rs:269`): STATUS reads fixed
`STABLE | ENABLED`. V5 §5.7 pinned `STATUS.STABLE = 1 at reset` as
a load-bearing invariant; regression test at
`peripherals/phase1_tests.rs:177-185`.

**Target**:
- Reset state: `STATUS.STABLE = 1`, `xosc_stable_at_cycle = None`.
  Preserves V5 invariant.
- On firmware-driven `CTRL.ENABLE = 0`: `STATUS.STABLE` reads 0
  immediately; `xosc_stable_at_cycle = None`.
- On firmware-driven `CTRL.ENABLE = 1`: arm
  `xosc_stable_at_cycle = master_cycle + STARTUP_DELAY * 256`.
  `STATUS.STABLE` reads 0 until `master_cycle >= target`, then 1.

**Silicon observable** (final-state diff, no `custom_sled` needed):
- Setup: write `CTRL.ENABLE = 0`, then write `CTRL.ENABLE = 1` in
  the same `setup` batch.
- `max_sysclks`: large enough that `STATUS.STABLE` should settle
  to 1 by end (`STARTUP_DELAY * 256 + margin`, default ~50 000
  sys_clks).
- Observe: `(XOSC_BASE + STATUS_OFFSET, STABLE_MASK)` expects `1`.

The scenario diffs the settled state, not the transition cycle;
that's sufficient to catch "startup latency not modelled" and
"STATUS wrong during/after transition".

**Regression anchor**: the existing
`peripherals/phase1_tests.rs:177-185` test covers the
reset-invariant path. Add a second unit test for the
enable-disable-enable transition. The silicon scenario covers the
post-enable case only.

**Implementation**: add `xosc_stable_at_cycle: Option<u64>` to the
existing XOSC state in `bus/peripherals.rs`. Mirrors
`pll_sys_lock_at_cycle`.

**Open question** (§9): `STARTUP_DELAY` counter pacing — sys_clk
or xosc. Assumption sys_clk.

### §3.3 POWMAN COUNT + MATCH

**Current** (`peripherals/powman.rs`): 64-bit COUNT/MATCH as
`AON_COUNT_LO` (0x08) + `AON_COUNT_HI` (0x0C); MATCH similarly at
0x10/0x14. Storage only — counter doesn't advance. Warn-once on
**write** to COUNT/MATCH (the HLD V6 said "read" — incorrect, the
code has it on write at `peripherals/powman.rs:150, 168`).

**Caveat — unverified constants**: `POWMAN_BASE = 0x4010_0000` is
flagged "assumption" in the module docstring. Register offsets and
`STATUS.READY` bit position are "educated-guess placements". The
POWMAN NVIC line is verified (`IRQ_POWMAN_IRQ_TIMER = 45` at
`irq.rs:123`). Resolution: the pre-flight gate in §8 verifies the
base before the scenario commits.

**Target**:
- COUNT advances at 1 tick per POWMAN clock source (XOSC / 4 by
  default; 3 MHz on 12 MHz XOSC).
- MATCH fires `POWMAN_IRQ_TIMER` (NVIC line 45) when `COUNT ==
  MATCH` and `MATCH_EN` is set. One-shot — IRQ asserts; firmware
  clears.
- ARCHSEL stays **warn-once on non-Arm write**. V7 does not
  progress core selection. Explicitly preserved for the RISC-V
  Hazard3 track (see §12).
- `POWMAN_IRQ_POW` (line 44) stays unwired — no power events
  modelled.

**Silicon observable** (COUNT-only in Phase 1):
- Setup: write MATCH_LO = K, MATCH_HI = 0, MATCH_EN = 1, enable
  POWMAN.
- `max_sysclks = K * (sys_clk_hz / powman_clk_hz) + margin`.
  Concretely, for K = 100, `max_sysclks ≈ 100 * 50 + 200 = 5200`.
- Observe: `(POWMAN_BASE + AON_COUNT_LO, 0xFFFF_FFFF)` expects K,
  and `(POWMAN_BASE + AON_COUNT_HI, 0xFFFF_FFFF)` expects 0.

**MATCH-IRQ scenario — deferred**: NVIC ISPR at `0xE000_E204` is
outside `silicon_periph_diff`'s `is_mmio` range (SRAM + 0x4xxx–
0x5xxx + 0xDxxx only — `silicon_scenarios.rs:2525-2529`). MATCH
IRQ firing belongs in `silicon_isr_diff_rp2350` with a custom
vector table + handler stub that writes a memory marker. Deferred
to the next phase when NVIC priority levels (Bucket B) also land —
the pair validates MATCH-under-preemption properly.

**Implementation**: add `aon_count: u64`, `aon_match: u64`,
`match_en: bool` to `PowmanRegs`. Drive from
`tick_peripherals(cycles)` like TIMER0/1. Drop the warn-once on
COUNT/MATCH **writes** — they're real now. Keep warn-once on
ARCHSEL / AON_DRIVE (still storage-only). Route IRQ via
`raise_irqs_u64(1u64 << 45)` — **not** `1u64 << 45 % 64`; Rust
operator precedence would make that 0.

**Named unit tests** (acceptance criterion §11):
- `powman_count_advances_at_expected_rate`
- `powman_match_fires_irq_line_45`
- `powman_archsel_non_arm_write_warns_once` (regression)

**Open questions** (§9): POWMAN clock source default
(XOSC/4 assumed), base address confirmation.

### §3.4 GLITCH_DETECTOR — ARM readback

**Current** (`peripherals/inert.rs:128, 139`): HashMap storage;
`STATUS.ARM` forced 0 on read; `TRIG_STATUS` W1C. Base
`0x4015_8000` flagged unverified.

**Target**: `STATUS.ARM` reads back what was written to `CTRL.ARM`.
`TRIG_STATUS` stays at 0 forever (no glitch). No IRQ.

**Silicon observable**: setup writes `CTRL.ARM = 1`; observe
`STATUS.ARM` expecting 1 and `TRIG_STATUS` expecting 0.

**Implementation**: replace the forced-0 in the existing HashMap
read path with a masked readback of the written value. ~10 lines.

### §3.5 TBMAN — PLATFORM selector

**Current** (`peripherals/inert.rs:45`): HashMap storage only.

**Target**: PLATFORM field reads the silicon-observed value
(assumption: `0b01` for real ASIC; confirm via probe-rs read at
pre-flight). Remaining bits zero; read-only.

**Silicon observable**: one-shot read of `TBMAN_BASE + 0x00` at
reset; diff.

**Implementation**: hardcode PLATFORM bits in the read path.
No new module.

## §8 Landing plan

### Pre-flight (before each item's scenario commits)

Run `probe-rs read-words --chip RP235x <BASE> 16` on Arthur's
RP2354 and visually sanity-check the dump matches the expected
register layout. For SYSINFO, TBMAN, GLITCH_DETECTOR: this also
captures the read-only field values to hardcode. For POWMAN: this
confirms `0x4010_0000` is actually POWMAN (module docstring flags
it as assumption).

If pre-flight reveals a wrong base/offset, update the peripheral
module + bus match arm + scenario in one commit before the
behavioural change lands.

### Per-item cadence

Same as V5: implement → code-review → apply-feedback →
devil's-advocate → commit.

### Landing order (increasing surface area)

1. **SYSINFO** — smallest; no new state.
2. **TBMAN** — one read path.
3. **GLITCH_DETECTOR** — register readback.
4. **XOSC startup** — mirrors PLL lock; preserves V5 §5.7.
5. **POWMAN COUNT/MATCH** — counter + IRQ routing.

Cargo minor bump per item.

### Final step

Plan-vs-implementation audit (same as V5 §10 item 7) + update the
coverage audit matrix (`wrk_docs/2026.04.17 - RP2350 Peripheral
Coverage Audit.md`) to reflect the new grades.

  shared between the Arm/RISC-V core-selection path and V7
  POWMAN. V7 explicitly does **not** progress core selection:
  ARCHSEL stays warn-once on non-Arm write, and the RISC-V track
  retains ownership of that transition. No direct code collision
  expected.
- **Stale ROM audit**. `roms/rp2350/hello_dma.bin` was rebuilt for
  the RP2350 CTRL layout in commit `b67df6b`. Other ROMs under
  `roms/rp2350/` may have similar RP2040-built provenance. Not in
