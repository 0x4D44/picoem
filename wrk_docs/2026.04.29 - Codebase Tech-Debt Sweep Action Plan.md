## Phase 6 — Larger-scope items (multi-day, schedule separately)

These are **schedule-only** entries — do not start without explicit Arthur sign-off. Each is a multi-day refactor with non-trivial risk to differential oracles.

### 6.1 Encapsulation migration (Theme A)

The four `pub`-field migrations should be **one big-bang refactor**, not four piecemeal commits. Each piecemeal commit rewrites ~400 call sites; doing them stacked rewrites the same call sites four times.

Scope:
1. Existing `tech_debt.md:45-89` migration (`Emulator.{cores,bus,clock}` to `pub(crate)`).
2. `Bus::dma` consistency (already covered in Phase 1.3 H3 for RP2040 — stays in Phase 1).
3. R1 (Memory mutator invalidation hook).
4. `Registers.{r,xpsr,...}` direct mutation.

Estimated cost: ~2000 call-site updates across ~40 files (per the existing tracker entry). Build a `Sealed<T>` newtype that handles placeholder-substitution at promotion time so the migration is one type rename per affected field.

**Trigger to start:** Either a future maintainer hits a placeholder-state bug, OR Phase 7 of the dual-execution rollout makes encapsulation a hard requirement.

### 6.2 MPU enforcement (B3)

Plumb `Bus::mpu_check` through all data-read/write paths plus FPU lazy-flush. Gate on `MPU_CTRL.ENABLE=1` for zero-cost when disabled. This re-introduces the `Fault::MemManage` constructor.

**Trigger to start:** Phase 8 TrustZone work, or first corpus firmware that exercises MPU.

### 6.3 Cross-core exclusive-monitor granularity (B4)

Either wire `ExclusiveMonitors::snoop` into Serial mode, or replace `did_write_this_quantum` with per-core "wrote-to-word X" tracking. Add a silicon oracle case for cross-core LDREX/STREX with a competing peer write — currently zero coverage in `cycle_cases.rs`, `dualcore_cases.rs`, `dual_model.rs`.

**Trigger to start:** Whenever the silicon dual-core oracle catalogue gets its next expansion pass.

### 6.4 Mutation-testing v2 triage

Already has an HLD. Phase 0.1 reads it; this phase acts on it. Out of scope for this sweep's plan.
