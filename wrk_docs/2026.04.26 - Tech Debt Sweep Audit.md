# Tech Debt Sweep — Audit Report

**Date:** 2026-04-26
**Method:** four parallel Explore agents (one per major area) plus a devil's-advocate reviewer who challenged their findings against the actual code.
**Scope:** every crate under `d:\language\mdrp2354\crates\`, the workspace root, ROMs, fuzz drivers, and developer-facing docs.
**Posture:** this is a development sandbox emulator with active phase work, not a shipping product. Severity is calibrated accordingly — phased `#[allow(dead_code)]` placeholders that document a future stage are *not* debt; they're the contract.

The DA review caused several findings to be downgraded or rejected outright. The audit below records the **net** position after that reconciliation, with confidence labels:

- **(verified)** — the agent's claim was checked in the code and held up.
- **(challenged)** — the DA disputed the framing; resolution noted inline.
- **(rejected)** — false positive, removed from the "fix" list, kept here only so the next sweep doesn't re-discover it.

---

## Executive summary

The codebase is in better shape than four-agent sweeps usually suggest. The dominant pattern is *phased `#[allow(dead_code)]` placeholders that the agents could not contextualise without reading every HLD*. Three of the four reports inflated severity by treating those placeholders as debt. The DA review re-graded most of those items as intentional.

The actual debt clusters into five groups, ordered by ROI:

1. **Documentation rot in `CLAUDE.md`** — three lines still claim a `Peripheral` trait lives in `mdpicoem-common`. The trait was removed and `mdpicoem-common/src/lib.rs:30-32` explicitly says so. New contributors reading `CLAUDE.md` as ground truth will be misled. **5-minute fix, unbounded payoff.**
2. **`println!` / `eprintln!` in library code** (a handful of sites) — violates the project's own tracing convention from `2026.04.16 - HLD - Workspace Tracing Infrastructure.md`. Cheap to fix, easy to accept new ones if not policed.
3. **Cross-binary harness duplication** — real, ~400 lines, low-priority but ripe when next touching the harness CLI surface.
4. **Threaded-Emulator field-access footgun** — already in `tech_debt.md` (lines 45–89). Restating: typed-API guards are debug-only, raw `.bus.` / `.cores[` / `.clock.` access bypasses them silently. Real risk for any future contributor on the threaded path; mitigation cost (~1287 call sites) is high.
5. **In-flight RP2040 IRQ plumbing** — `silicon_isr_diff_rp2040` ships ahead of silicon hookup by design (per `CLAUDE.md` line 170 and the binary's header comment). Not abandoned; just waiting for `Bus::irq_pending` + pending-exception dispatch in `CortexM0Plus::step` to be validated.

Sections below detail each crate. References use absolute paths with line numbers.

## 2. `mdrp2350`

**Workspace-largest crate; the DA confirmed the agent over-flagged.**

### Real items (verified)

- **`d:\language\mdrp2354\crates\mdrp2350\src\threaded\emulator.rs:3024`** — `println!` in a stress-bench status line. `CLAUDE.md` "Logging & Tracing" section forbids `println!` in library code; this binary lives inside the lib crate. Replace with `tracing::info!` or move into a binary.
- **`d:\language\mdrp2354\crates\mdrp2350\src\bus\mod.rs:936`** — `println!()` in a bus trace path; same convention violation. Use `tracing::debug!`.
- **`d:\language\mdrp2354\crates\mdrp2350\src\core\exceptions.rs:191`** — FIXME(trustzone): EXC_RETURN does not encode the S bit, so NS exceptions claim Secure return. Real, **and** real-silicon impact for any TrustZone-using firmware. Tracked in code; not yet in `tech_debt.md` — promote it.
- **`d:\language\mdrp2354\crates\mdrp2350\src\bus\ppb.rs:392,772`** — TODO: SysTick CLKSOURCE=0 ref-clock scaling not modelled. Real timing divergence vector.
- **`d:\language\mdrp2354\crates\mdrp2350\src\core\execute_fpu.rs:1378,1429`** — TODO(phase-7.1): FPSCR.AHP not honoured in f16 conversions. Will produce wrong results for non-IEEE half-precision firmware; phase-tagged.
- **Tests `#[ignore]` at `tests_narrow.rs:1005,1020`** — IO_BANK0 INTR W1C semantics deferred. The deferral is correct; what's missing is a `tech_debt.md` entry pointing at them.

### Challenged / rejected

- **`core_riscv/execute.rs:42` `#[cfg_attr(not(test), allow(dead_code))]`** *(rejected)* — Verified: this is a test-convenience wrapper that delegates to `execute_sized()` (the production entry called from `step`). The cfg_attr is the correct hygiene pattern. Do **not** remove.
- **`expect_arm` / `expect_riscv` / `core_cycles` panics at `lib.rs:267-901`** *(rejected)* — Sealed-enum API contract enforcement. The panic message names the violation. Returning `Result` here would push noise to every caller for a misuse condition that should never reach prod. Leave alone.
- **`threaded/emulator.rs:407,421` panics on out-of-bounds core idx** *(rejected)* — Same pattern. M33 emulator has exactly two cores; a 3rd-index call is a programming error.
- **Shift-op duplication between `execute.rs` and `execute_thumb32.rs`** *(rejected)* — Different instruction widths, different decoders. The "duplication" is structural. Merging would require a parameterisation that helps no caller.
- **`threaded/bus.rs` vs `bus/mod.rs` `unreachable!()` register-dispatch arms** *(rejected)* — Async worker dispatch vs serial loop dispatch. Same shape, different code paths. Hand-tuned serial path matters for perf; threaded path is message-driven. Don't merge.
- **`#[allow(dead_code)]` on `bus/ppb.rs:20,665,700,722`** *(rejected)* — Spot-checked: `set_irq_pending` / `clear_irq_pending` / `irq_enabled` are referenced from `core/mod.rs`, `lib.rs`, `tests.rs`, `core_riscv/tests_p4.rs`, and `threaded/atomics.rs`. The `#[allow]` is to silence "unused on this build profile" noise; the items are live.

### Notes / things the agent flagged but were inconclusive

- **`core_riscv/tests_p2.rs..p5.rs` test-helper duplication (4354 lines).** Worth a 30-minute pass to extract a `tests_common` helper module if helper churn is high. Not urgent.
- **Bit-mask magic numbers across `execute_thumb32.rs`.** A `core::bit_fields` constants module would help, but only meaningfully so if someone is currently misreading widths. No incidents on file.

## 3. `mdrp2040`

**Best of the four reports — agent generally deferred to phased work and didn't over-flag.**

### Real items (verified)

- **`d:\language\mdrp2354\crates\mdrp2040\src\bus\mod.rs:483`** — `println!()` in MMIO trace fallback. Tracing-policy violation.
- **`d:\language\mdrp2354\crates\mdrp2040\src\peripherals\pwm.rs:310-313`** — `eprintln!()` gated on `MDPIO_PWM_TRACE` env var. Should be `tracing::debug!` so it's controllable via `RUST_LOG`.
- **`d:\language\mdrp2354\crates\mdrp2040\src\threaded\peripherals.rs`** — `ClocksState` / `ResetsState` / `TimerState` / `IoState` are stub mirrors of Serial Bus state. Only `TimerState` has a live `tick()` path on the threaded coordinator. UART / SPI / I2C / ADC / PWM / DMA per-cycle edge timing diverges Serial vs Threaded. **Already in `tech_debt.md` Stage 3b.4 §; restate visibility.**
- **In-flight IRQ plumbing in `lib.rs:680-708`** — `drain_pending_irqs_to_cores()` and the per-cycle interleave look complete on the EMU side; what's pending is silicon validation via `silicon_isr_diff_rp2040`. CLAUDE.md line 170 acknowledges this is intentional.

### Challenged / rejected

- **Sign-extend / add-with-carry / alignment-check helpers duplicated in mdrp2040 and mdrp2350** *(challenged → low priority)* — Two-line helpers, ARMv6-M vs ARMv8-M Mainline ISAs. Hoisting saves ~10 lines and creates a `mdpicoem-common::core_helpers` module that both crates would depend on for primitives that may diverge as ISA quirks surface. **Cost > benefit.** Defer until a third chip variant joins.
- **NVIC core logic "architecturally identical"** *(challenged → wrong)* — The DA notes ARMv6-M and ARMv8-M Mainline NVICs differ in priority bit width, IPR register layout, and security-state interaction. Surface looks the same; semantics don't. Don't merge.
- **`threaded/emulator.rs:325` panic on invalid core idx** *(rejected)* — same API-contract pattern as mdrp2350; correct as-is.
- **`threaded/shared.rs:137` `.expect("initial_ppb poisoned")`** *(rejected)* — Lock poisoning means a worker panicked mid-section, which already poisons the Emulator; further unwind is lost cause. Idiomatic.
- **`bus/mod.rs:708-710` "double-negation address mask"** *(rejected)* — `addr & !0x3000` is the standard pattern for stripping the 4-way alias bits on Pi peripherals. A named constant would be a marginal readability win, not debt.

### Notes

- **Dead-code allowances in mdrp2040 are uniformly justified.** The agent and DA agree: they're phase-tagged, the comments explain why, and the tracked-issues are in `tech_debt.md`. Continue this discipline.

## 8. Methodology notes

- **Why three of four reports inflated severity.** The agents were briefed to grep aggressively and cross-reference `tech_debt.md` but were not asked to read every HLD. Phased `#[allow(dead_code)]` placeholders that document a Stage-N future use therefore showed up as "unjustified". The DA pass corrected this; future sweeps should explicitly include "an `#[allow(dead_code)]` with a phase-tag comment is *correct*, not debt".
- **Why duplication recommendations are mostly downgraded.** "Hoist to `mdpicoem-common`" sounds like a free win but creates a leaky abstraction when the chip variants drift (they will: M33 has security state, M0+ doesn't; ARMv8-M NVIC ≠ ARMv6-M NVIC at the bit level). Better to keep clear chip-local code and revisit if a third variant arrives.
- **What this report deliberately does *not* cover.** Performance, observability beyond `tracing`, test coverage gaps, build-system hygiene beyond `cargo tree --duplicates`. These were out of scope.
