# RP2350 Peripheral Coverage — HLD V1

Companion to `2026.04.15 - HLD - RP2040 Peripheral Coverage V7.md`. That HLD is the
architectural template; this one lists the deltas for RP2350 and the Cortex-M33 /
ARMv8-M Mainline target. Read V7 first.

## 1. Purpose

Expand `mdrp2350` MMIO coverage beyond the eight peripherals modelled today
(SYSINFO, RESETS, CLOCKS, ROSC, XOSC, PLL_SYS, PLL_USB, QMI — plus SIO, PIO, PPB
and the QSPI/XIP/boot-RAM plumbing) so firmware in the motivating corpus (§3)
runs to completion instead of falling into the `HashMap<u32, u32>` fallthrough
at `crates/mdrp2350/src/bus/mod.rs:98`.

Scope: **TICKS + TIMER0/TIMER1** (Phase 1), **UART, SPI, I2C** (Phase 2),
**ADC, PWM** (Phase 3), **DMA** (Phase 4). Security block (OTP/SHA256/TRNG/
GLITCH_DETECTOR), POWMAN AON timer, HSTX, ACCESSCTRL: **deferred** unless
corpus evidence promotes them.

### Non-goals

- Full datasheet coverage. Model the register set the corpus actually touches.
- USB, ETM/TPIU, CORESIGHT_TRACE, TBMAN, BUSCTRL, SYSCFG, PSM, GLITCH_DETECTOR.
  Fallthrough until firmware demands otherwise.
- Non-pico-sdk runtimes. RISC-V Hazard3 cores. Non-secure state firmware.
- Cycle-accurate peripheral timing finer than one sys_clk.
- RP2040 mirror. Impls live in `crates/mdrp2350/`.
- Backwards compatibility or migration.

## 2. Current state

`crates/mdrp2350/src/bus/peripherals.rs` (337 lines) covers SYSINFO (read-only),
RESETS, CLOCKS (subset), ROSC, XOSC, PLL_SYS, PLL_USB, QMI. `bus/mod.rs` wires
SIO, PIO, PPB, boot-RAM, XIP SRAM, and the QSPI/flash surface. Everything else
round-trips through `peripheral_regs: HashMap<u32, u32>` with zero side effects.

Unlike RP2040, RP2350 **does not model SRAM bank contention** (CLAUDE.md
"Bank contention model" — mdrp2350 is dual-core-compute-only by design). No bus
changes are needed on that axis.

## 4. Oracle strategy

**Infrastructure is already built** — this is the single biggest difference
from V7's Phase 0. All RP2350 silicon oracles exist, wired to a Pico debug
probe attached to a real RP2354:

- `silicon_periph_diff_rp2350` — end-state peripheral differential. **Primary
  oracle for this HLD.** Authoring new `PeriphScenario` entries is the Phase-N
  exit gate, not building infrastructure.
- `probe_diff_rp2350` — instruction-level SWD single-step diff. Already
  catches M33 ISA regressions; unchanged by this work.
- `silicon_isr_diff_rp2350` — exception-entry / FP-lazy-save / tail-chain
  differential. Gains new scenarios as peripheral IRQs land (§6).
- `silicon_cycle_oracle_rp2350`, `silicon_dualcore_diff_rp2350` — unchanged,
  regression gates.
- `qemu_diff_m33` — CPU-level fuzz, unchanged.

**Missing piece: `mmio_trace_rp2350.rs`.** RP2040 V7 §4.3 introduces this
surface-and-iterate tool; RP2350 has no equivalent today. Phase 0 ports it
from the RP2040 variant (`mmio_trace_rp2040.rs`, currently being implemented).
Same shape: load firmware, flip `Bus::trace_enabled`, run N cycles, emit
`(addr, size, R/W, core, pc)`. The tail of the trace on a corpus binary shows
what to implement next.

### 4.1 Phase 0 exit criteria

1. `mmio_trace_rp2350` emits a non-empty trace of ≥500 peripheral MMIO entries
   on `hello_timer` and identifies the first pre-TIMER gap.
2. `silicon_periph_diff_rp2350` runs three new deliberately-broken scenarios
   with correct `first_divergence` output — same red-path validation as V7:
   - GPIO: wrong `SIO_GPIO_OUT` bit.
   - TIMER0: `TIMER0.TIMERAWL` read-path returns 0.
   - MMIO store: `XOSC_CTRL` write swallowed.
3. `CLOCKS.clk_*_selected` handshake audited. RP2350 shares the CLOCKS register
   shape with RP2040; V7 §4.4.5 documents the gap. If `bus/clocks.rs` lacks the
   handshake, fix it in Phase 0. Grep first — may already be present.

### 4.2 Triage

Same protocol as V7 §4.5. `probe_verify_rp2350` already exists.

## 5. Architecture

### 5.1 Peripheral pattern — inherent methods, no trait

**Identical to V7 §5.1.** Each peripheral is a struct in
`crates/mdrp2350/src/peripherals/<name>.rs` with inherent methods
(`read32`, `write32`, optional `tick`, `is_idle`). `Peripheral` trait is not
reintroduced — V7 already argues it away.

Fields and `irq_pending` are `pub(crate)` sibling fields on `Bus`; dispatch is
a match arm. Identical idiom.

### 5.2 Security alias handling

**New concern, not in V7.** ARMv8-M peripherals have Secure / Non-Secure
aliases on every APB peripheral, at offsets `+0x0000_0000` (S) and
`+0x1000_0000` (NS). V1 scope: **firmware in §3 runs entirely in Secure
state** (pico-sdk defaults to that for RP2350; non-secure toolchains are a
separate exercise).

Bus decode strips the S/NS alias bit before dispatching to the peripheral's
`read32`/`write32`, same way RP2040 strips atomic aliases today. The stripped
bit is preserved for a future SAU/IDAU layer; V1 asserts the access is from
Secure state (M33 `security == Secure`) and faults NS access as
RAZ/WI stub (return 0, discard writes) — don't fault, because pico-sdk init
sequences may touch NS aliases incidentally.

No per-peripheral secure-attributed register tables in V1. That belongs in a
future "RP2350 NS support" HLD if/when non-secure firmware enters scope.

### 5.3 IRQ plumbing

One field on `Bus`: `pub(crate) irq_pending: u64`. RP2350 has **52 external
IRQs** (Appendix B), vs RP2040's 26 — a `u64` covers it with headroom.

**M33 NVIC routing.** RP2350 has **two independent M33 NVICs** (one per core).
Each core's NVIC sees all 52 IRQs, with independent enable/pending/active
state. Peripherals assert `bus.irq_pending |= 1u64 << IRQ_N;` and the drain
loop walks both cores' NVICs, same shape as V7 §5.2:

```rust
if self.bus.irq_pending != 0 {
    let raised = std::mem::replace(&mut self.bus.irq_pending, 0);
    for irq in 0..IRQ_COUNT {
        if raised & (1u64 << irq) != 0 {
            self.cores[0].nvic.set_pending(irq as u16);
            self.cores[1].nvic.set_pending(irq as u16);
        }
    }
}
```

`nvic.set_pending` takes `u16` here because IRQ ids on M33 exceed 255 in the
architecture (though RP2350 uses ≤52). Use the type the existing NVIC stub
already takes; widen if needed.

**PPB NVIC today is a stub** (`crates/mdrp2350/src/bus/ppb.rs:470` —
"External IRQs default to 0"). Landing per-core pending/enable is a
prerequisite for Phase 1. Keep it minimal: pending latch, enable mask,
priority comparator. No grouping / subpriority in V1.

Level semantics and pulse sources (TIMER alarm match): same as V7 §5.2.

### 5.4 TICKS block — new dependency for TIMER0/1 and WATCHDOG

**Not in V7.** RP2350 factors out the 1 µs tick generator into a dedicated
TICKS peripheral at `TICKS_BASE = 0x4010_8000` with six tick domains
(proc0, proc1, timer0, timer1, watchdog, riscv). Each has `CTRL`, `CYCLES`,
`COUNT` registers.

TIMER0 / TIMER1 advance on their respective TICKS-generator edges; their
behaviour mirrors the RP2040 TIMER (64-bit TIMELR/TIMEHR, 4 alarms, INTR/INTE/
INTF/INTS, lazy scheduling per V7 §5.3/§5.5). The difference is the tick
source: RP2350 reads `TICKS.TIMER0_CYCLES` (default 12 — same 1 µs at
12 MHz clk_ref), RP2040 reads `WATCHDOG_TICK.CYCLES`.

Implement TICKS as a plain-storage peripheral (writes land, reads return
stored). Lazy scheduling on TIMER0/1 observes the current `CYCLES` value when
computing next-match-cycle; invalidate cached match cycles on TICKS writes.
One combined test: write `CYCLES=24`, verify TIMER0 advances at half rate.

### 5.5 Per-cycle tick and fast-path gate

**Identical to V7 §5.5.** Preserve the PIO fast-path gate
(`pio_all_idle && peri_idle && dma_idle && !any_irq`). RP2350's
`paced_bench_rp2350` benchmark is the regression oracle; throughput must not
regress from this HLD's landings. Track per-phase with a note in
`wrk_journals/`.

`Bus::all_peripherals_idle()`, `advance_lazy_scheduled()`, PIO IRQ routing
via `pending_irqs()` getter — all identical to V7, on a different bus. The
`pub fn pending_irqs(&self) -> u32` on `PioBlock` lives in
`crates/mdpicoem-common/src/pio/mod.rs` and is shared; V7 adds it for RP2040
and this HLD consumes it for RP2350 at zero marginal cost.

### 5.6 DMA — 16 channels

RP2350 DMA has **16 channels** (vs RP2040's 12) and a wider DREQ table
(Appendix C) that includes HSTX sources. Scope for V1 mirrors V7 §5.6.1:

- 16 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- `RING_SIZE`/`RING_SEL`, `CHAIN_TO`, `CH_ABORT`.
- `INTE0`/`INTE1`, `INTS0`/`INTS1` W1C, `DMA_IRQ_0`/`DMA_IRQ_1`. **Note:**
  RP2350 also has `DMA_IRQ_2`/`DMA_IRQ_3` — fold these in per-datasheet; same
  shape, just more W1C registers.
- Flat arbitration (lowest-channel-wins). Promote to tiered only if Phase 0
  trace evidence shows `HIGH_PRIORITY` usage on the corpus.
- **Not in V1**: CRC, sniff, byte-swap.

Emulator simplification on write visibility (cycle-issued, not AHB N+1):
identical to V7.

## 7. Testing

**Oracle hierarchy:**

1. `silicon_periph_diff_rp2350` — load-bearing; each peripheral ships scenarios
   sufficient to turn its corpus entry green.
2. `silicon_isr_diff_rp2350` — grows with Phase 1+ IRQ work.
3. `probe_diff_rp2350` — CPU-level fuzz, unchanged.
4. `qemu_diff_m33` — unchanged.
5. In-crate self-consistency checks (`#[cfg(test)]` per peripheral) — catch
   typos and protocol errors, not primary oracle.
6. Integration smoke — corpus binary runs to completion.

**Runtime.** Single `Session::auto_attach` reused (already the convention in
`test_silicon`). ~1 s/scenario. ≤80 new scenarios across phases → ~80 s
incremental silicon run.

**Flake policy.** Identical to V7 §7.

## 9. Risks & open questions

**9.1 NVIC stub is larger than it looks.** PPB NVIC today returns 0 for all
external-IRQ registers. Landing pending / enable / priority is a contained
scope but must happen in Phase 0, not smuggled into Phase 1. If it turns out
to need priority grouping semantics (BASEPRI on M33 *does* matter, unlike M0+),
scope expands — flag early.

**9.2 Security alias breadth.** §5.2 treats NS alias as RAZ/WI. If Phase 0
`mmio_trace_rp2350` shows pico-sdk touching NS aliases with non-trivial
expectations (e.g. reads with specific reset values), this commitment breaks
and we need a minimal SAU model. Trace-driven; not speculative today.

**9.3 Shared `peripherals/` directory name across crates.** Both
`crates/mdrp2040/src/peripherals/` (V7) and `crates/mdrp2350/src/peripherals/`
(this HLD) will exist with overlapping names (`timer.rs`, `uart.rs`, ...).
**Do not share code between them.** RP2350 peripherals have S/NS aliases,
different IRQ numbers, different base addresses, 52-vs-26 IRQ set, and TICKS
dependency. A common crate would force either the union of both chip's
quirks or ifdef-hell. Keep them parallel; if a genuine common helper emerges
(e.g. a FIFO newtype), lift to `mdpicoem-common` then.

**9.4 TICKS timing correctness.** RP2350 datasheet says the tick generator
divides `clk_ref` (12 MHz default) by `CYCLES` (default 12) to produce 1 µs.
If firmware reprograms `CYCLES` or `clk_ref`, TIMER0/1 cached match cycles
must invalidate. Failure mode: alarm fires at the wrong cycle, `hello_timer`
sleep is incorrect. Unit-test coverage: write CYCLES=24, arm 1 ms alarm,
verify it fires at twice the default cycle count.

**9.5 Probe rig failure.** No fallback oracle for silicon differentials. Rig
down → Phase 1+ stalls. Mitigation same as V7 §9.5: acknowledged.

**9.6 Coexistence with in-progress RP2040 work.** V7 implementation is
underway (`bus/mod.rs` modified, `mmio_trace_rp2040.rs` staged). This HLD's
Phase 0 `mmio_trace_rp2350.rs` port should follow RP2040's landing — copy
the final RP2040 shape, don't fork early.
