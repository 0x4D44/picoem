# Thumb-32 Instruction Decoder — Low-Level Design

Version: 1.0
Date: 2026-04-13
Status: V1 — post-review, incorporating three reviewer passes

## 1. Scope and Approach

Phase 1 goal: "can execute simple Thumb-2 binaries in flat memory."

**Implementation order: demand-driven.** Run a test binary, hit an unimplemented
opcode, implement it, repeat. No rigid tier system. The priority list below
guides which instructions to implement first, not a waterfall schedule.

**Priority list:**
1. **First** (get compiler output running): MOVW, MOVT, ADD.W/SUB.W (imm),
   CMP.W (imm), AND.W/ORR.W/BIC.W (imm), LDR.W/STR.W (imm12),
   LDRB.W/LDRH.W/STRB.W/STRH.W, B.W (cond + uncond), LDM.W/STM.W
2. **Then** (real code needs): shifted register ops, LDRD/STRD, MUL/MLA/MLS,
   SDIV/UDIV, SMULL/UMULL, CLZ, RBIT, BFI/BFC/UBFX/SBFX, wide extends,
   LDR.W (register offset, pre/post-index), TBB/TBH
3. **When needed** (system/bootrom): MSR/MRS, DSB/DMB/ISB, LDREX/STREX,
   coprocessor MRC/MCR/CDP, NOP.W/WFI.W, SSAT/USAT, IT blocks
4. **Deferred**: DSP extensions, FPU (Phase 7)

## 2. File Organization

One new file: `execute_thumb32.rs`. Split when it exceeds ~1,500 lines and
natural groupings are apparent. All Thumb-32 handlers are methods on
`CortexM33` (same pattern as existing Thumb-16 in `execute.rs`).

Additionally: update `decode.rs` to replace the current BL-only stub with
the full Thumb-32 dispatch tree.

## 3. Top-Level Decode Tree

Key dispatch fields from the two halfwords:
```
op1 = (hw0 >> 11) & 0x3    // hw0[12:11]
op2 = (hw0 >> 4) & 0x7F    // hw0[10:4]
op  = (hw1 >> 15) & 0x1    // hw1[15]
```

**CRITICAL FIX from review:** The `op1=11` branch must check `op` (hw1[15])
to distinguish long multiply/divide (op=0) from coprocessor (op=1). The V0
draft incorrectly used `op2 & 0x40`.

```rust
fn execute_thumb32(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let op1 = (hw0 >> 11) & 0x3;
    let op2 = (hw0 >> 4) & 0x7F;
    let op  = (hw1 >> 15) & 0x1;

    match op1 {
        0b01 => match op2 >> 5 {
            0b00 => if op2 & 0x04 == 0 {
                self.thumb32_ldm_stm(hw0, hw1, bus)
            } else {
                self.thumb32_load_store_dual(hw0, hw1, bus)
            },
            0b01 => self.thumb32_dp_shifted_reg(hw0, hw1),
            _    => self.thumb32_coprocessor(hw0, hw1, bus),
        },
        0b10 => if op == 0 {
            if op2 & 0x20 == 0 {
                self.thumb32_dp_modified_imm(hw0, hw1)
            } else {
                self.thumb32_dp_plain_imm(hw0, hw1)
            }
        } else {
            self.thumb32_branch_misc(hw0, hw1, bus)
        },
        0b11 => {
            if op2 & 0x40 != 0 {
                // op2[6] = 1: either data-proc/multiply (op=0) or coprocessor (op=1)
                if op == 1 {
                    return self.thumb32_coprocessor(hw0, hw1, bus);
                }
                match (op2 >> 4) & 0x3 {
                    0b00 => self.thumb32_dp_register(hw0, hw1),
                    0b01 => self.thumb32_multiply(hw0, hw1),
                    _    => self.thumb32_long_multiply(hw0, hw1),
                }
            } else {
                // op2[6] = 0: load/store single
                self.thumb32_load_store_single(hw0, hw1, bus)
            }
        },
        _ => self.thumb32_undefined(hw0, hw1),
    }
}
```

## 4. ThumbExpandImm (Modified Immediate Constants)

The 12-bit immediate `i:imm3:imm8` (hw0[10], hw1[14:12], hw1[7:0]) expands to
a 32-bit constant with carry-out. Used by all data-processing (modified
immediate) instructions.

```rust
#[inline(always)]
fn thumb_expand_imm_c(imm12: u32, carry_in: bool) -> (u32, bool) {
    if imm12 & 0xC00 == 0 {
        // Bits [11:10] = 00: byte replication patterns. Carry unchanged.
        let imm8 = imm12 & 0xFF;
        let val = match (imm12 >> 8) & 0x3 {
            0b00 => imm8,                           // 0x000000ii
            0b01 => (imm8 << 16) | imm8,            // 0x00ii00ii
            0b10 => (imm8 << 24) | (imm8 << 8),     // 0xii00ii00
            _    => imm8 * 0x01_01_01_01,            // 0xiiiiiiii
        };
        (val, carry_in)
    } else {
        // Bits [11:10] != 00: rotate (1:imm7) right by imm12[11:7].
        let unrotated = 0x80 | (imm12 & 0x7F);
        let rotation = (imm12 >> 7) & 0x1F;
        let val = unrotated.rotate_right(rotation);
        (val, val >> 31 != 0) // carry = MSB of result
    }
}
```

When the S bit is clear, callers can discard the carry:
```rust
#[inline(always)]
fn thumb_expand_imm(imm12: u32) -> u32 {
    thumb_expand_imm_c(imm12, false).0
}
```

## 5. Instruction Group Details

### 5.1 Data Processing (Modified Immediate)

Format: `11110_i_0_op[3:0]_S_Rn  0_imm3_Rd_imm8`

Extract `imm12 = (hw0[10] << 11) | (hw1[14:12] << 8) | hw1[7:0]`.
Call `thumb_expand_imm_c(imm12, apsr_c)`.

Match on op[3:0] (hw0[8:5]):

| op | S=0, Rd!=15 | S=1, Rd=15 | S=1, Rd!=15 | Notes |
|----|-------------|------------|-------------|-------|
| 0000 | AND | TST | ANDS | |
| 0001 | BIC | — | BICS | |
| 0010 | ORR (Rn!=15: ORR, Rn=15: MOV) | — | ORRS/MOVS | |
| 0011 | ORN (Rn!=15: ORN, Rn=15: MVN) | — | ORNS/MVNS | |
| 0100 | EOR | TEQ | EORS | |
| 1000 | ADD | CMN | ADDS | |
| 1010 | ADC | — | ADCS | |
| 1011 | SBC | — | SBCS | |
| 1101 | SUB | CMP | SUBS | |
| 1110 | RSB | — | RSBS | |

All: 1 cycle.

When S=1 and the immediate uses the rotation path, the C flag comes from
ThumbExpandImm's carry-out. When S=1 and the immediate uses replication,
the C flag is unchanged (carry_in passed through).

### 5.2 Data Processing (Plain Binary Immediate)

Format: `11110_i_1_op[4:0]_0_Rn  0_imm3_Rd_imm8`

These use zero-extended (NOT ThumbExpandImm) immediates.

**MOVW**: `op=00100`. `imm16 = (hw0[3:0] << 12) | (hw0[10] << 11) | (hw1[14:12] << 8) | hw1[7:0]`. Rd = imm16.

**MOVT**: `op=01100`. Same imm16 extraction. Rd[31:16] = imm16, Rd[15:0] unchanged.

**ADDW**: `op=00000, Rn!=15`. `imm12 = (hw0[10] << 11) | (hw1[14:12] << 8) | hw1[7:0]`. Rd = Rn + imm12.

**SUBW**: `op=01010, Rn!=15`. Rd = Rn - imm12.

**ADR** (ADDW/SUBW with Rn=15): Rd = Align(PC, 4) +/- imm12.

**BFI/BFC/SBFX/UBFX**: Bit field operations. BFC has Rn=1111.
- `lsb = (hw1[14:12] << 2) | hw1[7:6]`
- `width` varies by instruction.

**SSAT/USAT**: Saturation. Tier 3 (implement when needed).

All: 1 cycle.

### 5.3 Data Processing (Shifted Register)

Format: `11101_01_op[3:0]_S_Rn  0_imm3_Rd_imm2_tt_Rm`

Same ALU operations as 5.1, but second operand is barrel-shifted Rm:
- `shift_type` = hw1[5:4] (00=LSL, 01=LSR, 10=ASR, 11=ROR)
- `shift_amount` = (hw1[14:12] << 2) | hw1[7:6] (5 bits)
- Special: type=11, amount=0 → RRX (rotate right through carry by 1)

When Rn=1111 and op=0010: becomes LSL.W/LSR.W/ASR.W/ROR.W/RRX/MOV.W.

All: 1 cycle.

### 5.4 Load/Store Single

The most complex group. Dispatch on these hw0 fields:
```
hw0[10:9] = size (00=byte, 01=half, 10=word)
hw0[8]    = sign (1=signed, only valid for loads: LDRSB, LDRSH)
hw0[7]    = 1 → imm12 variant; 0 → imm8 or register
hw0[4]    = L bit: 1=load, 0=store
hw0[3:0]  = Rn (1111 = PC-relative literal)
```

**CRITICAL FIX from review:** When Rt=1111 (hw1[15:12]=1111) on a load, this
is a PLD/PLI preload hint, NOT a load to PC. Treat as 1-cycle NOP. Failing to
catch this will corrupt PC.

**Addressing modes (when hw0[7]=0, Rn!=1111):**
```
hw1[11] = 1 → imm8 with P/U/W
  hw1[10] = P (pre-index)
  hw1[9]  = U (add/subtract)
  hw1[8]  = W (writeback)
  hw1[7:0] = imm8
  Special: P=1,U=1,W=0 → unprivileged access (xT instructions)

hw1[11] = 0 → register offset
  hw1[5:4] = shift (LSL amount, 0-3)
  hw1[3:0] = Rm
```

**Cycle costs:**
- Load: 2 cycles (zero-wait-state memory)
- Store: 1 cycle (write-buffered)

### 5.5 Load/Store Multiple

Format: `11101_00_op_PUW_L_Rn  reglist[15:0]`

STMIA, STMDB, LDMIA, LDMDB. PUSH = STMDB SP!. POP = LDMIA SP!.
16-bit register list (R0-R15).

Cycle cost: 1 + N (N = register count). May be N on M33 — validate with DWT.

### 5.6 Load/Store Dual, Exclusive, Table Branch

**LDRD/STRD**: Two consecutive words. Rt, Rt2 from hw1.
8-bit word-aligned offset (imm8 << 2) with P/U/W addressing.

**LDREX/STREX**: For Phase 1, treat as normal load/store (no exclusive monitor).

**TBB/TBH**: Table branch byte/halfword. PC += Memory[Rn + Rm] (or *2 for TBH).

**CLREX**: 1-cycle NOP (no exclusive monitor yet).

### 5.7 Branches and Miscellaneous Control

**B.W conditional (T3):** `11110_S_cond_imm6  10_J1_0_J2_imm11`.
Range: +/- 1 MB. Offset = SignExtend(S:J2:J1:imm6:imm11:0, 21).

**B.W unconditional (T4):** `11110_S_imm10  10_J1_1_J2_imm11`.
Range: +/- 16 MB. I1 = NOT(J1 XOR S), I2 = NOT(J2 XOR S).

**BL:** Already implemented (keep existing handler, move to new file).

**MSR/MRS:** System register access. Requires SP banking helpers (add when
implementing MSR). SYSm byte selects register:
- 0-4: APSR, IAPSR, EAPSR, XPSR
- 5-9: IPSR, EPSR, IEPSR, MSP, PSP
- 16-20: PRIMASK, BASEPRI, BASEPRI_MAX, FAULTMASK, CONTROL

SP banking design (implement with MSR):
```rust
impl Registers {
    fn active_sp_is_psp(&self) -> bool {
        !self.in_handler_mode() && self.control & 2 != 0
    }
    fn sync_sp_to_banked(&mut self) {
        if self.active_sp_is_psp() { self.psp = self.r[13]; }
        else { self.msp = self.r[13]; }
    }
    fn sync_sp_from_banked(&mut self) {
        self.r[13] = if self.active_sp_is_psp() { self.psp } else { self.msp };
    }
}
```

**CRITICAL FIX from review:** Handler mode always uses MSP regardless of
CONTROL.SPSEL. The `active_sp_is_psp()` check must verify `!in_handler_mode()`.

**Hints:** NOP.W, YIELD.W, WFE.W, WFI.W, SEV.W — 1-cycle NOPs.
**Barriers:** DSB, DMB, ISB — 1-cycle NOPs for Phase 1 (in-order core).

### 5.8 Multiply and Divide

**32-bit result:** MUL, MLA, MLS — 1 cycle.
**64-bit result:** SMULL, UMULL, SMLAL, UMLAL — 1 cycle.
**Division:** SDIV/UDIV — data-dependent, 2-11 cycles on M33.

For Phase 1, SDIV/UDIV can use a constant cycle count (e.g., 4). Refine with
DWT CYCCNT later. Division by zero returns 0 (when CCR.DIV_0_TRP = 0, which
is the default).

### 5.9 Data Processing (Register)

Miscellaneous operations: CLZ, RBIT, REV.W, REV16.W, REVSH.W.
Wide shift by register: LSL.W, LSR.W, ASR.W, ROR.W.
Wide extend: SXTH.W, SXTB.W, UXTH.W, UXTB.W.
All: 1 cycle.

### 5.10 Coprocessor

Dispatch by `coproc = (hw1 >> 8) & 0xF`:
```rust
match coproc {
    0     => self.coproc_gpioc(hw0, hw1, bus),  // Phase 3
    4 | 5 => self.coproc_dcp(hw0, hw1),         // Phase 3
    7     => self.coproc_rcp(hw0, hw1),          // Phase 3
    10 | 11 => self.coproc_fpu(hw0, hw1),        // Phase 7
    _     => self.thumb32_undefined(hw0, hw1),   // UsageFault (NOCP)
}
```

No trait — plain match on known RP2350 coprocessors. Phase 1: all return
`thumb32_undefined`. Phase 3: implement CP0/4/5/7 stubs. Phase 7: FPU.

## 6. IT Block Design

IT blocks are needed before running real compiled code (GCC emits them for
conditionals). Not needed for individual instruction handler testing.

**State:** Add `it_state: u8` to `CortexM33`. Format: `cond[7:4]:mask[3:0]`.
`mask == 0` means not in IT block.

**IT instruction handler** (Thumb-16, currently caught by misc catch-all):
```rust
fn thumb16_it(&mut self, opcode: u16) -> u32 {
    self.it_state = (opcode & 0xFF) as u8;
    1
}
```

**Decode loop modification:**
```rust
fn decode_execute(&mut self, bus: &mut Bus) -> u32 {
    let in_it = self.it_state & 0xF != 0;
    let cond = if in_it { (self.it_state >> 4) & 0xF } else { 0xE };
    let cond_passed = self.regs.condition_passed(cond as u8);

    // ... fetch and decode as before ...

    let cycles = if cond_passed {
        // execute normally
    } else {
        1 // skipped: 1 cycle
    };

    if in_it { self.advance_it_state(); }
    cycles
}
```

**Advance logic:** Shift mask left; the new bit[4] becomes the condition LSB
for the next instruction (T/E encoding is baked into the mask by the IT
instruction).
```rust
fn advance_it_state(&mut self) {
    let mask = self.it_state & 0xF;
    if mask & 0x7 == 0 {
        self.it_state = 0; // last instruction in block
    } else {
        self.it_state = (self.it_state & 0xE0) | ((mask << 1) & 0x1F);
    }
}
```

**Flag suppression:** Inside an IT block, Thumb-16 instructions that normally
set flags unconditionally (ADDS, SUBS, MOVS, etc.) must suppress flag updates.
Thumb-32 instructions have an explicit S bit and are unaffected by IT state.

Implementation: `execute_thumb16` reads `self.it_state` directly (no parameter
needed — it has `&mut self`). When `self.it_state & 0xF != 0`, skip flag writes.

**xPSR sync (for future exception support):** IT state is architecturally stored
in xPSR bits [15:10, 26:25]. The `it_state` shadow must sync:
- Exception entry: write `it_state` into xPSR before stacking
- Exception return: read `it_state` from xPSR after unstacking
- MSR writes to xPSR: update `it_state`
These sync points are Phase 3 work.

| Instruction class | Cycles | Notes |
|---|---|---|
| Data processing (reg/imm/shifted) | 1 | |
| MOVW, MOVT | 1 | |
| MUL, MLA, MLS | 1 | |
| SMULL, UMULL, SMLAL, UMLAL | 1 | |
| SDIV, UDIV | 2-11 | Data-dependent; use 4 as placeholder |
| LDR/LDRB/LDRH/LDRSB/LDRSH | 2 | Zero-wait-state memory |
| STR/STRB/STRH | 1 | Write-buffered |
| LDM/STM (N regs) | 1+N | M33 may be N; validate with DWT |
| LDRD/STRD | 1+2 | M33 may be 2; validate with DWT |
| Branch taken | 2 | Pipeline refill; validate |
| Branch not taken | 1 | |
| BL | 4 | Already implemented; validate |
| CLZ, RBIT, REV, BFI/UBFX | 1 | |

| DSB, DMB | 1 | In-order core, no reordering |

## 8. Design Decisions Log

| Decision | Rationale |
|---|---|
| One file (`execute_thumb32.rs`), split later | Can't predict natural fault lines before writing code |
| Demand-driven implementation order | Implement what test binaries need, not a tier waterfall |
| IT blocks: implement before real binaries, not before handlers | Individual handler tests use `execute_one_wide()` without IT |
| SP banking: implement with MSR, not upfront | No Thumb-32 instruction needs it until MSR |
| Bus fault: defer to Phase 3 | Phase 1 is flat memory; bus fault is exception infrastructure |
| Coprocessor: plain match, not trait | 4 known coprocessors, compile-time dispatch |
| `it_state` as shadow of xPSR ITSTATE bits | Performance (avoid bit-field extraction every cycle); sync on exception entry/return |
| PLD/PLI (Rt=1111 on loads): treat as NOP | Prevents PC corruption; M33 has no cache to preload |
| Cycle timing: use M4 values, validate later | No published M33 table; M4 pipeline is architecturally similar |
| SDIV/UDIV: constant placeholder (4 cycles) | Data-dependent timing; refine with DWT CYCCNT |
| Unaligned LDR/STR: allow (current code handles it) | M33 supports unaligned access to normal memory by default |
| Unaligned LDRD/LDM/LDREX: should fault | Always-fault per spec; add alignment check when implementing |

## 9. Test Strategy

Hand-encoding Thumb-32 opcodes in hex is error-prone due to the complex
two-halfword encoding. Build test encoding helpers:

```rust
// In test module
fn encode_movw(rd: u8, imm16: u16) -> (u16, u16) { ... }
fn encode_ldr_w_imm12(rt: u8, rn: u8, imm12: u16) -> (u16, u16) { ... }
fn encode_add_w_imm(s: bool, rd: u8, rn: u8, imm12: u32) -> (u16, u16) { ... }
```

These are test infrastructure, not production code. They encode from named
fields to (hw0, hw1) pairs, making tests readable and verifiable.

For each implemented instruction: test correctness (register results, flag
updates), cycle count return value, and at least one edge case.
