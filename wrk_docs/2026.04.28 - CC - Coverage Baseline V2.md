# Code Coverage Baseline V2 — 2026-04-28

Author: Claude (CC) on `main`, parent commit `42c7bc1` plus the in-session pacer fix (`b849f22`).
Toolchain: `cargo +nightly llvm-cov --branch` (rustc nightly 2026-02-12, cargo-llvm-cov 0.6.21).
Target: drive branch coverage to **≥ 98%** on the in-scope testable code.

## 1. Method

```bash
cargo +nightly llvm-cov --workspace --exclude epio-sys \
    --branch --json --output-path /tmp/cov-full.json --release
```

`epio-sys` is excluded because its build script requires `clang` and the vendored `epio` C submodule (not present in this checkout). Coverage there would be a thin C-FFI shim; orthogonal to the Rust surface area we care about.

### Pre-baseline fixes

Two compile/test failures blocked the baseline run; both are fixed in `b849f22`:

1. **`crates/mdpicoem-common/src/pacer.rs:158`** — Rust 2024 edition no longer treats the body of an unsafe-receiving call as implicitly unsafe. Wrapped `std::arch::x86_64::__cpuid(0x80000007)` in an `unsafe { … }` block with a SAFETY note.
2. **`pacer::tests::test_update_sys_clk_hz_changes_quantum`** — under llvm-cov's parallel-test stress the calibrated `overhead` exceeded the small (≈7 k tick) 150 MHz quantum, saturating `quantum_tsc_ticks` to zero. Mirrored the existing 25 %-of-nominal clamp from `Pacer::with_quantum` into `update_sys_clk_hz` so high-Hz reprograms keep at least 75 % of the new nominal. The earlier (04-23) widening of the ratio bound to `[10, 100]` is preserved.

`cargo test --workspace --exclude epio-sys --release` is green: **27 test binaries, 4 030 + 235 unit tests pass, 0 fail, 41 ignored** (35 of those are bootrom-blocked silicon smoke tests; rest are platform-gated).

## 5. Shape of the deficit

Five recurring patterns dominate:

1. **Threaded runtime mailbox edges.** `mdrp2040::threaded::{bus, emulator, peripherals, atomics, memory}` collectively miss 97 branches at 54-80 %. The same files in `mdrp2350` add another ~36. These are mailbox event paths (peripheral callbacks, monitor events, contention-exclusive ticket handoff) and lifecycle paths (worker thread spin-up, panic-containment, halt-on-shutdown).
2. **Core hot-path corner cases.** `core/{mod,execute_fpu,execute_thumb32,exceptions,decode}` on M33 and M0+ miss 198 branches concentrated in (a) IT-block true/false fold-throughs, (b) UNDEFINED encoding HardFault paths, (c) lazy-FP / FPCCR variants on M33, and (d) EXC_RETURN error variants. Most are reachable via firmware blobs.
3. **Bus / peripheral MMIO corners.** `bus/mod.rs` (62 missed branches across the two chips) and `peripherals/{i2c, spi, uart, adc, powman}` (~50 missed total) cover address-decode, alias-port writes, WC1 sticky bits, and reset-mid-transaction edges.
4. **Top-level `lib.rs` paths.** `mdrp2350/src/lib.rs` (27 missed) and `mdrp2040/src/lib.rs` (17 missed) are the `Emulator::run` / `EmulatorBuilder::build` happy/error mix; many `ConfigError` arms aren't constructed in tests.
5. **Test infrastructure.** `mdrp2350/src/core_riscv/tests_p4.rs` shows up at 54 % branch — but per the 04-23 doc those numbers are just `assert!` macros whose fail arm never fires. We will exclude `tests*.rs` and `pio_tests.rs` from the new exclusion regex (see § 9).

## 6. What is structurally unreachable (unchanged)

Same as the 2026-04-23 baseline — keep these out of scope:

- **Hardware / silicon oracles** (`probe_*`, `silicon_*`, `bank_conflict_*`, `paced_bench_*`, `full_test_*`, `onerom_*_rp2350`, `smoke_per_core_cyccnt_rp2350`, `smoke_powman_pacing_rp2350`, `threaded_probe`, `threading_micro`, `workload_study_*`, `picogus_probe_pc`, `test_silicon`) — need a Pico debug probe + RP2354/RP2040 silicon.
- **QEMU oracles** (`qemu_diff_m33`, `qemu_diff_m0plus`, `qemu_diff_riscv32`, `softfloat_diff`, `picogus_diff_rp2040`, `riscv_probe_spike`, `probe_csrrw_riscv32`, `pio_microbench`, `mmio_trace_*`, `test_helper_job_object`) — spawn a QEMU subprocess; not available in the sandbox.
- **Hardware-oracle support libs** (`silicon_scenarios`, `isr_scenarios{,_rp2040}`, `dualcore_cases`, `cycle_cases`, `bank_conflict_cases`, `silicon_oracle`, `gdb_client`, `ieee754_ref`, `onerom_*`, `picogus_pins`).
- **TUI app shell** (`mdrp2350app/src/{main,ui,sim,firmware,panels/*}.rs` and the `mdrp2040app` equivalents) — needs a terminal at the keyboard.

In-scope **does** include the `devices/*` subtrees inside each app crate (LCD/bench device models, headlessly testable) and `snapshot.rs`.

## 8. Acceptance criteria

A run is "at goal" when, against the regex in § 7:

- Branch coverage ≥ **98.00 %**.
- Line / region / function coverage all ≥ Stage-0 values (96.41 / 96.48 / 96.59 %).
- `cargo test --workspace --exclude epio-sys` is green and `cargo build --release` shows no new warnings on touched files.

## 9. Risks / honest caveats

- **518 / 634 branches must fall.** Some of the residue is genuinely hard: PSM password-gated writes to a fault state, `unreachable!()` arms after exhaustive enum matches, and platform-gated `cfg` paths that only compile on `x86_64-windows`. We will use `#[cfg_attr(coverage_nightly, coverage(off))]` only with a one-line justification *in the source comment*, and only when the branch is provably unreachable from valid inputs.
- **Threaded paths concentrate the largest single chunk (~135 branches).** They are also the hardest to drive deterministically. Plan: prefer scenario-driven integration tests against the `Threaded` execution model rather than hand-mocked `mpsc` doubles, but accept the slower test runtime (≈ 5 s per `Threaded` start/stop pair).
- **One coverage run = ~12 minutes.** The full nightly+coverage build with `lto = fat` is the long pole. We will batch agent work between coverage runs (do 4-6 stage agents in parallel, then one re-measure) instead of measuring after each file.
