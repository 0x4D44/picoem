## §3 Per-item design

### §3.1 SYSINFO — fill read-only fields

**Current** (`bus/peripherals.rs:48`): `sysinfo_read` returns
`CHIP_ID = 0x0000_0002`, `PACKAGE_SEL = 0`, `PLATFORM = 1`.

**Target**: add the remaining read-only fields (`GITREF_RP2350`,
`CHIP_ID` revision field, additional PLATFORM bits) to match real
RP2354 silicon. (`GITREF_RP2350` is chip-revision-specific; another
RP2354 revision may need a scenario update.)

**Silicon scenario**: `silicon_periph_diff_rp2350`; one read at
reset, diff each u32 at documented offsets.

**Unit test**: `sysinfo_reads_hardcoded_readonly_fields`.

### §3.2 POWMAN COUNT + MATCH

**Current** (`peripherals/powman.rs`): 64-bit COUNT/MATCH as
`AON_COUNT_LO/HI` (0x08 / 0x0C), `AON_MATCH_LO/HI` (0x10 / 0x14).
Storage-only. Warn-once on first write to COUNT/MATCH
(`peripherals/powman.rs:150, 168`).

**Target**:
- COUNT advances at 1 tick per POWMAN clock source (XOSC / 4
  assumed; pre-flight measures).
- MATCH fires `POWMAN_IRQ_TIMER` (NVIC line 45) when COUNT ==
  MATCH and MATCH_EN is set. One-shot.
- `POWMAN_IRQ_POW` (line 44) stays unwired.
- ARCHSEL warn-once on non-Arm write preserved (see §10).

**Silicon scenario — MATCH fires IRQ line 45** (via
`silicon_isr_diff_rp2350`, patterned on
`isr_ext_irq_timer0_cold` at `isr_scenarios.rs:1010`):

- **RESETS setup** — POWMAN is **not** in `RESETS_POST_BOOTROM`
  (`bus/mod.rs:182-199`). Scenario must write
  `RESETS_RESET + ALIAS_CLR = (1 << RESET_POWMAN)` before any
  POWMAN access.
- **Vector table**: slot `16 + 45 = 61` points at a handler stub
  that writes `0xCAFE_BABE` to a memory marker and `bkpt #0`.
  Marker is pre-seeded to `0xDEAD_BEEF` by scenario setup so the
  observable distinguishes "IRQ fired and handler ran" from "MMIO
  returned zero".
- **Main**: enable POWMAN, set `AON_MATCH_LO = 100`, `MATCH_EN = 1`,
  NVIC `ISER1` bit 13 set (IRQ 45 / 32 = bank 1, 45 % 32 = bit 13;
  ISER1 at `0xE000_E104`, **not** ISER0).
- **Observable**: memory marker = `0xCAFE_BABE`; CYCCNT delta
  within a pre-flight-measured numeric window.
- **`max_sysclks`**: derived from pre-flight pacing ratio. For
  assumed XOSC/4 pacing (50 sys_clks / POWMAN tick) at K=100,
  budget is `100 * 50 + 1000 margin ≈ 6000 sys_clks`. Pre-flight
  confirms or corrects.

Why one scenario, not two: a cycle-exact COUNT-only observable
would require a tolerance-mask the oracle doesn't support, and
silicon MMIO setup writes themselves consume cycles and perturb
the measurement. Scenario-B implicitly validates the COUNT rate —
if MATCH fires on time, the pacing is right. Unit tests cover
COUNT rate explicitly.

**Unit tests**:
- `powman_count_advances_at_expected_rate` — tick N sys_clks,
  assert `count == N / sys_per_tick`.
- `powman_match_pends_nvic_line_45` — drive via the emulator's
  own bus; read NVIC ISPR1 bit 13 with PRIMASK=1 to observe a
  latched pending bit without dispatch. Closes the "unit test
  doesn't prove NVIC bank math" gap.
- `powman_archsel_non_arm_write_warns_once` — tripwire for
  concurrent RISC-V work (§10).

**Implementation**: add `aon_count: u64`, `aon_match: u64`,
`match_en: bool` to `PowmanRegs`. Drive from `tick_peripherals`.
Drop the warn-once on COUNT/MATCH **writes**. IRQ via
`raise_irqs_u64(1u64 << 45)` — `raise_irqs_u64` takes a u64
bitmask (see `bus/mod.rs` around line 1970).

### §3.3 GLITCH_DETECTOR — ARM readback

**Current** (`peripherals/inert.rs:128, 139`): HashMap storage;
`STATUS.ARM` forced 0 on read; `TRIG_STATUS` W1C.

**Target**: `STATUS.ARM` reads back the value written to
`CTRL.ARM`. `TRIG_STATUS` stays at 0. No IRQ.

**Silicon scenario** (`silicon_periph_diff_rp2350`): setup writes
`CTRL.ARM = 1`; observe `STATUS.ARM = 1`, `TRIG_STATUS = 0`.

**Unit test**: `glitch_detector_arm_readback_tracks_ctrl`.

### §3.4 TBMAN — PLATFORM selector

**Current** (`peripherals/inert.rs:45`): HashMap storage only.

**Target**: PLATFORM field reads the silicon-observed value
(assumption `0b01`; pre-flight confirms).

**Silicon scenario** (`silicon_periph_diff_rp2350`): one-shot read
of `TBMAN_BASE + 0x00` at reset.

**Unit test**: `tbman_platform_reads_silicon_value`.

## §8 Landing plan

**Pre-flight** (once, before POWMAN lands):

Write and run a one-off `smoke_powman_pacing_rp2350` binary under
`crates/mdpicoem-harness/src/bin/`:

- Release POWMAN from reset, enable, set a known MATCH value.
- Poll `AON_COUNT_LO` on probe-rs; record DWT CYCCNT deltas
  between distinct values.
- Print: actual sys_clks per POWMAN tick, `POWMAN_BASE` dump,
  offsets layout sanity.

Deleted after Phase 1 lands.

For SYSINFO / TBMAN / GLITCH_DETECTOR, pre-flight is a single
`probe-rs read-words --chip RP235x <BASE> 8` to capture values
and sanity-check the base.

If pre-flight reveals wrong base, wrong offsets, or a pacing
ratio different from the 50:1 assumption, re-scope the affected
item before landing — pacing-ratio wrongness cascades into
`max_sysclks` re-derivation for scenario B.

**Per-item cadence** (V5 convention): implement → code-review →
apply-feedback → devil's-advocate → commit.

**Order**: SYSINFO, TBMAN, GLITCH_DETECTOR, POWMAN.

Cargo minor bump per item.
