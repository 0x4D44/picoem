## §3 Per-item design

### §3.1 SYSINFO — fill read-only fields

**Current** (`bus/peripherals.rs:48`): `sysinfo_read` returns
`CHIP_ID = 0x0000_0002`, `PACKAGE_SEL = 0`, `PLATFORM = 1`.

**Target**: add the remaining read-only fields (`GITREF_RP2350`,
`CHIP_ID` revision field, additional PLATFORM bits) to match real
RP2354 silicon.

**Silicon scenario** (`silicon_periph_diff_rp2350`): one read at
reset, diff each u32.

**Unit test**: `sysinfo_reads_hardcoded_readonly_fields`.

### §3.2 POWMAN COUNT + MATCH

**Current** (`peripherals/powman.rs`): 64-bit COUNT/MATCH as
`AON_COUNT_LO/HI` (0x08 / 0x0C), `AON_MATCH_LO/HI` (0x10 / 0x14).
Storage-only. Warn-once on first write to COUNT/MATCH
(`peripherals/powman.rs:150, 168`).

**Implementation subtasks beyond the per-item module work**:
- Add `pub const RESET_POWMAN: u8 = 17;` to `bus/mod.rs` alongside
  the existing `RESET_*` constants (RESET_SYSINFO = 21,
  RESET_USBCTRL = 28 bracket it; 17 per datasheet). **Does not
  exist in tree today.**
- Wire `POWMAN_BASE => Some(RESET_POWMAN)` into `reset_bit_for_base`
  at `bus/mod.rs:213` so the existing RESETS guard gates POWMAN
  correctly. Without this, releasing the reset bit is a no-op for
  bus-level MMIO gating.

**Target**:
- COUNT advances at 1 tick per POWMAN clock (XOSC / 4 assumed;
  pre-flight measures).
- MATCH fires `POWMAN_IRQ_TIMER` (NVIC line 45) when COUNT ==
  MATCH and MATCH_EN is set. One-shot.
- `POWMAN_IRQ_POW` (line 44) stays unwired.
- ARCHSEL warn-once on non-Arm write preserved (§10).

**Silicon scenario — MATCH fires IRQ line 45** (via
`silicon_isr_diff_rp2350`, same shape as the existing
`isr_ext_irq_timer0_cold` scenario — see `isr_scenarios.rs`
around line 1417):

- **RESETS setup**: POWMAN is **not** in `RESETS_POST_BOOTROM`
  (`bus/mod.rs:182-199`). Scenario setup writes
  `RESETS_RESET + ALIAS_CLR = (1 << RESET_POWMAN)` first.
  `ALIAS_CLR` is `0x3000` per `silicon_scenarios.rs:26`.
- **Vector table**: slot `16 + 45 = 61` → handler stub that
  writes `0xCAFE_BABE` to a memory marker and `bkpt #0`. The
  marker is pre-seeded to `0xDEAD_BEEF` by setup so the
  observable distinguishes "handler ran" from "zeroed SRAM".
- **Main**: enable POWMAN; set `AON_MATCH_LO = 100`,
  `MATCH_EN = 1`; set NVIC ISER1 bit 13 (IRQ 45 is bank 1,
  bit 13; ISER1 at `0xE000_E104`, **not** ISER0).
- **Observable**: memory marker == `0xCAFE_BABE`; CYCCNT delta
  within a pre-flight-measured window.
- **`max_sysclks`**: `K * sys_per_tick + margin`. Numeric value
  filled in at implementation time from the pre-flight pacing
  measurement (§8). Budgeted ~6000 under the 50:1 XOSC/4
  assumption.

**Unit tests**:
- `powman_count_advances_at_expected_rate` — tick N sys_clks,
  assert `count == N / sys_per_tick`.
- `powman_match_pends_nvic_line_45` — drive via the emulator's
  own bus with PRIMASK=1 (blocks dispatch via `can_preempt` at
  `exceptions.rs:492`; doesn't block ISPR latching); read ISPR1
  bit 13. Validates NVIC bank math without silicon.
- `powman_match_enters_emulator_handler` — same setup but
  PRIMASK=0 and a 16-slot vector table in SRAM; assert the
  emulator takes the exception and PC lands at handler. Covers
  the emulator-side IRQ-entry path for IRQs ≥ 32 (a new
  NVIC-bank code path that neither unit test above exercises).
- `powman_archsel_non_arm_write_warns_once` — regression
  tripwire for the RISC-V track (§10).

**Implementation**: add `aon_count: u64`, `aon_match: u64`,
`match_en: bool` to `PowmanRegs`. Drive from `tick_peripherals`.
Drop the warn-once on COUNT/MATCH writes. IRQ via
`raise_irqs_u64(1u64 << 45)` — `raise_irqs_u64` in
`bus/mod.rs` around line 1970 takes a u64 bitmask.

### §3.3 GLITCH_DETECTOR — ARM readback

**Current** (`peripherals/inert.rs:128, 139`): HashMap storage;
`STATUS.ARM` forced 0 on read; `TRIG_STATUS` W1C.

**Target**: `STATUS.ARM` reads back the value written to
`CTRL.ARM`. `TRIG_STATUS` stays at 0. No IRQ.

**Silicon scenario** (`silicon_periph_diff_rp2350`): setup writes
`CTRL.ARM = 1`; observe `STATUS.ARM = 1`, `TRIG_STATUS = 0`.

**Unit test**: `glitch_detector_arm_readback_tracks_ctrl`.

### §3.4 TBMAN — PLATFORM selector

**Current** (`peripherals/inert.rs:45`): HashMap storage only.

**Target**: PLATFORM field reads the silicon-observed value
(assumption `0b01`; pre-flight confirms).

**Silicon scenario** (`silicon_periph_diff_rp2350`): one-shot
read of `TBMAN_BASE + 0x00` at reset.

**Unit test**: `tbman_platform_reads_silicon_value`.

## §8 Landing plan

**Pre-flight** (once, before POWMAN lands):

Write `crates/mdpicoem-harness/src/bin/smoke_powman_pacing_rp2350.rs`
— a one-off that releases POWMAN from reset, enables it, polls
`AON_COUNT_LO` via probe-rs, and prints (a) raw DWT CYCCNT sample
pairs for each observed COUNT transition, (b) the derived sys_clks
/ POWMAN-tick ratio, (c) a `POWMAN_BASE + 0x00..0x24` dump. The
smoke binary goes through the same implement → review →
devil's-advocate cycle as a production item — its output drives
`max_sysclks` and validates the 50:1 assumption, so it's not
throwaway glue. Kept under `src/bin/` after Phase 1 ships
(precedent: `smoke_per_core_cyccnt_rp2350`); re-run if the clock
tree changes.

For SYSINFO / TBMAN / GLITCH_DETECTOR, pre-flight is a single
`probe-rs read-words --chip RP235x <BASE> 8` to capture values
and sanity-check the base.

If pre-flight invalidates a base, offset layout, or the pacing
ratio, re-scope the affected item before landing. If POWMAN
pre-flight catastrophically invalidates the clock-source
assumption, land the three hygiene items and defer POWMAN to a
dated follow-on HLD.

**Per-item cadence**: implement → code-review → apply-feedback →
devil's-advocate → commit.

**Order**: SYSINFO, TBMAN, GLITCH_DETECTOR, POWMAN.

Cargo minor bump per item.
