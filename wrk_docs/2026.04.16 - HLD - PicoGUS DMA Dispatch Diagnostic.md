# HLD — PicoGUS DMA Dispatch Diagnostic (Rev. 1)

## 1. Problem

Three PIO bugs were fixed today; 127 K ISA autopushes now land in PIO0 RX FIFO with correct addr/data. Yet PSRAM stays at 0 non-zero bytes and PIO1 SM0 TX FIFO is never written. PicoGUS' DRAM-write dispatch path is firmware → DMA channel (READ_ADDR = SRAM staging, WRITE_ADDR = `0x5030_0010`/PIO1 TXF0, TREQ_SEL = PIO1-TX0) → DMA reads SRAM → DMA writes PIO1 TXF0 → PIO1 SM0 shifts bits to PSRAM. **Theory 2** says firmware reaches dispatch, but one of those steps silently fails. Phase D's journal documents the exact failure class (AL1 `TRANS_COUNT` at 0x1C was mis-classified as non-trigger). We need an end-of-run snapshot proving which of four stages failed.

## 2. Signal we want

Four-way verdict across 12 channels:

1. **No config.** No channel ever held `WRITE_ADDR ∈ 0x5030_0010..0x5030_001C` and no channel ever took a trigger-alias write.
2. **Configured, never triggered.** At least one channel's sticky PIO1-TXF mask is non-zero with `CTRL.EN=1`, but every `trig_*` counter is 0.
3. **Triggered, engine never served.** At least one `trig_*` counter > 0 but `transfers_issued == 0`.
4. **Engine served, PIO didn't consume.** `transfers_issued > 0` but PIO1 SM0 TX FIFO was never written / never drained.

## 3. Design

DREQ gating **is modelled** — `Dma::tick` at `crates/mdrp2040/src/dma.rs:481-497` calls `bus.collect_dreqs()`, then gates by `ch.treq_sel()` (dma.rs:490-492). Therefore a sticky "DREQ observed" bitmap is meaningful and non-trivial: if `ready` was true for a channel this tick, TREQ_SEL mapped to an asserted line. That lets verdicts 3a vs 3b diverge.

Counters added to `DmaChannel` (zero-init, no semantic change):
- `ever_wrote_pio1_txf_mask: u8` — sticky bit per TXF0..3; set by helper `mark_if_pio1_txf(new_addr)` called from every `WRITE_ADDR`-alias match arm: `CH_WRITE_ADDR | CH_AL2_WRITE_ADDR | CH_AL3_WRITE_ADDR` (dma.rs:421-424) **and** `CH_AL1_WRITE_ADDR_TRIG` (dma.rs:425-429). Evaluates the post-`apply_alias` `new` value so alias 2 (SET) / alias 3 (CLR) constructions are caught.
- `trig_ctrl: u32` — bump inside `CH_CTRL_TRIG` arm (dma.rs:441-445), offset `0x0C`.
- `trig_write_addr: u32` — bump inside `CH_AL1_WRITE_ADDR_TRIG` arm (dma.rs:425-429), offset `0x18`.
- `trig_trans_count: u32` — bump inside `CH_AL1_TRANS_COUNT | CH_AL2_TRANS_COUNT_TRIG` arm (dma.rs:435-440). **This is the Phase-D alias** — AL1 at `0x1C` triggers despite its name lacking `_TRIG`. Split into two counters for clarity: **`trig_trans_count`** for the `CH_AL1_TRANS_COUNT` path (`0x1C`) and **`trig_al2_trans`** for `CH_AL2_TRANS_COUNT_TRIG` (`0x24`). The match arm is shared (dma.rs:435), so branch on `inner` inside the arm.
- `trig_al3_read_addr: u32` — bump inside `CH_AL3_READ_ADDR_TRIG` arm (dma.rs:416-420), offset `0x3C`.
- `trig_multi: u32` — bump inside `REG_MULTI_CHAN_TRIGGER` loop (dma.rs:363-368) when this channel's bit is set.
- `transfers_issued: u64` — bump at top of `issue_transfer` (dma.rs:504).
- `dreq_observed_mask: u64` — sticky bit per TREQ index 0..63. In `Dma::tick` (dma.rs:488-497), when `ready` evaluates true for channel `i`, set `self.channels[i].dreq_observed_mask |= 1u64 << treq`. For `DREQ_FORCE` (63), set bit 63. Set **before** `issue_transfer` so DREQ observation persists even if arbitration later picks a different channel.

Visibility bump: `crates/mdrp2040/src/bus/mod.rs:267` — `pub(crate) dma: Dma` → `pub dma: Dma`, matching the precedents `pub gpio_in: u32` at bus/mod.rs:184 and `pub pio: [PioBlock; 2]` at bus/mod.rs:233.

Harness scrape: for each channel, end-state via `emu.bus.read32(DMA_BASE + ch*0x40 + offset)` (CTRL splices live BUSY — fine); history via `emu.bus.dma.channel(i)`.

## 6. Risks & open questions

- **Sticky-mask evasion via ctrl-only writes.** Addressed — `mark_if_pio1_txf(new)` runs on all four write-addr match arms including AL2 SET / AL3 CLR paths.
- **INCR_WRITE drift.** Initial write sets sticky bit; `transfers_issued` + final WRITE_ADDR disambiguate.
- **Channel re-programmed.** Sticky mask + trigger counters + `transfers_issued` survive; per-channel line flags "end-state WADDR not TXF but sticky set".
- **MULTI_CHAN_TRIGGER with `EN=0`.** `trig_multi` still increments — intentional (captures firmware intent).
- **DREQ timing false-positive.** `dreq_observed_mask` only records ticks where *this channel* was `ready`. A transient DREQ pulse on an un-armed channel won't be attributed — correct.
- **Performance.** ~3.7 M DMA ticks × one `u64 |=` and one `u64 +=` — sub-percent cost.

## 7. Acceptance

1. `cargo build -p mdrp2040` clean — no dead-code or unused-field warnings.
2. `cargo test -p mdrp2040 dma::tests` — all existing tests pass.
3. `cargo build -p mdpicoem-harness --bin picogus_diff_rp2040` clean — `pub dma` compiles at the use site.
4. Running `picogus_diff_rp2040 --trace monkey_island_theme.trace` prints a `--- Diag: DMA dispatch ---` block between the PIO1 pad-state block and the PIO/NVIC block.
5. **Strict verdict rule.** If any channel has `CTRL.EN=1` and a non-zero trigger counter and `transfers_issued == 0`:
   - If `(dreq_observed_mask >> ch.treq_sel()) & 1 == 0` → verdict MUST read **"TREQ never asserted — check firmware CTRL.TREQ_SEL=<N> or emulator DREQ plumbing for TREQ <N>"** naming the specific value.
   - If that bit IS set → verdict MUST read **"DREQ seen but engine did not serve — likely emulator engine gap"**.
   - The generic "ENGINE NEVER SERVED" label is reserved only for the (not-applicable-here) case where DREQ observation is unimplemented; since it IS implemented (dma.rs:481-497), that label must never fire, and the harness emits no disclaimer.
6. If `dma.rs`'s PSRAM-non-zero and PIO1-SM0-autopush counts are both 0, the verdict MUST NOT be "FULL DISPATCH OK".
7. No edits to `mdrp2350`, `sio`, `maybe_wake_core1`. `git diff --stat` shows exactly two `mdrp2040` files + one harness file.
