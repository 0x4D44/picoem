# QEMU Differential Test Harness — Low-Level Design

Version: 1.1.0
Date: 2026-04-13
Parent: HLD Section 10.3 (Oracle Layer 2)

## 1. Purpose

Validate Thumb-2 instruction semantics by executing identical instructions in
both QEMU (Cortex-M33 model) and our mdrp2354 emulator, then diffing register
state. This is Oracle Layer 2 — it validates **correctness** (right results,
right flags) but NOT cycle counts (that's Layer 3, probe-rs).

QEMU is not infallible. It is a second implementation to catch our bugs, not
ground truth. When they disagree, we triage (Section 10).

### Scope

Phase A (build first): Thumb-16 instructions only — the same ~52 opcodes our
62 hand-written tests cover, but with broader value-space coverage. All 16-bit
encodings, `TestCase.opcode` is `u16`.

Phase B (later): Thumb-32 instructions (including BL), as they are implemented
in the emulator. Requires adding `wide: Option<u16>` to TestCase and
`execute_one_wide_with_bus()` to the emulator.

### What This Does NOT Validate

- Cycle counts (QEMU doesn't model M33 pipeline timing)
- Bus arbitration or memory access timing
- Exception entry/return (requires multi-step sequences)
- IT blocks (requires emulator ITSTATE support)

## 2. Architecture

```
 ┌───────────────────────┐       ┌───────────────────────┐
 │   QEMU MPS2-AN505     │       │   mdrp2354 emulator   │
 │   GDB server :3333    │       │   (in-process)        │
 └───────────┬────────────┘       └───────────┬────────────┘
             │ TCP (P/p/m/M/s)                │ fn call
             └───────────┬────────────────────┘
                  ┌──────▼──────┐
                  │ qemu_diff   │
                  │ binary      │
                  └─────────────┘
```

No assembler toolchain at runtime. Both sides are fed raw opcode bytes — QEMU
via GDB memory-write packets, our emulator via `execute_one()`.

## 3. QEMU Setup

### 3.1. Launch

```
qemu-system-arm -machine mps2-an505 -cpu cortex-m33 -nographic -S -gdb tcp::3333
```

- `-S` halts at reset. We set up state via GDB before stepping.
- No `-kernel` needed. We write instructions directly to SRAM via GDB.

### 3.2. Memory Map (MPS2-AN505)

| Region       | Address      | Size  | Our use                    |
|--------------|-------------|-------|----------------------------|
| ssram-0      | 0x00000000  | 4 MB  | TEST_SLOT, TEST_SCRATCH    |
| Secure alias | 0x10000000  | 4 MB  | Vector table (init-svtor)  |

We write a minimal vector table to 0x10000000 once at startup (SP + reset
vector), then execute tests from ssram-0 directly.

### 3.3. Test Slot Addresses

```
QEMU_TEST_SLOT    = 0x00000100   # Instructions go here
QEMU_TEST_STACK   = 0x00040000   # SP for push/pop/load/store tests
QEMU_TEST_SCRATCH = 0x00000200   # Scratch SRAM for load/store data
```

For our emulator:
```
EMU_TEST_SLOT     = 0x20000100   # In our SRAM address space
EMU_TEST_STACK    = 0x20040000
EMU_TEST_SCRATCH  = 0x20000200
```

### 3.4. Process Lifecycle

```rust
struct QemuProcess {
    child: std::process::Child,
}

impl Drop for QemuProcess {
    fn drop(&mut self) {
        let _ = self.child.kill();
        let _ = self.child.wait();
    }
}
```

One QEMU instance per test run. The `Drop` guard ensures cleanup even on panic.
On Windows, `Child::kill()` calls `TerminateProcess`.

## 4. GDB RSP Client

### 4.1. Module: `gdb_client.rs`

Minimal GDB RSP client. ~200 lines. Implements 5 packet types.

```rust
pub struct GdbClient {
    stream: TcpStream,
    buf: Vec<u8>,
}

impl GdbClient {
    /// Connect with retry. Sets TCP_NODELAY (critical on Windows).
    pub fn connect(addr: &str, timeout: Duration) -> Result<Self>;

    /// Query halt reason (`?` packet). Verify QEMU is stopped.
    pub fn handshake(&mut self) -> Result<()>;

    /// Read one register (`p` packet). Returns 32-bit value.
    pub fn read_reg(&mut self, index: u8) -> Result<u32>;

    /// Write one register (`P` packet).
    pub fn write_reg(&mut self, index: u8, value: u32) -> Result<()>;

    /// Read memory (`m` packet).
    pub fn read_mem(&mut self, addr: u32, len: usize) -> Result<Vec<u8>>;

    /// Write memory (`M` packet).
    pub fn write_mem(&mut self, addr: u32, data: &[u8]) -> Result<()>;

    /// Single-step (`s` packet). Blocks until QEMU stops.
    pub fn step(&mut self) -> Result<()>;
}
```

No `g`/`G` (read/write all registers) packets. QEMU's M-profile target has a
legacy FPA register gap at indices 16-24 that makes `g`/`G` packet layout
complex and version-sensitive. Per-register `p`/`P` packets are simpler and
correct. At 17 registers per test, the overhead is ~1.7ms — acceptable.

### 4.2. Packet Framing

```
Send: $payload#XX   (XX = sum(payload bytes) % 256, 2-digit hex)
Recv: +              (ACK)
Recv: $response#XX
Send: +              (ACK)
```

### 4.3. Register Indices

Hardcoded constants. These have been stable across QEMU versions for 5+ years:

```rust
const REG_R0: u8  = 0;   // R0-R12 are indices 0-12
const REG_SP: u8  = 13;
const REG_LR: u8  = 14;
const REG_PC: u8  = 15;
const REG_XPSR: u8 = 25; // Indices 16-24 are legacy FPA (unused)
```

### 4.4. Startup Sanity Check

After connecting, read xPSR to verify register indices are correct:

```rust
fn sanity_check(gdb: &mut GdbClient) -> Result<()> {
    let xpsr = gdb.read_reg(REG_XPSR)?;
    // QEMU's M33 starts with T bit set (Thumb mode)
    assert!(xpsr & 0x0100_0000 != 0, "xPSR T bit not set — register \
        index {REG_XPSR} may be wrong. Check QEMU version.");
    Ok(())
}
```

This catches register-index mismatches immediately if QEMU changes its layout.

### 4.5. QEMU Version

Minimum: **QEMU >= 7.0** (MPS2-AN505 with stable M-profile GDB target).
Document actual tested version in a comment. On Windows, install via MSYS2
(`pacman -S mingw-w64-x86_64-qemu`) or the QEMU installer from qemu.org.

If QEMU ever changes these, every test will fail immediately and the fix is
changing these constants. No XML parsing needed.

**Constraint:** xPSR bits [8:0] (IPSR) are read-only via GDB. We cannot inject
exception state — only compare flags (bits [31:27]).

## 5. Emulator Side

No wrapper struct. The test runner uses `CortexM33` and `Bus` directly.

A single `Bus` is allocated once and reused across bus-tests (avoids 552KB
heap allocation per test — `Bus::new()` allocates 32KB ROM + 520KB SRAM).
For non-bus tests, skip the bus entirely.

```rust
// Allocated once, reused across tests
let mut shared_bus = Bus::new();

// Per-test setup
let mut core = CortexM33::new();
for &(reg, val) in &tc.reg_pre {
    let val = setup_reg(reg, val, tc, EMU_TEST_SCRATCH);
    core.set_reg(reg as usize, val);
}
core.regs.xpsr = tc.xpsr_pre;
core.regs.set_pc(EMU_TEST_SLOT);

// Execute
if tc.needs_bus {
    // Zero scratch region, write preconditions
    for i in 0..256 { shared_bus.write8(EMU_TEST_SCRATCH + i, 0); }
    for &(offset, val) in &tc.mem_pre {
        shared_bus.write8(EMU_TEST_SCRATCH + offset, val);
    }
    core.execute_one_with_bus(tc.opcode, &mut shared_bus);
} else {
    core.execute_one(tc.opcode);
};

// Read back: core.reg(n), core.regs.xpsr, shared_bus.read8(addr)
```

### 5.1. Execution Methods

| Width | No memory | With memory |
|-------|-----------|-------------|
| 16-bit | `execute_one(opcode)` | `execute_one_with_bus(opcode, &mut bus)` |
| 32-bit | `execute_one_wide(hw0, hw1)` | **Does not exist yet** |

**Prerequisite for Phase B:** Add `execute_one_wide_with_bus(hw0, hw1, &mut bus)`
to `CortexM33`. Trivial — same pattern as `execute_one_with_bus` but advances
PC by 4 and calls `execute_thumb32`.

Phase A (Thumb-16 only) is unaffected.

### 5.2. PC Semantics

`execute_one()` sets `regs.r[15] = current_pc + 2` before dispatching.
`read_pc()` returns `current_instr_addr + 4` (ARM Thumb convention).
Instructions that read R15 as a source operand use `read_pc()`, not
`regs.r[15]` — verified in the codebase.

## 6. Test Case Model

```rust
struct TestCase {
    /// Human-readable name (e.g., "ADDS R0, R1, R2 (overflow)")
    name: String,

    /// Instruction opcode (16-bit for Phase A).
    opcode: u16,

    /// Register preconditions: (index, value). Unset registers default to 0.
    reg_pre: Vec<(u8, u32)>,

    /// xPSR precondition. Default: 0x01000000 (T bit set, flags clear).
    xpsr_pre: u32,

    /// Whether this instruction accesses memory (use execute_one_with_bus).
    needs_bus: bool,

    /// Registers whose values are addresses (offsets from scratch base).
    /// The runner translates these by adding the per-side TEST_SCRATCH base.
    /// Non-listed registers are treated as literal values.
    addr_regs: Vec<u8>,

    /// Memory preconditions as offsets from scratch area.
    /// Written to QEMU_TEST_SCRATCH+offset and EMU_TEST_SCRATCH+offset.
    mem_pre: Vec<(u32, u8)>,

    /// Memory offsets to compare after execution.
    mem_check: Vec<u32>,

    /// xPSR flag mask for comparison. Default: MASK_ALL_FLAGS.
    xpsr_mask: u32,
}
```

### 6.1. xPSR Comparison Masks

```rust
/// N, Z, C, V, Q — all condition flags.
const MASK_ALL_FLAGS: u32 = 0xF800_0000;

/// N, Z only — for MUL where C and V are UNPREDICTABLE.
const MASK_NZ_ONLY: u32 = 0xC000_0000;

/// No flags — for MOV/ADD (high register) which don't update flags.
const MASK_NO_FLAGS: u32 = 0x0000_0000;
```

### 6.2. Default Preconditions

| Register | Default    | Rationale                       |
|----------|------------|---------------------------------|
| R0-R12   | 0          | Clean slate                     |
| SP       | TEST_STACK | Valid stack for push/pop        |
| LR       | 0xFFFFFFFF | Distinguishable sentinel        |
| PC       | TEST_SLOT  | (set per side)                  |
| xPSR     | 0x01000000 | T bit set, flags clear          |

### 6.3. Memory Addressing

Memory preconditions use **offsets from the scratch area**, not absolute
addresses. The test runner translates to each side's address space:

```rust
// QEMU side
for &(offset, val) in &tc.mem_pre {
    gdb.write_mem(QEMU_TEST_SCRATCH + offset, &[val]);
}

// Emulator side
for &(offset, val) in &tc.mem_pre {
    bus.write8(EMU_TEST_SCRATCH + offset, val);
}
```

For register preconditions that contain addresses (e.g., base register for
LDR), the test generator sets them relative to the scratch area:

```rust
// LDR R0, [R1, #4]: set R1 to scratch base
reg_pre: vec![(1, 0)],  // R1 = 0, translated to TEST_SCRATCH per side
```

The runner adds the appropriate TEST_SCRATCH base when setting up each side.

## 7. Test Generation

### 7.1. Strategy: Targeted Edge Cases

One strategy for Phase A: hand-selected edge cases per instruction. No
exhaustive register permutation (8x8x8 = 512 tests that all exercise the same
ALU path is waste). Instead:

- **2-3 register triples** per instruction to verify field extraction
- **~10 value-space edge cases** per instruction (zero, MAX, MIN, carry
  boundary, overflow boundary, sign extension, alternating bits)
- **Total: ~30 tests per instruction class, ~500 total for Thumb-16**

This catches the bugs that matter (wrong field extraction, wrong flag logic)
without drowning in redundant permutations.

### 7.2. Generator Structure

One generator function per instruction class, all in `lib.rs`:

```rust
fn gen_shift_imm() -> Vec<TestCase> { ... }
fn gen_add_sub_reg() -> Vec<TestCase> { ... }
fn gen_mov_cmp_imm8() -> Vec<TestCase> { ... }
fn gen_data_proc_reg() -> Vec<TestCase> { ... }
fn gen_special_data_bx() -> Vec<TestCase> { ... }
fn gen_load_store_reg() -> Vec<TestCase> { ... }
fn gen_load_store_imm() -> Vec<TestCase> { ... }
fn gen_load_store_sp() -> Vec<TestCase> { ... }
fn gen_adr_add_sp() -> Vec<TestCase> { ... }
fn gen_misc() -> Vec<TestCase> { ... }
fn gen_push_pop() -> Vec<TestCase> { ... }
fn gen_stm_ldm() -> Vec<TestCase> { ... }
fn gen_branch_cond() -> Vec<TestCase> { ... }
fn gen_branch_uncond() -> Vec<TestCase> { ... }
// gen_bl() -- Phase B (32-bit instruction, needs TestCase.wide field)

fn generate_all() -> Vec<TestCase> {
    let mut all = Vec::new();
    all.extend(gen_shift_imm());
    all.extend(gen_add_sub_reg());
    // ... etc — all Thumb-16 generators
    all
}
```

Generators for unimplemented instructions are simply commented out. No enum,
no capability registry, no indirection.

### 7.3. Overlapping Registers

When rd == rn or rd == rm, duplicate entries in `reg_pre` cause last-write-wins.
Generators must handle this:

```rust
// For ADDS Rd, Rn, Rm where Rn == Rm:
if rn == rm {
    reg_pre = vec![(rn, val)];  // single write, both operands get same value
}
```

### 7.4. Encoding Verification

The harness has a blind spot: if the test generator encodes the wrong
instruction, both QEMU and our emulator execute the same wrong thing, and the
test passes vacuously.

Mitigation: a `--verify-encodings` mode that shells out to `arm-none-eabi-objdump`
for a sample of generated opcodes and confirms the disassembly matches the
test name. Not run every time — just a periodic sanity check.

### 7.5. Excluded Instructions

| Instruction | Why excluded | When to add |
|-------------|-------------|-------------|
| WFI/WFE     | QEMU halts; GDB step may hang | After exception support |
| SVC/BKPT    | Triggers exception/halt | After exception support |
| UDF         | QEMU faults; our emulator NOPs | After exception support |
| IT          | Multi-instruction; needs ITSTATE | After emulator IT support |
| DMB/DSB/ISB | NOP in both; vacuous pass | Low priority |

## 8. Comparison

### 8.1. Register Comparison

Compare R0-R12 (absolute values), SP (absolute), LR as relative delta from
test slot (for BL which writes return address).

### 8.2. PC Comparison

QEMU and our emulator use different address spaces. Compare PC as relative
delta from each side's test slot:

```rust
let qemu_delta = qemu_pc.wrapping_sub(QEMU_TEST_SLOT);
let emu_delta = emu_pc.wrapping_sub(EMU_TEST_SLOT);
assert_eq!(qemu_delta, emu_delta);
```

### 8.3. Flag Comparison

Compare `(xpsr & tc.xpsr_mask)` between both sides. The mask excludes
UNPREDICTABLE flag bits and IPSR (always excluded).

### 8.4. Memory Comparison

Compare bytes at `mem_check` offsets from each side's scratch area.

## 9. Test Runner

### 9.1. Binary: `crates/mdrp2354-test-harness/src/bin/qemu_diff.rs`

```rust
fn main() -> Result<()> {
    // 1. Check qemu-system-arm is on PATH
    // 2. Spawn QEMU, connect GDB
    // 3. Write vector table to 0x10000000
    // 4. Generate test cases
    // 5. Run each test
    // 6. Print results, exit with code

    let qemu = QemuProcess::spawn()?;
    let mut gdb = GdbClient::connect("localhost:3333", Duration::from_secs(5))?;
    gdb.handshake()?;
    sanity_check(&mut gdb)?;  // Verify register indices
    setup_vector_table(&mut gdb)?;

    let tests = generate_all();
    let mut shared_bus = Bus::new();  // reused across bus-tests
    let mut pass = 0;
    let mut fail = 0;

    for tc in &tests {
        match run_one(&mut gdb, &mut shared_bus, tc) {
            Ok(()) => pass += 1,
            Err(diff) => {
                fail += 1;
                eprintln!("[FAIL] {}: {}", tc.name, diff);
            }
        }
    }

    println!("{pass}/{} passed", pass + fail);
    if fail > 0 { std::process::exit(1); }
    Ok(())
}
```

### 9.2. Single Test Flow

```rust
fn run_one(
    gdb: &mut GdbClient,
    shared_bus: &mut Bus,  // reused across tests
    tc: &TestCase,
) -> Result<(), String> {
    // ── QEMU setup ─────────────────────────────────────────
    // Write instruction + BKPT to test slot
    let bytes = tc.opcode.to_le_bytes();
    gdb.write_mem(QEMU_TEST_SLOT, &bytes)?;
    gdb.write_mem(QEMU_TEST_SLOT + 2, &0xBE00u16.to_le_bytes())?;

    // Set registers (defaults, then overrides)
    for i in 0..=12 { gdb.write_reg(i, 0)?; }
    gdb.write_reg(REG_SP, QEMU_TEST_STACK)?;
    gdb.write_reg(REG_LR, 0xFFFF_FFFF)?;
    gdb.write_reg(REG_PC, QEMU_TEST_SLOT)?;
    gdb.write_reg(REG_XPSR, tc.xpsr_pre)?;
    for &(reg, val) in &tc.reg_pre {
        let val = setup_reg(reg, val, tc, QEMU_TEST_SCRATCH);
        gdb.write_reg(reg, val)?;
    }

    // Zero scratch + write memory preconditions
    if tc.needs_bus {
        gdb.write_mem(QEMU_TEST_SCRATCH, &[0u8; 256])?;
        for &(offset, val) in &tc.mem_pre {
            gdb.write_mem(QEMU_TEST_SCRATCH + offset, &[val])?;
        }
    }

    // Step
    gdb.step()?;

    // Read QEMU post-state
    let mut qemu_regs = [0u32; 16];
    for i in 0..16 { qemu_regs[i] = gdb.read_reg(i as u8)?; }
    let qemu_xpsr = gdb.read_reg(REG_XPSR)?;

    // ── Emulator setup ─────────────────────────────────────
    let mut core = CortexM33::new();
    for i in 0..=12 { core.set_reg(i, 0); }
    core.set_reg(13, EMU_TEST_STACK);
    core.set_reg(14, 0xFFFF_FFFF);
    core.regs.set_pc(EMU_TEST_SLOT);
    core.regs.xpsr = tc.xpsr_pre;
    for &(reg, val) in &tc.reg_pre {
        let val = setup_reg(reg, val, tc, EMU_TEST_SCRATCH);
        core.set_reg(reg as usize, val);
    }

    // Execute
    if tc.needs_bus {
        // Zero scratch + write preconditions
        for i in 0..256u32 { shared_bus.write8(EMU_TEST_SCRATCH + i, 0); }
        for &(offset, val) in &tc.mem_pre {
            shared_bus.write8(EMU_TEST_SCRATCH + offset, val);
        }
        core.execute_one_with_bus(tc.opcode, shared_bus);
    } else {
        core.execute_one(tc.opcode);
    }

    // ── Compare ────────────────────────────────────────────
    let mut diffs = Vec::new();

    // Registers R0-R12 (absolute)
    for i in 0..=12 {
        if qemu_regs[i] != core.reg(i) {
            diffs.push(format!("R{i}: QEMU={:#010x} EMU={:#010x}",
                qemu_regs[i], core.reg(i)));
        }
    }

    // SP (absolute)
    if qemu_regs[13] != core.reg(13) {
        diffs.push(format!("SP: QEMU={:#010x} EMU={:#010x}",
            qemu_regs[13], core.reg(13)));
    }

    // LR (relative delta for BL, absolute otherwise)
    // ... similar comparison

    // PC (relative delta)
    let qemu_pc_delta = qemu_regs[15].wrapping_sub(QEMU_TEST_SLOT);
    let emu_pc_delta = core.reg(15).wrapping_sub(EMU_TEST_SLOT);
    if qemu_pc_delta != emu_pc_delta {
        diffs.push(format!("PC delta: QEMU={:#x} EMU={:#x}",
            qemu_pc_delta, emu_pc_delta));
    }

    // Flags (masked)
    let qemu_flags = qemu_xpsr & tc.xpsr_mask;
    let emu_flags = core.regs.xpsr & tc.xpsr_mask;
    if qemu_flags != emu_flags {
        diffs.push(format!("xPSR: QEMU={:#010x} EMU={:#010x} (mask={:#010x})",
            qemu_xpsr, core.regs.xpsr, tc.xpsr_mask));
    }

    // Memory
    for &offset in &tc.mem_check {
        let qemu_val = gdb.read_mem(QEMU_TEST_SCRATCH + offset, 1)?[0];
        let emu_val = shared_bus.read8(EMU_TEST_SCRATCH + offset);
        if qemu_val != emu_val {
            diffs.push(format!("MEM[+{offset:#x}]: QEMU={:#04x} EMU={:#04x}",
                qemu_val, emu_val));
        }
    }

    if diffs.is_empty() { Ok(()) } else { Err(diffs.join(", ")) }
}
```

### 9.3. Address Translation

Registers listed in `tc.addr_regs` contain offsets from the scratch area. The
runner translates these by adding the per-side scratch base:

```rust
fn setup_reg(reg: u8, val: u32, tc: &TestCase, scratch_base: u32) -> u32 {
    if tc.addr_regs.contains(&reg) {
        scratch_base + val
    } else {
        val
    }
}
```

Example: `LDR R0, [R1, #4]` with R1 pointing to scratch+0x10:

```rust
TestCase {
    opcode: 0x6848,           // LDR R0, [R1, #4]
    reg_pre: vec![(1, 0x10)], // R1 = scratch offset 0x10
    addr_regs: vec![1],       // R1 is an address
    needs_bus: true,
    mem_pre: vec![(0x14, 0xAB)], // scratch+0x14 = data to load
    ..
}
// Runner sets:
//   QEMU: R1 = QEMU_TEST_SCRATCH + 0x10 = 0x00000210
//   Emu:  R1 = EMU_TEST_SCRATCH  + 0x10 = 0x20000210
```

### 9.4. Error Recovery

- **QEMU timeout (5s):** Kill and respawn, skip the test.
- **GDB connection lost:** Respawn QEMU, reconnect, continue.
- **QEMU crash:** Log which test caused it, respawn, continue.

## 10. Triage Protocol

When QEMU and our emulator disagree:

1. **Verify the encoding.** Disassemble with `arm-none-eabi-objdump` to confirm
   the opcode is what we think it is.
2. **Check for UNPREDICTABLE.** If the ARM ARM says the result is UNPREDICTABLE,
   add appropriate masking and move on.
3. **Look up the ARM ARM pseudocode.** Trace through manually with the test's
   preconditions. Determine the correct answer.
4. **Fix or skip:**
   - Our emulator wrong → fix it
   - QEMU wrong → add to skip list with QEMU bug URL
   - Ambiguous → test on real hardware (Layer 3)

## 13. Implementation Notes

### 13.1. Vector Table / Test Slot Overlap

QEMU MPS2-AN505 maps 0x10000000 as a secure alias of ssram-0 at 0x00000000.
The vector table we write to 0x10000000 is physically the same memory as
0x00000000. Our test slot at 0x00000100 (offset 256) is safely past the
standard 48-entry vector table (48 * 4 = 0xC0 = 192 bytes). Do not move
TEST_SLOT below 0x100.

### 13.2. PC-Reading Instructions

Verified in the emulator code: all instructions that can encode R15 as a
source operand use `read_pc()` (returns `current_instr_addr + 4`, correct
per ARM Thumb convention), not `regs.r[15]` (which holds `current_pc + 2`).
No audit needed — this was confirmed during code review.

### 13.3. LR Comparison for BL (Phase B)

After BL, LR = return_address | 1. The return address is absolute and will
differ between sides. Compare as relative delta: `(LR & !1) - TEST_SLOT`
should match between both sides.
