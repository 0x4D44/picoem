# Phase 2: Bus Fabric — Low-Level Design

Version: 1.1.0
Date: 2026-04-13
Parent: HLD Section 5.4, Phase 2 (Section 15)

## 1. Current State

Most of Phase 2 is already implemented. The bus module has:

- **Address decode** to 15 downstream ports (ROM, XIP, SRAM0-9, FASTPERI,
  APB, SIO, PPB) via `downstream_port()`
- **SRAM banking** — `bank_for_address()` computes `(offset >> 2) & 7` for
  striped SRAM0-7, plus contiguous SRAM8-9
- **APB bridge latency** — 3-cycle read, 4-cycle write
- **Atomic aliases** — XOR/SET/CLR at +0x1000/2000/3000, +2 cycles for
  interposed APB peripherals
- **Dual-core contention** — `arbitrate_pair()` and `check_contention()`
  detect same-port access between Core 0 and Core 1, add 1-cycle stall
- **Orchestration** — `Emulator::step()` clears contention, steps Core 0,
  activates contention check, steps Core 1

50+ Phase 2 tests already pass.

**Known limitation:** The contention model tracks only **one** downstream
port per core (`core0_port`). Multi-word instructions (LDM/STM spanning
multiple SRAM banks) only record the last port accessed. Contention checks
against Core 1 only see that final port, not all ports touched. All existing
tests use single-word scenarios. Multi-access contention is deferred — it
matters for dual-core workloads but not for single-core correctness.

## 2. What Remains

### 2.1. Missing Downstream Ports

Current: 15 ports (0-14). RP2350 has 17:

| Port | Current | Needed |
|------|---------|--------|
| ROM | port 0 | OK |
| XIP_MAIN0 | port 1 | OK |
| XIP_MAIN1 | — | **Add** (second flash/PSRAM CS) |
| SRAM0-9 | ports 2-11 | OK |
| FASTPERI | port 12 | OK |
| APB | port 13 | OK |
| SIOB_PROC0 | — | **Add** (replace single SIO port) |
| SIOB_PROC1 | — | **Add** (core 1's SIO view) |

SIO is currently mapped as a single non-contending region (returns `None`
from `downstream_port()`). On real hardware, SIO appears in the crossbar as
two separate downstream ports (SIOB_PROC0 and SIOB_PROC1). Each core
accesses its own SIOB port, so inter-core SIO contention is impossible by
design. But DMA accessing SIO could contend with the core.

**Fix:** Add port IDs for XIP_MAIN1 (port 15), SIOB_PROC0 (port 16),
SIOB_PROC1 (port 17). Update `downstream_port()` to return the correct
SIOB port based on which core is accessing.

### 2.2. Bus Priority Register

Current: `arbitrate_pair()` uses fixed Core 0 wins priority. RP2350 has a
configurable `BUS_PRIORITY` register at `0x40064000` (BUSCTRL base) with
1-bit priority per master:

```
BUS_PRIORITY:
  bit 0  — PROC0 (0=low, 1=high)
  bit 4  — PROC1
  bit 8  — DMA_R
  bit 12 — DMA_W
```

When two masters have different priority levels, the higher wins. When same
level, round-robin (current loser wins next time).

**Fix:** Add `bus_priority: u32` field to Bus. Read it in `arbitrate_pair()`
to determine winner. Default 0 (all low = round-robin). The BUSCTRL register
block should be accessible at 0x40064000 (APB peripheral).

### 2.3. Intra-Core Fetch vs Data Contention

This is the key gap causing 14 cycle mismatches in probe_diff.

**The question:** Does the RP2350 crossbar see each core's I-bus and D-bus
as separate upstream ports, or are they merged?

**Evidence for merged (4 upstream masters):** The BUS_PRIORITY register has
4 entries (Proc0, Proc1, DMA_R, DMA_W), not 6. The performance counter
selectors show 4 masters.

**Evidence for separate (6 upstream):** Our hardware measurements show +1
cycle on some load/store operations where the instruction fetch and data
access could be targeting the same SRAM bank. The Cortex-M33 TRM describes
separate AHB interfaces.

**Resolution:** The M33 has two AHB interfaces internally, but the RP2350
bus fabric merges them per-processor before the crossbar. The +1 cycle on
some tests is likely the **processor-internal bus multiplexer** stalling
when both C-AHB (code) and S-AHB (system) need the bus in the same cycle.
This is internal to the M33, not the fabric.

**Approach:** Model this as a processor-internal stall, not a fabric
contention. In `CortexM33::step()`, when the instruction is a load/store
(data access in the same cycle as instruction fetch), check if both access
the same SRAM bank. If so, add 1 cycle. This is a local check in the core,
not the bus fabric.

```rust
// In CortexM33, after execute returns:
fn ibus_dbus_bank_conflict(&self, fetch_addr: u32, data_addr: u32) -> bool {
    let fetch_bank = Memory::bank_for_address(fetch_addr);
    let data_bank = Memory::bank_for_address(data_addr);
    // Both must be in striped SRAM (banks 0-7) for conflict
    fetch_bank.is_some() && fetch_bank == data_bank
}
```

This would fix the 14 outlier tests. However, we should **verify this theory
on hardware first** before implementing — run probe_diff with tests
specifically designed to trigger and avoid bank conflicts, confirming that
bank identity is the determining factor.

### 2.4. DMA Integration

The bus fabric supports DMA_R and DMA_W as upstream masters. DMA is Phase 6
in the HLD but the arbitration slots should exist now:

- DMA_R and DMA_W are separate upstream masters (can access different ports
  simultaneously)
- DMA has its own priority bits in BUS_PRIORITY
- DMA contends with processor accesses at the downstream port level

**For now:** Reserve the DMA priority slots but don't implement DMA stepping.
The arbitration logic should handle DMA when it arrives.

### 2.5. Performance Counters (Optional)

BUSCTRL has 4 performance counter registers, each selectable to count
events like `ACCESS_CONTESTED`, `STALL_UPSTREAM`, `STALL_DOWNSTREAM` for
any downstream port. These are useful for debugging but not required for
functional correctness.

**Defer.** Implement when needed for debugging bus timing issues.

## 3. Acceptance Criteria

Phase 2 is complete when:

1. `cargo test --workspace` passes (all existing Phase 2 tests + new ones)
2. `downstream_port()` returns correct port IDs for all 17 downstream ports
3. BUS_PRIORITY register is readable/writable at 0x40064000
4. Arbitration respects BUS_PRIORITY (high > low, round-robin at same level)
5. The 14 SRAM outlier cycle mismatches are either:
   (a) fixed by the bank-conflict model (if hardware verification confirms), OR
   (b) documented as measurement artifacts with evidence from targeted tests
6. No semantic regressions: `probe_diff` and `qemu_diff` still 382/382 PASS

## 4. Implementation Plan

### Stage 1: Add missing downstream ports + BUS_PRIORITY

Pure software, no hardware needed:
- Add XIP_MAIN1, SIOB_PROC0, SIOB_PROC1 to `downstream_port()`
- Add `bus_priority: u32` to Bus, map BUSCTRL at 0x40064000
- Update `arbitrate_pair()` to check priority bits
- Add round-robin state for same-priority tie-breaking
- Unit tests for all new functionality
- Run existing test suite + probe_diff to verify no regressions

### Stage 2: Hardware verification of bank-conflict theory

Targeted tests on real RP2354 via probe_diff:
- Test A: LDR where fetch PC and data address are in SAME SRAM bank
  (e.g., instruction at 0x20000100, data at 0x20000120 — both bank 0,
  since `(0x100>>2)&7 = 0` and `(0x120>>2)&7 = 0`)
- Test B: LDR where fetch and data are in DIFFERENT banks
  (e.g., instruction at 0x20000100, data at 0x20000124 — bank 0 vs bank 1)
- Test C: same instruction executed from ROM (0x00000xxx) + data in SRAM
- Measure 20 iterations of each, compare CYCCNT

If A consistently shows +1 vs B, bank conflict is confirmed → proceed to
Stage 3. If no difference, the 14 outliers are something else → document
as measurement artifacts and close Phase 2.

### Stage 3: I-bus/D-bus bank conflict model (only if Stage 2 confirms)

- Record fetch address in `decode_execute()` before dispatch
- After execute, if instruction accessed SRAM, check bank conflict
- Add 1 cycle if fetch and data hit same striped SRAM bank (0-7)
- This is in the core (M33 internal multiplexer), not the bus fabric
- Validate: `probe_diff --cycles` should resolve the 14 outliers
