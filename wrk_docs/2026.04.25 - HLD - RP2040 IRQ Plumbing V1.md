# RP2040 IRQ Plumbing — V1

Date: 2026-04-25
Status: design
Supersedes: nothing (extends `2026.04.15 - HLD - RP2040 Peripheral
Coverage V7.md` §5.2, §5.5, §6.1)

## 1. Purpose

Make `silicon_isr_diff_rp2040` PASS on the EMU side for both V1
scenarios:

- `isr_m0_timer_cold` — TIMER ALARM0 → NVIC IRQ #0 → handler.
- `isr_m0_tail_chain_pendsv_systick` — SysTick underflow + ICSR
  PENDSVSET → tail-chained PendSV + SysTick handlers.

The oracle ships ahead of silicon hookup; today it FAILs by design.
The exit criterion is "two scenarios green on EMU; FAIL surface
shrinks to genuine HW divergences when the probe attaches."

## 2. Current state — what's already there

V7 §5.2/§5.5 plumbing has landed in `crates/mdrp2040/src/`:

- `Bus::irq_pending: u32` — peripheral-asserted level/pulse bitmap
  (26 IRQ lines, `crates/mdrp2040/src/irq.rs`).
- `Bus::tick_peripherals` — per-cycle slow-path tick that folds
  TIMER alarms, UART/SPI/I2C/ADC/PWM level IRQs into `irq_pending`.
- `Emulator::drain_pending_irqs_to_cores` — drains `irq_pending`
  into both cores' per-core `Nvic::set_pending`.
- `CortexM0Plus::try_take_external_irq` — pre-instruction poll;
  picks lowest-priority-value pending+enabled IRQ, honours PRIMASK,
  doesn't preempt an active handler, dispatches via
  `enter_exception(16 + irq)`.
- `Bus::ppb` — VTOR, ICSR W1S/W1C bits, SHPR2/3 storage.

What's missing is the MMIO surface the firmware uses to *participate*
in this flow, plus the dispatch path for internal exceptions
(PendSV / SysTick) that don't go through the NVIC.

## 3. Gap analysis

| # | Gap | Today | Effect on oracle |
|---|---|---|---|
| 1 | NVIC ISER/ICER/ISPR/ICPR/IPR MMIO at `0xE000_E1xx..E4xx` | Not decoded — falls through Bus PPB region returning 0 / no-op | `MAIN_TIMER` `str` to `NVIC_ISER0` is silently dropped → IRQ #0 never enabled → `pending_and_enabled() == 0` → cold TIMER scenario hangs |
| 2 | SysTick (SYST_CSR/RVR/CVR at `0xE000_E010..0x1F`) | Not decoded; PPB `read32`/`write32` ignore the offset | Tail-chain scenario's `scenario_preamble_emu` writes are no-ops → SysTick never underflows → ICSR.PENDSTSET never asserted by HW → handler never runs |
| 3 | ICSR.PENDSVSET / PENDSTSET dispatch from step path | Bits latch in `Ppb::icsr` but no code polls them and calls `enter_exception(14/15)` | Even after firmware writes PENDSVSET via ICSR (the explicit `MAIN_TAIL` trigger), PendSV never dispatches |
| 4 | TIMER ALARM emission | Working — `poll_alarms` integrated by V7 §5.5 | None (verify with offline test, don't reimplement) |

Closing 1, 2, 3 satisfies the oracle. No other gaps surfaced during
the survey.

## 4. M33 → M0+ delta

The proven shape lives in `crates/mdrp2350/src/bus/ppb.rs`,
`crates/mdrp2350/src/peripherals/`, and `crates/mdrp2350/src/core/
exceptions.rs`. Everything below is the M0+-trimmed port. Surface to
keep visible during implementation:

- **No Secure / Non-Secure split.** ICSR / NVIC / SysTick have a
  single alias on M0+, not S/NS pair. The oracle uses
  `VTOR_ADDR = 0xE000_ED08` (singular) — keep it that way.
- **No FAULTMASK, no BASEPRI.** Priority masking is just PRIMASK.
  `try_take_external_irq` already encodes this; the new
  PendSV/SysTick dispatch (Gap 3) follows the same rule.
- **4 priority levels, not 8.** SHPR bytes only model bits [7:6]
  (already correct in `Ppb::exception_priority`). External IRQ
  priority comes from NVIC_IPR — same 2-bit-significant model.
- **No DWT CYCCNT.** The oracle's CYCCNT mailbox is a no-op on M0+
  (silicon_oracle's `enable_cyccnt`/`reset_cyccnt` tolerate read
  errors). No CYCCNT delta to chase.
- **17-entry vector table.** Oracle scenarios place TIMER_IRQ_0 at
  vector[16]; nothing for us to do — VTOR-driven walk reads from
  `mem[vtor + 4*exc_num]` already.
- **Configurable exceptions are SVCall (#11), PendSV (#14),
  SysTick (#15).** Other system exceptions (Reset, NMI, HardFault)
  have fixed priorities. The dispatch rule is the same as M33: pick
  lowest priority value among pending + (PRIMASK == 0 || prio < 0),
  tie-break by lowest exception number.

What we explicitly do **not** copy from M33:
- SAU / MPU registers.
- CPACR / FPCCR / FPCAR (no FPU on M0+; V8.5 Component 1's
  FPU-related plumbing is M33-only).
- AIRCR.PRIS / SCR.SLEEPDEEP fine-grained state.

## 5. Design

Three components, in order. Each is a small, atomic addition; none
require migrating existing call sites. No env vars, no feature flags
— land it plain.

### 5.1 Component A — NVIC MMIO surface

NVIC registers on Cortex-M0+ live at:

| Register | Address | Purpose |
|---|---|---|
| `NVIC_ISER0` | `0xE000_E100` | W1S enable bits, IRQs 0..31 |
| `NVIC_ICER0` | `0xE000_E180` | W1C enable bits |
| `NVIC_ISPR0` | `0xE000_E200` | W1S pending bits |
| `NVIC_ICPR0` | `0xE000_E300` | W1C pending bits |
| `NVIC_IPR0..7` | `0xE000_E400..0xE000_E41C` | 4 IRQs per word, top 2 bits significant |

RP2040 has 26 IRQs so all bits live in the single `0` register
group; bits 26..31 are RAZ/WI.

**Where it lives.** `Ppb::read32`/`write32`. Add four `match`
arms keyed on `addr & 0xFFFF`:

```rust
0xE100 => /* ISER0 — W1S into per-core Nvic.enabled */,
0xE180 => /* ICER0 — W1C */,
0xE200 => /* ISPR0 — W1S into per-core Nvic.pending */,
0xE300 => /* ICPR0 — W1C */,
0xE400..=0xE41F => /* IPR0..7 — per-IRQ priority byte, top 2 bits */,
```

**Per-core question.** M0+ NVIC state is per-CPU but the PPB is
shared across both cores (a Bus-level singleton). The currently-
executing core writes ISER → that core's enable bits should mutate.
Pattern: pass the active core index (already tracked via
`Bus::active_core()` for the SIO sibling-FIFO case) into the PPB
write path, the same way `peripheral_dispatch` does.

`Ppb::write32` becomes `Ppb::write32(addr, val, active_core,
nvics: &mut [Nvic; 2])`. Read path takes the same shape. Concrete
signature change is mechanical — every existing call site in
`bus/peripheral_dispatch.rs` already has access to `self.cores`'s
NVICs via a sibling field; we expose them by reference at the
call site.

(Per the V7 ownership rule in §5.1, all of this is direct
field access on `Bus`; no accessor methods that take `&mut self`.)

**Read semantics.** ISER/ICER read returns enabled-mask;
ISPR/ICPR read returns pending-mask; IPR returns the priority
bytes. Standard ARMv6-M.

**Behaviour outside the active write path.** For the cold-IRQ
scenario, only one core is awake (oracle halts core 1). Write goes
to `nvics[active_core]`. The non-active core's NVIC state is
untouched. This matches silicon — NVIC writes affect only the
issuing CPU.

**Tests** (in `bus/ppb.rs` `mod tests`):

- `nvic_iser_w1s_then_iser_read_roundtrip`.
- `nvic_iser_then_icer_clears`.
- `nvic_ispr_w1s_then_drain_dispatches` (integration: write ISPR0,
  call `try_take_external_irq`, observe PC at vector entry).
- `nvic_ipr_top_two_bits_significant` (write 0xC5, read 0xC0).

### 5.2 Component B — SysTick model

Five registers at `0xE000_E010..0xE000_E01F`:

| Offset | Name | Purpose |
|---|---|---|
| 0x10 | `SYST_CSR` | ENABLE (bit 0), TICKINT (1), CLKSOURCE (2), COUNTFLAG (16, RC) |
| 0x14 | `SYST_RVR` | 24-bit reload value |
| 0x18 | `SYST_CVR` | 24-bit current value (any write zeroes; reads decremented value) |
| 0x1C | `SYST_CALIB` | RAZ stub — RP2040 doesn't expose a meaningful calibration |

CLKSOURCE is per-core on M0+ (each core has its own SysTick) — same
ownership pattern as the NVIC: per-core state on the cores, MMIO
dispatch via `active_core`.

**Where it lives.** New struct `SysTick` in `core/systick.rs`,
owned per-core (one instance on each `CortexM0Plus`). PPB MMIO
delegates via `&mut cores[active_core].systick`.

```rust
pub struct SysTick {
    pub csr: u32,    // bits we care about: ENABLE, TICKINT, COUNTFLAG
    pub rvr: u32,    // 24-bit
    pub cvr: u32,    // 24-bit
}
```

**Tick.** Decrement once per `tick_peripherals` cycle when
`csr.ENABLE`. On underflow:
1. Reload `cvr = rvr` (next tick decrements from there).
2. Set `csr.COUNTFLAG`.
3. If `csr.TICKINT`, set ICSR.PENDSTSET (path via the same Bus PPB
   that `Ppb::write32(0xED04, 1<<26)` already supports — call into
   `bus.ppb.set_pendst()`).

**Sequencing.** SysTick belongs in the per-cycle slow-path loop in
`Emulator::step`. Add it adjacent to `tick_peripherals` (same
inner-loop iteration). It's a CPU-side counter, not a peripheral;
keep the call out of `tick_peripherals` so `Bus::all_peripherals_idle`
stays accurate.

**Idle gate.** `core.systick.is_active() = csr.ENABLE != 0`. Add to
the fast-path gate predicate alongside `pio_idle && peri_idle &&
dma_idle && !any_irq`. SysTick mid-countdown forces the slow path.
Most paced workloads don't enable SysTick, so the gate stays cheap
in steady state.

**Tests** (in `core/systick.rs` `mod tests`):

- `enable_then_underflow_sets_countflag_and_pendst`.
- `disable_during_countdown_freezes_cvr`.
- `cvr_write_clears_to_zero_and_clears_countflag` (architectural
  quirk).
- `read_cvr_returns_current_value` (post-decrement).

### 5.3 Component C — ICSR PendSV/SysTick dispatch

`try_take_external_irq` only handles IRQs ≥ 16. Internal
exceptions #14 (PendSV) and #15 (SysTick) live in ICSR sticky bits
and need their own dispatch poll.

**Add a sibling helper** to `CortexM0Plus`:

```rust
fn try_take_pendsv_systick<B: CoreBus>(&mut self, bus: &mut B) -> u32 {
    if self.regs.primask & 1 != 0 { return 0; }
    if bus.ppb_active() { return 0; }   // no preemption (M0+)

    let icsr = bus.read_icsr();
    let pendsv  = icsr & (1 << 28) != 0;
    let pendst  = icsr & (1 << 26) != 0;
    if !pendsv && !pendst { return 0; }

    // Pick lowest priority value; tie-break by lower exception
    // number (PendSV = 14 wins ties over SysTick = 15).
    let prio_pendsv = bus.shpr_priority(14);
    let prio_pendst = bus.shpr_priority(15);
    let (exc, prio) = match (pendsv, pendst) {
        (true, false) => (14u16, prio_pendsv),
        (false, true) => (15u16, prio_pendst),
        (true, true)  => if prio_pendsv <= prio_pendst { (14, prio_pendsv) }
                         else { (15, prio_pendst) },
        _ => unreachable!(),
    };

    // Clear the dispatched bit; the other stays sticky for tail-chain.
    bus.clear_icsr_pend(exc);
    self.enter_exception(exc, bus)
}
```

**Call ordering in `step`.** `try_take_external_irq` runs first
(NVIC IRQs ≥16 typically configure to higher priority than PendSV
in pico-sdk). If it dispatches, return. Otherwise call
`try_take_pendsv_systick`. If that dispatches, return. Otherwise
fetch+execute.

**Tail-chain behaviour.** PendSV and SysTick both sticky-set in
ICSR; when the first handler returns via EXC_RETURN,
`exit_exception` checks for any pending exception including ICSR
sticky bits. If one survives, tail-chain into it without unwinding
the stack frame. mdrp2350's `exit_exception` already does this for
M33 (search for `try_take_any_pending_exception` at
`crates/mdrp2350/src/core/exceptions.rs:422`). Port the same idiom
into `mdrp2040/src/core/exceptions.rs::exit_exception`: after the
EXC_RETURN unstack-validation, poll
`(try_take_external_irq | try_take_pendsv_systick)` once before
returning to thread mode; on dispatch, skip the unstack.

(M33 has lazy-FP entanglement that makes its tail-chain logic
heavier; the M0+ port is strictly simpler — same priority rule,
no FP context.)

**Tests** (in `core/exceptions.rs` `mod tests`):

- `pendsv_dispatches_when_pending_and_primask_clear`.
- `pendsv_blocked_by_primask`.
- `pendsv_blocked_by_active_handler` (no preemption — M0+ rule).
- `pendsv_systick_tail_chain_skips_unstack` (the load-bearing
  oracle scenario, mirrored as a unit test).
- `pendsv_priority_above_systick_when_equal` (tie-break rule).

## 6. Validation strategy

Three test surfaces, in order of execution speed:

### 6.1 Unit tests (per-component, listed §5)

Run on every `cargo test -p mdrp2040`. Implementer writes them
test-first; the oracle scenarios are the integration test, not
the unit test. Total: ~12 new tests, all in-crate.

### 6.2 Dual-model parity (`crates/mdrp2040/tests/dual_model.rs`)

Add one new dual-model case: a TIMER_IRQ_0 scenario that runs in
both Serial and Threaded, asserts identical end state (PC, MSP,
counter cell, TIMER.INTR). Catches the threaded `irq_pending` drain
path silently diverging from serial.

(The threaded runtime's IRQ drain happens at the barrier-sync
boundary, not per-cycle; the parity test is the existence proof
that the boundary placement doesn't lose IRQs.)

### 6.3 `silicon_isr_diff_rp2040` — exit criterion

Local invocation (no hardware) exercises the EMU side only — the
runner reads HW observables via probe-rs and produces a final
verdict, but we run it without a probe to flush the EMU pipeline:

```bash
# Force EMU-side dry run by stubbing the HW path.
cargo test -p mdpicoem-harness --test isr_scenarios_rp2040_emu \
  -- isr_m0_timer_cold isr_m0_tail_chain_pendsv_systick
```

A new (small) integration test file `crates/mdpicoem-harness/tests/
isr_scenarios_rp2040_emu.rs` runs each scenario's EMU half (image
upload, init regs, preamble, run for `max_millis*cycles_per_ms`,
read observables), without touching probe-rs. Asserts:

- `ctr_timer == 1` and `TIMER.INTR & 1 == 0` for cold.
- `ctr_pendsv == 1` and `ctr_systick == 1` for tail-chain.

This is the exit criterion. When both pass, the offline portion is
done. Silicon hookup follows on the next probe session.

## 7. Out of scope (V7 phasing)

- UART / SPI / I2C / ADC / PWM IRQ wiring — already plumbed via
  `tick_peripherals`, but no oracle scenario covers them in V1.
  V7 Phases 2–3.
- DMA IRQ_0 / IRQ_1 routing through `Bus::irq_pending`. V7 Phase 4.
- PIO IRQ routing (`pio[i].pending_irqs() → bus.irq_pending`). V7
  Phase 1 mentions it but no oracle scenario exercises it yet; will
  surface when a PIO ISR scenario is added.
- DWT CYCCNT modelling. M0+ silicon doesn't implement DWT in a
  uniform way; we follow the oracle's stance of treating CYCCNT as
  unobserved on M0+.
- Lazy-scheduled SysTick (advance many cycles at once when SysTick
  is the only thing forcing slow path). Not needed for V1 — paced
  workloads either run with SysTick enabled (slow path is correct)
  or disabled (fast path applies). Revisit if bench shows ≥5%
  regression from SysTick-enabled workloads.

## 8. Phasing

Single offline session. Three components in order so the unit
tests for B and C can ride on A's NVIC primitives.

| Step | Content | Exit |
|---|---|---|
| A | NVIC MMIO (ISER/ICER/ISPR/ICPR/IPR) on PPB; per-core dispatch via `active_core`; unit tests. | `cargo test -p mdrp2040` green; new tests in §5.1 pass. |
| B | SysTick struct + per-core ownership + tick in slow path + idle-gate participation; unit tests. | Step A still green; new tests in §5.2 pass. |
| C | `try_take_pendsv_systick` + `exit_exception` tail-chain poll; unit tests. | Steps A+B green; new tests in §5.3 pass. |
| Final | Dual-model parity case + scenario integration test (§6.2, §6.3). | `silicon_isr_diff_rp2040` EMU-side passes both V1 scenarios. |

## 9. Risks and open questions

**9.1 Per-core PPB writes.** The active-core dispatch pattern
exists for SIO; extending it to ICSR/NVIC/SysTick is mechanical but
touches every call site of `Ppb::read32`/`write32`. Risk: signature
churn collides with concurrent agent work on the bus dispatch
table. Mitigation: land Component A as one atomic commit;
implementer scopes the diff to PPB + call sites only.

**9.2 ICSR sticky semantics on tail-chain.** When PendSV dispatches,
its bit clears in ICSR; SysTick's bit stays set, so the EXC_RETURN
poll picks it up and tail-chains. Need to verify
`exit_exception`'s post-unstack poll happens *after* the EXC_RETURN
validation but *before* writing `xpsr` from the popped frame —
otherwise the IPSR comes from the unstacked thread-mode value, not
the new exception. The mdrp2350 reference at
`crates/mdrp2350/src/core/exceptions.rs:422` shows the right
ordering; copy faithfully.

**9.3 Cold TIMER timing on EMU.** `MAIN_TIMER` writes ALARM0=0x10
(16 µs), then enables INTE, then enables NVIC IRQ. If `tick_peripherals`
fires the alarm *before* `NVIC_ISER0` writes complete, the IRQ
enables onto an already-pending line — fine, dispatches next cycle.
If it fires *after*, also fine — dispatches when condition is met.
There's no race because the test runs at ROSC ~6.5 MHz and the main
sequence is < 8 instructions. Verify by including a pre-step
ordering test in §5.1.

**9.4 max_millis budget on EMU.** The oracle's `max_millis = 1500`
maps to ~9.7M cycles at default ROSC. If the slow-path tick adds
non-trivial overhead per cycle, EMU may run out of budget before
the alarm fires (16 µs deadline + 1500 ms budget ≈ 100,000× margin
— headroom is enormous, not actually a risk, but measure once after
B lands).
