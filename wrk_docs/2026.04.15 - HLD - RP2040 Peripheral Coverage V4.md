# RP2040 Peripheral Coverage — HLD V4

Supersedes V3. Incorporates Round-3 team review of 2026-04-15. Net change: tightening + concrete fixes to a small number of fiction passages in V3.

## 1. Purpose

Add emulation for RP2040 peripherals the motivating firmware corpus (§3) touches, so `mdrp2040` runs those binaries to completion instead of falling into `HashMap<u32, u32>` fallthrough.

Scope: **TIMER + WATCHDOG_TICK** (Phase 1), **UART, SPI, I2C** (Phase 2), **ADC, PWM** (Phase 3), **DMA** (Phase 4).

### Non-goals

- Full datasheet coverage. Implement the register set the corpus actually touches.
- WATCHDOG reset logic, RTC, USB, VREG, TBMAN, BUSCTRL, SYSCFG, PSM. Stay in HashMap fallthrough until a concrete firmware demands.
- Non-pico-sdk runtimes (MicroPython, Embassy, bare-metal).
- Cycle-accurate peripheral timing finer than one sys_clk.
- RP2350 mirror. Impls live in `crates/mdrp2040/`; extraction to `mdpicoem-common` when a second consumer arrives.
- Backwards compatibility or migration paths.

## 4. Oracle strategy

Hardware: physical RP2040 on the lab rig, Pico debug probe back-to-back, same topology as RP2354.

### 4.1 `probe_diff_rp2040`

Port `crates/mdpicoem-harness/src/bin/probe_diff_rp2350.rs`. Filter is probe-side only — `qemu_diff_m0plus.rs:291` stays strict (QEMU is `cortex-m0`). `probe_diff_rp2040` admits the Thumb-32 subset `BL`, `MRS`, `MSR`, `DSB`, `DMB`, `ISB`.

**Generator audit budget: 2 days.** If `crates/mdpicoem-harness/src/thumb32_gen.rs` doesn't emit the subset and writing the encoder cases exceeds 2 days, Phase 0 slips and the slip is journaled.

### 4.2 `silicon_periph_diff_rp2040`

Port `silicon_periph_diff_rp2350.rs`. Shape = RP2350's `PeriphScenario` + one u32:

```rust
pub struct PeriphScenario {
    pub name: &'static str,
    pub setup: &'static [(u32, u32)],
    pub max_sysclks: u32,
    pub min_sysclks: u32,            // NEW
    pub observe: &'static [(u32, u32)],
    pub observe_pins: u32,
    pub custom_sled: Option<&'static [u8]>,
}
```

`min_sysclks` catches "completed too fast" bugs as a soft assertion. If Phase 4 DMA ring proves insufficient, intermediate-state machinery is added **then**, not speculatively.

**Timing window is a soft assertion.** SysTick programmed at scenario start (`SYST_CSR = CLKSOURCE|ENABLE`, `SYST_RVR = 0x00FFFFFF`, `SYST_CVR = 0`). Read `CVR_start` before setup, `CVR_end` after halt. `window = CVR_start − CVR_end`. 24-bit window, no wrap for scenarios < 2^24 sys_clk. Report-only unless outside `[min_sysclks, max_sysclks]`. No framing cancellation — single-run. Cycle-accurate RP2040 timing is a separate oracle HLD if the corpus ever demands it.

### 4.3 MMIO capture — via the emulator bus

`crates/mdpicoem-harness/src/bin/mmio_trace_rp2040.rs` loads firmware into the existing emulator, flips a `Bus::trace_enabled` flag, and runs for a caller-specified cycle budget. **Hooks all six access methods (`read8/16/32` + `write8/16/32`) AND the internal peripheral dispatch paths (`peripheral_read32`, `sio_*`, `ppb.*`).** Byte/half-width accesses are traced at the widest dispatch point, not only at word boundaries, so UART_DR byte writes and status-register byte reads don't slip past.

Emits `(addr, size, R/W, core, pc)` to stdout as whitespace-separated columns. No file artefacts in the repo.

Why this works: the emulator is the tracer — no external tooling, no probe-rs memory watchpoints, no M0+ DWT dependency. Already-modelled peripherals log their hits, so we see the complete MMIO transaction stream before firmware falls into HashMap.

Limitation: the emulator has gaps. Firmware touching an unmodelled peripheral often faults or spins shortly after; the trace captures only up to that point. That truncation IS the signal — the trace's tail shows what we need to implement next.

### 4.4 Phase 0 exit criteria

1. `probe_diff_rp2040` runs `--fuzz 10000` green, including Thumb-32 subset.
2. `silicon_periph_diff_rp2040` runs a known-good SIO GPIO toggle scenario green.
3. `silicon_periph_diff_rp2040` runs **three** deliberately-broken scenarios — one per oracle class — and each prints FAIL with correct `first_divergence`:
   - GPIO: wrong `SIO_GPIO_OUT` bit.
   - TIMER: `TIMERAWL` read-path returns 0.
   - MMIO store: `XOSC_CTRL` write swallowed.
4. `mmio_trace_rp2040 --cycles 1_000_000 hello_timer.elf` emits a non-empty trace that includes reads at `TIMER_BASE + 0x28` (`TIMERAWL`) — proving firmware reaches `busy_wait_us_32` polling. TIMER is not yet implemented so `TIMERAWL` reads 0 from HashMap and the poll spins; the 1M-cycle budget caps the trace.

### 4.5 Triage (silicon ≠ emulator)

1. **Reproduce** on silicon with scenario/seed.
2. **Check probe-rs** by reading `SIO_BASE + 0x1C` (`GPIO_OUT_XOR`) — SIO is not RESETS-gated, reset value is 0. If probe-rs reads non-zero, probe-rs is suspect.
3. **Check silicon health** via `probe_verify_rp2040` — round-trip a known-correct-in-emulator register (SIO mirror). Silicon disagreeing with itself = board issue.
4. Only after (2) and (3) clear: assume emulator bug.

Divergences recorded in `wrk_journals/` with verdict + seed.

## 5. Architecture

### 5.1 Peripheral pattern — inherent methods, no trait

Delete `mdpicoem-common::Peripheral` (unused). Each peripheral is a struct in `crates/mdrp2040/src/peripherals/<name>.rs` with inherent methods:

```rust
pub struct TimerRegs { /* fields */ }

impl TimerRegs {
    pub fn read32(&mut self, offset: u32) -> u32 { ... }
    pub fn write32(&mut self, offset: u32, value: u32, alias: u32, irqs: &mut u32) { ... }
    pub fn tick(&mut self, irqs: &mut u32) { ... }   // only if stateful
}
```

No trait. Dispatch is a match arm in `Bus`. Consistency by code review.

**Ownership.** Peripheral fields and `irq_pending` are `pub(crate)` sibling fields on `Bus`. No accessor methods that borrow `&mut self`. Dispatch is direct field access; Rust's split-borrow sees disjoint `&mut` into different fields.

### 5.2 IRQ plumbing

One `Bus` field: `pub(crate) irq_pending: u32`. 26 IRQs (datasheet §2.3.2 — Appendix B). Peripherals assert via `*irqs |= 1u32 << IRQ_TIMER_IRQ_0;` (IRQ constants are `u32` to avoid a shift-width footgun; `1u8 << N` is UB for N ≥ 8).

**Level semantics.** Peripherals re-assert each cycle the IRQ condition holds. When firmware clears the source (W1C on `INTR`, drains the FIFO, etc.), the peripheral observes the cleared state on its next read/tick and stops asserting that cycle onward. NVIC pending latching is unchanged from existing code.

**Pulse sources** (TIMER alarm match): asserted exactly once at the match cycle via lazy-scheduled events (§5.5). Level vs pulse is a peripheral-internal distinction; `irq_pending` only carries "assert now".

**Drain per inner-cycle iteration.** Inlined in `Emulator::step`:

```rust
if self.bus.irq_pending != 0 {
    let raised = std::mem::replace(&mut self.bus.irq_pending, 0);
    for irq in 0..IRQ_COUNT {
        if raised & (1u32 << irq) != 0 {
            self.cores[0].nvic.set_pending(irq as u8);
            self.cores[1].nvic.set_pending(irq as u8);
        }
    }
}
```

Threaded cores later require `AtomicU32`; not built now.

### 5.3 RESETS and clock gating

**RESETS — Bus-level guard.** Before dispatching to a peripheral, `Bus::peripheral_read32`/`peripheral_write32` check `self.resets.is_held(RESET_BIT_X)`; held-in-reset peripherals return 0 (read) or no-op (write) without reaching the peripheral module. Tick path likewise short-circuits. Peripherals never see reset-gated calls. Table of `(BASE, RESET_BIT)` pairs lives at top of `bus/peripheral_dispatch.rs`.

**Emulator reset state = post-bootrom state.** `clk_sys = 125 MHz`, `clk_peri = clk_sys`, `clk_adc = 48 MHz`, `XOSC.STATUS.STABLE = 1`, `PLL_SYS.CS.LOCK = 1`, RESETS released for the commonly-used peripherals (per pico-sdk `runtime_init_clocks` final state). Deliberate simplification: firmware loaded via `load_image` skips the bootrom, so we start clocked. Firmware that itself reprograms CLOCKS reconfigures the `ClockTree` cache as today.

| Peripheral | Clock | V1 treatment |
|---|---|---|
| TIMER | `clk_ref / WATCHDOG_TICK.CYCLES` (1 µs) | Lazy; cached fire-cycles invalidated on WATCHDOG_TICK write. `CYCLES=0` → TIMER does not advance (matches silicon; divide-by-zero guard in lazy path). |
| ADC | `clk_adc` (48 MHz default) | Fixed-point accumulator `adc_phase += ADC_HZ; if adc_phase >= SYS_HZ { adc_phase -= SYS_HZ; adc.tick(); }`. Phase zeroed on `ClockTree` recompute. u32 safe for clk_adc ≤ 4 GHz. |

Other peripherals run at `clk_sys` in V1. Scaling added when firmware reprograms clk_peri (deferred).

### 5.4 Atomic aliases and byte/halfword access

**Alias per-register.** `write32(offset, value, alias, irqs)`. Peripheral decides:

- **Plain storage register**: `apply_alias_rmw(&mut stored, value, alias)` helper in `peripherals/mod.rs`.
- **Side-effect register** (TIMER INTR W1C, UART_DR FIFO push, DMA CH_TRIGGER): register-specific. TIMER_INTR alias-BITSET maps to W1C on set bits. UART_DR alias is silicon-unspecified; emulator treats as plain write. Each peripheral module documents its table.

**Narrow-access dispatch.** Only peripherals with byte/halfword-significant registers (UART_DR, SPI_DR, I2C_IC_DATA_CMD) opt in via dedicated match arms in `Bus::read8`/`write8`/`read16`/`write16`. Other peripherals fall back to the existing word-RMW. No method proliferation across peripherals that don't need it.

### 5.5 Per-cycle tick

Generalise the PIO slow-path loop at `crates/mdrp2040/src/lib.rs:303`:

```rust
for _ in 0..consumed {
    self.bus.tick_peripherals();
    self.tick_pio_and_route_irqs();      // uses existing PioBlock::step_n
    self.bus.update_gpio();
    self.drain_pending_irqs_to_cores();
}
```

`tick_peripherals` body:

```rust
fn tick_peripherals(&mut self) {
    if !self.resets.is_held(RESET_BIT_PWM) { self.pwm.tick(&mut self.irq_pending); }
    if !self.resets.is_held(RESET_BIT_ADC) { self.adc.tick(&mut self.irq_pending); }
    // UART/SPI/I2C: each tick() opens with an is_idle() early-out.
    self.uart0.tick(&mut self.irq_pending); self.uart1.tick(&mut self.irq_pending);
    self.spi0.tick(&mut self.irq_pending);  self.spi1.tick(&mut self.irq_pending);
    self.i2c0.tick(&mut self.irq_pending);  self.i2c1.tick(&mut self.irq_pending);
    self.tick_dma();                      // §5.6
}
```

**PIO IRQ routing.** `PioBlock` (in `mdpicoem-common`) keeps its existing `step_n(n, gpio_in)` signature — no cross-chip surgery. After each per-cycle `step_n(1, ...)` call, `Emulator::tick_pio_and_route_irqs` reads each block's `irq_flags()` and ORs into `bus.irq_pending`:

```rust
fn tick_pio_and_route_irqs(&mut self) {
    self.bus.pio[0].step_n(1, self.bus.gpio_in());
    self.bus.pio[1].step_n(1, self.bus.gpio_in());
    let bits = self.bus.pio[0].pending_irqs() | (self.bus.pio[1].pending_irqs() << 4);
    self.bus.irq_pending |= map_pio_bits_to_nvic(bits);
}
```

`pending_irqs()` is a new trivial getter on `PioBlock` (one accessor; no behaviour change). NVIC mapping: PIO0_IRQ_0 = 7, PIO0_IRQ_1 = 8, PIO1_IRQ_0 = 9, PIO1_IRQ_1 = 10 (Appendix B).

Peripherals with no per-cycle state (TIMER, RTC, WATCHDOG_TICK) have no `tick` method — computed lazily from `master_cycle` on read; alarm IRQs scheduled at write-time. At steady state 0–3 peripherals have real per-tick work.

### 5.6 DMA — bus master

`Dma` is a named field on `Bus`. Tick via owned swap:

```rust
// On Bus:
pub fn tick_dma(&mut self) {
    let mut dma = std::mem::take(&mut self.dma); // Dma: Default
    dma.tick(self); // bus sans dma; DMA reads bus.irq_pending directly
    self.dma = dma;
}
```

`Dma::tick(&mut self, bus: &mut Bus)` takes a DREQ snapshot into a local (`let dreqs = bus.collect_dreqs();`) before issuing any `bus.read32`/`write32`, avoiding simultaneous `&self.uart0` and `&mut bus` borrows.

**Ordering within a cycle** (documented contract):
1. PWM, ADC, UART, SPI, I2C tick (produces DREQ).
2. PIO tick + IRQ route (produces PIO DREQ).
3. `tick_dma` — reads DREQ snapshot, issues one transfer per enabled channel.
4. `update_gpio`, then drain `irq_pending` to both NVICs.

**Write visibility.** DMA writes to peripheral registers take effect the cycle they're issued (emulator simplification; real AHB is N+1 due to address/data phases). Peripherals servicing FIFOs observe the new state on their next tick (cycle N+1). No corpus scenario distinguishes same-cycle from N+1.

### 5.6.1 DMA V1 scope

- 12 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- **`RING_SIZE` / `RING_SEL`** — address masking. `audio_i2s` requires.
- **`CHAIN_TO`** — full chained triggering. When `TRANS_COUNT` reaches 0 on a channel with `CHAIN_TO != self`, enable the target channel. `audio_i2s` uses this for the reloader-channel pattern.
- **`CH_ABORT`** — writing 1-bits clears `BUSY` immediately. pico-sdk's `dma_channel_abort` polls `BUSY`; cycle-exact semantics don't matter.
- `INTE0`/`INTE1` enable masks, `INTS0`/`INTS1` W1C, `DMA_IRQ_0`/`DMA_IRQ_1` lines.
- `HIGH_PRIORITY`: priority-1 channels arbitrate before priority-0. Within-tier = lowest-channel-wins (no round-robin). **Phase 0 `mmio_trace_rp2040` on `audio_i2s` confirms whether any channel actually sets HIGH_PRIORITY; if unused, drop this in Phase 4 and simplify to flat arbitration.**
- **Not in V1**: CRC, sniff, byte-swap, read/write error IRQs, ring across non-aligned base.

**DREQ table.** Appendix C. `crates/mdrp2040/src/dreq.rs` lands in Phase 4 only — Phases 1–3 don't reference DREQ.

### 6.1 ISR-count scenario mechanism (Phase 1)

`PeriphScenario` shape is adequate; handler installation uses `custom_sled` + `setup`:

- **`setup`** writes: vector table entries at `0x20000000` (VTOR relocation), `TIMER.ALARM0` arm value, `TIMER.INTE` enable, `NVIC.ISER[0] |= 1 << IRQ_TIMER_IRQ_0`, VTOR = 0x20000000.
- **`custom_sled`** bytes contain: handler code at offset 0 (increments `*(u32*)0x20001000`, writes 1 to `TIMER.INTR` W1C, returns); main-code code at offset 0x100 (wait-for-interrupt loop); BKPT at known offset.
- **`observe`** reads `0x20001000` — the handler counter.
- **Pattern**: setup programs the vector-table entry to point to `0x20000000 + 1` (Thumb bit set), handler lives in sled starting at byte 0; main code starts at byte 0x100; scenario runner sets PC to `0x20000100 + 1` before stepping.

No new oracle binary; `silicon_periph_diff_rp2040` handles this via the existing `custom_sled` slot. If Phase 1 proves this shape insufficient, promote to a dedicated `silicon_isr_diff_rp2040` (mirrors RP2350); not speculative work up front.

## 7. Testing

**Oracle hierarchy:**

1. **`silicon_periph_diff_rp2040`** — load-bearing. Peripheral ships scenarios sufficient to turn its corpus entry green.
2. **`probe_diff_rp2040`** — CPU-level fuzz each phase. Catches `Bus` surgery regressions.
3. **In-crate self-consistency checks** — `#[cfg(test)]` per peripheral. Not unit tests in the strong sense (bidirectional bugs pass); catch typos, protocol errors.
4. **Integration smoke** — corpus binary runs to documented completion.

**Runtime.** Single `Session::auto_attach` reused across scenarios (per `test_silicon` convention). ~1 s/scenario. ≤60 scenarios in V1 ≈ 1 min silicon run.

**Flake policy.** Retry once on probe-rs `Io` or `Session` transient errors (strictly matched by error kind). Other failures = hard fail → triage per §4.5.

## 9. Risks & open questions

### 9.1 SysTick window is soft

`[min_sysclks, max_sysclks]` catches catastrophic miscount but **cannot distinguish N vs N±1 iterations** when the window's width exceeds one iteration cost. Phase 4 DMA ring off-by-one is the canonical case; the Phase-4-entry red-path scenario (§6) is the mitigation. If that proves insufficient, intermediate-state machinery is added then.

### 9.2 Bootrom re-hit

Phase 1 TIMER + Phase 2 UART unblock firmware past `busy_wait_us_32` into bootrom paths (`flash_get_unique_id`, `_reset_to_usb_boot`, `rom_func_lookup`) that collide with the SSI stub. **This HLD does not fix SSI.** Mitigation: `load_image` bypasses bootrom. Separate HLD when motivated.

### 9.3 HashMap fallthrough wrongness

Firmware reading USB_CTRL, BUSCTRL, VREG expecting specific reset values gets 0. `mmio_trace_rp2040` surfaces these; resolution is per-firmware (promote the peripheral or stub the register's reset value). Logged in `wrk_journals/`.

### 9.4 Concurrent workspace collision on `Bus`

Land `irq_pending` + `tick_peripherals` + RESETS guard + PIO IRQ routing as a **single atomic commit** before peripheral-specific code. Minimises merge surface.

### 9.5 Probe rig failure

No fallback oracle. Rig down → phase halts. Self-consistency checks and `qemu_diff_m0plus` keep running but don't exercise peripherals. Acknowledged.

### 9.6 Phase 2 prerequisite audit

Before writing UART, verify `CLOCKS` model implements the `_selected` register handshake. pico-sdk `clock_configure` busy-waits on `CLOCKS.clk_peri_selected` reflecting the new AUXSRC. If the emulator model doesn't step `_selected`, `hello_uart` hangs inside `runtime_init_clocks` before ever reaching UART code. Journal audit result in Phase 2 kickoff.

### 9.7 Dual-core APB write contention

`silicon_periph_diff_rp2040` scenario authors: do not cross-core write the same APB register same-cycle. Emulator is single-threaded (core 0 always wins); silicon AHB arbitration is undocumented ordering. No corpus firmware does this; scenario authors could.
