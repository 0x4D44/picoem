# Silicon Test Coverage Expansion

**Date:** 2026-04-16
**Status:** Final (V3 — promoted after two review rounds + supervisor review)
**Scope:** mdrp2350 only (RP2040 benefits indirectly from shared patterns)

## Context

The `test_silicon` orchestrator wires five oracles against live RP2354 hardware:
probe_diff (ISA), cycle (timing), periph (peripheral state), dualcore (contention),
and isr (exception paths). Coverage is solid for PIO, clocks/PLL, TIMER0, and the
Phase 2 peripheral suite (UART0 TX, SPI0 loopback, I2C0 NACK, ADC one-shot, PWM
wrap, DMA mem-to-mem + chain). But several implemented features have no silicon
scenario, and several peripherals have storage-only registers that real firmware
will exercise.

This HLD covers closing those gaps in four phases, ordered by effort and
dependency.

## Key finding: ICSR dispatch is already wired

Investigation during planning revealed that `try_take_any_pending_exception`
(`exceptions.rs:422`) already polls PENDSVSET, PENDSTSET, NMIPENDSET, and
external IRQs — called at the top of every `step()` (`mod.rs:110`). The ICSR
W1S/W1C write semantics are also implemented (`ppb.rs:454-465`).

The seven ISR oracle scenarios were documented as "expected to FAIL until dispatch
is wired" but **both the dispatch path and the ICSR write path already exist**.
The stale documentation (isr_scenarios.rs module header, silicon_isr_diff_rp2350
banner, and the 2026-04-15 journal entry) must be updated. The scenarios may fail
only because of the **banked SP staleness bug** (`tech_debt.md:131`) — or they may
already pass. Phase 2 establishes the truth by running the oracle before and after
the SP fix.

## Phase 1 — Close pure test gaps

**Goal:** Add silicon scenarios for features that are implemented and unit-tested
but have no differential validation against hardware.

**Emulator changes:** None. Test-only.

### 1.1 SIO integer divider

The divider is fully functional: signed/unsigned compute, quotient/remainder,
dirty-flag management (`sio/mod.rs:416-472`). Unit tests exist but no silicon
scenario exercises it.

**New periph scenario: `sio_divider_unsigned`**
- Setup: write DIV_UDIVIDEND (0xD000_0060) and DIV_UDIVISOR (0xD000_0064).
- Observe: DIV_QUOTIENT (0xD000_0070), DIV_REMAINDER (0xD000_0074),
  DIV_CSR (0xD000_0078).
- Validates compute + dirty-clear-on-read semantics.

**New periph scenario: `sio_divider_signed`**
- Setup: write DIV_SDIVIDEND (0xD000_0068) and DIV_SDIVISOR (0xD000_006C).
- Observe: DIV_QUOTIENT (0xD000_0070), DIV_REMAINDER (0xD000_0074),
  DIV_CSR (0xD000_0078).
- Validates signed division (negative divisor, negative dividend, division by
  zero). Note: RP2350 div-by-zero returns quotient=0xFFFF_FFFF (unsigned) or
  +1/-1 (signed, depending on dividend sign), and remainder=dividend (NOT zero).

### 1.2 SIO MTIME

Functional: 64-bit counter, per-core compare, match detection (`sio/mod.rs:
478-514`). No silicon scenario.

**New periph scenario: `sio_mtime_count_and_match`**
- Custom sled: enable MTIME via MTIME_CTRL (0xD000_01A0), spin for N cycles,
  write MTIMECMP[0] below current count to trigger match, then **disable MTIME**
  (write 0 to MTIME_CTRL) before the final BKPT. Disabling before BKPT is
  critical: on real silicon MTIME keeps ticking during probe readback, but the
  emulator stops when `run()` returns. Without disabling, the raw MTIME value
  will diverge by the probe readback latency (hundreds to thousands of cycles).
- Observe: MTIME_CTRL (0xD000_01A0 — should be 0 after disable),
  MTIME low (0xD000_01A8), MTIME high (0xD000_01AC — frozen value after disable),
  MTIMECMP[0] low (0xD000_01B0).
- Note: MTIME is 64-bit; observe both 32-bit halves separately.
- Limitation: the emulator computes `mtime_match_asserted` internally but does
  not route it to NVIC (`IRQ_SIO_IRQ_MTIMECMP`, IRQ 29). The scenario validates
  counting + register round-trip, not match-to-interrupt delivery. On real
  silicon the match WOULD pend IRQ 29. Wiring the NVIC routing is out of scope
  for Phase 1 (test-only) but should be tracked as a gap.

### 1.3 TIMER1

Same model as TIMER0, different base address (0x400B_8000 per
`peripherals/timer.rs:52`). TIMER0 has two silicon scenarios; TIMER1 has zero.

**New periph scenario: `timer1_alarm0_fire_and_clear`**
- Clone of `timer0_alarm0_fire_and_clear` with addresses adjusted to TIMER1 base
  0x400B_8000.
- Validates that the second timer instance is correctly wired to the bus decode.

### 1.4 Doorbells — deferred to dualcore oracle

SIO doorbells are fully functional (`sio/mod.rs:636-671`), but they are
inherently cross-core: writing DOORBELL_OUT_SET from core N sets bits on
core (1-N)'s pending register. The periph oracle runs single-core — any scenario
that writes OUT_SET and reads IN_SET from the same core will always observe zero,
producing a trivial false-PASS.

Meaningful validation requires a dualcore case (core 0 writes OUT_SET, core 1
reads IN_SET, or vice versa). **Add a `dualcore_doorbell_roundtrip` case in a
later pass** rather than a misleading single-core periph scenario now.

### Verification

```bash
cargo build -p mdpicoem-harness --release
cp target/release/test_silicon.exe /tmp/ts_phase1.exe
/tmp/ts_phase1.exe --probe 2e8a:000c:E46410955F614129 --filter sio_divider
/tmp/ts_phase1.exe --probe 2e8a:000c:E46410955F614129 --filter sio_mtime
/tmp/ts_phase1.exe --probe 2e8a:000c:E46410955F614129 --filter timer1
```

All three new scenario groups should PASS. If any FAIL, investigate the emulator's
register model — the implementation exists but may have edge-case bugs that unit
tests didn't catch (which is exactly why we're adding silicon scenarios).

## Phase 2 — Banked SP fix + ISR oracle verification

**Goal:** Establish the ISR oracle baseline, fix the banked SP staleness bug, then
re-run to measure the impact.

### 2.0 ISR oracle baseline (before any fix)

Run the ISR oracle as-is, with zero emulator changes:

```bash
/tmp/ts_phase2.exe --probe 2e8a:000c:E46410955F614129 --filter isr_
```

Record which scenarios PASS, FAIL, and what the mismatch is (stacked-frame
address, register value, CYCCNT delta). This tells us whether the SP staleness
bug is actually the blocker, or whether the scenarios already pass. This step
costs nothing and prevents wasted effort if the oracle already works.

Also update stale documentation:
- `isr_scenarios.rs` module header (claims `step()` doesn't poll ICSR — it does)
- `silicon_isr_diff_rp2350.rs` banner (same stale claim)
- CLAUDE.md ISR "expected to FAIL" language

### 2.1 Banked SP staleness fix

**Bug:** `enter_exception` (`exceptions.rs:80-81`) reads `self.regs.psp`/`.msp`
directly, but regular instructions (PUSH, POP, SUB SP, ADD SP) write to `r[13]`
via `set_sp()` without syncing to the banked fields. If any SP-modifying
instruction runs before an exception, the stacked frame address is wrong.

`exit_exception` (`exceptions.rs:272`) has the same pattern: reads `self.regs.psp`
or `.msp` for the unstack address while in handler mode. Handler prologue/epilogue
modifies `r[13]` without syncing, so nested exceptions see a stale MSP.

**Fix:** One line each:

`enter_exception`, before the `let use_psp` line (after the lockup check):
```rust
self.regs.sync_sp_to_banked();
```

`exit_exception`, before the `let sp = if return_to_psp` line:
```rust
self.regs.sync_sp_to_banked();
```

This mirrors the mdrp2040 Phase 4.B fix documented in `tech_debt.md:131-133`.

**Files:**
- `crates/mdrp2350/src/core/exceptions.rs` — the two-line fix
- `crates/mdrp2350/src/tests.rs` — unit test: modify SP via SUB, trigger
  exception, verify frame is stacked at the correct (post-SUB) address

### 2.2 ISR oracle re-run (after fix)

Re-run the ISR oracle and diff against the Phase 2.0 baseline. Record which
scenarios flipped from FAIL→PASS (attributable to the SP fix) vs which remain
FAIL (different root cause — investigate individually).

Update `tech_debt.md:131-133` based on actual results.

### Verification

The ISR oracle is the verification. Compare 2.0 (before) and 2.2 (after) outputs.

## Phase 3 — Peripheral fidelity upgrades

**Goal:** Make storage-only registers functional where real firmware observes
incorrect behaviour, then add silicon scenarios to validate.

No dependency on Phase 1 or 2 at the code level. Run after Phase 1 as a
sequencing preference (Phase 1 establishes that existing scenarios pass, so
regressions from Phase 3 emulator changes are detectable).

### 3.1 ADC round-robin channel advancement

**Current state:** RROBIN bits stored in CS but AINSEL never advances between
samples (`tech_debt.md:825-828`). Multi-channel firmware sees single-channel
behaviour.

**Fix** (`peripherals/adc.rs`): Two changes needed:

1. **FIFO word format.** The emulator currently stores raw 12-bit samples with
   a bespoke channel encoding in bits [11:8]. Real hardware produces a 16-bit
   FIFO word: ERR[15]:AINSEL[14:12]:RESULT[11:0]. The emulator's
   `complete_conversion` must be updated to produce the hardware format so that
   the observe mask works identically on both sides. This is a prerequisite for
   any FIFO-based observation to be meaningful.

2. **AINSEL advancement.** When a conversion completes and RROBIN is nonzero,
   advance AINSEL to the next set bit in RROBIN (wrapping).

**New periph scenario: `adc_round_robin_2ch`**
- Setup: CS with RROBIN = 0x03 (channels 0+1), EN=1, START_MANY=1.
  FCS.SHIFT=1 (include channel tag in FIFO words).
- Custom sled: spin for enough cycles that 2+ conversions complete.
- Observe: CS.AINSEL (should have advanced). For FIFO observation, **mask to
  channel-tag bits only** (bits [14:12] in the unshifted word, or bits [13:11]
  when SHIFT=1) — the sample value bits will differ between HW (analog noise on
  floating pins) and EMU (deterministic model). Choose the mask based on the
  hardware FIFO format after the emulator's FIFO format is corrected.

### 3.2 PWM fractional DIV

**Current state:** Slices advance CTR once per clk_sys regardless of DIV
(`tech_debt.md:820-821`).

**Fix** (`peripherals/pwm.rs`): The CH_DIV register format is INT[11:4]:FRAC[3:0]
— an 8-bit integer part and 4-bit fractional part, 12 bits total (masked to
0x0FFF at `pwm.rs:238`). Reset value 0x0010 = integer 1, frac 0 = divisor 1.0.

Add a `frac_accum: u16` field to `PwmSlice`. The current `tick()` receives a
`cycles: u32` parameter and must remain O(1) (the existing path is O(1) via
modular arithmetic; a per-tick loop would regress performance for large quanta).
Closed-form for a batch of `cycles` ticks:

```
let int_part = (div >> 4) as u32;       // INT[11:4]
let frac_part = (div & 0xF) as u32;     // FRAC[3:0]
let total_frac = frac_accum as u32 + frac_part * cycles;
let carry = total_frac / 16;
frac_accum = (total_frac % 16) as u16;
let advance = int_part * cycles + carry;
// ... advance CTR by `advance`, wrapping at TOP+1
```

At DIV=1.0 (INT=1, FRAC=0): `total_frac = 0 + 0*cycles = 0`, `carry = 0`,
`advance = 1*cycles + 0 = cycles`. This is **identical** to current behaviour.
This invariant is critical: the existing `pwm_wrap_irq` scenario (which uses the
reset DIV=1.0) must not regress.

**New periph scenario: `pwm_fractional_div`**
- Setup: slice 0 with TOP=0xFFFF, DIV = 0x0020 (integer 2, frac 0 = divisor 2.0),
  EN=1.
- Run for `max_sysclks = 200`.
- Observe: CTR (should be ~100 with DIV=2.0 — half of the ~200 that DIV=1.0 would
  produce), INTR (wrap flag should be clear — TOP=0xFFFF is far above CTR=100).
  Using a large TOP avoids wrap and isolates the divisor effect. The existing
  `pwm_wrap_irq` scenario already covers wrap behaviour at DIV=1.0.

### 3.3 DMA timer pacing

**Current state:** TIMER0..3 registers stored but not applied
(`tech_debt.md:850-851`). Transfers fire instantly regardless of pacing.

**Fix** (`dma.rs`): DMA timers use TREQ_SEL values 0x3B–0x3E (59–62). These are
DMA-internal — they are NOT in the peripheral DREQ bitmap returned by
`collect_dreqs()`. The fix must special-case these inside `Dma::tick()`:

1. Add `timer_accum: [u32; 4]` to the `Dma` struct.
2. At the top of `tick()`, for each timer register with a nonzero Y (denominator,
   bits [15:0]) AND nonzero X (numerator, bits [31:16]), accumulate X per sysclk.
   When accum >= Y, subtract Y and assert the timer's DREQ. Guard: if Y=0, the
   timer is disabled (do not fire). If X=0, the rate is zero (never fire).
   The register format is X[31:16]:Y[15:0], rate = X/Y per clk_sys.
3. In the DREQ readiness check (`dma.rs:477`), for TREQ 59–62, check the
   corresponding timer's asserted flag instead of the `dreqs` bitmap.
4. Add `DREQ_TIMER0..3` constants to `dreq.rs`.

**New periph scenario: `dma_timer_paced`**
- Setup: DMA channel 0 with TREQ = 0x3B (TIMER0), TIMER0 = suitable X/Y rate
  (e.g. X=1, Y=10 → one transfer per 10 sysclks), 4-word mem-to-mem transfer.
- Custom sled: spin for enough sysclks that the paced transfer completes
  (4 words * 10 sysclks/word = ~40+ sysclks, budget 200).
- Observe: destination buffer populated, TRANS_COUNT = 0, CH0_CTRL_TRIG.BUSY = 0.

This scenario distinguishes paced from instant — if pacing isn't applied, the
transfer completes in ~4 cycles; with pacing, it takes ~40.

## Phase 4 — Deeper peripheral paths

**Goal:** Address remaining fidelity gaps that affect firmware beyond the current
test corpus.

No dependency on Phase 3. Can be developed in parallel with Phase 3 and merged
in sequence. Only requires Phase 1 to have established the baseline.

### 4.1 PIO INTn routing split

**Current state:** All PIO IRQ[3:0] flags route to both NVIC lines
(`tech_debt.md:232-242`). Multi-IRQ firmware sees spurious wakes.

**Fix:** Wire `INT0_INTE`/`INT1_INTE` (offsets 0x12C/0x138) into the PIO→NVIC
dispatch path. Each flag routes to the NVIC line whose INTE mask includes it.

**New periph scenario: `pio0_int_routing_split`**
- Setup: PIO0 with two SMs producing different IRQ flags. INT0_INTE enables flag 0
  only; INT1_INTE enables flag 1 only.
- Observe: NVIC pending bits for PIO0_IRQ_0 vs PIO0_IRQ_1 — should be
  independently set, not mirrored.

### 4.2 UART RX via loopback

**Current state:** RX FIFO exists but is never populated. RXFE=1 forever
(`tech_debt.md:786-791`). The UART module stores UARTCR (including LBE, bit 7)
but does not act on it.

**Fix** (`peripherals/uart.rs`): Wire LBE in the TX drain path. When
`UARTCR.LBE` (bit 7) is set and a byte is popped from the TX FIFO for
transmission, push that byte into the RX FIFO instead of (or in addition to)
discarding it. This is ~10 lines in the `tick()` function's TX drain branch.
Also update UARTFR flags (clear RXFE, set RXFF if full).

This is a small but real emulator change — not just adding `push_rx_byte`.

**New periph scenario: `uart0_rx_loopback`**
- Setup: UART0 with LBE=1 (UARTCR bit 7), FEN=1, UARTEN=1, TXE=1, RXE=1,
  baud configured.
- Custom sled: write a byte to UARTDR (TX), spin until UARTFR.TXFE, then
  spin until UARTFR.RXFE clears, read UARTDR (RX).
- Observe: UARTFR (RXFE should be clear after loopback), UARTDR (read should
  return the transmitted byte).

### 4.3 PIO RESETS gating

**Current state:** PIO ticks unconditionally regardless of RESETS bit
(`tech_debt.md:222-230`).

**Fix:** Gate `tick_pio` on the RESETS.DONE bit for each PIO block. One conditional
per step per PIO block.

This is low-impact — firmware that de-asserts RESETS before enabling SMs already
works. Only firmware that expects a running SM to freeze mid-execution when RESETS
is reasserted would diverge. No silicon scenario planned — verify via unit test
only (assert that `tick_pio` is a no-op while RESETS is asserted).

### Verification

```bash

/tmp/ts_phase4.exe --probe 2e8a:000c:E46410955F614129 --filter uart0_rx
```

PIO RESETS gating: unit test only.

## What's deliberately excluded

These are tracked in `tech_debt.md` but not in this plan:

- **Second peripheral instances** (UART1, SPI1, I2C1) — mechanical clones once
  first instance is correct. Add when firmware needs them.
- **Cryptographic accelerators** (TRNG, SHA256) — niche, no firmware in corpus.
- **OTP, POWMAN, GLITCH_DETECTOR, HSTX** — specialised blocks, not on the
  emulator roadmap for current firmware targets.
- **Interpolator computation** — storage-only stub. No firmware in corpus uses
  interpolator math. Add when PicoGUS or similar needs it.
- **I2C SCL timing** — transactions fire synchronously. Correct for current
  firmware that polls at completion, wrong for firmware that observes bus-cycle
  timing. Defer until a firmware target needs it.
- **DMA BSWAP, SNIFF/CRC, HIGH_PRIORITY** — storage-only. No firmware uses these.
- **PWM PH_CORRECT, A_INV/B_INV** — storage-only. No firmware uses these.
- **SIO doorbells** — need a dualcore case, not a periph scenario. Deferred to
  a future dualcore oracle expansion.

## V2 changes from V1

- Fixed SIO divider observe addresses: QUOTIENT=0x70, REMAINDER=0x74, CSR=0x78
  (V1 had them 8 bytes too low — would have caused false PASS).
- Fixed MTIME addresses: counter at 0xD000_01A8/01AC, MTIMECMP[0] at
  0xD000_01B0/01B4 (V1 confused MTIME with MTIMECMP).
- Fixed TIMER1 base: 0x400B_8000 (V1 had 0x400B_C000 — would hit unmapped space).
- Fixed PWM DIV format: INT[11:4]:FRAC[3:0] = 8.4 format, 12-bit total
  (V1 said "16.4" — accumulator overflow logic was wrong).
- Dropped doorbell periph scenario (single-core writes OUT_SET for other core,
  reads own IN_SET → always zero → false PASS). Deferred to dualcore oracle.
- Added Phase 2.0: run ISR oracle BEFORE SP fix to get a real baseline.
- Added explicit ADC FIFO observe mask (channel-tag bits only, not sample values
  — floating pins produce noise on real HW).
- Specified DMA timer pacing in `Dma::tick()` (not via `collect_dreqs` — TREQ
  59-62 are DMA-internal, not in the peripheral DREQ bitmap).
- Specified UART LBE wiring in tick path (not just `push_rx_byte` — the scenario
  needs TX→RX loopback to work on both HW and EMU).
- Removed false Phase 4→3 dependency. Phases 3 and 4 are independently
  implementable.
- Called out `pwm_wrap_irq` as the specific regression risk from PWM frac DIV,
  with the DIV=1.0 invariant.
- Flagged stale ISR documentation that must be updated (isr_scenarios.rs header,
  silicon_isr_diff_rp2350 banner, journal entry).

## V3 changes from V2

- MTIME sled must disable MTIME (write 0 to MTIME_CTRL) before BKPT. On real
  silicon MTIME keeps ticking during probe readback; the emulator stops when
  `run()` returns. Without disabling, raw MTIME values diverge by probe latency.
- ADC FIFO format must be fixed as part of Phase 3.1. The emulator currently
  stores raw 12-bit samples with a bespoke channel encoding; real hardware
  produces ERR[15]:AINSEL[14:12]:RESULT[11:0]. The observe mask depends on the
  hardware format. Called out as a prerequisite, not just a mask choice.
- PWM fractional accumulator specified as O(1) closed-form batch computation
  (V2 described a per-tick loop that would regress performance for large quanta).
- DMA timer pacing: added explicit X=0 and Y=0 guards. Y=0 = timer disabled
  (not "fire every tick"). X=0 = rate zero (never fire). Clarified register
  format: X[31:16]:Y[15:0], rate = X/Y per clk_sys.
- Fixed div-by-zero remainder: it is the dividend, not 0x00000000. Signed
  div-by-zero quotient is +1 or -1 depending on dividend sign.
- Noted stale `pwm.rs:105` doc comment ("16.4") should be corrected to "8.4"
  when the fractional divider is implemented in Phase 3.
