# Phase 5: Dual Core + SIO — Low-Level Design

Version: 0.4.0
Date: 2026-04-13
Parent: HLD Section 15, Phase 5
Depends: Phase 4 complete (bootrom + flash boot working)

## 1. Purpose

Enable both Cortex-M33 cores to run simultaneously. Core 1 boots the real
bootrom, enters the bootrom's FIFO-polling wait loop, and can be launched
by Core 0 via the standard Pico SDK `multicore_launch_core1` protocol.
Implement the remaining SIO block features (FIFO, spinlocks, divider,
doorbells, platform timer, interpolator stubs) and the RCP coprocessor
encoding + salt propagation needed for the bootrom's Core 1 path to exit
its wait loop.

### Milestone

Integration test: load bootrom + dual-core test binary → both cores
execute the bootrom from the reset vector → Core 0 reaches its
application, runs the launch protocol, and sends the launch sequence via
FIFO → Core 1 exits `wait_for_rcp_salt` (via the RCP salt validity
mechanism), wakes from WFE, processes the launch sequence, and branches
to its application entry → each core sets a distinct GPIO pin → test
asserts both pins in SIO GPIO_OUT AND that Core 1's PC is outside the
bootrom.

## 2. Design

### 2.1. SIO struct refactor

Move GPIO state (`gpio_out`, `gpio_oe`, `gpio_in`) from Bus into Sio. Make
Sio handle region-0xD 32-bit register dispatch via
`read32(offset, core_id)` and `write32(offset, val, core_id)`. Move `Sio`
from `Emulator` into `Bus` (removing `pub sio: Sio` from Emulator).

GPIO_HI_IN (offset 0x008) stays on Bus because `read_gpio_hi_in()` needs
`flash_loaded`. Bus handles that one offset directly before delegating
the rest. Same carve-out for sub-word reads: `if (reg_offset & !3) == 0x008`.

```rust
// Bus::read32 for region 0xD:
0xD => {
    let reg_offset = addr & 0xFFF;
    if reg_offset == 0x008 {
        self.read_gpio_hi_in()
    } else {
        let core = self.active_core();
        self.sio.read32(reg_offset, core)
    }
}
```

**Address masking:** change all four SIO dispatch sites (`read8`, `read16`,
`read32`, `write32`) from `addr & 0x0FFF_FFFF` to `addr & 0xFFF`. Collapses
both Secure (0xD0000000) and Non-Secure (0xD4000000) aliases to the same
register. All RP2350 SIO registers live below 0x200; 12-bit masking is
sufficient.

**Sub-word SIO access:** `read8`/`read16` call
`self.sio.read32(offset & !3, core)` (after the 0x008 carve-out) and
extract the byte/halfword. `write8`/`write16` continue to silently ignore
SIO — pre-existing behavior, not known to affect bootrom or SDK code.

**Helper decomposition:** `Sio::read32` / `Sio::write32` delegate to
per-subsystem helpers: `gpio_read`, `gpio_write`, `fifo_read`, `fifo_write`,
`spinlock_read`, `spinlock_write`, `divider_read`, `divider_write`,
`doorbell_read`, `doorbell_write`, `mtime_read`, `mtime_write`,
`interp_read`, `interp_write`.

**SIO reset:** `Sio::reset()` method that explicitly reinitializes every
field:
- `gpio_out = 0`, `gpio_oe = 0`, `gpio_in = 0`
- `fifo_to_core0 = Fifo::new()`, `fifo_to_core1 = Fifo::new()`
- `fifo_wof = [false; 2]`, `fifo_roe = [false; 2]`
- `spinlock_bits = 0`
- `divider = [Divider::default(); 2]`
- `doorbell_pending = [0; 2]`
- `mtime = 0`, `mtime_ctrl = 0`, `mtimecmp = [0; 2]`, `mtime_match_asserted = [false; 2]`
- `interp = [[0; 32]; 2]`

Called from `Emulator::reset()` alongside other subsystem resets.
Enumerating explicitly (rather than reassigning `Sio::new()`) prevents
accidentally leaving fields stale if `Sio::new()` later gains construction
parameters.

**External access changes:** verified by grep across the workspace:
- `crates/mdrp2354/src/tests.rs`: 4 lines (5306, 5320, 5332, 5333) reading
  `emu.bus.gpio_out` / `emu.bus.gpio_oe`.
- `crates/mdrp2354-app/src/sim.rs`: 2 lines (46, 47) reading
  `emu.bus.gpio_out` / `emu.bus.gpio_oe`.
- Other crates (`mdrp2354-test-harness`, `mdrp2354-debug`, `mdrp2354-periph`,
  `mdrp2354-pio`) contain no references.

Total: **6 lines** to update. V3 undercounted at 4; V4 includes mdrp2354-app.

### 2.2. Inter-processor FIFO

Two 8-entry circular buffers, one per direction.

```rust
struct Fifo {
    buf: [u32; 8],
    head: u8,
    tail: u8,
    count: u8,
}

// In Sio:
fifo_to_core1: Fifo,  // Core 0 writes, Core 1 reads
fifo_to_core0: Fifo,  // Core 1 writes, Core 0 reads
fifo_wof: [bool; 2],  // sticky write overflow, per core
fifo_roe: [bool; 2],  // sticky read underflow, per core
```

| Offset | Register | Read | Write |
|--------|----------|------|-------|
| 0x050 | FIFO_ST | Status (see below) | W1C: see code sketch |
| 0x054 | FIFO_WR | — | Push to OTHER core's RX queue |
| 0x058 | FIFO_RD | Pop from THIS core's RX queue | — |

**FIFO_ST bits (calling-core view):**
- Bit 0 (VLD): this core's RX queue has data
- Bit 1 (RDY): other core's RX queue has space
- Bit 2 (WOF): sticky write overflow (W1C)
- Bit 3 (ROE): sticky read underflow (W1C)

**FIFO_ST W1C code sketch:**
```rust
fn fifo_st_write(&mut self, val: u32, core: usize) {
    if val & 0x4 != 0 { self.fifo_wof[core] = false; }
    if val & 0x8 != 0 { self.fifo_roe[core] = false; }
    // Bits 0 (VLD) and 1 (RDY) are read-only; other bits ignored.
}
```

Both W1C and "write 0xFFFFFFFF clears everything" interpretations are
compatible — `0xFF & 0x4 != 0` and `0xFF & 0x8 != 0` both clear. The SDK
writes 0xFFFFFFFF, which works.

**Empty read**: returns 0, sets ROE for the reader.
**Full write**: data dropped, sets WOF for the writer.

**Event signaling on write:** on a successful FIFO_WR (non-overflow), also
set `bus.event_flag[other_core] = true`. Matches RP2350 hardware (FIFO
writes wake WFE) and provides a safety net. Event infrastructure is added
in Stage A1, so Stage A2's FIFO wires event signaling without creating an
unvalidated transient.

**FIFO IRQ delivery is NOT implemented** (no NVIC pending-bit storage —
see §2.5). Code that uses FIFO IRQ (as opposed to FIFO + SEV/WFE) will
not receive the interrupt.

### 2.3. Hardware spinlocks

32 shared locks, stored as a `u32` bitmask.

```rust
spinlock_bits: u32,  // bit N = SPINLOCK<N> claimed
```

| Offset | Register | Read | Write |
|--------|----------|------|-------|
| 0x100 + 4*N | SPINLOCK<N> | If bit N clear → set it, return `1 << N`. Else return 0. | Clear bit N (any value) |
| 0x05C | SPINLOCK_ST | `spinlock_bits` | — |

Return `1 << N` on successful claim (RP2350 hardware). Any write releases.

**Fairness:** Core 0 steps first and wins all contested claims. Valid
arbitration model; no deadlock. Pathological livelock theoretically
possible but not observed.

### 2.4. Integer divider

Per-core hardware divider. Immediate computation. CSR.READY always 1.

```rust
#[derive(Default, Clone, Copy)]
struct Divider {
    dividend: u32,
    divisor: u32,
    quotient: u32,
    remainder: u32,
    signed: bool,
    dirty: bool,
    reads_pending: u8,  // 0 = clean, 1 = Q or R read, 2 = both read (clears dirty)
}
// In Sio:
divider: [Divider; 2],
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x060 | DIV_UDIVIDEND | Write: store, mark unsigned. Read: return dividend. |
| 0x064 | DIV_UDIVISOR | Write: store, compute unsigned Q/R, mark DIRTY. |
| 0x068 | DIV_SDIVIDEND | Write: store, mark signed. |
| 0x06C | DIV_SDIVISOR | Write: store, compute signed Q/R, mark DIRTY. |
| 0x070 | DIV_QUOTIENT | Read: quotient; advance reads_pending counter. Write: direct set. |
| 0x074 | DIV_REMAINDER | Read: remainder; advance reads_pending counter (clears DIRTY when both read). Write: direct set. |
| 0x078 | DIV_CSR | Bit 0 READY (always 1). Bit 1 DIRTY. |

**DIRTY semantics**: set on any div register write. Cleared after the
reader reads both QUOTIENT and REMAINDER — this matches the SDK's context-
save protocol.

**Division by zero** (RP2350):
- Unsigned: quotient = 0xFFFFFFFF, remainder = dividend
- Signed: quotient = 1 if dividend < 0 else -1, remainder = dividend

**Why immediate is correct**: the SDK relies on hardware auto-stall when
reading results early; it does NOT insert delays. With immediate
computation, results are always "already done" when read, so auto-stall
never triggers. Cycle count is off by up to 8 per division.

**Verify against datasheet**: the RP2350 datasheet should confirm the
divider still lives in SIO at 0x060–0x078 (unchanged from RP2040). If the
RP2350 removed the SIO divider in favor of a different mechanism, §2.4 and
Stage B3 become empty and can be deleted. Verify at start of Stage B3
implementation.

### 2.5. Doorbells

4 doorbell bits per core (RP2350 DOORBELL_* registers are 4 bits wide).

```rust
doorbell_pending: [u8; 2],  // lower 4 bits significant
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x180 | DOORBELL_OUT_SET | Write: `doorbell_pending[1 - core] \|= val & 0xF` |
| 0x184 | DOORBELL_OUT_CLR | Write: `doorbell_pending[1 - core] &= !(val & 0xF)` |
| 0x188 | DOORBELL_IN_SET | Read: `doorbell_pending[core]` |
| 0x18C | DOORBELL_IN_CLR | Write: `doorbell_pending[core] &= !(val & 0xF)` |

**IRQ delivery is NOT implemented.** The NVIC at `bus/ppb.rs` returns 0
for all reads in `0xE100..=0xE4FF` and ignores writes — there is no
per-IRQ pending bit storage. Phase 5 provides register round-trip only.
Tests must observe `emu.bus.sio.doorbell_pending[core]` directly. Adding
NVIC pending-bit storage is out of scope.

### 2.6. Platform timer (MTIME)

64-bit counter, per-core 64-bit compare, edge-triggered match flag.

```rust
mtime: u64,
mtime_ctrl: u32,
mtimecmp: [u64; 2],
mtime_match_asserted: [bool; 2],
```

| Offset | Register | Behavior |
|--------|----------|----------|
| 0x1A0 | MTIME_CTRL | Bit 0 = enable |
| 0x1A8 | MTIME (low) | R/W low 32 bits |
| 0x1AC | MTIMEH (high) | R/W high 32 bits |
| 0x1B0 | MTIMECMP0 (low) | Core 0 compare, low 32 |
| 0x1B4 | MTIMECMP0H | Core 0 compare, high 32 |
| 0x1B8 | MTIMECMP1 (low) | Core 1 compare, low 32 |
| 0x1BC | MTIMECMP1H | Core 1 compare, high 32 |

Offsets are best-effort against RP2350 datasheet — verify and adjust
during implementation without requiring a design change. The reviewer
team flagged alternative offsets (e.g., MTIME_CTRL at 0x1A4, MTIMECMP
aliased-per-core at 0x1B8) that should be cross-checked against the
datasheet's definitive register map before the MTIME commit lands.

Increment logic in `Emulator::step()` after the wake check:
```rust
if self.bus.sio.mtime_ctrl & 1 != 0 {
    let new_mtime = self.bus.sio.mtime.wrapping_add(1);
    self.bus.sio.mtime = new_mtime;
    for core in 0..2 {
        let match_now = new_mtime >= self.bus.sio.mtimecmp[core];
        if match_now && !self.bus.sio.mtime_match_asserted[core] {
            self.bus.sio.mtime_match_asserted[core] = true;
            // IRQ delivery deferred (§2.5). Match state is observable
            // via mtime_match_asserted for tests.
        }
        if !match_now {
            self.bus.sio.mtime_match_asserted[core] = false;
        }
    }
}
```

Edge-triggered: fires once on `<` → `>=` transition. Clears on wraparound
or MTIMECMP rewrite to a value `> mtime`. Re-writing MTIMECMP to an
already-satisfied value does NOT re-fire (the asserted flag stays true
until a `<` transition). Matches real hardware's level-sensitive pending
bit.

**MTIME does NOT wake WFE.** Match state latches only into
`mtime_match_asserted` — it does not write `event_flag` or NVIC. Any
program using `MTIMECMP + WFE` for timed wakeups will sleep forever. Use
FIFO_WR or explicit SEV instead. Documented in §7.

**Prescaler simplification:** MTIME ticks once per system clock when
enabled. Real RP2350 uses a TICKS peripheral for 1 MHz prescaling, not
modeled. Acceptable for Phase 5 — the bootrom doesn't depend on MTIME
units.

### 2.7. Interpolator stubs

Two interpolators per core (INTERP0 at 0x080–0x0BC, INTERP1 at 0x0C0–0x0FC),
16 words each = 32 words per core. Register backing store only.

```rust
interp: [[u32; 32]; 2],  // [core][reg] where reg = (offset - 0x080) >> 2
```

Reads return last-written value. No computation. Full interpolator
arithmetic is Phase 7.

### 2.8. Event state, WFE, SEV

The bootrom's Core 1 wait loop uses WFE. The SDK's `multicore_launch_core1`
sends SEV. Hints must stall/wake.

**Shared state on Bus**:
```rust
pub event_flag: [bool; 2],  // per-core ARM event register
```

**Per-core state on CortexM33**:
```rust
pub(crate) wfe_waiting: bool,
```

**WFE**: if `bus.event_flag[self.core_id]` is set → clear it, return 1
cycle. Else → `self.wfe_waiting = true`, return 1 cycle.

**SEV**: set `bus.event_flag[0] = true; bus.event_flag[1] = true`
(broadcast to both cores including issuer, per ARM ARM).

**FIFO_WR auxiliary event**: on successful FIFO write, also set
`bus.event_flag[other_core] = true` (see §2.2).

**Core step gate**: `CortexM33::step()` first check is
`if self.wfe_waiting { return; }` before the existing `halted` and
`stall_cycles` checks. A WFE-sleeping core is frozen — no decrement,
fetch, or bus access.

**Emulator wake check**, in `Emulator::step()` after both cores step:
```rust
for i in 0..2 {
    if self.cores[i].wfe_waiting && self.bus.event_flag[i] {
        self.bus.event_flag[i] = false;
        self.cores[i].wfe_waiting = false;
    }
}
```

**Order within `Emulator::step()`**:
1. `clock.tick()`
2. `bus.clear_contention_state()`
3. `cores[0].step(&mut bus)`
4. `bus.begin_contention_check()`
5. `cores[1].step(&mut bus)`
6. Wake check
7. MTIME increment

MTIME runs after the wake check as a matter of ordering discipline — in
Phase 5, MTIME doesn't feed the wake decision anyway, but keeping MTIME
last preserves future flexibility if/when MTIME IRQ wake is added.

**Event flag reset**: `Emulator::reset()` clears `event_flag[0..2]`.

**Latency**: 1 emulator tick from SEV to WFE wake. Modeling simplification
— real hardware has some internal cost to a sleeping core, but this is
functionally correct.

### 2.9. Hint instruction dispatch

Current state:
- **Thumb-32** (`execute_thumb32.rs:845–857`): `thumb32_misc_control`
  decodes `hint = hw1 & 0xFF` and has arms for NOP/YIELD/WFE/WFI/SEV, all

**Required changes (Stage B1):**

1. `execute_thumb32.rs:778`: rename `_bus` → `bus`, pass to
   `thumb32_misc_control`.
2. `execute_thumb32.rs:845`: add `bus: &mut Bus` parameter.
3. `execute_thumb32.rs:852–854`:
   ```rust
   0x02 => self.wfe(bus),
   0x03 => 1,                        // WFI stays NOP
   0x04 => { bus.signal_sev(); 1 },  // SEV
   ```
4. `execute.rs:730–733`:
   ```rust

       0x0 | 0x1 => 1,                       // NOP, YIELD
   ```

and `self.wfe(bus)` reads `bus.event_flag[self.core_id]` and mutates
`self.wfe_waiting`. Both already hold `&mut bus`.

### 2.10. Core 1 boot

Change `Emulator::reset()` to boot both cores at the reset vector:

```rust
pub fn reset(&mut self) {
    let initial_sp = self.bus.memory.rom_read32(0);
    let reset_vector = self.bus.memory.rom_read32(4);
    for id in 0..2 {
        self.cores[id] = CortexM33::with_id(id as u8);
        self.cores[id].regs.msp = initial_sp;
        self.cores[id].regs.r[13] = initial_sp;
        self.cores[id].regs.set_pc(reset_vector & !1);
        self.cores[id].regs.xpsr = 1 << 24;
    }
    self.bus.clear_bus_fault();
    self.bus.ppb = [Default::default(), Default::default()];
    self.bus.event_flag = [false; 2];
    self.bus.rcp_salt = [0; 2];
    self.bus.rcp_salt_valid = [false; 2];
    self.bus.resets_state = 0x1FFF_FFFF;
    self.bus.sio.reset();
    self.clock = Clock { cycles: 0, sys_clk_hz: self.clock.sys_clk_hz };
}
```

Core 1 is no longer halted. The bootrom reads CPUID, branches to
`core1_boot_path` (0x1c6), and enters the WFE + `rcp_canary_status` loop
at `wait_for_rcp_salt` (0x1c4). Exit depends on §2.11's salt validity
mechanism.

**Pico SDK launch protocol** (SDK side, reference only):
1. Core 0 drains its RX FIFO.
2. Core 0 sends `{0, 0, 1, vtor, sp, entry}` one word at a time: push,
   SEV, read echo, compare; restart on mismatch.
3. Core 1 (in bootrom, after exiting wait loop) receives each word,
   echoes it, verifies the sequence, then sets VTOR, SP, and branches to
   `entry`.

### 2.11. RCP coprocessor decoding and salt propagation (Stage B2)

**The critical blocker for Core 1 boot.** The current handler at
`core/coprocessor.rs:58` uses `(hw0 >> 12) & 0xF == 0xE &&
hw1 & (1 << 4) != 0` — matching only the 0xEE prefix (MCR/MRC T1). Real
bootrom RCP instructions use 0xFE (MCR2/MRC2 T2) and 0xFC (MCRR2/MRRC2
T2) and fall through silently.

**Encoding classes in the bootrom** (verified against `roms/arm-bootrom.dis`):

| Mnemonic | Example | Encoding | hw0 high byte |
|----------|---------|----------|---------------|
| `rcp_canary_get`   | `fe16 373c` at 0x8c | MRC2 | 0xFE |
| `rcp_canary_check` | `fe06 273c` at 0x9a | MCR2 | 0xFE |
| `rcp_canary_status pc` | `fe30 f710` at 0x1d2 | MRC2 (Rt=15) | 0xFE |
| `rcp_salt_core0` | `fc41 0780` at 0x3998 | MCRR2 | 0xFC |
| `rcp_salt_core1` | `fc43 2781` at 0x399c | MCRR2 | 0xFC |
| `rcp_iequal r2,r3` | `fc43 2770` at 0x1ee | MCRR2 | 0xFC |
| `rcp_iequal r0,r1` | `fc41 0770` at 0x40c | MCRR2 | 0xFC |
| Other `rcp_bvalid`, `rcp_count_*` | various `fc4x ????` | MCRR2 | 0xFC |

Core 1's wait loop at 0x1c4–0x1d6:
```
1c4 <wait_for_rcp_salt>: wfe
1c6 <core1_boot_path>:   movw r2, #613 ; ... ; sub.w r7, r0, #140
1d2:                     rcp_canary_status pc, nodelay
1d6:                     bpl.n 1c4           ; bpl = branch if N==0
```

`bpl` loops back if N==0, exits if N==1. Core 1 needs canary_status to
return N=0 while its salt is invalid, N=1 after Core 0 validates.

Core 0's canary_status sites at 0x38b8 and 0x3990 run BEFORE Core 0
executes `rcp_salt_core0`/`rcp_salt_core1` at 0x3998/0x399c, so they need
the "invalid" result (N=0, V=0) to satisfy `bvc`/`bvs`/`bmi` checks.

Phase 4 currently works because rcp_canary_status is a silent NOP, and
Core 0's subsequent flag checks happen to be satisfied by flags left
over from the preceding `sub.w r7, r0, #140`. Lucky coincidence.

#### 2.11.2. Extended RCP handler

Add `bus: &mut Bus` to `cp7_rcp`. Update the `thumb32_coprocessor`
dispatcher (line 20: `7 => self.cp7_rcp(hw0, hw1)`) to pass bus.

Split decoding into two encoding families:

```rust
fn cp7_rcp(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let hw0_high = (hw0 >> 8) & 0xFF;
    match hw0_high {
        0xEE | 0xFE => self.cp7_mcr_mrc_family(hw0, hw1, bus),
        0xEC | 0xFC => self.cp7_mcrr_mrrc_family(hw0, hw1, bus),
        _ => 1,  // Not a recognized CP7 encoding
    }
}

fn cp7_mcr_mrc_family(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let is_cdp = hw1 & (1 << 4) == 0;
    if is_cdp {
        return 1;  // CDP / CDP2: accept silently (rcp_panic etc.)
    }
    let is_mrc = (hw0 >> 4) & 1 != 0;   // L bit
    let rt = ((hw1 >> 12) & 0xF) as usize;
    let core = bus.active_core();

    if is_mrc {
        if rt == 15 {
            // rcp_canary_status pc: write NZCV to APSR.
            // N = salt_valid[core]; Z=0, C=0, V=0.
            let n = if bus.rcp_salt_valid[core] { 1u32 << 31 } else { 0 };
            self.regs.xpsr = (self.regs.xpsr & 0x0FFF_FFFF) | n;
        } else {
            // rcp_canary_get: return salt XOR deadbeef (stub)
            self.regs.r[rt] = bus.rcp_salt[core] ^ 0xDEAD_BEEF;
        }
    } else {
        // MCR2: rcp_canary_check assertion — accept silently
    }
    1
}

fn cp7_mcrr_mrrc_family(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let l_bit = (hw0 >> 4) & 1;
    if l_bit != 0 {
        return 1;  // MRRC2 from CP7: not used by bootrom
    }

    // MCRR2 dispatch: discriminator is (opc1, CRm) from hw1.
    //   hw1[15:12] = Rt  (first source register)
    //   hw1[7:4]   = opc1
    //   hw1[3:0]   = CRm
    // (hw0[3:0] holds Rt2 per ARMv8-M MCRR2 encoding; we discard Rt2
    //  since our salt stub is value-agnostic.)
    //
    // Observed RCP instruction encoding (verified against arm-bootrom.dis):
    //   rcp_salt_core0: opc1=8, CRm=0   (example: fc41 0780)
    //   rcp_salt_core1: opc1=8, CRm=1   (example: fc43 2781)
    //   rcp_iequal:     opc1=7, CRm=0   (example: fc41 0770, fc43 2770)
    //   rcp_bvalid, rcp_count_*: other (opc1, CRm) pairs — silent NOP
    let opc1 = ((hw1 >> 4) & 0xF) as u8;
    let crm  = (hw1 & 0xF) as u8;
    let rt   = ((hw1 >> 12) & 0xF) as usize;

    match (opc1, crm) {
        (8, 0) => {
            // rcp_salt_core0
            bus.rcp_salt[0] = self.regs.r[rt];
            bus.rcp_salt_valid[0] = true;
        }
        (8, 1) => {
            // rcp_salt_core1
            bus.rcp_salt[1] = self.regs.r[rt];
            bus.rcp_salt_valid[1] = true;
        }
        _ => {
            // rcp_iequal, rcp_bvalid, rcp_count_*, etc.: silent NOP
        }
    }
    1
}
```

**Key correctness properties:**

1. **Rt=15 MRC2 writes APSR, NOT r[15]**. Single most important fix —
   without it, `rcp_canary_status pc` would corrupt PC on first execution.
2. **Discriminator is (opc1, CRm) from hw1, NOT hw0[3:0]**. V3 mistakenly
   treated hw0[3:0] (which is actually Rt2 per ARM ARM) as "CRn" and
   would have misrouted `rcp_iequal` (opc1=7) through the salt-write
   path. V4 correctly matches on opc1+CRm from hw1.
3. **State-dependent flag output**: `rcp_salt_valid[core]` flips only when
   `rcp_salt_coreN` MCRR2 executes. Core 1 exits wait loop when its salt
   is marked valid.
4. **Phase 4 regression analysis**:
   - Core 0 at 0x38b8: `rcp_salt_valid[0] = false` → N=0, V=0 → `bvc 38c0`
     V=0 taken → skip sabotage → good path ✓
   - Core 0 at 0x3990: `rcp_salt_valid[0] = false` → N=0, V=0
   - 0x3994 `bvs`: V=0 → NOT taken → continue ✓
   - 0x3996 `bmi`: N=0 → NOT taken → continue → execute salt init ✓
   - 0x3998 `rcp_salt_core0 r0, r1`: (opc1=8, CRm=0) matches → set
     `rcp_salt[0] = r[0]`, `rcp_salt_valid[0] = true`
   - 0x399c `rcp_salt_core1 r2, r3`: (opc1=8, CRm=1) matches → set
     `rcp_salt[1] = r[2]`, `rcp_salt_valid[1] = true`
   - 0x39a0 SEV: wakes Core 1
   - Core 1 next canary_status: `rcp_salt_valid[1] = true` → N=1 → `bpl`
     NOT taken → exit wait loop ✓
5. **rcp_canary_get behavior change** (documented): V3/V4's handler writes
   `bus.rcp_salt[core] ^ 0xDEAD_BEEF` into target register. Phase 4's
   silent-NOP handler left the target untouched. All bootrom call sites
   follow a get→store→check pattern that doesn't use the canary value in
   arithmetic, so the change is observable only to callers that hold the
   canary in a non-stack register across a function call boundary —
   which the bootrom does not do on the Phase 4 execution path. Document
   as a known behavior change; verify via Phase 4 regression run.

**Uncertainties to resolve during B2 implementation:**

- Cross-check the opc1 values against the pico-bootrom-rp2350 source tree
  if accessible. The `(opc1=8, CRm=0/1)` mapping is inferred from bootrom
  bytes (`fc41 0780` and `fc43 2781`) but should be verified against the
  assembler macro definition if possible.
- Verify MCRR2 Rt position at hw1[15:12] matches the ARMv8-M ARM (not
  RP2350-specific). The LLD's extraction is the ARM standard.
- LDC/STC with P=0 to CP7 shares the 0xEC/0xFC top byte. Not exercised
  by bootrom; the MCRR2 handler's silent-NOP fallthrough absorbs any
  accidental LDC/STC without fault or state change. Add a stricter check
  on `hw0[7:5] == 0b010` if robustness becomes necessary.

**Phase 4 regression test plan**: after implementing §2.11.2 (Stage B2),
re-run `test_flash_boot_blinky`. Expected: Core 0 still reaches flash and
sets GPIO 25 within the existing cycle budget; exact cycle count may
shift by tens of thousands of cycles due to Core 1's contention on ROM
fetches. If the stuck detector fires, first check
`emu.cores[1].regs.ipsr() != 0` — a Core 1 fault loop manifests as Core 0
progress stalling. If Core 0's final PC is wrong, trace the new RCP
handler's effect on flag state at 0x38bc / 0x3994 / 0x3996.

## 7. Known Limitations

- **No divider latency.** Immediate results. Cycle count off by up to 8 per division. Phase 8.
- **SIO divider presence on RP2350 unverified.** §2.4 assumes the RP2350 kept the SIO hardware divider from RP2040. Verify against datasheet; if absent, delete §2.4 and B3.
- **No interpolator computation.** Register store only. Phase 7.
- **GPIO_HI_OUT / GPIO_HI_OE.** Writes accepted and silently dropped; reads return 0.
- **No NVIC pending-bit storage.** Doorbell, MTIME, and FIFO register states round-trip, but IRQ delivery does NOT fire — `bus/ppb.rs` has no ISPR/ICPR backing store. Tests must observe state via direct field access.
- **MTIME does not wake WFE.** MTIME compare match latches `mtime_match_asserted` but does NOT set `event_flag` or NVIC. Programs using `MTIMECMP + WFE` for timed wakeups will sleep forever.
- **MTIME prescaler not modeled.** MTIME ticks once per system clock. `time_us_64()` advances faster than real.
- **WFI treated as NOP.** Bootrom uses WFE; WFI-based sleep (needs pending-IRQ check) not modeled.
- **Zero-latency FIFO.** Core 0's write is visible to Core 1 in the same emulator tick. SDK uses WFE/SEV synchronization so protocol correctness holds; relevant only for pathological polling loops.
- **Spinlock fairness.** Core 0 always wins contested claims (steps first). No deadlock.
- **RCP instructions are stubbed.** `rcp_canary_check` and `rcp_panic` are silent NOPs; `rcp_canary_get` returns `salt ^ 0xDEAD_BEEF` into the target register (changes caller-visible register state vs the current silent NOP, see §2.11.2); `rcp_canary_status pc` sets `N = rcp_salt_valid[core]` with Z=C=V=0; `rcp_iequal`, `rcp_bvalid`, `rcp_count_*` are silent NOPs. Only `rcp_salt_coreN` actually mutates cross-core state. **Silent assertions mask emulator bugs** — if the emulator miscomputes state that would hit a canary_check mismatch on silicon, the bug is hidden. For debugging, consider temporarily turning `rcp_panic` into a `UsageFault` to surface failing paths.
- **MCRR2 Rt2 discarded.** Only the first source register is stored to `rcp_salt`. Hardware treats salt as 64-bit; we collapse to 32-bit. Sufficient for salt validity; insufficient if any downstream code reads both halves.
- **Sub-word reads at GPIO_HI_IN advance the LFSR per call.** Reading 4 bytes from 0xD0000008–0x0B via individual `read8` calls yields 4 independent noise samples (not a coherent 32-bit view).
- **No TrustZone differentiation.** Secure and NS SIO aliases map to the same state.
- **PERI_NONSEC, TMDS, RISCV_SOFTIRQ registers not modeled.** Reads return 0, writes ignored.
- **CP0 GPIOC coprocessor unchanged.** Pure stub. Bootrom uses memory-mapped SIO.
- **NSACR writes silently ignored** (pre-existing).
- **Silent LDC/STC to CP7.** Top byte 0xEC/0xFC overlaps with LDC/STC P=0 encoding. Bootrom doesn't exercise this; MCRR2 handler's silent-NOP fallthrough absorbs any accidental LDC/STC without fault.

## 8. Risk Assessment

**Highest risk: §2.11.2 RCP rewrite affecting Core 0's bootrom path.**
V4's state-dependent model is designed to produce N=0, V=0 flags at Core
0's canary_status sites (before salt init), satisfying all three flag
checks (`bvc 38c0`, `bvs 39ac`, `bmi 39a2`). This is analytical — we
haven't traced the exact instructions preceding 0x38b8 and 0x3990 to
confirm that other flag-consuming branches downstream aren't affected by
the zeroed Z/C flags. **Mitigation**: Stage A1 includes the RCP handler
rewrite AND keeps Phase 4's `test_flash_boot_blinky` as the first gate.
If A1 can't pass Phase 4, the handler is wrong — iterate before
proceeding to A2. Expected fix path: adjust flag values or add per-site
handling of canary_check.

**Medium risk: `rcp_canary_get` register clobber behavior change.** V4's
handler writes `0xDEAD_BEEF` into the target register where Phase 4's
silent NOP left it untouched. Bootrom call sites use a get→store→check
pattern, so the change is not observable for stored/reloaded canaries.
But any function that holds the canary in a non-stack register across a
call boundary would see a caller-visible change. **Mitigation**: Phase 4
regression test catches it. If broken, switch the canary_get stub to a
no-op (leave rX unchanged) — this works because Phase 4 hasn't been
relying on the return value for anything.

**Medium risk: MCRR2 opc1/CRm mapping.** The `(opc1=8, CRm=0/1)` mapping
for `rcp_salt_core0/core1` is inferred from bootrom bytes, not cited from
the pico-bootrom-rp2350 source. **Mitigation**: cross-check during B2
implementation (the bootrom source is open). If opc1 differs, swap the
constants — ≤3 line fix.

**Medium risk: Test binary hand-assembly complexity.** ~150–300 lines of
Python hand-assembly. SDK launch protocol's restart-on-mismatch logic is
non-trivial. **Mitigation**: §5 fallback to Pico SDK build.

**Medium risk: SIO divider presence on RP2350.** Reviewer flagged
uncertainty about whether the SIO divider exists on RP2350 (may have been
removed in favor of a different mechanism). **Mitigation**: verify at
start of B3 via datasheet. If absent, skip B3 entirely.

**Low risk: SIO refactor.** PPB pattern is proven. 6 external references
to update (4 in tests.rs, 2 in mdrp2354-app). 4 dispatch-site mask fixes.

**Low risk: FIFO, spinlocks, doorbells, MTIME, interpolator stubs.**
Independent, self-contained, well-defined semantics. Each has unit tests.

**Low risk: WFE/SEV correctness.** Clean state model on Bus. Unit-testable
in isolation before B2.

**Pre-existing risk (documented): `active_core()` boolean hack.** Relies
on `contention_check_active` flip. Phase 5's wake check runs with the
flag left over from Core 1's step but never queries `active_core()`.
Any future cross-core logic added after Core 1's step must not assume
`active_core()` returns the correct value.
