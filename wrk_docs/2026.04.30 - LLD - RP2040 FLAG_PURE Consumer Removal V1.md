## Commit shape

Single commit, no amend. Subject and body proposal:

```
mdrp2040: drop unused FLAG_PURE consumer; gate classifier as test-only

The iter7 fast-path skip that consumed DecodedOp::FLAG_PURE was
attempted and reverted within noise (commit 2621534): +0.06% on
paced_bench_rp2040, +0.23% on picogus_diff_rp2040 — bench data in the
revert journal. The populate-side classifier kept running every cache
miss, writing a bit no one read. This drops the populate-time
classify, the FLAG_PURE constant, and the unused `is_pure()` accessor.

The four classifier helpers (`classify_is_pure`,
`classify_thumb16_pure`, `classify_thumb16_misc_pure`,
`classify_thumb32_pure`) are kept under `#[cfg(test)]` because
mutation-testing V3 Stream A (commit dabf3b3) lands ~28 dedicated
classifier tests on M0+ that use them as the decode oracle.
`#[cfg(test)]` removes them from the production build entirely while
preserving Stream A's coverage.

Closes D5 in
wrk_docs/2026.04.29 - Codebase Tech-Debt Sweep Report.md.
Design: wrk_docs/2026.04.30 - HLD - RP2040 FLAG_PURE Consumer
Removal V1.md. Implementation: wrk_docs/2026.04.30 - LLD - RP2040
FLAG_PURE Consumer Removal V1.md.
```

The HLD's suggested subject is reused unchanged. (I considered
`mdrp2040: remove unused FLAG_PURE bit; gate classifier #[cfg(test)]`
but the HLD's wording is fine and reuses the original audit-trail
phrasing.)

## Risks called out (deltas / additions vs. design HLD)

The design HLD §Risks names exactly one risk: future-sweep agents may
delete the `#[cfg(test)] fn classify_is_pure` as test-only dead code.
Mitigation is a doc-comment that explicitly references V3 Stream A.
This LLD's Edit 3 implements that mitigation in expanded form.

I see no additional risks worth surfacing:

- **No call-graph surprises.** Workspace-wide grep confirms M0+ has no
  production caller; the M33 sibling is out of scope.
- **No `is_wide` collateral.** `is_wide()` is `pub(crate)` and
  consumed by both the production path and the tests; it is not
  touched by this change.
- **No build-feature interactions.** Both `--features threading` and
  the default features compile with `cfg(test)` set during the test
  build, so Stream A's tests resolve in either configuration.
- **No `Cargo.toml` version bump needed** — neither
  `mdrp2040`'s nor any consumer crate's public API changes;
  `is_pure()` was `pub(crate)`. (Per CLAUDE.md "Version management":
  internal cleanup → no bump required because the file isn't a
  versioned manifest. The HLD doesn't request one either.)
- **No CLAUDE.md amendment required** — the HLD §Non-goals already
  rules this out and the closing reference in the commit body is
  sufficient.

The W2 agent's catch on the previous workstream (`Ppb lives on
CortexM33, not Bus`) was a structural mismatch between the design HLD
and the source tree. No analogous mismatch here — the design HLD's
file paths and line numbers all match the working tree, and the
referenced commits (`2621534`, `dabf3b3`, `42ee533`) all exist.
