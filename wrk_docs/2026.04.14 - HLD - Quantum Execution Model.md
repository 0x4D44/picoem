# Quantum Execution Model

Version: 1.0.0
Date: 2026-04-14

## Problem

`Emulator::step()` currently advances exactly one virtual cycle per call. For a
multi-cycle instruction the sequence is: decode+execute on the first cycle,
then N-1 calls that each do nothing but decrement `stall_cycles`
(`core/mod.rs:94-97`), with all of the scheduling surround — `clock.tick()`,
bus contention bookkeeping, PIO tick, SIO mtime, WFE/SEV check
(`lib.rs:127-156`) — paid on every one of those wasted cycles.

At ~1.5 cycles per average instruction plus a 9-cycle LDM and the per-cycle
scheduling tax, the step loop runs several times more than the instruction
stream requires. `paced_bench --dual-core` currently achieves ~74 MHz/core
against a 150 MHz target.

The architectural cost exists to keep cycle-level interleaving between the
two cores coherent for bank-contention modeling and for same-cycle
observability of cross-core effects. Neither actually pays off:

- Cross-core state (SIO, shared SRAM, NVIC raises) is already observed with
  up-to-1-cycle latency in practice. Firmware cannot distinguish that from
  up-to-N-cycle latency at moderate N.
- `DWT_CYCCNT` and `SysTick` return hardcoded `0` from `Ppb::read32`
  (`bus/ppb.rs:121`). Firmware has no observable cycle counter at all today,
  so whatever cycle precision we are "preserving" is invisible to it.
- Bank contention is modelled as "+1 cycle when core 1 hits the same
  downstream port core 0 just touched" (`bus/mod.rs:422-436`). Structurally a
  cycle-interleave-only approximation with no sensible analogue once cores
  are decoupled.

The current per-cycle model is paying for precision nobody can observe.

## Proposed change

Run both cores in fixed-size cycle **quanta**. Within a quantum each core
executes instructions atomically, accumulating its own cycle count.
Peripherals tick the full quantum at the boundary. Bank contention is
deleted. DWT and SysTick are wired to the real per-core cycle count.

Quantum size is a `u32` field on `Emulator` with a default of 64 cycles and a
builder setter, so benches can sweep it.

### `Emulator::step` (after)

```rust
pub fn step(&mut self) -> u64 {
    let target = self.clock.cycles + self.quantum_cycles as u64;

    // Each core runs until its own cycle count catches up to the target.
    // A multi-cycle instruction at the boundary may overshoot; the overshoot
    // carries forward — next quantum the core executes proportionally fewer
    // instructions until its cycles realigns with the clock.
    for core_id in 0..2 {
        while !self.cores[core_id].is_halted()
            && self.cores[core_id].cycles < target
        {
            self.cores[core_id].step(&mut self.bus);
        }
    }

    self.clock.advance(self.quantum_cycles as u64);
    self.tick_peripherals(self.quantum_cycles);
    self.tick_systick();
    self.wake_checks();
    self.clock.cycles
}
```

`run(cycles)` loops `step()` until `clock.cycles >= cycles` — already the
intended contract.

### `CortexM33::step` (after)

Executes one instruction atomically and advances the core's own cycle count
by the instruction's cycle cost. No `stall_cycles`.

```rust
pub fn step(&mut self, bus: &mut Bus) {
    if self.wfe_waiting || self.halted { return; }
    let mut cycles = self.decode_execute(bus);
    // ... existing bus-fault / pending-fault handling, which may replace
    //     `cycles` with the exception-entry cost — unchanged logic ...
    self.cycles += cycles as u64;
}
```

The `stall_cycles: u32` field is removed. `cycles: u64` replaces it. The
`saturating_sub(1)` at `core/mod.rs:127` goes away. The `stall_cycles()`
accessor is deleted. A `cycles()` accessor is added.

### Bank contention: deleted

Removed outright:

- Fields `Bus::core0_port`, `Bus::contention_check_active`
- Methods `Bus::clear_contention_state`, `Bus::begin_contention_check`,
  `Bus::check_contention`
- The six `contention = check_contention(addr); self.extra_wait_states +=
  contention` callsites in read/write paths
  (`bus/mod.rs:501, 578, 694, 778, 891, 967`)

`Bus::extra_wait_states` remains — still needed for APB latency bookkeeping,
unaffected by this change.

If a probe-side workload ever identifies a case where absent contention
changes observable firmware behavior, reintroduce as an aggregated
per-quantum adjustment then — not speculatively.

### DWT wiring

Per-core, on `CortexM33`:

```rust
dwt_ctrl: u32,        // bit [0] CYCCNTENA
dwt_cyccnt_base: u32, // reads return (cycles as u32).wrapping_add(base)
demcr: u32,           // bit [24] TRCENA
```

New cases in `Ppb::read32` / `write32` at DWT addresses (`0xE000_1000` CTRL,
`0xE000_1004` CYCCNT) and DEMCR (`0xE000_EDFC`).

Read of CYCCNT returns `(core.cycles as u32).wrapping_add(dwt_cyccnt_base)`
iff `DEMCR.TRCENA` and `DWT_CTRL.CYCCNTENA`, else `dwt_cyccnt_base`
(whatever was last written — typically 0).

Write to CYCCNT sets `dwt_cyccnt_base = written.wrapping_sub(core.cycles as
u32)`, so the next read returns `written + (cycles elapsed since the write)`.

### SysTick wiring

Per-core, 24-bit down-counter. `Ppb` gains:

```rust
syst_csr: u32,           // [0] ENABLE, [1] TICKINT, [2] CLKSOURCE, [16] COUNTFLAG
syst_rvr: u32,           // 24-bit reload value
syst_cvr: u32,           // 24-bit current value
last_systick_cycles: u64 // per-core snapshot of cores[i].cycles at last tick
```

At quantum end `tick_systick` is called for each enabled SysTick:

```rust
let delta = (core.cycles - ppb.last_systick_cycles) as u32;
ppb.last_systick_cycles = core.cycles;
if ppb.syst_csr & ENABLE == 0 { return; }

let mut rem = delta;
loop {
    if rem <= ppb.syst_cvr {
        ppb.syst_cvr -= rem;
        break;
    }
    rem -= ppb.syst_cvr + 1;
    ppb.syst_cvr = ppb.syst_rvr & 0xFFFFFF;
    ppb.syst_csr |= COUNTFLAG;
    if ppb.syst_csr & TICKINT != 0 {
        core.ppb_pend_systick();
    }
}
```

Reading CVR returns `syst_cvr` and clears COUNTFLAG. Writing CVR clears both
`syst_cvr` and COUNTFLAG (hardware spec).

`CLKSOURCE` (ref clock at half rate) is deferred — initial implementation
treats both sources as system clock. Add a `TODO` comment; wire up when
firmware needs it.

### Peripheral quantum tick

```rust
fn tick_peripherals(&mut self, cycles: u32) {
    let gpio_in = self.bus.gpio_in;
    for pio in &mut self.bus.pio { pio.step_n(cycles, gpio_in); }
    self.update_gpio();
    self.bus.sio.tick_mtime_n(cycles);
}

fn wake_checks(&mut self) {
    for i in 0..2 {
        if self.cores[i].wfe_waiting && self.bus.event_flag[i] {
            self.bus.event_flag[i] = false;
            self.cores[i].wfe_waiting = false;
        }
    }
}
```

`Pio::step_n` and `Sio::tick_mtime_n` are new n-cycle variants:

- `Sio::tick_mtime_n(n)`: `self.mtime = self.mtime.wrapping_add(n as u64);`
- `Pio::step_n(n, gpio_in)`: initial implementation is `for _ in 0..n {
  self.step(gpio_in); }`. A bulk-advance optimization is future work if PIO
  appears hot in a flamegraph; loop version has no correctness risk.

## What does NOT change

- Instruction semantics. Every opcode handler in `execute.rs`,
  `execute_thumb32.rs`, `execute_fpu.rs` already returns its cycle count. No
  handler changes.
- `execute_one` / `execute_one_with_bus` / `execute_one_wide` /
  `execute_one_wide_with_bus` — used by unit tests, `qemu_diff`, and
  `probe_diff`. Still single-instruction, still return cycle count.
- Per-instruction bus cycle accounting, APB latency
  (`Bus::extra_wait_states`), wait-state reset per instruction.
- Exception entry, EXC_RETURN, fault handling mechanics.
- IT-block state, security state transitions.
- Fast-path bus read, condition-passed optimization, skip-halted-core
  optimization (reshaped to fit the quantum loop: halted cores fail the
  `while` predicate and are skipped naturally).
- `Pacer` — already measures by emulated cycles.

## Non-goals

- No bank contention model.
- No sub-quantum interrupt delivery precision. Timer/NVIC events observed up
  to one quantum late. WFE wake likewise.
- No SysTick `CLKSOURCE=0` (ref clock) scaling. Deferred.
- No dynamic quantum tuning. Single configurable constant.
- No feature flags, no env vars, no rollback. The old per-cycle path is
  deleted, not gated.

## Impact on existing tests

- **Unit tests in `core/tests.rs`.** One reference to `c.stall_cycles()` at
  line 846. Replace with `c.cycles()` or delete — the assertion was checking
  the stall counter resets, which is no longer a meaningful thing to test.
- **`qemu_diff`, `probe_diff`.** Zero impact. Both use `execute_one*` entry
  points, which are already per-instruction and unaffected.
- **`paced_bench`, `full_test`.** Go through `Emulator::step` /
  `Emulator::run`. Each `step()` call now advances by the quantum, not
  1 cycle. `run(cycles)` contract unchanged.
- **New unit tests added in commit 2:** DWT CYCCNT read-after-write,
  CYCCNTENA gate, DEMCR.TRCENA gate, SysTick underflow count, COUNTFLAG
  read-clears, TICKINT pends exception.

## Risks

- **WFE/WFI wake latency up to 1 quantum.** Q=64 at 150 MHz ≈ 430 ns.
  Firmware busy-waiting on a timer or NVIC event with sub-400-ns expectations
  will see a change. No known current user.
- **Overshoot accounting.** A 33-cycle LDM starting at core.cycles=60 leaves
  core.cycles=93 when the quantum target was 64. Next quantum the core
  executes proportionally fewer instructions until cycles realigns with
  clock. Over many quanta the rate averages 1:1. Correct, but
  counter-intuitive — needs a comment in the step loop.
- **PIO `step_n` loop implementation.** Naive loop preserves all cross-cycle
  state; only a bulk-advance rewrite could introduce bugs, and that is out of
  scope here.
- **SysTick per-core edge cases.** Multi-reload within one quantum handled by
  the `loop`. Underflow when disabled: don't tick. Write to CVR during
  quantum: handled at register-write time (clear cvr + COUNTFLAG); next tick
  computes delta from the new snapshot.

## Commit plan

Two commits for reviewability. Each commit compiles and passes tests in isolation.

1. **Quantum refactor + delete contention.** Core + bus + emulator + peripheral
   n-cycle variants + test fixup. Validate with full unit-test run +
   `qemu_diff --fuzz 100000` + a `paced_bench` perf check.
2. **DWT + SysTick wiring.** PPB register additions + quantum-end
   `systick_advance` call. Unit tests listed above.

## Success criteria

- All unit tests green.
- `qemu_diff --fuzz 100000` green (no regression — this oracle is unaffected,
  so any delta is a bug we introduced).
- `paced_bench --dual-core` shows measurable improvement over 74 MHz/core
  baseline. Target: first pass ≥ 90 MHz/core. Hitting 150 MHz/core is not
  expected from this change alone.
- DWT CYCCNT and SysTick CVR return live cycle counts to firmware.

## Relation to the threaded dual-core HLD

The threaded HLD (`2026.04.14 - HLD - Threaded Dual-Core Emulation.md`)
assumes a quantum-based per-core loop: `for 0..Q { core.step() }`. This
refactor establishes exactly that shape in single-threaded form. Landing this
first simplifies the threaded work — the worker loop body becomes the inner
`while cycles < target` from above.
