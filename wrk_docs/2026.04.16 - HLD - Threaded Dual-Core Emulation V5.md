# Threaded Dual-Core Emulation

Version: 5.0.0
Date: 2026-04-16
Supersedes: V4 (2026-04-14)

## Problem

Dual-core paced throughput on a 3 GHz host: **73.8 MHz per core** (49% of
150 MHz target). Single-core is 143.8 MHz (96%). The 2× gap comes from
sequentially executing both cores in one host thread.

## Target

**Realistic ceiling: ~105–125 MHz per emulated core** (70–83% of 150 MHz).

Model:
- Single-core baseline: 143 MHz (21 host cycles/emu cycle)
- Four host threads: Core 0, Core 1, PIO, Coordinator
- Per-quantum overheads: SpinBarrier ×2 (~100 ns total), coordinator
  phase (~100–200 ns), arrival skew between threads
- Efficiency depends heavily on quantum size Q (see §Quantum sizing)

Phase 0c micro-prototype measures real primitive costs before we commit
to full integration.

**Success criterion:** `paced_bench --threaded --dual-core` achieves
≥105 MHz per core on the synthetic workload. Threshold aligned with
model's lower bound — not aspirational.

## Quantum sizing

Q (cycles per quantum) controls the fidelity/throughput trade-off.
Smaller Q = tighter cross-domain timing. Larger Q = less barrier
overhead per emulated cycle.

Estimated per-core efficiency at various Q values (4 active PIO SMs,
non-pipelined, ~100 ns barrier overhead, ~150 ns coordinator phase):

| Q | Est. efficiency | Est. MHz/core |
|---|---|---|
| 32 | ~45% | ~64 |
| 64 | ~57% | ~81 |
| 128 | ~70% | ~100 |
| 256 | ~80% | ~114 |

Q=32 is the **minimum-correctness bound** — the finest granularity
we support. Operating point will be Q=128–256, tuned during Phase 5
against the synthetic workload. The micro-prototype (Phase 0c)
replaces these napkin estimates with measurements.

**Pipelining** (coordinator processes quantum N−1 while others run
quantum N) would recover ~5–7% efficiency. Deferred to post-V5 —
adds IRQ delivery latency complexity for modest gain.

## Host assumptions

| Concern | Assumption | Rationale |
|---|---|---|
| Host CPU | x86_64 | `Pacer` requires `rdtsc`/`rdtscp` + `constant_tsc`. |
| Host OS | Windows | Thread pinning via `SetThreadAffinityMask`. |
| Host cores | ≥ 5 physical | 4 pinned workers + OS. Detect at startup; error on < 4. |
| Memory model | TSO | x86 SeqCst fences are cheap. Relaxed loads are plain `mov`. |

`ThreadedEmulator` gates to `#[cfg(all(target_arch = "x86_64",
target_os = "windows"))]`.

## Non-goals

- No per-cycle bus contention in threaded mode (documented trade-off).
- No hybrid mode — single-threaded OR threaded per invocation.
- No dynamic thread count.
- No env vars, no feature flags.
- No `ThreadedEmulator → Emulator` reverse conversion.
- No pipelining in V1.
- No `mdrp2354-app` threaded mode in V1 (paced_bench only).

## Thread topology

Four threads, each pinned to a physical host core:

```
  ┌─────────────────────┐  ┌─────────────────────┐
  │ Worker 0 (Core 0)   │  │ Worker 1 (Core 1)   │
  │ for 0..Q {          │  │ for 0..Q {          │
  │   core0.step(bus)   │  │   core1.step(bus)   │
  │ }                   │  │ }                   │
  └──────────┬──────────┘  └──────────┬──────────┘
  ┌──────────┴──────────┐  ┌──────────┴──────────┐
  │ Worker 2 (PIO)      │  │ Worker 3 (Coord.)   │
  │ for 0..Q {          │  │ (idle during exec)  │
  │   pio.step_all(gpio)│  │                     │
  │ }                   │  │                     │
  └──────────┬──────────┘  └──────────┬──────────┘
             │                        │
         ════╧════════════════════════╧════  Barrier 1
             │
  ┌──────────┴─────────────────────────────────────┐
  │ Coordinator phase (worker 3 only; 0/1/2 idle)  │
  │  1. Timer ticks (SysTick, TIMER0/1, watchdog)  │
  │  2. SIO: MTIME advance, divider/interp tick    │
  │  3. Doorbell → peer NVIC atomic write          │
  │  4. DMA step (all active channels)             │
  │  5. Peripheral step (UART, SPI, I2C, ADC, PWM) │
  │  6. IRQ delivery: peripheral → NVIC atomics    │
  │  7. WFI wake check per core                    │
  │  8. Dual-WFI deadlock → ExitReason::BothWfi    │
  │  9. Pacer spin-wait                            │
  │ 10. Check stop signal                          │
  └──────────┬─────────────────────────────────────┘
             │
         ════╧════  Barrier 2 (all resume)
```

Workers 0–2 spin-wait at barrier 2 during the coordinator phase.
Coordinator (worker 3) spin-waits at barrier 1 during the execution
phase. This is the accepted overhead — pipelining is a future
optimization.

## SpinBarrier (4-way, flat)

```rust
pub struct SpinBarrier {
    generation: AtomicU32,
    count:      AtomicU32,
    parties:    u32,          // = 4
    poisoned:   AtomicBool,
}

pub enum BarrierResult { Released, Poisoned }

impl SpinBarrier {
    pub fn wait(&self) -> BarrierResult {
        if self.poisoned.load(Acquire) { return Poisoned; }
        let gen = self.generation.load(Acquire);
        let n = self.count.fetch_add(1, AcqRel) + 1;
        if n == self.parties {
            self.count.store(0, Relaxed);
            self.generation.store(gen.wrapping_add(1), Release);
        } else {
            loop {
                if self.poisoned.load(Acquire) { return Poisoned; }
                if self.generation.load(Acquire) != gen { break; }
                std::hint::spin_loop();
            }
        }
        Released
    }
    pub fn poison(&self) { self.poisoned.store(true, Release); }
}
```

Target: <100 ns ready-to-ready per crossing. Two crossings per quantum.

## State ownership

### Per-thread ownership

| State | Owner | Access from other threads |
|---|---|---|
| `CortexM33` core 0 (regs, stall, IT, faults, DCP, RCP) | Worker 0 | None |
| `CortexM33` core 1 | Worker 1 | None |
| `Ppb` core 0 (SCB, MPU, SAU, SysTick, FPCCR) | Worker 0 | None |
| `Ppb` core 1 | Worker 1 | None |
| `PioBlock[3]` (instruction mem, SM state, clock dividers) | Worker 2 | CPU MMIO via lock-free FIFOs + atomic control |
| Timers, DMA, APB peripherals | Worker 3 | CPU MMIO via sharded mutexes |

### Shared state (atomic / lock-free)

| State | Type | Readers | Writers |
|---|---|---|---|
| SRAM (520 KB) | `Box<[AtomicU32]>` | All | Workers 0/1, coordinator (DMA) |
| ROM (32 KB) | `Box<[u8]>` | All | None (immutable) |
| XIP flash | `Box<[u8]>` | All | None (immutable after load) |
| GPIO pins (48) | `[AtomicU32; 2]` | All | Workers 0/1 (SIO CP0), worker 2 (PIO), coordinator |

## Bus decomposition

The single-threaded `Bus` is a monolith. Threading decomposes it:

```rust
/// Shared across all threads. Cheap to clone (all Arc).
pub struct SharedState {
    memory:    Arc<SharedMemory>,    // SRAM + ROM + XIP
    gpio:      Arc<AtomicGpio>,      // [AtomicU32; 2]
    sio:       Arc<ThreadedSio>,     // FIFOs, spinlocks, doorbells, MTIME
    pio:       Arc<ThreadedPio>,     // lock-free FIFOs + atomic control
    peripherals: Arc<Peripherals>,   // sharded mutexes
    nvic:      Arc<SharedNvic>,      // atomic ISPR/ICPR/IABR per core
    monitors:  Arc<ExclusiveMonitors>,
    cores:     Arc<CoreFlags>,       // halted, wfe_waiting, event_flag
}

/// Per-CPU-thread bus view. Wraps SharedState + per-core PPB.
pub struct WorkerBus {
    core_id: CoreId,
    shared:  SharedState,
    ppb:     Ppb,                    // per-core, NOT shared
}

/// PIO thread's bus view. Reads/writes atomic GPIO, FIFOs, IRQ flags.
pub struct PioBus {
    shared: SharedState,
}

/// Coordinator's bus view. Owns timers, DMA, peripheral structs.
pub struct CoordinatorBus {
    shared:      SharedState,
    timers:      Timers,             // SysTick (both cores), TIMER0/1
    dma:         Dma,
    uart0:       UartRegs,
    spi0:        SpiRegs,
    i2c0:        I2cRegs,
    adc:         AdcRegs,
    pwm:         PwmRegs,
    ticks:       TicksRegs,
    clock_tree:  ClockTree,
}
```

`WorkerBus::read32(addr)` / `write32(addr, val)` dispatches:
- SRAM/ROM/XIP → `shared.memory` atomic ops
- SIO → `shared.sio` atomic ops
- PIO MMIO → `shared.pio` lock-free FIFO push/pop + atomic control
- Peripheral MMIO → `shared.peripherals` mutex acquire
- PPB → `self.ppb` (local, no sync)
- GPIO CP0 → `shared.gpio` atomic ops

## SharedMemory

```rust
pub struct SharedMemory {
    sram: Box<[AtomicU32]>,     // 130K words = 520 KB
    rom:  Box<[u8]>,            // 32 KB, read-only
    xip:  Box<[u8]>,            // flash image, read-only after load
}
```

- `read32`: atomic load (Relaxed)
- `read16`/`read8`: word load + shift/mask
- `write32`: atomic store (Relaxed) + `snoop_exclusive`
- `write16`/`write8`: CAS loop (load word, mask, store) + `snoop_exclusive`
- `cas32(addr, expected, new) -> bool`: for STREX

## Atomic GPIO

```rust
pub struct AtomicGpio {
    out: [AtomicU32; 2],   // pins 0–31, 32–47
    oe:  [AtomicU32; 2],   // output enable
}
```

All access via Relaxed atomics — on x86 these compile to plain `mov`.
Zero staleness: PIO reads current pin state every cycle, CPUs see
PIO-driven pin changes immediately. No buffering, no quantum delay.

GPIO input merging: each writer (SIO CP0, PIO pad_out, external
stimulus) does atomic read-modify-write on the relevant bits. The
coordinator merges `oe` masks at quantum boundary for conflict
detection (two drivers on one pin = bus fight, logged as warning).

## LDREX / STREX

Per-core `exclusive_address: Option<u32>` + `exclusive_value: u32`
on `CortexM33`. Exclusive monitors as `[AtomicU64; 2]` encoding
tag + valid bit.

```rust
// LDREX rX, [rY]
core.exclusive_address = Some(addr);
core.exclusive_value   = shared_memory.read32(addr);
rX = core.exclusive_value;

// STREX rZ, rX, [rY]
if core.exclusive_address != Some(addr) {
    rZ = 1;  // monitor invalidated by peer
    return;
}
match shared_memory.cas32(addr, core.exclusive_value, rX) {
    true  => { rZ = 0; snoop_invalidate_all(addr); }
    false => { rZ = 1; }
}
core.exclusive_address = None;
```

`snoop_invalidate_all(addr)` clears both monitors on every write.
Two cores racing STREX: both call CAS with their captured values;
exactly one wins.

## ThreadedSio

```rust
pub struct ThreadedSio {
    // Inter-core FIFOs (rtrb lock-free SPSC queues)
    fifo_0to1_prod: rtrb::Producer<u32>,
    fifo_0to1_cons: rtrb::Consumer<u32>,
    fifo_1to0_prod: rtrb::Producer<u32>,
    fifo_1to0_cons: rtrb::Consumer<u32>,

    // Sticky status per core
    fifo_st: [AtomicU32; 2],

    // Spinlocks
    spinlocks: [AtomicU32; 32],

    // Doorbells
    doorbells: [AtomicU32; 2],

    // Per-core divider/interpolator (only owning core accesses)
    div_state:  [Divider; 2],
    interp:     [[u32; 32]; 2],

    // Machine timer (coordinator advances, CPUs read)
    mtime:      AtomicU64,
    mtime_ctrl: AtomicU32,
    mtimecmp:   [AtomicU64; 2],
}
```

`rtrb` is the sole new dependency — vendored, single-purpose
lock-free SPSC queue. Capacity 8 entries per FIFO (matches hardware).

Doorbell propagation: CPU writes `doorbells[peer]` atomically.
Coordinator reads at quantum boundary, writes peer NVIC atomic.
Latency: up to 1 quantum.

Divider and interpolator are per-core, accessed only by the owning
CPU thread — no atomics needed. Coordinator does NOT tick these;
results are computed inline on write (matching real hardware's
single-cycle SIO semantics).

## ThreadedPio

```rust
pub struct ThreadedPio {
    // PIO blocks owned by PIO thread (NOT shared)
    // Stored separately, handed to PIO thread at spawn

    // Lock-free FIFOs: CPU pushes TX, PIO pops TX; PIO pushes RX, CPU pops RX
    tx_fifos: [[rtrb::Producer<u32>; 4]; 3],  // CPU side
    rx_fifos: [[rtrb::Consumer<u32>; 4]; 3],  // CPU side
    // (PIO thread holds the other ends)

    // Atomic control (CPU writes, PIO reads each cycle)
    sm_enabled: [AtomicU8; 3],     // per-block SM enable mask
    irq_flags:  [AtomicU8; 3],     // PIO writes, coordinator reads

    // DREQ signals (PIO writes, coordinator reads for DMA)
    dreq:       [AtomicU8; 3],     // 4 TX + 4 RX bits per block
}
```

PIO thread loop:
1. Read `sm_enabled` atomics to know which SMs are active
2. For each active SM: read GPIO via `AtomicGpio`, execute PIO
   instruction, write GPIO via `AtomicGpio`, pop/push lock-free FIFOs
3. Update `irq_flags` and `dreq` atomics

CPU MMIO writes to PIO control registers (clock dividers, pin
mappings, instruction memory) are **infrequent** (setup-time only).
These use a small atomic command queue: CPU pushes a `PioCommand`
enum, PIO thread drains at start of each quantum.

```rust
pub enum PioCommand {
    WriteInstrMem { block: u8, addr: u8, value: u16 },
    SetClkDiv { block: u8, sm: u8, int_div: u16, frac_div: u8 },
    SetPinMapping { block: u8, sm: u8, mapping: PinMapping },
    // ... other infrequent control register writes
}
```

This avoids mutexing the PioBlock internals. Hot-path FIFO access
is lock-free. Cold-path control is queued.

## Peripheral access from CPU threads

```rust
pub struct Peripherals {
    apb:    Mutex<ApbPeripherals>,   // UART, SPI, I2C, ADC, PWM
    clocks: Mutex<ClocksPll>,
    qmi:    Mutex<QmiRegs>,
    resets: Mutex<ResetsState>,
}
```

**Lock order: `clocks < qmi < resets < apb`.** Matches boot sequence.

Enforcement via `PeripheralGuard` RAII wrapper with thread-local
lock stack:

```rust
thread_local! {
    static LOCK_STACK: RefCell<[u8; 4]> = RefCell::new([0; 4]);
    static LOCK_DEPTH: Cell<u8> = Cell::new(0);
}

pub struct PeripheralGuard<'a, T> {
    inner: MutexGuard<'a, T>,
    level: u8,
}

impl<'a, T> PeripheralGuard<'a, T> {
    fn acquire(mutex: &'a Mutex<T>, level: u8) -> Self {
        LOCK_STACK.with(|s| {
            let depth = LOCK_DEPTH.with(|d| d.get());
            if depth > 0 {
                let stack = s.borrow();
                let top = stack[(depth - 1) as usize];
                assert!(level > top, "lock order violation: {} <= {}", level, top);
            }
        });
        let inner = mutex.lock().unwrap();
        LOCK_STACK.with(|s| {
            let depth = LOCK_DEPTH.with(|d| d.get());
            s.borrow_mut()[depth as usize] = level;
            LOCK_DEPTH.with(|d| d.set(depth + 1));
        });
        Self { inner, level }
    }
}

impl<'a, T> Drop for PeripheralGuard<'a, T> {
    fn drop(&mut self) {
        LOCK_DEPTH.with(|d| d.set(d.get() - 1));
    }
}
```

CPU threads take peripheral mutexes for individual MMIO reads/writes.
Coordinator takes them during the coordinator phase for `tick()`.
Contention is rare: CPU peripheral MMIO is infrequent relative to
memory/SIO/PIO access.

## WFI / halt semantics

```rust
// WFI execution in core step:
core.halted.store(true, Release);
return;

// Worker loop:
loop {
    for _ in 0..Q {
        if core.halted.load(Acquire) { break; }
        core.step(bus);
    }
    barrier.wait();  // barrier 1
    barrier.wait();  // barrier 2
}

// Coordinator wake check:
for id in 0..2 {
    if cores[id].halted.load(Acquire)
       && nvic[id].any_pending_enabled() {
        cores[id].halted.store(false, Release);
    }
}
if both_halted && !any_progress_source(remaining) {
    return ExitReason::BothWfi;
}
```

"Progress source" = any timer armed within remaining duration, any
DMA channel active, any PIO SM enabled. Not just timers — any
source that could eventually raise an IRQ.

## API

```rust
#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
pub struct ThreadedEmulator { ... }

impl ThreadedEmulator {
    /// One-way conversion. Decomposes Emulator into shared state.
    pub fn from_emulator(emu: Emulator) -> Self;

    /// Run until duration expires or a stop condition is hit.
    pub fn run(
        &mut self,
        pacer: &mut Pacer,
        duration: Duration,
        stop: Arc<StopSignal>,
    ) -> ExitReason;

    /// Stop workers, reset all state, restart workers.
    pub fn reset(&mut self);

    /// Read-only access to core state (for UI/debugger).
    pub fn core(&self, id: CoreId) -> &CortexM33;

    /// Quantum size (tunable).
    pub fn set_quantum(&mut self, q: u32);
}

pub enum ExitReason {
    Duration,
    Stopped,
    BothWfi,
    Breakpoint { core: CoreId, pc: u32 },
    EmulatorError { core: CoreId, reason: StopReason },
    Panic(String),
}

pub struct StopSignal(AtomicBool);
impl StopSignal {
    pub fn new() -> Arc<Self>;
    pub fn stop(&self);
    pub fn is_stopped(&self) -> bool;
}
```

`from_emulator` consumes `Emulator`, decomposes `Bus` into shared
state, moves cores and PPBs into worker-local storage. No reverse
conversion.

`reset()` poisons the barrier, joins worker threads, resets all
shared state to power-on defaults, respawns workers.

`ExitReason::EmulatorError` uses the existing `StopReason` enum.

## Shutdown + panic handling

**Clean shutdown:** coordinator sees `stop.is_stopped()` → calls
`barrier.poison()` before its barrier 2 arrival. All workers see
`Poisoned` and exit.

**Panic:** `catch_unwind` around each worker's loop body. On panic:
1. `stop_signal.stop()`
2. `barrier.poison()`
3. Store payload in `Arc<Mutex<Option<String>>>`
4. Worker exits

`ThreadedEmulator::run` joins threads, returns `ExitReason::Panic`
if payload present.

## Implementation phases

### Phase 0a — Workload study (2 weeks)

Unchanged from V4. Instrumentation + synthetic dual-core workload +
compound decision gate. Proceed only if core 1 active ≥20%, cross-core
SRAM writes <10%.

### Phase 0b — Prerequisite refactors (3–4 weeks)

Dependency chain:

```
0b.1 PPB move  →  0b.2 LDREX/STREX  →  0b.3 atomize cross-core + NVIC
     (1 wk)           (1 wk)                (4 days)
```

**0b.1 Move PPB to CortexM33.** Delete `Bus::active_core()`. Every
bus method takes `CoreId`. Move `rcp_salt`/`rcp_salt_valid` to
`CortexM33`. ~62 call sites — mechanical, guided by type errors.

**0b.2 LDREX/STREX.** Per-core exclusive monitor on `CortexM33`.
CAS on shared memory. Snoop on all writes.

**0b.3 Atomize.** `halted`, `wfe_waiting`, `event_flag` → `AtomicBool`.
NVIC `ispr`/`icpr`/`iabr` → `[AtomicU32; 8]`.

All three are independently valuable for correctness regardless of
whether threading proceeds.

### Phase 0c — Primitives micro-prototype (2–3 days)

Runs **in parallel** with Phase 0b. Standalone binary measuring:
1. 4-way SpinBarrier round-trip latency
2. `AtomicU32` shared-memory read/write throughput under contention
3. Masked CAS loop (byte/halfword write) cost under contention
4. Lock-free queue (rtrb) push/pop throughput
5. `Mutex` lock/unlock cycle time

Replaces napkin estimates with measurements. Feeds into Phase 5
quantum tuning. If barrier latency is >500 ns, revisit the entire
threading approach before committing to Phases 1–5.

### Phase 1 — SharedMemory + AtomicGpio + exclusive monitors (1 week)

`SharedMemory` struct with AtomicU32 SRAM. `AtomicGpio` struct.
`ExclusiveMonitors` with CAS. Unit tests for all access patterns.

### Phase 2 — SpinBarrier + ThreadedSio + ThreadedPio (1–2 weeks)

SpinBarrier (4-way). ThreadedSio with rtrb FIFOs and atomic fields.
ThreadedPio with lock-free FIFOs, atomic control, PioCommand queue.
Loom tests for barrier, exclusive snoop, doorbell propagation.

### Phase 3 — ThreadedEmulator + WorkerBus + worker loop (1–2 weeks)

Bus decomposition: `SharedState`, `WorkerBus`, `PioBus`,
`CoordinatorBus`. `ThreadedEmulator::from_emulator` decomposition.
4-thread worker loop. Thread pinning.

TSan validation on platform-neutral primitives (SpinBarrier,
SharedMemory, ThreadedSio, ThreadedPio) via Linux build of those
types only.

### Phase 4 — Pacer + StopSignal + ExitReason + reset + panic (1 week)

Integration with existing `Pacer`. Shutdown protocol. Panic handling.
`ThreadedEmulator::reset()`.

### Phase 5 — WFI, benchmark, quantum tuning (1 week)

WFI/halt semantics in worker loop. `paced_bench --threaded --dual-core`.
Tune Q against synthetic workload. Measure per-quantum overhead
breakdown.

**Total: 10–12 weeks.** Phases 0a and 0c run in parallel.

## Validation

1. **Single-threaded tests continue to pass.** Phases 0a–0b are
   additive; no existing test changes semantics.
2. **Loom tests** (Phase 2): SpinBarrier, exclusive snoop, doorbell,
   SIO FIFO, PIO FIFO.
3. **Dual-run differential test.** Same firmware under `Emulator` and
   `ThreadedEmulator`. Compare observable state at sync points.
   Cycle counts WILL differ.
4. **TSan** (Phase 3): platform-neutral primitives only. Build those
   types for Linux (no cfg gate on primitives), run under TSan.
5. **QEMU differential**, extended to threaded mode.
6. **Benchmark:** `paced_bench --threaded --dual-core` on synthetic.

## Rollback policy

Phase 5 criterion: ≥105 MHz per core on synthetic workload.

- **<105 MHz:** revert Phases 3–5. Phases 0a–2 stay — PPB move,
  LDREX/STREX, atomics, shared memory types, threaded SIO/PIO
  primitives are all independently useful. Pivot to decode cache.
- **≥105 MHz:** ship.

No feature flags. Keep or delete.

## Risks

1. **Phase 0a gate fails.** Synthetic workload doesn't justify
   threading. Shelve; decode cache becomes follow-up.
2. **Phase 0c shows prohibitive primitive costs.** Barrier >500 ns
   or atomic contention >30%. Shelve.
3. **Bus decomposition harder than estimated.** The monolithic `Bus`
   touches everything. Phase 3 is the highest-risk phase.
4. **PIO thread overhead.** Lock-free FIFOs + atomic GPIO + command
   queue may cost more than direct PioBlock::step in coordinator.
   Phase 5 measures this; fallback is folding PIO back into
   coordinator.
5. **Q too large for PIO fidelity.** If Q=256 is needed for
   throughput but breaks PIO protocol timing, we have a conflict.
   Mitigation: PIO uses atomic GPIO (zero staleness for pin I/O),
   so Q only affects FIFO/control latency, not pin timing.
6. **`rtrb` audit.** Single new dependency. Review during Phase 2.
7. **Low-core host.** < 4 cores = error at startup. Documented.
