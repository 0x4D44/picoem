## §3 Per-item design

### §3.1 SYSINFO CHIP_ID literal

**Current** (`bus/peripherals.rs::sysinfo_read`): returns
`0x0000_524D` for offset 0x00. This came from the pico-sdk
`SYSINFO_CHIP_ID_RESET` header literal, which is a documentation
mnemonic ('R','M' — "Raspberry Microcontroller"), NOT the
runtime silicon constant.

**Silicon ground truth** (V11 Stage 6, probe `E46410955F614129`):
HW returns `0x0000_4927` masked at `0x0FFF_FFFF`. Field decode:

- MANUFACTURER [11:0] = `0x927` (Raspberry Pi)
- PART [27:12] = `0x0004` (RP2354)
- REVISION [31:28] = masked out (varies by die)

Full register value = `0x0004_0927` (REV nibble depends on the
die — silicon scenario mask deliberately ignores it).

**Target**: `bus/peripherals.rs::sysinfo_read` returns
`0x0004_0927` for offset 0x00. Mask in
`silicon_scenarios.rs::sysinfo_readonly_fields` stays at
`0x0FFF_FFFF` (already correct).

**Unit test**: existing
`sysinfo_reads_hardcoded_readonly_fields` updates its
expected literal.

**Silicon scenario**: no change to the scenario itself;
`sysinfo_readonly_fields` will go GREEN once the literal is
right.

### §3.2 POWMAN INTE gating

**Current** (`peripherals/powman.rs::advance`, lines 416-467):

```rust
if count >= alarm && (self.timer & TIMER_ALARM_ENAB_BIT) != 0 {
    self.timer &= !TIMER_ALARM_ENAB_BIT;
    self.timer |= TIMER_ALARM_BIT;
    self.intr |= INT_TIMER_BIT;
    return 1u64 << IRQ_POWMAN_IRQ_TIMER;  // ← raises unconditionally
}
```

The comment at lines 201-205 explicitly noted that we chose NOT
to gate on INTE during V11; that was the wrong call. Silicon
gates the NVIC line on `INTE.TIMER` in addition to NVIC ISER.
Without `INTE.TIMER` set, the alarm event latches in INTR but
the NVIC line never asserts.

**Target**: still set `INTR.TIMER` and `TIMER.ALARM` on count
reaching alarm (those are unconditional latch events on
silicon). But gate the NVIC raise on `INTE.TIMER`:

```rust
if count >= alarm && (self.timer & TIMER_ALARM_ENAB_BIT) != 0 {
    self.timer &= !TIMER_ALARM_ENAB_BIT;
    self.timer |= TIMER_ALARM_BIT;
    self.intr |= INT_TIMER_BIT;
    if (self.inte & INT_TIMER_BIT) != 0 {
        return 1u64 << IRQ_POWMAN_IRQ_TIMER;
    }
}
0
```

Also: when firmware later sets `INTE.TIMER` while
`INTR.TIMER` is already latched, the NVIC line should
re-assert. This is a level-sensitive output on silicon. To
keep the change minimal, wire the re-assertion through the
existing `tick_peripherals` path: `write32(INTE_OFFSET, ...)`
returns the same `1u64 << IRQ_POWMAN_IRQ_TIMER` mask if the
write transitions `(intr & inte) & INT_TIMER_BIT` from 0 to
non-zero. `Bus::tick_peripherals` already folds `advance`'s
return into `raise_irqs_u64`; extend it to also fold the
return of POWMAN MMIO writes that transition INTS.

**Unit tests** (added):
- `powman_match_does_not_pend_nvic_when_inte_timer_clear` —
  drive alarm fire with `INTE = 0`; assert ISPR1 bit 13 is 0.
- `powman_match_pends_nvic_when_inte_timer_set` — drive alarm
  fire with `INTE.TIMER = 1`; assert ISPR1 bit 13 is 1
  (existing `powman_match_pends_nvic_line_45` test renamed to
  this and updated to write INTE first).
- `powman_inte_set_after_intr_re_pends_nvic` — drive alarm
  fire with INTE=0 (no NVIC); then write INTE.TIMER=1; assert
  ISPR1 bit 13 latches.

**Silicon-scenario change** (`isr_scenarios.rs::MAIN_IRQ_POWMAN`):
add a write of `POWMAN_INTE = 0x5AFE_0002` (password +
INT_TIMER_BIT) BEFORE the NVIC ISER1 enable. This grows the
main routine by 3 instructions (ldr r4 / ldr r5 / str). The
literal pool grows by two halfwords for INTE and the password
literal. Recompute literal-pool offsets per the same PC-align
convention documented at `isr_scenarios.rs:1326-1342`.

`max_sysclks` budget unchanged (5500 — three extra
instructions are well inside the margin).

**Existing test that needs renaming**:
`powman_match_pends_nvic_line_45` — must now first write
`INTE.TIMER` before driving advance to alarm. Either rename
to `powman_match_pends_nvic_when_inte_timer_set` per above, or
keep the name and add the INTE write as setup.

### §3.3 Smoke binary investigation (best-effort)

`smoke_powman_pacing_rp2350.exe` fails at the first
`read_word_32(POWMAN_BASE + READ_TIME_LOWER)` after releasing
POWMAN from reset and writing TIMER.RUN. ARM error
(`NoAcknowledge`) suggests the bus access aborts.

**Hypothesis**: POWMAN needs a clock source selected before
TIMER reads return live values. Per pico-sdk
`powman_timer_start`, the canonical sequence is:

1. Release POWMAN from reset.
2. Select clock source via `POWMAN_TIMER.USE_LPOSC` or
   `POWMAN_TIMER.USE_XOSC`.
3. Set `POWMAN_TIMER.RUN`.

The smoke binary today writes `TIMER = RUN | ALARM_ENAB`
without selecting a clock source. Add a USE_LPOSC bit to the
TIMER write and retry.

**Acceptance gate**: best-effort only. If the smoke binary
still faults after adding USE_LPOSC, capture the failure mode
in the V12 journal and defer to V13.
