# Bus Narrow-Access Audit — Design

**Date:** 2026-04-17
**Crate:** `mdrp2350` (M33 emulator)
**Sibling:** consider a follow-up for `mdrp2040` once this lands; same
shape applies, different peripheral set.

## 1. Purpose

The RP2350 emulator's `Bus::{read8, write8, read16, write16}` narrow
access paths have grown organically. Fixes have landed reactively —
one aperture at a time, triggered by a specific firmware image
(UARTDR for printf, SSPDR for SPI flash, SIO GPIO_OUT for OneROM
CPU-serve). The result is ~400 lines of per-aperture boilerplate with
inconsistent coverage: some apertures have full narrow handling, some
drop writes silently, some fall to a catch-all HashMap that ignores
peripheral semantics.

This HLD replaces the per-aperture code with a single unified dispatch
pattern that routes every narrow access through `read32` / `write32`.
All current side-effect and semantic exceptions (UART DR, SPI DR, I²C
DATA_CMD, ADC FIFO, SIO GPIO_OUT replication, APB SET/CLR/XOR
aliases) are preserved as explicit front-of-function fast-paths. A new
class — write-1-to-clear (W1C) registers — gets its own pre-emptive
fast-path list to avoid a known RMW hazard.

After landing, every aperture × every narrow op is correct by
construction; the per-aperture audit that used to be needed every
time a new peripheral landed is replaced by one predicate check
(`is_w1c_narrow_reg`) and one list update.

### Non-goals

- Alias-semantics rework. Existing SET/CLR/XOR routing via `pass_alias`
  to `peripheral.write32(offset, val, alias)` is correct; this HLD
  does not change it.
- Cycle-accurate narrow-access wait states. Separate workstream.
- `mdrp2040` parity. Follow-up HLD once this one lands.
- Exhaustive PPB semantic coverage. The goal is correct narrow
  dispatch, not perfecting PPB register models.

## 2. Evidence — why per-aperture doesn't scale

Survey of all four narrow ops in `bus/mod.rs` (lines 1361–2546)
against every aperture on the chip. Legend: ✅ explicit correct
handling; ⚠ handled but semantics worth documenting; ❌ gap (silent
drop, fall-through, or wrong value).

| Aperture | read8 | write8 | read16 | write16 |
|---|---|---|---|---|
| ROM (0x0) | ✅ | ✅ read-only | ✅ | ✅ read-only |
| XIP flash + SRAM (0x1) | ✅ | ✅ | ✅ | ✅ |
| SRAM + aliases (0x2) | ✅ | ✅ alias arithmetic | ✅ | ✅ alias arithmetic |
| APB Phase-2 peripherals (0x4/0x5) | ✅ side-effect + RMW | ✅ | ✅ | ✅ |
| **DMA (0x5000_0000)** | **❌ catch-all HashMap** | **❌ catch-all HashMap** | **❌ catch-all HashMap** | **❌ catch-all HashMap** |
| PIO (0x5020/30/40) | ✅ | ⚠ silent no-op | ✅ | ⚠ silent no-op |
| SIO (0xD) | ✅ RMW via `read32`+splice | ✅ GPIO_OUT replicates + RMW for rest | ✅ | ✅ |
| boot_ram (0xE…) | ✅ | ✅ | ✅ | ✅ |
| coresight_trace (0xE…) | ✅ | ✅ | ✅ | ✅ |
| **PPB (0xE, rest)** | **❌ returns 0 (stub)** | **❌ silent drop** | ✅ extracts from `ppb.read32` | **❌ silent drop** |
| Unmapped | ✅ bus_fault + 0 | ⚠ silent drop (asymmetric) | ✅ bus_fault + 0 | ⚠ silent drop |

The per-aperture approach has three structural problems:

1. **Adding a peripheral requires touching four match arms.** Easy to
   forget one.
2. **Side-effect replication is manual.** When a `write32` side
   effect lands (NVIC ISPR → `irq_pending` mirror, QMI window
   recompute, TIMER invalidation, CLOCKS recompute, …), the narrow
   paths don't get it automatically. The NVIC mirror (lines 2841–2864)
   is a concrete example: a per-aperture PPB narrow fix would have to
   duplicate the mirror code or forget it.
3. **~400 lines of RMW boilerplate** that say essentially the same
   thing for each peripheral.

## 3. Design — unified narrow dispatch

### 3.1 Core pattern

Every narrow write becomes, in order:

1. If the (region, aperture, offset) matches a **side-effect fast-path**
   — UARTDR / SSPDR / IC_DATA_CMD / ADC_FIFO — call the peripheral's
   native narrow method and return.
2. If the target is in the **SIO GPIO_OUT/OE replicating family**,
   replicate the narrow value across all lanes of the 32-bit word
   and call `self.write32(word_addr, replicated)`. Return.
3. If the alias bits (`(addr >> 12) & 3`) are non-zero, this is an
   APB atomic alias (SET/CLR/XOR). Lane-shift the narrow value,
   leaving other lanes zero, and call `self.write32(addr, lane_shifted)`
   — the peripheral's write32 handles the merge per its alias
   semantics. Return.
4. If the target is a **W1C register** (§4 catalogue), do RMW with
   the register's W1C bits masked out: read the current word,
   `AND !w1c_mask` to zero the W1C positions, splice the narrow
   value into its lane, call `self.write32(word_addr, merged)`.
   This is the critical correction — see §3.3. Return.
5. Default: RMW. Read the current word via `self.read32(word_addr)`,
   splice the narrow value into its lane, and call
   `self.write32(word_addr, merged)`. The peripheral's full write32
   side-effects (NVIC mirror, TIMER invalidation, etc.) run exactly
   as they would for a native wide write.

Narrow reads are simpler:

1. Side-effect fast-paths (UARTDR, SSPDR, IC_DATA_CMD, ADC_FIFO,
   PIO RXF0) call the peripheral's narrow read. Return.
2. Default: extract the target lane from `self.read32(word_addr)`.

### 3.2 Why routing through `self.write32` is safe

Three concerns and their resolutions:

- **Read-side effects during RMW (step 5).** Peripheral `read32` can
  pop FIFOs (UARTDR, SSPDR, IC_DATA_CMD, ADC_FIFO, PIO RXF). All of
  those are caught by step 1's fast-paths and don't reach the RMW
  path. The remaining peripheral reads are stateless (register
  storage). Verified by survey of `read32` in each peripheral module.
- **Recursive bus cycle accounting.** `self.read32` / `self.write32`
  each update `last_access_cycles` and `extra_wait_states`. A narrow
  RMW would double-count. Mitigation: the narrow op sets its own
  cycle cost up front and `read32`/`write32` must not accumulate on
  recursive calls. Simplest implementation: save `last_access_cycles`
  + `extra_wait_states` before the recursive call and restore after.
- **Infinite recursion.** `write32` does not call `write8`/`write16`,
  so there is no recursion risk. `read32` likewise.

### 3.3 W1C fast-path rationale (RMW-with-mask)

Write-1-to-clear registers interpret each 1 bit in a write as "clear
this pending/enable bit"; write 0 is no-op. Reading returns the
current state. The peripheral surface is mixed:

- **Pure W1C**: every bit is W1C (e.g. NVIC_ICPR, NVIC_ICER, CFSR,
  HFSR, DFSR, UART ICR, SPI SSPICR, TIMER INTR, PWM INTR,
  DMA INTR/INTS, GLITCH_DETECTOR TRIG_STATUS).
- **Mixed W1C**: some bits are W1C, others RW (e.g. DMA CH_CTRL
  bits 29/30 W1C + bits 0–28 RW, SIO INTERPn_CTRL_LANE0 bits 23–25
  W1C + bits 0–22 RW, SIO FIFO_ST bits 2/3 W1C + bits 0/1 RO,
  ADC FCS UNDER/OVER bits, SHA256 CSR ERR_WDATA_NOT_RDY bit).

The default RMW pattern breaks for any register with W1C bits:

- `read32(ICPR)` returns current pending bits — e.g. `0x0000_0108`.
- Splice byte `0x08` at lane 1 → merged = `0x0000_0808`.
- `write32(ICPR, merged)` — W1C clears every 1 bit in merged.
  Bit 3 (currently pending, read back, spliced back) gets cleared
  alongside the intended bit 11. Bug.

Skip-RMW (lane-shift with zeros, which I proposed earlier) works for
pure W1C but **breaks mixed registers** — writing 0 to an RW bit in
another lane overwrites the RW state.

Correct approach — **RMW-with-W1C-mask**:

```rust
let old = self.read32(word_addr);
let cleaned = old & !w1c_mask;   // zero out W1C bits before splice
let mut bytes = cleaned.to_le_bytes();
bytes[byte_idx] = val;
self.write32(word_addr, u32::from_le_bytes(bytes));
```

This works for every class:

- **Pure W1C** (mask = `0xFFFF_FFFF`): `cleaned = 0`; merged word
  carries only the spliced lane; peripheral applies W1C only where
  the user's byte has 1 bits. No other pending/enable bits disturbed.
- **Mixed W1C, writing an RW lane**: the W1C bits in other lanes
  are zeroed in the merged word (W1C treats 0 as "no change" →
  preserved), RW bits in OTHER lanes read back as their old values
  (RW overwrite with same value → no change), target lane takes the
  new byte.
- **Mixed W1C, writing a lane containing W1C bits**: W1C bits in
  other lanes zeroed → preserved. W1C bits in THIS lane take the
  user's byte (W1C cleared where byte has 1, preserved where byte
  has 0). RW bits in this lane take the user's byte as a plain
  overwrite (correct — this is the user's intent for a byte write
  to a mixed lane).

The single `w1c_narrow_mask(addr) -> u32` predicate (returning `0`
for non-W1C, else the mask) drives the dispatch. `w1c_mask == 0`
collapses back to the default RMW.

## 4. W1C register catalogue

Each entry is `(address, w1c_mask)`. Pure W1C registers have
`mask = 0xFFFF_FFFF`. Mixed registers have a mask covering only the
W1C bits. Addresses confirmed via the peripheral source files; bit
masks from source comments cross-referenced against the RP2350
datasheet.

### 4.1 ARM PPB (region 0xE)

| Address       | Name            | Mask           | Notes |
|---------------|-----------------|----------------|-------|
| `0xE000_E180` | NVIC_ICER0      | `0xFFFF_FFFF`  | IRQs 0–31 clear enable |
| `0xE000_E184` | NVIC_ICER1      | `0xFFFF_FFFF`  | IRQs 32–51 clear enable |
| `0xE000_E280` | NVIC_ICPR0      | `0xFFFF_FFFF`  | IRQs 0–31 clear pending |
| `0xE000_E284` | NVIC_ICPR1      | `0xFFFF_FFFF`  | IRQs 32–51 clear pending |
| `0xE000_ED28` | SCB_CFSR        | `0xFFFF_FFFF`  | Configurable fault status |
| `0xE000_ED2C` | SCB_HFSR        | `0xFFFF_FFFF`  | Emulator models HFSR as pure W1C (`hfsr &= !val`); reserved bits stay 0 and are never set, so a full-register mask is safe and simpler than the architectural `0x4000_0002` |

SHCSR, ICSR, DFSR intentionally absent:

- **SCB_SHCSR** (`0xE000_ED24`) — our emulator stores SHCSR as plain
  RW (`self.shcsr = val` at `ppb.rs:490`). No W1C bits modelled,
  and the architecture's per-bit semantics would only matter if we
  modelled them. Default RMW handles it correctly.
- **SCB_ICSR** (`0xE000_ED04`) — mixed W1S (NMIPENDSET / PENDSVSET /
  PENDSTSET) + W1C-via-separate-bit (PENDSVCLR / PENDSTCLR). RMW is
  safe here because the W1S bits are idempotent when written back at
  their read values, and the W1C-triggering bits (25, 27) are
  write-only and read as 0, so RMW writes 0 back to them and the
  peripheral's `if val & ICSR_PENDSxCLR != 0` guard is not entered.
- **SCB_DFSR** (`0xE000_ED30`) — not currently modelled in our PPB
  (`ppb.rs` has no `0xED30` arm). No catalogue entry until the
  register is added.

### 4.2 DMA (region 0x5)

My original catalogue had the DMA offsets wrong; corrected from
`crates/mdrp2350/src/dma.rs:72-88`. RP2350 has **two** DMA IRQ
channels, not four:

| Address       | Name          | Mask           | Notes |
|---------------|---------------|----------------|-------|
| `0x5000_0400` | DMA_INTR      | `0x0000_FFFF`  | Per-channel IRQ latch, 16 channels |
| `0x5000_040C` | DMA_INTS0     | `0x0000_FFFF`  | IRQ0 ack (W1C on INTR) |
| `0x5000_041C` | DMA_INTS1     | `0x0000_FFFF`  | IRQ1 ack |

**DMA channel CTRL family** (per-channel at `ch*0x40` + CTRL alias
offset `0x0C / 0x10 / 0x20 / 0x30`, all four aliases share storage):
mixed register with W1C bits 29 (WRITE_ERROR) and 30 (READ_ERROR)
per `dma.rs:149`. 16 channels × 4 aliases = 64 entries with
`mask = 0x6000_0000`. Implementation: a range predicate rather than
64 flat entries — "if `(addr - DMA_BASE) < 16*0x40` AND
`(offset & 0x3F) matches 0x0C|0x10|0x20|0x30`, mask = 0x6000_0000".

| Address       | Name            | Mask           | Notes |
|---------------|-----------------|----------------|-------|

### 4.7 IO_BANK0

Six `INTR` raw-status registers at `IO_BANK0_BASE + 0x230..=0x244`
(stride 4, 8 GPIOs per register). Edge-detect bits (pos/neg) are
W1C; level-detect bits (hi/lo) latch while the pin holds the level
and are RO. Per GPIO the bit layout is 4 bits: `{level_hi,
level_lo, edge_hi, edge_lo}` — so the W1C mask is `0x3333_3333`
(edge bits only) for each of the six registers.

| Address       | Name            | Mask           |
|---------------|-----------------|----------------|
| `0x4002_8230` | IO_BANK0_INTR0  | `0x3333_3333`  |
| `0x4002_8234` | IO_BANK0_INTR1  | `0x3333_3333`  |
| `0x4002_8238` | IO_BANK0_INTR2  | `0x3333_3333`  |
| `0x4002_823C` | IO_BANK0_INTR3  | `0x3333_3333`  |
| `0x4002_8240` | IO_BANK0_INTR4  | `0x3333_3333`  |
| `0x4002_8244` | IO_BANK0_INTR5  | `0x3333_3333`  |

`PROC{0,1}_INTE/F/S` and `DORMANT_WAKE_INTE/F/S` are not W1C — INTE
is enable (RW), INTF is force (RW), INTS is a computed status read.

### 4.8 SIO (region 0xD)

| Address       | Name                   | Mask           | Notes |
|---------------|------------------------|----------------|-------|
| `0xD000_0050` | SIO_FIFO_ST            | `0x0000_000C`  | Bits 2 (WOF), 3 (ROE) W1C |
| `0xD000_00AC` | SIO_INTERP0_CTRL_LANE0 | `0x0380_0000`  | Bits 23–25 OVERF W1C |
| `0xD000_00EC` | SIO_INTERP1_CTRL_LANE0 | `0x0380_0000`  | Bits 23–25 OVERF W1C |

`CTRL_LANE1` does not carry OVERF bits (they live only in LANE0 per
`interp.rs:37-38`) so LANE1 is not W1C.

### 4.9 Other

| Address       | Name                        | Mask           | Notes |
|---------------|-----------------------------|----------------|-------|
| `0x4015_8008` | GLITCH_DETECTOR.TRIG_STATUS | `0xFFFF_FFFF`  | Confirmed pure W1C per `inert.rs:138-146` |
| `0x400F_8000` | SHA256.CSR                  | `0x0000_0008`  | Only bit 3 (ERR_WDATA_NOT_RDY) is W1C per `sha256.rs:154-156`. Bit 0 (START) is self-clearing-W — reads as 0, so RMW writes 0 back safely without re-triggering |

### 4.10 Catalogue maintenance

Stored in `crates/mdrp2350/src/bus/w1c.rs` as a `pub(crate) fn
w1c_narrow_mask(addr: u32) -> u32`. Body is a `match` on `addr`
(and one range check for the DMA CH_CTRL family) returning the mask
or `0`. The match-based predicate is fast (the compiler lowers a
small match to a jump table) and easy to extend when a new
peripheral lands.

Implementation reminder: when adding a new peripheral, its W1C
audit is one bullet on its landing checklist — add entries to
`w1c.rs`, add regression tests to §6.5, done.

## 5. Implementation shape

Pseudocode for `write8` (write16 is identical modulo lane width):

```rust
pub fn write8(&mut self, addr: u32, val: u8) {
    self.invalidate_reservation_at(addr);
    let (cycles, extra) = Self::write_latency(addr >> 28);
    self.last_access_cycles = cycles;
    self.extra_wait_states += extra;
    let saved_cycles = self.last_access_cycles;
    let saved_waits = self.extra_wait_states;

    // 1. Memory regions and XIP — handled directly, no peripheral routing.
    let region = addr >> 28;
    match region {
        0x0 => return, // ROM read-only
        0x1 if Self::is_xip_sram(addr) => {
            self.xip_sram_write8(addr, val);
            self.invalidate_pc_range(addr, 1);
            self.emit_trace_if_enabled('W', 1, addr, val as u32);
            return;
        }
        0x2 if (addr & 0x00FF_FFFF) < SRAM_SIZE as u32 => {
            self.write_sram_narrow(addr, val);
            return;
        }
        _ => {}
    }

    // 2. Side-effect fast-paths (UARTDR / SSPDR / IC_DATA_CMD / ADC_FIFO).
    if let Some(()) = self.try_narrow_side_effect_write8(addr, val) {
        return;
    }

    // 3. SIO GPIO_OUT family — replicate across lanes.
    if region == 0xD && Self::is_sio_gpio_out_replicating_reg(addr & 0xFFF & !3) {
        self.write32(addr & !3, u32::from(val) * 0x0101_0101);
        self.last_access_cycles = saved_cycles;
        self.extra_wait_states = saved_waits;
        return;
    }

    let alias = (addr >> 12) & 3;
    let word_addr = addr & !3;
    let byte_idx = (addr & 3) as usize;

    // 4. Alias write — no RMW, alias at peripheral handles merge.
    if alias != 0 {
        let lane_shifted = (val as u32) << (byte_idx * 8);
        self.write32(addr, lane_shifted);
        self.last_access_cycles = saved_cycles;
        self.extra_wait_states = saved_waits;
        return;
    }

    // 5. RMW with W1C mask. For non-W1C registers the mask is 0, so
    //    `cleaned == old` and this is plain RMW. For W1C registers,
    //    clearing the W1C bits in `cleaned` before splicing means the
    //    merged word carries W1C bits only where the user's byte has
    //    1 bits — preserving uninvolved pending/enable state.
    let w1c_mask = Self::w1c_narrow_mask(word_addr);
    let old = self.read32(word_addr);
    let cleaned = old & !w1c_mask;
    let mut bytes = cleaned.to_le_bytes();
    bytes[byte_idx] = val;
    self.write32(word_addr, u32::from_le_bytes(bytes));
    self.last_access_cycles = saved_cycles;
    self.extra_wait_states = saved_waits;
    self.emit_trace_if_enabled('W', 1, addr, val as u32);
}
```

Expected size: `write8` ~50 lines, `write16` ~50 lines, `read8`
~30 lines, `read16` ~30 lines. Down from ~400 lines of
per-aperture boilerplate. Plus `is_w1c_narrow_reg` (~10 lines) and
`try_narrow_side_effect_write8`/`read8`/`write16`/`read16` helpers
(~20 lines each).

## 6. Test strategy

### 6.1 Invariants (the core matrix)

For every aperture in §2, one test per narrow op × {lane 0, 1, 2, 3}.
Asserts: targeted lane updated, other lanes preserved. Parametrised
loop over apertures so the test surface grows automatically with the
catalogue.

### 6.2 Side-effect fast-path regression

- UARTDR byte read pops exactly one byte; halfword read pops one byte
  zero-extended.
- SSPDR halfword write pushes one SPI frame.
- IC_DATA_CMD byte write pushes one I²C transaction.
- ADC FIFO byte write swallowed (read-only).

### 6.3 SIO GPIO_OUT replication (regression)

Already tested in `tests.rs` post-`ac19a28`. Keep the three tests
(`sio_gpio_out_byte_write_replicates_across_lanes`,
`sio_gpio_oe_byte_write_replicates_across_lanes`,
`sio_gpio_out_halfword_write_replicates`).

### 6.4 Alias preservation

- `write8(CLOCKS_CLK_SYS_CTRL + 0x2000 + 1, 0xAB)` — APB SET alias,
  lane 1 → verify only bits 8–15 in CLOCKS_CLK_SYS_CTRL are OR'd with
  0xAB (other lanes untouched, other bits in lane 1 OR'd in).

### 6.5 W1C behaviour — the critical correctness class

Two test shapes per entry in §4's catalogue.

**Shape A — pure W1C: writing a byte clears only the target lane's bits.**

```rust
#[test]
fn nvic_icpr_byte_write_clears_only_target_lane() {
    let mut bus = Bus::new();
    // Pre-pend IRQs 3 (lane 0) and 11 (lane 1).
    bus.write32(0xE000_E200, 0x0000_0808); // NVIC_ISPR0: bits 3, 11
    // Byte-clear lane 1: bits 8-15. 0x08 → clear bit 11.
    bus.write8(0xE000_E280 + 1, 0x08);
    // Bit 3 must survive — neither explicitly cleared nor read-and-rewritten.
    assert_eq!(bus.read32(0xE000_E200), 0x0000_0008);
}
```

**Shape B — mixed W1C: writing to a non-W1C lane preserves the W1C bits.**

```rust
#[test]
fn dma_ch_ctrl_byte_write_to_lane_0_preserves_error_flags() {
    let mut bus = Bus::new();
    release_dma(&mut bus);
    // Synthesize an error state: bits 29, 30 latched.
    // (Easier path: write a full word that sets them via the DMA's
    // error-simulation test hook, or exercise a real error condition.
    // Mechanism TBD at implementation time.)
    set_ch_ctrl_error_bits(&mut bus, 0);
    // Byte-write lane 0 of CH0 CTRL_TRIG to toggle EN or other RW bit.
    bus.write8(DMA_BASE + 0x0C + 0, 0x01); // lane 0
    // Error flags (bits 29, 30) must not have been cleared by RMW.
    let ctrl = bus.read32(DMA_BASE + 0x0C);
    assert_eq!(ctrl & 0x6000_0000, 0x6000_0000,
        "RMW of non-W1C lane must not disturb W1C bits in other lanes");
}
```

One test each for: NVIC_ICER/ICPR (Shape A); SCB_CFSR/HFSR (A);
DMA_INTR / INTS0 / INTS1 (A); DMA channel CTRL family (B, per-channel
W1C preservation); UART ICR / SPI SSPICR (A); TIMER INTR /
PWM_INTR (A); IO_BANK0 INTR0..5 (B — level bits are RO so only edge
bits cleared); SIO FIFO_ST (B, 2-bit W1C in a 4-bit register);
SIO INTERP0/1_CTRL_LANE0 (B, OVERF W1C alongside RW control bits);
GLITCH_DETECTOR TRIG_STATUS (A); ADC FCS (B); SHA256_CSR (B —
ERR_WDATA_NOT_RDY cleared without disturbing START semantics).

Two additional guard tests for the PPB SHCSR/ICSR "not in catalogue"
decision:

- **SHCSR narrow write is plain RW.** Byte-write to SHCSR must update
  the target lane and leave the rest intact (no spurious W1C
  behaviour via default RMW).
- **ICSR RMW idempotence.** Pre-pend PendSV via `ICSR_PENDSVSET`.
  Byte-read ICSR lane 3 (contains PENDSVSET bit). Byte-write a
  different lane. Re-read: PENDSVSET must still be set (proves the
  RMW round-trip through W1S bits is idempotent).

### 6.6 NVIC_ISPR narrow write triggers dispatch

Byte-pend IRQ 8 via `write8(NVIC_ISPR0 + 1, 0x01)`. Step the core with
IRQ 8's bit set in NVIC_ISER. Assert the IRQ fires within one step
(proves `irq_pending` mirror is inherited through the unified path,
not lost).

### 6.7 Unmapped bus fault symmetry

`write8(0xA000_0000, 0x42)` sets `bus_fault_pending`. Mirror for
`write16`. Matches `read8`/`read16` unmapped behaviour.

### 6.8 OneROM canary

Run `onerom_serving_oracle_rp2350` and
`onerom_serving_oracle_cpu_rp2350` as part of the full regression
sweep. Both must stay at 15/15 PASS.

## 7. Implementation order

2. **Build the unified skeleton.** Replace `write8` / `write16` /

3. **Populate `w1c_narrow_mask`** from §4's catalogue (entries in

4. **Delete the old per-aperture RMW code.** ~400 lines removed.

## 9. Out of scope

- `mdrp2040` parity. Separate HLD follow-up.
- Cycle-accurate narrow-access wait states. Orthogonal workstream.
- Making `read8`/`read16` on unmapped regions beyond region 0xE
  bus-fault. Already fault correctly per the existing code.
- New peripheral modelling. If a peripheral isn't modelled today,
  narrow access to it still falls to `peripheral_regs` HashMap via
  the `warn_unmodelled_mmio` path. That's existing behaviour and
  out of scope.

## 10. Risk

**Medium.** Three concrete risks:

- **Bus cycle double-counting via recursive `read32`/`write32`.** §3.2
  mitigation (save/restore on recursive call) is simple and tested
  directly. Low likelihood of silent bug; a regression would show up
  as wrong cycle counts in the silicon cycle oracle.
- **A W1C register missing from the §4 catalogue.** Silent incorrect
  behaviour on narrow writes to the missed register. Mitigation: the
  catalogue is complete as of the 2026-04-17 peripheral-module
  sweep — every W1C register modelled in the emulator is listed.
  Three registers (SCB_SHCSR, SCB_ICSR, SCB_DFSR) were surveyed and
  deliberately left out with reasoning inline in §4.1: SHCSR is
  plain RW in our model; ICSR's W1S/write-only bits are idempotent
  under RMW; DFSR isn't modelled. Guard tests in §6.5 pin the
  SHCSR-is-plain-RW and ICSR-is-RMW-safe assumptions. A future
  peripheral addition that introduces W1C semantics must add to
  `w1c.rs` + §6.5 tests per §4.10.
- **Peripheral `read32` side-effect surprises.** §3.2 covers the known
  FIFO-pop readers via fast-paths. If any other peripheral turns out
  to have a side-effect read that's exercised during RMW, the fix is
  to add a fast-path. Low likelihood; the emulator's peripheral
  surveys are reasonably thorough.

The OneROM oracles (both modes, both 15/15) serve as canaries — any
break in SIO or APB narrow semantics lights them up immediately.
