# HLD — PicoGUS Capture Coverage Diagnostic (Rev. 1)

## 1. Problem

Theory 1 claims the 75% gap between fired trace rows (514,667) and PIO0 SM0 autopushes (127 K) is **selection bias on setup events**. Every GUS DRAM write is a three-event sequence: `0x343 <- 0x43` selects the DRAM-low register, `0x344 <- addr16` loads the 20-bit DRAM address, `0x347 <- data` writes the byte. If the PIO at clkdiv=2 misses either setup write, the firmware's handler for `0x347` uses a stale or zero address and silently drops the byte — PSRAM stays empty even though the data arrived. If the 127 K captures are spread uniformly across `(0x343, 0x344, 0x347)`, setup loss is the blocker; if only bulk `0x347` repeats are dropped, Theory 1 is falsified and attention shifts to the DMA path (Theory 2).

## 2. Signal we want

A per-class `(fired, captured, captured-misattributed, drop%)` table that resolves:

- 0x343 `<- 0x43` / `<- 0x44` / `<- 0x4C` / other (DRAM-low, DRAM-high, global-mode, etc.) — exact value
- 0x344 write16 split into `addr_lo` / `addr_hi`
- 0x347 `<- data` (DRAM byte, volume bucket)
- 0x345 bucketed by exact value (some entries are GUS register transactions — treat like 0x343)
- Any other port/value pairs appearing in the trace
- Whether drops cluster near a specific wall-clock region of the trace

## 3. Design

### 3.1 Classification axis

Primary key: `(port, value_class)`.

| Port | Buckets |
|---|---|
| `0x343` | exact value (`0x43`, `0x44`, `0x4C`, other) |
| `0x344` | split into `addr_lo` + `addr_hi` halves |
| `0x345` | exact value (each sub-type distinguishable) |
| `0x347` | single `data` bucket |
| all other ports | exact value |

Secondary slicing: event index bucketed into deciles of trace progress.

### 3.2 Where counters live

One field added to the library, one file of net-new harness code.

- **Library touch (minimal):** `crates/mdpicoem-common/src/pio/sm.rs` — add `pub last_autopush_word: u32` on `StateMachine` and write `self.last_autopush_word = self.isr` **beside the existing `autopush_count` bump at line 585** — i.e. inside the autopush branch only (lines 581–586). **Do not** set it in `exec_push` (line 686) — that path handles explicit `PUSH` instructions, does not bump `autopush_count`, and is irrelevant for PicoGUS' SM0 (which uses autopush exclusively). Keeping field semantics tied 1:1 to `autopush_count` avoids stale-mirror bugs if any future SM program mixes autopush with explicit PUSHes. ~1 line added (the field decl), 1 line added beside the counter bump. No feature flag. No RX-FIFO-snoop path.
- **Harness:** all coverage logic inside `crates/mdpicoem-harness/src/bin/picogus_diff_rp2040.rs`. New `CaptureCoverage` struct with per-`(port,value_class)` `fired`, `captured`, `captured_misattributed`, `post_roll_orphans`, plus `[fired,captured] × 10` deciles. Existing `autopush_count` already `pub`.

### 3.3 Fired-vs-captured correlation — count delta plus decode verification

Post-mux-fix (commit `81873b9`), `drive_write_cycle` holds the bus `WRITE_ADDR_HOLD + WRITE_DATA_HOLD = 12 + 25 = 37` sysclks (`picogus_diff_rp2040.rs:113,119`). PIO slots 13–15 `IN PINS,10 [3]`, `NOP [3]`, `IN PINS,8` autopush consume ~13 PIO-ticks = ~26 sysclks at clkdiv=2 — within the 37-sysclk drive window under nominal scheduling, **but not guaranteed**: the SM may be mid-instruction when the mux flips, or stalled on a full RX FIFO. Event N's push can therefore land inside event N+1's drive window. This is the misattribution risk the supervisor flagged as load-bearing.

Per fired event the harness performs:

```
let before_cnt = sm0.autopush_count;
drive_write_cycle(inner, port, data, wide);
let after_cnt  = sm0.autopush_count;
let word       = sm0.last_autopush_word;       // new field
let (d_addr, d_data) = decode(word);           // (word>>14)&0x3ff, (word>>24)&0xff
cov.record(ev, after_cnt - before_cnt, d_addr, d_data);
```

Decoding (`IN_SHIFTDIR=1`, 10 then 8 bits): `addr = (word>>14)&0x3ff`, `data = (word>>24)&0xff`.

Classification rules:

- `delta == 1` && decoded `(addr,data)` matches fired → **captured** (attributed to current event).
- `delta == 1` && decode mismatches fired → **captured-misattributed**. Credit this push to the *previous* event's class (its late push arrived); current event is pending — tracked as `pending_from_prev` and rechecked on next cycle.
- `delta == 0` → **not-captured-this-cycle**. Stays pending; if the next event shows a mismatched push, this one gets the credit.
- `delta > 1` → **catch-up**. Decode identifies only the last push; credit current event (if decode matches) and the immediately preceding pending event. Record residual as `catch_up_unattributed` when >2.

### 3.4 Edge cases

- Events past `--duration` cap: excluded from totals.
- `Write16` expands to two `(port, port+1)` ISA cycles recorded as two sub-events, each delta-checked independently.
- Stall events (`summary.stall_events > 0`): recorded dropped with `stalled` flag.
- Read events: skipped by replay; ignored.
- **Post-roll reconciliation:** after the last trace event, step 1 ms of extra cycles. Compute `autopush_count_final − autopush_count_at_last_event` and decode `last_autopush_word`. If decode matches the final event's `(addr,data)`, credit the final event's class; otherwise increment `post_roll_orphans` (distinct from `captured`).

## 6. Risks & open questions

- **Correlation misattribution (addressed).** Decode verification resolves event N's push landing in event N+1's window; `captured_misattributed` is a first-class bucket rather than silent drift. Residual risk: identical consecutive `(addr,data)` fires (e.g. repeating `0x347 <- 0xC5`) — decode matches regardless, so delta is authoritative and mis-credit is impossible since both events share the same class.
- **Post-roll orphans.** Concretely measured: `autopush_count_final − autopush_count_at_last_event`, credited by decode match or surfaced as `post_roll_orphans`.
- **Stall-induced FIFO-full drops.** `autopush_count` only bumps when FIFO had room. A stall-flagged event correctly reports `delta=0` and is counted dropped; no special handling needed.
- **Captured-but-ignored.** Out of scope — dispatch-side loss belongs to Theory 2.
