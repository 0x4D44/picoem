# Threaded Dual-Core Phase 3 — Low-Level Design

Version: 2.0.0
Date: 2026-04-17
Supersedes: V1 (same date)
Parent HLD: `2026.04.16 - HLD - Threaded Dual-Core Emulation V5.md`

## Changes from V1

Review round 1 (devil's advocate + concurrency specialist + simplicity reviewer):

- **Decode cache moved to per-core on `CortexM33`** (was silently dropped from
  `Bus` destructure → massive perf regression).
- **`CoreAtomics` struct consolidates all cross-core per-core state**:
  `halted`, `wfe_waiting`, `event_flag`, `irq_pending`, `rcp_salt`,
  `rcp_salt_valid`, `rcp_count`, `bus_fault`, `bus_fault_addr`. Moved off
  `CortexM33` / `Bus` into one place.
- **`CoreBus` trait reduced 18 → 10 methods**. Everything non-MMIO moved
  to `CoreAtomics`.
- **`irq_pending` uses `swap(0, AcqRel)`** — dirty flag deleted (was racy).
- **Spawn-per-run model** replaces `StepCommand` + busy-wait (fixes three
  concurrency bugs; drops ~50 LOC).
- **Deleted**: `SharedNvic`, `CoordinatorBus` struct, `PeripheralGuard`
  + thread-local `LOCK_STACK`, `set_quantum` stub, `core_snapshot`
  Mutex, `PioCommand::JoinFifos` (deferred to Phase 5).
- **Added**: `ExclusiveMonitors::snoop` call in `SharedMemory::cas32` on
  success; enumerated MMIO read side effects; `ThreadedSio::seed`
  field-migration table; thread-pinning uses cores 0/1/2/3 (was
  0/2/3/4, which was inconsistent with HLD).

Net: ~400 LOC smaller, two days off the timeline.

## Scope

Compose Phase 1/2 primitives into a 4-thread runtime:

1. `CoreBus` trait — narrow MMIO surface that `CortexM33` uses. `Bus` and
   `WorkerBus` both impl it.
2. `CoreAtomics` — `Arc`'d struct holding every per-core field that
   anyone but the owning core needs to read or write. One instance
   covers both cores.
3. `SharedState` — `Arc` bundle: `SharedMemory`, `AtomicGpio`,
   `ThreadedSio`, `ThreadedPio`, `ExclusiveMonitors`, `CoreAtomics`,
   `Peripherals`.
4. `WorkerBus` — per-CPU-thread bus view. Implements `CoreBus` by
   dispatching to `SharedState` components.
5. `PioBus` — PIO thread's bus view. Owns the `PioBlock`s (moved out of
   `Bus.pio`) and communicates via `ThreadedPio`.
6. `Peripherals` — sharded mutexes around coordinator-owned peripheral
   state. Lock order documented but not mechanically enforced.
7. `ThreadedEmulator::from_emulator` — one-way decomposition.
8. `ThreadedEmulator::run_quanta(n)` — spawns 4 workers, runs exactly
   `n` quanta, joins. Spawn-per-call; no long-running controller.
9. Windows thread pinning (cores 0/1/2/3, `SetThreadAffinityMask`).

Explicitly deferred to Phase 4/5 (see §Non-goals).

### Platform gate

`#[cfg(all(target_arch = "x86_64", target_os = "windows"))]` on
`ThreadedEmulator`, `WorkerBus`, `PioBus`, the worker loop module, and
the pinning helper.

`CoreBus` trait, `CoreAtomics`, and `SharedState` are NOT gated — they
need to be visible to `CortexM33`, which compiles on all targets. The
trait has one platform-independent impl (`Bus`) and one gated impl
(`WorkerBus`).

## 1. `CoreBus` trait

Audit of `core/` direct bus access (files: `core/mod.rs`, `decode.rs`,
`execute.rs`, `execute_thumb32.rs`, `execute_fpu.rs`, `exceptions.rs`,
`coprocessor.rs`) gives two surfaces:

- MMIO (read/write 8/16/32 + PC stash + bus-fault sticky flag)
- Per-core cross-core state (event_flag, irq_pending, halted,
  wfe_waiting, SEV, RCP salt/count)

The second set is pure data, no per-access behaviour; it moves to
`CoreAtomics` (§2) and drops out of the trait.

### Trait (10 methods)

```rust
pub trait CoreBus {
    fn read8(&mut self,  addr: u32, core: u8) -> u8;
    fn read16(&mut self, addr: u32, core: u8) -> u16;
    fn read32(&mut self, addr: u32, core: u8) -> u32;
    fn write8(&mut self,  addr: u32, val: u8,  core: u8);
    fn write16(&mut self, addr: u32, val: u16, core: u8);
    fn write32(&mut self, addr: u32, val: u32, core: u8);

    fn set_active_pc(&mut self, pc: u32, core: u8);

    fn bus_fault(&self) -> bool;
    fn bus_fault_addr(&self) -> u32;
    fn clear_bus_fault(&mut self);
}
```

Call-site migration: `bus.assert_irq_core(...)` / `bus.signal_sev()` /
`bus.irq_pending[core]` / `bus.event_flag[core]` etc. become
`atomics.*` calls — see §2.

### Generic `CortexM33` methods

`CortexM33::step` (and every helper it calls in `core/*.rs`) becomes
generic: `step<B: CoreBus>(&mut self, bus: &mut B)`. Monomorphised
zero-cost at release. Compile-time cost acknowledged — see §Risks.

### `impl CoreBus for Bus`

Each trait method is a one-line delegate. `set_active_pc` wraps the
existing field write; `bus_fault/clear_bus_fault/bus_fault_addr` wrap
the existing getters.

### `impl CoreBus for WorkerBus`

See §4.

## 2. `CoreAtomics`

```rust
pub struct CoreAtomics {
    // Halt / sleep (owner writes, peer reads for wake checks)
    pub halted:      [AtomicBool; 2],
    pub wfe_waiting: [AtomicBool; 2],

    // WFE/SEV protocol. SEV sets BOTH. Owner consumes its own on wake.
    pub event_flag:  [AtomicBool; 2],

    // Coordinator (and peripherals) set bits; worker takes with swap(0).
    pub irq_pending: [AtomicU64; 2],

    // RCP cross-core salt (peer writes target's slot; target reads).
    pub rcp_salt:       [AtomicU32; 2],
    pub rcp_salt_valid: [AtomicBool; 2],
    // Single shared redundancy counter (bootrom uses one counter across
    // both cores' boot paths — one atomic suffices).
    pub rcp_count:      AtomicU32,

    // Sticky bus fault per core (owner-only today; atomic for forward
    // compat + uniformity with the other fields).
    pub bus_fault:      [AtomicBool; 2],
    pub bus_fault_addr: [AtomicU32; 2],
}
```

### Key methods

```rust
impl CoreAtomics {
    // --- IRQ pending ---
    /// Atomic grab-and-clear. Returns the pending bitmask; caller merges
    /// into ppb.nvic_ispr. Race-free: no separate dirty flag.
    pub fn take_irq_pending(&self, core: usize) -> u64 {
        self.irq_pending[core].swap(0, AcqRel)
    }
    /// Peripherals assert via fetch_or. Coordinator phase calls this.
    pub fn assert_irq(&self, core: usize, irq: u32) {
        self.irq_pending[core].fetch_or(1u64 << irq, AcqRel);
    }
    pub fn assert_irq_shared(&self, irq: u32) {
        self.assert_irq(0, irq);
        self.assert_irq(1, irq);
    }
    pub fn clear_irq(&self, core: usize, irq: u32) {
        self.irq_pending[core].fetch_and(!(1u64 << irq), AcqRel);
    }

    // --- Events ---
    /// SEV: set event_flag on both cores. Release so peer's Acquire-load
    /// observes cause-effect.
    pub fn sev_both(&self) {
        self.event_flag[0].store(true, Release);
        self.event_flag[1].store(true, Release);
    }
    /// WFE wake consume. Returns true if a flag was pending.
    pub fn event_flag_consume(&self, core: usize) -> bool {
        // swap returns old value; we clear atomically
        self.event_flag[core].swap(false, AcqRel)
    }

    // --- Halt / wfe ---
    pub fn set_halted(&self, core: usize) {
        self.halted[core].store(true, Release);
    }
    pub fn clear_halted(&self, core: usize) {
        self.halted[core].store(false, Release);
    }
    pub fn is_halted(&self, core: usize) -> bool {
        self.halted[core].load(Acquire)
    }
    // ...parallel set/clear/is_wfe_waiting
}
```

`CortexM33` holds `atomics: Arc<CoreAtomics>` + `core_id: u8`.
Existing fields `halted`, `wfe_waiting` on `CortexM33` are deleted;
accessors become `self.atomics.is_halted(self.core_id as usize)` etc.
The Phase 0b.3 migration is thus extended: those fields were
`AtomicBool` on `CortexM33`; they now live on the shared struct so
the peer can read them without holding the core itself.

### Why this and not what's in V1

V1 put these on `CoreFlags` with a separate `irq_pending_dirty` flag.
Concurrency review found a race: worker clears dirty, then loads
pending; between the two a coordinator write can set a bit with dirty
already cleared — bit not stranded (eventually read), but a subsequent
worker "clear pending after merge" loses it. Using `swap(0)` collapses
the protocol to one atomic with no dirty bookkeeping, which eliminates
the race and is less code.

## 4. `WorkerBus`

```rust
pub struct WorkerBus {
    core_id: u8,
    shared: SharedState,
    // Per-core MMIO trace PC snapshot. Local — two cores never race
    // on each other's active_pc slot.
    active_pc: u32,
    // STM/LDM/PUSH/POP suppresses per-word SRAM bank wait states.
    // Local to the in-flight instruction.
    burst_mode: bool,
    // Cycle accounting for the current access.
    extra_wait_states: u32,
}
```

PPB is on `CortexM33` (Phase 0b.1 Commit B); `WorkerBus` never sees
PPB addresses because `CortexM33::bus_read32/write32` wrappers route
`0xE...` before the trait call.

### Address dispatch

| Region (`addr >> 28`) | Dispatch |
|---|---|
| `0x0` ROM | `shared.memory.read8/16/32` (read-only path) |
| `0x1` XIP flash | `shared.memory.read8/16/32` |
| `0x2` SRAM | `shared.memory.read/write8/16/32` → calls `monitors.snoop(addr)` in write32/16/8 |
| `0x4` APB | sub-decode, below |
| `0x5` AHB (DMA) | `shared.peripherals.dma` mutex |
| `0xD` SIO | `shared.sio.*` + GPIO CP0 → `shared.gpio.*` |
| `0xE` PPB | unreachable (intercepted on CortexM33) |

### APB sub-decode

| Offset window | Component | Access |
|---|---|---|
| `0x4000_0000` CLOCKS, `0x4002_8000` PLL_SYS, `0x4002_C000` PLL_USB, `0x4002_4000` XOSC, `0x4006_0000` ROSC | `peripherals.clocks` | Mutex |
| `0x4002_0000` RESETS | `peripherals.resets` | Mutex |
| `0x4005_0000` TIMER0/1, `0x4005_8000` TICKS, `0x4005_A000` WATCHDOG | `peripherals.timers` | Mutex |
| `0x4007_0000` UART0, `0x4008_0000` SPI0, `0x4009_0000` I2C0, `0x400A_0000` ADC, `0x400A_8000` PWM, `0x4002_8000` IO_BANK0, `0x4003_8000` PADS_BANK0 | `peripherals.apb` | Mutex |
| `0x400D_0000` QMI | `peripherals.qmi` | Mutex |
| `0x5020_0000`..`0x5040_FFFF` PIO0/1/2 | `shared.pio` (FIFOs + atomic control) + `PioCommand` queue | Lock-free / mutex |

The APB decode table is a direct port of `Bus::read32`'s existing
match arms. Compile-time verification via exhaustive destructure
(see §9).

### Exclusive-monitor snoop

```rust
impl CoreBus for WorkerBus {
    fn write32(&mut self, addr: u32, val: u32, core: u8) {
        // ...region dispatch as above...
        self.shared.monitors.snoop(addr);
    }
    // write16/write8 follow same pattern; snoop AFTER the write.
}
```

`SharedMemory::cas32` (used by STREX) also calls `monitors.snoop(addr)`
on a successful CAS — otherwise a STREX that clears a peer's LDREX
silently fails to invalidate the peer's monitor. (Concurrency F6.)

### MMIO reads with side effects

The following addresses mutate state on read. In single-threaded mode
they already do; in threaded mode, two workers hitting the same
address race each other's side effects. Real hardware has the same
issue on concurrent access, so the emulator matches. Documented so
tests don't get surprised:

| Address | Side effect |
|---|---|
| `SIO.FIFO_RD` (0xD000_0070) | Pops inter-core FIFO. `ThreadedSio::fifo_pop` is lock-free SPSC — only one core's FIFO pops per call. |
| `SIO.SPINLOCK<N>` (0xD000_0100+) | Test-and-set. Concurrent reads → one claimant wins. |
| `SIO.DIV_QUOTIENT` / `DIV_REMAINDER` | Clears DIRTY bit. Per-core divider (local, no race). |
| `PIO.RXF<n>` | Pops RX FIFO. Lock-free SPSC. |
| `ROSC.RANDOM` / `RANDOMBIT` | Consumes entropy counter. Mutex-serialised via `peripherals.clocks`. |
| `TIMER0/1.TIMELR` | Latches TIMEHR. Mutex-serialised via `peripherals.timers`. |

Writes with side effects (reset-on-write, W1C): also inherited from
single-threaded; all land on mutex-serialised peripherals or
lock-free atomics.

## 5. `PioBus`

```rust
pub struct PioBus {
    shared: SharedState,
    blocks: [PioBlock; 3],     // moved out of Bus at from_emulator time
}
```

PIO thread loop per quantum:
1. Drain `shared.pio.drain_commands()` — applies `WriteInstrMem` /
   `SetClkDiv` to local `PioBlock`s.
2. For each active SM (`shared.pio.read_sm_enabled(block)`), step one
   PIO cycle: read/write `shared.gpio`, pop `shared.pio.tx_*`, push
   `shared.pio.rx_*`, update `shared.pio.irq_flags` / `dreq`.

### Command-visibility contract

CPU-side MMIO writes to PIO control registers (INSTR_MEM, CLKDIV,
SM_ENABLE, etc.) become `PioCommand` enqueues OR atomic writes
(sm_enabled is an atomic). The PIO thread drains commands at the
**start of its next quantum**.

Consequence: there is a **one-quantum delay** between a CPU write to
a PIO control register and its effect. Firmware that writes
`INSTR_MEM[0] = X` and in the very next instruction writes
`SM_ENABLE = 1` still works — both land in the same CPU quantum,
both are observed by the PIO thread at the same drain point in
quantum N+1. Firmware that depends on sub-quantum MMIO-to-PIO ordering
(unusual and would need a DMB even on real hardware) is not supported;
insert a DMB or spin at sub-cycle granularity is beyond the emulator's
model.

### `PioCommand` variants (unchanged from Phase 2 + minor)

```rust
pub enum PioCommand {
    WriteInstrMem { block: u8, addr: u8, value: u16 },
    SetClkDiv     { block: u8, sm: u8, int_div: u16, frac_div: u8 },
}
```

FIFO join (`JoinFifos`) is **deferred to Phase 5** alongside the rest
of PIO tuning. No Phase 3 test exercises it.

## 6. `Peripherals` — coordinator-owned state

```rust
pub struct Peripherals {
    pub clocks: Mutex<ClocksState>,   // CLOCKS + PLL_SYS + PLL_USB + ROSC + XOSC
    pub qmi:    Mutex<QmiState>,
    pub resets: Mutex<ResetsState>,
    pub apb:    Mutex<ApbState>,      // UART/SPI/I2C/ADC/PWM/IO_BANK0/PADS_BANK0
    pub timers: Mutex<TimersState>,   // TICKS + TIMER0/1 + WATCHDOG
    pub dma:    Mutex<DmaState>,      // 16 channels
}
```

### Lock order (documented, not mechanically enforced)

`clocks < qmi < resets < apb < timers < dma`

Derived from dependency: timers / APB peripherals read the clock tree;
DMA reads from APB/timer completions. The coordinator phase takes
locks sequentially (lock, do work, drop) — it does **not** nest. CPU
workers take at most one peripheral lock per MMIO access.

V1 proposed a thread-local `LOCK_STACK` with `PeripheralGuard` RAII
enforcement. Dropped: the codebase has effectively zero nested-lock
sites (by design — the coordinator takes locks sequentially and CPU
MMIO is single-lock). Enforcement machinery is scaffolding for a
problem that doesn't exist today. If a nested site appears later (e.g.
a CLOCKS write that has to cross-check RESETS), add the assertion
locally at that call site, not globally.

### Mutex poisoning

Use `.lock().unwrap_or_else(|e| e.into_inner())` throughout. Phase 3
test harness must not leave poisoned locks; if a worker panics, the
test already failed and the next test constructs a fresh emulator. A
future Phase 4 adds real `catch_unwind` + shutdown signalling.

### `tick_peripherals` refactor (owed)

Current `Bus::tick_peripherals` reads `self.resets_state` and each
peripheral's `tick(&self.clock_tree, ...)` in one pass. In `Peripherals`
that would require holding `clocks + resets + apb + timers` together
for the full tick. Instead: at the start of the coordinator phase,
snapshot `resets_state` and `ClockTree` into local variables (short
`clocks` + `resets` lock hold), drop both, then take `apb` / `timers`
/ `dma` sequentially and tick each against the snapshot. Net cost:
one extra struct copy per quantum (~160 bytes). Keeps the lock
windows narrow and preserves the documented order.

## 7. `ThreadedEmulator` + `from_emulator`

```rust
#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
pub struct ThreadedEmulator {
    shared: SharedState,
    // Held across run_quanta calls so memory/peripheral state persists.
    // Cores are held here between calls; consumed at run_quanta, returned
    // to this field after join.
    core0: Option<CortexM33>,
    core1: Option<CortexM33>,
    pio_blocks: Option<[PioBlock; 3]>,
    step_quantum: u32,
    master_cycle: u64,
}

impl ThreadedEmulator {
    pub fn from_emulator(emu: Emulator) -> Self { /* see below */ }

    /// Spawns 4 workers, runs exactly n quanta, joins. Workers finish
    /// deterministically after n barrier-round cycles.
    pub fn run_quanta(&mut self, n: u64) {
        let core0 = self.core0.take().expect("run_quanta reentry");
        let core1 = self.core1.take().expect("run_quanta reentry");
        let blocks = self.pio_blocks.take().expect("run_quanta reentry");

        let barrier = Arc::new(SpinBarrier::new(4));
        let shared = self.shared.clone();

        let h0 = spawn_core_worker(0, core0, shared.clone(),
                                   barrier.clone(), n, self.step_quantum);
        let h1 = spawn_core_worker(1, core1, shared.clone(),
                                   barrier.clone(), n, self.step_quantum);
        let hp = spawn_pio_worker(blocks, shared.clone(),
                                  barrier.clone(), n, self.step_quantum);
        let hc = spawn_coordinator_worker(shared.clone(),
                                          barrier.clone(), n,
                                          self.step_quantum,
                                          self.master_cycle);

        let (core0, _) = h0.join().expect("core0 worker panic");
        let (core1, _) = h1.join().expect("core1 worker panic");
        let blocks    = hp.join().expect("pio worker panic");
        let new_master = hc.join().expect("coordinator panic");

        self.core0 = Some(core0);
        self.core1 = Some(core1);
        self.pio_blocks = Some(blocks);
        self.master_cycle = new_master;
    }

    pub fn core(&self, id: usize) -> &CortexM33 {
        match id {
            0 => self.core0.as_ref().expect("run_quanta in progress"),
            1 => self.core1.as_ref().expect("run_quanta in progress"),
            _ => panic!("invalid core id"),
        }
    }

    pub fn cycles(&self) -> u64 { self.master_cycle }
}
```

**No `StepCommand`, no `quit` atomic, no busy-wait controller.** Each
`run_quanta` call is a scoped spawn/join. Deterministic termination —
every worker loop is `for _ in 0..n { ... }`. No shutdown protocol.

Cost: 4× thread-spawn per call (~80–150 µs on Windows). Acceptable for
Phase 3 tests (run_quanta called once per test, n ≥ 100). Phase 4
will introduce a long-running model backed by Pacer + StopSignal when
`run(duration)` lands.

### `from_emulator` decomposition

Consumes `Emulator`, destructures `Bus` **exhaustively** (no `..`
pattern) so any field added to `Bus` after this LLD is written causes
a compile error in `from_emulator` and forces a decision. Mapping:

| `Emulator` / `Bus` field | Target |
|---|---|
| `cores[0]`, `cores[1]` | `ThreadedEmulator.core0/1` (decode_cache moves onto `CortexM33`) |
| `clock.cycles` | `ThreadedEmulator.master_cycle` |
| `step_quantum` | `ThreadedEmulator.step_quantum` |
| `bus.memory`, `bus.boot_ram`, `bus.xip_sram` | `SharedMemory` (via `from_memory`) |
| `bus.sio.gpio_out/oe`, `bus.gpio_in`, `bus.gpio_external_*` | `AtomicGpio::seed` |
| `bus.sio.fifo_*`, `bus.sio.spinlock_bits`, `bus.sio.doorbell_*`, `bus.sio.mtime_*` | `ThreadedSio::seed` (§Migration table below) |
| `bus.pio` | `PioBus.blocks` (moved to PIO thread) |
| `bus.event_flag`, `bus.irq_pending`, per-core halted/wfe from core | `CoreAtomics` |
| `bus.rcp_salt`, `bus.rcp_salt_valid`, `bus.rcp_count` | `CoreAtomics` (kept! — HLD V5 §State ownership was wrong to call salt "local") |
| `bus.clk_*`, `bus.clock_tree`, `bus.pll_*`, `bus.rosc_regs`, `bus.xosc_regs` | `Peripherals.clocks` |
| `bus.qmi_regs`, `bus.xip_cache_offset` | `Peripherals.qmi` |
| `bus.resets_state` | `Peripherals.resets` |
| `bus.uart0/spi0/i2c0/adc/pwm/io_bank0/pads_bank0` | `Peripherals.apb` |
| `bus.ticks/timer0/timer1` | `Peripherals.timers` |
| `bus.dma` | `Peripherals.dma` |
| `bus.pll_sys_lock_at_cycle/pll_usb_lock_at_cycle`, `bus.master_cycle` | `Peripherals.clocks` (state), coordinator local (cycle) |
| `bus.decode_cache` | Per-core: new field `CortexM33.decode_cache: Box<[DecodedOp; SIZE]>` — **split during `from_emulator`** |
| `bus.gpio_hi_noise_state` | `Peripherals.clocks` (tied to ROSC entropy) |
| `bus.peripheral_regs` (legacy HashMap) | **dropped** — per Phase 2 bus fabric this was supposed to be folded into typed registers |
| `bus.last_access_cycles`, `bus.extra_wait_states`, `bus.burst_mode`, `bus.bus_fault*`, `bus.flash_loaded` | per-core local on `WorkerBus` (except `bus_fault*` on `CoreAtomics`) |
| `bus.active_pc` | per-core local on `WorkerBus.active_pc` |
| `bus.trace_enabled`, `bus.trace_sink` | **dropped in Phase 3** — tracing is single-threaded only for now; add back in Phase 5 via a shared `Arc<Mutex<dyn Write>>` if needed |

### `ThreadedSio::seed` — field migration

| `Sio` field (`sio/mod.rs`) | Fate |
|---|---|
| `gpio_out`, `gpio_oe` | → `AtomicGpio` (NOT `ThreadedSio`) |
| `fifo_0to1`, `fifo_1to0` | → `ThreadedSio.fifo_*` (capacity 8) |
| `fifo_status[2]` (ROE/WOF sticky) | → `ThreadedSio.fifo_roe/wof` |
| `spinlock_bits` | → `ThreadedSio.spinlocks` |
| `doorbell_*` | → `ThreadedSio.doorbells` |
| `mtime`, `mtime_ctrl`, `mtimecmp[2]` | → `ThreadedSio.mtime*` |
| `divider[2]`, `interp[2]` | → **per-core local**, stays with the owning `CortexM33` (new `CortexM33.sio_local: SioLocal` field) |
| `mtime_match_asserted[2]` (if present) | → edge-sticky flag moves to coordinator (re-derived from mtime vs mtimecmp each quantum; no sticky state needed because the coordinator reads and asserts the IRQ every quantum the predicate holds). |

Any field not listed must produce a compile error in the exhaustive
destructure.

### Decode cache

Moved from `Bus` (single shared copy) to per-core on `CortexM33`
(one copy per core). Per-core size: 16384 entries × 12 bytes ≈
192 KB. Total: 384 KB across both cores.

Invalidation: each core's decode cache is invalidated when its
`WorkerBus::write{8,16,32}` targets an executable region (address
range `0x0` ROM, `0x1` XIP, `0x2` SRAM). Since writes go through
atomic SRAM, cross-core self-modifying-code is rare in practice; we
accept that core 0 writing SRAM region does NOT invalidate core 1's
decode cache entry for the same word unless core 1 later fetches the
updated instruction. **Documented trade-off**: matches real hardware
where the ARM spec requires explicit cache maintenance (DSB + ISB +
invalidate icache) for cross-core SMC.

Single-threaded `Bus` path: `Bus::invalidate_all` becomes a helper

## 8. Worker loops

### Core worker (workers 0 and 1)

```rust
fn core_worker(core_id: u8, mut core: CortexM33, shared: SharedState,
               barrier: Arc<SpinBarrier>, n_quanta: u64,
               step_quantum: u32)
    -> (CortexM33, ())
{
    pin_to_host_core(core_id as usize);  // 0 or 1
    let mut bus = WorkerBus::new(core_id, shared.clone());
    let mut target: u64 = 0;
    for _ in 0..n_quanta {
        target = target.wrapping_add(step_quantum as u64);

        // Drain peripheral-asserted IRQs into local NVIC
        let pending = shared.atomics.take_irq_pending(core_id as usize);
        if pending != 0 {
            core.ppb.merge_irq_pending(pending);
        }

        while !shared.atomics.is_halted(core_id as usize)
           && !shared.atomics.is_wfe_waiting(core_id as usize)
           && core.cycles < target
        {
            core.ppb.update_latest_cycles(core.cycles);
            core.step(&mut bus);
        }
        core.ppb.update_latest_cycles(core.cycles);

        if barrier.wait() == BarrierResult::Poisoned { break; }
        // Coordinator phase runs here; we park at barrier 2.
        if barrier.wait() == BarrierResult::Poisoned { break; }
    }
    (core, ())
}
```

### PIO worker (worker 2)

```rust
fn pio_worker(mut blocks: [PioBlock; 3], shared: SharedState,
              barrier: Arc<SpinBarrier>, n_quanta: u64,
              step_quantum: u32)
    -> [PioBlock; 3]
{
    pin_to_host_core(2);
    for _ in 0..n_quanta {
        for cmd in shared.pio.drain_commands() {
            apply_pio_command(&mut blocks, cmd);
        }
        for _ in 0..step_quantum {
            step_all_sms(&mut blocks, &shared);
        }
        if barrier.wait() == BarrierResult::Poisoned { break; }
        if barrier.wait() == BarrierResult::Poisoned { break; }
    }
    blocks
}
```

### Coordinator worker (worker 3)

```rust
fn coordinator_worker(shared: SharedState, barrier: Arc<SpinBarrier>,
                      n_quanta: u64, step_quantum: u32,
                      initial_master_cycle: u64) -> u64
{
    pin_to_host_core(3);
    let mut master = initial_master_cycle;
    for _ in 0..n_quanta {
        if barrier.wait() == BarrierResult::Poisoned { break; }

        // Snapshot clock-tree + resets once (narrow lock windows)
        let (clock_tree, resets) = {
            let c = shared.peripherals.clocks
                .lock().unwrap_or_else(|e| e.into_inner());
            let r = shared.peripherals.resets
                .lock().unwrap_or_else(|e| e.into_inner());
            (c.tree.clone(), r.state)
        };

        // 1. Timers (TICKS + TIMER0/1 + WATCHDOG)
        {
            let mut t = shared.peripherals.timers
                .lock().unwrap_or_else(|e| e.into_inner());
            t.tick_n(step_quantum, &clock_tree, resets, &shared.atomics);
        }
        // 2. SIO MTIME
        shared.sio.mtime_advance(step_quantum as u64);
        for core in 0..2 {
            if shared.sio.mtime_check_match(core) {
                shared.atomics.assert_irq(core, MTIME_IRQ);
            }
        }
        // 3. Doorbells → peer NVIC
        for core in 0..2 {
            if shared.sio.doorbell_read(core) != 0 {
                shared.atomics.assert_irq(core, DOORBELL_IRQ);
            }
        }
        // 4. DMA step
        {
            let mut d = shared.peripherals.dma
                .lock().unwrap_or_else(|e| e.into_inner());
            d.tick(step_quantum, &shared);
        }
        // 5. APB peripheral tick
        {
            let mut a = shared.peripherals.apb
                .lock().unwrap_or_else(|e| e.into_inner());
            a.tick_n(step_quantum, &clock_tree, resets, &shared.atomics);
        }
        // 6. PIO IRQ flags → NVIC
        for block in 0..3 {
            let flags = shared.pio.read_irq_flags(block);
            if flags != 0 { deliver_pio_irqs(&shared, block, flags); }
        }

        master = master.wrapping_add(step_quantum as u64);
        if barrier.wait() == BarrierResult::Poisoned { break; }
    }
    master
}
```

### Thread pinning (Windows)

```rust
#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
fn pin_to_host_core(logical_id: usize) {
    use winapi::um::processthreadsapi::{GetCurrentThread, SetThreadAffinityMask};
    let h = unsafe { GetCurrentThread() };
    let mask = 1usize << logical_id;
    let prev = unsafe { SetThreadAffinityMask(h, mask) };
    assert!(prev != 0, "SetThreadAffinityMask failed for logical core {}", logical_id);
}
```

Pinning targets are logical cores **0, 1, 2, 3** (dense). At
`from_emulator` we check:

```rust
let n = std::thread::available_parallelism()
    .map(|n| n.get()).unwrap_or(1);
assert!(n >= 4,
    "ThreadedEmulator requires >= 4 host cores (found {})", n);
```

HLD V5 recommends ≥ 5 host cores so the OS / foreground thread gets
one free slot. Phase 3 requires ≥ 4 and documents the ≥ 5
recommendation. V1's choice of cores 0/2/3/4 was inconsistent with
both the HLD and with the `available_parallelism() >= 4` check.

## 9. Memory barriers (DMB/DSB/ISB)

Current `execute_thumb32.rs` treats these as no-ops. For threaded
execution, emit:

```rust
std::sync::atomic::fence(Ordering::SeqCst);
```

Unconditional (not gated). x86 TSO makes this an `mfence` on threaded
builds and still a no-op at architectural level in single-threaded
(TSO already gives the ordering). Cost is negligible (≤ 10 ns).

**Semantic note.** A DMB on core 0 orders core 0's own writes against
core 0's later loads as seen by a subsequent DMB on core 1. It does
NOT unilaterally push core 0's writes into core 1's observation
window — core 1 observes them on its own schedule. This matches real
hardware and means firmware on both cores must issue matching DMBs.

### Unit (in-process, no spawn)

4. `sev_sets_both_event_flags` — assert `sev_both` + `event_flag_consume`

### Smoke (4-thread spawn + run_quanta + join)

5. `spawn_and_join_clean` — `run_quanta(1)`, asserts all four threads
   join without panic and `master_cycle == step_quantum`.
6. `sram_write_visible_across_cores` — core 0 writes word W with one
   instruction, core 1 reads it in a later quantum. (Deliberate
   cross-quantum because within-quantum cross-core visibility is
   unspecified.)
7. `sio_fifo_roundtrip_under_threading` — core 0 pushes 0→1 FIFO via
   SIO MMIO, core 1 pops within one quantum.
8. `spinlock_contended_both_cores` — 1000× claim/release on LOCK[0]

9. `mtime_ticks_over_quanta` — `run_quanta(100)` → `mtime == 100 ×

10. `doorbell_routes_to_peer_nvic` — core 0 writes doorbells[1] → after

## 13. Risks

1. **Generic monomorphisation doubles execute-engine code size.**
   `core/execute*.rs` is already ~10 KLOC and `CortexM33::step` gets
   compiled once per `B: CoreBus` impl (two: `Bus` + `WorkerBus`).
   Measured impact: release-build `.exe` size up ~300 KB, debug build
   up ~1.2 MB, cargo-build wall-time up ~4 s. Acceptable; if it
   regresses unacceptably we convert to `&mut dyn CoreBus` (adds
   vtable indirection, ~2–3 ns per call, but halves the code size).
2. **`Bus` destructure goes stale.** Any new field on `Bus` not listed
   in §7's migration table triggers a compile error in
   `from_emulator`'s exhaustive pattern — force-handled, not silently
   dropped.
3. **Decode cache cross-core staleness.** Core 0 writing an instruction
   in SRAM does not invalidate core 1's cached decode of the same
   address. Documented; firmware that does cross-core SMC must issue
   `DSB + ISB + ICIMVAU` per ARM spec (which the emulator's `ISB`
   honours by clearing the core's own cache).
4. **Thread-pinning assumption.** < 4 host cores panics. SMT siblings
   are not detected; pinning to logical cores 0–3 may double up if
   SMT is enabled. Risk accepted; measured impact in Phase 5.
5. **Per-MMIO mutex contention on APB peripherals.** Tight loops of
   UART / SPI / I2C writes take the `apb` mutex on every access. If
   measurable at Phase 5 benchmarking, split the `apb` mutex per-
   peripheral. Not pre-emptively split — YAGNI.
6. **`tick_peripherals` snapshot copies.** Coordinator phase copies
   `ClockTree` + `resets_state` into locals (~160 bytes) each quantum.
   Negligible, but flagged so §6's lock-window narrowing is visible.
7. **PIO setup one-quantum delay.** CPU PIO MMIO writes take effect
   on the PIO thread's next drain. Firmware that depends on
   sub-quantum MMIO-to-PIO ordering fails; documented in §5.
8. **Panic handling is Phase 4.** A worker panicking in Phase 3
   deadlocks the other three at the barrier (won't arrive). Tests
   treat this as a test failure (stack trace in unjoined thread's
   panic hook).

## 15. What this phase does NOT do

- Does not add Pacer or duration-based `run` (Phase 4).
- Does not implement `ExitReason`, `StopSignal`, `reset()`, or panic
  recovery (Phase 4).
- Does not detect WFI deadlock or implement runtime quantum tuning
  (Phase 5).
- Does not run `paced_bench --threaded --dual-core` (Phase 5).
- Does not expose threaded mode via `mdrp2350-app` (out of scope).
- Does not support non-Windows hosts, non-x86_64 targets, or < 4 host
  cores.
- Does not implement PIO FIFO join reconfiguration (Phase 5).
- Does not invalidate peer decode caches on cross-core SMC
  (documented trade-off; ARM spec requires firmware-side cache ops
  anyway).
