# Phase 3: Interrupts, Faults, and Boot — Low-Level Design

Version: 0.1.0
Date: 2026-04-13
Parent: HLD Section 15, Phase 3

## 1. Purpose

Add exception handling (NVIC, faults, SysTick), coprocessor stubs, and
peripheral stubs — the minimum set required for the real RP2350 bootrom to
execute from reset and reach the "no flash detected" error path.

This is the bridge from "instruction executor" to "can run real firmware."

### Milestone

Load the real RP2350 bootrom (32 kB). Execute from reset. Bootrom initializes
clocks, probes for flash via BusFault, detects no flash. Integration test
verifies the PC lands in the expected fallback path.

### What the bootrom needs (and nothing more)

Walk the boot path to determine the minimum feature set:

| Step | Bootrom action | Requires |
|------|---------------|----------|
| 1 | CPU reset: SP from ROM[0], PC from ROM[1] | Reset sequence |
| 2 | RCP instructions: stack canary salt write | CP7 stub |
| 3 | SYSINFO read: chip ID / platform | Peripheral stub |
| 4 | RESETS: bring peripherals out of reset | Peripheral stub |
| 5 | XOSC enable, PLL configure, clock switch | Peripheral stubs |
| 6 | Enable BusFault in SHCSR, install handler | SCB + exception entry |
| 7 | Attempt XIP read at 0x10000000 | BusFault delivery |
| 8 | BusFault handler runs, sets "no flash" flag | Exception return |
| 9 | Returns to thread code, sees flag, enters USB boot | — |

## 2. Key Design Decisions

### 2.1. PPB state lives on Bus

PPB (0xE0000000-0xE00FFFFF) is per-core, but we place the state on `Bus` to
avoid modifying any load/store instruction handler. The bus dispatches PPB
accesses to the active core's PPB instance via an `active_core` index:

```rust
pub struct Bus {
    // ... existing fields ...
    pub ppb: [Ppb; 2],      // per-core PPB state
    active_core: u8,         // set by Emulator before each core steps
}
```

Region 0xE in `bus.read32`/`write32` dispatches to `ppb[active_core]`. Every
existing LDR/STR to a PPB address works unchanged through the bus path.

**Why not on CortexM33?** Putting PPB on the core would require either (a)
wrapping every `bus.readN`/`bus.writeN` call in instruction handlers with a
PPB check (~50 call sites), or (b) adding `data_read32`/`data_write32` wrappers.
Both create significant churn for no functional gain. Bus dispatch is the
existing pattern; we extend it.

### 2.2. BusFault signaling via latch

Add a sticky fault flag to Bus (same pattern as `extra_wait_states`):

```rust
bus_fault: bool,
bus_fault_addr: u32,
```

Set on access to unmapped regions (where bus currently returns 0 silently).
The core checks `bus.bus_fault()` after `decode_execute()` and clears it.

For multi-access instructions (LDM), the fault latches on the first bad access.
Remaining accesses may partially complete — this is architecturally correct
(M33 bus faults can be imprecise).

### 2.3. Exception entry/return as multi-cycle operations

Exception entry pushes 8 words, fetches a vector, and switches mode — charged
as ~12 cycles via `stall_cycles` (same mechanism as multi-cycle instructions).
The actual state change happens atomically in host code; the cycle counter
reflects correct emulated timing.

### 2.4. Peripheral stubs inline in Bus

Bootrom-critical peripherals (SYSINFO, RESETS, CLOCKS, XOSC, PLL) are
implemented as match arms in the bus's 0x4 region handler. No trait dispatch,
no HashMap lookup for known addresses. The existing `peripheral_regs` HashMap
remains as fallback for unclaimed APB addresses.

## 3. PPB Register File

### 3.1. Ppb struct

```rust
pub struct Ppb {
    // SysTick (0xE000E010-0xE000E01F)
    syst_csr: u32,           // Control/Status: ENABLE, TICKINT, CLKSOURCE, COUNTFLAG
    syst_rvr: u32,           // Reload Value (24-bit)
    syst_cvr: u32,           // Current Value (24-bit)

    // NVIC (0xE000E100-0xE000E4FF)
    nvic_iser: [u32; 2],     // Set-Enable (IRQ0-63, RP2350 uses 0-51)
    nvic_icer: [u32; 2],     // Clear-Enable
    nvic_ispr: [u32; 2],     // Set-Pending
    nvic_icpr: [u32; 2],     // Clear-Pending
    nvic_iabr: [u32; 2],     // Active Bit (read-only, managed by exception logic)
    nvic_ipr: [u8; 64],      // Priority (8-bit per IRQ, only bits [7:5] used)

    // SCB (0xE000ED00-0xE000ED8F)
    vtor: u32,               // Vector Table Offset (reset: 0)
    aircr: u32,              // Application Interrupt/Reset Control
    scr: u32,                // System Control (SLEEPONEXIT, SLEEPDEEP, SEVONPEND)
    ccr: u32,                // Configuration Control (STKALIGN, DIV_0_TRP, etc.)
    shpr: [u8; 12],          // System Handler Priority (exceptions 4-15)
    shcsr: u32,              // System Handler Control/Status (enable + pending + active)
    cfsr: u32,               // Configurable Fault Status (MMFSR[7:0] | BFSR[15:8] | UFSR[31:16])
    hfsr: u32,               // Hard Fault Status
    mmfar: u32,              // MemManage Fault Address
    bfar: u32,               // Bus Fault Address
    cpacr: u32,              // Coprocessor Access Control (0xE000ED88)
}
```

### 3.2. PPB dispatch

`Ppb::read32(offset)` and `Ppb::write32(offset, val)` use a match on
`offset & 0xFFFF` (PPB is within 0xE000xxxx):

| Offset range | Register block |
|-------------|---------------|
| 0xE004 | ICTR (read-only: number of IRQ lines) |
| 0xE010-0xE01C | SysTick CSR/RVR/CVR/CALIB |
| 0xE100-0xE104 | NVIC_ISER0-1 |
| 0xE180-0xE184 | NVIC_ICER0-1 |
| 0xE200-0xE204 | NVIC_ISPR0-1 |
| 0xE280-0xE284 | NVIC_ICPR0-1 |
| 0xE300-0xE304 | NVIC_IABR0-1 |
| 0xE400-0xE43F | NVIC_IPR0-15 (packed 4 bytes per register) |
| 0xED00 | CPUID (read-only: 0x411FD210 = Cortex-M33 r1p0) |
| 0xED04 | ICSR (interrupt control/state) |
| 0xED08 | VTOR |
| 0xED0C | AIRCR |
| 0xED10 | SCR |
| 0xED14 | CCR |
| 0xED18-0xED20 | SHPR1-3 (packed bytes) |
| 0xED24 | SHCSR |
| 0xED28 | CFSR |
| 0xED2C | HFSR |
| 0xED34 | MMFAR |
| 0xED38 | BFAR |
| 0xED88 | CPACR |

Constants: `CPUID_M33 = 0x411F_D210`, `SYST_CALIB = 0x0000_0000` (no reference
clock), `ICTR = 0x0000_0001` (64 IRQ lines in 2 registers).

Write semantics follow ARM: NVIC_ISER is set-only (write 1 to enable, write 0
has no effect). NVIC_ICER is clear-only. CFSR bits are write-1-to-clear. Etc.

### 3.3. Ppb defaults

On reset: VTOR=0, CCR=0x00000200 (STKALIGN=1, 8-byte aligned stacking),
CPACR=0 (all coprocessors disabled). All other fields zero.

## 4. Exception Entry and Return

New file: `crates/mdrp2354/src/core/exceptions.rs`

### 4.1. Exception entry

```rust
impl CortexM33 {
    /// Push exception frame, fetch vector, enter handler mode.
    /// Returns cycle cost (~12).
    pub fn enter_exception(&mut self, exc_num: u16, bus: &mut Bus) -> u32 {
        let use_psp = !self.regs.in_handler_mode()
                      && self.regs.active_sp_is_psp();
        let sp = if use_psp { self.regs.psp } else { self.regs.msp };
        let frame_sp = (sp - 32) & !0x7;  // 8-byte aligned

        // Encode IT state into xPSR for stacking
        let stacked_xpsr = self.regs.xpsr | self.encode_it_to_xpsr();

        // Push: R0, R1, R2, R3, R12, LR, ReturnAddress, xPSR
        bus.write32(frame_sp + 0,  self.regs.r[0]);
        bus.write32(frame_sp + 4,  self.regs.r[1]);
        bus.write32(frame_sp + 8,  self.regs.r[2]);
        bus.write32(frame_sp + 12, self.regs.r[3]);
        bus.write32(frame_sp + 16, self.regs.r[12]);
        bus.write32(frame_sp + 20, self.regs.lr());
        bus.write32(frame_sp + 24, self.return_address(exc_num));
        bus.write32(frame_sp + 28, stacked_xpsr);

        // Update SP
        if use_psp { self.regs.psp = frame_sp; }
        else { self.regs.msp = frame_sp; }

        // Set LR to EXC_RETURN
        //   0xFFFF_FFF9: return to Thread, MSP, no FP
        //   0xFFFF_FFFD: return to Thread, PSP, no FP
        //   0xFFFF_FFF1: return to Handler, MSP, no FP
        self.regs.r[14] = if self.regs.in_handler_mode() {
            0xFFFF_FFF1  // nested: return to Handler, MSP
        } else if use_psp {
            0xFFFF_FFFD  // return to Thread, PSP
        } else {
            0xFFFF_FFF9  // return to Thread, MSP
        };

        // Fetch vector from table
        let vtor = bus.ppb[self.core_id as usize].vtor;
        let vector = bus.read32(vtor.wrapping_add((exc_num as u32) * 4));
        self.regs.set_pc(vector & !1);

        // Enter handler mode: set IPSR, force MSP, clear IT state
        self.regs.xpsr = (self.regs.xpsr & !0x1FF) | (exc_num as u32);
        self.regs.control &= !2;  // handler mode always uses MSP
        self.regs.sync_sp_from_banked();
        self.it_state = 0;

        12  // exception entry cycles
    }
}
```

**Return address:** For synchronous faults (BusFault, UsageFault), the return
address is the faulting instruction's address (so the handler can retry). For
SVCall, SysTick, PendSV, and external IRQs, it's the next instruction. The
`return_address(exc_num)` method selects based on exception type.

### 4.2. Exception return

Triggered when PC is loaded with an EXC_RETURN magic value (0xFFxxxxxx).
Detection points: `BX Rm` and `POP {PC}`.

```rust
fn is_exc_return(val: u32) -> bool {
    val & 0xF000_0000 == 0xF000_0000
}

/// Pop exception frame, restore mode. Returns cycle cost (~12).
pub fn exit_exception(&mut self, exc_return: u32, bus: &mut Bus) -> u32 {
    let return_to_psp = exc_return & 0x4 != 0;
    let sp = if return_to_psp { self.regs.psp } else { self.regs.msp };

    // Pop frame
    self.regs.r[0]  = bus.read32(sp + 0);
    self.regs.r[1]  = bus.read32(sp + 4);
    self.regs.r[2]  = bus.read32(sp + 8);
    self.regs.r[3]  = bus.read32(sp + 12);
    self.regs.r[12] = bus.read32(sp + 16);
    self.regs.r[14] = bus.read32(sp + 20);
    let return_pc   = bus.read32(sp + 24);
    let return_xpsr = bus.read32(sp + 28);

    self.regs.set_pc(return_pc & !1);
    self.regs.xpsr = return_xpsr;
    self.it_state = Self::decode_it_from_xpsr(return_xpsr);

    // Deallocate frame
    if return_to_psp { self.regs.psp = sp + 32; }
    else { self.regs.msp = sp + 32; }

    // Restore SPSEL from EXC_RETURN
    self.regs.control = (self.regs.control & !2)
        | if return_to_psp { 2 } else { 0 };
    self.regs.sync_sp_from_banked();

    // Clear active exception in NVIC
    let exc_num = return_xpsr & 0x1FF;  // from stacked IPSR
    bus.ppb[self.core_id as usize].clear_active(exc_num as u16);

    12
}
```

Hook into instruction handlers: in `BX Rm` (execute.rs) and `POP {PC}`
(execute.rs), check `is_exc_return(target)`. If true, call `exit_exception`
instead of setting PC normally. Return 12 cycles.

### 4.3. IT state encoding

The IT block state must survive exception entry/return. EPSR encodes IT in
bits [26:25] (upper 2) and [15:10] (lower 6):

```rust
fn encode_it_to_xpsr(&self) -> u32 {
    let it = self.it_state as u32;
    ((it & 0xC0) << 19) | ((it & 0x3F) << 10)  // [26:25] | [15:10]
}

fn decode_it_from_xpsr(xpsr: u32) -> u8 {
    (((xpsr >> 19) & 0xC0) | ((xpsr >> 10) & 0x3F)) as u8
}
```

On exception entry: encode into stacked xPSR, clear `it_state`.
On exception return: decode from popped xPSR.

## 5. Fault Delivery

### 5.1. Modified step()

```rust
pub fn step(&mut self, bus: &mut Bus) {
    // SysTick ticks every cycle regardless of core stall state
    if bus.ppb[self.core_id as usize].tick_systick() {
        bus.ppb[self.core_id as usize].pend_systick();
    }

    if self.stall_cycles > 0 {
        self.stall_cycles -= 1;
        // Even while stalled, check for pending interrupts
        if let Some(exc) = self.highest_pending(bus) {
            if self.can_preempt(exc, bus) {
                let cycles = self.enter_exception(exc, bus);
                self.stall_cycles += cycles;
            }
        }
        return;
    }

    let mut cycles = self.decode_execute(bus);

    // Synchronous bus fault from data access
    if bus.bus_fault() {
        let ppb = &mut bus.ppb[self.core_id as usize];
        ppb.cfsr |= 1 << 8;  // BFSR.PRECISERR
        ppb.bfar = bus.bus_fault_addr();
        ppb.cfsr |= 1 << 15; // BFSR.BFARVALID
        bus.clear_bus_fault();

        if ppb.shcsr & (1 << 17) != 0 {  // BUSFAULTENA
            cycles = self.enter_exception(5, bus);
        } else {
            cycles = self.enter_exception(3, bus);  // escalate to HardFault
        }
    }

    // Synchronous fault from instruction (e.g. UsageFault on UDF)
    if let Some(fault) = self.pending_fault.take() {
        cycles = self.deliver_fault(fault, bus);
    }

    // Asynchronous: check pending interrupts
    if let Some(exc) = self.highest_pending(bus) {
        if self.can_preempt(exc, bus) {
            cycles += self.enter_exception(exc, bus);
        }
    }

    self.stall_cycles = cycles.saturating_sub(1);
}
```

### 5.2. Priority evaluation

```rust
/// Current execution priority (lower number = higher priority).
fn execution_priority(&self, bus: &Bus) -> i16 {
    let ppb = &bus.ppb[self.core_id as usize];
    let mut prio: i16 = 256;  // lowest possible

    if self.regs.faultmask & 1 != 0 { prio = -1; }
    else if self.regs.primask & 1 != 0 { prio = 0; }
    else if self.regs.basepri != 0 {
        prio = (self.regs.basepri & 0xFF) as i16;
    }

    // Active exceptions raise effective priority
    let ipsr = self.regs.ipsr();
    if ipsr > 0 {
        let exc_prio = ppb.exception_priority(ipsr as u16);
        if exc_prio < prio { prio = exc_prio; }
    }

    prio
}

/// Can this exception preempt current execution?
fn can_preempt(&self, exc_num: u16, bus: &Bus) -> bool {
    let exc_prio = bus.ppb[self.core_id as usize].exception_priority(exc_num);
    exc_prio < self.execution_priority(bus)
}
```

Exception priority lookup: exceptions 1-3 have fixed priorities (-2, -1 for
NMI, HardFault). Exceptions 4-15 use `shpr[(exc-4)]`. IRQ N (exception 16+N)
uses `nvic_ipr[N]`. Only bits [7:5] are implemented (8 priority levels).

### 5.3. Fault types

```rust
enum Fault {
    UsageFault,   // undefined instruction, div-by-zero (if CCR.DIV_0_TRP)
    BusFault,     // unmapped memory access
    HardFault,    // escalated or double fault
}
```

Fault sources wired up in Phase 3:

| Source | Fault | Detection point |
|--------|-------|----------------|
| Undefined instruction | UsageFault | `thumb16_undefined`, `thumb32_undefined` |
| Disabled coprocessor | UsageFault (NOCP) | `thumb32_coprocessor` when CPACR denies |
| Unmapped bus access | BusFault | Bus sets `bus_fault` flag |
| SVC instruction | SVCall (exc 11) | `thumb16_cond_branch_svc` |

The instruction handlers set `self.pending_fault = Some(Fault::UsageFault)`
and return 0 cycles. `step()` picks it up and delivers the exception.

## 6. SysTick

Per-core 24-bit countdown timer, ticked every system clock cycle.

```rust
impl Ppb {
    /// Tick SysTick. Returns true if interrupt should pend.
    pub fn tick_systick(&mut self) -> bool {
        if self.syst_csr & 1 == 0 { return false; }  // ENABLE

        if self.syst_cvr == 0 {
            self.syst_cvr = self.syst_rvr & 0x00FF_FFFF;
            self.syst_csr |= 1 << 16;  // COUNTFLAG
            self.syst_csr & 2 != 0     // TICKINT
        } else {
            self.syst_cvr -= 1;
            false
        }
    }
}
```

SysTick is exception 15. When `tick_systick()` returns true, set pending via
`pend_systick()` which sets the appropriate bit in SHCSR/ICSR.

## 7. Coprocessor Stubs

New file: `crates/mdrp2354/src/core/coprocessor.rs`

Extend the existing `thumb32_coprocessor` dispatch:

```rust
pub(crate) fn thumb32_coprocessor(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let coproc = ((hw1 >> 8) & 0xF) as u8;

    // Check CPACR access permission
    let cpacr = bus.ppb[self.core_id as usize].cpacr;
    let access = (cpacr >> (coproc as u32 * 2)) & 0x3;
    if coproc != 7 && access == 0 {  // CP7 (RCP) ignores CPACR
        self.pending_fault = Some(Fault::UsageFault);  // NOCP
        return 0;
    }

    match coproc {
        0 => self.cp0_gpioc(hw0, hw1, bus),
        4 | 5 => self.cp4_5_dcp(hw0, hw1),
        7 => self.cp7_rcp(hw0, hw1),
        10 | 11 => self.fpu_execute(hw0, hw1, bus),
        _ => {
            self.pending_fault = Some(Fault::UsageFault);
            0
        }
    }
}
```

### 7.1. RCP (CP7) — Redundancy Coprocessor

The bootrom uses RCP for stack canary operations via MCR/MRC to CP7.

State: `rcp_salt: u32` field on CortexM33.

- **MCR p7, ...**: Store value as salt. Accept all encodings.
- **MRC p7, ...**: Return `salt ^ 0xDEAD_BEEF` (dummy canary). The real RCP
  uses random delay + hardware randomness; we return a deterministic value.
- **CDP p7, ...**: Canary check assertion. Accept silently (never trigger NMI).

1 cycle per operation.

### 7.2. DCP (CP4/5) — Double-Precision Coprocessor

The bootrom uses DCP for CRC/SHA during flash verification. The DCP operates
on 64-bit values passed through pairs of CDP/MCR/MRC instructions.

State: `dcp_acc: [f64; 8]` array on CortexM33.

Phase 3 stub strategy: accept MCR/MRC transfers (move data between ARM regs
and DCP accumulators). For CDP operations, implement the small subset the
bootrom actually uses. Unknown CDP encodings are accepted as NOPs. This is
sufficient because the bootrom only reaches DCP during flash CRC — with no
flash, the DCP code path may not execute at all.

1 cycle per operation.

### 7.3. GPIOC (CP0) — GPIO Coprocessor

Fast single-cycle GPIO access via coprocessor port.

- **MRC p0, ...**: Read GPIO pin state. Return `sio.gpio_in` (the SIO GPIO
  input register, all zeros when no external pins are connected).
- **MCR p0, ...**: Write GPIO output. Forward to `sio.gpio_out`.
- **MCRR/MRRC**: 64-bit wide GPIO access (48 pins fit in 64 bits).

1 cycle per operation.

## 8. Peripheral Stubs for Boot

Replace `peripheral_regs` HashMap lookup with direct match arms for known
peripherals in the bus's 0x4 region handler. Add a small struct per peripheral
stub with backing state where needed.

### 8.1. SYSINFO (0x40000000)

Read-only:

| Offset | Name | Value |
|--------|------|-------|
| 0x000 | CHIP_ID | 0x0000_0002 (RP2350) |
| 0x004 | PACKAGE_SEL | 0x0000_0000 (RP2350A, QFN60) |
| 0x008 | PLATFORM | 0x0000_0001 (ASIC, not FPGA) |

### 8.2. RESETS (0x40020000)

Backing state: `reset_state: u32` (bit per peripheral, 1 = in reset).
Default: all bits set (everything in reset).

| Offset | Name | Behavior |
|--------|------|----------|
| 0x000 | RESET | Read/write. Write 0 to bit = deassert reset |
| 0x004 | WDSEL | Ignored (watchdog select) |
| 0x008 | RESET_DONE | Mirrors `~reset_state` (instant completion) |

The bootrom clears specific reset bits and polls RESET_DONE until they appear.
Instant completion avoids needing a timer.

### 8.3. CLOCKS (0x40010000)

The bootrom configures CLK_REF and CLK_SYS. Minimal stub:

| Offset | Name | Behavior |
|--------|------|----------|
| 0x030 | CLK_REF_CTRL | Accept writes |
| 0x038 | CLK_REF_SELECTED | Always 0x1 (selected) |
| 0x060 | CLK_SYS_CTRL | Accept writes |
| 0x068 | CLK_SYS_SELECTED | Always 0x1 (selected) |

Other clock registers: accept writes, return 0 on read. The bootrom checks
`*_SELECTED` to confirm the clock mux has switched; returning "selected"
immediately satisfies this.

### 8.4. XOSC (0x40048000)

The bootrom starts the crystal oscillator and waits for it to stabilize.

| Offset | Name | Behavior |
|--------|------|----------|
| 0x000 | CTRL | Accept writes (bootrom writes enable sequence) |
| 0x004 | STATUS | Return bit 31 set (STABLE) + bit 12 set (ENABLED) |
| 0x008 | STARTUP | Accept writes (delay config) |

### 8.5. PLL_SYS (0x40050000)

The bootrom configures PLL and waits for lock.

| Offset | Name | Behavior |
|--------|------|----------|
| 0x000 | CS | Return bit 31 set (LOCK) |
| 0x004 | PWR | Accept writes |
| 0x008 | FBDIV_INT | Accept writes |
| 0x00C | PRIM | Accept writes |

### 8.6. ACCESSCTRL (0x40060000)

TrustZone access control. Return 0 for all reads (everything accessible).
Accept all writes.

## 9. Reset Sequence

New method `Emulator::reset()`:

```rust
pub fn reset(&mut self) {
    // Read vector table from ROM
    let initial_sp = self.bus.memory.rom_read32(0);
    let reset_vector = self.bus.memory.rom_read32(4);

    // Core 0: execute from reset vector
    self.cores[0] = CortexM33::with_id(0);
    self.cores[0].regs.msp = initial_sp;
    self.cores[0].regs.r[13] = initial_sp;
    self.cores[0].regs.set_pc(reset_vector & !1);
    self.cores[0].regs.xpsr = XPSR_T;  // Thumb mode

    // Core 1: held (sleeps until woken via SIO FIFO, Phase 5)
    self.cores[1] = CortexM33::with_id(1);
    self.cores[1].halt();  // stall indefinitely

    // Clear bus state
    self.bus.clear_bus_fault();
    self.bus.ppb = [Ppb::default(), Ppb::default()];
    self.bus.resets_state = 0x1FFF_FFFF;  // all peripherals in reset

    // Reset clock
    self.clock = Clock::new(self.clock.sys_clk_hz);
}
```

## 10. Emulator step() changes

```rust
pub fn step(&mut self) -> u64 {
    self.clock.tick();

    // Contention tracking (unchanged)
    self.bus.clear_contention_state();

    // Core 0
    self.bus.set_active_core(0);
    self.cores[0].step(&mut self.bus);

    // Core 1
    self.bus.begin_contention_check();
    self.bus.set_active_core(1);
    self.cores[1].step(&mut self.bus);

    self.clock.cycles
}
```

SysTick ticking moves into `CortexM33::step()` (each core ticks its own SysTick
from the PPB array via `bus.ppb[core_id]`). This keeps the per-core timing
correct even when one core is stalled.

## 11. Instruction handler changes

### 11.1. SVC (execute.rs)

```rust
0xF => {
    // SVC #imm8
    self.pending_fault = None;  // SVC is not a fault
    // Exception delivery handled in step() — set pending SVCall
    bus.ppb[self.core_id as usize].pend_svcall();
    1
}
```

Actually, SVC is synchronous — it should enter the exception immediately.
Better: return a sentinel that tells step() to enter SVCall. Or just call
`enter_exception(11, bus)` directly from the instruction handler and return
its cycle cost.

### 11.2. CPS (execute.rs)

Wire up to actually modify PRIMASK/FAULTMASK:

```rust
0b0110 => {
    let im = (opcode >> 4) & 1;  // 0=enable (IE), 1=disable (ID)
    let affect_f = opcode & (1 << 0) != 0;
    let affect_i = opcode & (1 << 1) != 0;
    if affect_i { self.regs.primask = im as u32; }
    if affect_f { self.regs.faultmask = im as u32; }
    1
}
```

### 11.3. BX Rm / POP {PC} (execute.rs)

Add EXC_RETURN detection:

```rust
// In BX Rm handler:
let target = self.regs.r[rm];
if Self::is_exc_return(target) {
    return self.exit_exception(target, bus);
}
self.regs.set_pc(target & !1);
```

Same pattern in POP {PC} — check the value loaded for PC before using it.

### 11.4. Undefined instruction handlers

Change from NOP to fault:

```rust
pub(crate) fn thumb16_undefined(&mut self, _opcode: u16) -> u32 {
    self.pending_fault = Some(Fault::UsageFault);
    0
}

pub(crate) fn thumb32_undefined(&mut self, _hw0: u16, _hw1: u16) -> u32 {
    self.pending_fault = Some(Fault::UsageFault);
    0
}
```

### 11.5. WFI

Change from NOP to actual wait-for-interrupt:

```rust
// WFI: stall until any interrupt is pending
self.wfi_stall = true;
1
```

In `step()`, check `wfi_stall`: skip `decode_execute` and just check for
pending interrupts. When one arrives, clear `wfi_stall` and deliver it.

**Integration test strategy:**
1. Load bootrom binary (from SDK release ELF or raw binary)
2. Call `emu.reset()`

test reports the PC and recent instruction trace to help diagnose where it
got stuck.

## 14. Known Limitations (acceptable for Phase 3)

- **No tail-chaining.** Returning from one exception then immediately entering
  another does the full pop+push instead of the optimized sequence. Functionally
  correct, wastes ~12 cycles. Fix in Phase 8 if profiling shows it matters.

- **No lazy FP context save.** FPCA/LSPEN are tracked in registers but FP
  context is not pushed on exception entry. Fix in Phase 7 with full FPU.

- **No MPU enforcement.** MPU registers can be written but don't affect memory
  access permissions. Phase 3 bootrom doesn't configure MPU.

- **No precise exception model.** Multi-access instructions (LDM) may partially
  complete before BusFault. M33 allows this (imprecise bus faults).

- **Core 1 permanently stalled.** Dual-core wake via SIO FIFO is Phase 5.

- **Peripheral stubs return instant ready.** No clock cycle delay for PLL lock
  or XOSC stabilization. Bootrom polls these in tight loops — instant ready
  makes the loops exit immediately, which is correct behavior from the
  bootrom's perspective (it just checks "are you ready yet?").
