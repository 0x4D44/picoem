# Threaded Dual-Core Phase 0 — Low-Level Design

Version: 1.0.0
Date: 2026-04-16
Parent HLD: 2026.04.16 - HLD - Threaded Dual-Core Emulation V5.md

## Scope

Phase 0 prerequisite refactors and validation. Three sub-phases:

- **0b** — PPB move, LDREX/STREX, cross-core atomization (main work)
- **0a** — workload instrumentation + synthetic dual-core program
- **0c** — primitives micro-prototype (barrier, atomics, queues)

Implementation order: 0b first (critical path, independently valuable),
0c in parallel (standalone binary), 0a after 0b lands.

---

## Phase 0b.1 — Move PPB to CortexM33

### Goal

Eliminate `Bus::active_core()`. Move the per-core `Ppb` from
`Bus.ppb: [Ppb; 2]` to `CortexM33.ppb: Ppb`. Move `rcp_salt` and
`rcp_salt_valid` to `CortexM33`. Thread `CoreId` through every Bus
method that currently relies on `active_core`.

After this phase, `Bus` has no concept of "which core is running" —
the caller always supplies `CoreId` explicitly.

### Migration strategy

**Step 1: Add `ppb: Ppb` to `CortexM33`, keep `Bus.ppb` temporarily.**

```rust
// core/mod.rs
pub struct CortexM33 {
    // ... existing fields ...
    pub(crate) ppb: Ppb,           // NEW
    pub(crate) rcp_salt: u32,      // moved from Bus
    pub(crate) rcp_salt_valid: bool, // moved from Bus
}
```

Initialize in `CortexM33::with_id()`:
```rust
ppb: Ppb::default(),
rcp_salt: 0,
rcp_salt_valid: false,
```

**Step 2: Add PPB intercept to CortexM33.**

CortexM33 currently calls `bus.read32(addr)` / `bus.write32(addr, val)`
for all addresses including PPB (0xE000_0000–0xEFFF_FFFF). Add wrappers
that intercept the PPB range:

```rust
// core/mod.rs
impl CortexM33 {
    /// Bus read with PPB intercept. PPB addresses route to self.ppb;
    /// everything else goes through Bus.
    pub(crate) fn bus_read32(&mut self, addr: u32, bus: &mut Bus) -> u32 {
        if addr >> 28 == 0xE {
            self.ppb.read32(addr)
        } else {
            bus.read32(addr, self.core_id)
        }
    }

    pub(crate) fn bus_write32(&mut self, addr: u32, val: u32, bus: &mut Bus) {
        if addr >> 28 == 0xE {
            self.ppb.write32(addr, val);
            // If ISPR/ICPR write, sync back to bus.irq_pending
            self.sync_nvic_to_irq_pending(addr, bus);
        } else {
            bus.write32(addr, val, self.core_id);
        }
    }
}
```

**Step 3: Add `core_id: u8` parameter to Bus methods.**

These Bus methods currently use `self.active_core` internally:

| Method | Current signature | New signature |
|---|---|---|
| `read32` | `(&mut self, addr: u32) -> u32` | `(&mut self, addr: u32, core: u8) -> u32` |
| `write32` | `(&mut self, addr: u32, val: u32)` | `(&mut self, addr: u32, val: u32, core: u8)` |
| `read16` | `(&mut self, addr: u32) -> u16` | `(&mut self, addr: u32, core: u8) -> u16` |
| `write16` | `(&mut self, addr: u32, val: u16)` | `(&mut self, addr: u32, val: u16, core: u8)` |
| `read8` | `(&mut self, addr: u32) -> u8` | `(&mut self, addr: u32, core: u8) -> u8` |
| `write8` | `(&mut self, addr: u32, val: u8)` | `(&mut self, addr: u32, val: u8, core: u8)` |
| `set_active_pc` | `(&mut self, pc: u32)` | `(&mut self, pc: u32, core: u8)` |

Remove:
- `Bus::active_core()` (getter)
- `Bus::set_active_core()` (setter)
- `Bus::active_core` field

The compiler will flag every call site that passes the wrong number
of arguments. This is the mechanical bulk of the migration — ~65
`active_core` call sites + ~20 Bus method call sites in core code that
need the `core_id` parameter added.

**Step 4: Remove PPB dispatch from Bus::read32/write32.**

Currently `Bus::read32` has:
```rust
0xE => self.ppb[self.active_core()].read32(addr),
```

Delete these branches. PPB is now handled by CortexM33's intercept
(Step 2). If Bus somehow receives a PPB-range address, return 0
(defensive, should never happen — add `debug_assert!(addr >> 28 != 0xE)`).

**Step 5: Decouple IRQ routing from PPB.**

Currently `Bus::assert_irq_core` does:
```rust
self.irq_pending[core] |= 1u64 << irq;
self.ppb[core].set_irq_pending(irq);  // <-- Bus can't do this after move
```

After the move, Bus only sets `irq_pending`. The NVIC mirror sync
happens in `Emulator::step()`:

```rust
// In Emulator::step(), before each core's instruction loop:
self.cores[core_id].ppb.sync_from_irq_pending(
    self.bus.irq_pending[core_id]
);
```

And `Ppb::sync_from_irq_pending` reconstructs `nvic_ispr` from the
u64 bitmap:
```rust
impl Ppb {
    pub fn sync_from_irq_pending(&mut self, pending: u64) {
        self.nvic_ispr[0] = pending as u32;
        self.nvic_ispr[1] = (pending >> 32) as u32;
    }
}
```

The reverse sync (firmware writes ISPR via MMIO → update bus.irq_pending)
is handled in `CortexM33::sync_nvic_to_irq_pending()`:
```rust
fn sync_nvic_to_irq_pending(&self, addr: u32, bus: &mut Bus) {
    let low = addr & 0xFFFF;
    if matches!(low, 0xE200..=0xE207 | 0xE280..=0xE287) {
        bus.irq_pending[self.core_id as usize] =
            self.ppb.nvic_ispr[0] as u64
            | (self.ppb.nvic_ispr[1] as u64) << 32;
    }
}
```

**Step 6: Update Emulator-level PPB access.**

Three sites in `lib.rs` access `bus.ppb[core_id]` directly:

```rust
// Before:
self.bus.ppb[core_id].update_latest_cycles(cycles);
self.bus.ppb[core_id].systick_advance(cycles);

// After:
self.cores[core_id].ppb.update_latest_cycles(cycles);
self.cores[core_id].ppb.systick_advance(cycles);
```

And in `Emulator::reset()`:
```rust
// Before:
self.bus.ppb = [Default::default(), Default::default()];
self.bus.rcp_salt = [0; 2];
self.bus.rcp_salt_valid = [false; 2];

// After (PPB resets with the core):
// (CortexM33::with_id already initializes ppb, rcp_salt, rcp_salt_valid)
```

**Step 7: Delete `Bus.ppb`, `Bus.rcp_salt`, `Bus.rcp_salt_valid`.**

Remove fields and all remaining references. The compiler catches
anything missed.

**Step 8: Update direct `bus.ppb[core]` field access in core code.**

The bulk of the work. ~136 `bus.ppb[` / `self.ppb[` occurrences. By file:

| File | Count | Pattern |
|---|---|---|
| `core/exceptions.rs` | ~43 | `bus.ppb[core].field` → `self.ppb.field` |
| `tests.rs` | ~67 | `emu.bus.ppb[0].field` → `emu.core(0).ppb.field` or `emu.cores[0].ppb.field` |
| `bus/mod.rs` | ~10 | IRQ routing (Step 5), PPB dispatch (Step 4) |
| `core/execute_fpu.rs` | ~6 | `bus.ppb[core_idx].fpccr` → `self.ppb.fpccr` |
| `core/mod.rs` | ~4 | `bus.ppb[core].cfsr` → `self.ppb.cfsr` |
| `core/coprocessor.rs` | ~2 | `bus.ppb[bus.active_core()].cpacr` → `self.ppb.cpacr` |
| `lib.rs` | ~4 | (Step 6 above) |

For `core/exceptions.rs`, `core/execute_fpu.rs`, `core/mod.rs`,
`core/coprocessor.rs`: these are all methods on `CortexM33` (or called
from CortexM33 methods), so `bus.ppb[core]` becomes `self.ppb`.

For `tests.rs`: tests access PPB through `Emulator`. Either:
- `emu.cores[0].ppb.field` (if `cores` is public or `pub(crate)`)
- `emu.core(0).ppb.field` (through existing accessor)

### Call site migration checklist

1. `bus/mod.rs` — remove PPB field, remove active_core, add CoreId params,
   remove PPB dispatch cases, update IRQ routing (Steps 3-5, 7)
2. `core/mod.rs` — add ppb/rcp fields, add bus_read32/write32 wrappers,
   update bus fault handler (Steps 1-2, 8)
3. `core/exceptions.rs` — `bus.ppb[core]` → `self.ppb` (~43 sites) (Step 8)
4. `core/execute_fpu.rs` — `bus.ppb[core_idx]` → `self.ppb` (~6 sites) (Step 8)
5. `core/coprocessor.rs` — `bus.ppb[bus.active_core()].cpacr` → `self.ppb.cpacr`,
   `bus.rcp_salt[core]` → `self.rcp_salt` (Step 8)
6. `core/execute.rs` — `bus.read32(addr)` → `self.bus_read32(addr, bus)` for
   any instruction that does memory access (many sites, mechanical)
7. `core/execute_thumb32.rs` — same as execute.rs
8. `lib.rs` — update step(), reset(), tick_systick(), wake_checks() (Step 6)
9. `tests.rs` — `emu.bus.ppb[N]` → `emu.cores[N].ppb` (~67 sites) (Step 8)

### What stays on Bus

- `irq_pending: [u64; 2]` — set by peripherals (Bus owns peripherals)
- `event_flag: [bool; 2]` — set by SEV (Bus::signal_sev), FIFO push, consumed by Emulator::wake_checks. Stays for now; Phase 0b.3 may move or atomize.
- `active_pc: [u32; 2]` — indexed by core_id parameter instead of active_core
- `rcp_count: u32` — shared across cores, stays on Bus

### Verification

1. `cargo build` — compiler catches all missing parameters and dead references
2. `cargo test -p mdrp2350` — all existing tests pass (no semantic change)
3. `cargo test --workspace` — no regressions
4. `cargo run -p mdpicoem-harness --bin qemu_diff -- --fuzz 10000` — no new mismatches

## Phase 0b.2 — LDREX/STREX

### Goal

Replace the current stubs with a proper exclusive monitor. Per-core
`exclusive_address` + `exclusive_value` on CortexM33. STREX uses CAS
semantics for correctness under future threading.

### Current state

- LDREX (`0xE850`): treated as normal LDR
  (`execute_thumb32.rs:711-717`)
- STREX (`0xE840`): treated as normal STR, Rd always gets 0
  (`execute_thumb32.rs:729-737`)
- CLREX (`0xF3BF, 0x8020`): 1-cycle NOP
  (`execute_thumb32.rs:866`)
- LDREXB/LDREXH/STREXB/STREXH: comment says "Phase 1", falls through
  to LDRD/STRD

### New fields on CortexM33

```rust
pub(crate) exclusive_address: Option<u32>,
pub(crate) exclusive_value: u32,
```

Initialized to `(None, 0)` in `with_id()`.

### Implementation

**LDREX** (replace `execute_thumb32.rs:711-717`):
```rust
// LDREX Rt, [Rn, #imm8<<2]
let rn = (hw0 & 0xF) as usize;
let rt = ((hw1 >> 12) & 0xF) as usize;
let imm8 = (hw1 & 0xFF) as u32;
let addr = self.regs.r[rn].wrapping_add(imm8 << 2);
let val = self.bus_read32(addr, bus);
self.regs.r[rt] = val;
self.exclusive_address = Some(addr);
self.exclusive_value = val;
return 2; // same as LDR
```

**STREX** (replace `execute_thumb32.rs:729-737`):
```rust
// STREX Rd, Rt, [Rn, #imm8<<2]
let rn = (hw0 & 0xF) as usize;
let rt = ((hw1 >> 12) & 0xF) as usize;
let rd = ((hw1 >> 8) & 0xF) as usize;
let imm8 = (hw1 & 0xFF) as u32;
let addr = self.regs.r[rn].wrapping_add(imm8 << 2);

if self.exclusive_address == Some(addr) {
    // Monitor still valid — attempt store
    let current = self.bus_read32(addr, bus);
    if current == self.exclusive_value {
        // Value unchanged since LDREX — store succeeds
        self.bus_write32(addr, self.regs.r[rt], bus);
        self.regs.r[rd] = 0; // success
    } else {
        // Value changed by other writer — store fails
        self.regs.r[rd] = 1;
    }
} else {
    // Monitor invalidated — store fails
    self.regs.r[rd] = 1;
}
self.exclusive_address = None; // STREX always clears monitor
return if addr >> 28 == 0xD { 1 } else { 2 };
```

Note: in single-threaded mode, the value-comparison check is redundant
(no concurrent writer can change the value between LDREX and STREX
unless the same core wrote to the address explicitly). It's included
for correctness under future threading — the CAS pattern from the HLD.

**CLREX** (replace `execute_thumb32.rs:866`):
```rust
0x2 => {
    self.exclusive_address = None;
    1
}
```

**Snoop on write**: every bus write from either core must invalidate the
peer's exclusive monitor. Add to `Bus::write32` / `write16` / `write8`:

```rust
// In Bus — called after every write
pub fn snoop_exclusive(&mut self, addr: u32, writer_core: u8) {
    // For now this is a placeholder — in single-threaded mode,
    // Emulator::step runs cores sequentially, so we store the
    // snoop addr and check when switching cores.
    self.last_write_addr = Some(addr);
    self.last_write_core = writer_core;
}
```

And at core-switch in `Emulator::step()`:
```rust
// Before stepping core 1, check if core 0 wrote to core 1's
// exclusive address (and vice versa)
if let Some(write_addr) = self.bus.last_write_addr.take() {
    let peer = 1 - core_id;
    if self.cores[peer].exclusive_address == Some(write_addr) {
        self.cores[peer].exclusive_address = None;
    }
}
```

Actually, simpler: since cores run sequentially, just snoop ALL writes.
After core 0's quantum, invalidate core 1's monitor if core 0 wrote
anywhere within the monitored region. After core 1's quantum, invalidate
core 0's monitor. The granularity is "any write invalidates" — matching
Cortex-M33's "entire exclusive monitor cleared on any write by peer"
architecture.

```rust
// In Emulator::step(), after each core's quantum:
let peer = 1 - core_id;
if self.cores[peer].exclusive_address.is_some() {
    // Conservative: any write by this core invalidates peer's monitor.
    // Real hardware uses address-range tagging, but for correctness
    // "any write = invalidate" is strictly more conservative and correct.
    if self.cores[core_id].did_write_this_quantum {
        self.cores[peer].exclusive_address = None;
    }
}
```

Add `did_write_this_quantum: bool` to CortexM33. Set to `true` on any
`bus_write32/16/8`, cleared at start of each quantum.

**LDREXB/LDREXH/STREXB/STREXH**: same pattern, narrower access width.
The exclusive monitor tracks the word-aligned address regardless of
access width (per ARM architecture). Implement after LDREX/STREX works.

### Verification

1. Unit tests: LDREX→STREX success, LDREX→write→STREX fail,
   LDREX→CLREX→STREX fail, cross-core LDREX→STREX race
2. `qemu_diff --fuzz 10000` — LDREX/STREX now produces correct results
   vs QEMU (currently silently wrong since STREX always succeeds)

## Phase 0b.3 — Atomize cross-core fields + WFI

### Goal

Convert cross-core mutable fields to `AtomicBool` / `AtomicU32` as
preparation for threading. Implement proper WFI (currently a NOP).

### Fields to atomize

| Field | Current type | Location | New type | Rationale |
|---|---|---|---|---|
| `halted` | `bool` | `CortexM33` | `AtomicBool` | Coordinator clears on wake |
| `wfe_waiting` | `bool` | `CortexM33` | `AtomicBool` | Coordinator clears on wake |
| `event_flag` | `[bool; 2]` on Bus | Bus | `[AtomicBool; 2]` | SEV writes both; WFE reads own |
| `nvic_ispr` | `[u32; 8]` on Ppb | CortexM33.ppb | `[AtomicU32; 8]` | Coordinator writes IRQs |
| `nvic_icpr` | `[u32; 8]` on Ppb | CortexM33.ppb | `[AtomicU32; 8]` | Coordinator writes |
| `nvic_iabr` | `[u32; 8]` on Ppb | CortexM33.ppb | `[AtomicU32; 8]` | Coordinator writes |

### Migration pattern

For each field, the migration is mechanical:
```rust
// Before:
self.halted = true;
if self.halted { ... }

// After:
self.halted.store(true, Ordering::Release);
if self.halted.load(Ordering::Acquire) { ... }
```

In single-threaded mode, the atomic operations compile to the same
machine code as plain loads/stores on x86 (Relaxed would suffice,
but Acquire/Release is correct for the future threaded use and costs
nothing on x86-TSO).

### WFI implementation

Replace the NOP stubs with proper halt:

```rust
// core/execute.rs, line 743 (Thumb-16 WFI):
0x3 => {
    self.halted.store(true, Release);
    1
}

// core/execute_thumb32.rs, line 856 (Thumb-32 WFI.W):
0x03 => {
    self.halted.store(true, Release);
    1
}
```

Wake path (already exists in `Emulator::wake_checks`, needs atomic update):
```rust
fn wake_checks(&mut self) {
    for i in 0..2 {
        // WFE wake
        if self.cores[i].wfe_waiting.load(Acquire)
            && self.bus.event_flag[i].load(Acquire)
        {
            self.bus.event_flag[i].store(false, Release);
            self.cores[i].wfe_waiting.store(false, Release);
        }
        // WFI wake: halted core with pending enabled IRQ
        if self.cores[i].halted.load(Acquire)
            && self.bus.irq_pending[i] != 0
        {
            // Check if any pending IRQ is actually enabled in NVIC
            if self.cores[i].ppb.any_pending_enabled(self.bus.irq_pending[i]) {
                self.cores[i].halted.store(false, Release);
            }
        }
    }
}
```

Add `Ppb::any_pending_enabled(pending_mask: u64) -> bool`:
```rust
pub fn any_pending_enabled(&self, pending: u64) -> bool {
    let iser = self.nvic_iser[0] as u64 | ((self.nvic_iser[1] as u64) << 32);
    (pending & iser) != 0
}
```

### `step()` guard update

```rust
// core/mod.rs step() — already checks halted, update to atomic:
if self.halted.load(Acquire) {
    return;
}
if self.wfe_waiting.load(Acquire) {
    return;
}
```

### SEV update

```rust
// bus/mod.rs signal_sev() — update to atomic:
pub fn signal_sev(&mut self) {
    self.event_flag[0].store(true, Release);
    self.event_flag[1].store(true, Release);
}
```

### Verification

1. `cargo test -p mdrp2350` — all tests pass with atomic types
2. WFI-specific tests:
   - WFI halts core, core doesn't execute further instructions
   - Pending enabled IRQ wakes halted core
   - Pending disabled IRQ does NOT wake halted core
   - Dual-WFI with timer alarm: both cores halt, timer fires, one wakes
3. `qemu_diff --fuzz 10000` — WFI now halts (may surface new mismatches
   if fuzz generates WFI — these are correctness improvements)

## Phase 0a — Workload study

### Goal

Measure dual-core workload characteristics to validate threading
assumptions. Add per-core instrumentation counters. Author a synthetic
dual-core Thumb program.

### Instrumentation counters

Add to `Emulator` (or a side-channel struct):

```rust
pub struct WorkloadCounters {
    pub per_core: [CoreCounters; 2],
}

pub struct CoreCounters {
    pub decode_execute_cycles: u64,  // cycles spent in step()
    pub wfi_cycles: u64,             // cycles spent halted
    pub wfe_cycles: u64,             // cycles spent in WFE
    pub sram_reads: u64,             // SRAM read32/16/8 count
    pub sram_writes: u64,            // SRAM write32/16/8 count
    pub sio_accesses: u64,           // SIO region accesses
    pub peripheral_accesses: u64,    // APB/AHB peripheral accesses
    pub ppb_accesses: u64,           // PPB accesses (NVIC, SCB, etc.)
}
```

Increment in `CortexM33::bus_read32/write32` based on address range.
Track WFI/WFE cycles as `(quantum_target - core.cycles)` when core
is halted/waiting.

### Synthetic dual-core workload

Thumb assembly program loaded via `load_image`:
- Core 0: tight loop with periodic GPIO toggle (SIO CP0) + shared
  SRAM write + SIO FIFO push
- Core 1: tight decode loop + shared SRAM read + SIO FIFO receive

Both cores use real instructions (no NOPs). Proxy for firmware that
exercises dual-core communication.

Core 1 launch: core 0 writes core 1's vector table entry and wakes
it via SEV (or directly via `Emulator::core_mut(1).wake()`).

### Reporting

Add `--instrumented` flag to `paced_bench`. After the run, print:
- Per-core: decode/execute %, WFI %, WFE %, SRAM R/W count,
  SIO access count, peripheral access fraction
- Cross-core: shared SRAM write % (writes to the same 4-byte aligned
  address as a read from the other core)

### Decision gate

Proceed to Phase 1 only if ALL of:
- Core 1 active (non-WFI/WFE) ≥ 20%
- Cross-core SRAM writes < 10% of total
- Peripheral access ratio measured (informs mutex sharding)

## Phase 0c — Primitives micro-prototype

### Goal

Measure real costs of threading primitives on the target hardware.
Replace napkin estimates from HLD §Quantum sizing with measurements.

### New binary

`crates/mdpicoem-harness/src/bin/threading_micro.rs`

Add to `Cargo.toml`:
```toml
[[bin]]
name = "threading_micro"
path = "src/bin/threading_micro.rs"
```

### Measurements

1. **4-way SpinBarrier round-trip.** Spawn 4 threads, each increments
   a counter then hits barrier. Measure wall-clock per barrier crossing
   averaged over 1M iterations.

2. **AtomicU32 shared memory throughput.** 2 threads reading/writing
   same cacheline vs. different cachelines. Measure ops/sec.

3. **Masked CAS loop cost.** Simulate byte-write-to-shared-word: one
   thread writes bytes via CAS loop, another reads the same word.
   Measure CAS retries and throughput.

4. **rtrb queue throughput.** SPSC push/pop across 2 threads. 8-entry
   queue matching SIO FIFO depth. Measure ops/sec.

5. **Mutex lock/unlock cycle.** `std::sync::Mutex<u32>`, 2 threads
   contending. Measure lock-to-unlock latency.

### Go/no-go

- SpinBarrier crossing > 500 ns → threading approach is questionable
- AtomicU32 contended throughput < 50 Mops/s → shared SRAM model
  needs redesign
- Results feed into Phase 5 quantum tuning

### Thread pinning

Reuse the `win::boost_and_pin(core)` pattern from `paced_bench`.
Pin measurement threads to adjacent physical cores for realistic
cache-coherence behavior.
