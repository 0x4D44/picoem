# RP2350 — RISC-V Hazard3 Core Support (V3)

**Date:** 2026-04-17
**Crate:** `crates/mdrp2350/`
**Supersedes:** V2.
**Companion audit:** `wrk_docs/2026.04.16 - HLD - RP2350 Feature Coverage Audit.md`
**Review artefacts:** two rounds of four-reviewer pass (architecture, ISA, test, devil's advocate). V3 corrects ten ISA-level factual errors against the RP2350 datasheet + Hazard3 source, drops two abstraction smells, and resolves two open questions.

## 1. Goal

Run an RP2350 RISC-V firmware binary selected by `EmulatorBuilder::arch(Arch::RiscV)`. First-cut target: a **bare-asm `blinky-riscv.bin`** (no SDK, no libc, no B-extension use) toggling a GPIO pin.

**Honest scope statement (corrected from V2):** V1 ships the enum, plumbing, ISA core, atomics, IRQ controller, and a developer smoke firmware. **No SDK-built RP2350 RISC-V firmware will run** — the SDK toolchain emits Zba/Zbb/Zbs/Zbkb/Zca/Zcb/Zcmp by default. Real-world firmware support is a follow-up phase. V1 is a vehicle for landing the enum + plumbing + base ISA, not a usable production emulator.

## 2. Background

RP2350 ships **two** complete dual-core complexes on the same die. Selection is by OTP fuse + POWMAN at power-up; only one runs at a time.

- **Arm path** — 2× Cortex-M33. Implemented.
- **RISC-V path** — 2× **Hazard3** (Wren6991/Hazard3). Not implemented.

Hazard3 extensions (per Hazard3 csr.adoc + custom_extensions.adoc):

- RV32I + M + A + C; Zicsr; Zifencei.
- B-extension parts: Zba, Zbb, Zbs, Zbkb, Zbc. *No* RVA/RVB profile flag; "B" by itself is wrong (V1 error).
- Zcmp + Zcb (compressed push/pop, extra compressed loads/stores).
- Custom: `h3.bextm`, `h3.bextmi`, `h3.block`, `h3.unblock`; custom CSRs incl. `h3.misa` at `0xBF1`.

The two paths share Bus, SIO, peripherals, clocks, DMA, PIO, memory map. SIO already exposes RISC-V observables as **storage only**: `RISCV_SOFTIRQ`, `MTIME`/`MTIMECMP`, `mtime_match_asserted`. Neither asserts an IRQ into a CPU today — that wiring is P4 work.

We do not run the bootrom; ARCHSEL/POWMAN handover stays unmodelled.

**Hazard3 upstream A-extension spec is empty (`(TODO)` in instruction_pseudocode.adoc).** The RP2350 datasheet §3.8.1.13 is the *only* spec for atomics behaviour; we lock to it.

## 3. Non-goals

- **U-mode, PMP** — storage-only or absent.
- **Hazard3 debug module** — silicon oracle deferred (§8 Q3).
- **Bootrom dispatch, ARCHSEL, POWMAN.**
- **Full B-ext (Zba/Zbb/Zbs/Zbkb/Zbc), Zcmp, Zcb.** Deferred. Pinned firmware target is bare-asm rv32imac. (§4.5)
- **Custom Hazard3 instructions** `h3.bextm`/`h3.bextmi`. Deferred.
- **`h3.block` wake on `h3.unblock`.** V1 decodes both as no-ops (HINT-space `slt x0,*,*`); firmware that uses `h3.block` to await `h3.unblock` will deadlock. Accepted V1 limitation; revisit when SDK support lands.
- **`fence` / `fence.i`** — no-op (no decoded-op cache on RISC-V side). Tripwire in §4.8.
- **A-extension reservation precision under threaded cores.** Serial-interleave only; tripwire in §4.7.
- **Toolchain dependency.** `gen_blinky_riscv.py` emits raw bytes (§4.5).
- **Performance counters** beyond `mcycle`/`minstret` (alias `Clock::cycles`).

## 4. Design

### 4.1 Cores — enum with shim-based migration

```rust
// crates/mdrp2350/src/lib.rs
pub enum Cores {
    Arm([CortexM33; 2]),
    RiscV([Hazard3; 2]),
}

impl Cores {
    pub fn expect_arm(&self)         -> &[CortexM33; 2];
    pub fn expect_arm_mut(&mut self) -> &mut [CortexM33; 2];
    pub fn expect_riscv(&self)       -> &[Hazard3; 2];
    pub fn expect_riscv_mut(&mut self) -> &mut [Hazard3; 2];
    pub fn is_arm(&self)   -> bool;
    pub fn is_riscv(&self) -> bool;
}

pub struct Emulator {
    pub cores: Cores,    // was: [CortexM33; 2]
    pub bus: Bus,
    pub clock: Clock,
    pub step_quantum: u32,
}
```

**Public API of `Emulator` — all existing M33 accessors preserved as shims** (V3 change vs V2):

```rust
// SHIMS — keep existing call sites compiling untouched. They internally
// call cores.expect_arm() and panic on a RiscV emulator (programmer error).
pub fn core(&self, id: usize) -> &CortexM33     { &self.cores.expect_arm()[id] }
pub fn core_mut(&mut self, id: usize) -> &mut CortexM33;
// New, symmetric.
pub fn core_riscv(&self, id: usize) -> &Hazard3;
pub fn core_riscv_mut(&mut self, id: usize) -> &mut Hazard3;
```

**Migration shape, corrected.** V2 said ~119 sites; actual count is ~460 references across ~31 files (Grep). The honest call-site shape:

- `emu.core(i).regs.r[x]` — works as today via the shim. No rewrite.
- `emu.cores[i].regs.r[x]` — direct field access, currently legal because `cores` is `pub`. Becomes `emu.cores.expect_arm()[i].regs.r[x]`. Mechanical rewrite. **Add a sed pattern to the P1a PR description.**
- `for i in 0..2 { emu.cores[i] ... }` — same rewrite; the `expect_arm()` cost is one match per loop, not per iteration if the call is hoisted. If hoisting matters, use `let arm = emu.cores.expect_arm_mut(); for i in 0..2 { arm[i] ... }`.

**Why this changes the P1a budget.** V2 proposed an en-bloc rewrite of all sites. With shims for `core(id)`/`core_mut(id)`, the rewrite shrinks to **only the direct-field-access sites** (~50–80, not 460). P1a becomes a small mechanical PR.

**`Emulator::wake_checks`** dispatches on the enum directly — no trait needed:

```rust
fn wake_checks(&mut self) {
    match &mut self.cores {
        Cores::Arm(cs) => for c in cs {
            if c.wfe_waiting && self.bus.event_flag[c.id() as usize] {
                self.bus.event_flag[c.id() as usize] = false;
                c.wfe_waiting = false;
            }
        },
        Cores::RiscV(cs) => for c in cs {
            // wfi wakes when mip != 0 (NOT mip & mie — V2 error).
            // The wake doesn't have to deliver the trap; mstatus.MIE / mie
            // gate delivery, but wake-from-wfi is sensitive to mip alone.
            if c.wfi_parked && c.mip() != 0 {
                c.wfi_parked = false;
            }
        },
    }
}
```

**`Emulator::step`** (V3: trait dropped; explicit dispatch):

```rust
pub fn step(&mut self) -> u64 {
    self.bus.master_cycle = self.clock.cycles;
    let target = self.clock.cycles + self.step_quantum as u64;
    match &mut self.cores {
        Cores::Arm(cs)   => step_pair_arm(cs, &mut self.bus, target),
        Cores::RiscV(cs) => step_pair_riscv(cs, &mut self.bus, target),
    }
    self.clock.advance(self.step_quantum as u64);
    self.tick_peripherals(self.step_quantum);
    self.tick_systick();      // Arm-only; no-op for RiscV. See §4.6.
    self.fan_out_riscv_irqs(); // RiscV-only; no-op for Arm. New, see §4.6.
    self.wake_checks();
    self.clock.cycles
}
```

`step_pair_arm` and `step_pair_riscv` are two ~16-line free functions, near-identical but for what they call inside the inner loop. Why no trait: two arms, two call sites; a `pub(crate) trait CoreStep` saves ~8 lines and adds a default-no-op `publish_cycles_to_ppb` whose presence is a smell (V2 review). Two free functions is the simpler design.

**Performance footnote.** The outer match runs once per `step()` (~2.3 M/s at 150 MHz). Branch-predictor-friendly; not on the hot path. V2's words on this were overspent — the actual cost is invisible against `tick_peripherals` (which iterates three PIO blocks every quantum). No further discussion warranted.

### 4.3 Reset

`Emulator::reset` is an outer arch match. Bus reset (RESETS, clocks, peripherals, SIO) is shared verbatim.

**Arm arm** — unchanged (`lib.rs:81-140`).

**RISC-V arm:**

- Both harts: x0..x31 = 0.
- `pc` = `0x0000_0000` — Hazard3 RTL `RESET_VECTOR` default; RP2350 maps the bootrom there. **(Q1 resolved, V3.)**
- `mhartid` per hart: core 0 → 0, core 1 → 1. **(Q2 resolved, V3 — RP2350 datasheet §3.8.5 line 17688.)**
- `mstatus` = 0 (M-mode, MIE=0, MPIE=0, MPP=00).
- `mtvec` = `0x0000_1FFC` with MODE=Vectored (bit 0 = 1; bit 1 hardwired to 0). Datasheet table 373. *Implication:* any trap before firmware sets MTVEC dispatches into the bootrom alias; P2 unit tests must set MTVEC explicitly or chase phantom traps.
- `mcountinhibit` = `0b11` (cy + ir inhibited at reset; firmware enables).
- `meicontext.noirq` = `1`.
- `misa` = `0x4094_1105` — MXL=01, I (bit 8), M (bit 12), A (bit 0), C (bit 2), **X (bit 23 — non-standard extensions present, mandatory for Hazard3's custom CSRs)**. V2 omitted bit 23.
- `h3.misa` (CSR `0xBF1`) — storage-only for V1 (read returns 0, writes round-trip). Firmware that probes it falls back to base-ISA assumptions, which is what V1 supports anyway.
- All other CSRs = 0.

### 4.5 ISA scope — bare-asm rv32imac for V1

| Feature | V1? | Notes |
|---|---|---|
| RV32I base | **Yes** | All loads/stores, ALU, branches, jal/jalr, lui/auipc, fence (no-op). |
| M | **Yes** | mul/mulh/div/rem; div-by-zero per RISC-V spec. |
| A | **Yes** | lr.w, sc.w, amo*.w. See §4.7. |
| C | **Yes** | Required for any rv32imac toolchain output. |
| Zicsr | **Yes** | CSR dispatch; rules per "CSR trap rules" below. |
| Zifencei | **Yes** | No-op for V1; tripwire for future cache. |
| Zba/Zbb/Zbs/Zbkb/Zbc | **No** | Follow-up phase. |
| Zcmp / Zcb | **No** | Follow-up. |
| `h3.bextm` / `h3.bextmi` | **No** | Follow-up. |
| `h3.block` / `h3.unblock` | Decode-tolerant no-op | HINT-space `slt x0, x0, x0` / `slt x0, x0, x1`. Firmware using `h3.block` will deadlock; accepted limitation. |
| `misa` read | **Yes** | Standard bitmap = `0x4094_1105`. |

**Firmware constraint, restated.** SDK builds use `-march=rv32ima_zicsr_zifencei_zba_zbb_zbs_zbkb_zca_zcb_zcmp` (pico-sdk issue #1937). V1 ships only `roms/rp2350/blinky-riscv.bin` from `gen_blinky_riscv.py` (raw-byte encoder, ~150–250 LoC of new mini-assembler, with a disasm comment per emitted instruction so the PR is reviewable). SDK firmware will not run on V1 — explicitly out of scope (§8 Q4).

**CSR trap rules** (V3 — V2 over-collapsed these):

| Case | Behaviour |
|---|---|
| Unimplemented CSR address | `mcause=2` (illegal instruction). |
| `csrrw` / `csrrs` with `rs1 != x0` / `csrrc` with `rs1 != x0` to a read-only CSR (bits `[11:10]==0b11`) | `mcause=2`. |
| `csrrs` / `csrrc` with `rs1 == x0` to a read-only CSR | **Read-only access; NO trap.** Spec-mandated. |
| Access from too-low privilege | `mcause=2` (we run M-mode only; effectively never triggers). |

V2's blanket "unknown CSR → mcause=2" was wrong: a `csrr a0, mvendorid` (which is `csrrs a0, mvendorid, x0`) must NOT trap — `mvendorid` is read-only, but a no-write read is legal. Hazard3 follows the spec; the emulator must too.

**Fail loudly on unknown opcodes.** Decode miss → `warn!("unimplemented RISC-V opcode", insn, pc)` then trap with `mcause=2`. **In `qemu_diff_riscv32 --fuzz` mode, the `warn!` escalates to test failure** — V2's approach silently skipped opcodes under fuzz.

### 4.6 Interrupts

| Source | RISC-V plumbing | RP2350 side | Status |
|---|---|---|---|
| `msip` (software) | `mip.MSIP` per hart | `SIO.RISCV_SOFTIRQ` storage at `sio/mod.rs:30,166` | Storage ✓; IRQ assert ✗ (P4) |
| `mtip` (timer) | `mip.MTIP` per hart | `SIO.MTIME`/`MTIMECMP` + `mtime_match_asserted` | Storage + match flag ✓; IRQ assert ✗ (P4) |
| `meip` (external) | `mip.MEIP`, vectored via `meinext` | `bus.irq_pending[core]` (52 lines) | Transport ✓; CSR window ✗ (P4) |

`bus.irq_pending: [u64; 2]` is arch-agnostic; peripherals fan into it via `assert_irq_core` / `assert_irq_shared`. The Hazard3 IRQ-controller CSR window (`meiea`/`meipa`/`meifa`/`meipra`/`meinext`/`meicontext` at `0xBE0..0xBE5`) reads from the same bitmap.

**`fan_out_riscv_irqs` — new step-loop hook (V3).** Runs after `tick_peripherals`, before `wake_checks`:

```rust
fn fan_out_riscv_irqs(&mut self) {
    if !self.cores.is_riscv() { return; }
    // mtip per hart from SIO mtime match
    for c in 0..2 {
        if self.bus.sio.mtime_match_asserted[c] {
            self.bus.assert_irq_core(c, IRQ_RISCV_MTIMER); // P4 sentinel
        }
    }
    // msip per hart from RISCV_SOFTIRQ
    let sw = self.bus.sio.riscv_softirq() & 0x3;
    for c in 0..2 {
        if (sw >> c) & 1 != 0 {
            self.bus.assert_irq_core(c, IRQ_RISCV_SOFT);
        }
    }
}
```

V2 did not pin where this fan-out lives. Order matters: an `mtip` raised this quantum should wake a `wfi` *this* quantum, not next.

**`mtvec` modes.** Bit 0 = direct vs vectored. **Bit 1 hardwired to 0** (Hazard3 csr.adoc) — RAZ/WI to mask out reserved encodings 2/3. Both modes must be implemented in P2.

**NMI (V3 cite).** Per RP2350 datasheet §3.2.1 (line 5130), **NMI is Cortex-M33-only** on RP2350 — `NMI_MASK0/1` route IRQs into the M33 NMI input. On the Hazard3 side those same sources arrive as ordinary external IRQs with elevated `meicontext.preempt` priority. Hazard3 has **no separate NMI channel** (csr.adoc); V2's `Fault::Nmi` reuse was wrong, and V3 confirms the answer is "use the IRQ controller, no special channel needed."

**PPB on RISC-V.** Pure storage round-trip. The NVIC ISPR mirror at `bus/mod.rs:2216` writes `irq_pending`; harmless on RISC-V because no Hazard3 firmware writes to ARM NVIC addresses. **Known gap (P4):** `irq_pending` is currently maintained only via the ISPR mirror — ICPR/ICER/IPR aliases are not. If an Arm firmware ever writes through ICPR to clear pending, the bitmap drifts. Same for the eventual RISC-V case (Hazard3 firmware writes `meifa.write1clear` instead, so this is a spec-compliant divergence we should explicitly note).

**`bus.set_active_pc(pc)` per RISC-V instruction.** Required for MMIO trace attribution (`bus/mod.rs:782`). One-liner in `execute.rs` dispatch loop.

**`wfi`.** Hart parks on `wfi`; resumes when `mip != 0` (NOT `mip & mie != 0` — wake-from-wfi is sensitive to `mip` alone, even with interrupts disabled, per spec). `mstatus.MIE`/`mie` still gate trap *delivery*. Implementation: `wfi_parked: bool` on `Hazard3`, set by the opcode, cleared in `wake_checks` (§4.1).

**`tick_systick` is Arm-only.** RISC-V has no SysTick; mtime ticks already happen in `Sio::tick_mtime_n` from `tick_peripherals`. `tick_systick` is a no-op for RISC-V — no rename needed; just guard with `if self.cores.is_arm()`.

### 4.7 Atomics

Single-host-thread, serial-interleave. **Locked to RP2350 datasheet §3.8.1.13** (Hazard3 upstream A-spec is empty).

**`Bus::reservation: [Option<u32>; 2]`** — per-core, word-aligned address.

**Reservable region:** `0x2000_0000..0x2008_2000` (528 KB main SRAM per RP2350 datasheet table 366, line 17281). V2 used `0x80000` (520 KB, the M33-banked size) — wrong; the unbanked tail is reservable too.

**Trap codes (V3 corrected):**

| Operation | Misalign | Bus / outside-reservable | Source |
|---|---|---|---|
| `lr.w` | `mcause=4` (load addr misalign) | `mcause=5` (load access fault) | Datasheet §3.8.1.13 line 16267-16323 |
| `sc.w` / `amo*.w` | `mcause=6` (store/AMO addr misalign) | `mcause=7` (store/AMO access fault) | Datasheet §3.8.1.13 line 16267-16323, 15967 |

V2's "misalign or outside SRAM → mcause=5" was three-quarters wrong.

**AMO outside the reservable region.** On real silicon, `lr.w`/`sc.w` outside SRAM silently fail forever (reservation never succeeds — likely deadlocking firmware). `amo*.w` outside SRAM **traps with `mcause=7`**, breaking the implicit retry loop. The emulator must replicate the trap behaviour or SDK code that does `amo*.w` to APB will hang us where it would fault on silicon.

**Invalidation.** Any `Bus::write8`/`write16`/`write32(addr, _)` clears every reservation where `reservation[c] == Some(addr & !3)`. Word-alignment masking is mandatory — sub-word stores invalidate the containing word's reservation per spec. DMA writes go through `Bus::write*` (`dma.rs:547`), so DMA invalidates correctly at no extra cost.

**Bypass paths to be aware of:** `Bus::boot_ram_write32` (region 0xE) and `bus.memory.sram_write*` (used in 9 test sites) **bypass `Bus::write*`**. SRAM-only restriction makes the boot-RAM bypass safe (out of region). Direct SRAM byte-pokes from tests *would* leak — but those are pre-firmware setup paths, before any `lr.w` could have run. Document and move on; if a future maintainer adds an SRAM-targeted runtime helper that bypasses `write*`, they need to invalidate manually.

**Tripwire.** `Bus::reservation` + serial-interleave is incompatible with the threaded-cores HLD (`wrk_docs/2026.04.14 - HLD - Threaded Dual-Core Emulation*.md`). `tech_debt.md` entry to be added when P3 ships, pointing forward.

### 4.8 Decoded-op cache

Skip for V1. RISC-V decode goes raw-fetch every instruction.

**`fence.i` tripwire.** When the RISC-V decode cache is added later, `fence.i` MUST flush it. Land this as a `debug_assert!(!RISCV_DECODE_CACHE_EXISTS, "fence.i is a no-op; wire invalidation first")` in the cache-add PR's `fence.i` execute path, forcing a deliberate replacement.

### 4.9 Tests — `Bus::new()` change, no parallel constructor

V2 proposed `Bus::minimal()` — a parallel constructor. V3 drops it. Instead, change the existing `decode_cache: Box<[DecodedOp; DECODE_CACHE_SIZE]>` field (`bus/mod.rs:396`) to use `Box::new_zeroed()` (cheap to allocate, no per-element initialization), or accept the 192 KB × ~100 RISC-V tests = ~19 MB of test-time heap. 19 MB on a dev machine is a non-issue. Drop `Bus::minimal()`; one constructor.

## 6. Phasing

**P0 — Probe-rs Hazard3 attach spike (1 day, runs before P1a).**
On the bench: flash a known-good Hazard3 binary (bootrom RISC-V trampoline + spin), `probe-rs attach --chip RP2350 --core 2`, read `mhartid` and `misa`, set HW breakpoint, step one instruction. Pass = all four work; informs P6 viability. Fail = capture the exact error and decide between forking probe-rs, switching to OpenOCD-RISC-V, or the UART-mailbox fallback (Q3). Do this **first** so the team isn't designing P4 around an oracle that may not exist.

**P1a — `Cores` enum migration (small PR with shims).**
Introduce `Cores` enum with `Arm` arm. Add `expect_arm*()`, `is_arm`/`is_riscv`. Add the `Emulator::core(id)`/`core_mut(id)` shims. Migrate **only** the direct-`emu.cores[i]` field-access sites (~50–80, not 460); shimmed-API call sites are untouched. Define `step_pair_arm` (free function, no trait). All existing tests/oracles pass.

**P1b — Hazard3 skeleton.**
Add `RiscV` arm, `core_riscv/` module with stub `Hazard3::step()` (advances PC by 4, returns 1 cycle), reset path with verified Q1/Q2 values. Builder `.arch(Arch::RiscV)`. Smoke: build a RISC-V emulator, step 100 times, observe cycles advance.

**P2 — RV32I + Zicsr + Zifencei + CSRs.**
Full base ISA, CSR file with **strict trap rules** (§4.5), trap entry/return, `mtvec` direct + vectored, `mret`, `ecall`/`ebreak`, illegal-instruction trap. Per-opcode unit tests.

**P2.4 — `qemu_diff_riscv32` GDB-stub spike (1 day, before P2.5).**
Connect to `qemu-system-riscv32` GDB stub, attempt to read `x0..x31 + pc` via flat indices (likely works) AND `mstatus`/`mcause`/`mepc`/`mtval`/`mip`/`mie` via flat indices and via `qXfer:features:read`. Record which path works for each register. Output decides P2.5's diff surface.

**P2.5 — `qemu_diff_riscv32` harness (RV32I only).**
Mirrors `qemu_diff_m33` shape. **Pinned invocation:** `qemu-system-riscv32 -cpu rv32,a=true,m=true,c=true,zicsr=true,zifencei=true -machine virt -nographic -gdb tcp::3335 -S -kernel <bin>`. Diffs `x0..x31 + pc` plus whatever CSR set P2.4 confirmed. Fuzz mode (`--fuzz N --seed S`). Register as oracle #13 in CLAUDE.md.

**P3 — M, A, C.**
Mul/div, atomics (using `Bus::reservation` per §4.7), compressed decoder. Per-class fuzz generators added to `qemu_diff_riscv32`. **Atomics property test** (two-core interleaved random `lr.w`/`sc.w`/store sequences against shared address pool, oracle = hand-rolled reservation tracker with documented invariants) lands here; not an external oracle.

**P4 — IRQ controller + time source wiring.**
Hazard3 IRQ controller CSR window. `mtip` from `sio.mtime_match_asserted` via `fan_out_riscv_irqs`. `msip` from `sio.riscv_softirq`. Trap dispatch at instruction boundary. **IRQ scenario suite** of ~25–35 hand-authored hex images (per-CSR-window read/write × 6, `meinext` priority arbitration ×4, `meicontext` save/restore through nested entry ×3, `meifa` force-bit ×3, `meipra` priority changes ×3, MEIP↔meinext interlock ×3, `wfi` wake from each source ×3); oracle = hand-computed expectations. Lands as **Unit-tested only** in audit terms; *Verified* requires P6 silicon.

**P5 — App integration + smoke firmware.**
`mdrp2350app` `--arch riscv` flag (or new `mdrp2350app-riscv` binary if the TUI's M33-specific panels make a flag awkward). `gen_blinky_riscv.py` emits `roms/rp2350/blinky-riscv.bin`. Smoke test in `crates/mdrp2350/tests/firmware.rs` asserts GPIO toggles. **Developer smoke; not a validation claim** (§7).

**P6 — Silicon harness (separate HLD).**
Gated on P0 outcome. If P0 passes, `probe_diff_riscv_rp2350` becomes the *Verified* oracle for P4. If P0 fails, fallback per Q3.

**Property-test invariants (P3 atomics).** Document explicitly in `core_riscv/atomics.rs`:

1. After `lr.w` at addr A by core C, `reservation[C] == Some(A & !3)`.
2. After any `Bus::write*(B, ...)` where `B & !3 == A & !3`, `reservation[C]` for every core that held A is `None`.
3. `sc.w` by core C at addr A succeeds iff `reservation[C] == Some(A & !3)` AND `A` is word-aligned AND `A` is in the reservable region.
4. After successful `sc.w`, `reservation[C] == None`.
5. After failed `sc.w`, memory at A is unchanged.

Without these, the test is a stochastic equality check that drifts.

## 8. Open questions / risks

**Q1 — RESOLVED (V3).** Reset PC = `0x0000_0000`. Hazard3 RTL `RESET_VECTOR` default; RP2350 maps bootrom there. `gen_blinky_riscv.py` emits an image loaded via `load_image(0x2000_0000, ...)` and a tiny stub at `0x0000_0000` that jumps to it (or, simpler: `load_image(0x0000_0000, ...)` and run from ROM region directly — confirm in P5 design).

**Q2 — RESOLVED (V3).** `mhartid = 0/1` per RP2350 datasheet §3.8.5.

**Q3 — Probe-rs Hazard3 attach (P0 spike).** Now with a 1-day spike scheduled before P1a; result feeds P6 design.

**Q4 — Biggest scope risk: SDK firmware unrunnable on V1.** SDK toolchain emits Zba/Zbb/Zbs/Zbkb/Zca/Zcb/Zcmp by default. V1 supports none of these. The largest workload V1 can run is a Python-encoded blinky. Defensible (audit-discipline applied) but should be **stated, not buried**. Real-world firmware support is a follow-up phase whose scope is full B-extension subset + Zcmp + Zcb + revisit `h3.unblock` wake. Estimate: comparable in size to P2+P3 combined.

**Q5 — Cycle accuracy.** RISC-V V1 uses flat 1-cycle costs except mul/div (3) and loads (2). The M33 audit lists ~14 known cycle-model gaps; RISC-V will inherit the class. Add `silicon_cycle_oracle_riscv_rp2350` to P6 scope; **owner + date assigned at P5 close-out**, not "tracked in tech_debt.md" (which is the V2 wording for "will slip").

**Q6 — Threaded cores.** `Bus::reservation` + serial-interleave is incompatible with the threaded-core HLD. Tripwire in §4.7.

**Q7 — `h3.misa` semantics.** Storage-only for V1. Firmware probing it falls back to base-ISA assumptions, which matches V1 scope. Revisit if breakage.

**Q8 — `irq_pending` mirror coverage.** Maintained only via NVIC ISPR mirror; ICPR/ICER/IPR aliases not. P4 known-gap; spec-compliant divergence on RISC-V (Hazard3 firmware uses `meifa.write1clear`).

**Q9 — `expect_arm()` panic discipline under cross-arch aggregator harnesses.** `test_silicon` and any future multi-arch runner must dispatch on `cores.is_arm()` before calling `expect_arm*()`. P5 TUI integration is the first such caller; design it accordingly.

**Q10 — P1a coordination.** V2 said "merge promptly" — not a plan. V3 mitigates by preserving `Emulator::core(id)` as a shim, shrinking the rewrite from ~460 sites to ~50–80. Ship P1a in a single morning to minimize concurrent-branch friction, and write the PR description with the exact sed pattern so reviewers can verify mechanically.

## 9. What this HLD deliberately does NOT include

Per CLAUDE.md quality philosophy:

- No migration plan for pre-existing harnesses beyond the mechanical sed described in §4.1. Dev sandbox.
- No backwards-compatibility shims **except** the `Emulator::core(id)`/`core_mut(id)` accessor shims (which exist to *reduce* migration churn, not preserve old behaviour — they panic on RISC-V).
- No feature flags, no env vars.
- No bootrom / ARCHSEL / POWMAN.
- No `CoreStep` trait, no `step_pair<C>` generic. Two arms, two free functions.
- No `Bus::minimal()` parallel constructor. One constructor; cheap allocation via `Box::new_zeroed()`.
- No SDK firmware support in V1 (Q4).
- No silicon oracle in V1 (P6 separate HLD, gated on P0).
- No abstraction layer beyond what's already here. If the design grows beyond this document, the growth is wrong.
