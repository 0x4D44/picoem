## Item-by-item recommendation

### (a) `PioBus` + `take_blocks` — **KEEP**, narrow the comment

This is the only item that's genuinely paused future work. The Threaded
PIO Per-Block Workers HLD V4 (2026-04-22) specifies the worker contract;
the struct and `take_blocks` are the carrier scaffolding for when
`pio_worker_body` lands.

**Action:** narrow the existing `#[allow(dead_code)]` comments from
`"consumed by Stage 7's pio_worker_body"` to a concrete HLD pointer:

```rust
#[allow(dead_code)] // PIO worker — see 2026.04.22 - HLD - Threaded PIO Per-Block Workers V4 §<section>
```

The HLD pointer rots later than abstract "Stage 7" naming. ~2 lines of
diff. Single commit.

**Decision needed:** confirm Stage 7 / PIO worker is still planned.
If it's been quietly dropped, this item collapses to "delete".

### (b) `WorkerBus::shared()` — **DELETE**

Three call sites, all in `crates/mdrp2040/src/threaded/emulator.rs`:

- `:952` and `:953` — single test (`shared_state_clone_round_trip` /
  similar) that asserts `Arc::clone(threaded.shared())` returns a
  pointer-equal Arc. **Tests the accessor against itself** — the
  exact antipattern we deleted in D7 last week.
- `:1372` — another test using `Arc::clone(threaded.shared())` to set
  up a fresh worker for an isolated assertion.

The doc-comment on `shared()` says it's "used by the worker loop in
Stage 3b.4 and by diagnostics" — but Stage 3b.4 landed without ever
calling it, and there are no diagnostics consumers.

**Action:** delete `WorkerBus::shared()` and the two test sites. The
test at `:1372` needs a different mechanism for fresh-worker setup —
check whether the test is still meaningful (it may be testable via the
public ThreadedEmulator API instead).

**Decision needed:** drop the test at `:1372` outright, or rewrite it
against the public API?

### (c) `WorkerBus::clock_tree()` — **DELETE**

Zero callers, production or test. Doc-comment claims it's used by the
"Stage 3b.4 coordinator" but Stage 3b.4 landed without it. Pure dead
code with a sub-millisecond mutex acquisition cost on the path of any
caller that *did* exist (`self.shared.peripherals.clocks.lock()`).

**Action:** delete. Single commit, ~7 lines.

**Decision needed:** none — this is uncontroversial dead code, listed
here only because the original sweep author flagged it as
forward-scaffolding rather than dead.

### (d) `with_thread_mask` (both chips) — **DELETE**

Both chips have the same shape:

- Builder method on `ThreadedEmulator` to override the default
  host-core pinning mask.
- Single test per chip (`with_thread_mask_persists` /
  `with_thread_mask_sets_mask_and_chain_returns_self`) that only
  asserts the setter writes the field.
- Zero production callers.

The intent was paced_bench / diagnostics tuning. paced_bench shipped
without ever overriding the default mask. So it's an unused builder
method whose only test exercises itself.

**Action:** delete the method on both chips and both self-tests. The
default pinning mask `[0, 1, 2]` (RP2040) / `[0, 1, 2, 3, 4, 5]`
(RP2350) becomes the only pinning option. If diagnostics ever need to
override, it can be added back at that point in three lines.

**Decision needed:** confirm paced_bench / any other tooling has no
live plan to use this. (Cursory grep through `harness/src/bin/`
suggested no.)

### (e) `WorkerBus::core_id()` — **DELETE**

Exactly one caller, a single-line test assertion at
`crates/mdrp2350/src/threaded/bus.rs:1987`. The doc-comment is candid:
"Accessor for tests only". The test is a self-assertion against the
constructor parameter.

**Action:** delete the accessor and the assertion. The constructor
already takes `core_id` as a parameter and stores it; round-tripping it
through an accessor proves nothing.

**Decision needed:** none — this is the same antipattern as (b)'s
self-tests.
