# HLD — Fuzz `--class` Filter UX V1

**Date:** 2026-04-18
**Author:** Claude Opus 4.7 (HLD agent)
**Parent:** `wrk_journals/2026.04.18 - JRN - Follow-ups Campaign.md` (Follow-up 5)
**Scope:** `crates/mdpicoem-harness/src/bin/test_rp2350_qemu_diff_riscv32.rs`
**Status:** Awaiting team-lead sign-off.

## Goal

Make `--fuzz N --class X` run N cases **of class X**, not N mixed cases filtered down to the X-fraction.

## Current behaviour

`run_fuzz` (lines 707-726) calls `riscv_gen::generate_fuzz(rng, count)` — a weighted dispatcher that allocates `count * weight_bp/10_000` cases per class — then applies a post-filter:

```rust
let raw = riscv_gen::generate_fuzz(&mut rng, count);
let tests = match class_filter {
    Some(c) => raw.into_iter().filter(|tc| tc.class == c).collect(),
    None    => raw,
};
```

Consequence: classes with low weight run far fewer than N cases. `--fuzz 1000 --class rv32c` (weight 500 bp = 5%) yields ~50 cases; `--class zifencei` (200 bp = 2%) yields ~20. The wrk_journal entry of 2026-04-18 already flags this as a surprise to users.

## Proposed behaviour

- `--fuzz N` (no `--class`) — unchanged: N weight-distributed mixed cases.
- `--fuzz N --class X` — **N cases of class X**.
- Reproduction hint line unchanged: when class is set, reproduce command already prints `--class {class_str}` correctly.

## Design options

### Option A — Pre-dispatch on `--class` (recommended)

When `class_filter.is_some()`, call the already-public per-class generator (e.g. `gen_fuzz_rv32c(rng, count)`) for exactly `count` cases. Drop the post-filter.

Pros:
- Every class already has a dedicated `pub fn gen_fuzz_<class><R: Rng>(rng, count) -> Vec<RiscvTestCase>` in `riscv_gen.rs` (rv32i_alu, rv32i_mem, rv32i_misaligned, rv32i_branch, rv32i_upper, rv32m, rv32a, rv32c, zicsr, zifencei, csr_side_effect — all eleven). No new public API surface.
- Deterministic: N cases in, N cases out.
- Zero wasted generator work.
- Touches only `run_fuzz` (~10 lines) plus an internal `dispatch_per_class` helper. No changes to `riscv_gen.rs`.

Cons:
- Seed determinism for `--fuzz N --class X` **changes** relative to today, because the RNG no longer advances through other classes first. This is an acceptable one-time break — any user reproducing a pre-change fail will already have the `--class` string and can pin the old binary or accept the new seed path. Document the shift in the commit message.
- `--fuzz N` without `--class` is untouched, so its seed→bug reproducibility is preserved (the common case).

### Option B — Oversample-and-filter

Loop generating mixed batches until `count` post-filter cases accumulate. Reuses `generate_fuzz` verbatim.

Pros: No API touch at all; existing mixed RNG path unchanged.

Cons: Wasteful — for `zifencei` (2% weight) the generator runs ~50× more work than needed. Mixed-RNG ordering still means the N-th `zifencei` case depends on all the discarded mixed cases in between, which makes seeded reproduction fragile across any future weight rebalancing. Rejected.

### Option C — New `--fuzz-class X:N` flag

Preserve `--fuzz N --class X` meaning-unchanged; add a second flag for "N of X".

Pros: Strict back-compat for any script currently relying on "N mixed, filtered".

Cons: No evidence any script does — `grep --fuzz --class` across the repo finds zero hits outside the binary help text and one wrk_journal note complaining about the current behaviour. Adds parser surface + docs + a confusing two-flag story for a wart nobody relies on. Rejected.

### Recommendation

**Option A.** The pre-existing per-class generator API makes this the minimal, cleanest fix.

## Risks

- **Seed reproduction drift** (with `--class`): pre-change `--fuzz 1000 --seed 42 --class rv32c` and post-change do not produce the same case stream. Mitigation: note in commit message; the mixed-mode `--fuzz N --seed S` (no `--class`) — the regression-gate workflow — is byte-identical.
- **User script breakage**: grepped `CLAUDE.md`, `README.md`, `wrk_docs/**`, `wrk_journals/**` — no script uses `--fuzz N --class X` as part of a pinned reproduction. The one journal reference (2026.04.18 RISC-V Oracle Residuals) explicitly calls out the current behaviour as a quirk. Safe to change.
- **Weight-table semantics**: `RiscvClass::weight_bp` and `generate_fuzz`'s residue-absorption logic remain untouched; only `run_fuzz`'s class path is affected.

## Test plan

1. Unit test in `riscv_gen.rs` tests module (or a small integration test in the binary): `assert_eq!(gen_fuzz_zifencei(&mut rng, 100).len(), 100)` and `for tc in cases { assert_eq!(tc.class, RiscvClass::Zifencei); }` for each of the 11 classes (likely already covered by the existing `check_class` helper at line 2266).
2. Smoke check (manual, documented in journal): `test_rp2350_qemu_diff_riscv32 --fuzz 100 --class zifencei --seed 42` prints `Generated 100 tests` and `Total: 100` in the summary.
3. Regression invariant: `--fuzz 1000 --seed 42` (no `--class`) generates the identical case sequence pre- and post-change — spot-check of the first five `tc.name` strings.

## Acceptance criteria

- `--fuzz N --class X` produces exactly N test cases, all of class X, for every X in `RiscvClass::ALL`.
- `--fuzz N` without `--class` produces the same cases as pre-change (byte-for-byte with a given seed).
- CLAUDE.md and the binary's `--help` text updated to state "`--fuzz N --class X` runs N cases of class X".
- Existing `cargo test -p mdpicoem-harness` suite passes.
- `--fuzz 2000` seed 42 regression baseline stays green (per journal gate).

## Out of scope

- Weight-table tuning (LLD §6 owns that).
- Multi-class selection (`--class a,b,c`) — add if a user asks, not before.
- Applying the same fix to the M33 / M0+ fuzz binaries (they use a different `FuzzClass` path with its own `select_fuzz_class` helper; separate HLD if needed).

**Sign-off: APPROVED as-is.**

Option A is correct — the fact that every class already has a dedicated generator with matching signature makes this a mechanical change, not an architectural one. Option B's RNG-waste and Option C's flag-bloat both rightly rejected.

The seed-reproduction-drift risk is acknowledged and correctly bounded: the common case (`--fuzz N` regression gate) is byte-identical; only the per-class reproduction changes, and the blast radius check (no scripts found) is sound.

CLAUDE.md doc update is in scope for the implementation agent — flag there, not in a separate doc-only commit.

Out-of-scope items (weight tuning, multi-class, M33/M0+ parity) are correctly deferred.
