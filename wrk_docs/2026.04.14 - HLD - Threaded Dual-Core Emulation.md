# Threaded Dual-Core Emulation

Version: 4.0.0
Date: 2026-04-14

## Problem

Dual-core paced throughput on a 3 GHz host: **73.8 MHz per core** (49% of
150 MHz target). Single-core is 143.8 MHz (96%). The 2x gap comes from
sequentially executing both cores in one host thread.

## Target (honest, modeled)

**Realistic ceiling: ~115–125 MHz per emulated core** (77–83% of 150 MHz).

Model:
- Single-core baseline: 143 MHz (21 host cycles/emu cycle)
- Each worker runs one emulated core on its own host core
- Per-quantum overheads: SpinBarrier ×2 (~200ns), coordinator (~100ns),
  atomic-load overhead (~10%), cache coherence traffic (5–15%)
- Expected: 107–121 MHz per core ≈ **2x improvement over 73.8 MHz**

Hitting 150 MHz per core requires additional interpreter work (decode
cache / targeted JIT). Follow-up, not this HLD.

## Host platform & architecture assumptions

| Concern | Assumption | Rationale |
|---|---|---|
| Host CPU | x86_64 | `Pacer` requires `rdtsc`/`rdtscp` + `constant_tsc` CPUID. Same constraint exists today. |
| Host OS | Windows | Thread pinning uses `SetThreadAffinityMask` raw FFI already in `paced_bench.rs`. |
| Host cores | ≥ 3 physical | 2 for workers + 1 for OS/monitoring. On 2-core hosts, threading is counterproductive. Detect and warn. |
| Memory model | TSO-like | x86 provides strong-enough ordering that SeqCst fences are cheap. |

`ThreadedEmulator` gates to `#[cfg(all(target_arch = "x86_64", target_os
= "windows"))]`. Linux and macOS are out of scope for V1; future work
can add `sched_setaffinity` (Linux) / `thread_policy_set` (macOS). No
env vars, no feature flags — the cfg gate is sufficient.

## Non-goals

- No per-cycle bus contention in threaded mode (documented trade-off).
- No hybrid mode — pure single-threaded OR pure threaded per invocation.
- No dynamic thread count.
- No env vars, no feature flags.
- No reverse conversion `ThreadedEmulator → Emulator` — one-way only.
- No non-x86_64 / non-Windows threaded mode in V1.

## Phase 0: Validation + prerequisite refactors

### 0a. Workload study (~2 weeks)

Budget expanded from V3's 1 week — workload authorship is real work.

**Instrumentation (week 1).** Add per-core counters to `paced_bench`:
decode/execute cycles, WFI cycles, contention stall cycles, cross-core
memory access counts, peripheral access fraction (APB/AHB/clocks/QMI/
resets broken out), SIO FIFO/spinlock access counts.

**Synthetic dual-core workload authorship (week 2).** Bootrom runs
core 0 only. We author a representative dual-core Thumb program:
core 0 does periodic GPIO toggle + shared SRAM write + SIO FIFO send;
core 1 does tight decode loop + shared SRAM read + SIO FIFO receive.
Proxy for "realistic firmware that uses both cores" — not a prediction
of OneROM, an honest substitute.

**Compound decision gate.** Proceed to Phase 0b only if ALL of:
- Core 1 active (non-WFI) ratio ≥ 20% on synthetic workload
- Cross-core SRAM writes < 10% of total accesses (otherwise cache
  coherence traffic dominates — threading won't help)
- Peripheral access ratio measured (informs mutex sharding strategy)

If any gate fails, shelve threaded mode, pivot to decode cache.

**Chicken-and-egg acknowledgement.** OneROM doesn't exist. We use
bootrom + synthetic as a proxy. Phase 5's benchmark will validate
against whatever real workload emerges.

### 0b. Prerequisite refactors (~3–4 weeks)

Dependency chain (NOT independent commits — they sequence):

```
0b.1 PPB move  ─►  0b.2 LDREX/STREX  ─►  0b.3 atomize cross-core + NVIC
     (1 wk)         (1 wk)                 (3–4 days)
```

All three touch `src/core/mod.rs`. 0b.1 and 0b.2 both touch
`execute_thumb32.rs`. Must land in order.

**0b.1 Move PPB to `CortexM33`** (1 wk). PPB is per-core in hardware.
Currently `Bus::ppb: [Ppb; 2]` accessed via `Bus::active_core()` — a
shared mutable flag, unsafe under threading. Move `Ppb` onto
`CortexM33`. Delete `Bus::active_core()`. Every bus method takes
`CoreId` parameter.

**0b.2 Implement LDREX/STREX properly** (1 wk). Per-core
`exclusive_address: Option<u32>` AND `exclusive_value: u32` on
`CortexM33`. LDREX captures both. STREX performs a CAS on the shared
memory word using the captured value — only succeeds if the word
still equals it. This is genuinely atomic against concurrent writers.
Snoop logic invalidates the monitor on ANY write from EITHER core.

**0b.3 Atomize cross-core `CortexM33` fields + NVIC** (3–4 days).
Review caught V3 missed NVIC. Peripheral MMIO writes on worker 0
can raise an IRQ for core 1 by writing core 1's NVIC from worker 0.
ISPR/ICPR/IABR must be atomic.

## Phase 1: Threaded execution path

### API: types, one-way conversion, peripheral injection

```rust
/// Single-threaded cycle-accurate. Reference for validation.
pub struct Emulator { ... }

impl Emulator {
    pub fn run(&mut self, cycles: u64) -> u64 { ... }
}

#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
pub struct ThreadedEmulatorBuilder { ... }

#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
impl ThreadedEmulatorBuilder {
    pub fn from_emulator(emu: Emulator, peripherals: Peripherals) -> Self;
    pub fn build(self) -> ThreadedEmulator;
}

#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
pub struct ThreadedEmulator { ... }

#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
impl ThreadedEmulator {
    pub fn run(
        &mut self,
        pacer: &mut Pacer,
        duration: Duration,
        stop: Arc<StopSignal>,
    ) -> ExitReason;
}

pub enum ExitReason {
    Duration,
    Stopped,
    BothWfi,
    Breakpoint { core: CoreId, pc: u32 },
    EmulatorError { core: CoreId, fault: Fault },
    Panic(String),

```

**Builder resolves peripheral injection.** Today
`EmulatorBuilder::new(config).build()` injects `Box<dyn Peripheral>`
trait objects into `Emulator`. `ThreadedEmulatorBuilder::from_emulator`
extracts them, re-wraps with `Arc<Mutex<…>>` per shard, moves them
into `ThreadedEmulator`'s shared state.

**Peripheral trait migration:** add `ThreadSafePeripheral: Send + Sync`
super-trait. All current impls are `Send + Sync` trivially; the
bound is a compile-time check.

### StopSignal + shutdown protocol

```rust
pub struct StopSignal(AtomicBool);
impl StopSignal {
    pub fn new() -> Arc<Self> { ... }
    pub fn stop(&self) { self.0.store(true, Release); }
    pub fn is_stopped(&self) -> bool { self.0.load(Acquire) }
}
```

**Explicit shutdown protocol:** When worker 0's coordinator phase
sees `stop.is_stopped()`, it calls `barrier.poison()` BEFORE its
second barrier arrival. Worker 1, waiting, sees poison and returns
`BarrierResult::Poisoned`. Worker 1 then exits its loop cleanly.

This is the ONLY path to clean shutdown. Workers always route through
the barrier; they never exit without a barrier traversal.

### Worker panic handling

`catch_unwind` around each worker's loop body. On panic:
1. `stop_signal.stop()`
2. `barrier.poison()`
3. Store payload via `Arc<Mutex<Option<PanicPayload>>>`
4. Worker exits

`ThreadedEmulator::run` returns `ExitReason::Panic(payload)` on
detection.

### Thread topology: 2 workers, coordinator folded into worker 0

```
  ┌────────────────────────────────┐  ┌────────────────────────────┐
  │ Worker 0 (pinned, coordinator) │  │ Worker 1 (pinned)          │
  │                                │  │                            │
  │ loop {                         │  │ loop {                     │
  │   for 0..Q { core0.step() }    │  │   for 0..Q { core1.step()} │
  │   barrier.wait()               │  │   barrier.wait()           │
  │                                │  │                            │
  │   pacer.spin_wait_quantum()    │  │   (parks at 2nd barrier)   │
  │   handle_cross_core_events()   │  │                            │
  │   if stop.is_stopped() {       │  │                            │
  │     barrier.poison();          │  │                            │
  │     return;                    │  │                            │
  │   }                            │  │                            │
  │   barrier.wait()               │  │   barrier.wait()           │
  │ }                              │  │ }                          │
  └────────────────────────────────┘  └────────────────────────────┘
```

**`handle_cross_core_events()` covers everything `Emulator::step` does
between `bus.clear_contention_state()` and the next `clock.tick()`:**

1. Timer ticks (SysTick, RTC, watchdog)
2. MTIME advance (SIO machine timer)
3. SIO divider result-ready propagation
4. SIO interpolator tick
5. Doorbell propagation (atomic read → peer NVIC atomic write)
6. PIO block tick (all three blocks)
7. GPIO high/low merge + noise injection
8. Peripheral `step()` for all APB/AHB peripherals
9. WFI wake check (per-core): if halted AND peer NVIC has pending
   enabled IRQ, clear halted
10. Dual-WFI deadlock check: if both halted AND no timer fires within
    remaining duration, exit with `ExitReason::BothWfi`
11. Decrement `remaining_duration`

Coordinator overhead dominates per-quantum cost (~20% of quantum).
Worker 1 spin-waits during this. Accepted because the alternative
(third coordinator thread) burns a whole host core.

### SpinBarrier

```rust
pub struct SpinBarrier {
    generation: AtomicU32,
    count:      AtomicU32,
    poisoned:   AtomicBool,
}

pub enum BarrierResult { Released, Poisoned }

impl SpinBarrier {
    pub fn wait(&self) -> BarrierResult {
        if self.poisoned.load(Acquire) { return BarrierResult::Poisoned; }
        let my_gen = self.generation.load(Acquire);
        let n = self.count.fetch_add(1, AcqRel) + 1;
        if n == 2 {
            self.count.store(0, Relaxed);
            self.generation.store(my_gen.wrapping_add(1), Release);
        } else {
            loop {
                if self.poisoned.load(Acquire) { return BarrierResult::Poisoned; }
                if self.generation.load(Acquire) != my_gen { break; }
                std::hint::spin_loop();
            }
        }
        BarrierResult::Released
    }
    pub fn poison(&self) { self.poisoned.store(true, Release); }
}
```

Target: <100 ns ready-to-ready. Two crossings per quantum.

### Shared memory: AtomicU32 backing

```rust
pub struct SharedMemory {
    sram:      Box<[AtomicU32]>,  // 130K × 4B = 520 KB
    rom:       Box<[u8]>,         // read-only, no atomics
    xip:       Box<[AtomicU32]>,  // if writable via QMI
    exclusive: [AtomicU64; 2],    // per-core monitor: tag + valid
}
```

- `read32`: single atomic load (Relaxed)
- `read16`/`read8`: word load + bit extract
- `write32`: atomic store + `snoop_exclusive`
- `write16`/`write8`: masked CAS loop + `snoop_exclusive`
- `cas32(addr, expected, new) -> bool`: for STREX

### STREX correctness

V3 had a race: snoop after the write wasn't atomic. V4 fix: STREX
performs a CAS using the value captured at LDREX time.

```rust
// LDREX rX, [rY]
core.exclusive_address = Some(rY_value);
core.exclusive_value   = shared_memory.read32(rY_value);
rX = core.exclusive_value;

// STREX rZ, rX, [rY]
if core.exclusive_address != Some(rY_value) {
    rZ = 1; // fail: peer invalidated our monitor
    return;
}
match shared_memory.cas32(rY_value, core.exclusive_value, rX) {
    true  => { rZ = 0; snoop_invalidate_all(rY_value); } // success
    false => { rZ = 1; }                                 // value changed
}
core.exclusive_address = None; // STREX always clears local monitor
```

The CAS on the shared word is the atomic synchronization point.
Two cores racing each call CAS with their own captured values;
exactly one wins. `snoop_invalidate_all(addr)` clears all cores'
monitors on every memory write via Release/Acquire CAS, so a
monitor-clear happens-after the data write.

### Memory ordering: DMB/DSB → `fence(SeqCst)`

V3 fix retained. AcqRel is insufficient (no store-load ordering);
SeqCst emits `mfence` on x86 which is correct.

```rust
match instr {
    DMB | DSB => std::sync::atomic::fence(Ordering::SeqCst),
    ISB => {
        std::sync::atomic::fence(Ordering::SeqCst);
        // Future: flush decode cache if added
    }
}
```

Single-threaded mode: no-ops.

### WFI / halted semantics

```rust
// In core step when WFI executed:
if instr == WFI {
    core.halted.store(true, Release);
    return;
}

// In worker loop:
loop {
    for _ in 0..Q {
        if core.halted.load(Acquire) { break; }
        core.step(shared, ...);
    }
    barrier.wait();
    // worker 0 runs coordinator; worker 1 waits
    barrier.wait();
}

// Coordinator wake check:
for core_id in 0..2 {
    if cores[core_id].halted.load(Acquire)
       && cores[core_id].ppb.nvic.any_pending_enabled_atomic() {
        cores[core_id].halted.store(false, Release);
    }
}
if both_halted && !any_timer_firing_before(remaining_duration) {
    return ExitReason::BothWfi;
}
```

### SIO: threaded-only redesign

```rust
pub struct ThreadedSio {
    fifo_to_core0_prod: rtrb::Producer<u32>,
    fifo_to_core0_cons: rtrb::Consumer<u32>,
    fifo_to_core1_prod: rtrb::Producer<u32>,
    fifo_to_core1_cons: rtrb::Consumer<u32>,
    spinlocks: [AtomicU32; 32],
    fifo_st_0: AtomicU32,     // sticky WOF/ROE per core
    fifo_st_1: AtomicU32,

    // Per-core hardware state - atomic so coordinator can advance
    // and owning core can poll
    div_state_0: AtomicU64,
    div_state_1: AtomicU64,
    interp0_core_0: AtomicU64,
    interp1_core_0: AtomicU64,
    interp0_core_1: AtomicU64,
    interp1_core_1: AtomicU64,

    // Doorbells
    doorbell_0: AtomicU32,
    doorbell_1: AtomicU32,
}
```

`rtrb` vendored dep provides the FIFO. Sticky flags translated from
push/pop success returns. Divider/interp state atomized so the
coordinator can tick results.

**Doorbell propagation:** write to `doorbell_0` by core 0 must raise
core 1 NVIC IRQ. Coordinator reads doorbell atomic at quantum
boundary, writes peer NVIC atomic. Firmware-observable latency: up
to 1 quantum. Matches SIO "asynchronous delivery" spec.

### Peripherals: sharded mutexes with RAII lock order

```rust
pub struct Peripherals {
    apb:    Mutex<ApbPeripherals>,
    ahb:    Mutex<AhbPeripherals>,
    clocks: Mutex<ClocksPll>,
    qmi:    Mutex<QmiRegs>,
    resets: Mutex<ResetsState>,
}
```

**Lock order: `clocks < qmi < resets < apb < ahb`.** Matches boot
sequence (clocks → flash → peripherals).

**Enforcement: runtime mechanism (not debug_assert-only).** Each
peripheral lock is obtained through a `PeripheralGuard` RAII wrapper
that tracks acquired levels in a thread-local. Out-of-order acquire
panics in debug, logs and continues in release. ~30 lines of code,
catches deadlock precursors in ALL builds.

```rust
thread_local! {
    static LOCK_STACK: RefCell<SmallVec<[u8; 4]>> = RefCell::new(SmallVec::new());
}

pub struct PeripheralGuard<'a, T> {
    inner: MutexGuard<'a, T>,
    level: u8,
}

impl<'a, T> PeripheralGuard<'a, T> {
    fn acquire(mutex: &'a Mutex<T>, level: u8) -> Self {
        LOCK_STACK.with(|s| {
            if let Some(&top) = s.borrow().last() {
                if level <= top {
                    if cfg!(debug_assertions) {
                        panic!("lock order violation: {} <= {}", level, top);
                    } else {
                        eprintln!("WARN: lock order violation {} <= {}", level, top);
                    }
                }
            }
        });
        let inner = mutex.lock().unwrap();
        LOCK_STACK.with(|s| s.borrow_mut().push(level));
        Self { inner, level }
    }
}

impl<'a, T> Drop for PeripheralGuard<'a, T> {
    fn drop(&mut self) {
        LOCK_STACK.with(|s| { s.borrow_mut().pop(); });
    }
}
```

If profiling shows a single mutex is hot, shard further (per
peripheral instance). Defer until measured.

## Rollback policy

Phase 5 success criterion: `paced_bench --threaded --dual-core` on
the synthetic workload achieves ≥110 MHz per core.

- **<110 MHz:** revert Phases 3–5 (ThreadedEmulator, worker, run
  threaded). Phases 0a–2 stay — they're independent improvements
  (PPB move, proper LDREX/STREX, atomics, shared memory type,
  threaded SIO primitives) useful for correct single-threaded AND
  future threading. Pivot to decode cache.
- **≥110 but <120 MHz:** accept. Document gap. Decode cache as
  multiplicative follow-up.
- **≥120 MHz:** ship.

No feature flags; we either keep or delete.

## What this does NOT do

- No JIT or decode cache (separate follow-ups).
- No cycle-accurate dual-core (single-threaded retains that).
- No support for Hazard3 RISC-V cores.
- No Linux/macOS threaded mode in V1.

## Risks

1. **Phase 0a says "no".** Compound gate might fail on synthetic.
   Shelve; decode cache becomes the follow-up. Phases 0b still ship.
2. **Target not achieved.** Rollback policy above.
3. **Cache coherence traffic worse than modeled.** Phase 0a's
   cross-core write gate catches this before investment.
4. **`rtrb` audit.** Single dep, review once during Phase 2.
5. **Low-core host.** 2-core host = worker 1 shares with OS.
   Detect at startup; error out clearly.

- **Hazard3 RISC-V**: out of scope.
