# Phase 6: PIO — Low-Level Design

Version: 0.1.0
Date: 2026-04-13
Parent: HLD Section 15, Phase 6
Depends: Phase 5 complete (dual-core + SIO)

## 1. Purpose

Implement the RP2350's three Programmable I/O (PIO) blocks. Each block
contains 4 state machines running a 9-instruction ISA with fractional
clock dividers, TX/RX FIFOs, autopush/autopull, and GPIO pin mapping.
Add a minimal GPIO pin state model so PIO output is observable.

### Milestone

PIO UART TX and SPI examples produce correct waveforms: a PIO program
loaded into instruction memory, configured with the appropriate clock
divider and pin mapping, shifts data out of the TX FIFO onto GPIO pins
with cycle-accurate timing verifiable against expected waveform patterns.

### What exists today

| Component | Status | Gap for Phase 6 |
|-----------|--------|-----------------|
| `mdrp2354-pio` crate | Empty stub (`// Phase 6.`) | Not used — implement PIO as module in core crate |
| `PioInterface` trait | Defined in `lib.rs:27-32` | Remove — direct integration, no trait objects |
| `GpioChange` struct | Defined in `lib.rs:35-38` | Remove — replaced by GPIO pin state model |
| Bus AHB dispatch | Region 0x5 falls through to `peripheral_regs` HashMap | Add PIO0/1/2 dispatch at 0x5020/5030/5040 |
| GPIO model | SIO has `gpio_out`/`gpio_oe`/`gpio_in`; `gpio_in` always 0 | Update `gpio_in` to reflect PIO-driven pins |
| `Emulator::step()` | Steps cores + SIO mtime | Add PIO stepping after core steps |
| DMA | Does not exist | Deferred — milestone achievable without DMA |
| PIO IRQ → NVIC | NVIC stubs return 0 | Deferred — PIO-internal IRQ flags only |

## 2. Key decisions

**PIO in the core crate, not mdrp2354-pio.** The separate crate requires
trait objects for bus dispatch (circular dependency otherwise). This adds
indirection on the hot path and wiring complexity for no benefit — PIO is
a module like SIO, not an external plugin. The `mdrp2354-pio` crate
stays as a dead placeholder (remove later if desired).

**No function-select register emulation.** The real RP2350 has IO_BANK0
registers (0x4001_4000) with per-pin FUNCSEL fields that route
peripherals to GPIO pads. For Phase 6 we skip this and merge GPIO output
by output-enable priority: if a PIO block drives a pin (OE=1), its value
wins over SIO. This is sufficient for all PIO test programs and avoids
emulating a register block that no PIO program writes directly (the SDK
helper functions do, but those aren't running on the emulator yet).

**DMA deferred.** The milestone is PIO waveform correctness. PIO programs
can be fed via CPU writes to TX FIFO — DMA is an optimization. FIFOs
expose a DREQ-ready interface so DMA can plug in later.

**PIO-internal IRQ only.** The 8 IRQ flags per PIO block are implemented
(needed for WAIT IRQ and IRQ instructions). Routing PIO IRQs to NVIC
lines is deferred — no Phase 6 test program needs NVIC-delivered PIO
interrupts.

## 3. PIO block architecture

### 3.1 Data structures

```
crates/mdrp2354/src/pio/
  mod.rs       — PioBlock struct, register dispatch, stepping
  sm.rs        — StateMachine struct, clock divider, instruction execution
  decode.rs    — 16-bit instruction decoder
  fifo.rs      — TX/RX FIFOs with joining
```

```rust
/// One PIO block (RP2350 has three: PIO0, PIO1, PIO2).
pub struct PioBlock {
    sm: [StateMachine; 4],
    instr_mem: [u16; 32],       // Shared 32-word program memory
    irq_flags: u8,              // 8 IRQ flags (bits 0-7)
    irq_force: u8,              // Forced IRQ flags
    input_sync_bypass: u32,     // Stub — store only
    pad_out: u32,               // Combined SM output values
    pad_oe: u32,                // Combined SM output enables
}

pub struct StateMachine {
    // Program state
    pc: u8,                     // 0-31
    x: u32,                     // Scratch register X
    y: u32,                     // Scratch register Y
    isr: u32,                   // Input shift register
    osr: u32,                   // Output shift register
    isr_count: u8,              // Bits shifted into ISR (0-32)
    osr_count: u8,              // Bits shifted out of OSR (0-32)

    // Execution state
    delay_count: u8,            // Post-instruction delay countdown
    stalled: bool,              // WAIT / blocking PUSH/PULL stall
    enabled: bool,              // CTRL SM_ENABLE bit

    // Clock
    clkdiv_int: u16,            // Integer part of 16.8 divider
    clkdiv_frac: u8,            // Fractional part (8 bits)
    clkdiv_acc: u16,            // Fractional accumulator (9 bits needed)

    // Configuration (from SMn registers)
    execctrl: u32,              // EXECCTRL register value
    shiftctrl: u32,             // SHIFTCTRL register value
    pinctrl: u32,               // PINCTRL register value

    // FIFOs
    tx_fifo: PioFifo,
    rx_fifo: PioFifo,

    // Pin output (per-SM, merged into PioBlock.pad_out/pad_oe)
    out_pins: u32,              // OUT/MOV pin values
    out_pindirs: u32,           // OUT/SET PINDIRS values
    set_pins: u32,              // SET pin values
    set_pindirs: u32,           // SET PINDIRS values
    sideset_pins: u32,          // Side-set pin values
}
```

### 3.2 Fractional clock divider

Each SM has a 16-bit integer + 8-bit fractional clock divider. On every
system clock cycle, the fractional accumulator advances by `frac`. When
it overflows (≥256), the SM gets an extra tick that cycle.

```
let effective_div = if int == 0 && frac == 0 { 1 } else { int };
// Each system clock:
acc += frac;
let extra = if acc >= 256 { acc -= 256; 1 } else { 0 };
// SM ticks once every `effective_div` system clocks,
// with occasional (effective_div - 1) intervals from frac overflow.
```

Special cases:
- `int=0, frac=0` → SM runs every system clock (divider = 1)
- `int=1, frac=0` → SM runs every system clock (divider = 1)
- `int=1, frac=128` → SM runs at ~1.5x system clock period
  (alternates 1-cycle and 2-cycle intervals)
- `int=N, frac=0` → SM runs every N system clocks

Implementation: a down-counter `tick_counter` initialized to
`effective_div - 1`. Each system clock it decrements. At zero the SM
executes one PIO cycle (instruction or delay tick) and reloads. The
fractional accumulator shortens one interval per overflow.

```rust
/// Returns true if this SM should execute a PIO cycle this system clock.
fn clock_tick(&mut self) -> bool {
    if !self.enabled { return false; }

    let int = self.clkdiv_int.max(1) as u32;

    // Fractional accumulator
    self.clkdiv_acc += self.clkdiv_frac as u16;
    let frac_tick = if self.clkdiv_acc >= 256 {
        self.clkdiv_acc -= 256;
        true
    } else {
        false
    };

    self.tick_counter = self.tick_counter.saturating_sub(1);
    if frac_tick && self.tick_counter > 0 {
        self.tick_counter -= 1; // Fractional shortening
    }

    if self.tick_counter == 0 {
        self.tick_counter = (int - 1) as u8;
        true
    } else {
        false
    }
}
```

Note: when `int` is large the counter type may need to be `u16`. Since
the integer divider is 16 bits, `tick_counter` should be `u16`.

### 3.3 Instruction decoder

PIO instructions are 16 bits. The top 3 bits select the opcode. The
next 5 bits encode delay and/or side-set (split configured per-SM).
The bottom 8 bits are opcode-specific.

```
[15:13]  Opcode (3 bits)
[12:8]   Delay / side-set (5 bits, split per PINCTRL.SIDESET_COUNT)
[7:0]    Operand (8 bits, layout varies by opcode)
```

**Delay / side-set split:**

PINCTRL.SIDESET_COUNT (bits [31:29]) specifies the total bits used for
side-set (including the enable bit if EXECCTRL.SIDE_EN is set).

```
sideset_count = pinctrl[31:29]
delay_bits = 5 - sideset_count
```

If EXECCTRL.SIDE_EN is set, the MSB of the side-set field is an enable
bit — side-set only fires when this bit is 1.

```
instruction bits [12:8] = dddss  (example: 2 side-set bits, 3 delay)
                        = ssddd  (wrong — side-set is in the upper bits)
```

Side-set occupies the TOP bits of the [12:8] field, delay the BOTTOM.

**Decoded instruction:**

```rust
pub struct DecodedInsn {
    pub op: PioOp,
    pub delay: u8,
    pub sideset: Option<u8>,  // None if side-set disabled or SIDE_EN=1 and enable=0
}

pub enum PioOp {
    Jmp { condition: u8, address: u8 },
    Wait { polarity: bool, source: u8, index: u8 },
    In { source: u8, bit_count: u8 },
    Out { destination: u8, bit_count: u8 },
    Push { if_full: bool, block: bool },
    Pull { if_empty: bool, block: bool },
    Mov { destination: u8, op: u8, source: u8 },
    Irq { clear: bool, wait: bool, index: u8 },
    Set { destination: u8, data: u8 },
}
```

Operand field layouts per opcode:

| Opcode | Bits [7:0] | Fields |
|--------|-----------|--------|
| `000` JMP | `ccc aaaaa` | condition[7:5], address[4:0] |
| `001` WAIT | `p ss iiiii` | polarity[7], source[6:5], index[4:0] |
| `010` IN | `sss nnnnn` | source[7:5], bit_count[4:0] (0→32) |
| `011` OUT | `ddd nnnnn` | destination[7:5], bit_count[4:0] (0→32) |
| `100` PUSH/PULL | `d ie b 00000` | direction[7] (0=push,1=pull), if_x[6], block[5] |
| `101` MOV | `ddd oo sss` | destination[7:5], operation[4:3], source[2:0] |
| `110` IRQ | `0 c w nnnnn` | clear[6], wait[5], index[4:0] |
| `111` SET | `ddd vvvvv` | destination[7:5], data[4:0] |

### 3.4 Instruction executor

Every PIO instruction takes exactly 1 PIO clock cycle (plus any delay
cycles and stall cycles). The execution flow per PIO tick:

```
if delay_count > 0:
    delay_count -= 1
    apply side-set (if configured — side-set persists during delay)
    return

if stalled:
    re-evaluate stall condition
    if still stalled: return
    stalled = false

fetch instruction from instr_mem[pc]
decode
execute (may set stalled = true)
if not stalled:
    apply side-set
    set delay_count = decoded.delay
    advance PC (with wrap check)
```

**PC advancement and WRAP:**

After each non-stalling instruction, PC increments. If PC was at
`wrap_top`, it wraps to `wrap_bottom` instead of incrementing. This is
NOT a jump — no extra cycle. The instruction at `wrap_top` executes
normally, then PC becomes `wrap_bottom`.

```rust
fn advance_pc(&mut self) {
    let wrap_top = ((self.execctrl >> 12) & 0x1F) as u8;
    let wrap_bottom = ((self.execctrl >> 7) & 0x1F) as u8;
    if self.pc == wrap_top {
        self.pc = wrap_bottom;
    } else {
        self.pc = (self.pc + 1) & 0x1F;
    }
}
```

**Instruction semantics (key points only — obvious instructions omitted):**

**JMP conditions:**

| Code | Condition | Semantics |
|------|-----------|-----------|
| 000 | Always | Unconditional |
| 001 | !X | X == 0 |
| 010 | X-- | Post-decrement X; jump if X was non-zero before decrement |
| 011 | !Y | Y == 0 |
| 100 | Y-- | Post-decrement Y; jump if Y was non-zero before decrement |
| 101 | X!=Y | X != Y |
| 110 | PIN | Input pin (JMP_PIN from EXECCTRL) is high |
| 111 | !OSRE | OSR is not empty (osr_count < threshold) |

**IN** shifts `bit_count` bits from `source` into ISR. Direction depends
on SHIFTCTRL.IN_SHIFTDIR (0=left, 1=right). Bit count of 0 means 32.
After shifting, `isr_count += bit_count`. If autopush is enabled and
`isr_count >= push_threshold`, automatically push ISR to RX FIFO and
clear ISR.

**OUT** shifts `bit_count` bits from OSR to `destination`. Direction
depends on SHIFTCTRL.OUT_SHIFTDIR. After shifting, `osr_count +=
bit_count`. If autopull is enabled and `osr_count >= pull_threshold`,
automatically refill OSR from TX FIFO.

Special destination `OUT EXEC` (101): the shifted-out value is executed
as a PIO instruction on the next cycle. Special destination `OUT PC`
(101): shifted-out value sets PC directly.

**PUSH/PULL:**

PUSH writes ISR to RX FIFO and clears ISR + isr_count. If `block` and
FIFO is full, SM stalls. If `if_full` and FIFO is full, instruction is
a no-op (no stall, no push).

PULL reads TX FIFO into OSR and sets osr_count to 0. If `block` and
FIFO is empty, SM stalls. If `if_empty` and FIFO is empty, copies X
into OSR instead.

**Autopull fires before OUT reads OSR** — this is critical. When
osr_count reaches the threshold, the next OUT instruction auto-refills
OSR from TX FIFO before shifting. If TX FIFO is empty and autopull would
fire, the SM stalls (same as blocking PULL).

**Autopush fires after IN writes ISR** — when isr_count reaches the
threshold after an IN instruction, ISR is pushed to RX FIFO
automatically.

**MOV operations:**

| Code | Operation |
|------|-----------|
| 00 | None (copy) |
| 01 | Invert (bitwise NOT) |
| 10 | Bit-reverse (reverse all 32 bits) |

**IRQ:**

`index[4]` is the relative flag. When set, the actual IRQ number is
`(index[1:0] + sm_id) % 4 | (index[2] & 4)`. This lets each SM address
its own IRQ flag without hardcoding.

If `clear`: clear the flag. If `!clear`: set the flag. If `wait`: stall
until the flag is in the desired state (cleared if we just set it —
i.e., wait for another SM or CPU to clear it).

**WAIT sources:**

| Code | Source | Semantics |
|------|--------|-----------|
| 00 | GPIO | Wait for absolute GPIO pin `index` to match `polarity` |
| 01 | PIN | Wait for input pin (in_base + index) to match `polarity` |
| 10 | IRQ | Wait for IRQ flag `index` to match `polarity`; auto-clear on match |

### 3.5 FIFOs

Each SM has a TX FIFO and RX FIFO, each 4 entries deep.

```rust
pub struct PioFifo {
    buf: [u32; 8],   // 8 slots to support joined mode
    head: u8,
    tail: u8,
    count: u8,
    depth: u8,       // 4 normally, 8 when joined
}
```

**Joining:** SHIFTCTRL.FJOIN_TX joins both FIFOs into an 8-deep TX FIFO
(RX FIFO unavailable). FJOIN_RX does the reverse. Only one can be set.

When joining is reconfigured, both FIFOs are flushed.

**FSTAT register (0x004):**

```
[27:24] TXEMPTY  — bit N set when SM N's TX FIFO is empty
[19:16] TXFULL   — bit N set when SM N's TX FIFO is full
[11:8]  RXEMPTY  — bit N set when SM N's RX FIFO is empty
[3:0]   RXFULL   — bit N set when SM N's RX FIFO is full
```

**FLEVEL register (0x00C):** 4 bits per SM per direction (TX level in
[7:4,15:12,23:20,31:28], RX in [3:0,11:8,19:16,27:24]). Encodes the
number of entries currently in the FIFO.

### 3.6 GPIO integration

**Pin mapping** (from PINCTRL):

| Field | Bits | Meaning |
|-------|------|---------|
| OUT_BASE | [4:0] | First GPIO for OUT/MOV PINS |
| SET_BASE | [9:5] | First GPIO for SET PINS |
| SIDESET_BASE | [14:10] | First GPIO for side-set |
| IN_BASE | [19:15] | First GPIO for IN PINS / WAIT PIN |
| OUT_COUNT | [25:20] | Number of OUT pins (0-32) |
| SET_COUNT | [28:26] | Number of SET pins (0-5) |
| SIDESET_COUNT | [31:29] | Side-set bits (including enable) |

Pin indices wrap modulo 32. When OUT writes 8 bits starting at pin 28,
it wraps: pins 28-31 get bits 0-3, pins 0-3 get bits 4-7.

**GPIO state model:**

Add to Bus:

```rust
pub gpio_in: u32,  // Combined pin state (readable by SIO and PIO)
```

Replace SIO's `gpio_in` field — Bus becomes the single source of truth
for pin input state. SIO GPIO_IN reads (offset 0x004) return
`bus.gpio_in` instead of `sio.gpio_in`.

After each PIO step, the emulator merges pin state:

```rust
fn update_gpio(&mut self) {
    // Start with SIO-driven pins
    let mut out = self.bus.sio.gpio_out & self.bus.sio.gpio_oe;
    let mut oe = self.bus.sio.gpio_oe;

    // PIO blocks override (last block with OE wins)
    for pio in &self.bus.pio {
        let pio_mask = pio.pad_oe;
        out = (out & !pio_mask) | (pio.pad_out & pio_mask);
        oe |= pio_mask;
    }

    self.bus.gpio_in = out;
}
```

Each PIO block's `pad_out`/`pad_oe` are updated at the end of
`PioBlock::step()` by merging all 4 SMs' pin outputs. SM0 has lowest
priority; SM3 highest (matching hardware).

| | | | |
| **Per-SM registers (stride 0x18, SM0 at 0x0C8):** | | |

## 5. Bus integration

### 5.1 Bus dispatch

Add PIO blocks to Bus:

```rust
pub pio: [PioBlock; 3],
```

In Bus `read32` and `write32`, within the region 0x4/0x5 match:

```rust
0x5020_0000 => self.pio[0].read32(offset),
0x5030_0000 => self.pio[1].read32(offset),
0x5040_0000 => self.pio[2].read32(offset),
```

Atomic alias handling is already done by the bus before dispatch (the
`canonical` / `alias` computation). PIO `write32` receives the alias
value for SET/CLR/XOR semantics on applicable registers (CTRL, IRQ).

Sub-word access: `read8`/`read16` extract from `read32` (same pattern
as SIO). `write8`/`write16` ignored (PIO registers are 32-bit access
only in practice).

### 5.2 Emulator step integration

In `Emulator::step()`, after core stepping and WFE/SEV wake check:

```rust
// Step PIO blocks
let gpio_in = self.bus.gpio_in;
for pio in &mut self.bus.pio {
    pio.step(gpio_in);
}
self.update_gpio();

self.bus.sio.tick_mtime();
```

PIO steps after cores because cores may have written to PIO registers
(FIFO pushes, SM enables) on this cycle. The PIO step processes those
writes and executes any SM that ticks.

### 5.3 Cleanup

Remove from `lib.rs`:
- `PioInterface` trait (replaced by direct `PioBlock` module)
- `GpioChange` struct (replaced by `pad_out`/`pad_oe` model)

Move `gpio_in` from Sio to Bus. Update SIO GPIO_IN reads (offset 0x004)
to return `bus.gpio_in` (passed as parameter to `sio.read32` or read
directly by Bus before delegating).

## 6. Implementation stages

### Stage A: Module structure + registers + bus dispatch

**Create** `crates/mdrp2354/src/pio/mod.rs`, `sm.rs`, `decode.rs`,
`fifo.rs`.

**Implement:**
- `PioBlock` struct with `[StateMachine; 4]`, `instr_mem`, `irq_flags`
- `PioBlock::read32(offset)` / `write32(offset, val, alias)` register dispatch
- `StateMachine` struct with all config register fields
- `PioFifo` struct (push, pop, is_full, is_empty, level, flush)
- Bus dispatch: add `pio: [PioBlock; 3]` to Bus, route AHB addresses
- Remove `PioInterface` trait and `GpioChange` from `lib.rs`
- Move `gpio_in` from Sio to Bus

**Tests (in `pio/mod.rs`):**
- Register roundtrip: write SMn_CLKDIV/EXECCTRL/SHIFTCTRL/PINCTRL, read back
- Instruction memory: write 32 words, read back from DBG_CFGINFO
- FIFO: push to TXF0, check FSTAT reflects non-empty, pop from RXF0
- FIFO joining: set FJOIN_TX, verify 8-deep TX FIFO
- CTRL: enable/disable SMs, verify `sm.enabled` state
- Bus dispatch: write PIO0/1/2 registers via Bus::write32 at correct addresses
- IRQ: write IRQ_FORCE, read IRQ, W1C to clear
- FSTAT/FLEVEL accuracy across FIFO operations

**Exit criterion:** CPU code can program PIO registers through the bus.

### Stage B: Clock divider + instruction decoder + executor

**Implement:**
- `decode.rs`: `decode(insn: u16, pinctrl: u32, execctrl: u32) -> DecodedInsn`
- Side-set / delay extraction based on PINCTRL.SIDESET_COUNT and EXECCTRL.SIDE_EN
- `StateMachine::clock_tick() -> bool` fractional divider
- `StateMachine::execute_cycle()` — fetch, decode, execute, delay, wrap
- All 9 PIO instructions (see §3.4)
- Stall logic for WAIT, blocking PUSH/PULL
- `PioBlock::step(gpio_in)` — tick each enabled SM's clock, execute if ready
- Add PIO stepping to `Emulator::step()`

**Tests:**
- Clock divider: verify tick frequency for int=1/frac=0, int=2/frac=0,
  int=1/frac=128, int=65535/frac=0
- Decoder: one test per opcode with known bit patterns
- Side-set/delay split: test with sideset_count=0,1,2,3,5
- JMP: all 8 conditions
- SET X/Y + MOV: verify register state
- WRAP: instruction at wrap_top wraps to wrap_bottom, no extra cycle
- Delay: instruction with delay=3 takes 4 total PIO cycles
- WAIT GPIO: SM stalls until pin matches polarity
- IRQ set/clear/wait with relative indexing
- OUT/IN: shift left vs right, bit_count=0 (meaning 32)
- MOV with invert and bit-reverse operations
- PUSH/PULL blocking vs non-blocking
- Force-execute via SMn_INSTR write

**Exit criterion:** PIO programs execute correctly in isolation. A simple
SET/JMP loop toggles pin state at the configured clock rate.

### Stage C: Autopush/autopull + GPIO integration

**Implement:**
- Autopush: after IN, if `isr_count >= push_threshold`, push ISR → RX
  FIFO and clear ISR
- Autopull: before OUT reads OSR, if `osr_count >= pull_threshold`,
  refill OSR from TX FIFO (stall if empty)
- GPIO pin state model: `bus.gpio_in` updated from merged SIO + PIO state
- PIO pin mapping: apply OUT/SET/side-set values to correct GPIO pins
  per PINCTRL bases and counts, with modulo-32 wrapping
- `PioBlock::step()` merges all 4 SMs' pin outputs into `pad_out`/`pad_oe`
- `Emulator::update_gpio()` merges SIO + PIO into `bus.gpio_in`
- SIO GPIO_IN reads return `bus.gpio_in`

**Tests:**
- Autopush: IN 8 bits four times → ISR auto-pushed at threshold 32
- Autopush threshold 16: push after 2x IN 8
- Autopull: OUT reads from FIFO-refilled OSR
- Autopull stall: empty TX FIFO stalls SM when autopull fires
- Pin mapping: OUT 4 bits at out_base=5 sets GPIO [8:5]
- Pin wrap: OUT 4 bits at out_base=30 sets GPIO [1:0,31:30]
- Side-set: side-set persists during delay cycles
- GPIO merge: PIO drives pin 5, SIO drives pin 10, gpio_in reflects both
- PIO overrides SIO on shared pin: PIO OE=1 on pin 7 wins over SIO

**Exit criterion:** PIO programs can shift data out to GPIO pins and the
pin state is observable via SIO GPIO_IN reads.

### Stage D: Waveform integration tests

**Test programs and verification:**

1. **PIO blinky** — Toggle GPIO 25 at a known rate.
   - Program: `SET PINS, 1` / `SET PINS, 0` / `JMP 0` (with delay)
   - Configure clock divider for known period
   - Run N system cycles, sample `bus.gpio_in` bit 25 at each cycle
   - Assert transitions occur at expected cycle counts

2. **PIO UART TX** — Transmit 0x55 ('U') at 115200 baud.
   - Standard PIO UART TX program: pull from FIFO, shift out 8 bits
     with start bit (low) and stop bit (high), LSB first
   - Clock divider = sys_clk / baud_rate (150 MHz / 115200 ≈ 1302)
   - Push 0x55 to TX FIFO
   - Run emulator, record GPIO transitions
   - Expected waveform: idle high → start(low) → 10101010 → stop(high)
   - Assert each bit boundary occurs at ±1 system clock of expected cycle

3. **PIO SPI** — Clock out a byte with CLK + MOSI.
   - Two side-set pins: CLK on side-set, MOSI on OUT
   - Program: pull, out 1 bit + side-set CLK high, nop + side-set CLK low, loop
   - Verify CLK toggles and MOSI transitions align with CLK edges

**Test oracle:** For each test, compute the expected GPIO transition
times from the PIO program, clock divider setting, and instruction
timing. This is our ground truth — the emulator must match cycle-for-
cycle.

**Exit criterion:** All three waveform tests pass. Milestone achieved.

## 8. Risks

**Side-set / delay encoding bugs.** The 5-bit field split between
side-set and delay is the #1 source of PIO emulator bugs. The split
depends on PINCTRL.SIDESET_COUNT and EXECCTRL.SIDE_EN, both of which can
change at runtime. Mitigation: exhaustive unit tests for all
sideset_count values (0-5) with and without SIDE_EN.

**Autopull timing.** Autopull fires *before* OUT reads the OSR, not
after. Getting this wrong produces subtly incorrect shift output.
Mitigation: specific test that verifies OUT reads freshly-pulled data
when OSR is exhausted.

**Clock divider accuracy at large divisors.** With int=65535 and
frac=255, the SM ticks extremely rarely. The fractional accumulator must
not overflow or lose precision. Mitigation: test at extreme divider
values.
