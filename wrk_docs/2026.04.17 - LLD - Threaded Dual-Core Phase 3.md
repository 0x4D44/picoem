# Threaded Dual-Core Phase 3 — Low-Level Design

Version: 1.0.0
Date: 2026-04-17
Parent HLD: `2026.04.16 - HLD - Threaded Dual-Core Emulation V5.md`
Builds on: Phase 1 (SharedMemory, AtomicGpio, ExclusiveMonitors) + Phase 2
(SpscQueue, SpinBarrier, ThreadedSio, ThreadedPio).

## Scope

Compose the Phase 1/2 building blocks into a 4-thread runtime:

1. `CoreBus` trait — the per-core bus API surface CortexM33 calls through.
   Existing `Bus` and new `WorkerBus` both implement it.
2. `SharedState` — the `Arc`-wrapped bundle of all cross-thread state.
3. `WorkerBus` — per-CPU-thread bus view. Dispatches MMIO to the right
   component in `SharedState`.
4. `PioBus` — PIO thread's bus view. Accesses `AtomicGpio` + FIFOs.
5. `Peripherals` + `CoordinatorBus` — coordinator-owned state plus
   lock-order discipline for CPU-thread peripheral MMIO.
6. `ThreadedEmulator::from_emulator` — one-way decomposition of the
   existing `Emulator` into the threaded runtime.
7. Four worker loops (core 0, core 1, PIO, coordinator) spin-synchronised
   by two `SpinBarrier` crossings per quantum.
8. Windows thread pinning.
9. `ThreadedEmulator::run_quanta(n)` — the minimal, synchronous driver
   usable from tests. Duration-based `run` with Pacer/StopSignal is
   explicitly Phase 4 (see §Non-goals).

The HLD's coordinator phase lists 10 steps; Phase 3 covers steps 1–6.
Steps 7–10 (WFI wake, dual-WFI deadlock, pacer spin, stop-signal check)
land in Phases 4 and 5.

### Platform gate

`ThreadedEmulator`, `WorkerBus`, `PioBus`, `CoordinatorBus`, and the
worker-loop module are all gated with
`#[cfg(all(target_arch = "x86_64", target_os = "windows"))]`.

The `CoreBus` trait itself is NOT gated — it has to be visible to
`CortexM33`, which compiles on all targets. The trait has one
platform-independent impl (`Bus`) and one gated impl (`WorkerBus`).

## 1. `CoreBus` trait

`CortexM33::step` currently takes `&mut Bus`. To support both the
single-threaded and threaded paths without duplicating the execute
engine, the core becomes generic over a trait that captures exactly the
surface the core uses on the bus.

### Surface (audited from `core/` source)

Grep over `crates/mdrp2350/src/core/` (Phase 0 implementations) turned
up six families of direct bus access:

| Family | Methods used |
|---|---|
| Data access | `read8/16/32`, `write8/16/32` (all `(addr, core_id)`) |
| PC stash | `set_active_pc(pc, core)` |
| Faults | `bus_fault()`, `bus_fault_addr()`, `clear_bus_fault()` |
| IRQ assert | `assert_irq_core`, `assert_irq_shared`, `clear_irq_core`, `clear_irq_shared` |
| Events | `signal_sev()` |
| Direct fields | `irq_pending[core]`, `irq_pending_dirty[core]`, `event_flag[core]` |

The direct fields must be promoted to methods so both impls look
identical at the call site.

### Trait

```rust
pub trait CoreBus {
    // Data access
    fn read8(&mut self, addr: u32, core: u8) -> u8;
    fn read16(&mut self, addr: u32, core: u8) -> u16;
    fn read32(&mut self, addr: u32, core: u8) -> u32;
    fn write8(&mut self, addr: u32, val: u8, core: u8);
    fn write16(&mut self, addr: u32, val: u16, core: u8);
    fn write32(&mut self, addr: u32, val: u32, core: u8);

    // PC stash (for MMIO trace + active_pc array)
    fn set_active_pc(&mut self, pc: u32, core: u8);

    // Bus faults
    fn bus_fault(&self) -> bool;
    fn bus_fault_addr(&self) -> u32;
    fn clear_bus_fault(&mut self);

    // IRQ assertion (peripherals assert into these)
    fn assert_irq_core(&mut self, core: usize, irq: u32);
    fn assert_irq_shared(&mut self, irq: u32);
    fn clear_irq_core(&mut self, core: usize, irq: u32);
    fn clear_irq_shared(&mut self, irq: u32);

    // Events (WFE/SEV protocol)
    fn signal_sev(&mut self);
    fn event_flag_load(&self, core: usize) -> bool;
    fn event_flag_store(&self, core: usize, val: bool);

    // Per-core IRQ-pending latch
    fn irq_pending(&self, core: usize) -> u64;
    fn set_irq_pending(&mut self, core: usize, val: u64);
    fn take_irq_pending_dirty(&mut self, core: usize) -> bool;
}
```

All trait methods are thin: the existing `Bus` already exposes every
operation needed (public or `pub(crate)`). The `WorkerBus` impl
delegates to `SharedState` components.

### Generic `CortexM33` methods

`core/mod.rs`, `core/decode.rs`, `core/execute.rs`,
`core/execute_thumb32.rs`, `core/execute_fpu.rs`, `core/exceptions.rs`,
and `core/coprocessor.rs` all switch from `&mut Bus` to `B: CoreBus`:

```rust
// Before
pub fn step(&mut self, bus: &mut Bus) { ... }

// After
pub fn step<B: CoreBus>(&mut self, bus: &mut B) { ... }
```

Monomorphisation is free at release — every call site has a
statically-known `B`. No virtual dispatch. The internal
`core.ppb.bus_read32` PPB-intercept wrappers introduced in Phase 0b.1
already take `&mut Bus`; they switch to `&mut B: CoreBus` too.

The `bus.irq_pending[core]` / `bus.event_flag[core]` / etc. field
accesses rewrite to method calls: `bus.irq_pending(core)`,
`bus.event_flag_load(core)`, etc. Count: roughly 20 sites (see grep
output used to derive the trait surface).

### `impl CoreBus for Bus`

One-line delegates per method. `Bus::event_flag` is already `[AtomicBool; 2]`
so `event_flag_load/store` wrap `load(Acquire)` / `store(val, Release)`.
`Bus::irq_pending` and `irq_pending_dirty` become accessors around the
existing fields.

## 2. `SharedState`

The `Arc`-shared bundle carried by every worker thread's bus view.

```rust
pub struct SharedState {
    pub memory: Arc<SharedMemory>,
    pub gpio: Arc<AtomicGpio>,
    pub sio: Arc<ThreadedSio>,
    pub pio: Arc<ThreadedPio>,
    pub monitors: Arc<ExclusiveMonitors>,
    pub peripherals: Arc<Peripherals>,
    pub core_flags: Arc<CoreFlags>,
    pub nvic: Arc<SharedNvic>,
}

#[derive(Default)]
pub struct CoreFlags {
    pub halted: [AtomicBool; 2],
    pub wfe_waiting: [AtomicBool; 2],
    pub event_flag: [AtomicBool; 2],
    // Peripheral-asserted IRQ pending latch (one u64 per core).
    // AtomicU64 so coordinator (asserter) and worker (reader/merger)
    // never race.
    pub irq_pending: [AtomicU64; 2],
    // Set by any writer to irq_pending[core]; cleared by the owning
    // worker after it merges into ppb.nvic_ispr.
    pub irq_pending_dirty: [AtomicBool; 2],
    // Sticky bus fault per core (single-core-attributed today).
    pub bus_fault: [AtomicBool; 2],
    pub bus_fault_addr: [AtomicU32; 2],
}

pub struct SharedNvic {
    // Placeholder for future cross-core NVIC-ISPR writes (ICSR.PENDSVSET,
    // inter-core exceptions). For Phase 3, NVIC state remains on ppb;
    // the coordinator writes irq_pending[core] and sets the dirty flag,
    // and each worker merges its slot at the top of step().
    _reserved: (),
}
```

`CoreFlags` moves `halted`, `wfe_waiting`, `event_flag`, and the IRQ
latches off `Bus`/`CortexM33` into a single shared struct. `halted`
and `wfe_waiting` are logically per-core but must be cross-readable by
the coordinator (WFI wake + dual-WFI deadlock detection land in
Phase 5; the atomics just need to exist here).

**Design note: why `irq_pending` moves to a shared atomic.** In
single-threaded mode today, `Bus::assert_irq_*` writes
`bus.irq_pending[core]` and sets the dirty flag. The core picks it up
on its next `step()`. In threaded mode, the coordinator is the sole
asserter (peripheral ticks happen in the coordinator phase), but both
CPU workers need to read and merge their own slot. Moving
`irq_pending[core]` to `AtomicU64` serialises this without a mutex.

`SharedNvic` is vestigial in Phase 3 — it's here so Phase 4/5 can
extend without another churn pass when `ICSR.PENDSVSET` writes from
one core need to pend on the peer.

## 3. `WorkerBus`

Per-CPU-thread view. Owned by one worker thread; never shared.

```rust
pub struct WorkerBus {
    core_id: u8,
    shared: SharedState,
    // Per-core MMIO trace PC snapshot. Local so two cores never
    // race on each other's active_pc slot.
    active_pc: u32,
    // Burst-mode flag (STM/LDM/PUSH/POP suppresses per-word SRAM bank
    // wait states). Local — burst is per-instruction.
    burst_mode: bool,
    // Cycle accounting for the current access. Matches Bus's
    // extra_wait_states field; stays local.
    extra_wait_states: u32,
}
```

PPB is NOT on `WorkerBus` — it lives on `CortexM33` after Phase 0b.1
Commit B. The PPB-intercept wrappers (`CortexM33::bus_read32/write32/
16/8`) route PPB addresses to `self.ppb` before calling the trait's
`read/write` methods.

### Address dispatch in `WorkerBus::read32/write32/...`

Mirror the single-threaded `Bus::read/write` decode path, but route each
address class to its shared-state component:

| Region | `addr >> 28` | Dispatch |
|---|---|---|
| ROM | `0x0` | `shared.memory.read8/16/32` |
| XIP flash | `0x1` | `shared.memory.read8/16/32` |
| SRAM | `0x2` | `shared.memory.read/write8/16/32` |
| APB peripherals | `0x4` | Sub-decode — SIO/PIO/clocks/PLL/timers/UART/SPI/I2C/ADC/PWM/IO_BANK0/PADS_BANK0/RESETS/QMI/XOSC/ROSC |
| AHB peripherals (DMA, etc.) | `0x5` | `shared.peripherals.apb` lock |
| SIO (single-cycle IO) | `0xD` | `shared.sio` atomic ops + GPIO CP0 → `shared.gpio` |
| PPB | `0xE` | Never reaches here — intercepted on `CortexM33` |

APB sub-decode (offset `0x4` region):

| Offset | Component | Owner | Access pattern |
|---|---|---|---|
| `0x0000_0000` CLOCKS | `Peripherals.clocks` | Coordinator | Mutex |
| `0x0002_8000` PLL_SYS | `Peripherals.clocks` | Coordinator | Mutex |
| `0x0002_C000` PLL_USB | `Peripherals.clocks` | Coordinator | Mutex |
| `0x0004_0000` RESETS | `Peripherals.resets` | Coordinator | Mutex |
| `0x0005_0000` PWM | `Peripherals.apb` | Coordinator | Mutex |
| `0x0005_0000` TIMER0 / `0x0005_1000` TIMER1 / `0x0005_2000` WATCHDOG | `Peripherals.timers` | Coordinator | Mutex |
| `0x0005_8000` TICKS | `Peripherals.timers` | Coordinator | Mutex |
| `0x0006_0000` PIO MMIO | `shared.pio` + `PioCommand` queue | PIO thread | Atomic / lock-free queue |
| `0x0007_0000` UART0 / `0x0008_0000` SPI0 / `0x0009_0000` I2C0 / `0x000A_0000` ADC | `Peripherals.apb` | Coordinator | Mutex |
| `0x000D_0000` QMI | `Peripherals.qmi` | Coordinator | Mutex |

The `0xD` region is single-cycle IO and must NOT take a mutex — all
SIO access is via `ThreadedSio`'s lock-free atomics. GPIO CP0 reads
(`GPIO_IN`, `GPIO_OUT`) route to `shared.gpio` directly.

### Worker-owned vs shared access

`WorkerBus::write32` also invalidates the peer's exclusive monitor
(Phase 1 `ExclusiveMonitors::snoop`) after a data-side write, replacing
the Phase 0b.2 `did_write_this_quantum` flag. `snoop` is a relaxed
atomic-compare — very cheap.

```rust
fn write32(&mut self, addr: u32, val: u32, core: u8) {
    // ... dispatch as above ...
    self.shared.monitors.snoop(addr);
}
```

The current Phase 0b.2 flag-based snoop is left intact for the
single-threaded `Bus` path (cheaper there) — no regression.

### Bus faults

`bus_fault` and `bus_fault_addr` on `CoreFlags` are per-core. Each
worker reads and clears its own slot — the coordinator never touches
them.

## 4. `PioBus`

The PIO thread's bus view. Single-owner (the PIO thread); no other
thread constructs one.

```rust
pub struct PioBus {
    shared: SharedState,
    // PioBlocks live here — moved from `Bus.pio` at from_emulator time.
    blocks: [PioBlock; 3],
}
```

### PIO thread responsibilities

1. Drain `shared.pio.drain_commands()` at the top of each quantum.
   Dispatch each `PioCommand` into the appropriate `PioBlock` field
   (`WriteInstrMem` → `block.instr_mem[addr] = value`; `SetClkDiv` →
   `block.sm[sm].clkdiv_*`).
2. For each active SM (mask from `shared.pio.read_sm_enabled(block)`):
   - Read current pin state via `shared.gpio.read_out(0)` /
     `shared.gpio.read_oe(0)`.
   - Execute one PIO instruction against `PioBlock` local state.
   - Push TX-pop / RX-push into `shared.pio` FIFOs.
   - Write pin updates via `shared.gpio.write_out` (masked to the SM's
     pin ownership).
3. Update `shared.pio.write_irq_flags(block, …)` and
   `shared.pio.write_dreq(block, …)` so the coordinator can propagate
   IRQs to NVIC and DREQs to DMA.

The `PioBlock` struct itself (from `mdpicoem-common`) is **not** wrapped
in atomics — only the PIO thread touches it. CPU-thread MMIO hits
`ThreadedPio`'s FIFOs + command queue, never the `PioBlock` directly.

### FIFO join (deferred infra)

Phase 2 notes that FIFO join (depth 4 ↔ 8) is a Phase 3 concern. For
Phase 3, `PioCommand::JoinFifos { block, sm, direction }` is added to
the enum. When the PIO thread drains a `JoinFifos` command, it marks
a per-SM join flag on its local `PioBlock`; the SM's execute path
reads the joined queues instead of the per-direction one. The actual
queue replacement (SpscQueue with capacity 8) happens inside
`ThreadedPio` guarded by the same mutex as the command queue — CPU
writes that would push/pop during the reconfigure block wait on that
mutex.

This is infrequent (setup-time reconfiguration), so a short mutex
hold is fine.

## 5. `Peripherals` + `CoordinatorBus`

### `Peripherals`

```rust
pub struct Peripherals {
    pub clocks: Mutex<ClocksState>,      // CLOCKS + PLL_SYS + PLL_USB + ROSC + XOSC
    pub qmi:    Mutex<QmiState>,
    pub resets: Mutex<ResetsState>,
    pub apb:    Mutex<ApbState>,         // UART/SPI/I2C/ADC/PWM/IO_BANK0/PADS_BANK0
    pub timers: Mutex<TimersState>,      // TICKS + TIMER0 + TIMER1 + WATCHDOG
    pub dma:    Mutex<DmaState>,         // 16 channels
}
```

Each `*State` struct owns the register image + derived fields currently
in `Bus` (e.g. `ClocksState` owns `clk_sys_ctrl`, `clk_sys_div`,
`clock_tree`, `pll_sys_regs`, `pll_sys_lock_at_cycle`, etc.).

### Lock order (HLD V5)

`clocks < qmi < resets < apb < timers < dma`

Expanded from the HLD's four-level order to six to cover timers and
DMA. Order is derived from real dependency: timers read the clock
tree; DMA reads from apb/timer sources.

### Lock-order enforcement

Thread-local lock stack with a `PeripheralGuard<'a, T>` RAII wrapper,
identical in spirit to HLD V5 §"Peripheral access from CPU threads":

```rust
thread_local! {
    static LOCK_STACK: RefCell<[u8; 6]> = RefCell::new([0; 6]);
    static LOCK_DEPTH: Cell<u8> = Cell::new(0);
}

pub struct PeripheralGuard<'a, T> {
    inner: MutexGuard<'a, T>,
    level: u8,
}

impl<T> PeripheralGuard<'_, T> {
    fn acquire(mutex: &Mutex<T>, level: u8) -> Self {
        LOCK_DEPTH.with(|d| {
            let depth = d.get();
            if depth > 0 {
                let top = LOCK_STACK.with(|s| s.borrow()[(depth - 1) as usize]);
                assert!(level > top,
                    "lock order violation: acquiring level {} while holding {}",
                    level, top);
            }
            LOCK_STACK.with(|s| s.borrow_mut()[depth as usize] = level);
            d.set(depth + 1);
        });
        Self { inner: mutex.lock().unwrap(), level }
    }
}

impl<T> Drop for PeripheralGuard<'_, T> {
    fn drop(&mut self) {
        LOCK_DEPTH.with(|d| d.set(d.get() - 1));
    }
}
```

Level constants:
```rust
pub const LVL_CLOCKS: u8 = 1;
pub const LVL_QMI:    u8 = 2;
pub const LVL_RESETS: u8 = 3;
pub const LVL_APB:    u8 = 4;
pub const LVL_TIMERS: u8 = 5;
pub const LVL_DMA:    u8 = 6;
```

Violations `panic!` in debug builds; compile out in release. That's
the standard cost for this idiom.

### `CoordinatorBus`

```rust
pub struct CoordinatorBus {
    shared: SharedState,
    // Coordinator-local cycle accounting
    master_cycle: u64,
    step_quantum: u32,
}
```

The coordinator doesn't own `Peripherals` exclusively — it takes the
same `PeripheralGuard` path as CPU threads. The only difference is
timing: the coordinator phase runs after the execution barrier, so CPU
threads are parked at barrier 2 and contention is zero during the
coordinator's traversal. Takes locks in full order per quantum.

## 6. `ThreadedEmulator::from_emulator`

One-way conversion — consumes `Emulator`, produces `ThreadedEmulator`.
No reverse path.

```rust
pub struct ThreadedEmulator {
    shared: SharedState,
    barrier: Arc<SpinBarrier>,
    workers: Vec<JoinHandle<()>>,
    // Handles for tests that synchronously drive N quanta
    step_cmd: Arc<StepCommand>,
    // Read-only core state for external inspection (TUI/debug)
    // Mirrored by core-0/core-1 worker at barrier 2.
    core_snapshot: Arc<[Mutex<CortexM33Snapshot>; 2]>,
}

struct StepCommand {
    quanta_remaining: AtomicU64,
    quit: AtomicBool,
}
```

### Decomposition body

```rust
pub fn from_emulator(emu: Emulator) -> Self {
    let Emulator { cores, bus, clock, step_quantum } = emu;

    // Move core state onto workers
    let [core0, core1] = cores;

    // Decompose Bus
    let Bus {
        memory, sio, pio, event_flag,
        irq_pending, irq_pending_dirty,
        resets_state, ticks, timer0, timer1,
        uart0, spi0, i2c0, adc, pwm, io_bank0, pads_bank0,
        dma, clk_ref_ctrl, clk_sys_ctrl, clk_sys_div,
        clock_tree, pll_sys_regs, pll_usb_regs,
        pll_sys_lock_at_cycle, pll_usb_lock_at_cycle,
        rosc_regs, xosc_regs, qmi_regs, xip_cache_offset,
        gpio_in, gpio_external_in, gpio_external_mask,
        boot_ram, xip_sram,
        // drop: peripheral_regs, last_access_cycles, extra_wait_states,
        //       bus_fault, bus_fault_addr, flash_loaded, burst_mode,
        //       decode_cache, trace_*, active_pc, master_cycle,
        //       rcp_salt, rcp_salt_valid, rcp_count,
        //       gpio_hi_noise_state
        ..
    } = bus;

    // Build SharedMemory from Memory's backing
    let shared_mem = Arc::new(SharedMemory::from_memory(memory,
                                                        boot_ram, xip_sram));
    // Build AtomicGpio from SIO's gpio_out/oe + gpio_in
    let shared_gpio = Arc::new(AtomicGpio::seed(
        sio.gpio_out, sio.gpio_oe, gpio_in,
        gpio_external_in, gpio_external_mask));
    // Build ThreadedSio from SIO FIFOs + spinlocks + doorbells
    let shared_sio = Arc::new(ThreadedSio::seed(&sio));
    // Build ThreadedPio communication surface; PIO blocks themselves
    // hand off to the PIO thread
    let shared_pio = Arc::new(ThreadedPio::new());

    // Build Peripherals — move register images into mutex-guarded state
    let peripherals = Arc::new(Peripherals::from_bus_components(
        clk_ref_ctrl, clk_sys_ctrl, clk_sys_div, clock_tree,
        pll_sys_regs, pll_usb_regs,
        pll_sys_lock_at_cycle, pll_usb_lock_at_cycle,
        rosc_regs, xosc_regs,
        qmi_regs, xip_cache_offset,
        resets_state,
        uart0, spi0, i2c0, adc, pwm, io_bank0, pads_bank0,
        ticks, timer0, timer1,
        dma,
    ));

    // CoreFlags: seed from existing event_flag + irq_pending
    let core_flags = Arc::new(CoreFlags::seed(
        event_flag, irq_pending, irq_pending_dirty));

    let shared = SharedState {
        memory: shared_mem,
        gpio: shared_gpio,
        sio: shared_sio,
        pio: shared_pio,
        monitors: Arc::new(ExclusiveMonitors::new()),
        peripherals,
        core_flags,
        nvic: Arc::new(SharedNvic::default()),
    };

    let barrier = Arc::new(SpinBarrier::new(4));
    let step_cmd = Arc::new(StepCommand::new());

    // Spawn 4 workers, pin each to a distinct physical core
    let workers = spawn_workers(
        shared.clone(), barrier.clone(), step_cmd.clone(),
        core0, core1, pio, step_quantum, clock.cycles);

    Self { shared, barrier, workers, step_cmd, core_snapshot: ... }
}
```

The existing `Emulator::load_image / load_bootrom / load_flash` are
not mirrored on `ThreadedEmulator` in Phase 3 — callers must load into
the `Emulator` and *then* convert.

### `from_emulator` budget

- ~150 lines in `threaded/emulator.rs` (decomposition + worker spawn).
- ~80 lines of helpers (`SharedMemory::from_memory`, `ThreadedSio::seed`,
  `CoreFlags::seed`, `Peripherals::from_bus_components`).

## 7. Worker loops

Four independent loops, one per thread. Each loop is a simple
"for-quantum-in-quanta" wrapper around per-thread work + two barrier
crossings.

### Worker 0 (CPU core 0)

```rust
fn core_worker(
    core_id: u8,
    mut core: CortexM33,
    shared: SharedState,
    barrier: Arc<SpinBarrier>,
    cmd: Arc<StepCommand>,
    mut step_quantum: u32,
    mut target: u64,
) {
    pin_to_physical_core(0);
    let mut bus = WorkerBus::new(core_id, shared.clone());
    loop {
        // Wait for the controller (ThreadedEmulator) to authorise work
        if cmd.quit.load(Acquire) { break; }
        if cmd.quanta_remaining.load(Acquire) == 0 {
            std::hint::spin_loop();
            continue;
        }

        // Execution phase: run until cycles catch up to target
        // Quantum-boundary IRQ merge (shared.core_flags → ppb.nvic_ispr)
        if shared.core_flags.irq_pending_dirty[core_id as usize]
               .swap(false, AcqRel) {
            let pending = shared.core_flags.irq_pending[core_id as usize]
                                .load(Acquire);
            core.ppb.merge_irq_pending(pending);
        }

        while !core.is_halted()
           && !core.is_wfe_waiting()
           && core.cycles < target {
            core.ppb.update_latest_cycles(core.cycles);
            core.step(&mut bus);
        }
        core.ppb.update_latest_cycles(core.cycles);

        // Publish the snapshot used by ThreadedEmulator::core(id)
        publish_snapshot(&core, core_id);

        if barrier.wait() == BarrierResult::Poisoned { break; }
        // Coordinator runs here (workers 0/1/2 spin at barrier 2)
        if barrier.wait() == BarrierResult::Poisoned { break; }

        target = target.wrapping_add(step_quantum as u64);
    }
}
```

Worker 1 is identical with `core_id = 1` and pinned to physical core 2
(pinning pattern below).

### Worker 2 (PIO)

```rust
fn pio_worker(
    shared: SharedState,
    mut blocks: [PioBlock; 3],
    barrier: Arc<SpinBarrier>,
    cmd: Arc<StepCommand>,
    step_quantum: u32,
) {
    pin_to_physical_core(3);
    let mut bus = PioBus::new(shared.clone(), blocks);
    loop {
        if cmd.quit.load(Acquire) { break; }
        if cmd.quanta_remaining.load(Acquire) == 0 {
            std::hint::spin_loop();
            continue;
        }

        // Drain command queue at start of quantum (CPU → PIO setup writes)
        for cmd in shared.pio.drain_commands() {
            bus.dispatch_command(cmd);
        }

        // Step all SMs for `step_quantum` cycles
        for _ in 0..step_quantum {
            bus.step_all_once();
        }

        if barrier.wait() == BarrierResult::Poisoned { break; }
        if barrier.wait() == BarrierResult::Poisoned { break; }
    }
}
```

`PioBus::step_all_once` walks active SMs per `shared.pio.read_sm_enabled`,
executes one PIO cycle each, syncs GPIO via `shared.gpio`, and pushes
TX-pop/RX-push results through the Phase 2 FIFOs.

### Worker 3 (Coordinator)

```rust
fn coordinator_worker(
    shared: SharedState,
    barrier: Arc<SpinBarrier>,
    cmd: Arc<StepCommand>,
    step_quantum: u32,
    mut master_cycle: u64,
) {
    pin_to_physical_core(4);
    let mut bus = CoordinatorBus { shared: shared.clone(),
                                   master_cycle,
                                   step_quantum };
    loop {
        if cmd.quit.load(Acquire) { break; }
        if cmd.quanta_remaining.load(Acquire) == 0 {
            std::hint::spin_loop();
            continue;
        }

        // Execution phase: coordinator is idle at barrier 1
        if barrier.wait() == BarrierResult::Poisoned { break; }

        // Coordinator phase (steps 1–6 of HLD)
        bus.master_cycle = master_cycle;

        // 1. Timer ticks — SysTick is per-core (handled by core workers
        //    via `ppb.systick_advance` before their barrier 1 arrival).
        //    TIMER0 / TIMER1 / TICKS / watchdog:
        {
            let mut t = PeripheralGuard::acquire(
                &shared.peripherals.timers, LVL_TIMERS);
            t.ticks.tick_n(step_quantum);
            t.timer0.tick_n(step_quantum);
            t.timer1.tick_n(step_quantum);
        }

        // 2. SIO: MTIME advance (divider/interp tick is nop — computed
        //    on-demand in WorkerBus).
        shared.sio.mtime_advance(step_quantum as u64);
        if shared.sio.mtime_check_match(0) { assert_shared_irq(&shared, MTIME_IRQ); }
        if shared.sio.mtime_check_match(1) { assert_shared_irq(&shared, MTIME_IRQ); }

        // 3. Doorbell → peer NVIC atomic write
        for core in 0..2 {
            let bits = shared.sio.doorbell_read(core);
            if bits != 0 { assert_core_irq(&shared, core, DOORBELL_IRQ); }
        }

        // 4. DMA step (all active channels)
        {
            let mut dma = PeripheralGuard::acquire(
                &shared.peripherals.dma, LVL_DMA);
            dma.tick(&shared);
        }

        // 5. Peripheral step (UART/SPI/I2C/ADC/PWM)
        {
            let mut apb = PeripheralGuard::acquire(
                &shared.peripherals.apb, LVL_APB);
            apb.tick_all(step_quantum, &shared);
        }

        // 6. PIO IRQ flags → NVIC
        for block in 0..3 {
            let flags = shared.pio.read_irq_flags(block);
            if flags != 0 { deliver_pio_irqs(&shared, block, flags); }
        }

        master_cycle = master_cycle.wrapping_add(step_quantum as u64);

        // End of coordinator phase — release workers
        if barrier.wait() == BarrierResult::Poisoned { break; }

        let remaining = cmd.quanta_remaining.fetch_sub(1, AcqRel);
        if remaining == 0 { /* underflow — treat as quit */ break; }
    }
}
```

`assert_core_irq` / `assert_shared_irq` helpers take a CoreFlags
reference:
```rust
fn assert_core_irq(shared: &SharedState, core: usize, irq: u32) {
    let mask = 1u64 << irq;
    shared.core_flags.irq_pending[core].fetch_or(mask, AcqRel);
    shared.core_flags.irq_pending_dirty[core].store(true, Release);
}
```

## 8. `ThreadedEmulator::run_quanta`

The Phase 3 test driver. Runs exactly N quanta synchronously (the
calling thread blocks until all workers have completed N quantum
rounds).

```rust
impl ThreadedEmulator {
    pub fn run_quanta(&mut self, n: u64) {
        self.step_cmd.quanta_remaining.store(n, Release);
        // Busy-wait — workers pick up, execute, decrement
        while self.step_cmd.quanta_remaining.load(Acquire) != 0 {
            std::hint::spin_loop();
        }
    }

    pub fn core(&self, id: usize) -> CortexM33Snapshot {
        // Read the snapshot published at barrier 2
        self.core_snapshot[id].lock().unwrap().clone()
    }

    pub fn set_quantum(&mut self, _q: u32) {
        // Phase 3 stores the quantum once at construction. Runtime
        // resize lands in Phase 5 (quantum tuning).
        unimplemented!("Phase 5 — quantum tuning")
    }
}
```

No Pacer, no duration-based `run`, no stop signal, no panic handling.
These land in Phase 4. Phase 3's test harness calls `run_quanta` and
then inspects `core(0) / core(1)` + `shared.memory` / `shared.gpio`.

Drop semantics: `Drop for ThreadedEmulator` sets `quit=true`, pokes the
barrier with `poison()`, and joins all four threads. Tests relying on
`run_quanta` must let the `ThreadedEmulator` drop at end of scope.

## 9. Thread pinning (Windows)

```rust
#[cfg(all(target_arch = "x86_64", target_os = "windows"))]
fn pin_to_physical_core(logical_id: usize) {
    use winapi::um::processthreadsapi::{GetCurrentThread, SetThreadAffinityMask};
    let handle = unsafe { GetCurrentThread() };
    let mask = 1usize << logical_id;
    let prev = unsafe { SetThreadAffinityMask(handle, mask) };
    assert!(prev != 0, "SetThreadAffinityMask failed");
}
```

Host-core assumption (HLD): ≥ 5 physical cores available. Pinning
logical IDs 0/2/3/4 leaves logical ID 1 free for the OS and any
foreground thread. If the host advertises < 4 physical cores,
`ThreadedEmulator::from_emulator` panics at construction with a clear
error:

```rust
let n = std::thread::available_parallelism()
    .map(|n| n.get()).unwrap_or(1);
if n < 4 {
    panic!("ThreadedEmulator requires >= 4 host cores (found {})", n);
}
```

No silent fallback, no feature flag, no env var.

Add `winapi` crate (feature `processthreadsapi`) as a Windows-only
workspace dep. (Cargo.toml gate: `[target.'cfg(windows)'.dependencies]`.)

## 10. Memory barriers (DMB/DSB/ISB)

Currently `DMB/DSB/ISB` in `execute_thumb32.rs` are no-ops. For
threaded execution they must emit a CPU fence so writes by core 0
become visible to core 1 within one quantum.

```rust
match instr {
    DMB | DSB => std::sync::atomic::fence(Ordering::SeqCst),
    ISB => {
        std::sync::atomic::fence(Ordering::SeqCst);
        // Future: flush decode cache if added
    }
}
```

x86 TSO means `mfence` is emitted for SeqCst; cheap. In single-threaded
mode, the fence is still emitted — correctness only, no regression
since there's nothing to flush.

One change in `core/execute_thumb32.rs`, gated behind no cfg.

## 14. Risks

1. **Trait migration breaks something subtle.** `CortexM33` has a lot
   of `bus.field` access. Making every one of them method-based is
   mechanical but a grep pass can miss corner cases. Mitigation: full
   `cargo test -p mdrp2350` before touching the threaded module; the
   1969-test suite catches regressions.
2. **`Bus` decomposition misses a field.** The destructuring in
   `from_emulator` is complete per the field list, but fields added
   after this LLD was written could be dropped silently. Mitigation:
   destructure exhaustively (no `..`) so the compiler errors on
   additions.
3. **Peripheral mutex contention.** CPU MMIO to APB peripherals now
   contends with the coordinator. Expected to be rare, but if
   measurable we can split the APB mutex per-peripheral. Measured in
   Phase 5 — not preemptively split.
4. **Lock-order assertions fire in ordinary code.** Any call site that
   holds two locks against the intended order panics in debug.
   Mitigation: audit `Bus::read32/write32` dispatch for code paths
   that currently touch multiple peripherals in one call (e.g.
   CLOCKS writes that cascade through PLL registers). Resolve by
   either taking the outer lock only or promoting nested access to
   the outer lock's critical section.
5. **PIO thread starvation under heavy setup.** If firmware floods
   `PioCommand` at init, the PIO thread drains a big queue at the
   start of a quantum and might exceed the execution phase of the
   other workers. Those workers finish early and spin at barrier 1 —
   correct but wasteful. Phase 5 measures and tunes Q.
6. **Thread-pinning on a machine with SMT enabled.** Pinning to logical
   core N doesn't guarantee a distinct physical core. Real dual-core
   isolation needs awareness of SMT topology. Phase 3 documents this
   and accepts it; Phase 5 tuning revisits if benchmarks show
   sibling contention.
