# Bus Narrow-Write Drop Audit — Design

Version: 1.0
Date: 2026-05-07
Crate: `rp2350-emu`

## 1. Context

`rp2350-emu` 0.2.4 (this morning) closed a silent narrow-write drop on
PIO TX FIFOs: `Bus::write8` / `Bus::write16` had hard-coded the PIO
arms as `=> {}` no-ops with the comment "PIO: 32-bit access only", and
DMA byte-mode transfers (CTRL.DATA_SIZE=0) to `PIO2.TXF1` vanished
even though `TRANS_COUNT` decremented and `INTR` latched. Fix was
mechanical: replace the no-op arm with the same subword-alias
read-modify-write dispatch already used for UART / SPI / I2C / PWM.

While auditing, two more apertures still drop narrow writes
(`bus/mod.rs:1949-1951` + `:2677-2679` for RESETS,
`:2147` + `:2866` for USBCTRL_REGS). This HLD decides what to do
with each, and applies the same one-line fix to RESETS.

Reference: `2026.04.17 - HLD - Bus Narrow-Access Audit.md` proposed a
full unified-dispatch refactor of the four narrow paths. That refactor
hasn't landed and isn't proposed here — it is a much larger scope.
This HLD closes the two remaining drop arms in the existing
per-aperture style.

## 2. Audit

Every silent-drop arm in `Bus::write8` / `Bus::write16` today, after
the 0.2.4 PIO fix.

| Aperture | Base | write8 | write16 | Verdict | Reason |
|---|---|---|---|---|---|
| SYSINFO | `0x4000_0000` | drop | drop | **keep** | Read-only on silicon (CHIP_ID, PLATFORM, GITREF). Datasheet §5.2. |
| RESETS  | `0x4002_0000` | drop | drop | **fix**  | RESET / WDSEL / RESET_DONE accept narrow writes via AHB widening on silicon. Same family of bug as PIO 0.2.4. |
| PIO0/1/2 | `0x5020/30/40_0000` | (fixed in 0.2.4) | (fixed in 0.2.4) | n/a | — |
| USBCTRL_REGS | `0x5011_0000` | drop | drop | **defer** | DW_OTG controllers are typically word-only on silicon; needs datasheet §11.4 confirmation before either keeping or fixing. Not load-bearing for any current oracle. |

Anything not in this table is either already wired with the standard
subword-alias dispatch (UART, SPI, I2C, ADC, PWM, IO_BANK0,
PADS_BANK0, CLOCKS, PLLs, XOSC, ROSC, TIMER0/1, TICKS, SYSCFG, TBMAN,
GLITCH_DETECTOR, PSM, WATCHDOG, OTP, TRNG, SHA256, POWMAN), or
genuinely word-only with a different valid drop semantic (the SIO
catch-all does RMW via `read32`+splice, the unmapped catch-all sets
`bus_fault`).

## 3. Fix — RESETS narrow writes

`peripherals.rs:116` already exposes `resets_write(offset, val, alias)`
with the standard alias semantics (0=write, 1=XOR, 2=SET, 3=CLR). The
fix mirrors the PIO 0.2.4 patch verbatim, adapted for one peripheral
instead of three:

```rust
// In Bus::write8, replace:
0x4002_0000 => {
    // RESETS: only word-aligned writes meaningful, ignore byte
}
// with:
0x4002_0000 => {
    let word_addr = canonical & !3;
    let byte_idx = (canonical & 3) as usize;
    let reg_offset = word_addr & 0x0000_0FFF;
    let (word_val, pass_alias) = if alias == 0 {
        let old_word = self.resets_read(reg_offset);
        let mut bytes = old_word.to_le_bytes();
        bytes[byte_idx] = val;
        (u32::from_le_bytes(bytes), 0u32)
    } else {
        ((val as u32) << (byte_idx * 8), alias)
    };
    self.resets_write(reg_offset, word_val, pass_alias);
}
```

`Bus::write16` gets the symmetric halfword form (mirrors the PIO
halfword arm in 0.2.4). RESETS has only one writable register
(`RESET` at offset `0x000`, since `WDSEL` is `_ => {}` in
`resets_write` and `RESET_DONE` is read-only) so the dispatch
naturally targets the one register without needing per-offset
selection.

### Non-goals

- No new RESETS register coverage. WDSEL stays unmodelled.
- No alias-decoder change. The existing alias semantics are correct.
- No refactor to consolidate the per-aperture pattern (see §1
  reference to the prior unified-dispatch HLD).

## 4. Deferred — USBCTRL_REGS

The DW_OTG-style USB controller register set is largely 32-bit-only
on silicon. Until either (a) the RP2350 datasheet §11.4 is checked
to confirm narrow-write behaviour register-by-register, or (b) a
USB-driving harness comes online and a real failure points at one
of the drop arms, leave both arms as `=> {}` and update the comment
to reference this HLD:

```rust
// USBCTRL regs: silent drop pending datasheet §11.4 confirmation.
// See wrk_docs/2026.05.07 - HLD - Bus Narrow-Write Drop Audit V1.md §4.
USBCTRL_REGS_BASE => {}
```

If the oracle that lands first is `picogus_*` or any USB-PHY shim,
that's the trigger to revisit.

## 5. Kept — SYSINFO

`SYSINFO` (`0x4000_0000`) is read-only on silicon at every width.
Drop is correct. Existing comment `// SYSINFO: read-only, ignore byte
writes` is accurate and stays.

## 6. Test plan

One regression unit test, alongside the 0.2.4 PIO test in
`crates/rp2350-emu/src/tests.rs` (or a sibling file — pick whichever
is most natural for the existing layout):

```rust
#[test]
fn resets_narrow_writes_widen_to_32_bit() {
    let mut bus = Bus::new();
    // Start: RESETS.RESET reads as `resets_state` after reset
    // (default = all-ones, every peripheral held).
    let initial = bus.read32(0x4002_0000, 0);

    // Byte write to byte-lane 0 of RESETS.RESET clears bits 0..7.
    bus.write8(0x4002_0000, 0x00, 0);
    assert_eq!(bus.read32(0x4002_0000, 0), initial & 0xFFFF_FF00);

    // Halfword write to halfword-lane 1 of RESETS.RESET clears bits 16..31.
    bus.write16(0x4002_0002, 0x0000, 0);
    assert_eq!(bus.read32(0x4002_0000, 0), initial & 0x0000_FF00);

    // CLR-alias byte write at +0x3000 clears specific bits.
    bus.write32(0x4002_0000, 0xFFFF_FFFF, 0);     // re-arm
    bus.write8(0x4002_3000, 0x0F, 0);             // CLR alias, byte lane 0
    assert_eq!(bus.read32(0x4002_0000, 0), 0xFFFF_FFF0);
}
```

Confirm it fails on master before the fix (drop returns the unchanged
initial word for both narrow paths), passes after.

Full workspace test pass via `cargo test --workspace --release
--exclude epio-sys` (epio-sys excluded per CLAUDE.md — requires
`clang` and vendored submodules).

## 7. Versioning

`rp2350-emu` 0.2.4 → 0.2.5 (patch — bug fix, no API change).
CHANGELOG entry mirrors the 0.2.4 shape.

## 8. What this isn't

- Not the unified-dispatch refactor from 2026-04-17. That remains a
  larger separate workstream.
- Not a USBCTRL behavioural model. Deferred to whichever harness needs
  USB first.
- Not a SYSINFO change. Read-only is correct.
- Not an `rp2040-emu` change. Sibling crate has its own narrow-access
  layer; if the same drop pattern exists there, it gets its own
  one-paragraph follow-up after this lands.
