# Decoded-Op Cache

Version: 1.0.0
Date: 2026-04-14

## 1. Problem

`paced_bench_rp2350 --workload basic --unpaced` measures 83.5 MHz / 36.80
host-cycles per emu-cycle (budget <33 per master HLD §12). The basic
workload is a 2-instruction loop (ADDS R0,R0,#1 at 0x2000_0002, B .-2 at
0x2000_0004). Profile shows every single iteration re-runs:

1. `bus.reset_extra_wait_states()` (accounted-for by Agent B, not here).
2. `bus.read16(pc)` — a ~80-line function with a `match addr >> 28`,
   APB/AHB dispatch, peripheral register map, SRAM-bank wait-state bump,
   contention bookkeeping. For a PC that has been executed 10^8 times
   already, this is entirely redundant work.
3. A top-level `is_wide` test on `hw0`.
4. A second `bus.read16(pc+2)` for Thumb-32.
5. The Thumb-16 or Thumb-32 dispatch match (bits 15:11 for T16; bits
   15:11 / 4:10 / 15 for T32).

Steps 2–5 are a pure function of the bytes at PC. The bytes at PC in
executable memory change only when firmware is loaded, or — very rarely
— when running code writes to an address it later executes. Caching
the decoded form keyed by PC short-circuits all of 2–5 on a hit.

## 2. Cached entry

```rust
/// One decoded instruction. 12 bytes. `Copy`.
#[derive(Clone, Copy)]
pub(crate) struct DecodedOp {
    /// The PC this entry is valid for. Used as the tag in a
    /// direct-mapped table. `u32::MAX` = empty / invalid slot.
    pub tag: u32,
    /// First halfword (the one at PC). Passed to `execute_thumb16` on
    /// narrow hits and `execute_thumb32` as `hw0` on wide hits.
    pub hw0: u16,
    /// Second halfword (at PC+2). Zero for narrow instructions.
    pub hw1: u16,
    /// Extra wait states the bus charged when this entry's halfwords
    /// were last fetched. Currently this is 0 everywhere except bank
    /// 2 / bank 6 SRAM (`sram_bank_wait` returns 1). Stored so that
    /// cache hits preserve the exact same returned cycle count as the
    /// non-cached path. On a hit we do NOT call `bus.read16`, so we
    /// add this directly to `extra_wait_states` instead. See §8.
    pub fetch_wait: u8,
    /// Packed flags.
    ///   bit 0 — `is_wide`
    ///   bit 1 — `is_pure` (Agent B — see §2.2)
    ///   bit 2 — `is_thumb16_flag_only` (pre-computed; saves a match
    ///           on every narrow-in-IT-block execution)
    ///   bits 3..7 — reserved
    pub flags: u8,
}
```

### 2.1 Size / packing

12 bytes. Rationale:

| Field             | Bits | Reason                                                    |
|-------------------|------|-----------------------------------------------------------|
| `tag: u32`        | 32   | Full PC. Using `(pc >> 1)` would save 1 bit but force a shift on every hit. Wasteful. |
| `hw0: u16`        | 16   | Raw bytes — mandatory, feeds `execute_thumb*`. |
| `hw1: u16`        | 16   | Same; 0 for narrow. |
| `fetch_wait: u8`  | 8    | See §8 / cycle-accuracy. Max observed value = 2 (wide instruction across bank 2/6 + bank 2/6), so 8 bits is abundant. |
| `flags: u8`       | 8    | See below. |

A 16-byte variant (add a `base_cycles: u8` + 3B pad) would be Agent B's
extension — not in this HLD's scope. 12 bytes fits 5⅓ entries per
64-byte cache line; direct-mapped lookup touches exactly one line.

Entries are `Copy`; lookup returns a value, so no borrow issue with
executing out of `&mut Bus` while reading the cache via `&mut Bus`.

### 2.2 `is_pure` reservation (Agent B interface)

Reserved as bit 1 of `flags`. **Always `false` in the Agent A
populate path.** Agent B will define the classification (which
instructions touch the bus, STM/LDM burst, APB, etc.) and update the
populate path accordingly. Until then every cache-populated entry is
conservatively treated as impure, forcing the current
`bus.reset_extra_wait_states()` + `bus.extra_wait_states()` accounting
to still run. Agent A MUST NOT gate any behaviour on `is_pure` being
`true`.

### 2.3 `is_thumb16_flag_only` pre-computation

`is_thumb16_flag_only(hw0)` is a small nested match that runs on every
narrow instruction executed inside an IT block (to decide whether to
restore flags). Pre-computing it at decode time costs nothing on a miss
and saves the match on every subsequent hit. Narrow-only — for wide
instructions the bit is always 0.

## 3. Storage topology

### 3.1 Considered

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| Global direct-mapped array, say 8192 entries indexed by `(pc >> 1) & 0x1FFF` with full-PC tag | One lookup; single allocation; cache-line friendly | Tag compare mandatory; ROM + SRAM + XIP collide in 8 KB slots | **Picked.** |
| Per-region arrays (ROM dense, SRAM/XIP sparse direct-mapped) | ROM can be tagless (16 K halfwords indexed directly); tighter per-region tuning | Three arrays, three dispatches; region decode on every lookup; extra branch cost dwarfs the win for the basic workload which only touches SRAM | Rejected. |
| `HashMap<u32, DecodedOp>` | Minimal memory; no collision policy to think about | Hash + probe + pointer chase > bus.read16 for this tight a hot path. Hash-based code caches are for JITs over megabytes of code, not a 2-instruction loop | Rejected. |

### 3.2 Picked

One direct-mapped table, 16384 entries (2^14), indexed by
`(pc >> 1) & 0x3FFF`. 16384 × 12 B = 192 KB, heap-allocated in a
`Box<[DecodedOp; 16384]>`. Tag = full `pc`. Initial value in every
slot: `tag = u32::MAX` (will never match a real PC, which is at
minimum thumb-aligned and < 4 GB but `u32::MAX` is odd so guaranteed
non-matching).

Why 16384:

- The RP2350 ROM is 32 KB = 16384 halfwords exactly, so an entirely-ROM
  firmware maps 1:1 with zero aliasing.
- SRAM is 520 KB = 266240 halfwords; it aliases into 16384 slots at a
  ratio of 16.25:1. For the hot loops we're targeting (the basic
  workload uses 2 halfwords; realistic firmware inner loops use tens)
  this produces zero collisions in practice.
- 192 KB of heap is negligible next to the 520 KB SRAM and 4 KB boot
  RAM buffers the `Bus` already owns.

### 3.3 Cacheable region predicate

Only PCs in regions `0x0` (ROM), `0x1` (XIP / XIP-SRAM), `0x2` (SRAM)
are cached. PCs in other regions either can't execute (peripheral
space) or are dynamic (boot RAM, which has been used for jump tables
in RP2350 bootrom paths — measure before adding). Predicate:

```rust
#[inline(always)]
fn is_cacheable_pc(pc: u32) -> bool {
    matches!(pc >> 28, 0x0 | 0x1 | 0x2)
}
```

## 4. Placement

**Picked: on `Bus`.**

| Location | For | Against |
|---|---|---|
| `Bus` | Shared across both cores (dual-core basic workload gets the same cache hit rate per core); single box; lives next to the memory that backs it, so the invalidation hooks (which are bus-level operations) are right there. | If we ever move to true threaded dual-core (HLD `Threaded Dual-Core Emulation` is drafted but not landed), two cores will need synchronised access — but the draft makes `Bus` `Send + Sync` behind a mutex/RwLock anyway, and read-only hits would be hot-path-cheap with a `RwLock` read. Worry about it then. |
| `CortexM33` | Per-core; no sharing concerns in a future threaded world. | Doubles memory; halves hit rate on single-core workloads that jump between cores' code; invalidation hooks on flash/ROM loads would need to reach both cores. |
| `Emulator` | Neutral | `decode_execute` receives `&mut Bus`, not `&mut Emulator`; awkward accessor path. |

Field layout on `Bus`:

```rust
pub struct Bus {
    pub memory: Memory,
    // ... existing fields ...
    /// PC-keyed decoded-op cache. Direct-mapped, 16384 entries.
    /// See HLD 2026.04.14 §3.
    decode_cache: Box<[DecodedOp; 16384]>,
}
```

Constructor: fill with `DecodedOp { tag: u32::MAX, .. }`. Because the
array is 192 KB `Box` is mandatory (no stack).

## 5. Hit path — modified `decode_execute`

```rust
pub(crate) fn decode_execute(&mut self, bus: &mut Bus) -> u32 {
    bus.reset_extra_wait_states();
    let pc = self.regs.pc();
    self.current_instr_addr = pc;

    // Cache lookup (bypasses bus.read16 + is_wide + re-fetch on hit).
    let entry = if is_cacheable_pc(pc) {
        let slot = ((pc >> 1) & 0x3FFF) as usize;
        let e = bus.decode_cache[slot];        // Copy, 12 B
        if e.tag == pc { Some(e) } else { None }
    } else {
        None
    };

    let (hw0, hw1, is_wide, flag_only) = match entry {
        Some(e) => {
            // On hit we skip bus.read16; re-apply the fetch wait-state
            // the non-cached path would have charged. See §8.
            bus.add_extra_wait_states(e.fetch_wait as u32);
            (e.hw0, e.hw1, (e.flags & 0b001) != 0,
             (e.flags & 0b100) != 0)
        }
        None => self.populate_decode_cache(bus, pc),
    };

    // --- Everything below is identical to today's decode.rs ---

    let in_it = self.it_state & 0xF != 0;
    let cond = if in_it { (self.it_state >> 4) & 0xF } else { 0xE };
    let cond_passed = self.regs.condition_passed(cond);

    if is_wide {
        self.regs.set_pc(pc.wrapping_add(4));
        let cycles = if cond_passed {
            self.execute_thumb32(hw0, hw1, bus)
        } else { 1 };
        if in_it { self.advance_it_state(); }
        cycles + bus.extra_wait_states()
    } else {
        self.regs.set_pc(pc.wrapping_add(2));
        let saved_flags = if in_it { self.regs.xpsr & 0xF800_0000 } else { 0 };
        let cycles = if cond_passed {
            self.execute_thumb16(hw0, bus)
        } else { 1 };
        if in_it && cond_passed && !flag_only {
            self.regs.xpsr = (self.regs.xpsr & !0xF800_0000) | saved_flags;
        }
        if in_it { self.advance_it_state(); }
        cycles + bus.extra_wait_states()
    }
}
```

Invariants preserved 1:1 with today:

- `bus.reset_extra_wait_states()` still called first (required by Agent
  B's eventual short-circuit; no-op here).
- `self.current_instr_addr = pc` still set before execute runs.
- `self.regs.set_pc(pc + {2,4})` still happens before execute runs.
- IT-block state save/restore/advance identical.
- Flag-only suppression identical; pre-computed flag used instead of
  recomputing.

## 6. Miss path — populate

```rust
#[cold]
#[inline(never)]
fn populate_decode_cache(&mut self, bus: &mut Bus, pc: u32)
    -> (u16, u16, bool, bool)
{
    // Fetch first halfword via the normal bus path — this is the only
    // time the expensive bus.read16 runs for a given PC until
    // invalidated. The wait states it accumulates (0 for ROM / XIP /
    // SRAM0/1/3/4/5/7/8/9; +1 for SRAM bank 2 or 6) are captured
    // below and stored on the cache entry so subsequent hits can
    // re-charge them without rerunning read16.
    let before = bus.extra_wait_states();
    let hw0 = bus.read16(pc);
    if bus.bus_fault() {
        // Fetch fault: DO NOT cache. See §7. Return a sentinel so the
        // caller drives the existing fault path without poisoning the
        // cache with bogus hw0.
        return (hw0, 0, false, false);
    }

    let wide = is_wide(hw0);
    let hw1 = if wide { bus.read16(pc.wrapping_add(2)) } else { 0 };
    if wide && bus.bus_fault() {
        return (hw0, hw1, true, false);
    }

    // fetch_wait = wait states the two fetches added. Bounded by 2
    // (both halves in bank 2/6). We do NOT reset extra_wait_states
    // here — it already contains the correct fetch-charge for the
    // non-cached execution of THIS instruction, matching today's
    // behaviour exactly. Only subsequent cache hits need to synthesise
    // the charge from `fetch_wait`.
    let fetch_wait_u32 = bus.extra_wait_states().saturating_sub(before);
    let fetch_wait = fetch_wait_u32.min(255) as u8;

    let flag_only = !wide && is_thumb16_flag_only(hw0);

    // Only cache cacheable-region PCs.
    if is_cacheable_pc(pc) {
        let mut flags = 0u8;
        if wide       { flags |= 0b001; }
        // bit 1 (is_pure) always 0 in Agent A populate — Agent B owns it.
        if flag_only  { flags |= 0b100; }
        let slot = ((pc >> 1) & 0x3FFF) as usize;
        bus.decode_cache[slot] = DecodedOp {
            tag: pc, hw0, hw1, fetch_wait, flags,
        };
    }

    (hw0, hw1, wide, flag_only)
}
```

`is_wide` and `is_thumb16_flag_only` stay in `decode.rs` — same bodies
as today. Populate is `#[cold] #[inline(never)]` so the hot path keeps
a tight prologue.

## 7. Invalidation model

Cache is "stale" only if the bytes at a cached PC change. Enumerated:

| Operation | Invalidates | Why |
|---|---|---|
| `Emulator::load_bootrom(data)` | ROM slots: `tag >> 28 == 0` | Replaces ROM bytes wholesale. |
| `Bus::load_flash(data)` | XIP slots: `tag >> 28 == 0x1` | Replaces flash bytes wholesale. |
| `Bus::write8/16/32` targeting region 0x2 (SRAM) | Single slot at `(addr >> 1) & 0x3FFF`, and the slot preceding it (a narrow cached at PC=N might now be the tail of a wide at PC=N-2 — or a wide cached at PC=N-2 might have its second halfword rewritten) | Stores to SRAM can mutate executable bytes. |
| `Bus::write8/16/32` targeting region 0x1 (XIP SRAM) | Single slot at `(addr >> 1) & 0x3FFF` (and preceding, same reasoning) | Rare, but XIP SRAM is writable. |
| `Memory::sram_write8/16/32` (backing store, called directly by tests via `bus.memory.sram_write*`) | **Not hooked.** Document the constraint. | These are `Memory`'s own methods; `Bus` does not see them. See §9. |
| `Emulator::poke` | Same as above — routes to `bus.memory.poke32` without going through `bus.write*` | **Not hooked in v1.0.0.** The only production caller is the paced_bench harness, which pokes BEFORE `emu.reset()` + before the first `step()` — i.e. before any cache entries exist. Adding a hook is cheap but not load-bearing for the bench. Document. |
| Exception entry (`enter_exception`) sets PC to `vector & !1` | Nothing. The cache is PC-keyed; the handler's PC gets its own slot. | Vector table lives in ROM/SRAM and is loaded via `load_bootrom`/`sram_write` — invalidation is whoever wrote the vectors. |
| Security-state transition (`transition_to_secure` / `_to_nonsecure`) | Nothing. The code bytes at a given PC don't change; execution does swap between banked register files, but the cache is indexed by the physical PC that `self.regs.pc()` returns. | Non-secure aliases of secure addresses produce different PCs, so the tag mismatches naturally. |

### 7.1 Hooked write paths

Add an `invalidate_one(pc_word_addr)` helper and call it from:

```rust
// In Bus::write8/16/32 (after the match body completes successfully):
match region {
    0x1 if Self::is_xip_sram(addr) => { ...; self.invalidate_pc_range(addr, N); }
    0x2 if offset < SRAM_SIZE as u32 => { ...; self.invalidate_pc_range(addr, N); }
    // other regions: no-op
}
```

Where N is 1, 2, or 4 bytes depending on the write width. Invalidation
logic:

```rust
#[inline]
fn invalidate_pc_range(&mut self, addr: u32, len: u8) {
    // Clear the slot for this halfword AND the preceding halfword (in case
    // a wide instruction spans the boundary).
    let start = addr & !1; // align down to halfword
    let end = (addr.wrapping_add(len as u32 - 1)) & !1;
    let mut p = start.wrapping_sub(2); // check preceding slot too
    let last = end;
    loop {
        if is_cacheable_pc(p) {
            let slot = ((p >> 1) & 0x3FFF) as usize;
            self.decode_cache[slot].tag = u32::MAX;
        }
        if p == last { break; }
        p = p.wrapping_add(2);
    }
}
```

### 7.2 Load-paths

```rust
// Bus::load_flash: after self.memory.load_flash(data):
self.invalidate_region(0x1);

// Emulator::load_bootrom routes to bus.memory.load_rom — add a new
// Bus::load_bootrom that does both:
pub fn load_bootrom(&mut self, data: &[u8]) {
    self.memory.load_rom(data);
    self.invalidate_region(0x0);
}
```

`invalidate_region(r)` walks all 16384 entries and clears any whose
tag's high nibble matches. 16384 × 4 B reads + compare is ~50 µs —
acceptable on a once-per-boot path. Alternative (per-region sub-array)
is not worth the extra indirection on the hot path.

`Emulator::load_bootrom` becomes `self.bus.load_bootrom(data)`.

## 8. Correctness preservation

Explicit tabulation of every invariant the HLD claims to preserve,
with the mechanism that preserves it:

| Invariant | Mechanism |
|---|---|
| Cycle counts returned by execute functions identical | Execute functions are called with the same `(opcode, bus)` as before; they don't read from the cache. |
| IT-block state transitions occur | `advance_it_state()` still called at end, same condition (`in_it`). |
| `current_instr_addr = pc` set before execute | Done unconditionally before cache lookup. |
| Flag-only-in-IT suppression | Same logic, but `is_thumb16_flag_only` pre-computed and retrieved from `flags` bit 2. |
| `bus.reset_extra_wait_states()` called per instruction | Called at the top of `decode_execute` as today. (Agent B may move this.) |
| `bus.extra_wait_states()` added to returned cycles | Still added at both wide / narrow return sites. |
| **Fetch wait-state charge (bank 2/6 SRAM)** | Captured on miss, stored in `DecodedOp::fetch_wait`, re-added on every subsequent hit via `bus.add_extra_wait_states(e.fetch_wait as u32)`. See §8.3. |
| Bus-fault on fetch fires | See §8.1. |
| `execute_one` / `execute_one_with_bus` / `execute_one_wide*` unchanged | See §8.2. |

### 8.1 Fetch faults

**Decision: do NOT cache faulty fetches; always re-fetch.** Rationale:

- Bus faults on fetch are rare (misaligned PC, unmapped region). They
  fire through `bus.bus_fault()` which is checked in `CortexM33::step`
  after `decode_execute` returns.
- Caching a fault would need to re-raise `bus_fault` on every cache hit
  at that PC. Error-path complexity for a cold path is a bad trade.
- If the fault is transient (firmware fixed the mapping), the next
  execution must re-check; a cached fault would lie.

Populate path (§6) returns early without writing the cache when
`bus.bus_fault()` is set. `decode_execute` continues into the execute
dispatch with `hw0` = whatever `read16` returned on fault (usually 0);
`step` sees `bus.bus_fault()` on return and calls `enter_exception(5)`
or `enter_exception(3)`. Identical to today.

### 8.2 Test-only execute_one paths

`CortexM33::execute_one`, `execute_one_with_bus`, `execute_one_wide`,
`execute_one_wide_with_bus` (core/mod.rs:237-273) bypass
`decode_execute` entirely — they call `execute_thumb16` / `_thumb32`
directly with a caller-provided opcode. **No change required.** These
paths never touch the cache.

`execute_one` constructs a local `Bus::default()` — which will contain
a fresh empty cache. Nothing to worry about.

### 8.3 Fetch wait-state preservation

Today `Bus::read16` on SRAM bank 2 or 6 adds +1 `extra_wait_states`
via `sram_bank_wait`. The current decode path accumulates that into
the returned cycle count. If we skipped `read16` entirely on hits, a
compute-only instruction (e.g. `ADDS`) at an address in bank 2/6 would
return one fewer cycle than today — a genuine cycle-accuracy
regression.

Resolution: store the fetch wait-state charge on the cache entry
(`fetch_wait: u8`) and re-add it on every hit via a new thin wrapper
`bus.add_extra_wait_states(n)`:

```rust
impl Bus {
    #[inline(always)]
    pub fn add_extra_wait_states(&mut self, n: u32) {
        self.extra_wait_states += n;
    }
}
```

On the basic workload (SRAM bank 0, `fetch_wait = 0` everywhere),
`add_extra_wait_states(0)` is trivially eliminable by LLVM once
inlined. On bank-2/6 code the +1 charge is preserved exactly.

Wide instructions whose two halfwords straddle bank 2/6 boundaries
(max `fetch_wait = 2`) are handled by simply storing the sum — the
cache entry doesn't need to re-derive per-half wait states since the
two halves always move together on fetch.

Unit test coverage: populate at a bank-0 address and a bank-2 address;
assert the cycle counts returned by `decode_execute` on the 1st and
2nd execution at each address are identical (first = populate+execute,
second = hit+execute).

## 9. SRAM writes that bypass `Bus`

`bus.memory.sram_write8/16/32` called directly by in-crate tests
(tests.rs:5469-5472) write to SRAM WITHOUT going through `Bus::write*`.
These do not trigger invalidation.

**Decision: don't hook `Memory::sram_write*`.** Reasoning:

- `Memory` is in `mdpicoem-common`, shared with `mdrp2040`. Adding a
  callback or making it generic drags a large dependency change into
  an unrelated crate.
- In-crate tests that load code via `bus.memory.sram_write*` do so
  BEFORE any `step()` — the cache is empty, so invalidation would
  be a no-op anyway.
- If a future test writes-then-executes-then-writes-then-executes at
  the same PC with different bytes, it must either (a) use
  `bus.write*` (which will invalidate), or (b) call a new
  `bus.invalidate_all()` helper (trivial to add) between writes.

Documented constraint, not a code change.

## 10. Worked example — basic workload

Layout after `emu.poke(0x2000_0000, 0x1C40_2001)` and
`emu.poke(0x2000_0004, 0x0000_E7FD)`:

- 0x2000_0000: `MOVS R0, #1`        (hw = 0x2001, narrow)
- 0x2000_0002: `ADDS R0, R0, #1`    (hw = 0x1C40, narrow)
- 0x2000_0004: `B .-2` → target 0x2000_0002 (hw = 0xE7FD, narrow)

Slots used: `(0x2000_0000 >> 1) & 0x3FFF = 0`,
`(0x2000_0002 >> 1) & 0x3FFF = 1`,
`(0x2000_0004 >> 1) & 0x3FFF = 2`.

| Cycle | PC | Cache action |
|---|---|---|
| 1 | 0x2000_0000 | miss → populate slot 0 (MOVS). |
| 2 | 0x2000_0002 | miss → populate slot 1 (ADDS). |
| 3 | 0x2000_0004 | miss → populate slot 2 (B). Branch taken to 0x2000_0002. |
| 4 | 0x2000_0002 | **hit** slot 1. |
| 5 | 0x2000_0004 | **hit** slot 2. |
| 6 | 0x2000_0002 | **hit** slot 1. |
| ... | ... | steady-state 100% hit rate. |

What's saved per hit (steady state, 2 instructions per loop body):

- No `bus.read16(pc)` call (20% of baseline time per the adjacent
  Fast Path Bus Read HLD — an ~80-line `match` with SRAM alias strip,
  bank-wait bump, `last_access_cycles` write).
- No `is_wide(hw0)` call.
- No Thumb-16 dispatch match (`opcode >> 11` → 32-arm switch).
  Execute functions `thumb16_add_sub` (ADDS) / `thumb16_branch` (B)
  are called directly — still unavoidable, but dispatched from the
  cache hit rather than from the match.

Qualitative speedup argument: the two wins above are the two biggest
items on the flamegraph outside the execute functions themselves. We
are not claiming a number — Agent B's short-circuit of the wait-state
accounting is expected to compound multiplicatively — but the basic
workload's inner loop should drop from ~22 host cycles per instruction
to something substantially smaller. Measurement gate is the bench
re-run.

## 11. Risks and edge cases

| Risk | Mitigation |
|---|---|
| **Self-modifying code — ROM** | Can't happen (ROM is read-only in the emulator — writes to region 0x0 are silently dropped in `Bus::write*`). No cache risk. |
| **SMC — flash** | Rare, but possible for bootloader flash programming. `Bus::load_flash` is the only path that changes XIP bytes; always invalidate on call. Runtime flash programming via QMI isn't modelled today; when it lands it must call `invalidate_region(0x1)`. Put a `// TODO: invalidate_region(0x1)` comment at the QMI write path for the future. |
| **SMC — SRAM** | Possible. `Bus::write*` to region 0x2 handled via `invalidate_pc_range`. |
| **SMC — XIP SRAM (0x1C00_0000..0x1C00_3FFF)** | Possible. Same hook. |
| **Security-state transitions (S ↔ NS)** | Cache is keyed by physical PC; different aliases produce different PCs. The banked register file swap (SP, LR, etc.) doesn't affect the `r[15]`-based lookup. Safe. |
| **Exceptions jumping to vector table** | Handler PC is a different slot from caller's PC. No special handling. Vector table content is written by ROM/SRAM loaders, which invalidate. |
| **PC wraparound** | `pc.wrapping_add(2)` in populate can wrap 0xFFFF_FFFE → 0. `is_cacheable_pc(0)` is true (ROM), so nothing breaks. A wide instruction at 0xFFFF_FFFE would fetch hw1 from address 0 — today's decode path does exactly this, so the cache inherits the same (nonsensical-but-defined) behaviour. |
| **Wide instr at PC where hw0 was previously seen as narrow** (code edit flips a halfword from 0x4600 to 0xE800) | Cache entry at `(pc>>1) & mask` has tag == pc; the `is_wide` bit is stale. Invalidation on the write to the modified byte clears the slot (§7.1). Next fetch misses and re-populates. |
| **Wide instr at boundary that gets its hw1 rewritten** | `invalidate_pc_range` clears the PRECEDING slot as well as the slot the write lands on, so a wide at PC=N with hw1 at N+2 is invalidated when anything in [N, N+3] is written. |
| **`execute_one_*` test paths** | Never touch the cache (§8.2). |
| **Dual-core** | Both cores share one cache. If core 0 and core 1 execute the SAME PC (same physical bytes) both benefit from one entry. If they execute different PCs at the same index (collision), the first fetch wins the slot until the second overwrites. Hit rate drops to ~0% only in pathological collision patterns; bench firmware has each core's loop in a different bank (0x2000_0000 vs 0x2000_1000) which hashes to distinct slots. No action needed. |
| **192 KB heap** | Up-front allocation on `Bus::new`. Acceptable next to existing `Bus` state (520 KB SRAM, ~16 KB XIP SRAM, many `HashMap`s). |
| **Threaded dual-core (draft HLD)** | A future `&Bus` shared across threads will need the cache behind a read-path lock. If that materialises, the cache becomes `RwLock<Box<[DecodedOp; N]>>` and hits take a read guard (still cheap vs `bus.read16`). Out of scope here. |
