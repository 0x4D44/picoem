# Thumb-32 Instruction Decoder — Low-Level Design

Version: 0.1.0 — DRAFT
Date: 2026-04-13

## 1. Prerequisites (Before Writing Thumb-32 Handlers)

The devil's advocate review found four issues that must be resolved before
implementing Thumb-32 handlers. Building on incorrect foundations wastes effort.

### 1.1 IT Block State Machine (BLOCKING)

**Problem:** There is zero IT block infrastructure. The IT instruction (0xBFxx)
currently falls through to a NOP catch-all. IT blocks change the semantics of
the decode loop — they make 1-4 subsequent instructions conditional without
condition fields in their encodings.

**Design:**

Add `it_state: u8` to `CortexM33`. This mirrors the ITSTATE field in xPSR
(bits [15:10] and [26:25], packed as an 8-bit value).

Format: `cond[3:0]:mask[3:0]` where:
- `cond` = base condition code
- `mask` = which subsequent instructions are covered (bitmask, MSB first)
- `mask == 0` means "not in IT block"

Modify `decode_execute()`:

```rust
fn decode_execute(&mut self, bus: &mut Bus) -> u32 {
    let pc = self.regs.pc();
    self.current_instr_addr = pc;
    let hw0 = bus.read16(pc);

    // Check IT block BEFORE executing
    let in_it = self.it_state & 0xF != 0;
    let cond = if in_it { (self.it_state >> 4) & 0xF } else { 0xE }; // 0xE = AL
    let cond_passed = self.regs.condition_passed(cond as u8);

    if is_wide(hw0) {
        let hw1 = bus.read16(pc.wrapping_add(2));
        self.regs.set_pc(pc.wrapping_add(4));
        let cycles = if cond_passed {
            self.execute_thumb32(hw0, hw1, bus)
        } else {
            1 // skipped instruction still costs 1 cycle
        };
        if in_it { self.advance_it_state(); }
        cycles
    } else {
        self.regs.set_pc(pc.wrapping_add(2));
        let cycles = if cond_passed {
            self.execute_thumb16(hw0, bus, in_it)
        } else {
            1
        };
        if in_it { self.advance_it_state(); }
        cycles
    }
}

fn advance_it_state(&mut self) {
    let mask = self.it_state & 0xF;
    if mask & 0x7 == 0 {
        self.it_state = 0; // Last instruction in block
    } else {
        // Shift mask left, invert condition for T/E slots
        self.it_state = (self.it_state & 0xE0) | ((mask << 1) & 0x1F);
    }
}
```

**Flag suppression in IT blocks:** Inside an IT block, Thumb-16 instructions
that normally always set flags (ADDS, SUBS, etc.) must NOT set flags unless
they are the last instruction and the encoding has S=1. Pass `in_it: bool` to
`execute_thumb16` and suppress flag updates when true.

For Thumb-32, the S bit is explicit in the encoding, so no suppression needed.

**IT instruction handler (Thumb-16, in the misc group 0xBFxx):**

```rust
// IT{x{y{z}}} cond — 1011_1111_firstcond_mask
fn thumb16_it(&mut self, opcode: u16) -> u32 {
    let firstcond = (opcode >> 4) & 0xF;
    let mask = opcode & 0xF;
    self.it_state = ((firstcond as u8) << 4) | (mask as u8);
    1
}
```

### 1.2 SP Banking (IMPORTANT)

**Problem:** R13 is used directly without tracking which banked SP is active.
MSR writing to CONTROL.SPSEL must switch R13 between MSP and PSP.

**Design:** Add helpers to Registers:

```rust
fn sync_sp_to_banked(&mut self) {
    if self.control & 2 != 0 { // SPSEL
        self.psp = self.r[13];
    } else {
        self.msp = self.r[13];
    }
}

fn sync_sp_from_banked(&mut self) {
    self.r[13] = if self.control & 2 != 0 { self.psp } else { self.msp };
}

fn set_control(&mut self, val: u32) {
    self.sync_sp_to_banked();
    self.control = val;
    self.sync_sp_from_banked();
}
```

Call `set_control()` from MSR handler. Call `sync_sp_from_banked()` on
exception entry/return (handler mode always uses MSP).

### 1.3 Bus Fault Return Path (IMPORTANT)

**Problem:** All bus reads return 0 for unmapped addresses. The bootrom needs
BusFault to probe for flash.

**Design:** Add a fault signal to Bus:

```rust
pub struct Bus {
    pub memory: Memory,
    /// Set by the last read/write if it accessed an unmapped address.
    pub fault: bool,
}
```

Bus read/write methods set `self.fault = true` for unmapped regions. The core
checks `bus.fault` after each memory access and, if set, enters the BusFault
handler (Phase 3). For Phase 1, the core can log the fault and continue.

This is a minimal change — add one bool check after each bus access, which is
already behind a branch (the address decode match).

### 1.4 File Organization (IMPORTANT)

**Problem:** execute.rs at 832 lines with ~52 opcodes. Thumb-32 adds ~150
more, projected 3,200+ lines.

**Design:** Split into modules:

```
core/
  mod.rs                  — CortexM33 struct, step(), IT state
  decode.rs               — Top-level dispatch (Thumb-16 and Thumb-32)
  execute.rs              — Thumb-16 handlers + helpers (existing)
  execute_dp.rs           — Thumb-32 data processing (modified imm, shifted reg, plain imm)
  execute_mem.rs          — Thumb-32 load/store (single, multiple, dual, exclusive)
  execute_branch.rs       — Thumb-32 branches, hints, barriers, MSR/MRS, system
  execute_mul.rs          — Thumb-32 multiply, divide, long multiply
  execute_coproc.rs       — Coprocessor (MRC/MCR/CDP), FPU stubs
  registers.rs            — Register file (existing)
```

All files impl CortexM33 — Rust allows multiple impl blocks across files in
the same crate. The dispatch in decode.rs calls into these modules.

Expected sizes:
- execute.rs: ~850 lines (existing Thumb-16, unchanged)
- execute_dp.rs: ~500 lines (ThumbExpandImm + ~30 data-proc opcodes)
- execute_mem.rs: ~600 lines (load/store single, multiple, dual, exclusive)
- execute_branch.rs: ~300 lines (branches, system, hints)
- execute_mul.rs: ~250 lines (multiply, divide, long multiply)
- execute_coproc.rs: ~200 lines (stubs, dispatch to CP0/4/5/7)

Total: ~2,700 additional lines, no single file over ~850.

## 2. Top-Level Thumb-32 Decode Tree

A 32-bit Thumb instruction is two consecutive halfwords (hw0, hw1).
hw0 bits[15:11] ∈ {0b11101, 0b11110, 0b11111}.

Key dispatch fields:
```
op1 = (hw0 >> 11) & 0x3    // hw0[12:11]
op2 = (hw0 >> 4) & 0x7F    // hw0[10:4]
op  = (hw1 >> 15) & 0x1    // hw1[15]
```

### Dispatch table

```
op1=01:
  op2[6:5]=00:
    op2[2]=0 → Load/Store Multiple (LDM, STM, PUSH, POP)
    op2[2]=1 → Load/Store Dual, Exclusive, Table Branch
  op2[6:5]=01 → Data Processing (shifted register)
  op2[6:5]=1x → Coprocessor, FPU

op1=10:
  op=0:
    op2[5]=0 → Data Processing (modified immediate)
    op2[5]=1 → Data Processing (plain binary immediate)
  op=1 → Branches and Miscellaneous Control

op1=11:
  op2[6:4]=000..011 → Load/Store Single (store, load byte/half/word)
  op2[6:4]=100 → Data Processing (register) — CLZ, RBIT, REV, extends
  op2[6:4]=101 → Multiply, Multiply-Accumulate, Divide (32-bit result)
  op2[6:4]=110..111 → Long Multiply, Long Divide (64-bit result) / Coprocessor
```

### Rust implementation

```rust
fn execute_thumb32(&mut self, hw0: u16, hw1: u16, bus: &mut Bus) -> u32 {
    let op1 = (hw0 >> 11) & 0x3;
    let op2 = (hw0 >> 4) & 0x7F;
    let op  = (hw1 >> 15) & 0x1;

    match op1 {
        0b01 => match op2 >> 5 {
            0b00 => if op2 & 0x04 == 0 {
                self.thumb32_ldm_stm(hw0, hw1, bus)
            } else {
                self.thumb32_load_store_dual(hw0, hw1, bus)
            },
            0b01 => self.thumb32_dp_shifted_reg(hw0, hw1),
            _    => self.thumb32_coprocessor(hw0, hw1, bus),
        },
        0b10 => if op == 0 {
            if op2 & 0x20 == 0 {
                self.thumb32_dp_modified_imm(hw0, hw1)
            } else {
                self.thumb32_dp_plain_imm(hw0, hw1)
            }
        } else {
            self.thumb32_branch_misc(hw0, hw1, bus)
        },
        0b11 => match op2 >> 4 {
            0b000..=0b011 => self.thumb32_load_store_single(hw0, hw1, bus),
            0b100         => self.thumb32_dp_register(hw0, hw1),
            0b101         => self.thumb32_multiply(hw0, hw1),
            _             => if op2 & 0x40 != 0 {
                self.thumb32_coprocessor(hw0, hw1, bus)
            } else {
                self.thumb32_long_multiply(hw0, hw1)
            },
        },
        _ => self.thumb32_undefined(hw0, hw1),
    }
}
```

## 3. ThumbExpandImm (Modified Immediate Constants)

The 12-bit immediate field is `i:imm3:imm8` where:
- `i` = hw0[10]
- `imm3` = hw1[14:12]
- `imm8` = hw1[7:0]

Combined: `imm12 = (i << 11) | (imm3 << 8) | imm8`

### Algorithm

```rust
/// Expand a 12-bit modified immediate to a 32-bit constant with carry-out.
/// carry_in is the current APSR.C (passed through for replication patterns).
#[inline(always)]
fn thumb_expand_imm_c(imm12: u32, carry_in: bool) -> (u32, bool) {
    if imm12 & 0xC00 == 0 {
        // Bits [11:10] = 00 — byte replication patterns
        let imm8 = imm12 & 0xFF;
        let val = match (imm12 >> 8) & 0x3 {
            0b00 => imm8,
            0b01 => (imm8 << 16) | imm8,
            0b10 => (imm8 << 24) | (imm8 << 8),
            _    => imm8 * 0x01_01_01_01, // 0xnnnnnnnn
        };
        (val, carry_in) // carry unchanged
    } else {
        // Bits [11:10] != 00 — rotate right of (1:imm7)
        let unrotated = 0x80 | (imm12 & 0x7F);
        let rotation = (imm12 >> 7) & 0x1F;
        let val = unrotated.rotate_right(rotation);
        (val, val >> 31 != 0) // carry = MSB of result
    }
}
```

### Performance considerations

The function has one branch (replication vs. rotation). The replication path
uses a 2-bit match (4 cases). The rotation path uses `u32::rotate_right()`
which compiles to a single `ror` instruction on x86. Both paths are branchless
after the top-level split. Total: ~5-8 host instructions. Well within budget.

Mark as `#[inline(always)]` since it's called from every data-processing
instruction.

## 4. Instruction Groups — Design Notes

### 4.1 Data Processing (Modified Immediate) — execute_dp.rs

Format: `11110_i_0_op[3:0]_S_Rn  0_imm3_Rd_imm8`

16 operations, each with S-bit variant. Special cases:
- Rd=1111 + S=1 → discard result, flags only (TST, TEQ, CMN, CMP)
- Rn=1111 → MOV/MVN (no source register)

Implementation: extract op, S, Rn, Rd, imm12. Call `thumb_expand_imm_c()`.
Single match on op[3:0] dispatching to the ALU operation. Reuse
`add_with_carry()` from existing helpers.

Cycle cost: 1 cycle (all). HIGH confidence.

### 4.2 Data Processing (Plain Binary Immediate) — execute_dp.rs

Format: `11110_i_1_op[4:0]_0_Rn  0_imm3_Rd_imm8`

Key instructions:
- **MOVW** (op=00100): Rd = imm16 (formed as imm4:i:imm3:imm8)
- **MOVT** (op=01100): Rd[31:16] = imm16, Rd[15:0] unchanged
- **ADDW** (op=00000): Rd = Rn + ZeroExtend(imm12) — NOT ThumbExpandImm
- **SUBW** (op=01010): Rd = Rn - ZeroExtend(imm12)
- **SBFX/UBFX/BFI/BFC**: bit field operations
- **SSAT/USAT**: saturation (DSP)

Note: ADDW/SUBW with Rn=1111 become ADR (PC-relative address generation).

For MOVW/MOVT, the 16-bit immediate encoding:
`imm16 = (hw0[3:0] << 12) | (hw0[10] << 11) | (hw1[14:12] << 8) | hw1[7:0]`

Cycle cost: 1 cycle (all). HIGH confidence.

### 4.3 Data Processing (Shifted Register) — execute_dp.rs

Format: `11101_01_op[3:0]_S_Rn  0_imm3_Rd_imm2_tt_Rm`

Same 16 ALU ops as modified immediate, but with barrel-shifted Rm:
- shift_type `tt`: 00=LSL, 01=LSR, 10=ASR, 11=ROR
- shift_amount: `imm3:imm2` (5 bits)
- Special: tt=11, amount=0 → RRX (rotate right through carry by 1)

When Rn=1111 and op=0010, becomes wide shift/rotate instructions:
LSL.W, LSR.W, ASR.W, ROR.W, RRX (with immediate shift amount).

Cycle cost: 1 cycle (all). HIGH confidence.

### 4.4 Load/Store Single — execute_mem.rs

This is the most complex group. Three addressing modes, five data sizes,
load vs store, plus literal (PC-relative) variants.

**Data sizes:** Byte, Halfword, Word (+ signed variants for loads: LDRSB, LDRSH)

**Addressing modes:**
1. Immediate 12-bit unsigned: `[Rn, #imm12]` — most common
2. Immediate 8-bit with P/U/W: `[Rn, #+/-imm8]{!}` or `[Rn], #+/-imm8`
3. Register with shift: `[Rn, Rm, LSL #0-3]`

Plus PC-relative literal loads (Rn=1111).

**Dispatch logic:**
```
hw0[10:9] = size (00=byte, 01=half, 10=word)
hw0[8]    = sign (for loads: 0=unsigned, 1=signed)
hw0[7]    = 1 for imm12, 0 for imm8/register
hw0[3:0]  = Rn (1111 = literal)

For hw0[7]=0 (not imm12):
  hw1[11] = 1 → imm8 with P/U/W
  hw1[11] = 0 → register offset (hw1[5:4] = shift amount)
```

**Cycle costs (zero-wait-state memory):**
| Operation | Cycles | Confidence |
|-----------|--------|------------|
| LDR (any addressing mode) | 2 | MEDIUM |
| LDR (pipelined after another LDR) | 1 effective | MEDIUM |
| STR (any addressing mode) | 1 | HIGH |
| LDRB/LDRH/LDRSB/LDRSH | 2 | MEDIUM |
| STRB/STRH | 1 | HIGH |

### 4.5 Load/Store Multiple — execute_mem.rs

Format: `11101_00_op_P_U_W_L_Rn  reglist[15:0]`

Four variants: STMIA, STMDB, LDMIA, LDMDB.
PUSH = STMDB SP!, POP = LDMIA SP!.

The 32-bit encoding allows registers R0-R15 (16-bit register list), unlike
Thumb-16 which is limited to R0-R7 + LR/PC.

**Cycle costs:**
| Operation | Cycles (M4) | Cycles (M33 estimate) | Confidence |
|-----------|-------------|----------------------|------------|
| LDM N regs | 1 + N | N | LOW |
| STM N regs | 1 + N | N | LOW |
| POP with PC | 1 + N + P | N + P | LOW |

The Aioanei thesis suggests M33 eliminated the 1-cycle setup overhead. Must
validate against hardware. **Start with 1+N (M4 model) and adjust after
DWT CYCCNT measurement.**

### 4.6 Load/Store Dual, Exclusive, Table Branch — execute_mem.rs

**LDRD/STRD (immediate):** Load/store two consecutive words.
- Rt and Rt2 from hw1[15:12] and hw1[11:8]
- 8-bit immediate offset, word-aligned (imm8 << 2)
- Pre/post-index with writeback (P/U/W bits)

**LDREX/STREX family:** Exclusive access for atomics. For Phase 1, model as
normal load/store (exclusive monitor tracking deferred to Phase 5).

**TBB/TBH:** Table branch byte/halfword. Used for switch statements.
- TBB: PC = PC + ZeroExtend(MemU[Rn + Rm])
- TBH: PC = PC + 2 * ZeroExtend(MemU[Rn + Rm*2])
- Cost: 2 + pipeline refill

**Cycle costs:**
| Operation | Cycles | Confidence |
|-----------|--------|------------|
| LDRD | 3 (M4) or 2 (M33?) | LOW |
| STRD | 3 (M4) or 2 (M33?) | LOW |
| LDREX | 2 | MEDIUM |
| STREX | 2 | MEDIUM |
| TBB/TBH | 4-5 (table read + branch) | LOW |

### 4.7 Branches and Miscellaneous Control — execute_branch.rs

**B.W conditional (T3):** 21-bit range (+/- 1 MB). Condition in hw0[9:6].
**B.W unconditional (T4):** 25-bit range (+/- 16 MB). Same offset encoding as BL.
**BL:** Already implemented.

**MSR/MRS:** Read/write special registers (APSR, MSP, PSP, PRIMASK, BASEPRI,
FAULTMASK, CONTROL). Critical for bootrom. Requires SP banking (Section 1.2).

**Hints:** NOP.W, YIELD.W, WFE.W, WFI.W, SEV.W — all 1-cycle NOPs for Phase 1.

**Barriers:** DSB, DMB, ISB. For the in-order M33, DSB/DMB are 1-cycle NOPs
unless the write buffer has pending writes. ISB flushes the pipeline
(1 + refill). Model all as 1 cycle for Phase 1.

**Cycle costs:**
| Operation | Cycles | Confidence |
|-----------|--------|------------|
| B.W taken | 2-3 | MEDIUM |
| B.W not taken | 1 | HIGH |
| MSR/MRS | 1-2 | MEDIUM |
| DSB/DMB | 1 | HIGH |
| ISB | 1 + P | MEDIUM |

### 4.8 Multiply, Divide — execute_mul.rs

**32-bit result:**
- MUL: Rd = Rn * Rm (1 cycle)
- MLA: Rd = Rn * Rm + Ra (1 cycle)
- MLS: Rd = Ra - Rn * Rm (1 cycle)

**64-bit result:**
- SMULL/UMULL: RdHi:RdLo = Rn * Rm (1 cycle, HIGH confidence)
- SMLAL/UMLAL: RdHi:RdLo += Rn * Rm (1 cycle)

**Division:**
- SDIV/UDIV: 2-11 cycles, data-dependent (early termination on leading zeros)

Division cycle count algorithm:
```rust
fn div_cycles(dividend: u32, divisor: u32) -> u32 {
    if divisor == 0 { return 2; } // div by zero returns 0 in 2 cycles
    let leading = dividend.leading_zeros();
    // Roughly: 2 + (32 - leading_zeros) / 3, clamped to 2-11
    (2 + (32 - leading) / 3).clamp(2, 11)
}
```

This is an approximation. Real hardware uses an iterative radix-2 or radix-4
divider. We'll refine with DWT CYCCNT measurements.

**DSP multiply variants** (SMLABB, SMLAD, SMMLA, USAD8, etc.): All 1-cycle.
Implement as Tier 4 — not needed for bootrom or basic SDK code.

### 4.9 Data Processing (Register) — execute_dp.rs or execute_mul.rs

Miscellaneous register operations:
- CLZ: count leading zeros (1 cycle)
- RBIT: reverse all 32 bits (1 cycle)
- REV.W / REV16.W / REVSH.W: byte reversal variants (1 cycle)
- Wide shift/rotate by register: LSL.W, LSR.W, ASR.W, ROR.W (1 cycle)
- Sign/zero extend: SXTH.W, SXTB.W, UXTH.W, UXTB.W (1 cycle)
- Sign/zero extend with add (DSP): SXTAH, UXTAB, etc. (1 cycle, Tier 4)

### 4.10 Coprocessor — execute_coproc.rs

RP2350 coprocessors:
| CP | Name | Used by |
|----|------|---------|
| 0 | GPIOC | Bootrom GPIO access |
| 4,5 | DCP | Double-precision FP, SHA-256, CRC |
| 7 | RCP | Redundancy/canary assertions |
| 10,11 | FPU | Single-precision floating point |

**Phase 1 stubs:**
- MRC/MCR: dispatch on coproc number, call trait method
- CDP: dispatch on coproc number
- LDC/STC: generate UsageFault (not used by bootrom)

**Phase 3 minimal implementations:**
- RCP (CP7): accept salt write, return dummy canary
- DCP (CP4/5): implement using host f64 for bootrom CRC
- GPIOC (CP0): forward to SIO GPIO registers

**FPU (CP10/11):** Phase 7. For now, check CPACR and generate UsageFault
(NOCP) if FPU instructions are executed without enabling.

Coprocessor cycle costs:
| Operation | Cycles | Confidence |
|-----------|--------|------------|
| MRC/MCR | 2 | MEDIUM |
| MCRR/MRRC | 2 | MEDIUM |
| CDP | 1+ (coprocessor-dependent) | LOW |

### 5.2 Pipeline Effects (Not Modeled in Phase 1)

These effects are real but deferred to post-hardware-validation:

1. **Load-use interlock**: 1-cycle stall when LDR result used by next
   instruction. Requires dependency tracking between consecutive instructions.

2. **I-bus/D-bus overlap**: Consecutive LDR instructions can pipeline to
   ~1 effective cycle. Would require modeling the dual-bus Harvard interface.

3. **Write buffer absorption**: STR completes in 1 cycle but buffer drain
   may stall subsequent stores. Would require modeling write buffer depth.

4. **Branch prediction (speculative fetch)**: M33 does speculative branch
   target fetch. May reduce taken-branch penalty from 2 to 1 in some cases.

### 5.3 Strategy

Start with M4 TRM values (conservative). The DWT CYCCNT oracle (Layer 3
testing) will reveal where we over-count or under-count. Adjust per-instruction
based on measured deltas. The cycle timing table above has confidence levels
to prioritize hardware validation.

2. SP banking (Section 1.2)
3. Bus fault signal (Section 1.3)

2. LDRD/STRD

4. MUL/MLA/MLS
5. SDIV/UDIV (with data-dependent timing)
6. SMULL/UMULL

8. Wide extend (UXTB.W, UXTH.W, SXTB.W, SXTH.W)

### Phase 1d: Tier 3 Instructions (system/bootrom)
1. MSR/MRS
2. DSB/DMB/ISB
3. LDREX/STREX (as normal load/store, exclusive monitor deferred)
4. TBB/TBH
5. Coprocessor stubs (MRC/MCR/CDP dispatch)
6. NOP.W, WFI.W, WFE.W, SEV.W
7. SSAT/USAT (saturation)

### Phase 1e: Tier 4 (DSP, deferred)
- SMLABB, SMLAD, SMMLA, USAD8, parallel add/sub, etc.

### Phase 7: FPU (separate phase per HLD)
- All VFP instructions (VADD, VSUB, VMUL, VDIV, VLDR, VSTR, etc.)
- For now: check CPACR, generate UsageFault (NOCP) for any FPU instruction.

## 7. Open Questions

1. **LDM/STM: 1+N or N cycles on M33?** The Aioanei thesis claims N. Our
   starting model uses 1+N (conservative). Must validate with DWT CYCCNT.

2. **LDRD/STRD: 3 or 2 cycles?** Same source claims improvement. Validate.

3. **Taken branch penalty: 1 or 2 cycles?** Depends on speculative fetch
   success. Model as 2, validate.

4. **IT instruction folding**: Can the IT instruction execute in 0 cycles
   when preceded by a 16-bit instruction? M3/M4 can fold IT. Not confirmed
   for M33. Model as 1 cycle, validate.

5. **SDIV/UDIV early termination formula**: Our approximation
   (`2 + (32 - leading_zeros) / 3`) is a guess. Need real measurements
   across the full input range.

6. **Unaligned access**: M33 supports unaligned word/halfword access (unlike
   M0+). Do unaligned accesses cost extra cycles? Probably not to SRAM (single
   bank), but cross-bank unaligned accesses might. Validate.
