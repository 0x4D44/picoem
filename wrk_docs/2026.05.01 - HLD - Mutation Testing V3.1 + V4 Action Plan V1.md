## 3. Thread 1 — VCVT.F16.F32 subnormal-rounding corpus

### 3.1 Mutation targets

V2.1 deep-pass + V3 Stream B classified these as Bucket 1 candidates (real test gap, corpus extension owed):

| Line | Mutation | Survives because... |
|---|---|---|
| 1534 | `mantissa & 1` → `mantissa & 0` etc. (lsb computation in subnormal branch) | Few inputs reach the subnormal branch with non-trivial lsb. |
| 1536 | `if round_bit != 0 && (sticky \|\| lsb != 0)` → `==` | The round-trigger condition rarely fires in random fuzz at the subnormal range. |
| 1553 | `(frac & 0xFFF) != 0` (sticky in normal branch) | Random fuzz rarely lands on f32 with `frac & 0xFFF == 0` exactly, so the mutated condition (XOR with constant) produces the same bool most of the time. |
| 1554 | `mantissa & 1` (lsb in normal branch) | Similar — round-half-to-even paths under-exercised. |
| 1563 | `if rounded > 0x3FF` → `>=` | `rounded == 0x3FF` boundary is rarely hit. |

### 3.2 Approach

Generate **deterministic** edge-case cases with carefully chosen mantissa patterns at the round_bit / sticky / lsb positions, then sweep these once per FPSCR mode. Continue using the random fuzz path on top.

**Subnormal targets** (8 exponents × 8 mantissa patterns per shift = 64 cases):

For each `e ∈ [-24, -15]` (8 values):
- For each `(round_bit, sticky_bits, lsb_bit)` ∈ {0, 1}³ (8 combos):
  - Build `m = (1 << 23) | (round_bit << (shift - 1)) | sticky_bits | (lsb_bit << shift)` where `shift = -e - 1`
  - Build f32 from sign=0, biased_exp=(e+127), mantissa=lower 23 bits of (m & 0x7F_FFFF)

Total: 8 × 8 = 64 deterministic subnormal cases. Mirror with sign=1 → 128.

**Normal-branch round-to-`0x3FF` boundary cases** (~16):

For each rounding mode, generate f32 inputs where `frac >> 13 == 0x3FE` (just below max mantissa) and `(frac >> 12) & 1 == 1` (round bit set), with sticky on/off and lsb on/off. Plus inputs where `frac >> 13 == 0x3FF` directly with various sticky.

**Normal-branch sticky/lsb variation** (~16):

For typical f32 in normal range (e ∈ [-14, 15]), sweep `frac & 0xFFF` ∈ {0x000, 0x800, 0xFFF} × `(frac >> 12) & 1` ∈ {0, 1} × `mantissa & 1` ∈ {0, 1}.

**Total**: ~160 deterministic targeted cases.

### 3.3 Wiring

Add `subnormal_rounding_edge_cases() -> Vec<f32>` near `half_edge_cases_f32()`. Extend the edge-case run path (None branch) to call both. For the fuzz path (Some(count)), prepend the deterministic sweep before the random loop so even short fuzz runs exercise the corner.

Re-run cargo-mutants scoped to `crates/mdrp2350/src/core/execute_fpu.rs` (using a `.cargo/mutants_v31_fpu.toml` config). Expect:

- 5 Bucket 1 candidates flip from missed → caught.

## 4. Thread 2 — softfloat_diff op-coverage extension

### 4.1 Op-by-op design

| Op | Operands | Reference impl | Encoder needed? | Notes |
|---|---|---|---|---|
| **VABS** | 1 (Sm → Sd) | `f32::abs` (clears sign bit) | Yes (`enc_vabs`) | Trivial. |
| **VNEG** | 1 | flip sign bit | Yes | Trivial. |
| **VMINNM** | 2 | IEEE 754-2008 minNum: NaN propagation rule + `-0/+0` sign rule | Yes | Compare against `fpu_minnum` source. |
| **VMAXNM** | 2 | IEEE 754-2008 maxNum: same rules | Yes | |
| **VCMP** | 2 (Sn vs Sm, writes FPSCR N/Z/C/V) | Standard f32 ordering + IOC for SNaN (VCMPE) / QNaN-quiet for VCMP | Yes (`enc_vcmp`, `enc_vcmpe`) | Tricky — output is FPSCR flags, not Sd. Refactor `run_single` slightly OR add a separate `run_one_vcmp` to keep `Op` enum f32-output-shaped. |
| **VCVT to U32** (rmode + rtz) | 1 (Sm → Sd reinterpreted as u32 bits) | round-then-saturate-to-u32 with FPSCR.RMode | Yes | |
| **VCVT to I32** (rmode + rtz) | 1 (Sm → Sd reinterpreted as i32 bits) | round-then-saturate-to-i32 | Yes | |
| **VSEL** | 3 (cond from FPSCR, Sn, Sm → Sd) | `if vsel_condition_holds(cond, fpscr) { Sn } else { Sm }` | Yes (`enc_vsel`) | Cond field encodes 4 variants (EQ, VS, GE, GT). Operands trivially propagate. |

### 4.2 Implementation strategy

**Smallest first.** Order: VABS → VNEG → VMINNM → VMAXNM → VCMP → VCVT → VSEL. Each lands as one commit so the journal can record per-op kill-rate deltas if I have time.

**Reuse `Op` enum where possible.** VABS/VNEG/VMINNM/VMAXNM all fit the existing `run_single` shape (f32 in, f32 out + FPSCR flags). Add Op variants and dispatch arms in `run_fpu`.

**Separate runners for VCMP / VSEL / VCVT-to-int.** Output type isn't f32:
- VCMP: writes FPSCR.NZCV; no Sd output. Add `run_vcmp_one` mirroring `run_one_half`'s shape.
- VCVT to int: output is i32/u32 reinterpreted as f32 bits. Could fold into Op enum if reference is shaped right, OR keep separate. Try Op enum first.
- VSEL: 3 operands. Add Op variant with arity-3.

**Reference impl source**: for IEEE-754 operations, prefer host f32 + manual FPSCR-flag derivation (matching mdrp2350's helpers in `execute_fpu.rs`). Avoid pulling in extra dependencies. The `ieee754_ref` module in `softfloat_diff.rs` already follows this pattern.
