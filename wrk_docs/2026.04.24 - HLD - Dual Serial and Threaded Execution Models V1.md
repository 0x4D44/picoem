# HLD — Dual Serial and Threaded Execution Models

**Date:** 2026-04-24
**Version:** V1 (revised after review; supersedes V1 draft of earlier today)
**Scope:** Both RP2350 and RP2040 emulators
**Status:** Draft — pending final review

## 1. Motivation

Threading and serial interleaving have different fixed overheads. Threading pays
for `SpinBarrier` sync, cross-core atomics, and SPSC queue traffic every
quantum. Serial pays for per-instruction core-switching and forgoes concurrent
execution entirely. Neither model dominates every workload.

**Measured crossover (anchor).** On OneROM CPU-mode (a real production workload),
Serial is faster than Threaded today on RP2350. The two models diverge on
real code we care about — the runtime selector is not a hypothesis.

The design goal is to let a caller — bench, app, harness — pick the model per
`Emulator` instance, from one binary, without rebuilding.

## 2. Goals

1. **Runtime selection**, not compile-time. Benchmarks A/B both models without a
   rebuild.
2. **Both chips**, same builder API. Cross-chip benchmarks are apples-to-apples.
3. **Serial stays primary / default.** It is the oracle-validated reference
   (QEMU + silicon differentials). Threaded is opt-in.
4. **Finish RP2350 threading re-alignment** deferred at the 2026-04-19 merge.
   The `threaded/` tree references CortexM33 fields and a generic step
   signature that main no longer has — prerequisite for everything else.
5. **Curated functional-test parity** on both models, not blanket
   parametrization. Scheduler-level testing, not whole-CPU-twice.

## 3. Non-goals

- Making threaded the default.
- Running `qemu_diff_*` / `probe_diff_*` / `silicon_*_diff_*` through threaded.
  Those single-step; threading is a throughput optimization.
- Modelling RP2040 bank contention in the threaded path. Contention cycles are
  virtual; silicon perf gap dwarfs accuracy gain (`tech_debt.md:195`).
- Cross-platform threading. Current `cfg(x86_64+windows)` gate stays.
- Promoting primitives to `mdpicoem-common` as a bulk refactor. See §6.4 for a
  narrow, in-flight extraction of `SpinBarrier` + SPSC when Stage 3 duplicates
  them.

## 5. Design — Runtime selector

### 5.1 Builder API (both chips, identical shape)

```rust
pub enum ExecutionModel {
    Serial,
    Threaded,
}

impl EmulatorBuilder {
    pub fn execution(mut self, model: ExecutionModel) -> Self { ... }
}

// Default: ExecutionModel::Serial
```

### 5.2 Construction and dispatch

`build()` returns `Result<Emulator, ConfigError>`:

- `Serial` always succeeds.
- `Threaded` succeeds on x86_64/Windows with the `threading` feature on.
- `Threaded` otherwise → `Err(ConfigError::ThreadingUnavailable)`. Not a panic
  — callers fall back explicitly.

Internal dispatch: **enum variants on `Emulator`'s inner field**, not a trait
object:

```rust
enum Inner {
    Serial(SerialState),
    Threaded(ThreadedEmulator),
}

pub struct Emulator { inner: Inner, /* shared immutable config */ }
```

Rationale: `Emulator` has exactly two variants forever, `Box<dyn EmuModel>`
adds allocation + indirection with no benefit, and `match` is clearer. This
is a clarity argument, not a perf argument — vtable cost is noise next to
per-step execution.

### 5.3 Feature flag

`threading` feature in `crates/mdrp2350/Cargo.toml` and
`crates/mdrp2040/Cargo.toml`. **Default: on.** Off-platform, the feature
compiles but `Threaded` selection fails at `build()` time — serial still
compiles portably.

### 5.4 Public API parity table

The two variants must present identical public surfaces for the methods
below. Divergence handling is explicit — Threaded-incompatible operations
return `Err(EmulatorError::NotSupportedInThreadedMode)`, not panic.

| Method | Serial | Threaded | Notes |
|---|---|---|---|
| `step() -> u64` | ✓ | `Err` | Threaded runs in quanta, not single-step. Single-stepping from outside a worker would require pausing threads and re-entering which defeats threading. |
| `run(cycles: u64)` | ✓ | ✓ | Threaded rounds up to nearest quantum boundary. |
| `run_quantum()` or similar | ✓ | ✓ | Primary threaded entry; Serial exposes for symmetry. |
| `load_bootrom` / `load_flash` / `load_image` | ✓ | ✓ | Construction-time only; no worker interaction. |
| `gpio_get(pin)` | ✓ | ✓ | Threaded reads `AtomicGpio`. |
| `gpio_set(pin, v)` | ✓ | ✓ (from outside run) | Threaded: only legal between quanta. Inside a quantum panics; guard with debug_assert. |
| `cores()[n].read_register(r)` | ✓ | ✓ (paused) | Threaded requires at-barrier or post-quantum; else returns stale. Documented. |
| `bus()` accessor | ✓ | ✗ | Threaded has no single `Bus`. Harnesses that poke MMIO directly must use typed accessors (`peripherals_mut`, `sio_mut`) that work on both paths. |

Stage 1b converts any `Emulator::bus()` consumers in harnesses to typed
accessors.

### 5.5 Panic containment in threaded workers

Worker threads execute inside `std::panic::catch_unwind`. On a caught panic:

1. Worker sets `SharedState::poisoned` atomic.
2. Worker releases its barrier slot with a `BarrierResult::Poisoned` variant
   (already present — `threaded/barrier.rs:389`).
3. Coordinator observes `Poisoned` at next barrier rendezvous, stops all
   workers, joins handles.
4. `Emulator::run`/`run_quantum` returns `Err(EmulatorError::WorkerPanicked {
   which, message })`.
5. Further calls on the `Emulator` return the same error; it is one-shot
   after a panic.

This supersedes the current silent-deadlock behaviour. Combined with Stage 5's
`SpinBarrier` watchdog, a stalled worker becomes a recoverable error.

stage is not closed.

## 7. Testing strategy

### 7.1 Curated dual-model smoke set

Per chip (Stages 2 + 4): ~20–30 tests in `tests/dual_model.rs`. Each test
is a function that takes `ExecutionModel` as a parameter and runs the
same assertion block on both. The bulk of `crates/mdrp2350/src/tests.rs`
and `crates/mdrp2040/src/tests.rs` stays single-model — they test CPU
execute/decode semantics, which is shared between paths. We are testing
the **scheduler**, not the CPU twice.

Inclusion criteria (one or more applies):
- Exercises cross-core observable ordering (FIFO, spinlock, IRQ).
- Touches shared-bus peripheral state from both cores.
- End-state depends on both cores completing work.

Exclusion criteria (any one applies):
- Asserts exact cycle counts.
- Asserts bank-contention +1 behaviour.
- Asserts exception-entry stacked-frame layout.
- Compares against QEMU or silicon.
- Depends on per-instruction interleave ordering.

### 7.2 Threaded correctness oracle — Serial end-state differential

Threaded drops qemu_diff / probe_diff / silicon_diff oracles by §3. The
compensating control: **Serial acts as the reference for Threaded.** Every
dual-model test is implicitly a differential — `assert_eq!(serial_result,
threaded_result)` wrapping whatever the body asserts. Workloads that
produce scheduler-dependent non-determinism (e.g., race on FIFO winner)
assert only eventually-consistent properties.

This is the ONLY correctness oracle for the threaded path. That is
acceptable because the CPU execute semantics are oracle-validated in
Serial; only the scheduler is novel.

### 7.3 Benchmark statistical methodology

`paced_bench_*` A/B mode runs each workload N≥5 times per model. Report
median MHz, IQR, and inter-model delta as `(median_threaded -
median_serial) / median_serial`. A winner is declared only if the delta
magnitude exceeds `max(3 × IQR / median_serial, 5%)`. Anything inside
the noise floor is reported as "tied." Wall-clock values include a
"machine idle at start" precondition (Arthur's judgement whether a run
is valid).

Rationale: Windows scheduler jitter easily produces ±3–5% per-run
variation; one-shot numbers are not diagnostic.

## 8. Risks

1. **Stage 1a may reveal scope >16h.** Explicit escalation path; see §6.1.
2. **Worker panics deadlock without §5.5 and Stage 5.** Mitigated by
   landing §5.5 in Stage 1b (panic containment) and Stage 5 (watchdog).
3. **Test determinism under threading.** Two workers racing a FIFO can
   produce different winners across runs. Dual-model tests must assert
   only eventually-consistent properties — enforced by review, not by
   type system.
4. **Benchmark noise masks small deltas.** §7.3 methodology mitigates;
   success criteria require N=5 reps.
5. **Contention-model interaction in functional tests.** A test that
   passes Serial because a +1 cycle delay resolves a race may fail
   Threaded. Mitigated by curation — tests that depend on timing are
   excluded from dual-model set.
6. **RP2040 threaded may not cross over.** Stage 4 has explicit
   delete-if-no-crossover path. Sunk cost: ~2 days of Stage 3 work + the
   common-crate extraction (which stays valuable for RP2350 alone).
7. **Platform gating drift.** Feature-gate + platform-`cfg`-gate layered
   on same module. One comment block in `mod.rs` documents both; review
   checklist enforces both gates must be `true` for Threaded variant to
   compile.
8. **`Emulator::bus()` consumers.** Harnesses calling `bus()` directly
   break the Threaded variant. Stage 1b audits and migrates to typed
   accessors; new code must not add `bus()` call sites.

## 9. Explicit non-decisions

- We do **not** pick a winner model. Workload-dependent.
- We do **not** delete the serial path. Ever.
- We do **not** change the default model. Default stays Serial.
- We do **not** run silicon oracles through threaded.
- We do **not** model bank contention in the threaded path.
- We do **not** bulk-migrate primitives to `mdpicoem-common`. Only
  `SpinBarrier` + SPSC move, and only at Stage 3 when RP2040 would
  otherwise duplicate them.

## 10. Rollback plan

Each stage is independently shippable to a sensible stopping point:

- **Stage 1a alone** — deliverable is the scope report; no code changes.
  If we stop here, nothing to roll back.
- **Stage 1b alone** — RP2350 has both models + selector + validated
  harness binaries. Useful in its own right. Rollback = revert the stage
  commits.
- **Stage 2 alone** — RP2350 A/B benchmark + test parity. Self-contained.
- **Stage 3 without 4** — RP2040 threaded exists but unvalidated. Do not
  ship; Stage 4 is strict prerequisite.
- **Stage 4 verdict = delete** — expected rollback path if no crossover.
  The RP2040 threaded tree goes; common-crate primitives stay; Stage 3
  is not a total loss (RP2350 keeps its cleaned-up primitives).

Commits are atomic per stage so `git revert <stage-commit>` works.
