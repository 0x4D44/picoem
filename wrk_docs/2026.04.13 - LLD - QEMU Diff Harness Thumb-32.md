# QEMU Differential Test Harness — Thumb-32 Extension

Version: 1.1.0
Date: 2026-04-13
Parent: QEMU Diff Harness V3 (Phase B)

## 1. Purpose

Extend the differential test harness from Thumb-16 (Phase A, 382 tests) to
cover Thumb-32 instructions. Same architecture: raw opcode bytes fed to both
QEMU and our emulator, single-step, diff post-state.

This document covers only what changes. The V3 LLD remains the reference for
the overall harness design (QEMU setup, GDB client, address constants,
comparison strategy, error recovery).

### Prerequisites (all met)

| Item | Location |
|------|----------|
| `execute_one_wide(hw0, hw1)` | `core/mod.rs:107` |
| `execute_one_wide_with_bus(hw0, hw1, bus)` | `core/mod.rs:116` |
| Thumb-32 decoder + executor | `core/decode.rs`, `core/execute_thumb32.rs`, `core/execute_fpu.rs` |

### Scope

All Thumb-32 integer, DSP, and branch instructions. FPU deferred (Section 9).


## 2. TestCase Changes

Two new fields, both with zero-cost defaults:

```rust
pub struct TestCase {
    // ... all existing fields unchanged ...

    /// Second halfword for Thumb-32 instructions. None = Thumb-16.
    pub hw1: Option<u16>,

    /// BL sets LR to a per-side absolute return address.
    /// When true, compare LR as delta from test slot.
    pub modifies_lr: bool,
}
```

`Default` gives `hw1: None, modifies_lr: false`. All 382 existing Thumb-16
tests compile and behave identically.

### Why `Option<u16>` not `u32`

The emulator API takes `(hw0: u16, hw1: u16)`. An `Option` maps directly to
that call boundary without unpacking. It also lets any consumer branch on
width with a single `match`.

### Why `modifies_lr` not auto-detection

BL writes `LR = return_addr | 1`. The return address is absolute and differs
per side, so absolute comparison fails. Delta comparison fixes BL but breaks
non-BL tests: both sides initialise LR to the sentinel `0xFFFF_FFFF`, and
delta-from-slot produces different values for different slot bases. An explicit
flag is one bit of state vs. fragile heuristics.


## 3. Runner Changes

### 3.1. QEMU side — instruction write

Currently writes 2 bytes (instruction) + 2 bytes (BKPT). For wide:

```rust
gdb.write_mem(QEMU_TEST_SLOT, &tc.opcode.to_le_bytes())?;
match tc.hw1 {
    None => {
        gdb.write_mem(QEMU_TEST_SLOT + 2, &BKPT_BYTES)?;
    }
    Some(hw1) => {
        gdb.write_mem(QEMU_TEST_SLOT + 2, &hw1.to_le_bytes())?;
        gdb.write_mem(QEMU_TEST_SLOT + 4, &BKPT_BYTES)?;
    }
}
```

Register setup, memory preconditions, step, and readback are unchanged.

### 3.2. Emulator side — execution dispatch

```rust
match tc.hw1 {
    None => if tc.needs_bus {
        core.execute_one_with_bus(tc.opcode, shared_bus);
    } else {
        core.execute_one(tc.opcode);
    },
    Some(hw1) => if tc.needs_bus {
        core.execute_one_wide_with_bus(tc.opcode, hw1, shared_bus);
    } else {
        core.execute_one_wide(tc.opcode, hw1);
    },
}
```

### 3.3. Fuzz failure output

Currently prints `opcode: {:#06x}`. For wide instructions, also print hw1:

```
[FAIL] FUZZ:DP_MOD:42 ADDS.W R3,R5,#0x1F
  hw0: 0xf115  hw1: 0x031f  xpsr_pre: 0x01000000  ...
```


## 4. Compare Changes

### 4.1. LR comparison

Replace absolute comparison with conditional delta:

```rust
if tc.modifies_lr {
    let qemu_lr = qemu.regs[14] & !1u32;  // strip Thumb bit
    let emu_lr  = emu.regs[14] & !1u32;
    let qemu_delta = qemu_lr.wrapping_sub(QEMU_TEST_SLOT);
    let emu_delta  = emu_lr.wrapping_sub(EMU_TEST_SLOT);
    if qemu_delta != emu_delta { /* report */ }
} else {
    if qemu.regs[14] != emu.regs[14] { /* report */ }
}
```

### 4.2. Everything else unchanged

PC delta, SP delta, R0-R12 absolute, xPSR masked, memory byte-by-byte — all
work for Thumb-32 without modification.


## 5. New xPSR Masks

```rust
/// N, Z, C, V, Q + GE[3:0] — for DSP parallel add/sub and SEL.
pub const MASK_ALL_FLAGS_GE: u32 = 0xF80F_0000;

/// Q flag only — for saturation (SSAT, USAT, QADD, etc.).
/// Q is sticky: test both 0→1 transition and 1→1 persistence.
pub const MASK_Q_ONLY: u32 = 0x0800_0000;
```

QEMU's xPSR read includes GE flags at bits [19:16]. No GDB client changes.


## 6. Encoding Helpers

### Design principle

One encoder per shared bit layout. Thumb-32 has ~5 major formats covering 60+
mnemonics. Per-mnemonic encoders would be 60+ functions differing by one
constant — the constant is a parameter instead.

All encoders return `(u16, u16)` matching the emulator's `(hw0, hw1)` API.

### 6.1. Data processing — modified immediate

Covers AND, BIC, ORR, ORN, EOR, ADD, ADC, SBC, SUB, RSB and their flag-only
variants (TST, TEQ, CMP, CMN, MOV, MVN when Rd=0xF or Rn=0xF).

```
hw0: 11110_i_0_op[3:0]_S_Rn[3:0]
hw1: 0_imm3_Rd[3:0]_imm8
imm12 = i : imm3 : imm8
```

```rust
fn enc_t32_dp_mod_imm(op: u16, s: bool, rn: u16, rd: u16, imm12: u16) -> (u16, u16)
```

Op constants: AND=0, BIC=1, ORR=2, ORN=3, EOR=4, ADD=8, ADC=10, SBC=11,
SUB=13, RSB=14.

### 6.2. Data processing — shifted register

Same ALU ops but Rm with barrel shift. Rn=0xF → standalone shift (MOV.W etc).

```
hw0: 11101_01_op[3:0]_S_Rn[3:0]
hw1: 0_imm3_Rd[3:0]_imm2_type[1:0]_Rm[3:0]
shift_amount = imm3 : imm2
```

```rust
fn enc_t32_dp_shift_reg(
    op: u16, s: bool, rn: u16, rd: u16,
    rm: u16, stype: u16, samount: u16,
) -> (u16, u16)
```

### 6.3. Data processing — plain binary immediate

These differ enough to warrant individual encoders:

```rust
fn enc_t32_movw(rd: u16, imm16: u16) -> (u16, u16)   // imm4:i:imm3:imm8
fn enc_t32_movt(rd: u16, imm16: u16) -> (u16, u16)
fn enc_t32_addw(rd: u16, rn: u16, imm12: u16) -> (u16, u16)
fn enc_t32_subw(rd: u16, rn: u16, imm12: u16) -> (u16, u16)
fn enc_t32_bfi(rd: u16, rn: u16, lsb: u16, width: u16) -> (u16, u16)
fn enc_t32_bfc(rd: u16, lsb: u16, width: u16) -> (u16, u16)
fn enc_t32_sbfx(rd: u16, rn: u16, lsb: u16, width: u16) -> (u16, u16)
fn enc_t32_ubfx(rd: u16, rn: u16, lsb: u16, width: u16) -> (u16, u16)
fn enc_t32_ssat(rd: u16, rn: u16, sat: u16, stype: u16, samount: u16) -> (u16, u16)
fn enc_t32_usat(rd: u16, rn: u16, sat: u16, stype: u16, samount: u16) -> (u16, u16)
```

### 6.4. Load/store single

Three addressing modes share an outer format. Size param selects byte/half/word
and signed variants.

```rust
fn enc_t32_ls_imm12(size: u16, load: bool, rn: u16, rt: u16, imm12: u16) -> (u16, u16)
fn enc_t32_ls_imm8(size: u16, load: bool, rn: u16, rt: u16, p: bool, u: bool, w: bool, imm8: u16) -> (u16, u16)
fn enc_t32_ls_reg(size: u16, load: bool, rn: u16, rt: u16, rm: u16, shift: u16) -> (u16, u16)
```

Size: 00=byte, 01=half, 10=word. Signed loads use a different opcode bit — the
encoder handles this via an additional `signed: bool` or a combined size enum.

### 6.5. Load/store multiple and dual

```rust
fn enc_t32_ldm(rn: u16, w: bool, db: bool, reglist: u16) -> (u16, u16)
fn enc_t32_stm(rn: u16, w: bool, db: bool, reglist: u16) -> (u16, u16)
fn enc_t32_ldrd(rt: u16, rt2: u16, rn: u16, p: bool, u: bool, w: bool, imm8: u16) -> (u16, u16)
fn enc_t32_strd(rt: u16, rt2: u16, rn: u16, p: bool, u: bool, w: bool, imm8: u16) -> (u16, u16)
fn enc_t32_tbb(rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_tbh(rn: u16, rm: u16) -> (u16, u16)
```

### 6.6. Multiply / divide

```rust
fn enc_t32_mul(rd: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_mla(rd: u16, rn: u16, rm: u16, ra: u16) -> (u16, u16)
fn enc_t32_mls(rd: u16, rn: u16, rm: u16, ra: u16) -> (u16, u16)
fn enc_t32_smull(rdlo: u16, rdhi: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_umull(rdlo: u16, rdhi: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_smlal(rdlo: u16, rdhi: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_umlal(rdlo: u16, rdhi: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_sdiv(rd: u16, rn: u16, rm: u16) -> (u16, u16)
fn enc_t32_udiv(rd: u16, rn: u16, rm: u16) -> (u16, u16)
```

DSP multiply variants (SMLABB, SMULBB, SMLAD, etc.) share a format —
one parameterised encoder with op/M/N bits.

### 6.7. Branches

```rust
fn enc_t32_b_cond(cond: u16, offset: i32) -> (u16, u16)    // T3: 21-bit signed
fn enc_t32_b_uncond(offset: i32) -> (u16, u16)              // T4: 25-bit signed
fn enc_t32_bl(offset: i32) -> (u16, u16)                    // 25-bit, I1=NOT(J1^S)
```

The offset is in bytes, must be even. The encoder computes S, J1, J2, imm10,
imm11 from the signed offset. This is the trickiest encoder — the J1/J2 XOR
trick for T4/BL differs from T3's direct encoding. Unit-test these encoders
against known good values from `arm-none-eabi-objdump`.

### 6.8. Miscellaneous

```rust
fn enc_t32_msr(rn: u16, sysm: u16) -> (u16, u16)
fn enc_t32_mrs(rd: u16, sysm: u16) -> (u16, u16)
fn enc_t32_clz(rd: u16, rm: u16) -> (u16, u16)
fn enc_t32_rbit(rd: u16, rm: u16) -> (u16, u16)
// etc. — small standalone encoders for utility instructions
```


## 7. Test Generators — Prioritised by Bug Risk

One generator function per instruction group, returning `Vec<TestCase>`.
Wired into `generate_all()` via a new module (Section 10).

### Priority 1 — Complex encoding or semantics, most likely to harbour bugs

**7.1. `gen_t32_dp_mod_imm()`** — ~80 tests

ThumbExpandImm has 5 sub-modes. This is the most likely place for encoding or
semantic bugs.

- Each ThumbExpandImm mode: plain byte (imm12[11:10]=00, [9:8]=00), byte-
  replicated ×2, ×3, ×4, and rotated (imm12[11:10]≠00)
- Carry-out from rotation (S=1, verify C flag)
- All 10 ALU ops with S=1 and interesting operands (zero, MAX, MIN, carry
  boundary, overflow boundary)
- Flag-only variants: TST (Rd=0xF), CMP (Rd=0xF), CMN, TEQ
- No-source variants: MOV.W (Rn=0xF), MVN.W (Rn=0xF)

**7.2. `gen_t32_load_store_single()`** — ~60 tests

Three addressing modes × 3 sizes × signed/unsigned. Focus on the P/U/W
matrix:

- imm12 positive offset: basic loads and stores (byte, half, word)
- imm8 with P=1, U=1, W=0 (positive offset, no writeback)
- imm8 with P=1, U=0, W=0 (negative offset)
- Pre-index writeback: P=1, W=1 (verify base register updated)
- Post-index: P=0, W=1 (verify base register updated *after* access)
- Register offset with LSL shift
- Signed loads (LDRSB, LDRSH) — verify sign extension
- PC-relative (Rn=0xF) — verify Align(PC,4) base
- Byte-at-address-boundary cases (alignment)

**7.3. `gen_t32_multiply_divide()`** — ~40 tests

- MUL, MLA, MLS with edge values (0, 1, -1, MAX, MIN)
- SMULL, UMULL: verify both RdLo and RdHi for large products
- SMLAL, UMLAL: verify 64-bit accumulate
- SDIV, UDIV: normal division, round-toward-zero, divide by zero → 0
- Signed overflow: INT32_MIN / -1 (SDIV should return INT32_MIN)

### Priority 2 — Well-defined semantics, moderate risk

**7.4. `gen_t32_branch()`** — ~30 tests

- B.W conditional: each condition code (EQ/NE/CS/CC/MI/PL/VS/VC/HI/LS/GE/LT/
  GT/LE), both taken and not-taken
- B.W unconditional: small positive, small negative, large offset
- BL: verify LR = (slot + 4) | 1, verify PC = slot + offset
  (set `modifies_lr: true`)
- Offset sign extension: maximum positive and negative offsets

**7.5. `gen_t32_dp_shift_reg()`** — ~50 tests

- Each ALU op with LSL #0, LSR #1, ASR #31, ROR #16
- RRX (type=ROR, amount=0): verify carry-in rotated to bit 31
- Carry-out from shift when S=1
- Rn=0xF special forms: MOV.W Rd, Rm, LSL #n (standalone shift)

**7.6. `gen_t32_ldm_stm()`** — ~20 tests

- STMIA.W / LDMIA.W with writeback, register lists including R8+
- STMDB.W / LDMDB.W (decrement-before)
- Small list (1 register) and large list (8+ registers)
- Verify memory contents and writeback value

**7.7. `gen_t32_ldrd_strd()`** — ~20 tests

- LDRD/STRD offset (P=1, U=1/0, W=0)
- LDRD/STRD pre-index (P=1, W=1) and post-index (P=0, W=1)
- Verify both Rt and Rt2

**7.8. `gen_t32_tbb_tbh()`** — ~10 tests

Table branch: set up table entries in scratch memory, step, verify PC. The
branch target = PC + 2 × table[index]. Needs `needs_bus: true`.

### Priority 3 — Narrow coverage or lower risk

**7.9. `gen_t32_dp_plain_imm()`** — ~30 tests

- MOVW: full 16-bit range, verify zero-extension to 32 bits
- MOVT: verify only upper 16 bits change, lower preserved
- ADDW, SUBW: 12-bit immediate, no flag update
- BFI: insert at LSB=0, LSB=16, width=1, width=32
- BFC: clear at various positions
- SBFX, UBFX: signed vs unsigned extraction

**7.10. `gen_t32_dsp()`** — ~40 tests

- SSAT, USAT: test Q flag set on saturation, no-op when in range
- QADD, QSUB, QDADD, QDSUB: saturating arithmetic with Q flag
- Parallel add/sub (SADD16, UADD8, etc.): verify GE flags
  (use `MASK_ALL_FLAGS_GE`)
- SEL: verify it reads GE flags correctly (set GE via parallel op, then SEL)
- Halfword multiply (SMLABB, SMULBB, etc.)

**7.11. `gen_t32_dp_register()`** — ~30 tests

- CLZ: 0→32, 1→31, 0x80000000→0
- RBIT: known patterns (0x01→0x80000000)
- REV.W, REV16.W, REVSH.W: byte reversal
- Wide register shifts: LSL.W Rd, Rn, Rm (shift by Rm[7:0])
- Extend-add: SXTAB, UXTAB, SXTAH, UXTAH with rotation

**7.12. `gen_t32_misc_control()`** — ~15 tests

- MSR/MRS: write PRIMASK, BASEPRI, FAULTMASK, read back
- NOP.W, DMB, DSB, ISB: verify no state change (trivial pass)

### Not tested

| Instruction | Reason |
|-------------|--------|
| FPU (VADD, VLDR, etc.) | Needs GDB FPU register indices (Section 9) |
| WFI.W, WFE.W | QEMU halts; single-step may hang |
| Coprocessor | Stubs only; not real hardware on RP2350 |

### Estimated totals

~425 targeted tests. With fuzz generators, expect 2000-3000 additional.


## 8. IT Block Testing — Deferred

The emulator supports IT blocks (Stages 10-11), but the single-step test
model cannot exercise them.

### Why it doesn't work

The obvious approach — set ITSTATE bits in `xpsr_pre` — fails on both sides:

- **Emulator:** `it_state` is a separate `u8` field on `CortexM33`, not
  derived from xPSR. `run_one_emu` writes `core.regs.xpsr = tc.xpsr_pre` but
  `it_state` stays at zero. The ITSTATE bits in xPSR are dead storage.
- **QEMU:** The M-profile GDB stub omits EPSR.T (bit 24) from reads and almost
  certainly ignores ITSTATE bits [26:25]/[15:10] on writes. This matches the
  ARM architecture's treatment of ITSTATE as execution state, not directly
  writable.

### What would be needed

A multi-step test model: execute an `IT` instruction (Thumb-16) to set the
condition, then step the target Thumb-32 instruction. This requires:

1. Writing two instructions to the test slot (IT + target + BKPT)
2. Stepping twice (or running to BKPT)
3. On the emulator side, calling `execute_one()` for IT then
   `execute_one_wide()` for the target

This is a different execution model from the current single-step harness.
Defer to a future phase.


## 9. Scratch Area — Grow for Thumb-32 Offsets

### Problem

The current 256-byte scratch area (zeroed per test) is too small for Thumb-32
addressing modes:

| Instruction | Max offset from base | Current scratch |
|-------------|---------------------|-----------------|
| Thumb-16 LDR (imm5×4) | 124 bytes | 256 ✓ |
| LDRD/STRD (imm8×4) | 1020 bytes | 256 ✗ |
| LDR.W (imm12) | 4095 bytes | 256 ✗ |

Reading beyond the zeroed region is dangerous: emulator SRAM is zero-
initialised, but QEMU's ssram-0 may not be. Unzeroed reads produce different
values → false diffs.

### Fix

Grow scratch from 256 to 1024 bytes. This covers the LDRD/STRD maximum (1020)
with margin. For LDR.W imm12 (up to 4095), constrain generators to offsets
within scratch size — the ALU computes `base + offset` identically for small
and large offsets, so field extraction is validated without needing a 4KB
scratch area.

Define the size as a constant so generators can reference it:

```rust
/// Scratch area size in bytes. Must cover the largest offset any test
/// generator uses. LDRD/STRD max = imm8×4 = 1020.
pub const SCRATCH_SIZE: u32 = 1024;
```

Update the zeroing loops in `run_one_emu` and `run_qemu_side` to use
`SCRATCH_SIZE` instead of hardcoded 256.

### Memory layout (unchanged addresses, larger scratch)

```
0x0000_0000  Vector table (192 bytes)
0x0000_0100  TEST_SLOT (6 bytes: 4-byte instr + 2-byte BKPT)
0x0000_0200  TEST_SCRATCH (1024 bytes, extends to 0x0000_0600)
              ... 260 KB gap ...
0x0004_0000  TEST_STACK
```

No address constants change. The gap to TEST_STACK is still 260KB.


## 10. Branch Offset Constraints

Single-step execution is safe regardless of target address. Both QEMU and the
emulator use `wrapping_add` for PC + offset, and unmapped reads return zero
(no fault). QEMU does not validate branch targets during single-step.

Generators should still constrain offsets to **realistic ranges** (±4KB from
slot) for two reasons:

1. Offsets that land outside SRAM on one side but inside on the other could
   produce different PC-read behavior if the branch target were ever fetched.
   (Doesn't affect single-step, but avoids surprises.)
2. Extremely large offsets don't exercise different logic — the offset
   computation is a single `wrapping_add` regardless of magnitude. Testing
   +0x10 and +0x1000 catches the same bugs as +0x1000000.


## 11. FPU — Deferred to Phase C

FPU instructions (40+ in `execute_fpu.rs`) read/write S0-S31 and FPSCR, which
are outside the current `RunState`.

### What Phase C would require

1. Determine GDB register indices for S0-S31 and FPSCR on QEMU M-profile.
   Indices 16-24 are legacy FPA (return E14 on QEMU 10.2). FPU registers are
   likely at 26+ but the exact layout is version-dependent and needs empirical
   verification.
2. Extend `RunState` with optional FPU fields.
3. Enable CPACCESS (CP10/CP11) in test setup before stepping FPU instructions.
4. FPU encoding helpers and generators.

### Why defer

The GDB index question requires hands-on investigation. Integer Thumb-32 is a
larger surface area and higher priority. FPU bugs will surface through the
existing unit tests (`tests.rs`) until Phase C.

```

```

`lib.rs` adds `pub mod thumb32_gen;` and wires `thumb32_gen::generate_all_t32()`
into `generate_all()`. Thumb-16 generators stay in `lib.rs` — moving them is
churn with no benefit.

Encoding helpers live in `thumb32_gen.rs` alongside the generators that use
them. If the file grows past ~2000 lines, split encoding helpers to
`thumb32_enc.rs`.

## 14. Encoding Verification

Same approach as Thumb-16 (V3 LLD Section 7.4): periodic sanity check with
`arm-none-eabi-objdump`. Especially important for:

- ThumbExpandImm: the 5 sub-modes are easy to get wrong in the encoder
- Branch offsets: J1/J2 XOR trick for BL vs direct encoding for conditional B.W
- LDRD/STRD: the imm8 is shifted left by 2 in the instruction, easy off-by-one

Write `#[test]` functions for encoders that verify known good `(hw0, hw1)`
values against ARM ARM examples.
