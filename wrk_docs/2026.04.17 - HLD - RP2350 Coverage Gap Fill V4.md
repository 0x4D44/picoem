## 1. Problem

The audit surfaced four classes of finite gap. V1 covered three; V2 added the fourth (inert registers inside modelled peripherals); V3 expands the fourth to match the audit §5 list in full:

1. **Silent inert-register reads/writes at unmodelled addresses** — MMIO that doesn't match any peripheral module hits `HashMap<u32, u32>` at `bus/mod.rs:231`.
2. **TICKS `0x81C` alias bug** — failing `ticks_timer0_retarget_halves_rate` silicon scenario.
3. **Interpolator dead storage** — `sio/mod.rs:45`.
4. **Missing peripherals** — roughly a dozen register blocks.
5. **Inert-but-known registers inside modelled peripherals** (expanded in V3): DMA BSWAP, CRC sniffer, DMA HIGH_PRIORITY, PWM DREQs, POWMAN ARCHSEL, **per-peripheral clock-gate enables in CLOCKS, BUSCTRL.BUS_PRIORITY, POWMAN AON-timer MATCH/COUNT writes** (the last three added in V3 per round-2 devil's advocate; COUNT warn added in V4 per round-3 combined reviewer). *Interpolator CTRL registers are NOT in this list — they become live-modelled via Part B, not warn-gated.*

## 2. What is out of scope

- **Security enforcement** (SAU / MPU / ACCESSCTRL actually gating bus accesses) — no HLD written yet; cross-cutting.
- **Cycle-model fixes** — `wrk_docs/2026.04.14 - HLD - Cycle Accounting Short-Circuit.md` and `wrk_docs/2026.04.16 - HLD - Cycle and DualCore Timing Accuracy.md` hold that work; this HLD does not touch the cycle model.
- **Bootrom execution** — no HLD written yet; needs an RP2350 ROM binary and signed-boot policy decisions.
- **RISC-V Hazard3** — `wrk_docs/2026.04.17 - HLD - RP2350 RISC-V Hazard3 Core Support.md` holds that work; separate work programme.
- **USB, HSTX, TMDS** — engineering-week-scale; each gets its own HLD.
- **No migration / back-compat / feature flags / env vars / trait abstractions.** Dev sandbox.
- **Silicon calibration session for interpolator** — §5.B.3 explains; unit tests are the first gate, silicon is the binding oracle when firmware demands it.

## 3. Approach at a glance

Match the existing `peripherals/mod.rs` inherent-methods convention exactly. New peripherals are plain structs, dispatched from match arms on `Bus::read32` / `Bus::write32`. APB aliases route through `apply_alias_rmw`. No trait, no generic abstraction, no new cross-cutting infrastructure beyond two `Bus` fields (warn set and watchdog-reset flag).

## 4. Part A — Inert-register observability

### A.1 Warn-once on HashMap fallthrough

**Change.** One field on `Bus`:

```rust
pub struct Bus {
    // … existing fields …
    warned_addrs: std::collections::HashSet<u32>,
}
```

At every HashMap fallthrough site in `Bus::read32` / `Bus::write32` (`bus/mod.rs:1280`, `:1549`, `:1559`, `:1692`, `:1952`, `:2047`):

```rust
if self.warned_addrs.insert(word_addr) {
    tracing::warn!(
        addr = format_args!("{:#010X}", word_addr),
        "unmodelled MMIO access"
    );
}
```

**Lifetime and concurrency clarifications (new in V3, DA7).**
- `warned_addrs` is per-`Bus` instance. Tests that construct their own `Bus` start with an empty set — there is no cross-test contamination.
- The emulator is single-threaded per `step()` call and the `Bus` is not `Sync`; no `HashSet` locking is needed.

**Dependency.** `tracing` (already workspace-wide). `tracing-subscriber = "0.3"` goes into `crates/mdrp2350/Cargo.toml` under `[dev-dependencies]`.

**Testing.** One unit test writes **twice** to an unmodelled address, captures events via `tracing::subscriber::with_default`, and asserts *exactly one* `WARN` for that address. The "twice" is load-bearing — it proves the warn-once semantic, not just the warn-once-in-theory. Address: `0x400F_8000` (SHA-256 base) until Part D.6 lands, then `0x5000_0100` (USB base, still out of scope).

### A.2 Warn-once convention for modelled-but-inert registers

V3 completes the audit §5 coverage. Each site is a `tracing::warn!` guarded by a small per-site flag local to the containing peripheral module. No shared infrastructure — the convention is six lines per site, duplicated, kept surgical.

| Peripheral / register | Trigger | Backing |
|---|---|---|
| DMA `CHn_CTRL.BSWAP` (bit 22) set | first write-with-bit-set per channel | `[bool; 16]` |
| DMA `SNIFF_CTRL.EN` (bit 0) set | first set | single `bool` |
| DMA `SNIFF_DATA` any write | first write | single `bool` |
| DMA `CHn_CTRL.HIGH_PRIORITY` (bit 1) set | first per channel | `[bool; 16]` |
| PWM `CHn_DMA` DREQ-enable bits | first per slice | `[bool; 12]` |
| POWMAN `ARCHSEL` write away from Arm | first non-Arm value | single `bool` |
| POWMAN AON-timer `MATCH` written | first write | single `bool` *(new in V3, DA8 compromise)* |
| POWMAN AON-timer `COUNT` written | first write | single `bool` *(new in V4, round-3 symmetry fix — COUNT-polling firmware would otherwise hang silently)* |
| CLOCKS per-peripheral gate `ENABLE` bit changes | first clear | single `bool` per affected register |
| BUSCTRL `BUS_PRIORITY` write | first write | single `bool` |

**Why a convention, not a framework.** Ten targeted sites with ten six-line guards is less code than one shared abstraction with registration, and it is easier to audit. If a future review shows the list doubling, revisit then.

**Unit-test pattern (new in V3, testing reviewer).** Each site's test writes twice to the register with the inert bit set, collects `tracing` events, asserts one `WARN` across the two writes. Copy-paste from the A.1 test.

### A.3 TICKS `0x81C` alias bug

Fix: internal offset gate in `ticks.rs` uses `offset & 0x7F` (the stride-relative form already computed) rather than the raw offset. Rust reviewer confirmed the code is one change. Enable the existing `ticks_timer0_retarget_halves_rate` silicon scenario; no new scenario.

## 5. Part B — Interpolator CTRL semantics

### B.1 Struct

Replace `interp: [[u32; 32]; 2]` in `sio/mod.rs:45` with a dedicated struct. Two instances per core.

```rust
// sio/interp.rs
pub struct Interp {
    pub accum:      [u32; 2],
    pub base:       [u32; 3],
    pub ctrl_lane:  [u32; 2],   // OVERF flags in CTRL_LANE0 bits [25:23]
}
```

### B.2 Register map

(Datasheet §2.7. Offsets relative to the interp base — `0x80` for interp0, `0xC0` for interp1, inside the SIO window.)

| Offset | Register   | Notes |
|--------|------------|-------|
| 0x00   | ACCUM0     | RW |
| 0x04   | ACCUM1     | RW |
| 0x08   | BASE0      | RW |
| 0x0C   | BASE1      | RW |
| 0x10   | BASE2      | RW |
| 0x14   | POP_LANE0  | RO, reads compute result *and* update ACCUMn |
| 0x18   | POP_LANE1  | RO, as above |
| 0x1C   | POP_FULL   | RO, as above |
| 0x20   | PEEK_LANE0 | RO, computes result, no side effects |
| 0x24   | PEEK_LANE1 | RO |
| 0x28   | PEEK_FULL  | RO |
| 0x2C   | CTRL_LANE0 | RW; read returns CTRL + OVERF |
| 0x30   | CTRL_LANE1 | RW |
| 0x34   | ACCUM0_ADD | W, ACCUM0 += (value & 0xFFFFFF) |
| 0x38   | ACCUM1_ADD | W |
| 0x3C   | BASE_1AND0 | W, writes low/high 16b to BASE0 / BASE1 |

Dispatch in `sio/mod.rs` (currently at `:107` read, `:148` write): swap the raw-storage arms for `self.interp[core][idx].read(offset_rel)` where `idx = (offset - 0x80) >> 6` and `offset_rel = (offset - 0x80) & 0x3F`.

### B.3 CTRL bit semantics

Per datasheet §2.7, per lane:
- SHIFT [4:0]: right-shift raw input by N.
- MASK_LSB [9:5], MASK_MSB [14:10]: low/high bit retained after shift.
- SIGNED [15]: sign-extend from MASK_MSB.
- CROSS_INPUT [16]: use other lane's ACCUM as this lane's raw input.
- CROSS_RESULT [17]: this lane's result is other lane's arithmetic.
- ADD_RAW [18]: POP updates ACCUM using pre-shift raw input (else shifted-masked).
- FORCE_MSB [20:19]: force bits [31:30] of result.
- BLEND [21], INTERP0 only: lane1 is α-blend fraction over BASE0/BASE1. **ACCUM1 in BLEND mode is interpreted as Q0.32 fixed-point (`0x8000_0000` = 0.5, `0xFFFF_FFFF` ≈ 1.0).** Pin during §9 datasheet check if the RP2350 SIO `interp` §2.7 description says otherwise.
- CLAMP [22], INTERP1 only: lane0 result clamped to [BASE0, BASE1].
- OVERF0/OVERF1/OVERF [25:23]: sticky signed-overflow flags; W1C via CTRL_LANE0.

### B.4 Testing

**Decision (kept from V2):** unit tests from the datasheet, not silicon scenarios. Reviewer round 2 accepted with a caveat: silicon is still the binding oracle — a silicon scenario lands the moment real firmware exposes a divergence.

**Concrete test vectors (new in V3, testing reviewer).** Minimum set — each test is 10–15 lines:

1. **SHIFT only.** `accum0 = 0xAAAA_AAAA`, SHIFT=4, MASK_LSB=0, MASK_MSB=31 → POP_LANE0 = `0x0AAA_AAAA`.
2. **SHIFT + MASK.** same input, SHIFT=4, MASK_LSB=0, MASK_MSB=7 → POP_LANE0 = `0xAA`.
3. **SIGNED sign-extension.** `accum0 = 0x0000_0080`, MASK_MSB=7, SIGNED=1 → POP_LANE0 = `0xFFFF_FF80`.
4. **CROSS_INPUT.** lane1 CTRL has CROSS_INPUT=1; PEEK_LANE1 reads from ACCUM0, not ACCUM1.
5. **ADD_RAW on POP.** POP_LANE0 updates ACCUM0 with BASE0 + raw (not shifted+masked). Verify ACCUM0 after POP.
6. **INTERP0 BLEND.** BASE0=100, BASE1=200, ACCUM1=0x8000_0000 (half) → PEEK_FULL = 150 (α=0.5).
7. **INTERP1 CLAMP.** BASE0=100, BASE1=200, ACCUM0=50 → PEEK_LANE0 clamped to 100; ACCUM0=250 → 200.
8. **CROSS_RESULT.** lane0 CTRL has CROSS_RESULT=1; reading PEEK_LANE0 returns lane1 arithmetic.

Eight tests cover the ten orthogonal CTRL bits with room for composite cases without combinatorial explosion. The devil's advocate round-2 concern that "unit tests are just plumbed-but-tested" is noted and accepted — §2.7 is our binding spec until silicon says otherwise; we reach for silicon the moment real firmware hits a divergence.

## 6. Part C — UART1 / SPI1 / I2C1

### C.1 Layout

`Bus` holds `uart: [Uart; 2]`, `spi: [Spi; 2]`, `i2c: [I2c; 2]`. Each peripheral module hoists the base address out; base is passed at construction along with IRQ/DREQ:

```rust
uart: [
    Uart::new(IRQ_UART0_IRQ, DREQ_UART0_TX, DREQ_UART0_RX),
    Uart::new(IRQ_UART1_IRQ, DREQ_UART1_TX, DREQ_UART1_RX),
],
```

Current `Uart::new` takes `nvic_irq: u32` (see `peripherals/uart.rs:164`); the constructor extends to take two DREQ ids as well. Same pattern for SPI and I2C.

### C.2 Dispatch

Flat match on base:

```rust
match addr & 0xFFFF_F000 {
    UART0_BASE => self.uart[0].read32(addr & 0xFFF),
    UART1_BASE => self.uart[1].read32(addr & 0xFFF),
    // …
}
```

### C.3 Testing

One routing scenario per peripheral type (UART, SPI, I2C) targeting the `_1` instance and proving the address decode. No duplication of `_0` behaviour tests.

## 7. Part D — Simple peripherals

### D.1 Inert cluster (SYSCFG + TBMAN + GLITCH_DETECTOR)

One file `peripherals/inert.rs`, three structs. Storage-only except:
- `GLITCH_DETECTOR.STATUS.ARM` returns 0 on read (no glitch in emulation).
- `GLITCH_DETECTOR.TRIG_STATUS` W1C via `apply_alias_rmw`.

Three bus match arms wire the three base addresses.

### D.2 PSM

Storage for `FRCE_ON`, `FRCE_OFF`, `WDSEL`. `DONE` mirrors `FRCE_ON` (instant handshake; documented limitation — real silicon has per-subsystem ramp latency).

### D.3 WATCHDOG

Countdown driven by TICKS WATCHDOG domain. Registers: `CTRL` (ENABLE, PAUSE_DBG0, PAUSE_DBG1, PAUSE_JTAG, TRIGGER), `LOAD`, `REASON`, `SCRATCH0..7`.

**No `TICK` register on RP2350** — that moved to TICKS. Firmware writes to the RP2040 `WATCHDOG_TICK` offset will hit the HashMap fallthrough, which is correct.

**Reset plumbing.** Add `watchdog_reset_requested: bool` to `Bus`, mirror the `bus_fault` idiom (setter, getter, clearer). CPU `step()` polls it before instruction fetch; if set, reseed state and jump PC to the reset-vector entry. Not per-core — watchdog reset is system-wide.

**Testing split (from round 1):**
- *Unit test, reset-firing:* program `LOAD=100`, `CTRL.ENABLE=1`, step, assert flag fires within 130 cycles (100 countdown + TICKS divider overhead), assert SCRATCH0..7 survive, PC is at reset vector. **Minimum cycles to fire with `LOAD=100` ≤ 130 (new in V3)** — bounded test duration.
- *Silicon scenario, non-firing:* program a large LOAD, enable, 1000-cycle window, verify countdown advanced but did not fire. End-state observable.

### D.4 OTP

16 KB backing store via `OTP_DATA` aperture. OR-only writes (fuse semantics). Reads return stored word. No SBPI, no row-lockout, no READY status (always ready). All intentional simplifications documented.

No fuse-load builder (cut in V2).

### D.5 TRNG

32-bit counter. `RNG_OUT` reads return-and-increment; `STATUS` always ready.

**pico-sdk self-test caveat (new in V3, testing reviewer).** If pico-sdk adds a runtime entropy self-test (e.g., "consecutive reads must differ in the high byte" or similar), a pure counter passes the "differ" test trivially but fails statistical checks. No current pico-sdk code does this; accepted risk.

### D.6 SHA-256

Use the `sha2 = "0.10"` crate. Rationale: hand-coded SHA-256 is its own verification burden and not in scope — the RP2350 block is a 16-word block compressor (firmware handles padding + length), so the `sha2` `compress256` entry point maps cleanly. Registers:

- `CSR` — `START` (W, self-clearing; resets accumulator), `WDATA_READY` (RO), `SUM_VALID` (RO), `ERR_WDATA_NOT_RDY` (RO, W1C).
- `WDATA` — block input; 16 writes per block.
- `SUM0..7` — RO digest.

Unit tests use FIPS-180 Appendix A vectors (empty, "abc", one-million-'a').

## 8. Part E — Medium peripherals

### E.1 POWMAN

Three sub-areas:

1. **AON timer — storage-only.** `COUNT` (64-bit), `MATCH` (64-bit), `STATUS.READY` always 1. No tick advancement. **`tracing::warn!` once on MATCH write** (new in V3) — "POWMAN AON MATCH programmed; emulator does not advance the timer. Firmware relying on AON wake will not fire." **Also warn-once on COUNT write** (new in V4) — "POWMAN AON COUNT written; timer does not advance." The symmetry closes the silent-hang case where firmware writes COUNT then polls it expecting progress.
2. **VREG.** Plain storage.
3. **ARCHSEL.** Plain storage + warn-once on any write changing value to non-Arm (§4.A2 list).

When firmware hits the AON warn in practice, that is the signal to implement clocked advancement — the LPOSC divider lookup becomes justified work at that point.

### E.2 CORESIGHT_TRACE

Storage-only at `0xE004_1000`.

## 10. Landing order

Six steps, each its own commit. Step 3 split in V3 (DA5, testing reviewer).

1. **Part A.1** (warn-once) + **A.3** (TICKS alias). Shared `Bus` field change — wattchdog-reset flag added in the same commit so step 3a doesn't touch `Bus` again. Observability first.
2. **Part C** — UART1/SPI1/I2C1 array reshape.
3a. **Part D.1 inert cluster + D.2 PSM + D.3 WATCHDOG** — small peripherals + watchdog reset path.
3b. **Part D.4 OTP + D.5 TRNG + D.6 SHA-256** — storage, counter, crate-backed hash. Independent of 3a; no shared `Bus` changes.
4. **Part A.2** (inert-register convention across DMA/PWM/CLOCKS/BUSCTRL/POWMAN) + **Part E** (POWMAN + CORESIGHT_TRACE).
5. **Part B** (interpolator) — largest single diff, own review pass.

**Effort estimate (new in V3, testing reviewer).** ~2–3 weeks for a single engineer: step 1 ≈ 1 day, step 2 ≈ 2 days, step 3a ≈ 3 days, step 3b ≈ 3 days, step 4 ≈ 3 days, step 5 ≈ 5–7 days. Plus ≈4 hours for the §9 checklist. Parallel tracks possible (step 2 independent of step 3a once step 1 lands).

## 11. Testing strategy

- **Unit tests** per peripheral — round-trip, reset, side effects.
- **Silicon scenarios** — one per new peripheral that has silicon-observable state at quiescent end-state. Not for interp (§5.B.4). Not for watchdog firing (§7.D.3). One per type only for UART1/SPI1/I2C1 routing (§6.C.3).
- **Warn-trace test** — see §4.A1. Each §4.A2 site has its own twice-writes-one-warn unit test.
- **Noise tolerance.** Between step 1 and step 4, scenario runs emit warns for addresses touched by tests but not yet modelled. Transient by construction — step 4 retires the audit §5 list; steps 3a/3b retire individual addresses. During this window, treat warns as progress markers, not failures. If the CI noise ratio becomes untenable, downgrade A.1 warns to `debug!` temporarily; not proposed now because the landing window is short.

## 12. Risks

- **Datasheet verification (§9)** — if a row surfaces a surprise, amend per §9's amendment gate.
- **Interpolator unit tests without silicon calibration** — first real firmware using blend/clamp/CROSS_* becomes the oracle of last resort.
- **Warn noise during landing** — acknowledged; transient.
- **pico-sdk TRNG self-test** — if landed upstream, the counter-TRNG breaks statistically-aware code. Revisit then.

## 13. What V3 deliberately does not do

- Does not address security enforcement, cycle-model fixes, bootrom execution, RISC-V, USB, HSTX, or TMDS — see §2.
- Does not track PC on `Bus` (cut V1).
- Does not pre-load OTP fuses (cut V1).
- Does not import an RNG crate (cut V1).
- Does not model AON-timer advancement — storage + warn on MATCH (V3 compromise).
- Does not land silicon interpolator scenarios upfront (cut V1; silicon remains the binding oracle for future divergence).
- Does not duplicate every `_0` scenario for `_1` instances (cut V1).
- Does not build a shared warn-framework; ten targeted convention sites (§4.A2).
- Does not add allowlist / filter infrastructure for warn-noise during landing.
