# LLD — QEMU Diff RISC-V (V1)

**Date:** 2026-04-17
**Scope:** Phase 2 of `2026.04.17 - HLD - RP2350 RISC-V Hazard3 Test Oracles.md` (§4 Phase 2).
**Companion:** `wrk_docs/2026.04.13 - LLD - QEMU Diff Harness V3.md` (ARM-side structural reference); `wrk_docs/2026.04.17 - HLD - RP2350 RISC-V Hazard3 Core Support V6.md` (core HLD §6 P2.4/P2.5).
**Deliverable:** `crates/mdpicoem-harness/src/bin/qemu_diff_riscv32.rs`, extensions to `gdb_client.rs`, new `riscv_gen.rs`.

## 1. Scope

Validate Hazard3 RV32IMAC + Zicsr + Zifencei instruction semantics by executing the same encoded instruction in both QEMU's generic `rv32` CPU and our `Hazard3` core, then diffing GPRs, PC, and a bounded CSR set. Sibling to `qemu_diff_m33`; differs in ISA, GDB port (**3335**), QEMU binary (`qemu-system-riscv32`), and CSR-diff mechanism. Deliberately out of scope: Hazard3 customs, atomics outside the reservable region, WARL exhaustion, cycle accuracy — those all defer to the silicon oracle (HLD §2).

## 2. QEMU invocation (PINNED)

Verified on host `qemu-system-riscv32 10.2.0 (v10.2.0-12105-g0f12d445bd)` at `C:\Program Files\qemu\qemu-system-riscv32.exe` via `-qmp` `qom-list` of `/machine/unattached/device[0]` (the CPU QOM object is typed `rv32-riscv-cpu`).

```
qemu-system-riscv32.exe
  -machine none -bios none
  -cpu rv32,a=true,m=true,c=true,zicsr=true,zifencei=true,f=false,d=false
  -m 8M -nographic -display none
  -gdb tcp::3335 -S
  -device loader,file=<bin>,addr=0x20000000,cpu-num=0
```

`f=false,d=false` explicitly disables F/D to keep the GDB register map GPR-and-PC-only and eliminate the FPR block (see "Defaults that matter" below). Stage 5 smoke verifies `-cpu rv32,f=false,d=false,help` accepts cleanly; if the QEMU build we pin rejects `f=false`, fallback is QOM property-introspection post-connect to confirm misa matches Hazard3's `0x4080_1105` (no F, no D). `-icount` is intentionally omitted — see §12 Q1 for rationale.

**Deviation from core HLD V6 §6 P2.5.** The HLD's pinned invocation uses `-kernel <bin>`. On QEMU 10.2 with `-machine none`, `-kernel` is rejected outright: `The -kernel parameter is not supported (use the generic 'loader' device instead).` Replaced with `-device loader,file=...,addr=0x20000000,cpu-num=0`. This matches the load address the P5 smoke firmware uses (`load_image(0x2000_0000, ...)`), so both sides converge on SRAM-base entry. Tracked as a HLD/LLD alignment item under `tech_debt.md` § "Test-Oracles HLD V4 §4 Phase 2 — QEMU invocation deviation" — core HLD should be amended to match on a future pass.

**Property syntax confirmed.** `-cpu rv32,help` is rejected (`Expected key=value format`), so properties were enumerated by QOM introspection. Lowercase single-letter booleans (`i`, `m`, `a`, `c`, `f`, `d`, `g`) and lowercase `zicsr` / `zifencei` are the exact property names; the core HLD's speculated syntax was correct. `priv_spec` default is `"v1.13.0"` (acceptable; RP2350 Hazard3 is privileged spec ≥ 1.12).

**Alternatives considered (machine selection).**

> - `-machine virt`: adds CLINT (`0x0200_0000`), PLIC (`0x0C00_0000`), UART, syscon — some address-map overlap with RP2350's SIO at `0xD000_0000` is tolerable, BUT the `virt` machine also defaults to 256 MiB at `0x8000_0000` which is the reset vector, forcing a different link base (`0x8020_0000` or later). That disagrees with RP2350's SRAM at `0x2000_0000`. **Rejected.**
> - `-machine sifive_e`: 16 KiB OCM at `0x0800_0000`, no SRAM at `0x2000_0000`. Incompatible with our RP2350 SRAM usage. **Rejected.**
> - `-machine none` + `-device loader`: allows arbitrary RAM placement via the loader; we put it at `0x2000_0000` matching RP2350's SRAM mapping; no MMIO aliases to collide with Hazard3 observables. **Chosen.**

**Defaults that matter.**
- `mmu=true` and `pmp=true` on `rv32`. We leave both at defaults; the Hazard3-side emulator doesn't model PMP, and QEMU's PMP in M-mode-only operation raises no traps unless firmware writes to `pmpcfg*` (which our corpus does not).
- `d=true` (RV32D) is enabled by default in the `rv32` CPU. The pinned invocation above sets `f=false,d=false` to disable both F and D — this should remove the 64-bit FPR block from the GDB register map and align misa with Hazard3 (`0x4080_1105`). Defence-in-depth still applies: the fuzz corpus emits no F/D opcodes (§11 tripwire), and the CSR-diff proxy never touches `fcsr`/`frm`/`fflags`.
- `zca`, `zcb`, `zcmp`, `zcmt` are `false` by default; we do not set them. `c=true` enables only the base C-extension quadrants. **Zcmp fuzz generates Zcmp-encoded bit patterns for decoder coverage on our side only** — QEMU rejects them as illegal (`mcause=2`), and we compare the illegal-instruction side-effect. See §7.

## 3. CSR-diff mechanism (PINNED)

**Empirical result.** QEMU 10.2 `target.xml` advertises `<xi:include href="riscv-csr.xml"/>`, but `qXfer:features:read:riscv-csr.xml:0,fff` returns `E00` — the CSR XML is unreachable. Direct `p <regnum>` for register indices ≥ 0x42 returns `E14` across a sweep of `0x40..0x100` and every standard CSR address (`0x300..0x344`). **Flat-index CSR read does not work on this QEMU build.**

**Register map served by the stub** (from `qXfer:features:read:target.xml`, `riscv-32bit-cpu.xml`, `riscv-32bit-virtual.xml` — with `d=false` per §2 the `riscv-64bit-fpu.xml` block drops out):

| Index (hex) | Register | Notes |
|---|---|---|
| 0x00..0x1F | x0..x31 GPRs | 32-bit |
| 0x20 | pc | 32-bit |
| 0x21 | priv | From riscv-32bit-virtual.xml (index may shift with fpu block absent — verify in Stage 5 smoke) |
| ≥ 0x22 | — | `E14` (unsupported) |

The original observation of FPR indices `0x21..0x40` was on a `d=true` default build; with `f=false,d=false` pinned, the FPU GDB feature block is expected to drop out entirely. Stage 5 smoke confirms the actual register-index map.

`g`/`G` packet size is 132 bytes = 33 × u32 = GPRs + PC only (FPRs are never in the `g` layout regardless of the `d` property). We therefore use per-register `p` / `P`.

**Mechanism chosen: instruction-splice proxy (option b from HLD §4 Phase 2).**

Before each test's `step`, we prepend a **CSR-read prelude** that spills the seven diff-set CSRs into an SRAM scratchpad; after the test, we append a **CSR-capture epilogue** that re-reads those CSRs into a second slot. The runner reads the scratchpad via `m <addr>,len` after the step to reconstruct pre- and post-state. The Zicsr instruction class is excluded from the proxy (the test IS a Zicsr instruction — instrumenting Zicsr with more Zicsr is self-masking); Zicsr tests are diffed via side-effect (GPR written, trap observed, `mepc`/`mcause` read through a *trap handler* that records into memory).

**Minimum CSR diff set (per HLD §4 Phase 2):**

| CSR | Address | Proxy `csrr` encoding note |
|---|---|---|
| `mstatus` | `0x300` | direct |
| `mie` | `0x304` | direct |
| `mtvec` | `0x305` | direct |
| `mscratch` | `0x340` | direct |
| `mepc` | `0x341` | direct |
| `mcause` | `0x342` | direct |
| `mip` | `0x344` | direct |

`mtval` excluded (Hazard3 hardwires 0; QEMU populates on faults — HLD pre-declared divergence).

**Proxy layout at test slot `0x2000_0100`:**

```
; code region — 56 bytes of prelude + test body + 56 bytes of epilogue + ebreak
0x2000_0100: csrr t0, mstatus   ; sw t0, 0x00(gp)   ... (7 CSRs × 2 instrs × 4 bytes = 56 bytes of prelude code)
0x2000_0140: <test instruction(s) under test>      (variable, 2..~16 bytes)
0x2000_0160: csrr t0, mstatus   ; sw t0, 0x20(gp)   ... (56 bytes of epilogue code)
0x2000_01A0: ebreak             ; halt (terminator, addr is the HW breakpoint target)
```

**Memory layout note.** The "56 bytes" above refers to **code size** (7× `csrrs` + 7× `sw` = 14 instrs × 4 bytes). The **data region** at scratchpad base `0x2000_0300` holds the CSR snapshots:

```
0x2000_0300: pre-snapshot  (7 CSRs × 4 bytes = 28 bytes, written by prelude's sw stream)
0x2000_0320: post-snapshot (7 CSRs × 4 bytes = 28 bytes, written by epilogue's sw stream)
                           (56 bytes total; reader uses `m 0x2000_0300,0x38`)
0x2000_0400: [self-check stub code — see §4.1]
0x2000_0500: self-check data region (56 bytes: pattern-A ×7 + pattern-B ×7 = 14 × 4 bytes)
```

No collisions: the scratchpad regions at `0x2000_0300`/`0x2000_0500` do not overlap the code region at `0x2000_0100..0x2000_01A4` or the self-check stub at `0x2000_0400..0x2000_04C0`.

`gp` (x3) is pre-loaded with the scratchpad base by the GDB-setup phase; the prelude reserves it as a caller-save proxy register. Encoder for `csrr rd, csr` is `csrrs rd, csr, x0` (`0x0000_2073 | (csr << 20) | (rd << 7)`).

**HW breakpoint.** QEMU's RV32 GDB stub honours `Z1,addr,2` (hardware breakpoint, 2-byte granule to cover compressed `c.ebreak`). Use that, not SW breakpoint insertion, to keep memory state untouched.

## 4. Proxy self-masking carve-out

The diff-set CSR sweep executes `csrr`/`csrw` on both sides for *every* test. A bug in our `csrr` implementation for one of the seven CSRs that happens to agree with QEMU's `csrr` is masked. Mitigations:

1. **Zicsr semantic subset is excluded from the proxy.** The Zicsr fuzz class never runs under proxy instrumentation; its pre- and post-state are observed via **GPR writes + trap handler side-effects** (a fixed minimal handler stub installed at `mtvec`, which writes `mcause` to `0x2000_01F0` and issues `ebreak`).
2. **Read-side-effect CSRs are not in the diff set.** `meinext` clears `meifa` on read; none of `{mstatus, mie, mtvec, mscratch, mepc, mcause, mip}` has a read side-effect on Hazard3 V1 scope.
3. **Silicon revalidation is the final oracle.** Phase 3 LLD's "CSR-proxy cross-check" row (HLD §4 Phase 3 silicon-only test categories) revalidates those specific seven CSR values against real Hazard3 RTL, closing the shared-bug case.

### 4.1 Proxy self-check at startup

Mitigation (1)–(3) close the obvious self-masking classes, but they do **not** close the case where our `csrrs rd, csr, x0` implementation and QEMU's share a *different* bug that both produce the same wrong answer. A stronger tripwire: read every diff-set CSR via **two distinct instruction patterns** before any test runs, and abort if either side disagrees with itself across the two reads.

**Pre-suite self-check sequence** (runs once, immediately after GDB attach, before the first test case):

Binary plants a fixed self-check stub at `0x2000_0400` that reads each of the 7 diff-set CSRs via two patterns and spills the results to a scratchpad at `0x2000_0500`:

```
; pattern A — csrrs (the proxy's main path)
0x2000_0400: csrrs t0, mstatus, x0  ; sw t0, 0x00(gp)    ; gp = 0x2000_0500
             csrrs t0, mie,     x0  ; sw t0, 0x04(gp)
             csrrs t0, mtvec,   x0  ; sw t0, 0x08(gp)
             csrrs t0, mscratch,x0  ; sw t0, 0x0C(gp)
             csrrs t0, mepc,    x0  ; sw t0, 0x10(gp)
             csrrs t0, mcause,  x0  ; sw t0, 0x14(gp)
             csrrs t0, mip,     x0  ; sw t0, 0x18(gp)
; pattern B — csrrw rd, csr, x0 (rd != x0; writes back same value read from CSR, which for rs1=x0 is a spec-equivalent no-op write)
             csrrw t0, mstatus, x0  ; sw t0, 0x1C(gp)
             csrrw t0, mie,     x0  ; sw t0, 0x20(gp)
             csrrw t0, mtvec,   x0  ; sw t0, 0x24(gp)
             csrrw t0, mscratch,x0  ; sw t0, 0x28(gp)
             csrrw t0, mepc,    x0  ; sw t0, 0x2C(gp)
             csrrw t0, mcause,  x0  ; sw t0, 0x30(gp)
             csrrw t0, mip,     x0  ; sw t0, 0x34(gp)
             ebreak
```

Data layout at `0x2000_0500`: 7×4 bytes pattern-A + 7×4 bytes pattern-B = 56 bytes total. Runner reads the full 56 bytes from both QEMU and emulator and compares pattern-A[i] vs pattern-B[i] **on each side independently**.

**Abort criterion.** If `pattern_A[i] != pattern_B[i]` on either side for any CSR `i`, the runner prints `proxy self-check failed on CSR 0xNNN via pattern <A|B>` and exits with non-zero status before running the test suite. The `csrrw rd, csr, x0` form with `rs1=x0` is a read-with-no-op-write per RISC-V spec §9.1.3 — the two patterns must agree.

**Self-check does NOT close every class.** It catches independent bugs between the two read encodings on either side, but it **cannot** catch a bug that affects both encodings identically on both QEMU and the emulator. Silicon remains the final oracle for Zicsr semantics (HLD §4 Phase 3 CSR-proxy cross-check). This is defence-in-depth, not proof of correctness.

**Relationship to the Zicsr-class exclusion.** The class exclusion in (1) above is independent: even with the self-check passing, Zicsr tests never run under the proxy — they use the trap-handler path. Both mechanisms stand.

## 5. WARL disposition

Hazard3 and QEMU's generic `rv32` implement WARL fields differently. V1 seeds the mask table with a **known starter list** from Hazard3 csr.adoc and core HLD V6 §4.3/§4.5, and grows the table **reactively** as fuzz findings land. Silicon remains the authoritative WARL oracle (HLD §6 Audit tier).

**Starter list (pinned at `riscv_gen.rs::WARL_MASKS` before Stage 5 smoke):**

| CSR | Field | Hazard3 | QEMU rv32 | Disposition |
|---|---|---|---|---|
| `mstatus` | `MPP` (bits 12:11) | Forced to `0b11` (M-mode only) | Accepts `0b00`/`0b01`/`0b11` | Mask QEMU's `mstatus.MPP` → `0b11` before compare |
| `mtvec` | `MODE` (bits 1:0) | Only `0` (Direct) and `1` (Vectored); bit 1 RAZ/WI | May accept `2` / `3` | Mask `mtvec.MODE` to `mode & 1` on QEMU side |
| `mcause` | Interrupt bit + cause code | Drops bits outside implemented cause range | May preserve full write | Skip variant: generator does not write invalid `mcause` values in fuzz |
| `mie` / `mip` | Per-bit implementation | Hazard3 implements only bits 3/7/11 (MSIE/MTIE/MEIE) | QEMU may implement more | Mask `mie`/`mip` to `bits & 0x888` on both sides |
| `misa` | Read value | Hazard3: `0x4080_1105` per core HLD §4.3 | QEMU: includes D bit (with `d=true` default; see §2 for disable) | Excluded from diff set — documented here for future readers |

**Reactive rows.** Additional WARL corners discovered during Stage 6 fuzz land as incremental table rows (plus a `warl_divergences.log` append entry citing the seed that tripped it). No exhaustive enumeration at design time — the HLD §4 Phase 2 explicitly scopes that out; silicon is the authoritative oracle for all WARL behaviour (HLD §6 Audit tier).

## 6. Fuzz classes + sample weights

Class names verbatim from HLD §4 Phase 2. Weights mirror `qemu_diff_m33`'s balance (heaviest on hot-path ALU, lighter on boutique classes; property-test picks up the residual encoding coverage).

| Class | Fuzz weight (per `--fuzz N`) | Edge-case count (default, no `--fuzz`) | Notes |
|---|---|---|---|
| RV32I ALU (register + immediate) | **30%** | ~60 | Hottest path; overflow/carry/shift-amount edges + register aliasing. Weight bumped +5% from the 5% reclaim on RV32C/Zcmp below |
| RV32I memory (aligned load/store) | **12%** | ~30 | LB/LH/LW/LBU/LHU/SB/SH/SW, aligned addrs only; scratchpad-offset addressing |
| RV32I misaligned load/store | **5%** | ~12 | Exercises `mcause` 4/6 — Hazard3 traps; QEMU (generic rv32) also traps. Hand-picked offsets |
| RV32I branch/jump | **10%** | ~25 | All 6 conditional branches + JAL/JALR at near/far offsets + compressed mirrors |
| RV32I upper (lui/auipc) + PC-relative pairs | **5%** | ~12 | lui alone; auipc/addi; auipc/jalr pairs |
| RV32M | **10%** | ~24 | MUL/MULH/MULHU/MULHSU/DIV/DIVU/REM/REMU + divide-by-zero + INT_MIN/−1 overflow corners |
| RV32A inside reservable region | **10%** | ~20 | Addresses pre-primed to `0x2000_0000..0x2008_2000`. `lr.w`/`sc.w`/`amo*.w`. Single-hart only in Phase 2 |
| RV32C (incl. Zcmp quadrant-2 sweep) | **5%** | ~30 | Weight halved from an initial 10% — trap-match is low-information per test and the 30 edge cases already sweep the quadrant bit space. Zcmp cases emit Hazard3-decoder-coverage bits; diff is `mcause=2` on BOTH sides; a no-trap emulator outcome is the precise signal that core HLD V6 §4.5's collision risk has materialised. This is the designed-for failure — we want to catch it. Reclaimed 5% went to RV32I ALU |
| Zicsr | **8%** | ~20 | CSRRW/CSRRS/CSRRC + imm variants across the seven-CSR set. **Not under proxy.** |
| Zifencei self-modifying probe | **2%** | ~4 | Write one word of code, `fence.i`, JALR to it |
| CSR-side-effect chains | **3%** | ~10 | `csrrw mstatus, t0` → conditional branch; multi-instruction sequence, bounded |

Single-instruction focus per `qemu_diff_m33` precedent; multi-instruction sequence classes are limited to "CSR-side-effect chains" (deliberately small) and deferred for the rest — silicon will reveal whether that's sufficient.

## 7. Encoder structure (`riscv_gen.rs`)

New module at `crates/mdpicoem-harness/src/riscv_gen.rs`. Public API:

```rust
pub struct RiscvTestCase {
    pub name: String,
    pub words: Vec<u32>,              // instruction word(s), LE-encoded
    pub reg_pre: Vec<(u8, u32)>,      // x-register pre-state (x1..x31)
    pub addr_regs: Vec<u8>,           // registers holding scratchpad offsets
    pub mem_pre: Vec<(u32, u8)>,      // scratchpad preconditions
    pub mem_check: Vec<u32>,          // scratchpad offsets to compare post-step
    pub csr_mask: CsrMask,            // per-CSR post-state mask (WARL carve-outs)
    pub class: FuzzClass,             // for filtering + reporting
    pub expect_trap: Option<u32>,     // Some(expected mcause) for illegal-op tests
}

pub enum FuzzClass {
    Rv32iAlu, Rv32iMem, Rv32iMemMisaligned, Rv32iBranchJump,
    Rv32iUpperPcRel, Rv32m, Rv32aReservable, Rv32c,
    Zicsr, Zifencei, CsrSideEffect,
}

// Edge-case generators
pub fn gen_rv32i_alu_edge_cases() -> Vec<RiscvTestCase>;
pub fn gen_rv32i_mem_edge_cases() -> Vec<RiscvTestCase>;
// ... one per class

// Fuzz generators
pub fn gen_fuzz_rv32i_alu(rng: &mut StdRng, count: usize) -> Vec<RiscvTestCase>;
pub fn gen_fuzz_rv32m(rng: &mut StdRng, count: usize) -> Vec<RiscvTestCase>;
// ... one per class

// Composition
pub fn generate_edge_cases() -> Vec<RiscvTestCase>;
pub fn generate_fuzz(rng: &mut StdRng, total_count: usize) -> Vec<RiscvTestCase>;

// Encoder helpers (public for property-test use)
pub fn enc_r(opcode: u32, rd: u8, funct3: u32, rs1: u8, rs2: u8, funct7: u32) -> u32;
pub fn enc_i(opcode: u32, rd: u8, funct3: u32, rs1: u8, imm12: i32) -> u32;
pub fn enc_s(opcode: u32, funct3: u32, rs1: u8, rs2: u8, imm12: i32) -> u32;
pub fn enc_b(opcode: u32, funct3: u32, rs1: u8, rs2: u8, imm13: i32) -> u32;
pub fn enc_u(opcode: u32, rd: u8, imm32: u32) -> u32;
pub fn enc_j(opcode: u32, rd: u8, imm21: i32) -> u32;
pub fn enc_csr(op: CsrOp, rd: u8, csr: u16, rs1_or_uimm5: u8) -> u32;
```

Encoder scope = RV32I + M + A (single-word AMO format) + C (16-bit quadrants, including Zcmp quadrant-2 bit patterns emitted as a sweep even though Hazard3 V1 decodes them as illegal) + Zicsr. No F/D. No Zba/Zbb/Zbs (these are Hazard3 customs — unit-tested only).

## 8. Property test

Per HLD §3 shared-code hazard mitigation. Lives in `#[cfg(test)]` alongside `riscv_gen.rs`.

**Approach.** An external authoritative decoder is used as the reference — no hand-rolled decoder introduced. Primary: `riscv-decode` crate (crates.io, MIT-licensed, decode-only, pinned to `0.2.3` at time of LLD write-up). This eliminates a private 200–300 LoC decoder as a shared-bug surface between the property test and `riscv_gen`.

**Cargo wiring.** Add to `crates/mdpicoem-harness/Cargo.toml` under `[dev-dependencies]`:
```toml
riscv-decode = "=0.2.3"
```
(Exact-version pin so drift in upstream behaviour surfaces explicitly.)

**Property-test flow.**
1. Generate 1000 random cases via `generate_fuzz(rng, 1000)`.
2. For each case, decode each 2- or 4-byte word via `riscv_decode::decode()`.
3. Assert the decoded instruction **class and operand tuple** matches the `TestCase.name`'s intended instruction (class-level agreement; don't require identical internal representations between `riscv-decode`'s enum and ours).
4. Assert the length (2 vs 4 bytes) matches what the encoder claimed.

**Zcmp fallback.** `riscv-decode` 0.2.3 does not cover the Zcmp quadrant-2 extension. For those encodings `riscv_gen` tags the case with `class == Rv32c` *and* a `expect_trap: Some(2)` (illegal-instruction on Hazard3 V1). The property test has a tiny ~20-line Zcmp sentinel arm that matches those encoded bit patterns directly and asserts the tag is consistent. This keeps the hand-rolled surface bounded to Zcmp only — an explicit carve-out rather than a full private decoder.

**Pre-bake check.** Before freezing the dependency, Stage 4 verifies `cargo add --dev riscv-decode@0.2.3 -p mdpicoem-harness` resolves. If `riscv-decode` becomes unavailable or its API drifts, fallback is `raki` (another RISC-V decoder on crates.io) with the same approach; last-resort fallback is hand-rolled with an explicit warning at the top of the property-test module.

**Pass criterion.** 1000/1000. If < 1000, that is an encoder bug, not a test-setup issue. Run as part of `cargo test -p mdpicoem-harness`.

## 9. QEMU infrastructure changes (Stage 3)

`gdb_client.rs`:

1. **New profile** `QemuProfile::RISCV32_RP2350`:
   ```rust
   pub const RISCV32_RP2350: Self = Self {
       machine: "none",
       cpu: "rv32,a=true,m=true,c=true,zicsr=true,zifencei=true,f=false,d=false",
       gdb_port: 3335,
       bios: Some("none"),                  // new field
       loader_addr: Some(0x2000_0000),      // new field
   };
   ```
   `bios` + `loader_addr` are new optional fields on `QemuProfile`; existing ARM profiles leave them `None`.

2. **`QemuProcess::spawn_with` dispatch.** When `profile.cpu` starts with `"rv32"`, spawn `qemu-system-riscv32` instead of `qemu-system-arm`; append `-bios none`, `-m 8M`, `-icount shift=0,align=off,sleep=off`, and `-device loader,file=<path>,addr=<loader_addr>,cpu-num=0`. A `<path>` parameter is needed because the RV profile loads a test-image stub — add a `spawn_with_image(profile, path)` variant and have ARM callers pass `None`.

3. **RV register constants.** Add `REG_RV_X0=0`..`REG_RV_X31=31`, `REG_RV_PC=32`. No CSR constants — CSRs go via the proxy.

4. **Sanity check.** After connect, read PC via `p20` and assert it equals the loader address (`0x2000_0000` when `-S` holds the CPU at reset with the loader active).

## 10. Test loop (`qemu_diff_riscv32.rs`)

Mirrors `qemu_diff_m33.rs` shape. Distinctive elements:

- **CLI.** `--fuzz N`, `--seed S`, `--class <rv32i|rv32m|rv32a|rv32c|zicsr|zifencei|csr-sideeffect|all>` (default all). No `--fpu` (no F/D). Edge-case default when invoked with no args (matches HLD §4 Phase 2 "mirrors `qemu_diff_m33` precedent").
- **Startup.** Build a 4 KB test-image stub (just `ebreak` padding at the entry and a minimal `mtvec` trap handler at offset 0x0200 that writes `mcause` to `0x2000_01F0` and ebreaks), write to a temp file, spawn QEMU with that path. On the emulator side, `emu.load_image(0x2000_0000, stub_bytes)` + set `pc = 0x2000_0000`.
- **Per-iteration.**
  1. `riscv_gen` produces a `RiscvTestCase`.
  2. Prepend CSR-read prelude, append CSR-capture epilogue + `ebreak` (unless `class == Zicsr` — that class uses the trap-handler path instead).
  3. Write all instruction words to QEMU via `M` at `0x2000_0100`.
  4. Same bytes to emulator bus via `emu.bus.write32`.
  5. Set `gp = 0x2000_0300` (scratchpad base), other GPR preconditions, PC = `0x2000_0100` on both sides.
  6. QEMU: `Z1,20000140,2`-style HW breakpoint at the last `ebreak`, `vCont;c`, `wait_for_halt`.
  7. Emulator: `emu.step()` in a loop until the emulator's PC hits the `ebreak` address (bounded; 256 steps max, escalate to FAIL on overrun).
  8. Read GPRs via `p0..p1F`, PC via `p20`, then `m 0x2000_0300,0x50` to reconstruct pre- and post-CSR snapshots.
  9. Diff GPRs (absolute), PC (relative to `0x2000_0100`), CSR set (with `csr_mask`), scratchpad `mem_check` bytes.
- **Unknown-opcode escalation.** The emulator's `warn!("unknown opcode ...")` is hooked in fuzz mode to escalate to test failure — the expected reference is QEMU's `mcause=2` delivery into our trap handler. Mirror of the `qemu_diff_m0plus` `UndefOnSilicon` diagnostic pattern.

## 11. Honest gaps (what V1 QEMU oracle does NOT cover)

- **Hazard3 customs** — `h3.bextm`, `h3.bextmi`, `h3.block`, `h3.unblock`, the `0xBE0..0xBE5` IRQ-controller CSR window, `h3.misa` at `0xBF1`. Silicon-only (HLD §4 Phase 3).
- **Atomics outside the reservable region** — RP2350 §2.1.6.2 says `amo*.w` → `mcause=7`; `lr.w`/`sc.w` → infinite loop. QEMU's generic `rv32` does not enforce this. Silicon-only.
- **WARL-field exhaustion** — reactive only (§5); enumerated WARL pass is a silicon follow-up.
- **SDK firmware** — core HLD Q4 exclusion; not a goal of this oracle.
- **Cycle accuracy** — QEMU doesn't model Hazard3 pipeline timing; `mcycle` cannot be diffed. Silicon-only (`silicon_cycle_oracle_riscv_rp2350`).
- **Multi-hart atomics** — Phase 2 fuzz is single-hart; two-core `lr`/`sc` interleaving lands as a hand-rolled property test in core-HLD P3, orthogonal to this oracle.
- **F/D float** — `d=true` default in QEMU enables FPRs in the GDB map, but our corpus emits no F/D instructions; Hazard3 has no F/D. Tripwire: `riscv_gen.rs` unit test asserts no generator path ever emits an opcode in `{0x07, 0x27, 0x43, 0x47, 0x4B, 0x4F, 0x53}`.
- **Interrupt delivery** — cold-case only; no `mip`/`mie` time-dependent interactions. P4's IRQ suite covers that under unit tests; silicon oracle validates.

## 12. Open questions

1. **`-icount` deferred.** `-icount shift=0,align=off,sleep=off` was removed from the pinned invocation in §2. The V1 diff compares GPR / PC / CSR state only — none of those require cycle-determinism. `-icount` can be added as a smoke-verified addition if a future diff dimension (e.g. `mcycle` within a bounded test window, instruction-retire accounting) needs it. The ARM-side harness does single-step; the RV-side uses `vCont;c` + HW breakpoint — icount's interaction with resume-to-breakpoint vs single-step on this QEMU build is unverified and not re-verified for V1.
2. **Vectored `mtvec` alignment — resolved (spec) + smoke-verify (QEMU).** Per RISC-V Privileged spec §3.1.7, `mtvec.BASE` requires **4-byte alignment** (not 64-byte). Our handler base `0x2000_0200` is 4-byte-aligned; `mtvec = 0x2000_0201` (BASE=`0x2000_0200`, MODE=1 Vectored) is legal. Remaining item: confirm QEMU's generic `rv32` accepts this write without rejecting it as WARL-masked to MODE=0. Smoke-verification only; no design decision outstanding.
3. **Compressed-instruction entry alignment with `-device loader`.** The loader places the image at `0x2000_0000`, which is 4-byte aligned — fine for both 16- and 32-bit instructions. But mid-test splicing at `0x2000_0140` must stay 2-byte aligned; encoder asserts this.
4. **QEMU WARL behaviour on `priv_spec=v1.13.0` vs Hazard3 (≥1.12).** Not yet measured; any WARL divergence will surface as reactive masks per §5.
5. **`Z1` HW breakpoint count limit** on this QEMU build. We only ever set one; Stage 5 smoke confirms.
6. **Compressed `ebreak` (`c.ebreak = 0x9002`) behaviour as terminator** when the preceding instruction is 4-byte. Currently we emit 4-byte `ebreak (0x00100073)`; all good. If Zcmp sweep needs 2-byte alignment padding, document then.
