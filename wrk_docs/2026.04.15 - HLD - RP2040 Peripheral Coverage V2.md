# RP2040 Peripheral Coverage — HLD V2

Supersedes V1. Incorporates team review of 2026-04-15.

## 1. Purpose

Add emulation for the RP2040 peripherals that real pico-sdk firmware touches, so `mdrp2040` can run the motivating firmware corpus (§3) to completion instead of falling into the `HashMap<u32, u32>` catch-all.

In scope: **TIMER + WATCHDOG_TICK** (Phase 1), **UART, SPI, I2C** (Phase 2), **ADC, PWM** (Phase 3), **DMA** (Phase 4). Optional, as-needed: **WATCHDOG reset logic, RTC** (Phase 5).

### Non-goals

- Full datasheet coverage per peripheral. Implement the observed register subset captured in §4.3; nothing speculative.
- USB device/host, VREG, TBMAN, BUSCTRL, SYSCFG, PSM. Stay in HashMap fallthrough until a concrete firmware demands them.
- Non-pico-sdk firmware runtimes (MicroPython, CircuitPython, Embassy, TinyGo). The register set may over- or under-cover; revisit when motivated.
- Cycle-accurate peripheral timing to finer than one sys_clk. Functional correctness and IRQ ordering are the goals; "does it finish within window W" is the strongest timing assertion.
- RP2350 mirror. Impls stay in `crates/mdrp2040/` until RP2350 actually consumes them; extraction to `mdpicoem-common` is deferred to the moment a second consumer exists (CLAUDE.md §Quality: "don't predict the future").
- Backwards compatibility or migration paths. Dev environment; we rewrite in place.

## 4. Oracle strategy

Hardware: physical RP2040 on the lab rig, back-to-back with a Pico debug probe. Same topology as the RP2354 setup.

### 4.1 `probe_diff_rp2040` — CPU-level oracle

Port `crates/mdpicoem-harness/src/bin/probe_diff_rp2350.rs` structure (probe-rs `Session::auto_attach` → per-test instruction + BKPT, diff R0–R15 + xPSR). Clarifications:

- **Filter scope is probe-only.** `qemu_diff_m0plus.rs:291` stays strict — QEMU is `cortex-m0` (see `crates/mdpicoem-harness/src/gdb_client.rs:56`); Thumb-32 encodings UNDEF there. `probe_diff_rp2040` gets its own test-case predicate that admits the small Thumb-32 subset (`BL`, `MRS`, `MSR`, `DSB`, `DMB`, `ISB`).
- **Generator audit.** Phase 0 verifies the existing generator in `crates/mdpicoem-harness/src/thumb32_gen.rs` actually emits the Thumb-32 subset cases; if it does not, Phase 0 adds minimal generator hooks. Relaxing a filter without a generator that hits the enlarged space is cosmetic.

### 4.2 `silicon_periph_diff_rp2040` — end-state scenario oracle

Port `silicon_periph_diff_rp2350.rs`'s `PeriphScenario`, with three shape changes:

```rust
pub struct PeriphScenario {
    pub name: &'static str,
    pub setup: &'static [SetupStep], // NEW: was &[(u32, u32)]
    pub max_sysclks: u32,
    pub min_sysclks: u32,             // NEW: catches "completed too fast" bugs
    pub observe: &'static [(u32, u32)],
    pub observe_pins: u32,
    pub checkpoints: &'static [Checkpoint], // NEW: intermediate observations
    pub custom_sled: Option<&'static [u8]>,
}

pub enum SetupStep {
    Write32 { addr: u32, value: u32 },
    WaitSysclks { count: u32 },       // for PLL reset, RESETS release settling
}

pub struct Checkpoint {
    pub at_sysclks: u32,              // sample point within the window
    pub observe: &'static [(u32, u32)],
}
```

**Why these three additions are load-bearing, not feature creep:**

- `WaitSysclks` — RP2040 has registers whose effect requires prior settling (PLL reset, RESETS.release, XIP_CTRL flush). Flat `(addr, value)` lists cannot express this.
- `min_sysclks` — DMA/ring scenarios can reach a correct end-state via "too many transfers wrapped round" paths. Window lower bound catches "completed too fast" which is the off-by-one ring-buffer bug class.
- `checkpoints` — DMA mid-transfer observability requires sampling before end. Without it, the whole DMA oracle class is blind to transient misbehaviour (see Oracle review §C2).

**Timing window: SysTick.** M0+ has no DWT CYCCNT. Protocol:

1. Program `SYST_RVR = max_sysclks + framing_padding`; `SYST_CVR = 0`; `SYST_CSR = CLKSOURCE|ENABLE`.
2. Run scenario sled.
3. Sample `SYST_CVR_start` before first setup write, `SYST_CVR_end` after halt.
4. `window = SYST_CVR_start - SYST_CVR_end` — in sys_clk ticks, no wrap because `max_sysclks < 2^24`.
5. **Framing cancellation**: run the scenario twice with `max_sysclks` and `max_sysclks/2`; the delta isolates per-cycle cost from probe halt/resume overhead. Mirrors `silicon_cycle_oracle_rp2350`'s K-delta protocol. Single-run windows are framing-polluted and the HLD treats them as soft assertions only.

### 4.3 Observed-register-set capture (Phase 0 sub-task)

The "observed register subset" claim requires empirical grounding, not guesswork. Phase 0 adds `scripts/trace_firmware_mmio.py`:

1. Flash firmware corpus entry on real RP2040 silicon via probe-rs.
2. Set memory watchpoints on peripheral base ranges (probe-rs `MemoryAccess`-based polling: halt every N ms, sample `LR`/`PC` + bus access log where available).
3. Log touched (address, access-size, R/W) tuples to JSON.
4. Output: `wrk_docs/trace/<firmware>.mmio.json` — the authoritative register set for that firmware.

This dataset drives the implementation spec per peripheral. Without it, "observed subset" is whichever registers I guessed. Phase 0's delivery of one trace (`hello_timer`) is the proof-of-method; subsequent phases re-run per corpus entry.

### 4.4 Phase 0 exit criteria — red-path validation

Phase 0 completes when **all four** of these hold:

1. `probe_diff_rp2040` runs `--fuzz 10000` green, including Thumb-32 encodings.
2. `silicon_periph_diff_rp2040` runs a known-good SIO GPIO toggle scenario green.
3. `silicon_periph_diff_rp2040` runs a **deliberately-broken** scenario (off-by-one on `SIO_GPIO_OUT`) and prints FAIL with correct `first_divergence`. Proves the oracle's red path fires; an oracle you haven't watched fail is worthless (CLAUDE.md §Quality).
4. `trace_firmware_mmio.py` produces a readable `hello_timer.mmio.json` with non-empty touched-register set.

### 4.5 Triage procedure (silicon ≠ emulator)

When oracles report divergence, resolution is not automatic. Documented procedure:

1. **Reproduce** on silicon with `--seed`; record the exact `PeriphScenario` (or instruction trace from `probe_diff_rp2040`).
2. **Check probe-rs** against datasheet canonical reset values — is `Session::read_word_32` returning what the datasheet says for an untouched peripheral? If not, the oracle is the bug.
3. **Check the silicon side** with the `probe_verify_rp2040` sanity scenario (port from RP2354) — same write-then-read on a register known correct (e.g., SIO GPIO mirror). If silicon diverges from itself across runs, board-level issue.
4. Only after (2) and (3) clear: assume emulator bug.

Record every divergence in `wrk_journals/` with the verdict. The journal is the memory of which direction blame has flowed; without it, the oracle becomes an anecdote generator.

## 5. Architecture

### 5.1 Peripheral pattern — inherent methods, no trait

Delete `mdpicoem-common::Peripheral` (currently unused). Each peripheral is a struct in `crates/mdrp2040/src/peripherals/<name>.rs` with inherent methods. Shape:

```rust
pub struct TimerRegs { /* fields */ }

impl TimerRegs {
    pub fn read32(&mut self, offset: u32) -> u32 { ... }
    pub fn write32(&mut self, offset: u32, value: u32, alias: u32, irqs: &mut u32) { ... }
    pub fn tick(&mut self, cycles: u64, irqs: &mut u32) { ... } // only if stateful
    pub fn in_reset(&self, resets: &ResetsState) -> bool { resets.is_held(RESET_BIT_TIMER) }
    // Optional, per §5.4:
    pub fn read8(&mut self, offset: u32) -> u8 { ... }
    pub fn write8(&mut self, offset: u32, value: u8, irqs: &mut u32) { ... }
}
```

**No trait.** Consistency is enforced by code review and a comment at the top of `peripherals/mod.rs` documenting the shape. If a later refactor shows a real need for dynamic dispatch, extract a trait then — not speculatively.

Dispatch is a match arm in `Bus::peripheral_read32`/`peripheral_write32`. Named field on `Bus`. Three mechanical steps per peripheral: new module, new field, new arm.

**Ownership**: peripheral fields and `irq_pending` are `pub(crate)` sibling fields on `Bus`. No accessor methods that borrow `&mut self`. Dispatch is direct field access: `self.timer.write32(off, val, alias, &mut self.irq_pending)`. Documented at top of `bus/mod.rs`.

### 5.2 IRQ plumbing

One field on `Bus`:

```rust
pub(crate) irq_pending: u32, // bit N == IRQ N asserted this cycle; 0 ≤ N < 26
```

Peripherals assert via `*irqs |= 1 << IRQ_TIMER_IRQ_0;` — plain bit op, no wrapper struct.

Constants in `crates/mdrp2040/src/irq.rs`:

```rust
pub const IRQ_COUNT: u8 = 26; // RP2040 datasheet §2.3.2 Table 26
pub const IRQ_TIMER_IRQ_0: u8 = 0;
// ... IRQ_TIMER_IRQ_1..3, IRQ_PWM_IRQ_WRAP, IRQ_USBCTRL_IRQ, IRQ_XIP_IRQ,
// IRQ_PIO0_IRQ_0, IRQ_PIO0_IRQ_1, IRQ_PIO1_IRQ_0, IRQ_PIO1_IRQ_1,
// IRQ_DMA_IRQ_0, IRQ_DMA_IRQ_1, IRQ_IO_IRQ_BANK0, ...
```

See Appendix B for the full table.

**Level semantics, not edge.** Peripherals assert the bit **every cycle the IRQ condition holds** (e.g., UART RX FIFO non-empty re-asserts every tick until the firmware drains it). The emulator's forwarder translates the level to NVIC set-pending; NVIC handles its own latching. This matches RP2040 silicon (IRQ inputs are level to NVIC) and sidesteps the de-assert semantics problem.

**Drain granularity.** `irq_pending` is drained **per inner-cycle iteration** of the tick loop, not per `Emulator::step`. A TIMER alarm matching on cycle 3 of a 10-cycle step is pending at cycle 3, not cycle 10.

**Forwarding to both cores.** Both NVICs receive the pending bits each inner cycle. Cheap early-out:

```rust
if self.bus.irq_pending != 0 {
    let raised = std::mem::take(&mut self.bus.irq_pending);
    for irq in 0..IRQ_COUNT {
        if raised & (1 << irq) != 0 {
            self.cores[0].nvic.set_pending(irq);
            self.cores[1].nvic.set_pending(irq);
        }
    }
}
```

Future threaded-cores work will need `AtomicU32` or equivalent; single-threaded today, change locally when the threading work lands. CLAUDE.md memory `feedback_threading_perf.md` says don't pre-build for threaded cores.

### 5.3 Peripheral clock and reset gating

**RESETS gating — uniform rule.** Every peripheral's `read32`/`write32`/`tick` begins with:

```rust
if resets.is_held(RESET_BIT_TIMER) { return /* read: 0, write: no-op, tick: no-op */ }
```

`ResetsState` is already tracked in the existing RESETS peripheral; expose a `pub fn is_held(bit: u32) -> bool` accessor. `Bus::peripheral_read32`/`peripheral_write32` pass `&self.resets` into the peripheral's dispatch helper (split-borrow-friendly since it's a different field).

**Clock gating — per-peripheral scaling.** Peripherals with a clock domain distinct from sys_clk scale their tick:

| Peripheral | Clock | Scaling |
|---|---|---|
| TIMER | `clk_ref / WATCHDOG_TICK.CYCLES` (target 1 µs) | Computed lazily in read path |
| ADC | `clk_adc` (48 MHz nominal) | Tick step derived from `clock_tree.adc_hz() / clock_tree.sys_hz()` |
| RTC | `clk_rtc` (~46875 Hz) | Lazy: recompute from `master_cycle` |
| UART/SPI/I2C | `clk_peri` (defaults to `clk_sys`) | Bit-rate derived from `clock_tree.peri_hz()` and internal baud divider |
| PWM | `clk_sys` | No scaling |
| DMA | `clk_sys` | No scaling |

`clock_tree.peri_hz()`/`adc_hz()`/`rtc_hz()`/`ref_hz()` accessors added to `ClockTree` if not present. `clk_peri` defaulting to `clk_sys` means the common case is trivial; firmware reprogramming clk_peri explicitly is the non-trivial case and is an existing test vector.

### 5.4 Atomic aliases and byte/halfword access

**Atomic alias handling stays at the peripheral.** Signature: `write32(offset, value, alias, irqs)`. The peripheral decides per-register:

- **Plain storage register** (e.g., TIMER_ALARM0, UART_IBRD): apply alias RMW to stored value.

  ```rust
  match alias {
      0x0000 => self.alarm0 = value,
      0x1000 => self.alarm0 ^= value,
      0x2000 => self.alarm0 |= value,
      0x3000 => self.alarm0 &= !value,
      _ => unreachable!(),
  }
  ```

- **Side-effect register** (e.g., TIMER_INTR — W1C; UART_DR — FIFO push; DMA CH_TRIGGER — kicks transfer): alias semantics don't apply uniformly. `alias=0x2000` (BITSET) on `INTR` means "set-to-1-clear-these" which maps to W1C on the flagged bits; alias on `UART_DR` is undefined in hardware. Each peripheral module documents the table.

Helper: `pub fn apply_alias_rmw(stored: &mut u32, value: u32, alias: u32)` in `peripherals/mod.rs` for the common case. Side-effect registers bypass it.

**Byte/halfword access on side-effect registers.** UART_DR, SPI_DR, I2C_IC_DATA_CMD are byte-accessible on silicon. Current `bus/mod.rs:594-596` does word-RMW which pops/pushes an extra FIFO entry. Fix: peripherals that need it expose explicit `read8`/`write8`/`read16`/`write16`. Bus dispatcher tries the typed method first; falls back to the existing word-RMW for peripherals that don't override.

### 5.5 Per-cycle peripheral tick — dirty-mask

Extend `crates/mdrp2040/src/lib.rs:303` to generalise beyond PIO. Slow-path:

```rust
for _ in 0..consumed {
    self.bus.tick_peripherals();       // only active peripherals
    self.bus.update_gpio();
    self.drain_pending_irqs_to_cores(); // from §5.2
}
```

**Active-mask optimisation.** `Bus` carries `active_tickers: u32`. Each peripheral sets its bit when becoming active (DMA channel enabled, PWM slice running, UART transmit in progress) and clears it when idle. `tick_peripherals` iterates only set bits:

```rust
let mut mask = self.active_tickers;
while mask != 0 {
    let idx = mask.trailing_zeros() as usize;
    mask &= !(1 << idx);
    PERIPHERAL_TICK_FNS[idx](self);
}
```

Fixed dispatch table `PERIPHERAL_TICK_FNS` — function pointers, inline-friendly. PIO's existing fast-path is folded in (PIO owns two bits, one per block).

**Lazy peripherals stay lazy.** TIMER, RTC, WATCHDOG_TICK never set their tick bits — they're computed on read from `master_cycle`, and alarm IRQs are scheduled by computing "at which `master_cycle` does the alarm fire" at write time, checked in the drain. No wasted tick calls.

Expected active peripheral count at steady state: 0–3. Cost dominated by CPU step, not ticking.

### 5.6 DMA — bus master

DMA lives on `Bus` as a named field, same as the others. Tick needs mutable access to the rest of `Bus`; resolve via owned swap, not a trait object:

```rust
// On Bus:
pub fn tick_dma(&mut self) {
    let mut dma = std::mem::take(&mut self.dma); // Dma: Default
    dma.tick(self, &mut self.irq_pending);
    self.dma = dma;
}
```

No `DmaMaster` trait. `Dma::tick` takes `&mut Bus` directly (excluding itself, since it's moved out). `Dma: Default` is trivial.

**Ordering within a cycle.** Fixed and documented:
1. Non-DMA peripherals `tick()` — updates their DREQ state.
2. `tick_dma()` — reads DREQ snapshot, issues one transfer per enabled channel.
3. `update_gpio()`.
4. Drain IRQ pending to both cores.

Means: DMA operates on the cycle's **post-tick** DREQ state. The first transfer after a peripheral becomes ready happens in the same cycle as the ready-transition. DMA writes become visible to peripherals the **next** cycle. Deterministic; documented as a contract.

**DREQ table.** `Dma::tick` reads `[u64; 1]` (a 40-bit bitmap — `DREQ_FORCE=63` is bit 63 in the same u64) assembled from peripherals. Appendix C pins the table. `Dma` is the only consumer; no DREQ infrastructure lands in Phase 1–3.

**DMA V1 scope** (revised from V1):
- 12 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `CHAIN_TO`, `TREQ_SEL`.
- **`RING_SIZE`/`RING_SEL` — IN SCOPE.** Ring mode is load-bearing for audio (`audio_i2s`) and logging-UART firmware. Implementation: ~10 lines, `addr_within_ring = (base & !((1<<ring)-1)) | ((addr + N) & ((1<<ring)-1))`.
- `CH_ABORT` — in scope. pico-sdk drivers rely on it.
- IRQ0 / IRQ1 per-channel enable mask (`INTE0`/`INTE1`), W1C on `INTS0`/`INTS1`.
- Fixed-priority arbitration: lowest-channel-wins if all equal. `HIGH_PRIORITY` bit honoured as priority-1 (two-tier priority arbiter — ~5 lines).
- **Not in V1**: channel chaining (`CHAIN_TO` respected for IRQ framing only, no chained triggering), CRC/sniff, byte-swap, ring across non-aligned base. Explicit.

## 7. Testing

**Oracle hierarchy:**

1. **`silicon_periph_diff_rp2040`** — load-bearing. Every peripheral ships scenarios sufficient to turn its corpus entry green. No scenario-count quota; the corpus is the gate.
2. **`probe_diff_rp2040`** — continuous CPU-level fuzz, every phase. Not peripheral-testing per se, but catches bus-surgery regressions.
3. **In-crate self-consistency tests** — per-peripheral `#[cfg(test)]` modules in `peripherals/<name>.rs`. Drive via inherent methods; assert on state. **These are not unit tests in the strong sense** — a bidirectional bug (same error in setup and observation) will pass. Call them "self-consistency checks"; they catch typos and protocol-level errors, not correctness.
4. **Integration smoke** — each corpus binary runs to its documented completion state. Binary pass/fail.

**Scenario runtime budget.** With ~6–8 scenarios per peripheral × 9 peripherals × ~3 s probe round-trip each ≈ 3–5 min silicon run, sharable with existing RP2354 catalogue under the `test_silicon` orchestrator (needs a `--chip rp2040` switch when wired, tracked in the orchestrator HLD). Soak-mode unattended multi-hour runs feasible.

**Flake policy.** Scenario runner retries once on probe transient errors (I/O, SWD disconnect). Persistent divergence is a hard fail; triage per §4.5. Retry budget written into the scenario runner — not a policy knob, no env var.

## 9. Risks & open questions

### 9.1 SysTick timing resolution

24 bits × sys_clk, ~134 ms window. Enough for every scenario we plan. PIO-counter fallback is not a V1 commitment — if a scenario ever needs sub-sys_clk resolution (it shouldn't), the PIO-counter escape hatch is a separate HLD.

### 9.2 Bootrom re-hit

Phase 1 TIMER + Phase 2 UART will unblock firmware that previously halted at `busy_wait_us_32`. Those firmwares will now reach bootrom paths (`flash_get_unique_id`, `_reset_to_usb_boot`, `rom_func_lookup`) that today collide with the SSI stub. **This HLD does not expand SSI**; the failure mode is "pico-sdk boot reaches SSI and halts". Documented, not fixed. Separate HLD when motivated.

### 9.3 Probe-rs as oracle

Trusted, not verified. Mitigation: §4.5 triage includes a "read a known-reset-value register and check against datasheet" step before concluding "emulator bug". Second RP2040 board not available today; single-board risk accepted.

### 9.4 HashMap fallthrough wrongness

Firmware reads USB_CTRL, BUSCTRL, VREG expecting specific reset values. HashMap returns 0. Some firmware doesn't care; some does. The TRACE run (§4.3) will surface these as "touches unmodelled address X expecting value Y"; resolution is per-firmware (promote the peripheral, or stub the single register with its reset value in the match arm). Known unknowns logged in `wrk_journals/`.

### 9.5 Dual-core arbitration

Both cores writing to UART_DR on the same sys_clk cycle: emulator policy is "core 0 first" (single-threaded interleave). Silicon: AHB arbitrates. No scenario exercises this today; the moment one does (unlikely on pico-sdk), we revisit. Documented policy.

### 9.6 Concurrent workspace collision

`Bus` is being modified in this HLD. Per CLAUDE.md multi-agent guidance, coordinate: land `irq_pending` + `active_tickers` fields and the tick loop extension as a single atomic commit early in Phase 1 before peripheral-specific code, minimising merge surface.

### 9.7 ISR re-entry semantics

Level semantics (§5.2) mean a peripheral re-asserts its IRQ every cycle the condition holds. Firmware clears the source in the ISR → next cycle, level is deasserted → no re-entry. Test with ≥1 scenario per IRQ-capable peripheral that increments an SRAM counter in the handler; assert count == silicon's count.

### 9.8 DMA abort / error IRQs

V1 scope includes `CH_ABORT` but not error IRQs (READ_ERROR, WRITE_ERROR in `CTRL`). If Phase 4 firmware raises errors, revisit.

### 9.9 GPIO FUNCSEL routing

Peripheral writes (UART TX register) should only reach the pad if `IO_BANK0.GPIOx_CTRL.FUNCSEL` is routed to that peripheral. Currently the emulator's IO_BANK0 model supports FUNCSEL but peripheral outputs don't check it before driving. ≥1 scenario per peripheral exercises the FUNCSEL path (set FUNCSEL, observe pin; clear FUNCSEL, observe no change).

### 9.10 Observable-via-SWD limitation

PIO FIFO occupancy mid-transfer, UART shift register state, DMA transfer-count mid-transfer — some of these are SWD-visible, some not. Where not visible, the emulator can diverge silently. Mitigation: derivative scenarios (make state influence something observable) rather than direct SWD read.
