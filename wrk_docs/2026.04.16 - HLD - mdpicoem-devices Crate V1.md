# HLD: mdpicoem-devices Crate

Date: 2026-04-16

## Problem

External (off-chip) device models are scattered across three crates:

| Device | Current location | Problem |
|--------|-----------------|---------|
| PSRAM (8 MB SPI) | `mdrp2040::peripherals::psram` | Chip crate contains board-specific hardware |
| LCD decoder | `mdrp2040app::devices::lcd` | Harness can't reuse it |
| I2S capture | `mdpicoem-harness::i2s_capture` | App can't reuse it |

This prevents sharing between app and harness, and mixes board-level
hardware with chip internals. As we add more external devices (DACs,
bus adapters, flash chips), the scattering gets worse.

## Solution

New crate `mdpicoem-devices` for all off-chip device models. A
`GpioDevice` trait in `mdpicoem-common` provides the per-cycle
integration hook for devices that drive GPIO pins back into the
emulator (PSRAM). Observer-only devices (LCD, I2S DAC) are plain
structs with their own APIs — they don't need the trait.

## Dependency graph

```
mdpicoem-common          ← GpioDevice trait
    ↑           ↑
mdrp2040    mdpicoem-devices    ← PSRAM, LCD, I2S DAC
    ↑           ↑
mdrp2040app / mdpicoem-harness  ← create devices, attach to emulator
```

No new dependencies between existing crates. `mdrp2040` already
depends on `mdpicoem-common`; the trait import adds zero weight.
`mdpicoem-devices` depends only on `mdpicoem-common` and `std`.

## GpioDevice trait (`mdpicoem-common`)

```rust
/// Off-chip device that participates in the GPIO pin merge.
///
/// Called once per system cycle from `update_gpio()`, after SIO + PIO
/// outputs have been merged. The device observes the merged pin state
/// and optionally drives pins back (e.g. PSRAM driving MISO).
pub trait GpioDevice {
    /// Bitmask of GPIO pins this device drives. Constant for the
    /// device's lifetime. The bus uses this to splice driven values
    /// into `gpio_in` without clobbering other sources.
    fn drive_mask(&self) -> u32;

    /// Observe merged GPIO state, update internal state, return
    /// values for driven pins (only bits in `drive_mask` matter).
    fn tick(&mut self, gpio: u32) -> u32;
}
```

### Bus merge (replaces current PSRAM-specific code)

Current code in `update_gpio()` (lib.rs:488):
```rust
if let Some(miso) = self.bus.psram.tick(out) {
    let mask = 1u32 << psram::PIN_MISO;
    out = (out & !mask) | ((miso as u32) << psram::PIN_MISO);
}
```

Becomes:
```rust
for dev in &mut self.bus.gpio_devices {
    let mask = dev.drive_mask();
    let vals = dev.tick(out);
    out = (out & !mask) | (vals & mask);
}
```

### Bus field

```rust
// mdrp2040::Bus
pub gpio_devices: Vec<Box<dyn GpioDevice>>,
```

Default: empty vec (zero cost for emulator configs without external
devices — QEMU diff testing, unit tests, etc.).

### Builder API

```rust
// mdrp2040::EmulatorBuilder
pub fn gpio_device(mut self, dev: Box<dyn GpioDevice>) -> Self {
    self.gpio_devices.push(dev);
    self
}
```

## Crate structure

```
crates/mdpicoem-devices/
  Cargo.toml
  src/
    lib.rs              re-exports
    psram.rs            ESP-PSRAM64H SPI model (from mdrp2040::peripherals::psram)
    lcd.rs              LCD bit-bang decoder (from mdrp2040app::devices::lcd)
    i2s_dac.rs          I2S PCM decoder (from mdpicoem-harness::i2s_capture)
    picogus_pins.rs     PicoGUS v4.0.0 pin constants (from mdpicoem-harness)
```

## What moves where

### PSRAM (`psram.rs`)

Move from `mdrp2040::peripherals::psram`.

Changes:
- Implement `GpioDevice` for `Psram`. `drive_mask()` returns
  `1 << pin_miso`. `tick()` wraps the existing `tick(&mut self,
  pins) -> Option<bool>` logic, returning the MISO bit in
  position.
- Pin constants become constructor parameters (default: GPIO 0-3
  for PicoGUS). Remove the hardcoded `PIN_*` constants from the
  struct; provide them as `Psram::picogus()` convenience constructor.
- Unit tests move with the code.
- Bus integration + PIO integration tests stay in `mdrp2040`
  (they need a full `Emulator`), updated to use the new builder
  API: `.gpio_device(Box::new(Psram::picogus()))`.

### LCD decoder (`lcd.rs`)

Move from `mdrp2040app::devices::lcd`.

Changes:
- `LcdState` moves into this file (it's just
  `rows: [[u8; 20]; 2], cursor: (u8, u8)` — no app dependencies).
- Pin constants become constructor parameters.
- No `GpioDevice` impl needed — the LCD is an observer called
  from outside via `sample(gpio: u32)`.
- Unit tests move with the code.

### I2S DAC (`i2s_dac.rs`)

Move from `mdpicoem-harness::i2s_capture`.

Changes:
- Rename `I2sCapture` → `I2sDac` (it models the PCM5102 DAC on
  PicoGUS — decodes I2S to PCM samples).
- Pin constants become constructor parameters instead of importing
  from `picogus_pins`.
- `write_wav()` stays as a method — WAV output is the DAC's
  natural deliverable.
- No `GpioDevice` impl needed — the DAC is an observer called
  from outside via `tick(gpio: u32, cycle: u64)`.
- Unit tests move with the code.

### Pin constants (`picogus_pins.rs`)

Move from `mdpicoem-harness::picogus_pins`.

Board-specific constants for the PicoGUS v4.0.0 hardware. Used by
the harness replayer and by the convenience constructors on the
device structs. No changes beyond path updates.

| `mdpicoem-harness/src/bin/picogus_diff_rp2040.rs` | Import from `mdpicoem_devices`, attach PSRAM via builder |

## What stays

- `mdrp2040::peripherals::{adc, timer, uart, spi, i2c, pwm, watchdog_tick}` — these
  are on-chip RP2040 peripherals, not external devices.
- `mdrp2040app::devices::bench` — SRAM sentinel poller, not a GPIO
  device.
- `mdrp2040::Bus::external_gpio_in_mask/override` — unchanged,
  still used by the harness for ISA pin injection.
