# Pacer Wall-Clock Accounting + Overhead Calibration

Version: 2.1.0
Date: 2026-04-13

## Problem

Two related issues discovered while running `paced_bench`:

1. **The pacer's `emulated_mhz()` is biased high by ~8%.** It computes
   `cycles / (emulation_ns + spin_ns)`, but there's wall-clock time that falls
   in *neither* bucket — the inter-quantum gap between `end_quantum()` returning
   and the next `begin_quantum()` call (loop plumbing, branch check, function
   call setup, atomic stats updates). On a 10-second run that reported 146.2
   MHz, the real rate was 135.2 MHz.

2. **The quantum target doesn't account for that overhead.** We compute
   `quantum_tsc_ticks` assuming the whole wall-clock second is made of perfect
   1µs quanta. The ~80ns/quantum overhead means we fit ~925K quanta into a
   wall second, not 1M, and we can't reach 150 MHz even with headroom.

Both stem from the same gap. Fix them both.

## Solution

Four small changes:

### 1. Add `wall_ns` to `PacerStats`

A new `AtomicU64` tracking **cumulative wall time since the first
`begin_quantum()`**. Updated at the end of every quantum with
`tsc_to_ns(final_tsc - first_begin_tsc)`. This is a **store**, not a
`fetch_add` — it's an absolute cumulative value derived from a single origin.

`PacerSnapshot` gets a matching `wall_ns: u64` field, and the derived metrics
switch their denominator:

```rust
pub fn emulated_mhz(&self) -> f64 {
    if self.wall_ns == 0 { return 0.0; }
    self.emulated_cycles as f64 / self.wall_ns as f64 * 1000.0
}

/// Upper bound on fraction of wall time spent emulating. Note: any OS
/// preemption that lands *during* an in-budget quantum's emulation phase
/// is counted as emulation time (we only timestamp at quantum boundaries).
/// Real utilization is lower by the preemption fraction.
pub fn utilization(&self) -> f64 {
    if self.wall_ns == 0 { return 0.0; }
    self.emulation_ns as f64 / self.wall_ns as f64
}

pub fn headroom(&self) -> f64 { 1.0 - self.utilization() }
```

`total_ns()` is removed — it was a leaky abstraction.

### 2. Pacer tracks `first_begin_tsc`

New field in `Pacer`:

```rust
first_begin_tsc: u64,  // TSC at the first begin_quantum (0 until set)
```

`begin_quantum()` sets it on the first call:

```rust
pub fn begin_quantum(&mut self) {
    let tsc = rdtscp();
    if self.first_begin_tsc == 0 {
        self.first_begin_tsc = tsc;
    }
    self.quantum_start_tsc = tsc;
}
```

`end_quantum()` captures its freshest TSC reading (either `now` from the spin
path or `emu_end` from the behind path) and uses it to compute wall_ns:

```rust
let final_tsc = /* freshest TSC at this point */;
let wall_tsc = final_tsc - self.first_begin_tsc;
self.stats.set_wall_ns(self.tsc_to_ns(wall_tsc));
```

### 3. Robust overhead calibration at startup

**Fidelity:** calibration must exercise the same atomic stats updates as
production `end_quantum()`, or it underestimates overhead by ~10ns.

**Noise rejection:** a single OS preemption during calibration can wreck a
naive single-batch measurement. Run multiple batches and take the minimum —
the minimum corresponds to the least-disturbed run.

**Safety clamp:** if calibration produces a pathological value (e.g. overhead
≥ nominal due to catastrophic preemption), fall back to a reasonable bound
rather than crashing.

```rust
/// Measure per-quantum overhead empirically. Runs 5 batches of 2000 no-op
/// quanta each and returns the minimum measured overhead (least disturbed
/// by OS preemption). Clamps to nominal/4 maximum to survive pathological
/// calibration runs.
fn calibrate_overhead(nominal_quantum_tsc: u64) -> u64 {
    const BATCHES: usize = 5;
    const PER_BATCH: u64 = 2000;

    // Throwaway stats to exercise the same atomic updates production does.
    let stats = PacerStats::new();

    let mut min_overhead = u64::MAX;
    for _ in 0..BATCHES {
        let first = rdtscp();
        let mut quantum_start = first;
        for _ in 0..PER_BATCH {
            // Mimic end_quantum: measurement + spin + stats updates
            let emu_end = rdtscp();
            let emulation_tsc = emu_end - quantum_start;
            if emulation_tsc < nominal_quantum_tsc {
                let target = quantum_start + nominal_quantum_tsc;
                let mut now = emu_end;
                while now < target {
                    std::hint::spin_loop();
                    now = rdtsc();
                }
                stats.add_emulation_ns(0);
                stats.add_spin_ns(0);
            } else {
                stats.add_emulation_ns(0);
                stats.increment_behind();
            }
            stats.add_emulated_cycles(150);
            stats.set_wall_ns(0);

            // Mimic next begin_quantum
            quantum_start = rdtscp();
        }
        let elapsed = quantum_start - first;
        let per_quantum = elapsed / PER_BATCH;
        let overhead = per_quantum.saturating_sub(nominal_quantum_tsc);
        if overhead < min_overhead {
            min_overhead = overhead;
        }
    }

    // Safety clamp: if calibration is catastrophically wrong, cap the
    // correction at 25% of nominal rather than panicking on zero ticks.
    let max_overhead = nominal_quantum_tsc / 4;
    min_overhead.min(max_overhead)
}
```

Called from `Pacer::new()` and `Pacer::with_quantum()` after TSC calibration:

```rust
let nominal = tsc_freq_hz * quantum_cycles / sys_clk_hz;  // via u128
let overhead = calibrate_overhead(nominal);
let quantum_tsc_ticks = nominal.saturating_sub(overhead);
assert!(quantum_tsc_ticks > 0, "...");
```

**Cost:** 5 batches × 2000 quanta × 1µs = ~10ms startup. One-time. The
calibration runs after the caller has (presumably) set affinity and priority,
so it measures realistic overhead for the production environment.

### 4. Relax the verdict in `paced_bench`

The old verdict (`behind_count == 0 && utilization < 1.0`) was binary and
impossible to satisfy on a general-purpose OS. A pure `behind_rate` threshold
is also wrong — a small number of very long miss events can tank the MHz
without showing up as high miss rate.

**Both conditions must pass.** `behind_rate` catches "how often do we miss".
`mhz_ratio` catches "how much wall time did we lose, however it was
distributed". A verdict is only promoted upward if both are satisfied.

```rust
let total_quanta = snap.emulated_cycles / quantum as u64;
let behind_rate = snap.behind_count as f64 / total_quanta.max(1) as f64;
let mhz_ratio = snap.emulated_mhz() / clock_mhz as f64;

let verdict = if mhz_ratio >= 0.99 && behind_rate < 0.001 {
    format!("REAL-TIME OK ({:.1}% of target, {:.2}% headroom, {:.3}% behind)",
            mhz_ratio * 100.0, snap.headroom() * 100.0, behind_rate * 100.0)
} else if mhz_ratio >= 0.95 && behind_rate < 0.01 {
    format!("REAL-TIME MARGINAL ({:.1}% of target, {:.2}% behind)",
            mhz_ratio * 100.0, behind_rate * 100.0)
} else {
    format!("CANNOT SUSTAIN REAL-TIME ({:.1}% of target, {:.2}% behind)",
            mhz_ratio * 100.0, behind_rate * 100.0)
};
println!("Verdict:        {}", verdict);
```

Thresholds (both must pass to promote upward):
- **OK**: mhz_ratio ≥ 99% AND behind_rate < 0.1%
- **MARGINAL**: mhz_ratio ≥ 95% AND behind_rate < 1%
- **CANNOT SUSTAIN**: anything worse

Expected outcomes with this design:
- Desktop / well-cooled machine → **OK**
- Current laptop with HIGH priority pinning → **MARGINAL** (we expect ~97-98%
  of target MHz once overhead is fixed, with 0.06% behind rate — matches
  MARGINAL's envelope)
- Plain release build (no PGO, no pinning, ~63% of target) → **CANNOT
  SUSTAIN**

This is honest about what the hardware + OS can deliver.

## What this does NOT do

- **No runtime control loop.** Pre-compensation is deterministic; a closed-loop
  PID would introduce stability concerns, noise sensitivity, and testing
  complexity for no measurable benefit once the overhead is removed.
- **No in-quantum rdtsc sampling.** Preemption during emulation is still
  counted as emulation. Utilization is therefore an upper bound — documented
  in the doc comment. Fixing this requires periodic sampling inside the
  emulation phase, which adds hot-path overhead for marginal diagnostic
  benefit.
- **No env vars, no feature flags.**

## Test strategy

- **Unit:** `PacerSnapshot::emulated_mhz/utilization/headroom` using `wall_ns`
  as denominator. Update existing tests to include the new field.
- **Unit:** Fresh `PacerStats` → snapshot has `wall_ns == 0` → derived metrics
  return 0.0.
- **Integration:** Run one quantum, verify `wall_ns > 0` after `end_quantum()`.
- **Integration:** `calibrate_overhead(nominal)` with a reasonable nominal
  returns a value ≤ `nominal / 4` (safety clamp).
- **Manual:** Re-run `paced_bench --seconds 10`. Target: reported MHz matches
  `total_cycles / wall_seconds` within 0.5%, both ≥ 149 MHz, verdict **OK**.
