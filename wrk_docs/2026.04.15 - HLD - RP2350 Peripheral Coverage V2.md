# RP2350 Peripheral Coverage — HLD V2

Companion to `2026.04.15 - HLD - RP2040 Peripheral Coverage V7.md`. That HLD is the
architectural template; this one lists the deltas for RP2350 and the Cortex-M33 /
ARMv8-M Mainline target. Read V7 first.

## Changes from V1

Round-1 review found three silicon-factual errors, four understated scope items,
and several collapse opportunities. V2 fixes:

- **NS alias stripping deleted** (V1 §5.2 was wrong — RP2350 enforces
  Secure/Non-Secure via ACCESSCTRL bus filtering, not an address-range alias).
- **Appendix B illustrative IRQ table deleted** (V1 table was wrong in ≥4 slots;
  the correct ordering pins to `crates/mdrp2350/src/irq.rs` in Phase 0a).
- **Fast-path gate deferred** — measure `paced_bench_rp2350` baseline in
  Phase 0, only introduce the gate if a regression is observed.
- **Phase 0 split into 0a (M33 exception / NVIC rework) and 0b (oracle prep)**,
  honestly budgeted at ~2 weeks. V1's "3–4 days" hid the NVIC/BASEPRI work.
- **Core-local IRQ routing** called out; dual-core `set_pending` is correct only
  for shared IRQs.
- **Phase 2 narrowed to UART0/SPI0/I2C0**; second instances deferred.
- **Phase 2+3 merged** into a single mixed-comms phase.
- **`trace_enabled` dropped as runtime flag**; `mmio_trace_rp2350` is a separate
  binary built with `cfg(feature = "mmio_trace")` hooking the bus at compile
  time, zero cost in normal builds.
- **Appendix C (DREQ table) deleted** — lives in `dreq.rs` when Phase 4 lands.
- Several sections collapsed to "See V7 §X" rather than restating.

## 1. Purpose

Expand `mdrp2350` MMIO coverage beyond the eight peripherals modelled today
(SYSINFO, RESETS, CLOCKS, ROSC, XOSC, PLL_SYS, PLL_USB, QMI — plus SIO, PIO,
PPB and the QSPI/XIP/boot-RAM plumbing) so firmware in the motivating corpus
(§3) runs to completion instead of falling into the `HashMap<u32, u32>`
fallthrough at `crates/mdrp2350/src/bus/mod.rs:98`.

Scope: **TICKS + TIMER0/TIMER1** (Phase 1), **UART0 + SPI0 + I2C0 + ADC + PWM**
(Phase 2, merged), **DMA** (Phase 3). Security block (OTP/SHA256/TRNG/
GLITCH_DETECTOR), POWMAN AON timer, HSTX, ACCESSCTRL, UART1/SPI1/I2C1, extra
DMA IRQs: **deferred** unless corpus evidence or mmio_trace evidence promotes
them (rollback plan: §9.3).

### Non-goals

- Full datasheet coverage.
- USB, ETM/TPIU, CORESIGHT_TRACE, TBMAN, BUSCTRL, SYSCFG, PSM.
- Non-pico-sdk runtimes, RISC-V Hazard3 cores, Non-Secure state firmware, SAU.
- Cycle-accurate peripheral timing finer than one sys_clk.
- RP2040 mirror. Impls live in `crates/mdrp2350/`.
- Backwards compatibility or migration.

## 2. Current state

`crates/mdrp2350/src/bus/peripherals.rs` covers SYSINFO, RESETS, CLOCKS, ROSC,
XOSC, PLL_SYS, PLL_USB, QMI. `bus/mod.rs` wires SIO, PIO, PPB. Everything else
round-trips through `peripheral_regs: HashMap<u32, u32>` with zero side effects.
No SRAM bank contention on RP2350 (CLAUDE.md). PPB NVIC is a stub — `ppb.rs:470`
returns 0 for external-IRQ priority, `:201`/`:332` are read/write blackholes.

## 5. Architecture

### 5.1 Peripheral pattern

**See V7 §5.1.** Inherent methods, no trait, `pub(crate)` sibling fields on
`Bus`, direct field dispatch. No changes for RP2350.

### 5.2 Security aliasing — deleted

**V1 was wrong.** Per RP2350 datasheet §2.1.2 (Bus security filtering) and
Tables 13/14, APB peripherals sit at `0x4000_0000–0x4FFF_FFFF` and AHB
peripherals at `0x5000_0000–0x5FFF_FFFF` — **one** address per peripheral;
security is enforced by the per-port bus filter driven by ACCESSCTRL, not by
a second aliased address range. The only split-address peripheral is SIO
(`SIO_BASE=0xd000_0000`, `SIO_NONSEC_BASE=0xd002_0000`, Table 15).

**V1 action: no NS-alias stripping.** V2 runs entirely in Secure state for
the §3 corpus; ACCESSCTRL and SAU modelling are deferred. `SIO_NONSEC_BASE`
is handled via the existing SIO address decode if pico-sdk touches it; the
Phase 0b bootrom trace (§4.2.9) confirms whether any non-trivial NS access
happens.

### 5.3 IRQ plumbing

**See V7 §5.2 for the drain-loop structure.** Widen `irq_pending` to `u64` to
cover 52 NVIC lines. `Nvic::set_pending` takes `u8` (52 < 256).

**RP2350 distinguishes shared vs core-local IRQs.** Datasheet §3.2: SIO
per-core IRQs — SIO_IRQ_FIFO, SIO_IRQ_BELL, SIO_IRQ_FIFO_NS,
SIO_IRQ_BELL_NS, SIO_IRQ_MTIMECMP — and the NS-variants of
IO_IRQ_BANK0/IO_IRQ_QSPI are **per-core inputs on the same IRQ number**:
the two cores observe different signals. Shared IRQs (TIMER0/1, UART, SPI,
I2C, DMA, PWM, ADC, etc.) assert on both cores.

`crates/mdrp2350/src/irq.rs` declares:

```rust
pub const IRQ_COUNT: u32 = 52;          // NVIC input count
pub const PERIPH_IRQ_COUNT: u32 = 46;   // silicon-connected; 46..51 hardwired 0
pub const CORE_LOCAL_IRQS: [u32; N] = [ /* SIO_IRQ_FIFO, BELL, MTIMECMP, FIFO_NS, BELL_NS, BANK0_NS, QSPI_NS — numbers pinned in Phase 0a */ ];
```

Drain dispatch checks membership in `CORE_LOCAL_IRQS` and routes to one core
only; otherwise both. Tests in `bus/ppb.rs` verify the split.

**Mid-quantum routing.** RP2350 `lib.rs` runs core 0's sub-quantum to
completion before core 1 (not interleaved like RP2040). Drain runs
**(a) between core-0 and core-1 sub-quanta** and **(b) at quantum end**, so
core-1 pending is fresh when it starts. Peripherals that assert during
core-0's run land on core 1 within one sub-quantum instead of waiting a
full quantum.

### 5.4 TICKS block

RP2350 factors the 1 µs tick generator out of WATCHDOG (RP2040) into a
dedicated peripheral at `TICKS_BASE = 0x4010_8000`. Six domains —
PROC0, PROC1, TIMER0, TIMER1, WATCHDOG, RISCV — each with `CTRL`, `CYCLES`,
`COUNT` registers. Default `CYCLES=12` produces a 1 µs tick from 12 MHz
`clk_ref` (datasheet §8.5, p.570).

TIMER0 and TIMER1 advance on their respective TICKS-generator edges; they
mirror the RP2040 TIMER shape (64-bit TIMELR/TIMEHR, 4 alarms,
INTR/INTE/INTF/INTS, lazy scheduling per V7 §5.3/§5.5). TICKS itself is
plain-storage (writes land, reads return stored).

**Invalidation path on TICKS write.** The `ticks.write32` path — not just
TIMER0/1 `write32` — must invalidate cached match cycles on TIMER0/1:

```rust
// In Bus::peripheral_write32 after ticks.write32:
if addr_is_ticks_cycles_write {
    self.timer0.invalidate_lazy();
    self.timer1.invalidate_lazy();
}
```

Failure mode without this: firmware reprograms TICKS `TIMER0_CYCLES`, cached
match fires at the old rate. Unit test: write `CYCLES=24`, arm 1 ms alarm,
verify fires at twice the default cycle count.

### 5.5 Per-cycle tick — fast-path gate DEFERRED

**V1 claim was wrong** — no fast-path gate exists on `mdrp2350` today. V2
does **not** introduce one. Rationale: V7's 49% throughput regression was
observed on RP2040 with a PIO-heavy benchmark; whether RP2350 shows the
same is unmeasured. Measuring first (§4.2.10) and introducing the gate
only if a regression is observed avoids preemptively adding
`all_peripherals_idle()` + `is_idle()` noise across every peripheral.

If Phase 1+ measurement shows >20% regression vs the §4.2.10 baseline,
introduce the gate via a follow-up HLD, not this one.

Tick path without gate: at the end of every `Emulator::step()` iteration,
`bus.tick_peripherals()` calls each stateful peripheral's `tick`, `pio.step_n(consumed, ...)` advances PIO, `bus.tick_dma()` runs DMA channels,
`drain_irqs` routes pending to NVIC. Per-cycle, every peripheral. Simple.

### 5.6 DMA — 16 channels

RP2350 DMA: 16 channels (datasheet §12.6.1, p.1095), DREQ table extended
with PIO2 + HSTX. V1 scope mirrors V7 §5.6.1:

- 16 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- `RING_SIZE`/`RING_SEL`, `CHAIN_TO`, `CH_ABORT`.
- **`INTE0`/`INTS0`, `INTE1`/`INTS1` only.** RP2350 silicon has four DMA
  IRQ lines (`DMA_IRQ_0..3`); V2 ships two. Promote to four if Phase 3
  trace shows `INTE2`/`INTE3` written. No per-IRQ routing matrix in V2.
- Flat arbitration (lowest-channel-wins). Promote to tiered only if
  trace evidence shows `HIGH_PRIORITY` usage.
- **Not in V2**: CRC sniff, byte-swap, `DMA_IRQ_2`/`DMA_IRQ_3` routing.

Emulator simplification on write visibility: **See V7 §5.6.**

## 7. Testing

**Oracle hierarchy** — see V7 §7 for the shape. Primary for this HLD:
`silicon_periph_diff_rp2350` with new scenarios per phase.

**Runtime budget.** Single `Session::auto_attach` reused. ~1 s/scenario.
~80 new scenarios → ~80 s silicon time.

**Authoring budget.** Scenario authoring (setup sequence + register
observe list + pin list + silicon reverify) runs 30–60 minutes per scenario
in practice. 80 scenarios = 40–80 engineering hours, dominant over
implementation time for Phases 2 and 3. Budget accordingly in
`wrk_journals/`.

**Transient-handshake blind spot (V7 §9.1 and §9.5 reprise).** DMA `BUSY`,
UART `FR.BUSY`, TIMER `ARMED`, `CH_AL1_CTRL.BUSY` toggle 0→1→0 within one
scenario window — end-state diff misses them. Mitigation: `min_sysclks`
lower bound per scenario catches "completed implausibly fast"; intermediate
halt-probe sampling is not added in V2 unless DMA chain bugs surface it.

**Flake policy.** See V7 §7; retry wrapper ported in Phase 0b.

## 9. Risks & open questions

**9.1 NVIC scope is a multi-day task.** Phase 0a lands ISER/ICER/ISPR/ICPR/
IABR/IPR per-core (6 banks × 2), plus BASEPRI folding into
`execution_priority`, plus external-IRQ poll in step. Mitigations: the
journal `wrk_journals/` records daily progress; if Phase 0a exceeds 10
working days the plan is reviewed before starting 0b.

**9.2 ICSR poll commit `2ed1c7c` must be validated.** That commit added
ICSR polling for PendSV/SysTick, which Phase 0a extends to external IRQs.
Before Phase 0a, confirm `silicon_isr_diff_rp2350`'s PendSV/SysTick
scenarios are green on the post-`2ed1c7c` tree (CLAUDE.md item 10 flagged
them as "expected to fail" pre-commit).

**9.3 Security-block rollback.** If Phase 0b `mmio_trace_rp2350` shows
firmware accessing OTP, SHA256, TRNG, GLITCH_DETECTOR, POWMAN, or
ACCESSCTRL with non-trivial expectations, add an inline plain-storage stub
with the correct reset value (same day; ≤2 hours per peripheral). Do not
open a new phase. If the access is read-and-compare-against-non-zero and
the register has active silicon behaviour, escalate to a per-peripheral
mini-HLD; mid-Phase-N stall is acknowledged.

**9.4 Lab-rig probe contention.** `test_silicon` on RP2350 and any `mdrp2040`
silicon oracle work share the Pico probe. Mitigation: probe bookings
tracked in a top-level scratchpad; long soaks announced before they start.
No code-side fix.

**9.5 Probe failure.** No fallback oracle. Acknowledged (same as V7 §9.5).

**9.6 Coexistence with in-progress RP2040 V7.** `bus/mod.rs`,
`core/decode.rs`, `core/exceptions.rs` on `mdrp2040` have unstaged edits
and `mmio_trace_rp2040.rs` is an untracked new file. V2 Phase 0b's
`mmio_trace_rp2350.rs` port waits for RP2040's final shape to land; do not
fork early. Any RP2040 field renames on shared types in `mdpicoem-common`
force review of this HLD's §5.1 claim that the pattern transfers.

**9.7 CORESIGHT / DAP-attached artefacts.** `silicon_periph_diff_rp2350`
runs with probe attached; some observables (SysTick calibration behaviour,
DMA `DBG_CTRL`, `clk_peri` gating affecting debug) may differ when DAP is
connected vs disconnected. V2 acknowledges this is a systemic silicon-side
caveat; scenarios avoid registers that the datasheet flags as
debug-dependent (none of the §3 corpus touches any). If a Phase 1+
divergence reproduces only with DAP attached, record in `wrk_journals/`
and revisit.

**9.8 `paced_bench_rp2350` floor is numeric.** §4.2.10 pins the number in
a journal entry at Phase 0b exit. Phases 1+ compare against that number,
not against "no regression" hand-waving. If a phase lands a >5% regression,
investigate before proceeding; >20% halts the phase until addressed.

**9.9 TICKS cross-invalidation.** If a future peripheral also depends on
TICKS tick rate (WATCHDOG when modelled; SYSTICK calibration), it must be
added to the invalidation set in §5.4. Tracked in `crates/mdrp2350/src/peripherals/ticks.rs` header comment.

**9.10 Scenario-authoring dominates Phase 2/3 time.** Per §7 authoring
budget — 40–80 hours is realistic, infrastructure is not the bottleneck.
