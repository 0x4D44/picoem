# RP2040 Peripheral Coverage — HLD V5

Supersedes V4. Incorporates Round-4 team review of 2026-04-15. Three localized fixes: Phase 0 exit criterion reachability, ISR-count vector[0] MSP, PIO fast-path preservation. Plus two YAGNI cuts (HIGH_PRIORITY moved out of V1; §9 compressed).

## 1. Purpose

Add emulation for RP2040 peripherals the motivating firmware corpus (§3) touches, so `mdrp2040` runs those binaries to completion instead of falling into `HashMap<u32, u32>` fallthrough.

Scope: **TIMER + WATCHDOG_TICK** (Phase 1), **UART, SPI, I2C** (Phase 2), **ADC, PWM** (Phase 3), **DMA** (Phase 4).

### Non-goals

- Full datasheet coverage. Implement the register set the corpus actually touches.
- WATCHDOG reset logic, RTC, USB, VREG, TBMAN, BUSCTRL, SYSCFG, PSM. HashMap fallthrough until a concrete firmware demands.
- Non-pico-sdk runtimes.
- Cycle-accurate peripheral timing finer than one sys_clk.
- RP2350 mirror. Impls live in `crates/mdrp2040/`.
- Backwards compatibility or migration.

## 4. Oracle strategy

Hardware: physical RP2040 on the lab rig, Pico debug probe back-to-back.

### 4.1 `probe_diff_rp2040`

Port `crates/mdpicoem-harness/src/bin/probe_diff_rp2350.rs`. Filter is probe-side only; `qemu_diff_m0plus.rs:291` stays strict. `probe_diff_rp2040` admits the Thumb-32 subset (`BL`, `MRS`, `MSR`, `DSB`, `DMB`, `ISB`).

**Generator audit budget: 2 days.** If `thumb32_gen.rs` doesn't emit the subset and writing the encoder exceeds 2 days, Phase 0 slips and the slip is journaled.

### 4.2 `silicon_periph_diff_rp2040`

Port `silicon_periph_diff_rp2350.rs`. Shape = RP2350's `PeriphScenario` + one u32:

```rust
pub struct PeriphScenario {
    pub name: &'static str,
    pub setup: &'static [(u32, u32)],
    pub max_sysclks: u32,
    pub min_sysclks: u32,            // NEW
    pub observe: &'static [(u32, u32)],
    pub observe_pins: u32,
    pub custom_sled: Option<&'static [u8]>,
}
```

`min_sysclks` catches "completed too fast" as a soft assertion. Intermediate-state machinery added in Phase 4 only if the DMA ring off-by-one bug class actually surfaces.

**Timing is a soft assertion.** SysTick programmed at scenario start; single-run window `[min_sysclks, max_sysclks]` report-only outside bounds. No framing cancellation.

### 4.3 MMIO capture — via the emulator bus

`crates/mdpicoem-harness/src/bin/mmio_trace_rp2040.rs` loads firmware into the emulator, flips a `Bus::trace_enabled` flag, runs for a caller-specified cycle budget. Hooks all six access methods (`read8/16/32` + `write8/16/32`) AND internal peripheral dispatch paths (`peripheral_read32`, `sio_*`, `ppb.*`). Emits `(addr, size, R/W, core, pc)` to stdout.

**Limitation** (deliberate): the emulator has gaps. Firmware touching unmodelled peripherals often spins or faults shortly after. That truncation IS the signal — the trace's tail shows what to implement next.

### 4.4 Phase 0 exit criteria

1. `probe_diff_rp2040 --fuzz 10000` green, including Thumb-32 subset.
2. `silicon_periph_diff_rp2040` runs a known-good SIO GPIO toggle scenario green.
3. Three deliberately-broken scenarios print FAIL with correct `first_divergence`:
   - GPIO: wrong `SIO_GPIO_OUT` bit.
   - TIMER: `TIMERAWL` read-path returns 0.
   - MMIO store: `XOSC_CTRL` write swallowed.
4. **Trace surface-and-iterate.** `mmio_trace_rp2040 --cycles 1_000_000 hello_timer.elf` emits a non-empty trace of ≥500 peripheral MMIO entries. The trace's **tail** — the last registers firmware reads before spinning in a polling loop — identifies the pre-TIMER peripheral gap (almost certainly CLOCKS/XOSC/PLL ready-state handshake; see §5.3). Resolving that gap is the final Phase 0 task; re-run until the trace reaches `TIMER_BASE + 0x28` (`TIMERAWL`) reads, confirming firmware progressed through `runtime_init_clocks` into `busy_wait_us_32`.

This is explicitly iterative: V4 assumed the first trace would reach TIMERAWL, which Round 4 showed is unrealistic (runtime_init_clocks polls for PLL_LOCK/XOSC_STABLE/CLOCKS._selected). Phase 0 exit includes closing whichever pre-TIMER gap the trace surfaces. Expected gap: emulator-init reset state semantics for XOSC/PLL/CLOCKS — see §5.3.

### 4.5 Triage (silicon ≠ emulator)

1. Reproduce on silicon with scenario/seed.
2. Check probe-rs by reading `SIO_BASE + 0x1C` (`GPIO_OUT_XOR`) — not RESETS-gated, reset value 0. Non-zero = probe-rs suspect.
3. Check silicon health via `probe_verify_rp2040` round-tripping a known-correct-in-emulator register.
4. Only after (2) and (3) clear: assume emulator bug.

Divergences recorded in `wrk_journals/` with verdict + seed.

## 5. Architecture

### 5.1 Peripheral pattern — inherent methods, no trait

Delete `mdpicoem-common::Peripheral`. Each peripheral is a struct in `crates/mdrp2040/src/peripherals/<name>.rs` with inherent methods:

```rust
pub struct TimerRegs { /* fields */ }

impl TimerRegs {
    pub fn read32(&mut self, offset: u32) -> u32 { ... }
    pub fn write32(&mut self, offset: u32, value: u32, alias: u32, irqs: &mut u32) { ... }
    pub fn tick(&mut self, irqs: &mut u32) { ... }   // only if stateful-per-cycle
    pub fn is_idle(&self) -> bool { ... }            // for fast-path gate; default true if no tick method
}
```

No trait. Dispatch is a match arm in `Bus`. Consistency by review.

**Ownership.** Peripheral fields and `irq_pending` are `pub(crate)` sibling fields on `Bus`. No accessor methods that borrow `&mut self`. Dispatch is direct field access; split-borrow sees disjoint `&mut`.

### 5.2 IRQ plumbing

One field on `Bus`: `pub(crate) irq_pending: u32`. 26 IRQs (Appendix B). Peripherals assert `*irqs |= 1u32 << IRQ_TIMER_IRQ_0;`. IRQ constants are `u32` to avoid the `1u8 << N (N≥8)` UB footgun.

**Level semantics.** Peripherals re-assert each cycle the condition holds. When firmware clears the source (W1C on INTR, drains the FIFO), the peripheral observes the cleared state on its next read/tick and stops asserting that cycle onward. NVIC pending latching is unchanged.

**Pulse sources** (TIMER alarm match): asserted exactly once at the match cycle via lazy-scheduled events (§5.5).

**Drain per inner-cycle iteration.** Inlined in `Emulator::step` (or the slow-path loop body per §5.5):

```rust
if self.bus.irq_pending != 0 {
    let raised = std::mem::replace(&mut self.bus.irq_pending, 0);
    for irq in 0..IRQ_COUNT {
        if raised & (1u32 << irq) != 0 {
            self.cores[0].nvic.set_pending(irq as u8);
            self.cores[1].nvic.set_pending(irq as u8);
        }
    }
}
```

### 5.3 RESETS and clock gating

**RESETS — Bus-level guard.** Before dispatching to a peripheral, `Bus::peripheral_read32`/`peripheral_write32` check `self.resets.is_held(RESET_BIT_X)`; held peripherals return 0 / no-op without reaching the peripheral module. Tick path likewise short-circuits.

**Emulator reset state = post-bootrom state.** Not just default register values — an active assertion that the CLOCKS subsystem behaves as if bootrom ran:

| Register/state | Emulator value at reset |
|---|---|
| `clk_sys` | 125 MHz |
| `clk_peri` | `clk_sys` |
| `clk_adc` | 48 MHz |
| `clk_ref` | 12 MHz (XOSC) |
| `XOSC.STATUS.STABLE` | 1 |
| `PLL_SYS.CS.LOCK` / `PLL_USB.CS.LOCK` | 1 |
| `CLOCKS.clk_*_selected` | mirrors `CTRL.AUXSRC` |
| RESETS | released for commonly-used peripherals |

**Furthermore, these registers must respond correctly to firmware reprogramming** (this is the Round-4 gap Phase 0 will surface):
- `XOSC.CTRL.ENABLE` write → `STATUS.STABLE` transitions to 1 **within 1 cycle** (datasheet says ≥1 ms; emulator shortcut is "eventually 1" which firmware's `while (!STABLE);` accepts).
- `PLL_SYS.PWR` write releasing reset → `CS.LOCK` transitions to 1 within 1 cycle.
- `CLOCKS.clk_*_ctrl.AUXSRC` write → `clk_*_selected` reflects the new source within 1 cycle.

Phase 0 audits whether the existing XOSC/PLL/CLOCKS models already do this. Trace evidence will tell us. If a model doesn't, Phase 0 fixes it as part of closing exit criterion 4.

| Peripheral | Clock | V1 treatment |
|---|---|---|
| TIMER | `clk_ref / WATCHDOG_TICK.CYCLES` (1 µs) | Lazy; cached fire-cycles invalidated on WATCHDOG_TICK write. `CYCLES=0` → TIMER does not advance (matches silicon; divide-by-zero guarded). |
| ADC | `clk_adc` (48 MHz default) | Fixed-point `adc_phase += ADC_HZ; if adc_phase >= SYS_HZ { adc_phase -= SYS_HZ; adc.tick(); }`. Phase zeroed on `ClockTree` recompute. |

Other peripherals = `clk_sys` in V1.

### 5.4 Atomic aliases and byte/halfword access

**Alias per-register.** `write32(offset, value, alias, irqs)`. Peripheral decides:
- **Plain storage**: `apply_alias_rmw(&mut stored, value, alias)` helper.
- **Side-effect** (TIMER INTR W1C, UART_DR FIFO push, DMA CH_TRIGGER): register-specific. TIMER_INTR alias-BITSET maps to W1C on set bits. UART_DR alias is silicon-unspecified; emulator treats as plain write.

**Narrow-access dispatch.** Only peripherals with byte/halfword-significant registers (UART_DR, SPI_DR, I2C_IC_DATA_CMD) opt into `Bus::read8/write8/read16/write16` match arms. Others fall back to existing word-RMW.

### 5.5 Per-cycle tick — fast path preserved

Generalise the existing slow-path loop at `crates/mdrp2040/src/lib.rs:297-314`. **Critical: keep the PIO fast-path gate.** `paced_bench_rp2040` has a documented ~49% throughput regression without it.

Generalisation: the gate predicate broadens from "PIO idle" to "PIO idle AND no non-lazy peripheral active". When true, bulk-advance; when false, per-cycle loop.

```rust
fn step(&mut self) -> u64 {
    let consumed = self.cpu_step_inner();

    let pio_idle = self.bus.pio_all_idle();
    let peri_idle = self.bus.all_peripherals_idle();
    let any_irq = self.bus.irq_pending != 0;

    if pio_idle && peri_idle && !any_irq {
        // Fast path: nothing observable happens per-cycle. Bulk.
        self.bus.advance_lazy_scheduled(consumed);   // TIMER alarms, ADC if active
        self.bus.update_gpio();
    } else {
        // Slow path: per-cycle observable state changes.
        for _ in 0..consumed {
            self.bus.tick_peripherals();             // PWM, ADC, UART, SPI, I2C
            self.tick_pio_and_route_irqs_single();   // step_n(1, ...) + pending_irqs()
            self.bus.update_gpio();
            self.drain_pending_irqs_to_cores();
        }
    }
    consumed
}
```

**`Bus::all_peripherals_idle()`** is a single method returning the AND of `is_idle()` getters — cheap; each peripheral's `is_idle` is one-liner on a couple of fields. Peripherals with no `tick` method (TIMER, RTC, WATCHDOG_TICK) are trivially idle. No `active_tickers` bitmap.

**`advance_lazy_scheduled`** on the fast path advances `master_cycle` by `consumed` and schedules any alarm IRQs whose match-cycle falls in the range; they go into `irq_pending` and get drained at start of next step. Deterministic.

**PIO IRQ routing via accessor.** `PioBlock::step_n(n, gpio_in)` stays as-is. After the per-cycle `step_n(1, ...)` (slow path) or after the bulk `step_n(consumed, ...)` via `advance_lazy_scheduled` (fast path — but fast path only runs when PIO idle, so no IRQ to route), Emulator reads `pio.pending_irqs()` and ORs into `bus.irq_pending`:

```rust
fn tick_pio_and_route_irqs_single(&mut self) {
    let gpio_in = self.bus.gpio_in();                      // &self, returns u32
    self.bus.pio[0].step_n(1, gpio_in);
    self.bus.pio[1].step_n(1, gpio_in);
    let bits = self.bus.pio[0].pending_irqs() | (self.bus.pio[1].pending_irqs() << 4);
    self.bus.irq_pending |= map_pio_bits_to_nvic(bits);    // NVIC IRQs 7..10
}
```

`pending_irqs() -> u32` is a new **trivial getter** on `PioBlock` — `self.irq_flags as u32`. Zero behaviour change; only exposes existing state.

### 5.6 DMA — bus master

`Dma` is a named field on `Bus`. Tick via owned swap:

```rust
pub fn tick_dma(&mut self) {
    let mut dma = std::mem::take(&mut self.dma); // Dma: Default
    dma.tick(self);
    self.dma = dma;
}
```

`Dma::tick(&mut self, bus: &mut Bus)` takes a DREQ snapshot into a local (`let dreqs = bus.collect_dreqs();`, returns `u64` via `&self`) before issuing any `bus.read32/write32`, avoiding cross-borrows.

**Ordering per cycle:**
1. PWM/ADC/UART/SPI/I2C tick (produces DREQ).
2. PIO tick + IRQ route (PIO DREQ).
3. `tick_dma` — DREQ snapshot → transfers.
4. `update_gpio`, drain `irq_pending`.

**Write visibility.** DMA writes take effect the cycle issued (emulator simplification; real AHB is N+1 due to address/data phases). Peripherals observe on their next tick. No corpus scenario distinguishes.

### 5.6.1 DMA V1 scope

- 12 channels, transfer sizes 1/2/4 bytes.
- `CTRL`, `READ_ADDR`, `WRITE_ADDR`, `TRANS_COUNT`, `TREQ_SEL`.
- **`RING_SIZE` / `RING_SEL`** — `audio_i2s` requires.
- **`CHAIN_TO`** — full chained triggering. When `TRANS_COUNT` reaches 0 on a channel with `CHAIN_TO != self`, enable the target. `audio_i2s` uses reloader-channel pattern.
- **`CH_ABORT`** — clears `BUSY` immediately. pico-sdk polls `BUSY`; cycle-exact doesn't matter.
- `INTE0`/`INTE1`, `INTS0`/`INTS1` W1C, `DMA_IRQ_0`/`DMA_IRQ_1`.
- **Priority**: flat arbitration — lowest-channel-wins, no HIGH_PRIORITY tier. Phase 0's `mmio_trace_rp2040` on `audio_i2s` confirms whether any channel sets HIGH_PRIORITY; if the trace shows the bit unused, this is correct as-is. If the trace shows HIGH_PRIORITY usage, promote to two-tier arbitration in Phase 4. Starts in the "Not in V1" list; moves in only if trace-driven evidence justifies.
- **Not in V1**: CRC, sniff, byte-swap, read/write error IRQs, ring across non-aligned base, **HIGH_PRIORITY two-tier arbitration**.

**DREQ table.** Appendix C. `crates/mdrp2040/src/dreq.rs` lands in Phase 4 only.

### 6.1 ISR-count scenario mechanism (Phase 1)

Uses existing `PeriphScenario.custom_sled` + `setup`; no new oracle binary.

**Memory layout for the scenario** (scenario runner uses this canonical layout):

```
0x20000000 : vector[0]  — initial MSP (= 0x2003F000, top of SRAM minus slack)
0x20000004 : vector[1]  — reset handler (unused; scenario sets PC directly)
0x20000044 : vector[17] — TIMER_IRQ_0 handler (= 0x20001000 + 1, Thumb bit set)
...        : other vectors zero
0x20001000 : handler code (from custom_sled byte offset 0)
0x20001100 : main code — WFE loop with BKPT after first wake (from custom_sled offset 0x100)
0x2003F000 : MSP (top of stack grows down)
```

**`setup` sequence** (order matters):
1. Write vector table entries (≥ vector[0] initial MSP + vector[N] handler per IRQ under test).
2. Write `TIMER.ALARM0` arm value.
3. Write `TIMER.INTE |= 1 << N` enable source.
4. Write `NVIC.ISER[0] |= 1 << IRQ_TIMER_IRQ_0` enable at NVIC.
5. Write `PPB.VTOR = 0x20000000`.

**`custom_sled`** contains handler bytes at offset 0 and main-loop bytes at 0x100.

**Scenario runner** sets MSP from vector[0], PC to `0x20001100 | 1`, clears PRIMASK, runs until BKPT in main code after handler fires.

**`observe`** reads `0x20001300` (SRAM counter), asserts equals silicon.

If Phase 1 proves the shape insufficient, promote to `silicon_isr_diff_rp2040` (mirrors RP2350) — but don't build speculatively.

## 9. Risks & open questions

**9.1 SysTick window is soft.** `[min_sysclks, max_sysclks]` catches catastrophic miscount but cannot distinguish N vs N±1 iterations when window width exceeds one iteration cost. Phase 4 DMA ring off-by-one is the canonical case; Phase 4 red-path scenario is the mitigation. Intermediate-state machinery added then if required.

**9.2 Bootrom re-hit.** Phase 1+ unblocks firmware into bootrom paths (`flash_get_unique_id`, `_reset_to_usb_boot`) colliding with the SSI stub. Mitigation: `load_image` bypasses bootrom. Separate HLD when motivated.

**9.3 HashMap fallthrough wrongness.** Firmware reading USB_CTRL/BUSCTRL/VREG expecting specific reset values gets 0. `mmio_trace_rp2040` surfaces these; per-firmware resolution (promote or stub the register's reset value). Logged in `wrk_journals/`.

**9.4 Concurrent workspace collision on `Bus`.** Land `irq_pending`, `tick_peripherals` with fast-path gate, RESETS guard, PIO IRQ routing, trace flag, and the lazy-advance hooks as a **single atomic commit** before peripheral-specific code.

**9.5 Probe rig failure.** No fallback oracle; rig down → phase halts. `qemu_diff_m0plus` keeps running but doesn't exercise peripherals. Acknowledged.

**9.6 CLOCKS/XOSC/PLL ready-state semantics.** Round-4 surfaced that pico-sdk `runtime_init_clocks` busy-waits on XOSC STABLE / PLL LOCK / CLOCKS `_selected`. Phase 0's exit criterion 4 (§4.4) makes closing this gap part of Phase 0, surfaced by the trace. Expected effort: 1–2 register model tweaks in `bus/clocks.rs`.

**9.7 Scenario-authoring note.** Emulator is single-threaded; cross-core same-cycle APB writes resolve core-0-wins deterministically, silicon AHB is undocumented ordering. Don't author `silicon_periph_diff` scenarios that rely on cross-core APB write ordering.

