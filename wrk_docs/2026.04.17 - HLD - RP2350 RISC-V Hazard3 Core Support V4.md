# RP2350 — RISC-V Hazard3 Core Support (V4)

**Date:** 2026-04-17
**Crate:** `crates/mdrp2350/`
**Supersedes:** V3.
**Companion audit:** `wrk_docs/2026.04.16 - HLD - RP2350 Feature Coverage Audit.md`
**Review artefacts:** three rounds of multi-reviewer pass. V4 fixes a wfi-wake spec regression introduced in V3, corrects the `misa` value (V3 erroneously included U/S bits we don't support), fixes the `mcountinhibit` reset value, splits MTIP/MSIP from the external-IRQ bitmap path, drops the unsafe `Box::new_zeroed()` recommendation, splits `sc.w` from `amo*.w` outside-reservable behaviour, switches QEMU to `-machine none`, expands the IRQ scenario taxonomy, and pre-registers the P0 decision tree.

## 1. Goal

Run an RP2350 RISC-V firmware binary selected by `EmulatorBuilder::arch(Arch::RiscV)`. First-cut target: a **bare-asm `blinky-riscv.bin`** (no SDK, no libc, no B-extension use) toggling a GPIO pin.

**Honest scope statement.** V1 ships the enum, plumbing, ISA core, atomics, IRQ controller, and a developer-smoke firmware. **No SDK-built RP2350 RISC-V firmware will run** (Q4). V1 is a vehicle for landing the enum + plumbing + base ISA, not a usable production emulator.

## 2. Background

RP2350 ships **two** dual-core complexes; selection is by OTP fuse + POWMAN at power-up; only one runs at a time.

- **Arm path** — 2× Cortex-M33. Implemented.
- **RISC-V path** — 2× **Hazard3** (Wren6991/Hazard3). Not implemented.

Hazard3 extensions (per Hazard3 csr.adoc + custom_extensions.adoc):

- RV32I + M + A + C; Zicsr; Zifencei.
- B-extension parts: Zba, Zbb, Zbs, Zbkb, Zbc.
- Zcmp + Zcb.
- Custom: `h3.bextm`, `h3.bextmi`, `h3.block`, `h3.unblock`; custom CSRs incl. `h3.misa` at `0xBF1`.

**Hazard3 upstream A-extension spec is empty** (`(TODO)` in instruction_pseudocode.adoc). The RP2350 datasheet §3.8.1.13 + §2.1.6.2 are the only specs for atomics behaviour; we lock to them.

The two paths share Bus, SIO, peripherals, clocks, DMA, PIO, memory map. SIO already exposes RISC-V observables as **storage only**: `RISCV_SOFTIRQ`, `MTIME`/`MTIMECMP`, `mtime_match_asserted`. Wiring those into the CPU `mip` is P4 work.

We do not run the bootrom; ARCHSEL/POWMAN handover stays unmodelled.

## 3. Non-goals

- **U-mode, S-mode, PMP** — no privilege model beyond M-mode for V1.
- **Hazard3 debug module** — silicon oracle deferred (§8 Q3, gated on P0).
- **Bootrom dispatch, ARCHSEL, POWMAN.**
- **B-ext (Zba/Zbb/Zbs/Zbkb/Zbc), Zcmp, Zcb.** Deferred. Pinned firmware target is bare-asm rv32imac.
- **Custom Hazard3 instructions** `h3.bextm`/`h3.bextmi`. Deferred.
- **`h3.block` wake on `h3.unblock`.** V1 decodes both as no-ops (HINT-space `slt x0,*,*`). Firmware using `h3.block` to await `h3.unblock` will deadlock — accepted V1 limitation.
- **`fence` / `fence.i`** — no-op (no decoded-op cache on RISC-V side). Tripwire in §4.8.
- **A-extension reservation precision under threaded cores.** Serial-interleave only; tripwire in §4.7.
- **Toolchain dependency.** `gen_blinky_riscv.py` emits raw bytes (§4.5).
- **Performance counters** beyond `mcycle`/`minstret`.

## 4. Design

### 4.1 Cores — enum with shim-based migration

```rust
// crates/mdrp2350/src/lib.rs
pub enum Cores {
    Arm([CortexM33; 2]),
    RiscV([Hazard3; 2]),
}

impl Cores {
    pub fn expect_arm(&self)         -> &[CortexM33; 2];
    pub fn expect_arm_mut(&mut self) -> &mut [CortexM33; 2];
    pub fn expect_riscv(&self)       -> &[Hazard3; 2];
    pub fn expect_riscv_mut(&mut self) -> &mut [Hazard3; 2];
    pub fn is_arm(&self)   -> bool;
    pub fn is_riscv(&self) -> bool;
}

pub struct Emulator {
    pub cores: Cores,
    pub bus: Bus,
    pub clock: Clock,
    pub step_quantum: u32,
}
```

**Public API of `Emulator` — preserved as shims (V3) to shrink P1a:**

```rust
pub fn core(&self, id: usize) -> &CortexM33     { &self.cores.expect_arm()[id] }
pub fn core_mut(&mut self, id: usize) -> &mut CortexM33 { &mut self.cores.expect_arm_mut()[id] }
pub fn core_riscv(&self, id: usize) -> &Hazard3;
pub fn core_riscv_mut(&mut self, id: usize) -> &mut Hazard3;
```

`expect_arm()` / `expect_arm_mut()` panic on a RiscV emulator. Documented programmer-error contract.

**Migration shape — actual count (V4 corrected).** Repository grep for `\.cores\[` inside workspace crates yields **~135 occurrences across 7 files** (V3 said 50–80; that was wrong). Breakdown: ~14 in `mdrp2350`, ~38 in `mdpicoem-harness`, balance in `mdrp2040` (unrelated to this work). The shimmed-API call sites (`emu.core(i)…`) need no rewrite. Direct-field-access sites need:

```
- emu.cores[i].regs.r[x] = v;
+ emu.cores.expect_arm_mut()[i].regs.r[x] = v;
```

P1a PR description must include the literal sed pattern so reviewers can verify mechanically. Ship in a single morning to minimize concurrent-branch friction (CLAUDE.md multi-agent note).

**Borrow-checker hazard for hoisting.** A naive hoist like

```rust
let arm = emu.cores.expect_arm_mut();           // borrows emu.cores mutably
for i in 0..2 {
    arm[i].step(&mut emu.bus);                  // ❌ second mut borrow of emu
}
```

does not compile — `expect_arm_mut()` borrows the whole `Cores`, which goes through `&mut self` on `Emulator`, conflicting with `&mut emu.bus`. The fix is to destructure once:

```rust
let Cores::Arm(arm) = &mut emu.cores else { unreachable!() };
let bus = &mut emu.bus;                         // independent field, OK
for i in 0..2 { arm[i].step(bus); }
```

The internal `step_pair_arm` / `step_pair_riscv` free functions take `&mut [CoreT; 2]` and `&mut Bus` as separate parameters, so they don't hit this. External harness loops that mix core access with bus writes must use the destructure pattern.

**`Emulator::wake_checks`** dispatches with explicit match, no trait:

```rust
fn wake_checks(&mut self) {
    let bus = &mut self.bus;
    match &mut self.cores {
        Cores::Arm(cs) => for c in cs {
            let id = c.id() as usize;
            if c.wfe_waiting && bus.event_flag[id] {
                bus.event_flag[id] = false;
                c.wfe_waiting = false;
            }
        },
        Cores::RiscV(cs) => for c in cs {
            // wfi wakes when (mip & mie) != 0. mstatus.MIE is ignored
            // for the wake decision (RV-priv §3.3.2 + RP2350 datasheet
            // §3.8.1 wfi page). mstatus.MIE/mie still gate trap delivery.
            // V3 said `mip != 0` — wrong; V4 reverts.
            if c.wfi_parked && (c.mip() & c.mie()) != 0 {
                c.wfi_parked = false;
            }
        },
    }
}
```

**`Emulator::step`** (free functions, no trait):

```rust
pub fn step(&mut self) -> u64 {
    self.bus.master_cycle = self.clock.cycles;
    let target = self.clock.cycles + self.step_quantum as u64;
    match &mut self.cores {
        Cores::Arm(cs)   => step_pair_arm(cs, &mut self.bus, target),
        Cores::RiscV(cs) => step_pair_riscv(cs, &mut self.bus, target),
    }
    self.clock.advance(self.step_quantum as u64);
    self.tick_peripherals(self.step_quantum);
    if self.cores.is_arm() { self.tick_systick(); }
    if self.cores.is_riscv() { self.fan_out_riscv_irqs(); }
    self.wake_checks();
    self.clock.cycles
}
```

### 4.3 Reset

`Emulator::reset` is an outer arch match. Bus reset (RESETS, clocks, peripherals, SIO) is shared verbatim.

**Arm arm** — unchanged.

**RISC-V arm:**

| State | Reset value | Source |
|---|---|---|
| `x0..x31` | 0 | RV-priv |
| `pc` | `0x0000_0000` | Hazard3 RTL `RESET_VECTOR` default; RP2350 maps bootrom there. **(Q1 resolved.)** |
| `mhartid` per hart | core 0 → 0, core 1 → 1 | RP2350 datasheet §3.8.5 line 17688. **(Q2 resolved.)** |
| `mstatus` | 0 | M-mode, MIE=0, MPIE=0, MPP=00 |
| `mtvec` (CSR-readable value) | **`0x0000_1FFD`** | BASE=`0x1FFC` + MODE=Vectored=1; bit 1 hardwired 0. RP2350 datasheet table 373 reset value 0x1FFF, with bit 1 RAZ/WI giving stored 0x1FFD. **(V3 said `0x1FFC` — that was the BASE field, not the stored value.)** |
| `mcountinhibit` | **`0b101`** | Bits CY=0 and IR=2 inhibited. Hazard3 csr.adoc :369. **(V3 said `0b11` — wrong; bit 1 is reserved.)** Firmware writes 0 to start counters. |
| `meicontext.noirq` | 1 | Hazard3 csr.adoc reset value |
| `mtval` | hardwired 0 | Hazard3 csr.adoc + RP2350 datasheet §3.8.4.1 line 17569 — Hazard3 does NOT store fault addresses. P2 implementers must not write to it. |
| `mconfigptr` (CSR 0xF15) | hardwired 0 | RV-priv 1.12 mandatory; Hazard3 csr.adoc :79. Read-only constant. |
| `misa` | **`0x4080_1105`** | MXL=01 (bit 30) + X (bit 23, non-standard ext present, mandatory for Hazard3 customs) + I (bit 8) + M (bit 12) + A (bit 0) + C (bit 2). **No U-bit (20), no S-bit (18), no B-bit (1)** — all out of V1 scope. **(V3 said `0x4094_1105` which included U+S bits we don't support.)** |
| `h3.misa` (CSR `0xBF1`) | 0 | Storage-only for V1 |
| All other CSRs | 0 | |

**Implication of `mtvec` reset.** Any trap before firmware sets MTVEC dispatches into the bootrom alias at `0x1FFC`. P2 unit tests must set MTVEC explicitly, or chase phantom traps.

### 4.5 ISA scope — bare-asm rv32imac for V1

| Feature | V1? | Notes |
|---|---|---|
| RV32I base | Yes | All loads/stores, ALU, branches, jal/jalr, lui/auipc, fence (no-op). |
| M | Yes | mul/mulh/div/rem; div-by-zero per RISC-V spec. |
| A | Yes | lr.w, sc.w, amo*.w. See §4.7. |
| C | Yes | Required for any rv32imac toolchain output. |
| Zicsr | Yes | CSR dispatch; rules below. |
| Zifencei | Yes | No-op for V1; tripwire for future cache. |
| Zba/Zbb/Zbs/Zbkb/Zbc, Zcmp, Zcb | No | Follow-up. |
| `h3.bextm`/`h3.bextmi` | No | Follow-up. |
| `h3.block`/`h3.unblock` | Decode-tolerant no-op | HINT-space `slt x0, x0, *`. Firmware using `h3.block` deadlocks; accepted. |
| `misa` read | Yes | `0x4080_1105`. |

**SDK `-march`** = `rv32ima_zicsr_zifencei_zba_zbb_zbs_zbkb_zca_zcb_zcmp` (pico-sdk issue #1937). V1 ships only `roms/rp2350/blinky-riscv.bin` from `gen_blinky_riscv.py`.

**CSR trap rules** (V4 — V3 missed the `csrrw` rd=x0 case):

| Case | Behaviour |
|---|---|
| Unimplemented CSR address | `mcause=2` (illegal instruction) |
| `csrrw` to read-only CSR (bits `[11:10]==0b11`) — even with `rd=x0` | `mcause=2`. The write side, not the read side, makes csrrw illegal. |
| `csrrs` / `csrrc` with `rs1 != x0` to read-only | `mcause=2` |
| `csrrs` / `csrrc` with `rs1 == x0` to read-only | **No trap.** Spec-mandated read-only access. |
| Access from too-low privilege | `mcause=2` (M-mode only; effectively never) |
| Write to WARL field with illegal value | Round to nearest legal per Hazard3 csr.adoc (`mstatus.MPP` writes round to 0b11 in M-mode-only systems; `mcause` writes drop bits outside the implemented cause range) |

**Fail loudly on unknown opcodes.** `warn!` + `mcause=2`. **In `qemu_diff_riscv32 --fuzz` mode, `warn!` escalates to test failure.**

### 4.6 Interrupts

**`mip` bit map (RV-priv §3.1.9):**

| Bit | Source | Plumbing |
|---|---|---|
| 3 (MSIP) | `SIO.RISCV_SOFTIRQ` per-hart bits | Driven directly into per-hart `mip[3]` by `fan_out_riscv_irqs` |
| 7 (MTIP) | `SIO.mtime_match_asserted[hart]` | Driven directly into per-hart `mip[7]` by `fan_out_riscv_irqs` |
| 11 (MEIP) | Hazard3 IRQ controller; reads `bus.irq_pending[hart]` via `meipa` window | Driven by IRQ controller logic (P4) reading the bitmap |

**V3 was wrong** to push MTIP/MSIP through `bus.assert_irq_core` — that fans into the 52-line external-IRQ bitmap which feeds MEIP, dispatching to the wrong vector. MTIP and MSIP are **direct `mip` bits** per RV-priv. V4 corrects:

```rust
fn fan_out_riscv_irqs(&mut self) {
    let Cores::RiscV(cs) = &mut self.cores else { return; };
    let sio = &self.bus.sio;
    for c in 0..2 {
        let mut mip = cs[c].mip();
        // MTIP — level-sensitive; sio.mtime_match_asserted is also level-sensitive
        // (Sio::tick_mtime_n re-evaluates every quantum, sio/mod.rs:436-443).
        if sio.mtime_match_asserted[c] { mip |=  1 << 7; }
        else                            { mip &= !(1 << 7); }
        // MSIP — bits [1:0] of RISCV_SOFTIRQ are per-hart software interrupt flags
        let sw = (sio.riscv_softirq() >> c) & 1;
        if sw != 0 { mip |=  1 << 3; }
        else       { mip &= !(1 << 3); }
        // MEIP (bit 11) is set/cleared inside the Hazard3 IRQ controller
        // (P4) based on bus.irq_pending[c] + per-CSR-window enables.
        cs[c].set_mip(mip);
    }
}
```

`sio.mtime_match_asserted` being level-sensitive (already implemented at `sio/mod.rs:436-443`) is intentional and matches RV-priv MTIP semantics — re-asserts every quantum until firmware writes MTIMECMP past MTIME.

`bus.irq_pending: [u64; 2]` stays the arch-agnostic transport for the 52 RP2350 NVIC inputs. Peripherals fan into it via the existing `assert_irq_core` / `assert_irq_shared`. The Hazard3 IRQ-controller CSR window (`meiea`/`meipa`/`meifa`/`meipra`/`meinext`/`meicontext` at `0xBE0..0xBE5`) reads the bitmap and produces `mip[11]` per per-CSR-window enables.

**`mtvec` modes.** Bit 0: 0=direct, 1=vectored. Bit 1 hardwired to 0 (RAZ/WI). Both modes implemented in P2.

**NMI.** RP2350 datasheet §3.2.1 (line 5132): NMI is **Cortex-M33-only**; `NMI_MASK0/1` route IRQs into the M33 NMI input. On the Hazard3 side those same sources arrive as ordinary external IRQs with elevated `meicontext.preempt` priority. Hazard3 has **no separate NMI channel** (csr.adoc) and no IRQ-number reservation for NMI-like sources. No design work required.

**PPB on RISC-V.** Pure storage round-trip. The NVIC ISPR mirror at `bus/mod.rs:2216` writes `irq_pending` — harmless on RISC-V because no Hazard3 firmware writes to ARM NVIC addresses. **Known gap (P4):** `irq_pending` is currently maintained only via the ISPR mirror — ICPR/ICER/IPR aliases are not. Spec-compliant divergence on RISC-V (Hazard3 firmware uses `meifa.write1clear` instead).

**`bus.set_active_pc(pc)` per RISC-V instruction.** Required for MMIO trace (`bus/mod.rs:782`). One-liner in `execute.rs` dispatch loop.

**`wfi`.** Hart parks; resumes when `(mip & mie) != 0`. **V3's `mip != 0` was wrong** — RV-priv §3.3.2 + RP2350 datasheet §3.8.1 wfi page both specify `mie` is respected (only `mstatus.MIE` is ignored for the wake decision). `mstatus.MIE` and `mie` still gate trap *delivery*. Implementation: `wfi_parked: bool` on `Hazard3`.

**`tick_systick` is Arm-only** — guarded with `if self.cores.is_arm()`.

**Sentinels `IRQ_RISCV_MTIMER` / `IRQ_RISCV_SOFT`.** Not currently in `crates/mdrp2350/src/irq.rs`. P4 owns adding them; they exist solely as documentation since MTIP/MSIP are now driven directly into `mip` rather than through the `assert_irq_*` path. The fan-out function above doesn't actually need IRQ-number constants — V3's pseudocode that referenced them was an artefact of the wrong design.

### 4.7 Atomics

Single-host-thread, serial-interleave. **Locked to RP2350 datasheet §3.8.1.13 + §2.1.6.2** (Hazard3 upstream A-spec is empty).

**`Bus::reservation: [Option<u32>; 2]`** — per-core, word-aligned address.

**Reservable region:** `0x2000_0000..0x2008_2000` (528 KB main SRAM per RP2350 datasheet table 366, line 17281).

**Trap codes:**

| Operation | Misalign | Bus / outside-reservable |
|---|---|---|
| `lr.w` | `mcause=4` (load addr misalign) | **Outside reservable: silently fails forever** (reservation never succeeds). Inside reservable but bus fault: `mcause=5`. |
| `sc.w` | `mcause=6` (store/AMO addr misalign) | **Outside reservable: silently fails (reservation never matched, write not performed)**. Inside reservable but bus fault: `mcause=7`. |
| `amo*.w` | `mcause=6` | **Outside reservable: `mcause=7`** (datasheet §2.1.6.2 line 1709-1715: only `amo*.w` traps; lr/sc loop forever on real silicon). |

V3 conflated `sc.w` with `amo*.w`. Per datasheet: outside the reservable region, `lr.w`/`sc.w` form an infinite loop (real firmware deadlocks); only `amo*.w` faults (mcause=7) to break the implicit retry pattern. The emulator must replicate both behaviours — silently looping for `lr.w`/`sc.w`, trapping for `amo*.w`.

**Invalidation.** Any `Bus::write8`/`write16`/`write32(addr, _)` clears every reservation where `reservation[c] == Some(addr & !3)`. Word-alignment masking is mandatory. DMA writes go through `Bus::write*` (`dma.rs:547`).

**Bypass paths (documented):** `Bus::boot_ram_write32` (region 0xE) and `bus.memory.sram_write*` (used in 9 test sites) bypass `Bus::write*`. SRAM-only restriction makes the boot-RAM bypass safe (out of region). Direct SRAM byte-pokes from tests are pre-firmware setup, before any `lr.w` could have run. Future runtime helpers that bypass `write*` must invalidate manually.

**Tripwire.** `Bus::reservation` + serial-interleave is incompatible with the threaded-cores HLD. `tech_debt.md` entry to be added when P3 ships.

### 4.8 Decoded-op cache

Skip for V1. RISC-V decode goes raw-fetch every instruction.

**`fence.i` tripwire.** `debug_assert!(!RISCV_DECODE_CACHE_EXISTS, "fence.i is no-op; wire invalidation first")` in the cache-add PR's `fence.i` execute path.

### 4.9 Tests — keep `Bus::new()`, accept the allocation

V3 proposed `Box::new_zeroed()` for the decode cache. **That is wrong** — `DecodedOp::empty()` (`bus/mod.rs:73`) sets `tag = u32::MAX` as the "invalid" sentinel; an all-zero cache would claim `PC=0` is cached with `hw0=0`, executing garbage at boot for any test that exercises the decode path. Either the sentinel changes (out-of-scope refactor) or zero-init is unsafe.

**V4 decision: keep `Bus::new()`'s `DecodedOp::empty()` initialization unchanged, accept the per-test allocation.** 192 KB × ~100 RISC-V tests = ~19 MB of test-time heap, freed at test end. Non-issue on a dev machine. No parallel constructor, no sentinel refactor.

## 6. Phasing

**P0 — Probe-rs Hazard3 attach spike (1 day, before P1a). Pre-registered decision tree:**

| P0 outcome | Path | Cost estimate |
|---|---|---|
| Attach + read CSRs + HW breakpoint + step all work | **A: probe-rs direct.** P6 = `probe_diff_riscv_rp2350` mirroring `probe_diff_rp2350`. | ~1 week P6 build-out |
| Attach works; HW breakpoints don't | **B: probe-rs + SW breakpoint loop** (writes `ebreak` opcodes via SWD memory-write). | ~2 weeks P6, plus per-target instrumentation |
| No attach at all | **C: UART-mailbox fallback** mirroring `silicon_cycle_oracle_rp2350`'s approach (firmware self-stops at known points, host reads via UART). | ~2 weeks P6, plus per-scenario firmware work |

Decision criteria pre-registered so the team doesn't rationalize the cheapest after the fact.

**P1a — `Cores` enum migration (small PR, shims preserve M33 API).**
Add `Cores` enum (`Arm` arm only). Add `expect_arm*()`, `is_arm`/`is_riscv`. Add `Emulator::core(id)`/`core_mut(id)` shims. Migrate ~135 direct-`emu.cores[i]` field-access sites across 7 files. Define `step_pair_arm` free function. All existing tests/oracles pass.

**P1b — Hazard3 skeleton.**
Add `RiscV` arm, `core_riscv/` module, stub `Hazard3::step()`, reset path with the verified §4.3 values. Builder `.arch(Arch::RiscV)`. Smoke: build, step 100, observe cycles advance.

**P2 — RV32I + Zicsr + Zifencei + CSRs.**
Full base ISA, CSR file with strict trap rules (§4.5), trap entry/return, `mtvec` direct + vectored, `mret`, `ecall`/`ebreak`. Per-opcode unit tests.

**P2.4 — `qemu_diff_riscv32` GDB-stub spike (1 day, before P2.5). Pre-registered pass threshold:**

Minimum CSR set diff-able via either flat indices or `qXfer:features:read` parsing: `{mstatus, mcause, mepc, mtval, mip, mie, mtvec, mscratch}`. **Below threshold → do not ship P2.5 with GPR-only diff** (defeats the Verified-tier claim for Zicsr). Fallback: build a small in-house single-hart reference (Sail-extracted RV32IMAC executable model, or spike-as-library) for the CSR diff. Picking GPR-only is explicitly forbidden.

**P2.5 — `qemu_diff_riscv32` harness.**
Mirrors `qemu_diff_m33`. **Pinned invocation** (V4 — V3's `-machine virt` brought a UART/PLIC/CLINT memory-map that aliased our RP2350 map):

```
qemu-system-riscv32 \
  -machine none -bios none \
  -cpu rv32,a=true,m=true,c=true,zicsr=true,zifencei=true \
  -m 8M -nographic \
  -icount shift=0,align=off,sleep=off \
  -gdb tcp::3335 -S \
  -kernel <bin>
```

`-machine none` removes peripheral aliases. `-bios none` removes the OpenSBI default. `-icount` pins step determinism. Fuzz mode (`--fuzz N --seed S`). Register as oracle #13.

**P3 — M, A, C.**
Mul/div, atomics (per §4.7), compressed decoder. Per-class fuzz generators in `qemu_diff_riscv32`. **Atomics property test** (two-core interleaved random `lr.w`/`sc.w`/store sequences, hand-rolled reservation tracker) lands here; not external.

**P4 — IRQ controller + time source wiring.**
Hazard3 IRQ controller CSR window. `mtip` from `sio.mtime_match_asserted` via `fan_out_riscv_irqs` (mip bit 7, direct). `msip` from `sio.riscv_softirq` (mip bit 3, direct). `meip` from IRQ controller reading `bus.irq_pending` (mip bit 11). Trap dispatch at instruction boundary. **IRQ scenario suite of ~40–55 hand-authored hex images** — V4 expanded from V3's 25–35:

| Category | Count | What it covers |
|---|---|---|
| Per-CSR-window read/write | 6 | `meiea`/`meipa`/`meifa`/`meipra`/`meinext`/`meicontext` round-trip |
| `meinext` priority arbitration | 4 | Ties, preempt threshold, no-pending, masked-pending |
| `meicontext` save/restore | 3 | Through nested entry, save-on-entry, restore-on-mret |
| `meifa` force-bit | 3 | Force, force+ack, force-while-pending |
| `meipra` priority changes | 3 | Change at rest, change mid-handler, change masked |
| MEIP↔meinext interlock | 3 | Latch, drain, contention |
| `wfi` wake from each source | 3 | MTIP, MSIP, MEIP |
| **`mie` per-bit masking** | 3 | MSIE/MTIE/MEIE independent gating |
| **`mstatus.MIE` global gate** | 3 | Including MPIE→MIE shuffle on entry/mret |
| **Nested preempt across `meicontext.preempt` levels** | 4 | With CSR-window save/restore interaction |
| **mret→wfi cascade** | 2 | Does the mret-destination wfi wake on the same pending bit that caused entry? |
| **Interrupt on branch-delay edge** | 2 | C-extension PC misalignment cases |

V4 added the bottom four categories that V3 missed (per-bit `mie` masking, global `mstatus.MIE`, nested preempt, mret→wfi cascade). Lands as **Unit-tested only**; *Verified* requires P6.

**P5 — App integration + smoke firmware.**
`mdrp2350app` `--arch riscv` flag. `gen_blinky_riscv.py` emits `roms/rp2350/blinky-riscv.bin`. Smoke test asserts GPIO toggles. **Developer smoke; not a validation claim.**

`gen_blinky_riscv.py` requirements (V4 expanded):

- Hand-encoder for RV32IMAC; ~150–250 LoC of new code.
- One disassembly comment per emitted instruction (mirrors `gen_blinky.py`).
- **Objdump round-trip assertion in CI:** when a `riscv32-unknown-elf-objdump` is available on the host, the script invokes it on the emitted binary and compares the disassembly output to its comment track. CI doesn't gate on having the toolchain installed (still toolchain-free for the bare path), but if it's present, the round-trip catches encoder bugs.
- Bare-asm landmines documented in the script header: (a) set `gp` if any later code uses linker relaxation; (b) align vectored mtvec table to 64 bytes (16 entries × 4); (c) use `mscratch` as caller-save slot for trap entry; (d) firmware must clear `mcountinhibit` before reading `mcycle`/`minstret` (reset value is `0b101`).

## 7. Testing strategy

**Coverage:**

| Phase | Ships | Audit tier |
|---|---|---|
| P2 + P2.5 | RV32I + Zicsr + Zifencei | **Verified** (QEMU diff, with CSR threshold) |
| P3 | M, C | **Verified** (QEMU diff) |
| P3 | A (single-core) | **Verified** (QEMU diff) |
| P3 | A (dual-core reservation invalidation) | **Unit-tested + property-tested** |
| P4 | IRQ controller, mtip/msip wiring | **Unit-tested only**; *Verified* requires P6 |
| P5 | Bare-asm blinky | Developer smoke |

**Property-test invariants (P3 atomics).** Document explicitly in `core_riscv/atomics.rs`:

1. After `lr.w` at addr A by core C, `reservation[C] == Some(A & !3)`.
2. After any `Bus::write*(B, ...)` where `B & !3 == A & !3`, `reservation[C]` for every core that held A is `None`.
3. `sc.w` by core C at addr A succeeds iff `reservation[C] == Some(A & !3)` AND `A` is word-aligned AND `A` is in the reservable region.
4. **(NEW V4)** `sc.w` at addr A by core C succeeds only if `(A & !3) == reservation[C]`'s stored address — i.e. the same word as the matching `lr.w`.
5. After successful `sc.w`, `reservation[C] == None`.
6. After failed `sc.w`, memory at A is unchanged.
7. **(NEW V4)** `amo*.w` outside the reservable region traps with `mcause=7` and memory is unchanged.

V3 missed #4 (a different-address `sc.w` could read as "any matching reservation succeeds") and #7 (no test for the AMO trap path). Without these the property test is a stochastic equality check that drifts.

**`-machine none` rationale.** V3's `-machine virt` instantiates a 16550 UART, goldfish RTC, CLINT, PLIC, fw_cfg, test-device — guest loads/stores aliasing those addresses diverge from the RP2350 map. `-machine none -bios none` removes them; `-m 8M` gives flat RAM; `-icount shift=0,align=off,sleep=off` pins step determinism for the differential.

## 8. Open questions / risks

**Q1 — RESOLVED.** Reset PC = `0x0000_0000`. `gen_blinky_riscv.py` emits an image and a tiny stub at `0x0000_0000` that jumps to it (or `load_image(0x0000_0000, ...)`).

**Q2 — RESOLVED.** `mhartid = 0/1`.

**Q3 — Probe-rs Hazard3 attach.** P0 spike scheduled before P1a; pre-registered decision tree (§6) feeds P6 design.

**Q4 — Biggest scope risk: SDK firmware unrunnable on V1.** SDK toolchain emits Zba/Zbb/Zbs/Zbkb/Zca/Zcb/Zcmp by default. V1 supports none. Largest workload V1 can run is a Python-encoded blinky. Real-world firmware support is a follow-up phase comparable in size to P2+P3 combined.

**Q5 — Cycle accuracy. Owner + date assigned at P5 start (V4 — V3 said "P5 close-out" which was deferral).** RISC-V V1 uses flat 1-cycle costs except mul/div (3) and loads (2). The M33 audit lists ~14 known cycle-model gaps; RISC-V will inherit. `silicon_cycle_oracle_riscv_rp2350` enters the P6 scope at P5 start as a named deliverable.

**Q6 — Threaded cores.** `Bus::reservation` + serial-interleave incompatible with threaded-core HLD. Tripwire in §4.7.

**Q7 — `h3.misa` semantics.** Storage-only for V1.

**Q8 — `irq_pending` mirror coverage.** Only ISPR alias maintained; ICPR/ICER/IPR not. P4 known-gap; spec-compliant on RISC-V.

**Q9 — `expect_arm()` panic discipline.** Cross-arch aggregator harnesses (`test_silicon`, future multi-arch runners) must dispatch on `cores.is_arm()` before calling `expect_arm*()`. P5 TUI integration is the first such caller.

**Q10 — P1a coordination.** Shim preserves M33 API; ~135 direct-field-access sites still need mechanical rewrite. Ship in a single morning to minimize concurrent-branch friction.

## 9. What this HLD deliberately does NOT include

Per CLAUDE.md quality philosophy:

- No migration plan beyond the mechanical sed.
- No backwards-compatibility shims **except** `Emulator::core(id)`/`core_mut(id)` (which exist to *reduce* migration churn; they panic on RISC-V).
- No feature flags, no env vars.
- No bootrom / ARCHSEL / POWMAN.
- No `CoreStep` trait, no `step_pair<C>` generic. Two arms, two free functions.
- No `Bus::minimal()` parallel constructor. One constructor; accept the test-heap cost.
- No SDK firmware support in V1 (Q4).
- No silicon oracle in V1 (P6 separate HLD, gated on P0).
- No `IRQ_RISCV_MTIMER` / `IRQ_RISCV_SOFT` IRQ-number constants — MTIP/MSIP are direct `mip` bits, not external IRQ lines.

If the design grows beyond this document, the growth is wrong.
